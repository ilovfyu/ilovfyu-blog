> [!info] 项目状态
> 计划中。官网的「虾壳」页面当前作为多 Agent 协同平台的认证入口，认证服务与 AI 中转服务端代码不在本仓库中。

## 系统边界

官网部署在 GitHub Pages，只提供静态前端。认证请求由构建时的 ​`VITE_XIAKE_AUTH_BASE_URL` 指向独立的认证服务；认证成功后进入多 Agent 协同平台，AI 请求由协同平台自己的后端负责。

浏览器中的 API 地址不是秘密，真正的供应商密钥必须只存在于中转服务端。中转服务负责模型白名单、请求限制、供应商路由、额度控制和审计；前端的长度限制只能改善用户体验，不能作为安全边界。

## 接口契约

建议只暴露一个固定的 ​`POST /api/xiake/chat` 接口，并在服务端严格校验请求：

- `model` 只能从服务端配置的模型白名单中选择，不能接受用户提供的 URL、provider 或 API key。
- `messages`​ 只允许 ​`user`​ 和 ​`assistant`​ 角色，拒绝客户端传入 ​`system`​、​`tool` 和任意额外字段。
- 单条消息限制为 8,000 字符，会话最多保留 20 条消息，总上下文限制为 32,000 字符。
- 只允许 ​`stream: true`，服务端设置最大输出 token、单请求超时和最大并发数。
- 请求体设置明确的字节上限，拒绝超大 JSON、畸形 JSON 和未知 ​`Content-Type`。
- 返回 OpenAI 兼容的 SSE 时，服务端不能把供应商原始错误、密钥、内部 URL 或堆栈直接返回给浏览器。

## 访问控制

这是一个登录后使用的聊天入口，不能依赖前端隐藏区域或 ​`Origin` 判断完成鉴权。FastAPI 必须验证服务端会话，并在 CDN/WAF 和应用层同时设置限制：

- CORS 只允许生产站点的精确来源，例如 ​`https://ilovfyu.dev`​；开发环境单独允许本地来源，不使用 ​`*`。
- 按 IP 设置短周期限流，并叠加全局 QPS、并发数、每日预算和单 IP 消耗上限。
- 对连续超限、明显自动化和异常 User-Agent 触发更严格的冷却；必要时增加 Turnstile 或登录后额度。
- 在反向代理层限制请求体、连接数、读取超时和 SSE 空闲超时，避免慢连接耗尽 worker。
- 供应商调用使用服务端固定的 HTTPS 地址和密钥；禁止把用户输入拼接为上游 URL，防止 SSRF 和开放代理。

## 登录与注册契约

官网的 ​`/xiake/` 是多 Agent 协同平台的认证主页，不在博客页面中承载聊天。GitHub、手机号和邮箱认证成功后，由认证服务创建服务端会话，再跳转到配置好的协同平台地址。

前端使用 ​`VITE_XIAKE_AUTH_BASE_URL` 作为认证基址，并调用以下接口：

- `GET /github?return_to=...`​、​`GET /google?return_to=...`​、​`GET /wechat?return_to=...`​：创建一次性 OAuth ​`state`​，存入 Redis，然后跳转到对应的第三方平台。​`return_to` 必须匹配服务端允许的协同平台地址，不能直接信任任意 URL。
- `GET /github/callback`​：验证 ​`state`、交换 GitHub access token、读取稳定的 GitHub 数字用户 ID，创建服务端会话后跳转协同平台。
- `POST /login`​：接收 ​`channel`​、​`account`​、​`password`​，支持 ​`phone`​ 与 ​`email` 两种 channel。
- `POST /register`​：接收 ​`channel`​、​`account`​、​`password`​、​`code`，验证一次性验证码并创建账号。
- `POST /code`​：接收 ​`channel`​、​`account`​、​`purpose`，发送注册验证码；必须设置账号、IP 和全局频率限制。
- `GET /forgot-password`：进入认证服务负责的密码找回流程。

手机号和邮箱应在服务端标准化并建立唯一索引。密码使用 Argon2id 等适合密码存储的算法，不记录明文密码；验证码应短时有效、一次性使用、限制尝试次数并以哈希形式保存。

认证成功后设置的 Cookie 至少包含 ​`Secure`​、​`HttpOnly`​、​`SameSite=Lax`​ 和合适的 ​`Domain`​、​`Path`​。生产环境不要把 Session ID 放进 URL 或 ​`localStorage`。会话保存在 Redis 或数据库中，设置空闲和绝对过期时间，并在登录、注册和权限变化后轮换会话 ID。

如果官网和认证 API 分别使用 ​`https://ilovfyu.dev`​ 与 ​`https://api.ilovfyu.dev`​，FastAPI CORS 必须精确允许官网来源并启用 credentials，不能使用 ​`allow_origins=["*"]` 搭配 Cookie。协同平台仍需在自己的后端验证会话，不能只相信从登录页跳转过来的请求。

GitHub OAuth Client Secret、短信/邮件服务密钥、会话 Secret 和供应商 API Key 都放在 Railway Sealed Variables 中。GitHub 账号关联应依据稳定的数字用户 ID，而不是可修改的用户名。

## 提示词与工具安全

提示词注入通常不是服务器入侵，但会影响模型行为和成本。中转服务应把系统提示词固定在服务端，客户端只能提交普通对话消息；当前官网聊天不应开放工具调用、代码执行、文件读取、联网浏览或任意函数调用。

如果未来增加 Agent 能力，每个工具都需要单独的权限、参数 schema、调用次数和预算限制；涉及写入、发送、删除或部署的操作必须进入人工确认状态，不能由模型直接执行。

## 日志与密钥

- API key 放在服务端密钥管理或运行时 Secret 中，不进入 Git、前端 bundle、错误响应和普通业务日志。
- 日志只记录 request ID、时间、状态码、模型、耗时、token 用量和限流结果；默认不记录完整对话内容。
- IP 等标识应按需要脱敏或哈希，并设置日志保留期限。
- 为供应商费用、错误率、429、5xx、并发数和异常流量设置告警，支持立即禁用某个模型或整个公开入口。
- 定期轮换供应商密钥，并为不同环境、不同供应商使用独立密钥和预算。

## 验收清单

上线前至少验证以下场景：

1. 直接调用接口时传入未授权模型、​`system` 角色、超长消息、未知字段和非 JSON 请求，均得到明确的 4xx。
2. 不带 Cookie、伪造 ​`Origin`、跨域预检、重复请求和并发请求不会绕过限流或泄露内部错误。
3. 供应商超时、断流、429、5xx 和空响应都会被转换为统一错误，且不会暴露供应商密钥、堆栈和内部地址。
4. 连续发送请求无法无限消耗供应商额度；达到 IP、全局或预算阈值后会快速失败。
5. 对话内容不会被当作 HTML 执行；前端只按纯文本渲染模型输出。

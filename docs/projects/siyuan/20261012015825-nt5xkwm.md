> [!abstract] 核心定位
> Obsidian 负责知识组织和项目管理，大语言模型负责教学设计，多模态模型负责理解与生成素材，TTS 负责配音，Remotion 等渲染引擎负责确定性合成。不要让模型直接生成不可编辑的完整视频，应先产生大纲、讲稿、分镜、板书动作和时间轴等结构化中间产物。

## 1. 建设目标

系统需要把 Obsidian 中一篇或一组结构化笔记转换为可审核、可编辑、可增量重建的教学视频，同时将成片、字幕、讲稿、分镜、板书和质量报告回写到 vault。

完整流程如下：

```text
Obsidian 笔记
    ↓
Markdown AST 与知识依赖分析
    ↓
教学目标、受众和课程大纲
    ↓
讲稿、分镜与板书计划
    ↓
代码、图表、图片、板书、配音与字幕素材
    ↓
音频驱动的统一时间轴
    ↓
Remotion / Motion Canvas / Manim 确定性渲染
    ↓
代码、事实、画面、字幕和音频质检
    ↓
人工审核与局部重生成
    ↓
视频及全部工程产物回写 Obsidian
```

## 2. 设计原则

1. 模型生成意图和结构，渲染器执行确定性动作。
2. Markdown 先转 AST，不把原始字符串交给所有后续 Agent 反复解释。
3. 分镜和时间轴是系统核心，成片只是结构化工程的渲染结果。
4. 讲稿、屏幕文字和朗读文本分开管理。
5. 代码必须由真实编译器或运行环境验证。
6. 技术图、公式和文字尽量使用 HTML、SVG、Canvas 或 LaTeX 生成，不让图像模型绘制精确内容。
7. TTS 产生实际音频和时间戳后，再确定最终镜头长度。
8. 所有事实保留来源，外部输入和模型补充内容必须可追溯。
9. 每个中间产物都可读、可改、可缓存、可版本化。
10. 支持人工审核和按场景局部重建，不因一个错字重做整条视频。

## 3. 总体架构

推荐采用"Obsidian 轻量入口 + 外部生成服务"，不要把模型调用、代码执行和视频渲染全部塞入 Obsidian 插件。

|组件|职责|
| ---------------------| ---------------------------------------------------------------|
|Obsidian Vault|管理知识、课程配置、审核笔记和最终产物|
|Obsidian 插件或命令|选择笔记、提交任务、显示状态、打开产物|
|Markdown Parser|解析标题、段落、代码、Callout、Mermaid、公式、WikiLink 和附件|
|Knowledge Resolver|收集前置知识、术语、来源和有限深度的关联笔记|
|Teaching Agent|生成学习目标、教学顺序、案例、练习和时长预算|
|Script Agent|生成旁白、屏幕文字和术语读音|
|Storyboard Agent|把教学内容拆为镜头和视觉动作|
|Blackboard Agent|生成板书布局、笔画动作、擦除和镜头跟随计划|
|Asset Pipeline|生成或收集图片、SVG、图表、代码画面和浏览器演示|
|TTS/ASR|生成配音和时间戳，并复核字幕对齐|
|Timeline Compiler|把讲稿、音频、画面、板书、字幕编译为统一时间轴|
|Render Engine|用 Remotion、Motion Canvas、Manim 和 FFmpeg 输出视频|
|Quality Service|检查事实、代码、字幕、画面、安全区、音量和节奏|
|Workflow Queue|负责阶段状态、并发、缓存、失败重试和恢复|

### 3.1 为什么使用外部服务

- 视频渲染和浏览器录制消耗较大，不适合绑定 Obsidian 窗口生命周期。
- FFmpeg、Chromium、字体和代码沙箱更适合独立环境。
- 外部服务便于使用任务队列、容器、GPU 和对象存储。
- CLI 可以先完成 MVP，后续插件只需调用稳定 API。

## 4. Obsidian 输入规范

建议给可生成视频的课程笔记增加统一 frontmatter：

```yaml
---
title: TypeScript 联合类型与类型窄化
video:
  enabled: true
  audience: 掌握 JavaScript 基础的 TypeScript 初学者
  level: beginner
  duration: 12m
  language: zh-CN
  format: landscape
  resolution: 1920x1080
  voice: zh-CN-teacher-01
  style: technical-dark
  presenter: voice-over
  prerequisites:
    - "[[02 基础类型变量与类型推断]]"
  outputs:
    directory: _Generated/Videos/TypeScript
---
```

### 4.1 Markdown 到视频的映射

|笔记元素|视频表达|
| ------------| ---------------------------------|
|标题|章节、场景分组和目录|
|段落|讲稿候选，不直接逐字朗读|
|列表|逐项出现的关键点或检查清单|
|代码块|IDE 动画、诊断、Diff 或运行结果|
|Mermaid|SVG 流程图和节点动画|
|表格|对比卡片或动态表格|
|Callout|提示、警告、重点结论|
|WikiLink|前置知识、补充镜头或课程跳转|
|LaTeX|公式排版、推导或板书|
|图片|原始视觉素材或参考图|
|引用与链接|事实来源和片尾参考资料|

### 4.2 少量视频指令

MVP 不宜设计复杂 DSL，可先使用 HTML 注释：

```md
<!-- video:scene title="为什么需要联合类型" duration="45s" -->
<!-- video:visual type="code-editor" -->
<!-- video:blackboard action="write" region="right" -->
<!-- video:pause duration="1.2s" -->
<!-- video:quiz type="single-choice" -->
```

等实际案例稳定后，再引入 ​`video-scene`​ 或 ​`blackboard` 自定义代码块。

## 5. 文档解析与知识准备

### 5.1 转换为统一 AST

```json
{
  "documentId": "typescript-narrowing",
  "title": "TypeScript 联合类型与类型窄化",
  "sections": [
    {
      "id": "union-types",
      "title": "联合类型",
      "blocks": [
        {
          "type": "paragraph",
          "text": "联合类型表示一个值可能属于多个类型集合。"
        },
        {
          "type": "code",
          "language": "ts",
          "code": "function printId(id: string | number) {}"
        }
      ]
    }
  ]
}
```

AST 需要保存源笔记、标题路径、原始行号和链接目标，后续生成的每个事实才能回溯来源。

### 5.2 控制知识扩展范围

默认只展开显式前置知识和一层 WikiLink，并设置：

- 最大笔记数量
- 最大字符或 token 数量
- 允许的目录
- 排除标签和敏感目录
- 外部链接白名单

不要把整个 vault 自动发送给模型。

## 6. 教学设计阶段

Teaching Agent 的任务不是摘要，而是设计一条可学习路径：

- 确认受众和前置知识。
- 将内容改写成可验证的学习目标。
- 识别核心概念和常见误区。
- 为概念安排问题、错误示例、解释、修复和练习。
- 分配每章和每个镜头的时间预算。
- 决定哪些内容使用代码、图表、板书或普通幻灯片。

技术课程推荐结构：

```text
问题场景
→ 错误示例
→ 为什么报错
→ 正确心智模型
→ 正确实现
→ 常见陷阱
→ 小练习
→ 小结
```

结构化输出示例：

```json
{
  "audience": "TypeScript 初学者",
  "durationSeconds": 720,
  "objectives": [
    "理解联合类型的值集合含义",
    "使用 typeof 完成窄化",
    "使用 never 完成穷尽检查"
  ],
  "sections": [
    {
      "title": "为什么需要窄化",
      "durationSeconds": 120,
      "pattern": "error-explain-fix",
      "visualMode": "code-and-blackboard"
    }
  ]
}
```

## 7. 讲稿与分镜

### 7.1 三层讲稿

|层级|内容|
| ----------------| ----------------------------------|
|Narration|实际旁白内容|
|On-screen text|屏幕显示的短句和标签|
|Director notes|镜头、动画、板书、停顿和强调动作|

```json
{
  "sceneId": "scene-03",
  "narration": "此时 id 可能是字符串，也可能是数字，因此不能直接调用字符串专属方法。",
  "spokenText": "此时 I D 可能是字符串，也可能是数字。",
  "onScreenText": [
    "string | number",
    "先窄化，再使用成员能力"
  ],
  "directorNotes": {
    "visual": "code-and-blackboard",
    "highlight": ["id.toUpperCase()"],
    "blackboardCue": "draw-union-sets",
    "pauseAfterSeconds": 0.8
  }
}
```

### 7.2 分镜数据

```ts
interface VideoScene {
  id: string;
  purpose: "hook" | "explain" | "demo" | "compare" | "quiz" | "summary";
  narration: string;
  estimatedDuration: number;
  visual:
    | CodeVisual
    | BlackboardVisual
    | DiagramVisual
    | SlideVisual
    | BrowserVisual
    | TerminalVisual;
  overlays: Overlay[];
  sources: SourceReference[];
}
```

每个镜头只能有一个主视觉焦点。代码在演示时，板书只保留简短提示；板书在推导时，不要同时滚动大段代码。

## 8. 多模态素材流水线

### 8.1 代码画面

使用 Shiki 或 Monaco Editor 加 Remotion 生成，不录制不可控的真实编辑器窗口：

```json
{
  "type": "code",
  "language": "ts",
  "steps": [
    { "action": "insert", "line": 2, "text": "id.toUpperCase();" },
    { "action": "showDiagnostic", "code": "TS2339" },
    { "action": "replace", "range": [2, 2], "text": "if (typeof id === \"string\") { ... }" }
  ]
}
```

正确示例必须通过真实编译，错误示例必须产生预期诊断。

### 8.2 技术图表

```text
Mermaid / D3 / React Flow
→ SVG
→ 标记可动画节点
→ Remotion 按时间轴控制描边、透明度和位置
```

精确文字、代码、公式和架构图不用文生图模型生成。图像模型更适合封面、背景和抽象比喻插图。

### 8.3 浏览器与终端

- Playwright 负责真实网页交互、截图和录屏。
- 终端命令在隔离容器中执行。
- 命令输出经过清洗后再进入视频。
- 禁止模型直接伪造关键编译或运行结果。

### 8.4 板书

板书不是一段提前录好的视频，而是一组可编辑的语义动作和矢量笔画：

```text
教学意图
→ 板书布局
→ write / draw / highlight / erase / move 动作
→ SVG Path 或 Canvas stroke
→ 音频时间戳对齐
→ Motion Canvas / Remotion 渲染
```

完整实现见 [教学视频板书实现方案](</projects/20261012015824-0jxktu6/>)。

## 9. 配音、字幕与时间轴

### 9.1 TTS 输出要求

- 场景音频
- 句子级时间戳
- 字或词级时间戳
- 语速和停顿
- 可选音素时间戳

技术术语需要词典：

```yaml
TypeScript: Type Script
tsconfig: TS config
keyof: key of
typeof: type of
Node.js: Node J S
npm: N P M
tsc: T S C
.d.ts: 声明文件
```

### 9.2 正确的时长计算顺序

```text
讲稿确认
→ TTS 生成真实音频
→ 获取时间戳
→ 板书和动画绑定词句时间
→ 计算镜头长度
→ 渲染
```

不要仅按文字长度猜测镜头时长。

### 9.3 字幕

使用"讲稿 + TTS 时间戳"生成初稿，再用 ASR 复核。输出：

- SRT
- WebVTT
- ASS 烧录样式
- 完整 transcript
- 关键词高亮轨道

## 10. 渲染方案

### 10.1 推荐技术分工

|技术|用途|
| ---------------| --------------------------------------------|
|Remotion|课程场景、字幕、代码、图表、转场和最终组合|
|Motion Canvas|板书笔画、精确时间线和手写动画|
|Manim|数学公式和复杂推导，可选|
|Shiki/Monaco|代码高亮和编辑器画面|
|Mermaid/D3|流程图、关系图和数据图|
|Playwright|浏览器演示|
|FFmpeg|拼接、转码、响度标准化、字幕和 HLS|

### 10.2 统一时间轴

```json
{
  "sceneId": "scene-03",
  "start": 85.2,
  "end": 116.8,
  "audio": "audio/scene-03.wav",
  "captions": [
    { "start": 85.2, "end": 89.5, "text": "联合类型表示一个值可能属于多个类型集合" }
  ],
  "events": [
    { "time": 88.0, "track": "code", "action": "highlight", "target": "line-2" },
    { "time": 91.4, "track": "blackboard", "action": "write", "target": "union-label" }
  ]
}
```

时间轴轨道至少包括：音频、字幕、主视觉、板书、指针、高亮、转场和背景音乐。

## 11. 质量检查

### 11.1 内容与事实

- 学习目标是否全部覆盖。
- 前置知识顺序是否正确。
- 示例是否支持结论。
- 是否区分类型检查和运行时行为。
- API、版本和命令是否有来源。
- 模型补充事实是否可追溯。

### 11.2 代码与配置

|内容|验证方式|
| ------------| ----------------------|
|正确代码|编译并按需运行|
|错误代码|验证预期错误码和位置|
|JSON/YAML|Schema 校验|
|Shell 命令|隔离容器执行|
|浏览器示例|Playwright 测试|
|板书公式|LaTeX 解析及数值抽样|

### 11.3 视听检查

- 字幕和板书是否超出安全区域。
- 字体在 1080p 和移动端是否可读。
- 画面是否匹配旁白。
- 是否长时间没有视觉变化。
- 板书笔画是否过快、遮挡或跳跃。
- 代码、字幕和板书是否争夺同一视觉区域。
- 是否存在静音、截断、爆音和音量不一致。

### 11.4 多模态抽帧复核

每 10 至 20 秒抽帧，将截图、旁白、分镜和教学目标交给视觉模型，检查可读性和画面一致性。多模态检查不能替代编译器、链接检查和音频分析。

## 12. 人工审核与增量生成

建议保留三个审批点：

|阶段|人工检查|
| ------------| ----------------------------------|
|教学大纲|学习目标、顺序和时长|
|讲稿与分镜|表述、画面、代码和板书计划|
|成片|节奏、字幕、音质、事实和视觉效果|

按依赖局部重建：

|修改内容|需要重建|
| --------------| -----------------------------|
|原始知识点|大纲之后全部阶段|
|讲稿|TTS、字幕、时间轴和相关镜头|
|单个板书动作|对应场景及最终拼接|
|配音人|TTS、字幕时间轴和视频|
|字幕样式|视频渲染|
|主题|视觉场景和最终视频|
|缩略图|仅缩略图|

## 15. 安全与授权

- 代码和命令在一次性容器中执行。
- 默认禁止读取整个 vault、宿主文件系统和 ​`.env`。
- 默认关闭网络，按域名白名单放行。
- 对模型输入做目录限制和密钥过滤。
- 防止外部抓取产生 SSRF。
- 不信任模型返回的路径和 shell 命令。
- 图片、字体、音乐和引用内容保存许可证与来源。
- AI 图片保存模型、提示词和生成日期。

## 16. MVP 范围

第一版只支持：

- 单篇 Markdown 输入
- 5 至 15 分钟中文横屏视频
- 文本卡片、代码、Mermaid 和板书四类主视觉
- TTS、字幕、1080p MP4、缩略图和质量报告
- 分镜审批后才生成音频和视频
- 真实代码编译验证
- 结果回写 vault

obsidian-video generate \

## 18. 首个样板建议

选择 ​`Language/TypeScript/核心语法/05 联合交叉窄化与穷尽检查.md` 制作 8 至 12 分钟样板：

1. 用代码演示联合类型错误。
2. 用板书画出两个类型集合。
3. 用代码和板书联合解释 ​`typeof` 窄化。
4. 用状态图解释可辨识联合。

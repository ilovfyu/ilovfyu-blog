SkillCache 是一个持续构建中的 Python 库，聚焦 Agent 使用的 Skills 发生增删改时，提示词前缀变化引起的 KV Cache / Prompt Cache 失效问题。

## 项目定位

将 Skills 的组织、变更识别与缓存策略封装为可集成的 Python 库。目标是在保证推理语义正确的前提下，提高可复用前缀的稳定性，减少不必要的重复预填充。

## 要解决的问题

Agent 的上下文通常由基础指令、Skills 说明、工具定义和当前任务共同组成。如果每次重新拼接 Skills，或者将经常变化的内容放在前部，小范围修改也可能使后续前缀缓存无法复用。

|场景|关注的问题|
| --------------------| ------------------------------------------|
|新增或移除 Skill|避免无关稳定内容被重新排列|
|修改某个 Skill|识别真正发生变化的内容及其影响范围|
|按任务加载 Skills|兼顾上下文长度、加载策略与前缀稳定性|
|多版本 Skills 共存|区分版本，避免把旧配置的缓存误用于新请求|

## 持续构建方向

以下是当前设计方向，尚不代表已经发布的接口或能力：

1. **稳定前缀组织**：分离稳定基础指令和动态 Skills 内容，研究确定性的提示词编排。
2. **变更识别**：记录 Skill 的标识与版本，定位内容变化和缓存复用边界。
3. **运行时适配**：根据推理后端提供的能力，适配前缀缓存或服务端 Prompt Cache。
4. **可观测验证**：对比相同任务下的缓存命中、重复预填充、首 Token 延迟与输出正确性。

## 正确性边界

在常见的因果 Transformer 前缀缓存中，缓存依赖当前 Token 及其前序上下文。修改前面的内容后，不能仅因后面某个 Skill 的文字未变就直接复用其旧 KV。优化重点是保留真正相同的前缀，并按后端规则重建受影响部分。[vLLM 前缀缓存设计](https://docs.vllm.ai/en/latest/design/prefix_caching/)

云端 Prompt Cache 与直接操作推理引擎 KV Cache 的能力不同。例如 Claude 的工具定义变化会影响相关缓存层级，适配方案需要遵守服务商的规则。[Claude 工具与缓存说明](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-use-with-prompt-caching)

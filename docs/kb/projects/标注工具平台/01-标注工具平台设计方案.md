::: abstract 核心定位
建设一个面向 AI 训练数据的标注工具平台（代号 **ILOVFYU-TAGFINDER**），统一承接图像、文本、音频、视频数据的导入、任务分发、标注执行、质量审核与数据集导出。平台同时支持三种标注方式：**人工标注**（手工框选、分类、描点、转录）、**大模型标注**（VLM/LLM 预标注与审核）、**检测模型标注**（YOLO 等检测/分割模型批量预标注与迭代），三种方式共享同一套任务状态机、Schema 体系与质量校验流程。项目代号：`ilovfyu-tagfinder`。
:::

## 1. 建设目标

平台需要把「原始数据 → 标准数据集」的整条链路做成可管理、可追溯、可回流的闭环，而不只是一个画框子的网页。

```text
数据导入（上传 / 对象存储 / API 同步）
    ↓
数据预处理（去重、脱敏、格式归一、缩略图）
    ↓
数据集与 Schema 定义（任务类型、类别清单、坐标体系）
    ↓
标注任务创建（批次、难度、人员、标注方式分配）
    ↓
标注执行
  ├─ 人工标注（编辑器 + 快捷键 + 撤销栈）
  ├─ 大模型标注（VLM/LLM 预标注，人工确认）
  └─ 检测模型标注（YOLO 批量预标注，人工修正）
    ↓
质检与抽检（规则校验 + 人工复检 + 一致率评估）
    ↓
版本管理与回流（返工样本重新进入任务队列）
    ↓
数据集导出（COCO / Pascal VOC / YOLO / JSONL）
    ↓
训练与评测，结果回流改进标注规则与模型权重
```

核心目标拆成五条：

1. **多方式并存**：人工、大模型、检测模型三种标注方式在同一套任务模型下协同，而不是三套互相割裂的子系统。
2. **质量可度量**：每一条标注都能追溯到人、模型、任务、版本，质检指标（通过率、一致率、返工率）可统计可导出。
3. **格式标准**：导出遵循 COCO、Pascal VOC、YOLO、JSONL 等行业通用格式，并保证与任务 Schema 一一对应。
4. **模型可迭代**：YOLO 等检测模型既是标注工具，也是被标注数据训练出来的产物，形成「标注 → 训练 → 回灌预标注」的闭环。
5. **协作与并发**：多人可并行标注同一批次，服务端负责版本冲突与进度同步，浏览器端断点续标。

## 2. 设计原则

1. 标注是数据工程的一部分，任务、人员、模型和质检必须有状态机，不能只靠页面。
2. 预标注（无论来自 YOLO 还是大模型）都只是候选结果，必须可确认、可修正、可回退。
3. 模型输出的置信度和来源必须记录，作为质检和返工的依据。
4. 标注格式与任务类型绑定：任务定义时即确定导出格式与类别体系，避免后续大规模转换。
5. 抽检不是可选项：抽样数量、覆盖范围、判定规则应可配置，并形成一致率指标。
6. 数据安全与脱敏前置：导入阶段完成敏感信息识别，标注与导出阶段不接触明文密钥。
7. 每个中间产物（预标注结果、人工修正、质检报告、导出数据集）都版本化、可缓存、可重放。
8. 支持断点续标：编辑器的修改提交到服务端，刷新或崩溃后不丢失已完成部分。
9. 标注数据与导出格式解耦：内部统一存结构化 JSON，导出时按目标格式序列化。
10. 服务端是唯一事实来源（source of truth），前端只做展示与编辑缓冲。

## 3. 行业标准与格式基线

平台遵循业界通用标注数据规范和格式，作为功能设计与导出能力的基线。

| 领域 | 常用格式 | 说明 |
|---|---|---|
| 图像检测 | COCO JSON / Pascal VOC XML | 目标检测、实例分割的主流格式 |
| 图像检测 | YOLO TXT | 归一化 bbox，适合 YOLO 系列直接训练 |
| 图像分割 | COCO JSON（polygon + RLE）/ 语义掩码 PNG | 实例分割、语义分割 |
| 图像关键点 | COCO JSON（keypoints 数组） | 人体姿态、关键点检测 |
| 图像分类 | CSV / JSONL（label 列） | 单标签、多标签分类 |
| 文本 | JSONL / IOB2 / spaCy JSON | 文本分类、实体抽取、关系标注 |
| 音频 | JSON / 分段时间戳 | 转写、事件标记、说话人分离 |
| 视频 | COCO 扩展 / 关键帧 + 插值 | 视频目标检测、跟踪 |

### 3.1 Schema 统一抽象

每种任务类型在平台内部对应一个 **Schema 定义**，是标注、校验、导出的唯一依据：

```json
{
  "task_type": "image-detection",
  "classes": ["car", "pedestrian", "truck"],
  "coordinate_system": "normalized",
  "annotation_fields": ["bbox", "category", "attributes"],
  "rules": {
    "bbox_min_area": 0.0001,
    "required_attributes": { "car": ["color"] }
  },
  "export_formats": ["coco", "yolo"]
}
```

- Schema 在任务创建时固化，修改需走版本化流程，避免已标注数据失配。
- 导出器按 Schema 的 `export_formats` 映射到目标格式。

## 4. 总体架构

采用「数据平台 + 标注工作台 + 模型推理服务 + 质检服务」的多服务架构，服务端负责状态与权限，浏览器只做编辑和预览。

| 组件 | 职责 |
|---|---|
| 数据接入层 | 对象存储 / 本地上传 / API 导入，自动解析、去重、缩略图与预览 |
| 任务编排层 | 数据集、批次、任务分配、状态机、返工与结算统计 |
| 标注工作台 | 浏览器编辑器，支持图像/文本/音频/视频四种画布，快捷键与撤销栈 |
| 预标注服务 | 统一调用入口，路由到 YOLO 推理服务或大模型 API，输出候选标注 |
| 质检服务 | 规则校验、抽检任务、人工复检、一致率计算与返工回流 |
| 导出与交付 | 按 Schema 序列化导出，生成数据集清单与质量报告 |
| 权限与审计 | 角色（管理员/标注员/审核员/只读）、操作日志、数据隔离 |

### 4.1 为什么预标注独立成服务

- YOLO 推理需要 GPU/批处理，大模型需要流式与配额管理，两者生命周期差异大，不应绑在标注页面里。
- 预标注结果要落库、可版本化，供人工确认前预览，也可被质检直接引用。
- 独立服务便于后续扩展新的标注模型（SAM、YOLO 新版本、自训模型）而不改编辑器。
- 模型服务有独立的超时、重试、熔断与预算控制，避免标注中断。

### 4.2 进程内模块划分

```text
FastAPI 主服务
├─ auth（认证会话）
├─ datasets（数据集）
├─ tasks（任务编排）
├─ annotations（标注读写）
├─ review（质检）
├─ export（导出）
└─ prelabel-client（预标注编排，HTTP 调推理服务）

推理服务（独立进程）
├─ yolo_engine（Ultralytics YOLO）
├─ vlm_engine（视觉语言模型）
└─ llm_engine（文本大模型）

Celery worker（异步任务）
├─ prelabel_task
├─ export_task
└─ review_task
```

## 5. 任务与数据模型

### 5.1 核心实体与关系

```text
User ──1:N── Task（分配/创建）
Dataset ──1:N── Asset ──1:N── AnnotationTask
AnnotationTask ──1:N── Annotation ──1:N── ReviewRecord
Dataset ──1:N── ExportJob
AnnotationTask ──N:1── TaskType（Schema）
```

### 5.2 数据库核心表

| 表 | 关键字段 | 说明 |
|---|---|---|
| users | id, username, password_hash, role | 角色：admin/annotator/reviewer/viewer |
| datasets | id, name, type, storage_prefix, status | 数据集与存储前缀 |
| assets | id, dataset_id, path, checksum, meta, width, height | 数据样本，meta 存分辨率/时长等 |
| task_types | id, key, schema_definition | 任务类型与 Schema JSON |
| tasks | id, dataset_id, type_id, assignee_id, strategy, status, progress | strategy：manual/llm/yolo/hybrid |
| annotations | id, task_id, asset_id, source, payload, confidence, version, created_by | source：human/llm/yolo |
| reviews | id, task_id, asset_id, result, comment, reviewer_id | result：pass/reject/disputed |
| export_jobs | id, dataset_id, format, status, output_path | 导出任务 |
| audit_logs | id, user_id, action, target, detail | 审计 |

### 5.3 任务类型定义

| 任务类型 | Schema 要点 | 支持方式 |
|---|---|---|
| image-classification | 类别列表、单/多标签 | 人工、大模型 |
| image-detection | 类别、bbox 坐标系（归一化/像素） | 人工、YOLO、大模型 |
| image-segmentation | polygon / RLE / 语义掩码 | 人工、YOLO-Seg、SAM、大模型 |
| image-keypoints | 关键点集合、可见性 | 人工、大模型 |
| text-classification | 标签集 | 人工、大模型 |
| text-ner | 实体类型、IOB2 | 人工、大模型 |
| audio-transcription | 分段时间戳、文本 | 人工、大模型（ASR） |
| video-detection | 帧序列、插值策略 | 人工、YOLO 跟踪插值 |

### 5.4 任务状态机

```text
created → assigned → in_progress
                     → pending_review（等待质检）
                     → approved（通过，可导出）
                     → rejected（返工，回到 in_progress 重新标注）
                     → disputed（争议，进入仲裁）
                     → paused（暂停，人工或超预算时）
```

- 状态迁移记录审计日志，异常迁移直接拒绝。
- 任务完成后自动进入 `pending_review`，由质检规则决定全检或抽检。

## 6. 标注方式设计

### 6.1 人工标注

面向精度优先、规则复杂或模型无法覆盖的场景，是全平台质量的兜底。

- **编辑器能力**：快捷键（框选/缩放/切换类别/撤销重做/上一个下一个）、吸附辅助、批量复制对象、多边形/魔法棒/吸附工具。
- **一致性保障**：标注指南（Label Guide）随任务展示，包含示例图与边界规则；类别色板固定，避免色盲混淆。
- **进度与盲测**：支持盲标（不展示他人标注）、双人标注对照、审核员复检。
- **产出字段**：标注者、开始/结束时间、设备、操作版本，全部入库。
- **撤销/重做**：前端维护本地操作栈，提交时以最终 payload 为准；服务端不做逐笔合并。

### 6.2 大模型标注

利用 VLM（视觉语言模型）与 LLM 完成预标注、批注和审核，适合标签体系明确、语义理解类任务。

- **VLM 预标注**：将图像 + 类别清单 + 提示词发送给 VLM，返回结构化 JSON（bbox / polygon / 类别），经 Schema 校验后落库为 `prelabel`。
- **LLM 文本标注**：文本分类、实体抽取、关系标注使用 LLM + 输出校验（枚举校验 / IOB2 正则），失败自动重试或转入人工。
- **审核式标注**：对已有标注做「类别纠错」「边界检查」「完整性检查」，输出修正建议，供人工一键确认。
- **质量控制**：大模型输出必须经过 Schema 校验（坐标范围、类别合法性、字段完整性），低置信或超时结果不自动进入通过状态。
- **成本控制**：按资产批量、按 token/调用次数预算、限流与熔断，配额耗尽自动回落人工。

```text
任务 → 组装提示词（含 Schema 与类别清单）
     → 调用 VLM/LLM API（限流 + 超时 + 重试）
     → 结构化输出解析
     → Schema 校验（类别/坐标/完整性）
     → 通过 → prelabel 落库，标记来源=llm
     → 失败 → 记录错误，转入人工
```

### 6.3 YOLO 检测模型标注

利用 YOLO 系列（detection / segmentation / OBB / keypoints）做批量预标注，人工只修正边界，是检测类数据的最常用加速手段。

- **模型接入**：模型服务封装统一推理接口，支持多版本模型并存（YOLOv5/v8/自训权重），按任务路由。
- **批量预标注**：对数据集批量推理，输出 YOLO 格式 bbox/polygon，经坐标与类别校验后生成 prelabel。
- **置信度阈值**：任务级配置 `conf_threshold`，低置信样本跳过预标注（进入人工）或标记为「需要重点检查」。
- **人工修正流**：编辑器加载 prelabel 后，标注员只删除错误框、修正边界、补充漏检；提交时记录「修正量」（新增/删除/修改数量），用于衡量模型收益。
- **模型迭代闭环**：已通过质检的数据导出为 YOLO 格式，微调模型，再把新模型权重回灌预标注服务，使自动覆盖率逐轮上升。

```text
数据集批量 → YOLO 推理（conf≥阈值）
          → 后处理（NMS、类别映射、坐标换算）
          → Schema 校验
          → prelabel 落库（来源=yolo, conf=0.87）
          → 人工确认/修正 → 质检 → 导出 YOLO 格式
          → 微调模型 → 回灌预标注
```

### 6.4 三种方式的协同与切换

- 一个任务可以选择「人工 / 大模型预标 / YOLO 预标 / 混合」，预标注完成后统一进入人工确认阶段。
- 任务级配置允许「先模型后人工」：模型先生成，人工确认率低于阈值时整批返工。
- 质检记录来源字段（human/llm/yolo），便于统计每种方式的返工率与吞吐。

## 7. 前端工作台交互设计

### 7.1 布局

```text
┌────────────┬──────────────────────────────┬────────────┐
│ 类别面板    │       标注画布（Konva）        │  图层列表   │
│ CLASS      │                              │  LAYERS    │
│ · car      │      图像 / 文本 / 音视频       │  · box 01  │
│ · person   │      （缩放 / 平移 / 吸附）     │  · box 02  │
│ · truck    │                              │  · poly 01 │
└────────────┴──────────────────────────────┴────────────┘
┌────────────────────────────────────────────────────────┐
│ 工具条：框选 | 多边形 | 关键点 | 分类 | 撤销 | 重做 | 提交 │
└────────────────────────────────────────────────────────┘
```

### 7.2 关键交互

- **编辑缓冲**：画布操作先进入前端本地状态，提交按钮将最终 payload 发服务端；刷新后从服务端最新版本恢复。
- **自动保存**：每完成一个资产自动提交，支持「上一张/下一张」连续标注不丢数据。
- **预标注展示**：`source=yolo/llm` 的候选以虚线样式呈现，标注员确认后转为实线（来源改为 human）。
- **快捷键体系**：`1-9` 切类别、`B` 框选、`P` 多边形、`K` 关键点、`Ctrl+Z/Y` 撤销重做、`←/→` 切换资产。
- **缩放平移**：鼠标滚轮缩放、空格拖拽平移，坐标按归一化存储，跨分辨率不漂移。

### 7.3 WebSocket 协作

- 任务详情页订阅进度推送，多人标注时可见「某人正在标注第 N 张」。
- 质检结果通过 WS 实时推送给对应标注员，支持即时返工。

## 8. API 契约（核心）

统一前缀 `/v1`，鉴权用 Bearer Token。

| 方法 | 路径 | 说明 |

| GET | /v1/auth/me | 当前用户 |
| GET/POST | /v1/datasets | 数据集列表/创建 |
| POST | /v1/datasets/{id}/assets | 资产上传 |
| GET | /v1/tasks | 任务列表（分页/筛选） |
| POST | /v1/tasks | 创建任务 |
| GET | /v1/tasks/{id} | 任务详情含 Schema |
| GET | /v1/tasks/{id}/next-asset | 取下一待标资产 |
| GET | /v1/tasks/{id}/annotations/{asset_id} | 取标注（含预标注） |
| PUT | /v1/tasks/{id}/annotations/{asset_id} | 提交标注 |
| POST | /v1/tasks/{id}/prelabel | 触发预标注 |
| POST | /v1/tasks/{id}/submit | 提交质检 |
| POST | /v1/reviews | 创建质检记录 |

### 8.1 标注提交示例

```json
{
  "asset_id": "a_1024",
  "annotations": [
    {
      "id": "ann_91",
      "category": "car",
      "bbox": [0.12, 0.31, 0.28, 0.19],
      "attributes": { "color": "white" },
      "source": "human",
      "confidence": null
    }
  ],
  "correction_stats": { "added": 0, "removed": 1, "modified": 2 },
  "version": 3
}
```

- 服务端以 `version` 做乐观并发控制：版本不匹配则返回 409，前端拉取最新再合并。
- `correction_stats` 用于统计模型预标接受率。

## 9. 质量保障

### 9.1 自动化校验

| 校验项 | 说明 |
|---|---|
| 坐标合法性 | bbox 越界、负宽高、多边形自交 |
| 类别合法性 | 不在 Schema 类别清单内则拒绝 |
| 完整性 | 必需字段缺失、空标注、重复标注 |
| 规则校验 | 业务规则（如「汽车标签必须包含车头框」） |

校验失败返回错误明细（字段级），前端在画布对应位置高亮。

### 9.2 人工复检与抽检

- 全检 + 抽检混合：高风险批次全检，低风险批次按比例抽检。
- 抽检比例、覆盖维度（按人/按类别/按批次）、通过阈值可配置。
- 双人标注一致性（对同一批资产两人独立标注）计算 IAA（Inter-Annotator Agreement），作为新人上岗与任务拆分的依据。

### 9.3 指标看板

| 指标 | 定义 |
|---|---|
| 通过率 | 首检通过任务数 / 总任务数 |
| 返工率 | 被驳回任务数 / 总任务数 |
| 抽检一致率 | 抽检一致资产 / 抽检资产 |
| 模型预标接受率 | 人工未修改或微调占比 |
| 人均/小时吞吐 | 按任务类型与方式统计 |
| 预标注覆盖率 | 有预标注资产 / 总资产 |

## 10. 数据导出与格式转换

- 导出在「已通过」状态上执行，未通过资产不进入交付数据集。
- 导出器按 Schema 映射到目标格式，并生成 `dataset.yaml`/`README` 清单，记录版本、类别、数量与质量摘要。
- 支持差分导出（仅导出本批次变更）与全量导出，支持与训练流水线对接。
- 导出走异步任务（Celery），完成后写入 MinIO 并在任务列表提供下载链接。

## 11. 权限、安全与审计

- 角色：管理员（任务与 Schema）、标注员（编辑）、审核员（质检）、只读（查看导出）。
- 数据隔离：不同项目/租户数据物理或逻辑隔离，导出与预标注都不泄露跨项目内容。
- 审计：关键操作（创建任务、修改 Schema、导出、批量删除、模型调用）落审计日志。
- 敏感数据处理：导入时识别个人隐私信息（人脸、车牌、证件），按策略打码、裁剪或限制访问。
- 预标注服务只接受可信来源的任务请求，请求带服务间鉴权，避免被当作开放代理。

## 12. 部署形态与里程碑

### 12.1 部署形态

- **MVP（单机/内网）**：FastAPI 后端 + PostgreSQL/MinIO + 浏览器标注编辑器，YOLO 推理为独立推理服务，大模型走 API。
- **规模化**：任务队列（Celery/Redis）、GPU 推理集群、对象存储扩展、租户与审计完善。

### 12.2 里程碑建议

1. **M1 图像检测闭环**：数据导入 → 人工标注 → 质检 → 导出 COCO/YOLO。验证编辑器与状态机。控制台可用假数据登录。
2. **M2 YOLO 预标注**：接入 YOLO 推理，人工修正流与修正量统计上线。
3. **M3 大模型标注**：VLM 图像预标注 + LLM 文本标注接入，Schema 校验与成本控制上线。
4. **M4 全任务类型**：分割、关键点、文本、音频、视频类型补齐。
5. **M5 模型迭代闭环**：导出回灌训练 → 权重回灌预标注，形成数据飞轮。

## 13. 关键决策记录

| 决策 | 选项 | 结论 | 理由 |
|---|---|---|---|
| 后端框架 | FastAPI vs Go zero | FastAPI | 模型生态、异步 IO、自动文档，标注场景更合适 |
| 前端画布 | Konva vs Fabric vs 原生 Canvas | Konva | 场景图 API、事件、变换矩阵完善，适合标注编辑 |
| 预标注实现方式 | 页面内置 vs 独立服务 | 独立服务 | 模型生命周期、GPU 与预算管理与编辑器解耦 |
| 预标注定位 | 直接入库 vs 候选确认 | 候选确认 | 保证质量底线，兼顾效率 |
| 标注内部存储 | 按格式存 vs 统一 JSON | 统一 JSON | 与导出格式解耦，便于多格式导出与版本管理 |
| 坐标体系 | 像素 vs 归一化 | 归一化 | 跨分辨率不漂移，导出时换算 |
| 导出时机 | 任意状态 vs 仅已通过 | 仅已通过 | 保证交付数据集质量与可追溯 |
| 模型结果保存 | 只存结果 vs 结果+置信度+来源 | 结果+置信度+来源 | 质检与模型迭代都依赖这些字段 |
| 并发控制 | 最后写入 vs 版本号乐观锁 | 版本号乐观锁 | 多人并行标注避免覆盖 |

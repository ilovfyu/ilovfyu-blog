本篇围绕一个完整生命周期展开：查找镜像、拉取、运行、观察、进入、停止、删除和清理。

## 1. 命令对象化结构

现代 Docker CLI 推荐使用“管理对象 + 动作”的形式：

```bash
docker image ls
docker container ls
docker volume ls
docker network ls
```

一些短命令仍很常用：

| 短命令 | 完整形式 | 作用 |
| --- | --- | --- |
| `docker pull` | `docker image pull` | 拉取镜像 |
| `docker run` | `docker container run` | 创建并启动容器 |
| `docker ps` | `docker container ls` | 列出容器 |
| `docker rm` | `docker container rm` | 删除容器 |
| `docker rmi` | `docker image rm` | 删除镜像 |

两种形式可以并用。脚本中应保持一致，提高可读性。

## 2. 镜像引用如何组成

完整引用可写成：

```text
registry.example.com/team/app:1.4.2
```

| 部分 | 示例 | 含义 |
| --- | --- | --- |
| Registry | `registry.example.com` | 镜像仓库服务 |
| Namespace | `team` | 用户或组织 |
| Repository | `app` | 镜像仓库名 |
| Tag | `1.4.2` | 人类可读版本标签 |
| Digest | `sha256:...` | 内容寻址标识 |

若省略 registry，默认通常是 Docker Hub；省略 tag 会隐式使用 `latest`，但生产中不要依赖这种省略。

推荐：

```bash
docker pull nginx:1.28-alpine
docker pull redis:8.2-alpine
```

生产可进一步固定 digest：

```bash
docker pull nginx:1.28-alpine@sha256:<从可信来源确认的摘要>
```

Tag 可以移动，digest 对应确定内容。不要把示例占位 digest 原样用于部署。

## 3. 查找与拉取镜像

Docker Hub 网页比 CLI 搜索更适合查看官方说明、支持架构和环境变量。

```bash
docker search nginx --filter is-official=true
docker pull nginx:1.28-alpine
```

查看本地镜像：

```bash
docker image ls
docker image ls nginx
docker image ls --digests
```

查看元数据：

```bash
docker image inspect nginx:1.28-alpine
```

查看历史层：

```bash
docker image history nginx:1.28-alpine
```

`history` 有助于理解层大小，但不能替代漏洞扫描，也不应把秘密写入任何构建层。

## 4. `docker run` 到底做了什么

```bash
docker run --name hello alpine:3.22 echo "hello Docker"
```

等价过程可以拆开观察：

```bash
docker create --name hello-2 alpine:3.22 echo "hello Docker"
docker start --attach hello-2
```

`docker run` 的核心步骤：

1. 本地没有镜像时拉取镜像。
2. 基于镜像创建容器可写层。
3. 应用网络、挂载、环境变量和资源配置。
4. 启动镜像入口进程。
5. 根据前台或后台模式连接输出。

容器不是“永远运行的小虚拟机”。主进程退出，容器就进入停止状态。

## 5. 常用运行参数

```bash
docker run \
  --name web \
  --detach \
  --publish 127.0.0.1:8080:80 \
  --env APP_ENV=development \
  --restart unless-stopped \
  nginx:1.28-alpine
```

| 参数 | 含义 |
| --- | --- |
| `--name` | 设置稳定、易读的容器名 |
| `-d`、`--detach` | 后台运行 |
| `-it` | 分配 TTY 并保持标准输入 |
| `--rm` | 停止后自动删除容器 |
| `-p`、`--publish` | 发布端口到宿主机 |
| `-e`、`--env` | 设置环境变量 |
| `--env-file` | 从文件读取环境变量 |
| `--mount` | 显式配置 volume/bind/tmpfs |
| `--restart` | daemon 重启后的重启策略 |

临时命令优先 `--rm`：

```bash
docker run --rm alpine:3.22 date -u
```

交互式 shell：

```bash
docker run --rm -it alpine:3.22 sh
```

## 6. 命令与镜像默认命令

运行镜像时追加的命令通常覆盖 Dockerfile 的 `CMD`：

```bash
docker run --rm nginx:1.28-alpine nginx -v
```

覆盖 entrypoint 需要显式指定：

```bash
docker run --rm --entrypoint /bin/sh nginx:1.28-alpine -c 'id && ls /'
```

排障时可短暂覆盖入口；生产定义不应依赖人工覆盖来修复错误镜像。

## 7. 列出与筛选容器

只看运行中容器：

```bash
docker ps
```

包括已停止容器：

```bash
docker ps -a
```

仅输出 ID：

```bash
docker ps -q
```

常用筛选：

```bash
docker ps --filter status=exited
docker ps --filter name=web
docker ps --filter ancestor=nginx:1.28-alpine
docker ps --filter label=com.example.project=demo
```

稳定脚本不要解析默认表格，使用 `--format`：

```bash
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}'
```

## 8. 启停与删除

```bash
docker stop web
docker start web
docker restart web
docker rm web
```

`docker stop` 先向 PID 1 发送终止信号，等待超时后才强制杀死：

```bash
docker stop --timeout 20 web
```

强制删除运行中容器：

```bash
docker rm --force web
```

应优先正常停止，让应用刷新缓冲区和关闭连接。`docker kill` 默认直接发 `SIGKILL`，只适合进程无响应等场景。

暂停与停止不同：

```bash
docker pause web
docker unpause web
```

暂停会冻结进程，并不执行优雅关闭。

## 9. 日志、进程与资源

```bash
docker logs web
docker logs --follow --tail 100 web
docker logs --since 10m --timestamps web
```

查看容器内进程：

```bash
docker top web
```

实时资源：

```bash
docker stats
docker stats web
docker stats --no-stream web
```

容器应用应把普通日志写到 stdout，把错误写到 stderr。直接写容器内文件会让采集、轮转和容器替换更困难。

## 10. `exec` 与 `attach` 的区别

在运行中容器启动新进程：

```bash
docker exec -it web sh
```

执行单条命令：

```bash
docker exec web nginx -T
```

`docker attach web` 连接的是容器主进程的标准流，误按 `Ctrl+C` 可能终止它。日常排障通常用 `exec` 或 `logs`。

注意：极简生产镜像可能没有 shell、`curl` 或包管理器。不要为了临时调试把一整套工具永久塞进生产镜像；可使用同网络的诊断容器。

## 11. 容器与宿主机之间复制文件

从容器复制：

```bash
docker cp web:/etc/nginx/nginx.conf ./nginx.conf
```

复制进容器：

```bash
docker cp ./nginx.conf web:/tmp/nginx.conf
```

`docker cp` 适合取证和临时操作，不是配置管理方案。可重复部署应通过镜像、Config、Secret 或只读挂载交付配置。

## 12. `inspect`：最可靠的事实来源

```bash
docker inspect web
```

只取具体字段：

```bash
docker inspect --format '{{.State.Status}}' web
docker inspect --format '{{.Config.Image}}' web
docker inspect --format '{{json .Mounts}}' web
```

常查位置：

- `.State`：状态、PID、退出码、健康状态。
- `.Config`：镜像、命令、环境变量、标签。
- `.HostConfig`：端口绑定、重启策略、资源限制。
- `.Mounts`：实际挂载源和目标。
- `.NetworkSettings.Networks`：网络和 IP。

环境变量可能含敏感信息，分享 inspect 输出前要脱敏。

## 13. 环境变量

直接传值：

```bash
docker run --rm -e APP_ENV=dev alpine:3.22 env
```

从当前 shell 透传：

```bash
export APP_ENV=dev
docker run --rm -e APP_ENV alpine:3.22 env
```

使用文件：

```dotenv
APP_ENV=development
LOG_LEVEL=info
```

```bash
docker run --rm --env-file .env alpine:3.22 env
```

不要提交包含密码的 `.env`，也不要认为环境变量不可见。拥有 inspect 权限的用户通常能读取它们。敏感信息应使用平台 Secret 管理能力并限制访问。

## 14. 标签与可管理性

```bash
docker run -d \
  --name labeled-web \
  --label com.example.project=tutorial \
  --label com.example.owner=platform \
  nginx:1.28-alpine
```

按标签筛选：

```bash
docker ps --filter label=com.example.project=tutorial
docker inspect --format '{{json .Config.Labels}}' labeled-web
```

标签适合记录项目、所有者、环境和自动化策略，不能存秘密。

## 15. 镜像标记、推送与登录

重新标记不会复制镜像层：

```bash
docker image tag demo-api:1.0 registry.example.com/team/demo-api:1.0
```

推荐通过标准输入登录：

```bash
printf '%s' "$REGISTRY_TOKEN" | \
  docker login registry.example.com --username "$REGISTRY_USER" --password-stdin
```

推送：

```bash
docker push registry.example.com/team/demo-api:1.0
```

退出：

```bash
docker logout registry.example.com
```

生产标签建议：

- `1.4.2`：精确发布版本。
- `git-&lt;short-sha&gt;`：对应源码提交。
- digest：部署时获得强不可变性。
- 不以 `latest` 作为唯一生产标识。

## 16. 删除与清理

删除指定镜像：

```bash
docker image rm nginx:1.28-alpine
```

镜像仍被容器引用时会拒绝删除。先确认并处理容器，而不是立即加 `--force`。

查看磁盘：

```bash
docker system df
docker system df --verbose
```

清理停止容器：

```bash
docker container prune
```

清理未使用镜像：

```bash
docker image prune
docker image prune --all
```

清理构建缓存：

```bash
docker builder prune
```

::: danger
`docker system prune --volumes` 可能删除未被容器引用但仍有业务数据的 volume。先列出、检查、备份，再清理。
:::

## 17. 常见陷阱

### 容器一启动就退出

```bash
docker ps -a
docker logs <容器名>
docker inspect --format '{{.State.ExitCode}} {{.State.Error}}' <容器名>
```

常见原因：主进程执行完毕、配置错误、文件权限错误、端口冲突或依赖不可达。

不要用 `tail -f /dev/null` 掩盖应用已经退出；修复入口命令。

### 容器名冲突

名称由已停止容器继续占用：

```bash
docker ps -a --filter name=web
docker rm web
```

### 修改容器后无法复现

`docker exec` 内安装包或改配置只改变当前容器可写层。删除重建后会消失。长期变更应进入 Dockerfile。

### 使用容器 IP 作为稳定地址

容器重建后 IP 可能变化。容器间通信应使用用户定义网络中的容器名或 Compose 服务名。

### 把容器当备份

容器可写层不是可靠备份。数据库数据应置于命名 volume，并建立应用一致性备份和恢复演练。

## 18. 实战：运行一个只读 Nginx

```bash
docker run -d \
  --name secure-web \
  --publish 127.0.0.1:8080:8080 \
  --read-only \
  --tmpfs /var/cache/nginx:rw,noexec,nosuid,size=64m \
  --tmpfs /var/run:rw,noexec,nosuid,size=16m \
  --cap-drop ALL \
  --cap-add NET_BIND_SERVICE \
  nginxinc/nginx-unprivileged:1.28-alpine
```

验证：

```bash
curl http://127.0.0.1:8080
docker inspect --format '{{.HostConfig.ReadonlyRootfs}}' secure-web
docker exec secure-web id
```

清理：

```bash
docker rm -f secure-web
```

安全参数要结合镜像行为验证。只读根文件系统通常仍需为运行时临时目录提供 tmpfs。

## 19. 命令速查

```bash
docker image ls
docker pull IMAGE:TAG
docker run --rm IMAGE:TAG COMMAND
docker run -d --name NAME IMAGE:TAG
docker ps -a
docker logs -f --tail 100 NAME
docker exec -it NAME sh
docker inspect NAME
docker stats --no-stream NAME
docker stop NAME
docker rm NAME
docker image rm IMAGE:TAG
docker system df
```

## 20. 练习与检查清单

1. 拉取 `alpine:3.22` 并查看 digest。
2. 创建名为 `sleep-lab` 的容器，后台运行 `sleep 300`。
3. 用 `exec` 查看容器内用户和进程。
4. 用 `inspect --format` 输出容器状态。
5. 正常停止并删除容器。
6. 启动一个带项目标签的 Nginx，再按标签筛选。

- [ ] 能解释 tag 与 digest 的区别。
- [ ] 临时容器会使用 `--rm`。
- [ ] 知道 `exec` 不等于 `attach`。
- [ ] 能从退出码和日志定位启动失败。
- [ ] 不把容器可写层当持久化存储。
- [ ] 清楚 prune 的删除范围后才执行。

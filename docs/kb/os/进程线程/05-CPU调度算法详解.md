::: abstract 本章定位
调度器（CPU Scheduler）决定"就绪队列里谁先上 CPU、跑多久"。本章覆盖教材全部经典算法：FCFS、SJF/SRTF、RR、Priority、MLFQ，给出甘特图与平均等待时间的完整手算过程，并对比各自优缺点。**面试最常考的不是概念，而是手算**——平均等待时间、平均周转时间、时间片对响应与开销的影响，务必自己动笔算一遍。
:::

## 1. 调度准则（Scheduling Criteria）

判断一个调度算法好不好，先定义度量指标。以进程 P 为例：

- **CPU 利用率（CPU utilization）**：CPU 忙的时间占比，越高越好（0~100%）。
- **吞吐量（Throughput）**：单位时间完成的进程数，如 3 进程/秒。
- **周转时间（Turnaround Time）** = 完成时间 − 到达时间 = 等待时间 + CPU 执行时间 + I/O 时间。
- **等待时间（Waiting Time）** = 在就绪队列里排队等待的时间之和（不包括执行与 I/O）。
- **响应时间（Response Time）** = 首次获得 CPU 的时间 − 到达时间。交互系统最关心它。

::: tip 四者的关系
周转 = 等待 + 执行 + I/O。调度算法能改变的只有"等待时间"。所以手算时核心都是算**等待时间**，再 + 执行时间得周转时间。
:::

| 准则 | 目标 | 关注者 |
|---|---|---|
| CPU 利用率 | 最大化 | 系统管理员 |
| 吞吐量 | 最大化 | 批处理系统 |
| 周转时间 | 最小化 | 批处理用户 |
| 等待时间 | 最小化 | 通用 |
| 响应时间 | 最小化 | 交互用户（终端/UI） |

::: warning 指标之间互相打架
要吞吐（长任务连续跑）就会牺牲响应（短任务干等）；要响应（时间片切细）就牺牲吞吐（切换开销大）。调度算法就是在这些目标间取舍——没有"全能冠军"，只有场景匹配。
:::

## 2. FCFS：先来先服务

### 2.1 规则与特点

- **非抢占**：一旦运行就一直跑到结束。
- 按到达就绪队列的顺序执行，等价于排队。
- 实现极简单（FIFO 队列），但问题显著。

### 2.2 手算（教材经典例）

三个进程全部在 0 时刻到达：P1=24、P2=3、P3=3（burst 单位 ms）。

**顺序 P1→P2→P3**：

```
| P1(24) |      P2(3)     |   P3(3)   |
0        24               27          30
```

| 进程 | 等待时间 | 完成时间 | 周转时间 |
|---|---|---|---|
| P1 | 0 | 24 | 24 |
| P2 | 24 | 27 | 27 |
| P3 | 27 | 30 | 30 |

- 平均等待 = (0+24+27)/3 = **17**
- 平均周转 = (24+27+30)/3 = **27**

**顺序 P2→P3→P1**：

```
| P2(3) | P3(3) |     P1(24)        |
0        3       6                   30
```

- 平均等待 = (6+0+3)/3 = **3**
- 平均周转 = (30+3+6)/3 = **13**

::: important 护航效应（Convoy Effect）
同样三个进程，顺序不同平均等待从 17 降到 3。长任务排在前面会让后面所有短任务陪跑——**护航效应**。FCFS 的等待时间高度依赖进程到达顺序，极不稳定。
:::

### 2.3 适用场景

CPU 密集 + 进程少且 burst 相近时不错（无抢占、实现简单）。交互式系统不可用（响应无保证）。

## 3. SJF 与 SRTF：最短作业优先

### 3.1 核心思想

**每次调度选择 CPU burst 最短的进程**。教材证明：**SJF 在所有调度算法中平均等待时间最小**（最优）。

两种形态：
- **SJF（非抢占）**：进程一旦开始运行就执行完。
- **SRTF（抢占式 SJF）**：若有新进程的剩余时间 < 当前进程剩余时间，就抢占当前进程。也叫 Shortest-Remaining-Time-First。

### 3.2 手算 SJF（非抢占）

四个进程 0 时刻到达：P1=6、P2=8、P3=7、P4=3。

顺序 = 按 burst 升序：**P4(3) → P1(6) → P3(7) → P2(8)**

```
| P4(3) | P1(6) | P3(7) |  P2(8)   |
0        3       9       16         24
```

| 进程 | 等待 | 周转 |
|---|---|---|
| P4 | 0 | 3 |
| P1 | 3 | 9 |
| P3 | 9 | 16 |
| P2 | 16 | 24 |

- 平均等待 = (0+3+9+16)/4 = **7**
- 平均周转 = (3+9+16+24)/4 = **13**

对比 FCFS（按 P1,P2,P3,P4 顺序）：平均等待 = (0+6+14+21)/4 = 10.25，SJF 完胜。

### 3.3 手算 SRTF（抢占）

进程不同时刻到达：

| 进程 | 到达 | Burst |
|---|---|---|
| P1 | 0 | 8 |
| P2 | 1 | 4 |
| P3 | 2 | 9 |
| P4 | 3 | 5 |

逐时刻模拟（时刻括号内为到达的新进程）：
- t=0：P1 运行（剩余 7 时，P2 到达 burst 4 < 7 → 抢占）
- t=1：P2 运行；t=2 P3 到（9，不抢）；t=3 P4 到（5 > 剩余 3，不抢）
- t=5：P2 完成。剩余 P1(7) P3(9) P4(5) → P4 最短，跑
- t=10：P4 完成。剩余 P1(7) P3(9) → P1 跑
- t=17：P1 完成。P3 跑
- t=26：P3 完成

```
|P1|    P2    |    P4    |    P1    |        P3        |
0  1          5          10         17                 26
```

| 进程 | 完成 | 等待 = 完成−到达−burst | 周转 |
|---|---|---|---|
| P1 | 17 | 17−0−8 = 9 | 17 |
| P2 | 5 | 5−1−4 = 0 | 4 |
| P3 | 26 | 26−2−9 = 15 | 24 |
| P4 | 10 | 10−3−5 = 2 | 7 |

- 平均等待 = (9+0+15+2)/4 = **6.5**
- 平均周转 = (17+4+24+7)/4 = **13**

SRTF 比非抢占 SJF 的 7 更小——抢占使"更短的任务"能更早插入。

### 3.4 SJF 的致命问题：不可实现

::: important SJF 需要预知未来
要选"最短 burst"，必须先知道每个进程的 CPU burst 长度——这**只有运行完才知道**，所以 SJF 理论最优、实际不可实现。只能**预测**：

指数平均预测：τ₍ₙ₊₁₎ = α·tₙ + (1−α)·τₙ
- tₙ = 第 n 次的真实 burst，τₙ = 第 n 次预测值，α 通常取 0.5
- α 越大越"信最近"，α=0 则永远用初始值
:::

（实际中 Linux 等系统用衰减统计近似预测，见 [多处理器调度与实时调度](/kb/os/进程线程/06-多处理器调度与实时调度/) 的 CFS。）

::: warning 另一个副作用：饥饿
短任务源源不断到来时，长任务永远轮不到 → **饥饿（starvation）**。
:::

## 4. RR：时间片轮转

### 4.1 规则

- **抢占式**：就绪进程按到达顺序排队，每次运行**一个时间片（time quantum, q）**，耗尽就移到队尾。
- 是所有交互式系统的基石（保证响应时间）。
- 特点：n 个进程、时间片 q 时，每个进程在 **n·q** 时间内必获一次 CPU（响应时间上界）。

### 4.2 手算：P1=24、P2=3、P3=3，q=4

```
| P1 |P2|P3| P1 | P1 | P1 | P1 | P1 |
0    4  7 10   14   18   22   26   30
```

P1 被切成 6 段（24/4），P2、P3 各 1 段，共 8 个调度段，7 次上下文切换。

| 进程 | 完成 | 等待 = 周转−burst | 周转 |
|---|---|---|---|
| P1 | 30 | 6 | 30 |
| P2 | 7 | 4 | 7 |
| P3 | 10 | 7 | 10 |

- 平均等待 = (6+4+7)/3 = **5.67**
- 平均周转 = (30+7+10)/3 = **15.67**

对比 SJF（平均等待 7/周转 13）：RR 等待更好但周转更差——**时间片轮转牺牲了短作业的尽快完成，换来的是所有进程的响应上界**。

### 4.3 时间片的选择：经典权衡

| 时间片 | 响应 | 上下文切换开销 |
|---|---|---|
| 很小（如 1ms） | 好 | 开销占比高 |
| 很大（如 100ms） | 差，退化接近 FCFS | 低 |

教材量化例：假设一次上下文切换 0.1ms：
- q = 1ms → 0.1/1 = **10%** 的时间花在切换上
- q = 10ms → 0.1/10 = **1%**
- q = 100ms → 0.1/100 = 0.1%，但响应上界 = n×100ms

::: important 原则：时间片要 >> 上下文切换时间
经验法则：q 通常取 10–100ms，把切换开销压在 1% 以内，同时保证交互响应"感觉不到延迟"。q 越小越公平、响应越快，但 CPU 越"忙"于换人。
:::

## 5. Priority 调度（优先级调度）

### 5.1 规则

每个进程有优先级（Priority）。**数值越小优先级越高**（或反之，按教材惯例用小的高）。分抢占式与非抢占式两种。SJF 其实是 Priority 的特例（优先级 = 预测 burst 反比）。

### 5.2 手算（非抢占）

| 进程 | Burst | 优先级 |
|---|---|---|
| P1 | 10 | 3 |
| P2 | 1 | 1 |
| P3 | 2 | 4 |
| P4 | 1 | 5 |
| P5 | 5 | 2 |

按优先级排序（1 最高）：**P2 → P5 → P1 → P3 → P4**

```
|P2| P5  |      P1      |P3|P4|
0  1     6             16 18 19
```

| 进程 | 等待 | 周转 |
|---|---|---|
| P2 | 0 | 1 |
| P5 | 1 | 6 |
| P1 | 6 | 16 |
| P3 | 16 | 18 |
| P4 | 18 | 19 |

- 平均等待 = (0+1+6+16+18)/5 = **8.2**
- 平均周转 = (1+6+16+18+19)/5 = **12**

### 5.3 饥饿与老化（Starvation & Aging）

::: warning 低优先级的绝境
高优先级进程源源不断时，低优先级进程可能**无限期等待** → 饥饿。甚至可能永远得不到 CPU。
:::

::: tip 解决方案：老化（Aging）
**随着等待时间增长，逐步提高进程的优先级**。例如每 15 分钟优先级 +1，那么低优先级的 P 只要等得够久，最终会升到最高并被调度。老化用"时间换公平"，把"可能永远等不到"变成"最多等多久"。
:::

## 6. MLFQ：多级反馈队列

### 6.1 规则

综合 FCFS/SJF/RR 优点的"现代调度模板"。核心：**按优先级分成多条队列，每队列有不同时间片，进程按行为动态升降级**。

教材标准 3 队列例子：

```
Q0 优先级最高  时间片 8   RR   ──> 用满 8ms 没完成 → 降级到 Q1
Q1            时间片 16  RR   ──> 用满 16ms 没完成 → 降级到 Q2
Q2            FCFS             ──> 按到达顺序跑完
```

**规则**：
1. 新进程进入 Q0（最高优先级）。
2. Q0 里按 RR q=8 调度；用满 8ms 未完成 → 降级 Q1。
3. Q1 里按 RR q=16；用满 16ms 未完成 → 降级 Q2。
4. Q2 里按 FCFS。
5. **只有当高优先级队列为空时，才服务低优先级队列**（否则优先）。

### 6.2 手算：P1 = 40ms，从 Q0 进入

| 阶段 | 队列 | 运行 | 剩余 |
|---|---|---|---|
| 1 | Q0（q=8） | 0–8 | 32 → 降级 |
| 2 | Q1（q=16） | 8–24 | 16 → 降级 |
| 3 | Q2（FCFS） | 24–40 | 0 → 完成 |

```
| Q0: P1(8) |   Q1: P1(16)   |   Q2: P1(16)   |
0           8                 24               40
```

- 如果中途有新进程进 Q0，它会优先于 Q1/Q2 里的 P1 运行 → **新进程获得最优响应**。
- 结果：I/O 密集（burst 短）的进程留在高队列享受快速响应；CPU 密集（burst 长）的进程被降级，不影响交互体验。

### 6.3 MLFQ 要处理的问题

| 问题 | 现象 | 解法 |
|---|---|---|
| 饥饿 | 高队列进程多时低队列永无 CPU | **老化**：等待过久的进程逐步升级回高队列 |
| 行为变化 | 进程从 I/O 密集变 CPU 密集 | 定期把所有进程重新放回最高队列 |
| 队列内调度 | 同队列多个进程 | 时间片 RR 或 FCFS |

### 6.4 Linux 的对应

::: important Linux 与 MLFQ 的关系
- Linux **O(1) 调度器**（2.6.0~2.6.22）是典型的 MLFQ：140 级优先级（0–99 实时 + 100–139 普通），普通级用 nice 值映射到不同优先队列，时间片随优先级分配。
- 现代 **CFS**（完全公平调度器，2.6.23 起）不再按"优先级 + 时间片"排队，改用红黑树按**虚拟运行时间**调度，追求公平而非多级反馈。但 CFS 仍保留实时队列（`SCHED_FIFO`/`SCHED_RR`）优先于普通任务。
- 一句话：MLFQ 是**理解思路**的最佳模型，CFS 是现代 Linux 的**真实实现**。详见 [多处理器调度与实时调度](/kb/os/进程线程/06-多处理器调度与实时调度/) 与 [Linux进程与调度实操](/kb/os/Linux/01-Linux进程与调度实操/)。
:::

## 7. 五算法优缺点对比表

| 算法 | 抢占 | 平均等待 | 响应 | 饥饿 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|---|---|---|
| FCFS | 否 | 差（依赖顺序） | 差 | 无 | 简单、公平 | 护航效应 | 批处理 |
| SJF（非抢占） | 否 | 最优 | 差 | 有 | 理论平均等待最小 | 需预知 burst、长作业饿死 | 批处理（理论） |
| SRTF（抢占） | 是 | 最优（可抢占下） | 好 | 有 | 最短剩余优先 | 需预知、频繁切换 | 理论 |
| RR | 是 | 尚可 | 最好 | 无 | 响应有上界、公平 | 周转差、切换开销 | 交互式 |
| Priority | 皆可 | 视优先级分布 | 高优先好 | **严重** | 可控、灵活 | 低优先级饿死 | 实时/多级系统 |
| MLFQ | 是 | 好 | 好 | 可解决（老化） | 综合多者、自适应 | 参数调校复杂 | **现代通用 OS** |

::: tip 记忆口诀
FCFS 排队最老实；SJF 理论最优但活在梦里；RR 图响应；Priority 图控制但会饿人；MLFQ 把前四者揉在一起，成了现代系统的标准答案。
:::

## 8. 手算综合例题

**例题**：四个进程到达时间与 burst 如下，分别用 SJF（非抢占）、SRTF、RR(q=3) 求平均等待与平均周转。

| 进程 | 到达 | Burst |
|---|---|---|
| A | 0 | 5 |
| B | 1 | 2 |
| C | 2 | 8 |
| D | 3 | 3 |

**① SJF（非抢占）**：t=0 只有 A 到达 → 必须跑 A。t=5 完成，此时 B(2)、C(8)、D(3) 就绪，按最短选 B→D→C。

```
|   A   |B| D |       C       |
0       5 7  10               18
```

- 等待：A=0，B=5−1=4，C=10−2=8，D=7−3=4 → 平均 = (0+4+8+4)/4 = **4**
- 周转：A=5，B=7−1=6，C=18−2=16，D=10−3=7 → 平均 = (5+6+16+7)/4 = **8.5**

**② SRTF（抢占）**：t=0 跑 A(剩4)；t=1 B(2) 到，B<A 抢；t=2 C(8) 到，不抢 B；t=3 D(3) 到，B 剩 0？t=3 时 B 已跑 2 完成。剩余 A(4) C(8) D(3) → D 最短跑 3-6；t=6 D 完成，A(4) C(8) → A 跑 6-10；C 跑 10-18。

```
|A| B | D |   A   |      C       |
0 1   3   6        10             18
```

- 等待：A = 完成10−到达0−burst5 = 5；B = 3−1−2 = 0；C = 18−2−8 = 8；D = 6−3−3 = 0 → 平均 = (5+0+8+0)/4 = **3.25**
- 周转：A=10，B=3−1=2，C=16，D=3 → 平均 = (10+2+16+3)/4 = **7.75**

**③ RR(q=3)**：到达顺序 A,B,C,D。

```
| A |B| C |D | A  | C   |  C   |
0   3  6   9  12  15    18    23   (C 完成于 8+15=23)
```

排一下：0–3 A，3–6 B（B burst 2，6 完成），6–9 C，9–12 D（D burst 3，12 完成），12–15 A（A 剩余 2 完成），15–23 C（剩余 8 完成）。

| 进程 | 完成 | 等待 = 完成−到达−burst | 周转 |
|---|---|---|---|
| A | 15 | 15−0−5 = 10 | 15 |
| B | 6 | 6−1−2 = 3 | 5 |
| C | 23 | 23−2−8 = 13 | 21 |
| D | 12 | 12−3−3 = 6 | 9 |

- 平均等待 = (10+3+13+6)/4 = **8**
- 平均周转 = (15+5+21+9)/4 = **12.5**

**结论对比**：

| 算法 | 平均等待 | 平均周转 |
|---|---|---|
| SJF | 4 | 8.5 |
| SRTF | **3.25** | **7.75** |
| RR(q=3) | 8 | 12.5 |

SRTF 最优（符合理论），RR 因时间片切碎而最差——但只有 RR 保证交互响应有上界。

## 9. 本章小结

- 调度准则：等待/周转/响应/吞吐/利用率，核心手算指标是**等待时间**。
- FCFS 简单但有护航效应；SJF/SRTF 最优但需预知 burst（指数平均预测）；RR 用时间片换响应上界，q 要远大于切换开销；Priority 灵活但会饥饿，用老化解决；MLFQ 综合四者成为现代调度模板，Linux 的 CFS 是它的现代继任者。
- 手算四步法：画甘特图 → 记完成时间 → 算等待=完成−到达−burst → 取平均。

## 10. 自测题

1. **FCFS 的护航效应怎么产生？** 长 burst 进程先到，后面所有短进程排队空等，平均等待被拉高且依赖到达顺序。
2. **SJF 为什么"最优却不可实现"？** 理论上平均等待最小，但需要预先知道每个进程的 burst 长度；实际用指数平均（τ = α·t + (1−α)·τ）预测。
3. **SRTF 与 SJF 的区别？** SRTF 是抢占式 SJF，新进程剩余时间更短时就抢占当前进程。
4. **RR 的时间片设太小/太大的后果？** 太小则上下文切换开销占比高（q=1ms、切换 0.1ms 时 10% 浪费）；太大则响应上界变差，退化为 FCFS。
5. **优先级调度的饥饿与解决？** 低优先级进程无限期等待；老化（aging）定期提升等待进程优先级。
6. **MLFQ 为什么适合现代 OS？** 高优先级队列短时间片保证交互响应，长任务降级到长时间片/ FCFS 保证吞吐，配合老化防止饥饿。
7. **周转时间和等待时间的关系？** 周转 = 等待 + burst + I/O 时间；调度只影响等待部分。
8. **手算：SJF 下 0 时刻到达 burst 为 6、8、7、3 的四个进程，平均等待是多少？** 顺序 P4(3)→P1(6)→P3(7)→P2(8)，等待 = 0+3+9+16=28，平均 **7**。

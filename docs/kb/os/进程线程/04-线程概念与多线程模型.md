::: abstract 本章定位
上一章我们抱怨"进程切换太贵、进程间通信太麻烦"，线程就是解药：**同一个进程内开多条执行流，共享地址空间，切换便宜、通信零拷贝**。这一篇讲线程与进程的本质区别、三种线程映射模型的取舍、三大线程库怎么用，以及 Linux 上线程的真实实现（clone + NPTL + task_struct 共享）。
:::

## 1. 线程的定义与为什么需要它

### 1.1 什么是线程

**线程（Thread）**是进程内的一个执行单元，是 **CPU 调度的基本单位**。一个进程可以有一个或多个线程，它们：

- **共享**：地址空间（代码、数据、堆）、打开的文件表、信号处理器、全局变量；
- **独占**：线程 ID、程序计数器（PC）、寄存器组、栈、栈指针。

```
一个进程 = 资源容器（地址空间/文件/信号）
   │
   ├── Thread 1：PC₁ 寄存器₁ 栈₁   ← 可运行、可被单独调度
   ├── Thread 2：PC₂ 寄存器₂ 栈₂
   └── Thread 3：PC₃ 寄存器₃ 栈₃
        ↑ 共享同一份 text/data/heap、共享 fd 表
```

### 1.2 进程 vs 线程 对比

| 维度 | 进程 | 线程 |
|---|---|---|
| 资源拥有 | 独立地址空间、独立 fd 表 | 共享所属进程的地址空间与 fd 表 |
| 调度单位 | 现代 OS 中实际调度线程 | 是 CPU 调度的基本单位 |
| 创建开销 | fork：复制页表 + COW 页表设置 | 只创建栈 + 上下文，快一个数量级 |
| 切换开销 | 换页表、刷 TLB/cache | 只切栈/寄存器/PC，共享页表不用换 |
| 通信 | 需要 IPC（管道/共享内存/消息） | 直接读写共享变量 |
| 健壮性 | 进程崩溃不影响其他进程 | 一个线程崩溃（如野指针）可能杀死整个进程 |
| 资源冲突 | 互不干扰 | 需要同步机制（见 [临界区问题](/kb/os/同步异步/01-临界区问题与互斥实现/)） |

### 1.3 多线程的动机（教材原文精华）

| 动机 | 例子 |
|---|---|
| 并行性（parallelism） | 多核 CPU 上让每个核跑一个线程 |
| 并发性（concurrency） | 单核上多个线程交错执行，掩盖 I/O 延迟 |
| 响应性 | 浏览器：UI 线程不阻塞，网络线程在后台下载 |
| 资源共享 | 线程天然共享进程数据，无需 IPC 拷贝 |
| 经济性 | 创建/切换都比进程便宜 |
| 可扩展性 | 新增核时通过加线程直接获益 |

## 2. 用户级线程 vs 内核级线程

### 2.1 谁认识线程？

| | 用户级线程（ULT） | 内核级线程（KLT） |
|---|---|---|
| 管理主体 | 用户空间的线程库（如 NPTL 的调度在用户态） | 内核 |
| 内核是否感知 | 内核只看到"一个进程"，不知道里面有几个线程 | 内核认识每个线程，每个都能被单独调度 |
| 调度方式 | 线程库自己调度，抢占发生在进程内部 | 内核调度器直接调度每个线程 |
| 切换成本 | 不涉及模式切换，很快 | 会进内核，比 ULT 慢 |
| 阻塞行为 | 一个线程阻塞（如 read），整进程所有线程全停 | 一个线程阻塞不影响其他线程 |
| 并行能力 | 单核上多个 ULT 无法同时运行在多个核 | 多核上可真正并行 |

### 2.2 关键取舍

::: warning 用户级线程的致命伤
用户级线程的库对内核不可见，内核仍然"一个进程一核调度"。所以用户级线程**没法利用多核并行**，而且某个线程一旦发起阻塞系统调用，**整个进程**（所有线程）都会停住。
:::

::: tip 现代实践
现代操作系统（Linux/Windows/macOS）几乎全部采用**内核级线程**。教材讲 ULT 更多是为了讲清历史与概念。用户态"协程/绿色线程"（如 Go goroutine、Python asyncio）是 ULT 思想的当代复兴，但会通过多路复用跑在内核线程上。
:::

## 3. 三种映射模型

### 3.1 many-to-one（多对一）

多个用户级线程映射到**一个**内核线程：

```
用户线程  U1  U2  U3
            \  |  /
          一个内核线程 K
```

- 优点：创建/切换快（纯用户态），不依赖内核。
- 缺点：无法并行；一个阻塞全进程停。
- 应用：早期系统、某些协程方案（教科书举例：Green Threads 历史方案）。

### 3.2 one-to-one（一对一）

每个用户线程映射一个内核线程：

```
用户线程  U1  U2  U3
          |   |   |
内核线程  K1  K2  K3
```

- 优点：真正并行、一个阻塞不影响其他。
- 缺点：每线程一份内核资源（栈/PCB），创建开销大，线程数受内核限制。
- 应用：**Linux（NPTL）、Windows**。

### 3.3 many-to-many（多对多）

多个用户线程映射到**多个**内核线程，且内核线程数可小于用户线程数：

```
用户线程  U1  U2  U3  U4
          |\ /|   |
          K1 K2   K3     ← 内核线程池，数量动态调整
```

- 优点：兼顾并行与灵活性，阻塞只影响挂在同一内核线程上的用户线程。
- 缺点：实现复杂（两级调度）。
- 变体：**two-level model**（两级模型），允许某些线程独占一个内核线程。
- 应用：Solaris 经典实现，现代较少。

::: important 面试一句话
many-to-one 便宜但不能并行、阻塞传染；one-to-one 能并行但开销大；many-to-many 折中但复杂。Linux/Windows 用 one-to-one。
:::

## 4. 线程库

线程库给应用程序提供创建/管理线程的 API。三大流派：

### 4.1 POSIX Threads（Pthreads）

标准 C 线程 API，Linux/macOS 原生支持，定义在 `<pthread.h>`。

```c
#include <stdio.h>
#include <pthread.h>

void *worker(void *arg) {
    long id = (long)arg;
    printf("thread %ld running\n", id);
    return NULL;
}

int main(void) {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, worker, (void *)1);
    pthread_create(&t2, NULL, worker, (void *)2);
    pthread_join(t1, NULL);   /* 等 t1 结束并回收 */
    pthread_join(t2, NULL);
    return 0;
}
```

```bash
gcc -pthread -o pt pt.c && ./pt
# 输出（顺序不定）：
# thread 1 running
# thread 2 running
```

### 4.2 Java Threads

Java 线程由 JVM 管理，`Thread` 类或 `Runnable` 接口：

```java
public class Demo {
    public static void main(String[] args) {
        Thread t1 = new Thread(() -> System.out.println("t1 running"));
        Thread t2 = new Thread(() -> System.out.println("t2 running"));
        t1.start();  // start() 才新建线程，run() 只是普通方法
        t2.start();
    }
}
```

### 4.3 Python threading

```python
import threading

def worker(name):
    print(f"thread {name} running")

t1 = threading.Thread(target=worker, args=(1,))
t2 = threading.Thread(target=worker, args=(2,))
t1.start()
t2.start()
```

::: warning Python GIL 陷阱
CPython 解释器有 **GIL（全局解释器锁）**，同一时刻只有一个线程能执行 Python 字节码——所以 **CPU 密集型多线程**在 CPython 里不会并行加速。需要真并行要用 `multiprocessing` 或多进程。I/O 密集型场景 GIL 影响不大。这正是"线程库 ≠ 并行保证"的典型案例。
:::

## 5. Linux 的线程实现

### 5.1 clone() 与 NPTL

Linux 创建线程不走 `fork`，而是 `clone()` 系统调用，通过标志位控制**共享什么、不共享什么**：

```c
// 创建线程的本质：clone 时共享地址空间与文件表
clone(CLONE_VM | CLONE_FS | CLONE_FILES | CLONE_SIGHAND | CLONE_THREAD,
      stack_start, SIGCHLD, arg);
```

| 标志 | 共享的内容 |
|---|---|
| `CLONE_VM` | 共享地址空间（页表） |
| `CLONE_FILES` | 共享文件描述符表 |
| `CLONE_FS` | 共享工作目录、umask 等 |
| `CLONE_SIGHAND` | 共享信号处理器 |
| `CLONE_THREAD` | 同属一个线程组（tgid 相同） |

::: important 为什么说"线程 = 轻量级进程"
在 Linux 眼里，**线程和进程都是 task_struct**，唯一区别是共享哪些字段。`ps -eLf` 输出里每个线程一行，PID 列显示线程组 ID（tgid），LWP 列才是线程自己的 ID。内核调度单位就是这些 task_struct，所以 Linux 是 one-to-one 模型，天然支持多核并行。
:::

### 5.2 NPTL（Native POSIX Thread Library）

- Linux 的 pthread 实现，从 glibc 2.3 起默认。
- 核心：**1:1 内核线程**（每个 pthread 对应一个 task_struct）。
- 线程 ID 用 PID 空间（LWP），`gettid()` 获取。
- 引入 futex 等快速同步原语。

### 5.3 观察线程

```bash
ps -eLf | head                # NLWP=线程数，LWP=线程ID
#   UID  PID  PPID  LWP ...
pgrep -n bash                 # 找到 shell 的 PID
ls /proc/$(pgrep -n bash)/task   # task 目录里每个子目录 = 一个线程
cat /proc/$(pgrep -n bash)/status | grep -i threads
top -H -p &lt;PID&gt;               # 按线程查看 CPU 占用（top 按 H 切换线程视图）
```

## 6. 线程池与线程本地存储

### 6.1 线程池（Thread Pool）

**问题**：频繁 `pthread_create`/销毁很贵（每次都要建栈、建内核任务、走系统调用）。
**方案**：启动时创建固定数量的工作线程放池里，任务来了**投递到池**，空闲线程取任务执行。

| | 每请求建线程 | 线程池 |
|---|---|---|
| 创建开销 | 每次请求付一次 | 启动付一次 |
| 线程数 | 无上限，可能耗尽资源 | 固定，超载排队 |
| 响应性 | 创建延迟 | 立即执行 |
| 典型场景 | 低并发 | Web 服务器（Tomcat、nginx worker）、数据库连接池 |

```python
from concurrent.futures import ThreadPoolExecutor

def work(n):
    return n * n

with ThreadPoolExecutor(max_workers=4) as pool:   # 池固定 4 线程
    for r in pool.map(work, range(10)):
        print(r)
```

### 6.2 线程本地存储（Thread-Local Storage, TLS）

**问题**：进程内共享全局变量是线程间通信的便利，但有时需要"每个线程私有的全局变量"（如线程自己的缓存、错误码）。
**方案**：TLS —— 每个线程一份同名变量副本。

```c
// C11 或 GCC 扩展
_Thread_local int err;        // 每个线程独立的 err
// 或 pthread_key_create / __thread
static __thread int cache;    // GCC 语法
```

```python
import threading

local = threading.local()
def setter(v):
    local.val = v            # 每个线程各自的 val
```

**用途**：数据库连接（每线程一条连接）、随机数种子、日志上下文、错误状态。

::: tip 与同步的关系
TLS 避免了锁，但本质仍是"每个线程读写自己的副本"，与共享数据的同步是两条路：**共享数据要上锁，私有数据用 TLS 最干净**。
:::

## 7. 本章小结

- 线程是 CPU 调度基本单位，共享进程资源、独占栈与寄存器，切换/创建都比进程便宜。
- 三种映射模型：many-to-one（便宜但阻塞传染）、one-to-one（并行但贵）、many-to-many（折中但复杂）。
- 线程库三巨头：Pthreads（C）、Java Thread、Python threading（注意 GIL）。
- Linux 用 clone() 实现线程，NPTL 是 1:1 内核线程，线程 = 共享部分字段的 task_struct。
- 线程池控制并发规模，TLS 给每个线程私有副本，二者都是实战高频手段。

## 8. 自测题

1. **线程独有什么、共享什么？** 独占：线程 ID、PC、寄存器、栈；共享：地址空间（代码/数据/堆）、fd 表、信号处理器。
2. **为什么线程切换比进程切换快？** 同进程线程共享页表，切换不换地址空间、不刷 TLB，只需保存/恢复栈与寄存器。
3. **many-to-one 模型的致命缺点？** 无法利用多核并行；一个线程发起阻塞系统调用会阻塞整个进程的所有线程。
4. **Linux 用哪种映射模型？** one-to-one（NPTL：每个 pthread 对应一个内核线程/task_struct）。
5. **`pthread_join` 的作用？** 等待指定线程结束并回收其资源（类似进程的 wait）。
6. **Python 多线程为什么 CPU 密集不加速？** GIL 保证同时只有一个线程执行字节码，需用 multiprocessing 绕过。
7. **线程池的价值？** 复用线程、避免反复创建/销毁开销、限制并发规模防止资源耗尽。
8. **TLS 与锁的区别？** TLS 给每线程私有副本，无需同步；锁是多个线程共享同一份数据时的互斥手段。

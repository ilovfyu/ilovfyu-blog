::: abstract 本章定位
本目录回答操作系统最核心的问题：**谁来用 CPU、按什么顺序用 CPU、用 CPU 时共享哪些资源**。覆盖 Ch3 Processes（进程）、Ch4 Threads（线程）、Ch5 CPU Scheduling（CPU 调度）三章，从"进程是什么"一路讲到"多处理器与实时调度"，并全部落到 Linux 上可以观察、可以验证。
:::

进程与线程是理解操作系统的第一块地基：**进程是资源分配单位，线程是 CPU 调度单位**。搞不懂这两者的区别、状态怎么转换、调度算法怎么算等待时间，后面读内存、同步、死锁、文件系统都会处处卡壳。

## 2. 推荐学习顺序

```
01 进程概念与状态模型 ──→ 02 进程控制块与系统调用 ──→ 03 进程切换与调度行为
                                                    │
                                                    ▼
06 多处理器调度与实时调度 ◄── 05 CPU调度算法详解 ◄── 04 线程概念与多线程模型
```

1. **[进程概念与状态模型](/kb/os/进程线程/01-进程概念与状态模型/)**（先建直觉）：进程 = 正在运行的程序 + 它的资源。必须先理解状态机与 fork/exec，否则后续所有概念没有载体。
2. **[进程控制块与系统调用](/kb/os/进程线程/02-进程控制块与系统调用/)**（理解内核侧）：PCB 是内核管理进程的"档案袋"，系统调用是用户代码接触内核的唯一通道。
3. **[进程切换与调度行为](/kb/os/进程线程/03-进程切换与调度行为/)**（理解代价）：知道上下文切换为什么贵，才能理解为什么调度算法要"少换人"。
4. **[线程概念与多线程模型](/kb/os/进程线程/04-线程概念与多线程模型/)**（并行的来源）：进程管资源、线程管计算，现代系统几乎全靠线程。
5. **[CPU调度算法详解](/kb/os/进程线程/05-CPU调度算法详解/)**（核心考点）：算法本身很简单，难在手算。这一篇必须动手算。
6. **[多处理器调度与实时调度](/kb/os/进程线程/06-多处理器调度与实时调度/)**（现代拓展）：多核亲和性、RMS/EDF 可调度性测试，以及 Linux 的真实调度器 CFS。

## 3. 各章一句话介绍

- [进程概念与状态模型](/kb/os/进程线程/01-进程概念与状态模型/)——进程是执行中的程序，包含 text/data/heap/stack 四段内存布局；它在一套 5 状态状态机里流转，Linux 用 `ps STAT` 的 R/S/D/T/Z/I 字母对应这些状态；`fork()` 复制出子进程、`exec()` 换掉进程镜像。
- [进程控制块与系统调用](/kb/os/进程线程/02-进程控制块与系统调用/)——PCB 记录进程的全部元数据（PID/状态/寄存器/调度/内存/文件）；用户态用 trap 中断进入内核态执行系统调用；`fork/wait/exit` 全家桶配合使用，`fork` 靠写时复制（COW）偷懒。
- [进程切换与调度行为](/kb/os/进程线程/03-进程切换与调度行为/)——上下文切换要保存/恢复寄存器并清空缓存，是调度开销的主要来源；调度器维护 ready queue / device queue 两类队列，在 Linux 上可以用 `vmstat`、`time` 观察真实切换成本。
- [线程概念与多线程模型](/kb/os/进程线程/04-线程概念与多线程模型/)——线程是同一进程内的轻量执行流，共享地址空间所以切换便宜；用户级线程与内核级线程各有取舍，三种映射模型（many-to-one/one-to-one/many-to-many）决定了并发能力；Linux 用 `clone()` + NPTL 实现原生线程。
- [CPU调度算法详解](/kb/os/进程线程/05-CPU调度算法详解/)——五个经典算法各有性格：FCFS 公平但有护航效应，SJF 最优但不可实现，RR 保证响应但切换开销大，Priority 高效但会饿死低优先级，MLFQ 综合三者被现代系统广泛采用；手算甘特图与平均等待时间是面试硬通货。
- [多处理器调度与实时调度](/kb/os/进程线程/06-多处理器调度与实时调度/)——多核时代调度要考虑亲和性（cache 友好）与负载均衡；硬实时调度靠 RMS/EDF 的数学保证期限，可调度性测试只需算利用率；Linux 用 CFS（`SCHED_OTHER`）保证公平、`SCHED_FIFO`/`SCHED_RR` 提供实时优先级。

## 4. Linux 实验清单

::: warning 实验前提
以下命令在 Linux 上执行（macOS 的 `ps`/`top` 参数略有不同）。建议用 WSL2 或云主机。观察类命令不会破坏系统，`kill` 请只在测试进程上使用。
:::

```bash
# 1. 看进程树：谁是谁的父进程（1 号是 init/systemd）
pstree -p | head -30
ps -ef --forest

# 2. 看进程状态：STAT 列就是本文讲的 Linux 状态机
ps -eo pid,ppid,stat,comm --sort=-pid | head
#   R=running, S=interruptible sleep, D=uninterruptible, T=stopped,
#   Z=zombie, I=idle kernel thread, < = high priority, N = nice

# 3. 看内存布局与打开的文件
cat /proc/$$/maps          # 进程地址空间（text/data/heap/stack）
ls -l /proc/$$/fd          # 打开文件表
cat /proc/$$/status        # 含 State 字段

# 4. 交互式观察：top / htop
top -d 1                    # 按 P 按 CPU 排序，按 t 看 CPU 折线
htop                        # 进程树视图按 F5

# 5. 上下文切换与调度统计
vmstat 1 5                  # cs 列 = context switches/sec，r 列 = 就绪队列长度
pidstat -w 1                # 每个进程的上下文切换速率（cswch/s）
time sleep 5                # real/user/sys 三段时间，理解内核态耗时

# 6. 调度实验：nice/renice 改优先级
sleep 300 &
sudo renice -n -10 $!       # 调高优先级（负数更高）
ps -o pid,pri,ni,stat,comm -p $!
chrt -l                     # 查看可用调度策略（SCHED_OTHER/SCHED_FIFO/SCHED_RR）

# 7. 系统调用与 fork 观察
strace -f -e trace=fork,execve,wait4 -c bash -c 'echo hi'   # fork/exec/wait 次数
cat /proc/sys/kernel/pid_max

# 8. 线程观察：同一进程内的轻量级进程
ps -eLf | head              # NLWP 列 = 线程数；pid 是线程组，lwp 是线程
ls /proc/$(pgrep -n bash)/task   # 线程目录

# 9. 孤儿/僵尸制造（在终端 A 执行）：
sleep 1 &                   # 用脚本让子进程先死、父进程不回收
#   kill 掉父进程后，子进程被 1 号收养 = 孤儿进程；
#   子进程先 exit 而父进程不 wait，ps 里显示 &lt;defunct&gt; = 僵尸进程
```

## 6. 本章小结

进程与线程这一主题撑起了操作系统的半边天：**资源由进程持有，计算由线程执行，CPU 时间由调度器分配**。本目录六篇按"对象 → 内核机制 → 代价 → 并行 → 算法 → 现代扩展"递进，全部知识都可以在 Linux 上用 `ps`/`top`/`vmstat`/`strace` 亲眼看到。

## 7. 自测题

1. **进程和程序的核心区别是什么？** 进程是程序在内存中的一次执行实例，拥有地址空间和资源；程序是被动文件。同一程序可对应多个进程。
2. **进程状态机中，哪些状态转换是"主动"的？** 运行→等待（请求 I/O 主动让出 CPU）、运行→就绪（被抢占或被时钟中断）、运行→终止（exit）。
3. **僵尸进程如何产生、如何清除？** 子进程先 exit 且父进程不 wait；父进程调用 `wait()` 回收，或父进程死后僵尸交给 init 回收。
4. **fork() 后如何区分父进程和子进程？** 子进程 getpid 是自己、父进程返回子 PID；子进程 `getppid` 是父进程。通常用 `fork()` 返回值判断。
5. **为什么说上下文切换比系统调用贵？** 系统调用不换进程、不丢缓存；上下文切换要保存/恢复全套寄存器并冲刷 TLB/cache。
6. **线程为什么比进程切换快？** 线程共享地址空间与文件表，上下文切换只需保存线程私有上下文（栈、寄存器、程序计数器），不需要切换页表。
7. **MLFQ 如何解决低优先级饥饿？** 用老化/时间戳机制：在低优先级队列待得太久的进程会被提升到高优先级队列。
8. **Linux 的 `ps` 中 STAT 字母 D 和 Z 分别代表什么？** D = 不可中断睡眠（如等磁盘 I/O），Z = 僵尸（已退出未回收）。

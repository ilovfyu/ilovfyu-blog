::: abstract 本章定位
安全要防的威胁到底长什么样？本篇从"威胁分类 → 程序威胁 → 经典攻击技术"逐层展开：中断/窃取/修改/伪造四类，木马/后门/逻辑炸弹/蠕虫/病毒一张表分清，重点剖析**缓冲区溢出**的原理、示例与防御，再讲 SQL 注入、社会工程与资源耗尽（DoS）。对应教材 Ch17 Security 的威胁与攻击部分。
:::

要懂防御，先得懂攻击者。本篇是"攻击者视角"全集：**代码层面的漏洞利用（缓冲区溢出、SQL 注入）、人的漏洞（社会工程）、资源层面的轰炸（DoS）**。学完你应能：画出一张栈布局图解释溢出，说清四类威胁的差异，并对任意"漏洞新闻"自动归类。

## 1. 威胁与攻击分类

教材把威胁按对信息/系统的作用效果分为四大类：

| 类别 | 英文 | 本质 | 例子 |
|---|---|---|---|
| **中断** | Interruption | 系统/资源**不可用**（违背可用性） | DoS、切断电源、磁盘损坏 |
| **窃取** | Interception | 数据被**未授权者读走**（违背机密性） | 嗅探网络、偷读文件 |
| **修改** | Modification | 数据被**未授权者篡改**（违背完整性） | 修改配置、注入恶意数据 |
| **伪造** | Fabrication | **凭空制造**未授权的数据/身份（违背完整性与真实性） | 伪造消息、冒充他人登录 |

```
          正常数据流
  ┌────┐              ┌────┐
  │ Alice │ ──────────► │ Bob  │
  └────┘              └────┘
     │                  ▲
 中断│(数据到不了)    窃取│(数据被偷看)
     ▼                  │
  ┌────┐  修改(被改) / 伪造(凭空造) ──┐
  │ Mallory │ ◄────────────────────┘
  └────┘
```

::: important 一句记忆
中断伤可用性，窃取伤机密性，修改伤完整性，伪造伤真实性与完整性。分类的用处是：**每类威胁对应不同的防御侧重**（中断→冗余与抗 DDoS，窃取→加密，修改→完整性校验，伪造→认证与签名）。
:::

## 2. 程序威胁（Program Threats）

攻击者利用"看似合法运行的程序"实施破坏。五种经典程序威胁一张表分清：

| 威胁 | 中文 | 本质 | 传播/激活方式 | 例子 |
|---|---|---|---|---|
| **Trojan Horse** | 木马 | 伪装成有用软件的**恶意程序**，骗你主动运行 | 用户下载/点击运行 | 假"免费杀毒"实际偷密码 |
| **Backdoor / Trap Door** | 后门 | 程序里**预留的隐蔽入口**，绕过正常认证 | 由作者或漏洞留下，被秘密使用 | 登录认证后门、调试口 |
| **Logic Bomb** | 逻辑炸弹 | 满足**特定条件才引爆**的恶意代码 | 潜伏在正常程序内等待触发 | 员工离职触发删库 |
| **Worm** | 蠕虫 | 能**自我复制**并**主动传播**的独立程序 | 无需宿主文件，网络自动复制 | Morris Worm、WannaCry |
| **Virus** | 病毒 | 寄生在宿主文件/程序里，靠宿主传播 | 需宿主+用户运行触发 | 宏病毒、感染 PE 文件 |

::: tip 木马与病毒一句话区分
**病毒要"感染宿主"才能活，木马不感染宿主、只是骗你运行它**。蠕虫最危险——不依赖任何人执行，自动在网络里繁殖。
:::

补充两类常见威胁：

- **SQL 注入（SQL Injection）**：把恶意 SQL 拼接进用户输入，让数据库执行非预期操作（见第 4 节）。
- **目录遍历（Directory Traversal）**：用 `../` 越权读取任意文件（如 `../../../../etc/passwd`），本质是"路径参数未校验"。

## 3. 缓冲区溢出（Buffer Overflow）

缓冲区溢出是整个软件安全史上**最经典的漏洞类别**，CERT/CC 曾统计它占安全公告的半数以上。C 语言的手动内存管理 + 不检查越界 = 溢出土壤。

### 3.1 栈布局（Stack Layout）

函数调用时，栈从高地址向低地址增长，每次调用压入一个栈帧（stack frame）：

```
高地址
┌────────────────────┐
│  ...调用者局部变量...  │
├────────────────────┤
│ 参数 / 返回地址(RIP) │ ← 函数返回时跳转到这里
├────────────────────┤
│  保存的帧指针(EBP)   │
├────────────────────┤
│   局部变量 buf[]     │ ← 缓冲区在此，向高地址增长（越界写即往上）
├────────────────────┤
│  ...被调用者栈...    │
低地址
```

关键点：**C 数组向高地址方向增长，而返回地址恰好在缓冲区"上方"**。用 `strcpy(buf, input)` 且 input 比 buf 长，就会一路往上覆盖 EBP 和**返回地址**。

### 3.2 攻击原理（示例）

```c
#include <stdio.h>
#include <string.h>

void vuln(char *input) {
    char buf[8];                     // 8 字节缓冲
    strcpy(buf, input);              // 不检查长度！越界拷贝
    printf("OK\n");
}

int main(int argc, char **argv) {
    vuln(argv[1]);                   // 用户可控输入
    return 0;
}
```

```bash
# 正常输入
$ ./a.out "hello"            # buf = "hello"，无溢出
# 溢出输入：超过 8 字节，覆盖栈上返回地址
$ ./a.out "AAAAAAAAAAAAAAAAAAAAAAAAAAAA"
Segmentation fault           # 返回地址被破坏，程序崩溃
# 经典利用：精心构造 payload 使返回地址指向 shellcode
$ ./a.out "$(python3 -c 'print("\x90"*100 + shellcode + ret_addr)')"
$ # 函数返回时跳进 shellcode → 以程序权限执行 shell
```

攻击者注入一段 **shellcode**（如 `exec("/bin/sh")` 的机器码），再用精心计算的返回地址让 CPU 跳进去，就获得了**被攻击程序的权限**——若程序是 root 权限运行（如 setuid 程序），攻击者直接提权为 root。

### 3.3 防御手段（每层都真实存在）

| 防线 | 机制 | 作用 |
|---|---|---|
| **ASLR**（地址空间布局随机化） | 每次启动随机化栈/堆/库的基址 | 使攻击者无法预测 shellcode 地址 |
| **NX / DEP**（不可执行栈） | 栈内存标记为不可执行（`mprotect PROT_EXEC` 关掉） | 即便跳到栈上也无法执行 shellcode |
| **Stack Canary**（栈金丝雀） | 返回地址前插入随机哨兵值，返回前校验 | 溢出覆盖会破坏 canary，立即 abort |
| **安全编译选项** | 编译器自动插 canary + 加随机化（`-fstack-protector`、PIE） | 编译期就注入防御 |
| **安全函数** | 用 `strncpy`/`snprintf`/`memcpy_s` 替代不安全的 `strcpy`/`sprintf` | 从源头杜绝越界写 |
| **内存安全语言** | Rust / Go / Java（带 GC/边界检查） | 编译/运行时自动阻止溢出 |

::: warning 为什么漏洞至今存在
老代码（C/C++、内核驱动、嵌入式）不可能重写；`strcpy` 家族仍大量存在。所以现代加固 = 编译选项 + 运行时防护 + 代码审计三管齐下。**理解溢出，是理解 Linux 内核防护（KASLR、SMEP）的起点。**
:::

## 4. SQL 注入

把不可信输入直接拼进 SQL 语句，破坏数据库完整性甚至拿到数据。

```sql
-- 有漏洞的写法（字符串拼接用户输入）
SELECT * FROM users WHERE name = 'alice' AND password = 'wrong' OR '1'='1'
--                                    用户输入： wrong' OR '1'='1
-- 条件恒真 → 绕过认证，直接登录！
```

```python
# 错误写法
cursor.execute(f"SELECT * FROM users WHERE name = '{user}'")

# 正确写法：参数化查询（预编译，输入被当数据而非代码）
cursor.execute("SELECT * FROM users WHERE name = %s", (user,))
```

防御核心三条：**参数化查询/预编译**、**最小数据库权限**（应用账号只拥有所需权限）、**输入校验与转义**。

## 5. 社会工程（Social Engineering）

攻击者不攻技术，攻人——利用信任、恐惧、贪念让人交出信息或执行操作。人的漏洞永远存在，是最难修补的"漏洞"。

| 手段 | 手法 | 识别特征 |
|---|---|---|
| **钓鱼（Phishing）** | 假冒可信机构发链接/附件，骗账号密码 | 仿冒域名、急迫语气、陌生发件人 |
| **鱼叉式钓鱼** | 针对特定个人定制（如 CFO 的邮件） | 内容精准、了解你的背景 |
| **电话钓鱼（Vishing）** | 假冒客服/领导电话索要验证码 | 索要验证码、恐吓 |
| **诱饵（Baiting）** | 丢 U 盘/二维码引诱插入扫描 | 来历不明设备/二维码 |
| **伪装（Pretexting）** | 编造身份（IT 维修）套取信息 | 要求提供凭据/重设密码 |

::: tip 反社会工程的三不原则
**不点可疑链接、不透露验证码、不做"帮忙重设密码"。** 系统能防住技术漏洞，人的环节靠培训与流程（双人复核、审批流）。
:::

## 6. 资源耗尽与拒绝服务（DoS）

**拒绝服务攻击（DoS / Distributed DoS）** 的目标是中断可用性——让服务崩溃或不可响应。本质是"资源有限，攻击者让你耗尽"。

| 攻击 | 原理 | 特征/防御 |
|---|---|---|
| **SYN Flood** | 发送大量只发 SYN 不完成三次握手的连接，塞满内核的半连接队列（SYN backlog） | 服务器不再响应新连接；用 SYN cookie、缩短超时、防火墙限速 |
| **ICMP 洪水** | 海量 Ping 报文耗尽带宽/CPU | 限速、关闭 echo |
| **放大攻击（Amplification）** | 用伪造源地址向 DNS/NTP 反射，小请求→大响应打到受害者 | 关闭开放递归、BCP38 源地址过滤 |
| **应用层慢攻击** | 慢速建立无数低速率连接占满连接池 | WAF、连接超时与频率限制 |

### fork 炸弹（示例：资源耗尽的本机版）

```bash
:(){ :|:& };:    # 经典 fork bomb（冒号函数递归派生进程）
```

一行就递归创建无限子进程，直到耗尽 PID 与内存。真实系统对此的防线：**每进程进程数限制（`ulimit -u`）、cgroup、容器限流**。这正是容器时代用 cgroup 限制资源的意义所在。

```
正常：Client ──SYN──► Server   Server ──SYN+ACK──► Client   Client ──ACK──► 建立
SYN flood：Mallory ──SYN(伪造IP)──► 疯狂塞满 Server 的半连接表 → 合法用户连不进来
```

## 7. 常见攻击面（Attack Surface）

攻击面 = 所有"攻击者可能触及的入口"。系统加固的第一步是**摸清自己的攻击面**：

| 类别 | 攻击面 | 说明 |
|---|---|---|
| 网络 | 开放端口、服务、协议 | 每个监听端口都是一个门（`ss -tlnp` 检查） |
| 应用 | Web 接口、上传、命令注入、反序列化 | 参数没校验就进系统 |
| 认证 | 弱口令、无 2FA、会话固定 | 最容易突破的环节 |
| 系统 | setuid 程序、内核模块、错误配置 | 提权路径 |
| 供应链 | 依赖库、镜像、更新源 | 第三方代码里藏后门（近年高危趋势） |
| 人 | 钓鱼、社会工程、误操作 | 永远存在的开口 |

::: warning 攻击面最小化原则
不需要的服务就关掉，不需要的端口就不监听，不需要的权限就不给。**攻击面越小，被攻破的数学期望越低。** 这与后一篇的最小权限/纵深防御一脉相承。
:::

## 本章小结

1. **威胁四分类**：中断（可用性）/ 窃取（机密性）/ 修改（完整性）/ 伪造（真实性与完整性），每类对应不同防御。
2. **程序威胁**：木马骗运行、后门藏入口、逻辑炸弹等条件、病毒靠宿主、蠕虫自传播。
3. **缓冲区溢出**：越界写覆盖返回地址→跳转 shellcode 提权；ASLR+NX+Canary+安全函数+内存安全语言层层防御。
4. **SQL 注入**：参数化查询是根治；**社会工程**：技术防不住人，靠意识与流程。
5. **资源耗尽**：SYN flood、放大攻击、fork bomb，靠限流、超时、cgroup 兜底。
6. **攻击面最小化**是加固的第一原则，也是通往防御篇（[安全防御与审计](/kb/os/安全/05-安全防御与审计/)）的桥梁。

## 自测题

1. **中断、窃取、修改、伪造分别违背哪一 CIA 属性？**
   > 中断→可用性，窃取→机密性，修改→完整性，伪造→真实性与完整性。

2. **病毒、蠕虫、木马三者传播方式的核心差异？**
   > 病毒需感染宿主文件并靠人运行；蠕虫独立程序、网络自动复制；木马不感染、骗用户主动运行。

3. **画一下栈帧布局，说明为什么缓冲区越界能控制执行流。**
   > 栈帧内局部变量在低地址、返回地址在高地址，C 数组向高地址增长，越界写先盖 EBP 再盖返回地址，函数返回时跳转到攻击者指定位置。

4. **栈溢出防御的 ASLR 和 NX 分别防什么？**
   > ASLR 随机化地址使攻击者无法预知 shellcode 落点；NX 把栈标为不可执行，即使跳进去也执行不了。

5. **SQL 注入的根治方案是什么？**
   > 参数化查询/预编译，把输入当数据而非 SQL 代码；配合最小数据库权限与输入校验。

6. **SYN flood 为什么能让服务器拒绝服务？**
   > 海量不完成的握手请求塞满半连接队列（SYN backlog），合法新连接无法入队，服务不可用。

7. **fork 炸弹为什么需要 cgroup/ulimit 才能防住？**
   > 递归派生进程会指数增长，单靠人工杀进程赶不上；需预先用 `ulimit -u` 或 cgroup 限制每进程可建子进程数。

8. **"攻击面最小化"在 Linux 上对应哪些具体动作？**
   > 关闭未用服务与端口（`ss -tlnp` 检查）、移除不必要的 setuid 程序、收紧 sudoers、审计监听端口与 cron 任务。

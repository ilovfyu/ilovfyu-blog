::: abstract 本章定位
本目录回答操作系统层面最"对抗"的问题：**谁在用什么权限访问什么资源，以及如何阻止坏人破坏它**。覆盖 Ch16 Protection（保护机制）与 Ch17 Security（安全防护）两章，从访问控制矩阵一路讲到缓冲区溢出、Rootkit、纵深防御与审计，并全部落到 Linux 上可以动手验证。
:::

保护（Protection）与安全（Security）是一枚硬币的两面：**保护是操作系统对内部"合法用户"之间的访问控制**（谁可以用这个文件），**安全是对外部"恶意主体"的攻防对抗**（入侵者怎么进来、我们怎么挡住）。前者是规则，后者是战争。搞懂这两块，再看数据库权限、Docker 容器、K8s RBAC、Web 认证都会一通百通。

01 保护机制与访问控制 ──→ 02 身份认证与密码学基础 ──→ 03 系统安全威胁与攻击
        │                                                        │
        ▼                                                        ▼

1. **[保护机制与访问控制](/kb/os/安全/01-保护机制与访问控制/)**（先建地基）：访问矩阵是整套权限理论的骨架，ACL vs Capability 是贯穿操作系统、数据库、云平台的通用思维模型。Linux 的 `rwx`、`setuid`、`sticky bit` 全部是它的实例化。
2. **[身份认证与密码学基础](/kb/os/安全/02-身份认证与密码学基础/)**（理解的钥匙）：密码学是安全的"数学内核"。不懂哈希与公私钥，后面 TLS、磁盘加密、签名全都看不懂。这篇概念多，但不求掌握算法细节，重在"能分清各种加密手段各解决什么问题"。
3. **[系统安全威胁与攻击](/kb/os/安全/03-系统安全威胁与攻击/)**（理解对手）：缓冲区溢出是理解安全必须亲手写一遍的攻击。这篇把"攻击者视角"打开，后面的防御才有针对性。
4. **[恶意软件与网络攻击](/kb/os/安全/04-恶意软件与网络攻击/)**（攻防实战）：病毒、Rootkit、MITM、钓鱼——把恶意软件分类搞清，再对齐防火墙/IDS 的防御原理。
5. **[安全防御与审计](/kb/os/安全/05-安全防御与审计/)**（落地成体系）：最小权限、纵深防御、SELinux、auditd、AIDE 把这些概念收拢成一套可以照做的加固清单。

面试速成看 01 + 03 + 05（访问控制、缓冲区溢出、纵深防御是高频考点）。系统性学习建议 5 篇全读，每篇都动手做实验清单——安全是最"纸上得来终觉浅"的领域。

## 3. 各篇一句话介绍

- [保护机制与访问控制](/kb/os/安全/01-保护机制与访问控制/)——保护关注"合法用户之间的资源隔离"：访问矩阵用"主体×客体→权限"描述所有授权关系，ACL 挂在客体上、Capability 挂在主体手上，两者撤销权限的代价完全不同；Linux 的 owner/group/other、rwx、sticky bit、setuid 就是这个模型的具体实现。
- [身份认证与密码学基础](/kb/os/安全/02-身份认证与密码学基础/)——认证回答"你是谁"（你知道/你拥有/你是什么三要素），密码用"盐+哈希"存储杜绝彩虹表；对称加密（AES）快、非对称加密（RSA/ECC）能安全分发密钥，二者结合就是 TLS；哈希与数字签名分别保证完整性与"确实是你签的"。
- [系统安全威胁与攻击](/kb/os/安全/03-系统安全威胁与攻击/)——威胁分为中断/窃取/修改/伪造四类；程序威胁里木马骗你运行、后门留后路、病毒靠宿主文件传播、蠕虫自我复制；缓冲区溢出靠覆盖返回地址劫持控制流，是"写烂代码的代价"的最佳反面教材。
- [恶意软件与网络攻击](/kb/os/安全/04-恶意软件与网络攻击/)——病毒/蠕虫/木马/勒索软件在"传播方式"上泾渭分明；Rootkit 钻进内核后用内核模块隐藏自己；MITM 站在通信中间冒充双方，重放攻击把截获的合法消息再发一遍；对付它们靠最小权限、纵深防御、白名单。
- [安全防御与审计](/kb/os/安全/05-安全防御与审计/)——防御是系统工程：最小权限 + 纵深防御 + 内核安全机制（capabilities/SELinux/seccomp/namespaces）层层设卡；auditd 记录"谁在何时碰了什么"，AIDE 用哈希基线发现文件被篡改；出事后的响应流程与加固清单就是安全运营的 SOP。

## 4. Linux 实验清单

::: warning 实验前提
以下命令在 Linux 上执行（macOS 的部分命令参数不同，建议用 WSL2 或云主机）。带 `sudo` 的改动类命令请只在测试机器上执行，不要在生产环境随便 `setcap` 或改 sudoers。
:::

```bash
# 1. ACL 读写（文件系统需支持，ext4/xfs 默认支持）
getfacl /etc/passwd                 # 查看 ACL 条目
setfacl -m u:alice:rw secret.txt    # 给 alice 加读写权限
setfacl -x u:alice secret.txt       # 删除该条目
# 注意：ACL 条目会让 ls -l 权限位尾部出现 '+'

# 2. 传统权限与特殊位
chmod 755 script.sh                 # rwxr-xr-x
chown -R root:admin /srv/app        # 改属主/属组
chmod +t /tmp                       # sticky bit：只允许文件主/root 删除
chmod u+s /usr/bin/passwd           # setuid：以属主身份执行（passwd 本就如此）
ls -l /usr/bin/passwd               # 应看到 -rwsr-xr-x 的 's'

# 3. capabilities（setuid 的现代替代）
getcap /usr/bin/ping                # 查看能力位：cap_net_raw=ep
sudo setcap cap_net_raw=ep /tmp/myping   # 给指定程序授网络能力
# 相比 setuid，capability 只给"最小所需"，不给 root 全部权力

# 4. openssl 加密与哈希
echo -n "hello" | sha256sum         # 哈希：固定 64 位十六进制
openssl rand -base64 32             # 生成 32 字节随机数（可作 salt）
echo -n "secret" | openssl dgst -sha256 -hmac "key"   # HMAC 消息认证码
openssl genrsa -out key.pem 2048    # 生成 RSA 私钥
openssl rsa -in key.pem -pubout -out pub.pem          # 导出公钥
# 用公钥加密、私钥解密，验证非对称加密流程

# 5. 磁盘加密（LUKS，需要 root + 磁盘）
sudo cryptsetup luksFormat /dev/sdX  # 初始化 LUKS 分区
sudo cryptsetup open /dev/sdX luks  # 打开映射为 /dev/mapper/luks
sudo mkfs.ext4 /dev/mapper/luks     # 在加密层上建文件系统

# 6. 审计日志（auditd）
sudo auditctl -w /etc/passwd -p wa -k passwd_watch   # 监视文件写访问
sudo ausearch -k passwd_watch        # 检索相关审计记录
sudo tail -f /var/log/audit/audit.log

# 7. sudoers（只读安全编辑）
sudo visudo                          # 语法检查后保存
# 给 alice 免密 sudo 执行某命令：
#   alice ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart nginx

# 8. 解读 ls -l 权限位
# -rwxr-xr-x  1 root root  220  /etc/passwd
#   ^     ^    ^  ^    ^
#  类型  rwx 硬链接 属主 属组
#  rwx: owner / r-x: group / r-x: other；首字符 - 为普通文件，d=目录，l=符号链接
#  目录的 r=可列出，w=可增删条目，x=可进入
```

## 本章小结

安全与保护 = **授权模型（谁碰什么）× 认证手段（确认是谁）× 威胁认知（谁在攻击）× 防御体系（怎么挡住）× 审计闭环（事后追责）**。五篇笔记严格按这个逻辑链展开：01 讲授权、02 讲认证、03 讲威胁、04 讲恶意软件与网络攻防、05 讲防御与审计。学完之后，你应该能不看资料画出访问矩阵、写一段能触发缓冲区溢出的 C 代码、说出密码加盐的理由、并给一台 Linux 服务器列出十条加固措施。

## 自测题

1. **访问矩阵的每一行和每一列分别对应什么实现方式？**
   > 行→主体，基于行实现为 Capability List（挂在主体手上）；列→客体，基于列实现为 ACL（挂在客体上）。

2. **为什么 ACL 撤销权限比 Capability 容易？**
   > ACL 存在客体上，改一处即全局生效；Capability 存在各主体手上，必须逐个回收或引入间接层（如对象服务器）才可撤销。

3. **密码为什么不能直接存哈希，而要加盐哈希？**
   > 无盐时相同的密码产生相同哈希，可被彩虹表反查；盐让每个用户哈希不同，且计算量大增，彩虹表失效。

4. **对称加密和非对称加密各自解决什么问题？**
   > 对称（AES）解决"高效加密"但需要共享密钥；非对称（RSA/ECC）解决"不共享密钥也能安全交换"但慢；TLS 用非对称交换会话密钥、对称加密数据。

5. **缓冲区溢出攻击的核心原理一句话是什么？**
   > 向固定大小的栈缓冲区写入超出长度的数据，覆盖相邻的返回地址，使函数返回时跳转到攻击者注入的 shellcode。

6. **病毒和蠕虫的最大区别是什么？**
   > 病毒需要附着在宿主程序上并靠"人运行宿主"传播；蠕虫是独立程序，通过网络自动复制传播，无需宿主。

7. **SELinux 和普通 Linux rwx 权限有什么本质不同？**
   > rwx 是 DAC（所有者自主决定）；SELinux 是 MAC（系统策略强制），即使文件所有者也不能违反既定安全策略。

8. **纵深防御为什么有效？**
   > 单层防线总会被攻破，纵深防御让攻击者必须同时绕过多层独立的防线，单点失效不至于全盘沦陷，为检测与响应争取时间。

::: abstract 本章定位
上一篇讲"攻击技术"，本篇讲"恶意代码与网络层面的攻防"：病毒/蠕虫/木马/勒索软件/间谍软件的传播对比、藏在内核的 Rootkit、中间人攻击 MITM、重放攻击、身份伪造与钓鱼，最后收拢到防火墙 / IDS / IPS 与核心防范原则。对应教材 Ch17 Security 的恶意软件与网络攻击部分。
:::

恶意软件（Malware，malicious software）是"代码化的攻击者"，网络攻击是"协议化的攻击者"。本篇要建立的思维是：**每种恶意软件都有独特的传播与驻留方式，每种网络攻击都针对协议的一个薄弱环节**。理解了传播与驻留，就知道该在哪个环节设防。

## 1. 恶意代码分类与传播对比

| 恶意代码 | 中文 | 是否需要宿主 | 如何传播 | 主要目的 | 典型特征 |
|---|---|---|---|---|---|
| **Virus** | 病毒 | 需要（寄生于宿主文件） | 感染宿主→人运行宿主 | 破坏/驻留/扩散 | 自我复制、依赖宿主文件 |
| **Worm** | 蠕虫 | 不需要（独立程序） | 通过网络自动复制 | 大规模扩散、DDoS 跳板 | 无宿主、自动传播、可打补丁前横扫 |
| **Trojan Horse** | 木马 | 不需要 | 伪装诱骗用户运行 | 后门、窃密、远控 | 披着合法软件的外衣 |
| **Ransomware** | 勒索软件 | 不需要（通常伪装） | 邮件附件、漏洞、钓鱼 | 加密数据勒索赎金 | 加密文件+勒索通知、常与蠕虫结合 |
| **Spyware / Adware** | 间谍软件/广告软件 | 常寄生 | 捆绑安装、网页挂马 | 窃取隐私、弹广告 | 后台静默收集、难察觉 |
| **Keylogger** | 键盘记录器 | 常寄生 | 捆绑/钓鱼 | 窃取键盘输入（密码） | 记录击键并回传 |
| **Rootkit** | 内核级后门 | 需高权限安装 | 利用漏洞提权后植入 | 隐藏自身与其他恶意软件 | 篡改内核/系统调用、隐蔽性最强 |

::: tip 病毒 vs 蠕虫的判定口诀
**需要宿主 = 病毒，不需要宿主 = 蠕虫。** 蠕虫是"病毒的网络版"，且能自动传播（无需用户点击），破坏半径大得多（WannaCry 一天内席卷全球就是蠕虫+勒索的组合）。
:::

```
恶意软件传染链（示意图）：
  钓鱼邮件 ──► 用户点击附件（木马/勒索）          ← 人为触发
  端口扫描 ──► 发现未打补丁服务 ──► 蠕虫利用漏洞自动复制 ──► 感染局域网 ──► 继续扫描
  合法软件 ──► 捆绑间谍软件 ──► 后台窃密
```

## 2. Rootkit 与内核模块

**Rootkit** 是一类特殊的恶意软件——它的目的是**隐藏自己**（以及它携带的其他恶意负载），让系统管理员和杀毒软件看不到它。最恶毒的 Rootkit 直接住在**内核层**。

### 2.1 Rootkit 藏在哪

| 层级 | 手法 | 对抗方式 |
|---|---|---|
| 应用层 | 替换 `ps`/`ls`/`netstat` 等工具 | 用无修改的系统工具或内存比对 |
| 库层 | 劫持 libc 库函数 | 校验库文件哈希 |
| **内核层** | 安装恶意**内核模块（LKM）**，hook 系统调用表 | 签名校验模块、`lsmod`、内核只读页保护 |
| 固件/Boot | 篡改引导程序 | UEFI Secure Boot |

### 2.2 内核 Rootkit 的技术原理

现代内核 Rootkit 通过 hook 系统调用（system call）让"恶意进程"对上层完全隐形：

```
用户程序调用 read()/getdents()（列目录）
        │
        ▼
   系统调用表（sys_call_table）
        │
   ┌────┴────┐
   │ 恶意 hook │  ← Rootkit 修改此表项，把合法函数替换成自己的
   └────┬────┘
        ▼
   原始内核函数：返回目录列表前，先把恶意文件的条目删掉
```

这样 `ls`、`ps`、`ss` 都"看不到"恶意进程和文件——管理员以为系统是干净的。防御要点：

- **模块签名强制**：只允许加载被签名密钥签名的内核模块（`module.sig_enforce`）。
- **内核完整性检查**：Linux 的 `lockdown` 模式、内核页只读保护（`CONFIG_STRICT_KERNEL_RWX`）。
- **运行时检测**：内存扫描比对 sys_call_table、检测挂钩点（如使用 Kprobes/LSMs 的白名单）。

::: warning Rootkit 与容器安全
容器逃逸的第一步往往就是向宿主内核植入模块。所以生产环境强制**只读挂载内核模块、开启模块签名校验、关闭自动加载**，这正是 [安全防御与审计](/kb/os/安全/05-安全防御与审计/) 中内核加固的内容。
:::

## 3. 中间人攻击（MITM）

**中间人攻击（Man-in-the-Middle）**：攻击者坐在通信双方之间，同时冒充双方——分别与 Alice、与 Bob 建立自己的连接，把双方的消息转发（可看、可改）给另一方。

```
正常： Alice ◄──加密──► Bob
MITM： Alice ◄──加密1──► Mallory ◄──加密2──► Bob
      （Alice 以为在跟 Bob 说话，Bob 以为在跟 Alice 说话，其实都在跟 Mallory 说话）
```

### 3.1 常见实现手段

| 手段 | 原理 | 场景 |
|---|---|---|
| ARP 欺骗 | 伪造 ARP 响应，让交换机把包发到攻击者 | 局域网内嗅探 |
| DNS 欺骗/劫持 | 篡改 DNS 解析结果，把域名指到攻击者 IP | 钓鱼、证书绕过 |
| Wi-Fi 假基站 | 部署同名热点诱导接入 | 公共场所蹭网 |
| SSL 剥离 | 把 HTTPS 降级为 HTTP 再窃听 | 用户不细看地址栏时 |

### 3.2 防御本质：端点认证

MITM 之所以能成功，是因为受害者**无法确认对方真的是对方**。破解之道就是 [身份认证与密码学基础](/kb/os/安全/02-身份认证与密码学基础/) 里的**数字证书 + 公钥体系**：

- TLS/HTTPS 用证书让客户端验证服务器身份，用签名让服务器验证客户端。
- 密码学上保证"密钥只在你和真正的对方之间"——即使流量被转发，攻击者没有私钥也读不懂内容。
- 用户侧：**检查证书是否受信、检查域名、HSTS 强制 HTTPS、不使用可疑 Wi-Fi**。

::: important MITM 的一句话答案
中间人攻击的根本漏洞是**缺乏端点认证**，根治手段是**用证书/公钥做双向身份验证**，而非单纯加密——加密只能防窃听，防不了"加密通道的另一端是攻击者"。
:::

## 4. 重放攻击（Replay Attack）

**重放攻击**：截获一条合法消息（如认证请求、转账指令），**原样再发一次**，让接收方误以为是新请求。攻击者不需要破解密码，只需要"复读"。

```
Alice ──认证请求 + 时间戳1──► 服务器（通过）
Mallory 截获请求
Mallory ──原样重放请求──► 服务器（再次通过！）  ← 如果请求本身有效，就被接受了
```

防御手段：

| 防御 | 原理 |
|---|---|
| **Nonce（一次性随机数）** | 每条消息带随机 nonce，服务器记录已用 nonce，重复即拒绝 |
| **时间戳 + 有效期** | 消息带时间戳，超过有效期（如 5 分钟）拒绝 |
| **序列号** | 每条消息递增序列号，乱序/重复拒绝 |
| **挑战-应答（Challenge-Response）** | 服务器发随机挑战，客户端用密钥加密应答，攻击者无法预录"有效应答" |

## 5. 身份伪造与欺骗（Spoofing）

**Spoofing** = 伪造来源身份，让接收方以为消息来自可信方。

| 类型 | 原理 | 防御 |
|---|---|---|
| IP 欺骗 | 伪造源 IP（如 BCP38 要求网关过滤不可信源地址） | 入口过滤（BCP38）、TCP 握手等依赖源地址的可信验证 |
| 电子邮件欺骗 | 伪造发件人地址 | SPF / DKIM / DMARC（验证邮件域名与签名） |
| ARP/DNS 欺骗 | 见 MITM 表 | ARP 静态表、DNSSEC、加密 DNS |
| MAC 欺骗 | 伪造 MAC 绕过接入认证 | 802.1X、端口安全 |

## 6. 钓鱼（Phishing）与凭证窃取

钓鱼是社会工程的"网络化形态"（见 [系统安全威胁与攻击](/kb/os/安全/03-系统安全威胁与攻击/) 第 5 节），目标直指**凭证**。近年主流手法：

- **钓鱼邮件 + 仿冒登录页**：骗取用户名密码。
- **钓鱼短信/二维码**：诱导扫码授权。
- **水坑攻击**：污染目标常访问的网站。
- **凭证填充（Credential Stuffing）**：用已泄露密码库批量试登录——**所以密码复用是最大的自我风险**。

::: tip 防钓鱼的三个硬措施
1. 关键系统一律 **MFA**（被盗密码不够用）；
2. 邮件启用 **SPF/DKIM/DMARC** 并配置反钓鱼网关；
3. 用户教育与**不点不明链接**，任何"紧急重设密码"都走独立可信通道核实。
:::

## 7. 网络防御：防火墙、IDS、IPS

### 7.1 防火墙（Firewall）

**防火墙**是网络边界上按规则放行/拦截流量的设备，依据来源、目的、端口、协议做静态决策。

| 类型 | 工作层次 | 特点 |
|---|---|---|
| 包过滤防火墙 | 网络/传输层（IP/端口） | 快，但不懂应用层内容 |
| 状态检测防火墙 | 网络/传输层 + 连接状态 | 记住 TCP 连接状态，只放行属于已有连接的回包 |
| 应用层防火墙 / WAF | 应用层（HTTP 等） | 能识破 SQL 注入、XSS 等应用攻击 |

```
Linux 实用示例（nftables/iptables 思想）：
  # 只允许 22、80、443 进入，其余默认丢弃
  iptables -P INPUT DROP
  iptables -A INPUT -p tcp --dport 22  -j ACCEPT
  iptables -A INPUT -p tcp --dport 80  -j ACCEPT
  iptables -A INPUT -p tcp --dport 443 -j ACCEPT
```

### 7.2 IDS 与 IPS

防火墙是"闸门"，IDS/IPS 是"哨兵"——**检测已知攻击模式（特征/签名）与异常行为**。

| 系统 | 中文 | 动作 | 例子 |
|---|---|---|---|
| **IDS**（Intrusion Detection System） | 入侵检测 | **检测+告警**，不阻断 | Snort（规则告警）、Suricata |
| **IPS**（Intrusion Prevention System） | 入侵防御 | **检测+阻断** | 在 IDS 基础上主动丢弃攻击流量 |
| HIDS | 主机入侵检测 | 检测单机上的异常（文件/进程/审计） | OSSEC、Wazuh、AIDE（见防御篇） |
| NIDS | 网络入侵检测 | 旁路检测网络流量 | Snort 部署在镜像端口 |

### 7.3 部署分层

```
              ┌──────────────┐
  Internet ──►│ 边界防火墙/IPS │──► DMZ（Web 服务器）
              └──────────────┘
                     │
              ┌──────┴──────┐
              │ 内部防火墙   │
              └──────┬──────┘
                     ▼
              ┌──────────────┐
              │ 内网 + 主机 HIDS │
              └──────────────┘
```

## 8. 防范原则（贯穿全篇）

| 原则 | 含义 | 在本篇的体现 |
|---|---|---|
| **最小权限（Least Privilege）** | 只授予完成任务所需的最小权限 | 应用账号不用 root、防火墙只开必要端口、模块签名控制加载 |
| **纵深防御（Defense in Depth）** | 多层独立防线，单层失效不致命 | 防火墙 + IDS + HIDS + 加密 + 审计 层层设卡 |
| **白名单（Whitelist）** | 默认拒绝、显式允许 | 防火墙默认 DROP、容器 seccomp 白名单、模块签名 |
| **默认安全（Fail-Safe Defaults）** | 配置错误时拒绝而非放行 | 新装系统默认关端口、SELinux enforcing |
| **攻击面最小化** | 少一个入口少一份风险 | 关闭无用服务与端口、移除 setuid 程序 |

::: important 白名单 vs 黑名单
黑名单（拒已知恶意）永远追不上新攻击；**白名单（默认拒绝+显式允许）** 从结构上限制了未知攻击。安全设计优先白名单思维。
:::

## 本章小结

1. **恶意软件分类的关键维度是传播与宿主**：病毒需宿主、蠕虫自复制、木马骗运行、勒索加密换钱、间谍/键盘记录器静默窃密。
2. **Rootkit 住内核**，hook 系统调用表隐藏恶意活动，靠模块签名 + 内核只读保护防御。
3. **MITM 的本质是缺端点认证**，根治靠证书/公钥双向验证；**重放攻击靠 nonce/时间戳/挑战应答**防"复读"。
4. **身份伪造**在 IP/邮件/ARP/DNS 各层都存在，分别用源过滤、SPF/DKIM/DMARC、DNSSEC 对抗。
5. **网络防御分层**：防火墙管"闸门"，IDS 管"告警"，IPS 管"阻断"，HIDS 管"单机"。
6. **贯穿一切的原则**：最小权限、纵深防御、白名单、默认拒绝。

## 自测题

1. **病毒、蠕虫、木马、勒索软件的传播差异一句话各是什么？**
   > 病毒感染宿主文件靠人运行传播；蠕虫独立网络自动复制；木马伪装诱骗用户运行；勒索软件常靠邮件附件或漏洞批量投放、以加密数据勒索。

2. **内核 Rootkit 为什么难发现？防御靠什么？**
   > 它 hook 系统调用让 `ps`/`ls` 等命令看不到恶意进程文件，管理员"查不出来"；防御靠内核模块签名校验、内核内存只读保护与完整性检测。

3. **MITM 为什么加密了还能被攻破？**
   > 攻击者分别与两端建立加密连接，充当"透明的中间人"；加密只防窃听不防冒充，必须用证书/签名确认"另一端是本人"。

4. **重放攻击为什么不需要破解密码？怎么防？**
   > 因为合法消息本身有效，只需原样重发；用 nonce、时间戳、序列号或挑战-应答使旧消息失效。

5. **防火墙、IDS、IPS 的分工是什么？**
   > 防火墙按规则在边界过滤流量；IDS 检测并告警；IPS 在 IDS 基础上主动阻断攻击流量；HIDS 负责单机内检测。

6. **为什么说白名单优于黑名单？**
   > 黑名单只防已知恶意、总有漏网；白名单默认拒绝、显式允许，从结构上限制了未知与未来的攻击。

7. **SPF/DKIM/DMARC 各自解决邮件伪造的什么问题？**
   > SPF 校验发件 IP 是否被授权；DKIM 用签名验证内容与域名；DMARC 规定验证失败时的处理策略，三者合起来抑制邮件伪造。

8. **纵深防御为什么能在恶意软件面前争取时间？**
   > 攻击者必须同时突破网络防火墙、主机防护、权限隔离、审计告警多层独立防线，任一单点被突破不至于立刻全盘沦陷，为检测与响应留出窗口。

::: abstract 本章定位
从这一章开始进入文件系统。本章回答"文件对用户和程序员长什么样"：文件的属性、常用操作与访问方法，目录如何组织成树，挂载如何把多个文件系统拼起来，硬链接与软链接的本质区别，以及 Linux 的权限模型。对应教材 Ch13 File-System Interface。
:::

## 1. 文件概念与属性

### 1.1 什么是文件

**文件（file）** 是操作系统向用户提供的最小持久化存储抽象：一个**命名的字节序列**。对用户而言，文件就是"能存下来的数据集合"；对 OS 而言，文件被映射到磁盘上的一组块（块的分配方式见 [文件系统实现](/kb/os/存储/04-文件系统实现/)）。

```text
用户视角:    file = 名称 + 内容（字节流）
OS 内部:     file = inode（元数据）+ 一组数据块
```

### 1.2 文件的属性（元数据）

| 属性 | 英文 | 含义 |
|---|---|---|
| 名称 | name | 用户可见的文件名（目录项里存，不在 inode 里） |
| 标识符 | identifier | OS 内部唯一 ID（Linux 就是 inode 号） |
| 类型 | type | 普通文件、目录、设备、套接字、链接等 |
| 位置 | location | 指向数据在磁盘上的位置（inode 数据块指针） |
| 大小 | size | 字节数 |
| 保护 | protection | 谁能读写执行（rwx 权限） |
| 时间戳 | time | 创建、修改、访问时间（atime/mtime/ctime） |

::: tip 在 Linux 里看全部属性

:::```bash
> stat /etc/hosts
> # 输出包含: inode 号、Size、Blocks、Access/Modify/Change 时间、UID/GID、权限
> ls -li /etc/hosts   # -i 显示 inode 号
> ```

::: important inode 里**没有文件名**
文件名只存在于**目录项**里（目录也是一个文件）。所以"重命名文件"只是改目录项，inode 不变——这也是 `mv` 几乎瞬间完成的原因。
:::

## 2. 文件操作

### 2.1 基本操作清单

| 操作 | 系统调用（Linux） | 作用 |
|---|---|---|
| 创建 | `open(O_CREAT)` | 分配 inode + 在目录中登记目录项 |
| 删除 | `unlink()` | 删除目录项、inode 引用减一；无人引用则释放空间 |
| 打开 | `open()` | 建立文件与进程的关联，返回文件描述符（fd） |
| 关闭 | `close()` | 释放 fd 与打开文件表项 |
| 读 | `read(fd, buf, n)` | 从当前偏移读 n 字节到缓冲区 |
| 写 | `write(fd, buf, n)` | 从当前偏移写 n 字节 |
| 定位 | `lseek(fd, offset, whence)` | 改变文件位置指针（文件偏移） |
| 截断 | `ftruncate()` | 调整文件大小 |

### 2.2 打开文件机制（重点）

打开文件时，内核维护 **打开文件表（open file table）**，核心是**文件偏移（file offset）**：

```text
进程 → 文件描述符表 (fd) → 打开文件表项 (offset, access mode, ...) → inode
```

- 每个文件描述符指向一个打开文件表项，表项里有**独立的文件偏移**。
- 同一文件被两次 `open()`，产生两个偏移（互不影响）。
- 文件偏移：顺序读时自动前进，`lseek` 手动跳。

::: warning 面试常问：dup vs 独立 open
`open()` 两次 → 两个独立的打开文件表项（各自偏移）。`dup(fd)` → 两个 fd 共享同一个打开文件表项（共享偏移）。前者如两个游标，后者如一个游标被两个句柄控制。
:::

### 2.3 文件描述符表细节

- 每个进程有一张 fd 表，0/1/2 默认是 stdin/stdout/stderr。
- 打开文件表由**内核全局共享**，跨进程 `fork` 时会复制 fd 表但共享打开文件表项。
- `inotifywait` 等工具能观测文件事件：

```bash
inotifywait -m /tmp     # 监控 /tmp 下的 create/delete/modify 事件
```

## 3. 访问方法

| 访问方法 | 英文 | 特点 | 场景 |
|---|---|---|---|
| 顺序访问 | sequential | 数据按顺序读写，文件偏移从 0 前进 | 磁带、日志、编译 |
| 直接访问 | direct/random | 任意位置随机读写，用块号或偏移寻址 | 数据库 |
| 索引访问 | indexed | 通过索引键（如 key）定位记录 | 老式索引文件 |

```text
顺序访问:  read 第 0 块 → 第 1 块 → 第 2 块 ...
直接访问:  read 第 n 块（n 任意）
索引访问:  key → 索引 → 块号
```

::: tip 现代观点
现代系统一般只用"顺序 + 直接（随机）"两种。数据库的 B+ 树索引、文件系统的 extent 都是在"直接访问"上的优化。索引访问在教材里是老式记录文件，面试知道"顺序/直接/索引"三分法即可，重点答**顺序 vs 随机**对缓存和调度的不同影响（见 [文件系统性能与空间管理](/kb/os/存储/05-文件系统性能与空间管理/)）。
:::

## 4. 目录结构

### 4.1 目录的本质

**目录（directory）** 也是一个文件，内容是**目录项（directory entry, dentry）的集合**：每个目录项保存"文件名 → inode 号"的映射。

```text
目录文件内容（示意）:
  name            inode
  ─────────────   ─────
  hosts           5234
  passwd          5235
  subdir/         5236
```

### 4.2 目录结构的演进

| 结构 | 英文 | 特点 | 缺陷 |
|---|---|---|---|
| 单级目录 | single-level | 所有文件在一个目录，同名冲突 | 多用户无法隔离 |
| 两级目录 | two-level | 每用户一个目录（/user/file） | 用户内仍会冲突，无法分组 |
| 树形目录 | tree | 任意嵌套，/a/b/c，最通用 | 无法共享同一文件给多路径 |
| 无环图目录 | acyclic graph | 树 + 链接（可共享），无环 | 删除与引用计数复杂 |
| 通用图目录 | general graph | 允许循环 | 需要垃圾回收检测循环 |

```text
树形目录:           无环图目录（共享 + 链接）:
  /                   /
  ├─ bin            ├─ bin
  │  └─ ls          ├─ usr
  ├─ usr               └─ lib ─┐(软链接)
  │  ├─ bin                       │
  │  └─ lib                 ┌─────┘
  └─ home                 lib2  (硬链接到 lib/某文件)
```

::: important 无环图 vs 通用图
无环图通过**硬链接**让同一文件出现在多个目录（共享 inode），需维护链接计数，删除文件=计数减一，减到 0 才释放。通用图允许目录间循环引用（如 `ln -s a b` 且 `b/a` 指向 a 自身），需要**垃圾回收**；Linux 软链接可制造循环，`find`/递归遍历需防循环。
:::

### 4.3 路径解析

路径是"从根（绝对路径）或当前目录（相对路径）逐级在目录项里查 inode"的过程：

```text
解析 /usr/bin/ls:
  /        → 根目录 inode（固定为 2）
  usr      → 在根目录项中找 "usr" → inode
  bin      → 在 usr 的目录项中找 "bin" → inode
  ls       → 在 bin 的目录项中找 "ls" → inode → 读文件
```

每解析一级 = 一次目录查找。路径越长、目录越大，解析越慢，所以有目录缓存（dentry cache / inode cache）。

## 5. 文件系统挂载

**挂载（mount）** 是把一个文件系统"接到"目录树的一个节点上，使该节点（挂载点）的子树指向新文件系统的根。

```bash
# 查看已挂载文件系统
mount
cat /proc/mounts

# 挂载：把 /dev/sdb1（ext4）挂到 /mnt/data
sudo mount -t ext4 /dev/sdb1 /mnt/data

# 卸载
sudo umount /mnt/data

# 查看设备信息（UUID、类型）
sudo blkid /dev/sdb1
```

::: important 挂载点遮挡
挂载后，挂载点目录原有的内容被"遮挡"，访问挂载点实际访问的是新文件系统。所以挂载前应把挂载点清空或确认无旧数据。
:::

## 6. 文件共享与链接

### 6.1 硬链接 vs 软链接（核心考点）

| 维度 | 硬链接（hard link） | 软链接/符号链接（soft/symbolic link） |
|---|---|---|
| 本质 | 同一个 inode 的另一个目录项 | 存**目标路径**的特殊文件 |
| inode 共享 | 共享同一个 inode（`ls -li` 号相同） | 独立的 inode（存的是路径字符串） |
| 源文件删除 | 链接计数减一，其他硬链接仍有效 | 链接"悬空"（dangling），指向不存在的路径 |
| 跨文件系统 | **不可以**（inode 无法跨 FS） | 可以（只是路径） |
| 对目录 | 通常**不允许**（防环） | 可以（`ln -s`） |
| 大小 | 与源相同（同一 inode） | 大小 = 路径字符串长度 |
| 创建 | `ln src link` | `ln -s src link` |

```text
硬链接:
  /data/a.txt ──┐ (相同 inode 1234)
  /data/b.txt ──┘    inode 1234 → 数据块

软链接:
  /data/c_link → /data/a.txt   (inode 5678, 内容是路径 "/data/a.txt")
```

::: tip 用 `ls -li` 亲眼验证

:::```bash
> echo hello > /tmp/orig
> ln /tmp/orig /tmp/hard      # 硬链接
> ln -s /tmp/orig /tmp/soft   # 软链接
> ls -li /tmp/orig /tmp/hard /tmp/soft
> # orig 与 hard 的 inode 号相同；soft 是另一个 inode，且 ls 显示 l 类型
> rm /tmp/orig
> cat /tmp/hard   # 正常（hello）
> cat /tmp/soft   # 报错：No such file（悬空链接）
> ```

::: warning 为什么不许对目录做硬链接
目录硬链接会形成循环引用（目录 A 含 A 自身），使路径解析无限递归。文件系统禁止，软链接允许但遍历时要防环。
:::

### 6.2 链接计数与删除

删除文件 = `unlink()` 目录项，inode 的**链接计数减一**；计数为 0 且无打开引用时才真正释放数据块（见 [文件系统可靠性与日志](/kb/os/存储/06-文件系统可靠性与日志/) 中磁盘配额与一致性）。

## 7. Linux 权限模型

### 7.1 rwx 与八进制

每个文件有三组权限（用户 owner / 组 group / 其他人 other），每组三个位：r(4) w(2) x(1)，八进制一位表示一组。

```text
权限字符串:  -rwxr-xr--
             │└┬┘└┬┘└┬┘
             │ │  │  └─ other: r-- = 4
             │ │  └──── group: r-x = 5
             │ └─────── owner: rwx = 7
             └──────── 类型: - 普通文件, d 目录, l 链接
```

| 八进制 | 二进制 | 权限 |
|---|---|---|
| 0 | 000 | 无 |
| 1 | 001 | --x |
| 2 | 010 | -w- |
| 3 | 011 | -wx |
| 4 | 100 | r-- |
| 5 | 101 | r-x |
| 6 | 110 | rw- |
| 7 | 111 | rwx |

### 7.2 常用命令

```bash
chmod 755 file.txt      # rwxr-xr-x
chmod u+x script.sh     # 给 owner 加执行权限
chmod -R g-w docs/      # 递归移除组写权限
chown user:group file   # 修改属主:属组
chown user file
chgrp group file
```

::: warning 目录权限与文件权限不同
- 目录的 **r**：能否列出目录内容（`ls`）。
- 目录的 **x**：能否**进入**目录（cd）或访问其中文件。**只有 r 没有 x 无法列出完整信息**。
- 文件的 **x**：能否执行。
例如 `--wx` 目录：可进入并创建/删除文件，但不能 `ls` 列出。
:::

### 7.3 特殊位（补充）

- **setuid**（`chmod u+s` / 4000）：执行时以属主身份运行（如 `/usr/bin/passwd`）。
- **setgid**（2000）：目录下新建文件继承组。
- **sticky bit**（`chmod +t` / 1000）：只有文件属主能删（如 `/tmp`，`drwxrwxrwt`）。

::: tip 文件系统权限在 Linux 上的观察

:::```bash
> ls -la /tmp   # 注意 /tmp 权限 drwxrwxrwt（t 为 sticky）
> ls -l /usr/bin/passwd   # -rwsr-xr-x（s 为 setuid）
> ```

## 8. 本章小结

- 文件 = 命名字节流，元数据在 inode，文件名只在目录项里，inode 号是内部标识。
- 打开文件机制：fd → 打开文件表项（含偏移）→ inode；两次 open 偏移独立，dup 共享。
- 访问方法：顺序/直接/索引；现代重点是顺序 vs 随机。
- 目录结构：单级→两级→树→无环图→通用图；无环图用硬链接共享，通用图有循环需回收。
- 挂载把文件系统接进目录树，挂载点内容被遮挡。
- 硬链接共享 inode（同 inode 号、不能跨 FS、不能对目录）；软链接存路径（可悬空、可跨 FS）。
- Linux 权限：owner/group/other × rwx，八进制；目录的 x 决定能否进入。

## 9. 自测题

1. 硬链接和软链接的本质区别是什么？跨文件系统可以建立哪种？
   <details><summary>答案</summary>
   硬链接是同一 inode 的另一个目录项（`ls -li` inode 号相同），软链接是存储目标路径的特殊文件。硬链接不能跨文件系统（inode 无法跨 FS），软链接可以。
   </details>

2. 删除源文件后，硬链接和软链接各自怎样？
   <details><summary>答案</summary>
   硬链接仍指向同一 inode，文件内容还在（链接计数减一）；软链接变成悬空链接，指向不存在的路径。
   </details>

3. `open()` 同一文件两次与 `dup(fd)` 有何区别？
   <details><summary>答案</summary>
   两次 `open()` 生成两个独立的打开文件表项、各有文件偏移；`dup(fd)` 让两个 fd 共享同一打开文件表项、共享偏移。
   </details>

4. 为什么文件名不存 inode 里？这带来什么好处？
   <details><summary>答案</summary>
   文件名存在目录项中。好处：重命名/移动只改目录项（mv 很快）、同一 inode 可被多个名字引用（硬链接）、目录结构独立于文件本体。
   </details>

5. 目录权限 r-x 和 rw- 分别能做什么、不能做什么？
   <details><summary>答案</summary>
   r-x：可列出并可进入（cd）、访问文件，但不能增删目录项；rw-：可列出可增删（因有 w），但无 x 不能 cd 进入，也无法真正访问其中文件。
   </details>

6. chmod 644 和 chmod 755 分别是什么权限？各适合什么？
   <details><summary>答案</summary>
   644 = rw-r--r--（属主可读写，其他只读），适合普通数据文件；755 = rwxr-xr-x（属主全权，其他可读可执行），适合脚本/可执行程序/目录。
   </details>

7. 树形目录和无环图目录的关键区别？
   <details><summary>答案</summary>
   树形目录每个文件/目录只有一个父路径；无环图目录通过硬/软链接允许同一文件被多路径引用（共享），但需要维护引用计数处理删除。
   </details>

8. 什么是挂载点遮挡？挂载一个文件系统到非空目录会怎样？
   <details><summary>答案</summary>
   挂载后，挂载点原内容被新文件系统"遮挡"，访问挂载点看到的是新文件系统；卸载后原内容恢复。
   </details>

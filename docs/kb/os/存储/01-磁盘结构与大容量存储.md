::: abstract 本章定位
一切存储调度的性能都受制于磁盘的物理结构。本章讲清楚 HDD 的盘面/磁道/扇区/柱面几何、寻道时间/旋转延迟/传输时间三要素，对比 HDD 与 SSD，介绍 RAID 0/1/5/6/10 的容量与容错，简述 SATA/SAS/NVMe 接口，最后给出从 cache 到 tape 的完整存储层级。对应教材 Ch11 Mass-Storage Structure。
:::

## 1. 为什么先讲物理结构

所有高级抽象（文件系统、RAID、调度器）最终都作用在**物理块**上。不了解"磁头要移动、盘片要旋转"，就理解不了为什么随机 IO 比顺序 IO 慢几个数量级，也就理解不了磁盘调度算法存在的理由。

::: important 一个必须记住的数量级对比
- CPU 访问 L1 cache：~1 ns
- 访问主存：~100 ns
- 访问 SSD：~0.1 ms（100 000 ns）
- 访问 HDD：~5–10 ms（5 000 000–10 000 000 ns）

一次 HDD 随机访问比一次主存访问慢约 **5 个数量级**，这解释了为什么操作系统要把缓存（页缓存）和调度（电梯算法）做到极致。
:::

## 2. 磁盘物理结构

### 2.1 术语：盘面、磁道、扇区、柱面

磁盘（HDD）由若干**盘面**（platter）叠成，每面有磁性涂层，有一个**读/写磁头**（head）在其上方浮动。

```text
            盘片（platter）
   ┌─────────────────────────┐
   │   ○───────●←── 磁道(track) │
   │  ╱  │  ╲                 │
   │ ○─┼──┼──┼─○             │
   │   扇区(sector)            │
   └─────────────────────────┘
           侧视图：
       ┌────────────────────┐
       │  ┌──────┐           │  磁道 i（所有盘面同一位置的磁道合称"柱面"）
       │  │ 盘面 │  ←─ 磁头   │
       │  └──────┘           │
       └────────────────────┘
```

| 术语 | 英文 | 定义 |
|---|---|---|
| 盘面 | platter | 单张圆形盘片，两面都可记录（通常两面都有磁头） |
| 磁道 | track | 盘面上的一条同心圆记录带 |
| 扇区 | sector | 磁道被切分的最小寻址单位，传统固定 512 B，现代 4K 盘用 4096 B |
| 柱面 | cylinder | 所有盘面同一半径磁道的集合 |
| 磁头 | head | 每面一个，负责读写；移动靠摇臂（actuator） |

### 2.2 存储地址与容量计算

块设备的基本地址单元是 **扇区（sector）**。早期按 CHS（Cylinder-Head-Sector）寻址，现在一律用 **LBA**（Logical Block Addressing，逻辑块地址，从 0 编号的线性块序列）。操作系统和文件系统看到的是 LBA，物理映射由磁盘固件完成。

**容量计算公式：**

```
磁盘容量 = 盘面数(磁头数) × 每面磁道数 × 每道扇区数 × 扇区大小
```

::: tip 典型计算例题 1
某磁盘有 4 个盘面、每面 512 个磁道、每磁道 200 个扇区、每扇区 512 B。求容量。


:::```
> 容量 = 4 × 512 × 200 × 512 B
>       = 4 × 512 × 102 400 B
>       = 209 715 200 B
>       = 200 MiB ≈ 0.2 GB
> ```

::: tip 典型计算例题 2（面试高频）
某磁盘 128 个盘面、每面 2048 个磁道、每磁道 64 个扇区、每扇区 512 B。求容量与总扇区数。


:::```
> 总扇区数 = 128 × 2048 × 64
>          = 128 × 131 072
>          = 16 777 216 个扇区
> 容量 = 16 777 216 × 512 B
>       = 8 589 934 592 B
>       = 8 GiB
> ```
>
> 这题的关键：**单位换算**。`8 589 934 592 B / 1024³ = 8 GiB`（2 的幂），若用 10 进制则是 `8.59 GB`。厂商标称用 GB（十进制），操作系统按 GiB（二进制）显示，所以买 500 GB 的盘 `df -h` 显示约 465 GiB。

::: warning GB 与 GiB 的坑
- `GB`（1 GB = 10⁹ B）：厂商容量、网络带宽常用。
- `GiB`（1 GiB = 2³⁰ B = 1 073 741 824 B）：操作系统 `df`/`lsblk` 内部计算常用。
差距约 7%，这就是"500 GB 硬盘实际只有 465 GiB"的原因。
:::

### 2.3 扇区与 4K 扇区

传统 HDD 扇区 512 B；2009 年后 **AF（Advanced Format）** 扇区改为 4096 B（4K），因为扇区越大，纠错（ECC）与格式开销占比越低。4K 盘通常仍对 OS 模拟为 512 B 逻辑扇区以兼容旧系统，但对齐问题（分区起始不在 4K 边界）会明显降低性能。

::: important Linux 验证命令

:::```bash
> # 物理扇区大小 vs 逻辑扇区大小
> lsblk -o NAME,PHY-SEC,LOG-SEC,SIZE,TRAN,ROTA
> # 磁盘是否机械盘：ROTA=1 表示 HDD，0 表示 SSD
> cat /sys/block/sda/queue/rotational
> # 分区是否 4K 对齐（start 应为 8 的倍数，8×512=4096）
> sudo fdisk -l /dev/sda
> ```

## 3. 磁盘访问时间三要素

一次磁盘 I/O 的总时间 = **寻道时间 + 旋转延迟 + 传输时间**。

### 3.1 三个时间

| 组成 | 英文 | 含义 | 数量级 |
|---|---|---|---|
| 寻道时间 | seek time | 磁头从当前磁道移到目标磁道的时间，与移动的磁道数成正比 | 2–15 ms，平均约 4–9 ms |
| 旋转延迟 | rotational latency | 目标扇区转到磁头下方的时间；平均 = 转半圈时间 | 7200 RPM 时约 4.17 ms |
| 传输时间 | transfer time | 数据从盘面读入并传输的时间，取决于块大小与带宽 | 数百 MB/s，传输一个 4 KB 块约 0.02 ms |

```
平均访问时间 = 平均寻道时间 + 平均旋转延迟 + 传输时间
```

### 3.2 计算例题（面试高频）

::: tip 计算平均访问时间
磁盘：转速 7200 RPM，平均寻道时间 4 ms，最大内部传输率 200 MB/s，扇区 512 B。求读取一个扇区的平均时间。


:::```
> ① 旋转延迟：转一圈 = 60 / 7200 = 8.33 ms，平均等半圈 = 8.33 / 2 = 4.17 ms
> ② 传输时间：512 B / 200 MB/s = 512 / 200 000 000 s = 0.00256 ms ≈ 0.003 ms
> ③ 总时间 = 4 + 4.17 + 0.003 ≈ 8.17 ms
> ```
>
> 结论：**一个扇区只有 512 B，但访问要花 8 ms**。旋转延迟和寻道时间占了 99.9%，这就是随机 IO 慢的根源——**传输时间几乎可以忽略，真正贵的是"把磁头挪过去"**。

::: tip 计算旋转延迟的通用公式
转速 `R` RPM，则一转 = 60/R 秒，平均旋转延迟 = 60/(2R) 秒。
- 5400 RPM：60/10800 = 5.56 ms
- 7200 RPM：60/14400 = 4.17 ms
- 10000 RPM：60/20000 = 3 ms
- 15000 RPM：60/30000 = 2 ms
:::

::: tip 计算"顺序读一个 1 MB 文件要多久"
若磁盘顺序传输率 150 MB/s，传输本身只要约 6.7 ms；但因为磁头已经在连续磁道上移动，**顺序 IO 只需一次寻道**（然后靠旋转连续读），所以顺序读约 6.7 ms + 一次寻道。**随机读 1 MB（256 个 4 KB 块）则要 256 次寻道+旋转 ≈ 256 × 8 ms ≈ 2 秒**。这就是数据库调优"用顺序 IO、不要随机 IO"的物理根源。
:::

### 3.3 为什么"旋转延迟"不能消除

盘片只能单向旋转，磁头无法"停住等"，只能等扇区转过来。对 HDD 而言这是物理必然，所以提高转速（10K/15K RPM）能缩短延迟，但更快磁头移动（寻道）收益更大——这就是磁盘调度算法优化寻道距离的动机（见 [磁盘调度算法与RAID](/kb/os/存储/02-磁盘调度算法与RAID/)）。

## 4. HDD vs SSD

### 4.1 原理差异

| 维度 | HDD（机械盘） | SSD（固态盘） |
|---|---|---|
| 介质 | 磁性盘片 + 移动磁头 | NAND 闪存单元，无机械部件 |
| 读原理 | 磁头感应磁场变化 | 电荷读取（浮栅晶体管） |
| 写原理 | 磁头改写磁场 | 闪存**只能按页写**、擦除按块（block），且先擦后写 |
| 访问单位 | 扇区（512 B / 4K） | 页（4–16 KB）写、块（数百 KB–几 MB）擦 |
| 寻址成本 | 寻道+旋转，与位置强相关 | **无寻道**，任意位置等延迟 |
| 随机 IOPS | ~100–200 | ~100 000–1 000 000 |
| 顺序带宽 | 150–250 MB/s | 500–7 000 MB/s（NVMe） |
| 延迟 | 5–10 ms | 0.05–0.2 ms |
| 寿命 | 无限改写 | 每单元有限擦写次数（P/E 数） |
| 抗震/噪音/功耗 | 差 / 有 / 高 | 好 / 无 / 低 |

### 4.2 两个关键推论

::: warning SSD 的"先擦后写"
闪存写一个页前，必须先把整块（多个页）擦除。更新一个小文件可能触发"读-改-写"整块，因此 SSD 有 **写放大（write amplification）**。Linux 靠 `TRIM`/`discard` 通知 SSD 哪些块空闲（见 [文件系统可靠性与日志](/kb/os/存储/06-文件系统可靠性与日志/)）。
:::

::: important SSD 不需要磁盘调度，但需要别的
没有寻道时间，SCAN 之类面向磁头移动的调度对 SSD 几乎无意义（现代内核用 `none`/`mq-deadline`）。SSD 真正要解决的是 **磨损均衡（wear leveling）**：尽量让每个闪存块被擦写的次数接近，避免个别块过早报废，以及 TRIM 让 GC 知道哪些是垃圾页。
:::

## 5. RAID

### 5.1 RAID 是什么

RAID（Redundant Array of Independent Disks）把多块物理磁盘组织成一个逻辑卷，目的有二：**性能**（并行读写）与**可靠性**（冗余容错）。RAID 通常在操作系统磁盘驱动之上、文件系统之下，由 RAID 控制器或内核 MD 模块实现。

### 5.2 常见 RAID 级别

| RAID | 最小盘数 | 容量（n 块盘，每块 B） | 容错能力 | 读性能 | 写性能 | 典型用途 |
|---|---|---|---|---|---|---|
| RAID 0 | 2 | n×B（无冗余） | 无，坏一块全丢 | 并行读，高 | 并行写，高 | 临时数据、性能极客 |
| RAID 1 | 2 | B（镜像） | 坏 1 块 | 可并行读，较高 | 需写两份，中 | 系统盘、数据库日志 |
| RAID 5 | 3 | (n−1)×B（奇偶校验，单块盘容量） | 坏 1 块 | 高（多盘并行） | 校验计算开销，中 | 通用文件服务器 |
| RAID 6 | 4 | (n−2)×B（双校验） | 坏 2 块 | 高 | 双校验计算，低 | 数据安全要求高 |
| RAID 10 | 4 | (n/2)×B（镜像+条带） | 每个镜像组坏 1 块 | 很高 | 高 | 数据库、核心业务 |

### 5.3 冗余计算例题

::: tip RAID 容量计算
5 块 2 TB 盘：
- RAID 0：5 × 2 = **10 TB**，任何 1 块坏数据全丢。
- RAID 5：4 × 2 = **8 TB**，可容忍 1 块坏。
- RAID 6：3 × 2 = **6 TB**，可容忍 2 块坏。
- RAID 10（需要偶数且≥4 块，5 块不适用）：若用 4 块 = 2 × 2 = **4 TB**，每个镜像对可坏 1 块。
:::

::: important RAID 5 的"写惩罚"
RAID 5 每写一个数据块，需要读旧数据、读旧校验、算新校验、写数据、写校验——一次"读-改-写"产生约 **4 次底层 IO（读 2 写 2）**。所以数据库这类重随机写场景更爱 RAID 10（写惩罚低）。坏盘后重建（rebuild）期间再坏一块，RAID 5 会丢数据，这是很多人升级到 RAID 6 的原因。
:::

### 5.4 RAID 0/1/5/10 怎么选（一句话）

- 只要速度不要命：RAID 0。
- 要命（系统/日志盘）：RAID 1。
- 要容量又要一块容错、读多写少：RAID 5。
- 写多、钱够、要安全：RAID 10（生产数据库默认）。

::: tip Linux 实验：用 mdadm 造一个软件 RAID

:::```bash
> # 用两个 loop 设备模拟两块盘，组成 RAID 1 试试
> sudo modprobe loop
> dd if=/dev/zero of=/tmp/disk1 bs=1M count=64
> dd if=/dev/zero of=/tmp/disk2 bs=1M count=64
> sudo losetup /dev/loop1 /tmp/disk1
> sudo losetup /dev/loop2 /tmp/disk2
> sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/loop1 /dev/loop2
> cat /proc/mdstat
> ```

## 6. 磁盘连接接口

| 接口 | 类型 | 带宽 | 特点 | 适用 |
|---|---|---|---|---|
| SATA | HDD/SSD 串行 | SATA III 6 Gb/s（约 600 MB/s 有效） | 便宜、单盘、命令队列浅（NCQ 32） | 家用盘、普通服务器 |
| SAS | HDD/SSD 企业级 | 12 Gb/s 起 | 双端口、命令队列深、错误处理更强、支持多盘背板 | 企业盘柜 |
| NVMe | 纯 SSD 协议 | PCIe 4.0 ×4 约 7 GB/s，PCIe 5.0 更高 | 走 PCIe 总线、**多队列（blk-mq）**、极低延迟 | 高性能 SSD、数据库 |

::: important NVMe 与 SATA 的本质区别
SATA 时代的协议按"单一命令队列 + 中断"设计，队列深度有限。NVMe 设计为 **每核多个队列（Multi-Queue）**，避免多 CPU 争用一把锁，配合内核 `blk-mq` 框架把 IO 压力打散到各核。这就是"NVMe 快"除了物理介质外，还有协议层面的原因。
:::

## 7. 存储层级（Storage Hierarchy）

数据速度从快到慢、成本从高到低、容量从小到大排列：

```text
寄存器 (register)         ~1 ns        字节级
  ↓
缓存 (cache L1/L2/L3)     ~1–10 ns      KB–MB
  ↓
主存 (main memory)        ~100 ns       GB
  ↓
固态盘 (SSD)              ~0.1 ms       数百 GB–TB
  ↓
机械盘 (HDD)              ~5–10 ms      TB
  ↓
光盘/磁带 (tape)          ~s            TB–PB（归档）
```

操作系统做两件事来弥合层级差：
1. **缓存**：把最近用过的数据从慢层复制到快层（页缓存，见 [文件系统性能与空间管理](/kb/os/存储/05-文件系统性能与空间管理/)、[内存](/kb/os/内存/06-内存性能与系统调优/)）。
2. **预读**：预测将来要用的数据提前取到快层（read-ahead，见 [文件系统性能与空间管理](/kb/os/存储/05-文件系统性能与空间管理/)）。

::: tip 磁带还有用吗？
有。磁带成本每 GB 最低、长期保存可靠，常用于**归档与冷数据备份**（AWS Glacier 一类就是磁带/光介质）。它只能顺序访问，所以适用"写多读少、且读也是整卷顺序读"的场景。
:::

## 8. 本章小结

- 磁盘容量 = 盘面数 × 磁道数 × 每道扇区数 × 扇区大小；注意 GB（10 进制）与 GiB（2 进制）的换算。
- 一次磁盘访问 = 寻道 + 旋转延迟 + 传输，其中传输时间可忽略，**随机访问的瓶颈是寻道与旋转**。
- HDD 随机 IOPS 约百级、SSD 十万级，SSD 靠无寻道 + 多队列取胜，但要处理写放大与磨损。
- RAID 用多盘换性能或冗余：0 无冗余、1 镜像、5 单校验、6 双校验、10 镜像+条带，用容量公式 (n−k)×B 心算。
- 存储层级每下降一层，延迟约大一个数量级；操作系统用缓存与预读弥合速度差。

## 9. 自测题

1. **计算**：某磁盘 64 个盘面、每面 1024 磁道、每道 32 扇区、每扇区 512 B。求总容量（结果用 GiB 表示）。
   <details><summary>答案</summary>
   总扇区 = 64 × 1024 × 32 = 2 097 152；容量 = 2 097 152 × 512 B = 1 073 741 824 B = **1 GiB**。
   </details>

2. **计算**：7200 RPM 磁盘，平均寻道 5 ms，内部传输率 100 MB/s，读取一个 4 KB 块的平均时间是多少？
   <details><summary>答案</summary>
   旋转延迟 = 60/(2×7200) = 4.17 ms；传输 = 4096 / 100 000 000 s = 0.041 ms；总计 = 5 + 4.17 + 0.041 ≈ **9.2 ms**。
   </details>

3. 为什么随机访问比顺序访问慢这么多？哪部分时间贡献最大？
   <details><summary>答案</summary>
   随机访问每次都要寻道 + 等旋转，这两项约 8–12 ms 且与块大小无关；顺序访问只花一次寻道，其余靠旋转连续读。**寻道与旋转延迟贡献最大，传输时间可忽略**。
   </details>

4. RAID 5 用 4 块 1 TB 盘，可用容量和容错能力是多少？
   <details><summary>答案</summary>
   容量 = (4−1)×1 = **3 TB**；可容忍任意 1 块盘损坏；重建期间再坏一块会丢数据。
   </details>

5. RAID 10 需要至少几块盘？坏两块盘在什么情况下安全？
   <details><summary>答案</summary>
   至少 **4 块**（2 个镜像组）。两块盘若分属不同镜像组则安全，若在同一镜像组则数据丢失。
   </details>

6. SSD 为什么没有寻道时间？它性能提升主要靠什么？
   <details><summary>答案</summary>
   无机械部件，任意地址延迟相同，所以无寻道。提升靠闪存多平面并行、NVMe 多队列协议、无旋转等待。代价是写放大与有限擦写寿命。
   </details>

7. 为什么 NVMe SSD 用多队列而 SATA 单队列？
   <details><summary>答案</summary>
   多核 CPU 并发提交 IO 时，单队列会成为锁竞争瓶颈；NVMe 的每核多队列配合内核 blk-mq，避免互斥锁，从而在极低延迟下支撑高 IOPS。
   </details>

8. 存储层级中"缓存"与"磁盘"之间靠什么机制弥合速度差？
   <details><summary>答案</summary>
   缓存（把热数据复制到主存，即页缓存）与预读（read-ahead）两个机制，配合调度与缓冲（见 [文件系统性能与空间管理](/kb/os/存储/05-文件系统性能与空间管理/)、[IO子系统](/kb/os/IO/03-内核IO子系统与缓冲/)）。
   </details>

::: abstract 本章定位
本章把前几章的机制串起来回答"文件系统怎么做得又快又不浪费"：块大小权衡、页缓存/双缓冲/统一缓冲、read-ahead 预读、内存映射文件、性能调优手段、磁盘配额、备份与快照，以及 RAID 与文件系统结合的生产实践。对应教材 Ch15 File-System Internals。
:::

## 1. 磁盘块大小的权衡

块（block）是文件系统与磁盘交互的基本单位（通常 4096 B）。块大小对性能与空间都有深刻影响：

| 维度 | 小块（如 1 KB） | 大块（如 64 KB） |
|---|---|---|
| 内部碎片 | 小（浪费少） | 大（一个 1 KB 文件占 64 KB） |
| 顺序读 | 慢（每块一次 IO，块多） | 快（一次能读更多数据，IO 次数少） |
| 寻道开销 | 大（块数多、需要更多次访问） | 小 |
| 元数据 | 指针多（间接层多） | 指针少（extent 更紧凑） |

::: important 权衡的本质
块大 → 顺序性能好、但内部碎片浪费空间；块小 → 空间利用率高、但块数多、寻道多、元数据开销大。**文件系统在"空间浪费"与"时间效率"之间折中**，现代默认 4 KB 是平衡点。
:::

::: tip 内部碎片例题
块大小 4 KB，存储 1000 个平均 2.5 KB 的文件，内部碎片平均多少？


:::```
> 每个文件占 1 块 = 4 KB，实际内容平均 2.5 KB
> 每个文件平均浪费 = 4 - 2.5 = 1.5 KB
> 1000 个文件浪费 = 1.5 KB × 1000 = 1.5 MB
> 空间利用率 = 2.5/4 = 62.5%
> ```
>
> 若块大小 1 KB：每个文件占 3 块（2.5→3），浪费 0.5 KB/文件，利用率 83%。**块越小内部碎片越少**。

## 2. 缓冲与缓存

### 2.1 为什么需要缓冲/缓存

磁盘与 CPU 速度差 5 个数量级（见 [磁盘结构与大容量存储](/kb/os/存储/01-磁盘结构与大容量存储/)）。缓存把"刚读过/要再读"的数据留在内存，避免重复访问磁盘。

| 概念 | 作用 |
|---|---|
| 缓冲（buffer） | 缓解速度不匹配、协调传输粒度，**数据只用一次** |
| 缓存（cache） | 保存可能**重复使用**的数据，提升命中率 |

### 2.2 页缓存（page cache）

Linux 把磁盘块缓存统一组织成**页缓存（page cache）**——按内存页（4 KB）为单位缓存文件内容。读写普通文件默认走页缓存：

```text
write() → 页缓存(脏页 dirty) → 后台回写 → 磁盘
read()  → 先查页缓存 → 命中直接返回 | 未命中读磁盘并填入缓存
```

```bash
free -h        # buff/cache 就是页缓存等
cat /proc/meminfo | grep -E 'Dirty|Writeback'
sync           # 强制把脏页刷盘
```

::: important 读写都是先写缓存
- 读：先查缓存，未命中才读盘。
- 写：默认 write-back（先写页缓存标记脏，后台再刷盘），所以 `write()` 返回不代表落盘——崩溃可能丢数据（见 [文件系统可靠性与日志](/kb/os/存储/06-文件系统可靠性与日志/)）。
- `fsync`/`sync` 强制落盘，数据库/重要写入必须用它。
:::

### 2.3 双缓冲与统一缓冲区缓存

- **双缓冲（double buffering）**：设备往缓冲 A 填数据时，CPU 从缓冲 B 消费，交替使用，避免互等，提高吞吐。
- **统一缓冲区缓存（unified buffer cache）**：Linux 把**块设备缓冲和文件页缓存合并**为同一个页缓存，避免一份数据在"buffer cache"和"page cache"各存一份、互相污染。

::: tip 现代内核的统一
老 Unix 有独立的 buffer cache 和 page cache。Linux 用 **page cache 统一**，`/proc/meminfo` 里的 `buffers`（块设备读写缓冲）与 `cached`（页缓存）都属于同一体系。`dd` 测速默认也走页缓存，若要测真实磁盘性能要加 `oflag=direct`。
:::

### 2.4 read-ahead 预读

文件系统预测进程会按顺序继续读，提前把后续块取入页缓存：

```bash
# 观察 read-ahead（mmap/顺序读优化）
dd if=bigfile of=/dev/null bs=1M   # 顺序读，命中预读缓存，吞吐接近磁盘上限
```

::: important 为什么顺序读快、随机读慢
顺序读时 read-ahead 提前取回大量块 → 命中缓存，IO 数量少；随机读每次只读一个块，预读基本失效，且块分布散 → 寻道+旋转开销大（见 [磁盘结构与大容量存储](/kb/os/存储/01-磁盘结构与大容量存储/)）。
:::

## 3. 内存映射文件（mmap）

**mmap** 把文件区域直接映射到进程地址空间，读写文件就像操作内存数组：

```c
// 用户态示意：映射文件前 4096 字节
void *p = mmap(addr, 4096, PROT_READ, MAP_PRIVATE, fd, 0);
char c = ((char*)p)[0];   // 读文件 = 读内存
munmap(p, 4096);
```

| 对比项 | mmap | 普通 read/write |
|---|---|---|
| 数据流 | 内存 ←→ 页缓存 ←→ 磁盘（借页表） | 用户缓冲区 ←拷贝→ 页缓存 ←→ 磁盘 |
| 系统调用 | 缺页时才触发，减少 read/write 调用 | 每次 read/write 都系统调用 + 拷贝 |
| 拷贝次数 | 少一次用户态拷贝 | 用户态与内核态各一次拷贝 |
| 典型用途 | 大文件、共享内存、加载可执行文件 | 小数据、流式处理 |

::: tip 何时用 mmap
大数据随机读写、多进程共享文件、加载动态库/可执行文件（内核直接 mmap）。流式顺序读写小数据用普通 read 更简单。详见 [内存](/kb/os/内存/06-内存性能与系统调优/)。
:::

## 4. 文件系统性能调优

| 手段 | 原理 | Linux 操作 |
|---|---|---|
| 增大缓存 | 更多内存做页缓存 | `sysctl vm.dirty_ratio`、加内存 |
| 控制回写 | 脏页阈值/频率 | `vm.dirty_background_ratio`、`vm.dirty_writeback_centisecs` |
| 调度器选择 | 顺序/随机 IO 用合适调度器 | `/sys/block/*/queue/scheduler`（见 [磁盘调度算法与RAID](/kb/os/存储/02-磁盘调度算法与RAID/)） |
| 块大小 | 大文件用大块、小文件用小块 | 格式化时 `mkfs.ext4 -b` |
| noatime | 关闭访问时间更新减少写 | `mount -o noatime` |
| 预读调整 | 调整 read-ahead 窗口 | `blockdev --setra` / `sysctl` |
| 直接 IO | 需要真实落盘/绕过缓存 | `dd oflag=direct`、`O_DIRECT` |

::: warning 调优要"对症"
随机 IO 瓶颈在寻道/旋转（[磁盘结构与大容量存储](/kb/os/存储/01-磁盘结构与大容量存储/)）→ 换 SSD 或 RAID；顺序 IO 瓶颈在带宽 → 看接口与 RAID 并行度；小文件多 → 关注 inode 与块大小。不要盲目加大缓存或改调度器。
:::

## 5. 磁盘配额

**磁盘配额（quota）** 限制用户/组可占用的块数或 inode 数（文件数），防止某个用户耗尽磁盘。

```bash
# 启用配额（需在挂载选项开启 usrquota/grpquota）
sudo mount -o remount,usrquota /home
# 设置配额
sudo edquota -u alice          # 交互设置 soft/hard 限制
sudo quotaon /home
```

配额有两档：
- **软限制（soft）**：可临时超过，超期未降级则拒绝。
- **硬限制（hard）**：绝对上限，超过即拒绝写入。

::: tip 配额与 inode
配额既可按块（空间）也可按 inode（文件数）限制。海量小文件的场景（如缓存目录）应同时限 inode，否则会被几十万个空文件耗尽 inode 表。
:::

## 6. 备份与快照

### 6.1 备份策略

| 策略 | 内容 | 特点 |
|---|---|---|
| 全量备份 | 备份全部数据 | 恢复简单，但耗时长、占空间 |
| 增量备份 | 只备份上次备份后变更 | 快、省空间，恢复要按顺序回放 |
| 差异备份 | 只备份上次**全量**后变更 | 恢复较快，介于两者之间 |

```bash
# 示例：tar 全量 + 增量（简化示意）
tar -czf full.tar.gz /data
tar -czf incr_$(date +%F).tar.gz --newer-mtime full.tar.gz /data
```

::: warning 备份的教训
备份要在**可验证、可恢复**的前提下设计。数据库要用 `mysqldump`/`pg_dump` 等一致性备份工具，而不是直接 tar 数据文件（否则得到的是不一致快照）。
:::

### 6.2 快照（snapshot）

快照是**某一时刻文件系统的只读副本**，实现常用**写时复制（COW）**：快照后修改的块才复制，未改的块共享原盘。

```text
创建快照时刻 T：
  所有块都"指向"原盘（不复制）
  之后修改块 X → 先把块 X 原内容复制到快照区，再写新内容到原盘
  快照始终能看到 T 时刻的块 X
```

- LVM 快照：`lvcreate -s -L 10G /dev/vg/lv` 支持在线快照。
- 文件系统快照：btrfs/ZFS 内建（见 [文件系统可靠性与日志](/kb/os/存储/06-文件系统可靠性与日志/)）。
- 快照 ≠ 备份：快照与原数据在**同一磁盘**，磁盘坏了快照也没了；快照适合快速回滚，备份适合灾难恢复。

## 7. RAID 与文件系统结合

### 7.1 分层

```text
文件系统 (ext4)
   ↓ 读写逻辑块
RAID (mdadm / 硬件 RAID)   ← 让文件系统看到一块"大而可靠"的盘
   ↓
物理磁盘 × N
```

- RAID 给文件系统提供的是**一块逻辑卷**，文件系统感知不到底层有几块盘。
- RAID 条带化与文件系统 extent 都"优化连续分配"，两者通常互相兼容；但**条带对齐**（文件系统块对齐 RAID chunk）能减少"读-改-写"。

::: tip 顺序 IO 与 RAID
RAID 0/5 把数据条带化到多块盘，顺序写可并行 → 吞吐接近 n×单盘。随机 IO 主要靠多盘分担 IOPS，不能像顺序那样线性叠加。
:::

### 7.2 生产实践要点

| 场景 | 建议 |
|---|---|
| 数据库（写多） | RAID 10（写惩罚低，见 [磁盘结构与大容量存储](/kb/os/存储/01-磁盘结构与大容量存储/)） |
| 文件服务器（读多） | RAID 5/6 + 大缓存 |
| 系统盘 | RAID 1（镜像） |
| 备份盘 | RAID 6 或单盘+异地备份 |
| 大文件顺序读 | RAID 0（可接受无冗余时） |

::: warning RAID 不是备份
RAID 保护的是"硬盘坏"；对"误删、勒索软件、逻辑损坏"无效。生产环境必须是 **RAID（硬件容错）+ 快照（逻辑回滚）+ 异地备份（灾难恢复）** 三层都做。
:::

## 8. 本章小结

- 块大小权衡：大块顺序性能好但内部碎片多；现代默认 4 KB 平衡。
- 页缓存是 Linux 统一缓存，读写都先过它；fsync 才保证落盘。
- read-ahead 让顺序读快，随机读因预读失效 + 寻道慢而慢。
- mmap 通过页表映射省掉用户态拷贝，适合大文件/共享内存。
- 调优要对症：随机 IO 换 SSD/RAID，顺序 IO 看带宽，小文件看 inode/块。
- 配额限制块数与 inode 数；备份分全量/增量/差异；快照用 COW 实现，但不是备份。
- RAID 在文件系统之下提供可靠卷，生产要 RAID+快照+异地备份三层。

## 9. 自测题

1. 块大小 8 KB，存储 500 个平均 5 KB 的文件，内部碎片空间利用率是多少？
   <details><summary>答案</summary>
   每文件占 1 块=8 KB，内容平均 5 KB，浪费 3 KB/文件；利用率 = 5/8 = **62.5%**。总浪费 = 500×3 KB = 1.5 MB。
   </details>

2. 块大小从 1 KB 改到 64 KB，顺序读和内部碎片分别如何变化？
   <details><summary>答案</summary>
   顺序读：块数减少、IO 次数减少、传输更连续，吞吐提升；内部碎片：平均每个文件多浪费，小文件尤其明显，空间利用率下降。
   </details>

3. `write()` 返回成功就代表数据已落盘吗？如何保证落盘？
   <details><summary>答案</summary>
   不一定。write 默认先写页缓存标记脏页，后台异步回写。要保证落盘需 `fsync(fd)` 或 `sync`。
   </details>

4. read-ahead 为什么能提升顺序读而随机读几乎无效果？
   <details><summary>答案</summary>
   预读把"接下来可能读的连续块"提前取入缓存，顺序读命中共连续块；随机读访问无规律、预读取回的块多半用不上，且随机块分布散导致寻道开销大。
   </details>

5. mmap 相比 read/write 少哪一步？适合什么场景？
   <details><summary>答案</summary>
   少一次用户态与内核态之间的显式数据拷贝（通过缺页把页缓存映射进地址空间）。适合大文件随机访问、进程间共享内存、加载可执行文件。
   </details>

6. 磁盘配额的软限制和硬限制区别？
   <details><summary>答案</summary>
   软限制可临时超过，需在宽限期（grace period）内降下来；硬限制是绝对上限，超过即拒绝写入。
   </details>

7. 快照为什么不是备份？
   <details><summary>答案</summary>
   快照通常与原数据同盘（同一介质），磁盘整体损坏则快照一并丢失；快照用于快速逻辑回滚，灾难恢复必须靠独立介质的备份。
   </details>

8. 数据库为什么常用 RAID 10 而不是 RAID 5？
   <details><summary>答案</summary>
   数据库随机写多，RAID 5 每次写有"读-改-写"的写惩罚（约 4 次底层 IO）；RAID 10 写惩罚低、容错好，虽然容量利用率低但性能与可靠更均衡。
   </details>

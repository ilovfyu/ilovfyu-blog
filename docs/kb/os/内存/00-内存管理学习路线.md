::: abstract 本章定位
本目录覆盖《Operating System Concepts》第 9 版 Ch8 Main Memory 与 Ch9 Virtual Memory：从"地址怎么翻译"（分页/分段/页表）到"内存不够用了怎么办"（虚拟内存/按需分页/页面置换），最后落到 Linux 的 zone、buddy、slab、OOM 与 free 命令。核心一句话：**内存管理的本质是用页表这个"翻译器"把逻辑地址空间虚拟化到有限的物理帧上，再用置换与回收策略让进程在内存吃紧时依然能跑**。
:::

内存是"速度与容量的中间层"：寄存器 < 缓存 < **主存** < 磁盘。CPU 每访问一次数据都要经过主存，主存的访问速度直接决定系统性能，而主存容量决定系统能同时装下多少进程。本系列围绕三个问题展开：

1. **怎么把进程的逻辑地址翻译成物理地址？** —— 连续分配（01）、分页（02）、分段与段页式（03）
2. **物理内存不够怎么办？** —— 虚拟内存、按需分页（04）、页面置换（05）
3. **在 Linux 上怎么看、怎么调？** —— mmap、zone/buddy/slab、free 命令（06）

## 2. 推荐学习顺序

**主线（必读，按顺序）**：

```
01 基础与连续分配 → 02 分页与页表 → 03 分段与段页式
        ↓                            ↓
04 虚拟内存与按需分页 → 05 页面置换算法 → 06 性能与系统调优
```

- **01 → 02**：先明白"为什么要虚拟化地址"（连续分配的空间浪费），再学分页这个答案。
- **02 → 03**：分页解决了碎片但不符合逻辑视角，分段补齐"逻辑视图"，二者结合成段页式。
- **02/03 → 04**：有了页表机制，才能把"不在内存的页"标记出来，实现按需分页。
- **04 → 05**：按需分页引发"内存满了要换谁"的问题，页面置换算法登场。
- **05 → 06**：置换、帧分配、TLB 都是性能问题，最后看 Linux 内核怎么工程化实现。

**分支（按需）**：
- 只面试算法 → 重点 02、05，手算地址转换和缺页次数。
- 只做工程排障 → 03 的 `/proc/pid/maps`、04 的 VmRSS、06 的 free/meminfo 直接看。
- 想追 Linux 内核 → 02 多级页表、06 buddy/slab/kswapd 两篇串联。

## 3. 六篇速览

| 篇目 | 一句话 |
|---|---|
| [内存管理基础与连续分配](/kb/os/内存/01-内存管理基础与连续分配/) | 把进程放进一整块连续内存，靠基址+限长寄存器翻译并保护地址，代价是外部碎片和低效的紧凑。 |
| [分页与页表结构](/kb/os/内存/02-分页与页表结构/) | 把内存切成等大帧、把进程切成等大页，用页表做任意映射，消灭外部碎片；页表太大就用多级/倒置页表。 |
| [分段与段页式](/kb/os/内存/03-分段与段页式/) | 按逻辑段（代码/数据/栈）给进程分内存，段表记 base+limit；与分页结合成段页式，x86 的 GDT/LDT 即此思想的实现。 |
| [虚拟内存与按需分页](/kb/os/内存/04-虚拟内存与按需分页/) | 让磁盘当"内存的延伸"，只把用到的页调入内存，其余标记 invalid，缺页时按 10 步流程处理；EAT 告诉你缺页有多贵。 |
| [页面置换算法](/kb/os/内存/05-页面置换算法/) | 内存满时选谁滚蛋：OPT 最优但不可实现，LRU 接近最优但太贵，Clock 是工程折中；工作集模型根治颠簸。 |
| [内存性能与系统调优](/kb/os/内存/06-内存性能与系统调优/) | 帧怎么分、页多大好、TLB 靠局部性；Linux 用 zone+buddy+slab 管物理页，用 kswapd 回收，用 OOM killer 兜底。 |

## 4. 实验清单

::: important 实验原则
每个机制都要能"用眼睛看到"。先学概念，再用下面的命令在 Linux 上验证，缺一不可。
:::

| 实验 | 命令 | 验证的知识点 |
|---|---|---|
| 页大小 | `getconf PAGESIZE` | 分页的基本单位（通常 4096 = 4KB） |
| 物理内存总量 | `free -h`、`cat /proc/meminfo | grep MemTotal` | 物理内存规模、free 字段含义 |
| 进程虚拟内存分布 | `cat /proc/$$/maps`、`pmap $$` | 用户态布局：text/data/heap/stack/mmap 区域 |
| RSS 与虚拟内存 | `cat /proc/$$/status | grep -E "VmSize|VmRSS|VmPeak"` | 虚拟地址 vs 常驻物理页的区别 |
| 页错误计数 | `perf stat -e page-faults,minor-faults,major-faults ls -R /usr` | 按需分页：首次访问触发 minor fault |
| 交换活动 | `vmstat 1` 观察 `si`/`so` 两列 | 缺页换入换出、颠簸迹象 |
| 内存回收 | `cat /proc/meminfo | grep -E "Dirty|Writeback|DirtyExpireCentisecs"` | pdflush/kswapd 写回脏页机制 |
| 进程内存映射 | `cat /proc/pid/smaps` 的 PSS/RSS 列 | 共享页计数（PSS 按比例摊分共享页） |
| 页表大小 | `grep Pmd /proc/meminfo`（`PageTables` 字段） | 页表本身的真实内存开销 |

推荐实验流程：

```bash
# 1. 页大小与总内存
getconf PAGESIZE
free -m

# 2. 看一个普通进程（如当前 shell）的地址空间
pmap $$ | head -20
cat /proc/$$/maps | head -20
grep -E "VmSize|VmRSS|VmData|VmStk" /proc/$$/status

# 3. 用 strace/perf 观察缺页
perf stat -e page-faults,minor-faults,major-faults ls /usr > /dev/null

# 4. 观察内存压力下的交换
vmstat 1 5
free -m  # 注意 available 字段
```

## 5. 常见面试考点清单

**必考（算法手算类）**：
- 给定逻辑地址 + 页大小 + 页表，算物理地址。
- 页表大小计算（单级/多级）。
- 逻辑地址拆分成"页号 + 偏移"的位数计算。
- 首次/最佳/最差适配在给定空洞序列下如何分配。
- FIFO / LRU / OPT / Clock 在给定引用串下算缺页次数。
- Belady 异常（FIFO 帧数增加缺页反而变多）。
- EAT 有效访问时间计算（含缺页率 p 的参数方程）。
- 多级页表各级偏移位数、倒置页表大小。

**常考（概念对比类）**：
- 逻辑地址 vs 物理地址 vs 虚拟地址。
- 内部碎片 vs 外部碎片，分页为什么消除外部碎片。
- 分页 vs 分段（8 点对比）。
- 虚拟内存为什么能比物理内存大。
- 按需分页与预调页（prepaging）。
- LRU 为什么最优却不可实现；Clock 如何近似 LRU。
- 工作集模型怎么定义、怎么解决颠簸。
- 全局置换 vs 局部置换。

**进阶（Linux 工程类）**：
- `free` 输出每列含义、`buff/cache` 与 `available` 的区别。
- OOM killer 的触发逻辑与 `oom_score_adj`。
- kswapd 的回收水位（high/low/min watermark）。
- mmap 文件映射与 `MAP_SHARED`/`MAP_PRIVATE` 的内存语义。
- 进程 RSS 为什么小于 VSZ、共享页如何计算 PSS。

::: abstract 本章定位
分页解决了"怎么翻译地址"，但物理内存仍然有限——装不下更大的程序、也装不下更多并发进程。本章给出**虚拟内存（Virtual Memory）**方案：把磁盘当作内存的延伸，**只把用到的页调入内存**（按需分页，demand paging），用不到的页留在磁盘，需要时通过**缺页中断**换入。本章核心：缺页的完整处理流程、valid-invalid 位、写时复制（COW），以及一个面试必考的公式——**有效访问时间 EAT = (1-p)·内存访问 + p·缺页处理**。
:::

## 1. 虚拟内存：把磁盘当内存延伸

### 1.1 思想

传统加载：进程执行前，整段可执行文件必须全部装入内存。虚拟内存：**只加载当前需要的页**，其余页保留在磁盘（swap 区或文件）中，需要时再调入。

```text
┌──────────┐        按需调入         ┌─────────────┐
│ 进程地址空间│ ◄──────────────────► │  物理内存     │
│ (虚拟,很大)│                       │ (帧有限)      │
│          │  未用页留在磁盘          └─────────────┘
│          │ ────────────────────────► 磁盘（swap/文件）
└──────────┘        换出/换入
```

由此做到两件事：
1. **程序可以比物理内存大**：只跑当前用到的部分。
2. **并发度提高**：物理内存同时装下更多进程的部分页。

### 1.2 虚拟内存的前提

- 分页/分段机制（[分页与页表结构](/kb/os/内存/02-分页与页表结构/)）：每页/每段能独立按需驻留。
- 页表的存在位（valid-invalid）：标记页在不在内存。
- 缺页中断机制：访问不在内存的页时陷入内核处理。
- 磁盘空间：swap 区必须足够放换出的页。

## 2. 按需分页与缺页

### 2.1 valid-invalid 位

页表每项的存在位（valid = 页在内存，invalid = 不在）：

```text
页表条目：
┌───────────┬─────────┬─────────────┐
│  帧号      │ 存在位   │  其他控制位   │
│  20 位     │ valid   │  R/W, dirty  │
└───────────┴─────────┴─────────────┘
valid=1 → 帧号有效，正常翻译
valid=0 → 页不在内存（在磁盘），访问即触发缺页
```

::: warning 两个"无效"要分清
**invalid 且未分配**：页号超出进程合法地址空间（真非法访问，直接杀掉进程）；**invalid 但已分配在磁盘**：页只是暂时被换出（正常缺页，按需调入后继续执行）。区分靠页表 + 进程地址空间的合法性检查。
:::

### 2.2 缺页处理流程（10 步）

访问一个 invalid 页时，硬件抛 page fault，控制权交内核。教材标准 10 步：

1. **陷入内核**：CPU 检测到缺页（PTE 存在位=0），保存现场，转入内核态缺页处理。
2. **保存现场**：保存用户程序的寄存器与进程状态（方便恢复执行）。
3. **确认中断类型**：OS 判断这次 trap 是缺页（而非其他异常）。
4. **检查合法性**：查内部页表/PCB 确认该访问合法；若页号越界或未分配 → 非法访问，终止进程（segfault）。
5. **找到磁盘位置**：在文件系统/swap 中定位该页的磁盘地址（从 PCB 或页表旁路记录中取）。
6. **分配空闲帧**：从空闲帧列表拿一帧；若无空闲帧，先执行**页面置换**（见 [页面置换算法](/kb/os/内存/05-页面置换算法/)），选一个牺牲页换出。
7. **调度磁盘读**：发起磁盘 I/O，把该页读入新帧。
8. **等待 I/O**：进程进入等待状态（睡眠），调度器让出 CPU 给别的进程；磁盘完成后发中断唤醒。
9. **更新页表**：该页 PTE 的存在位置 1，帧号填新帧；若换出了脏页则其 I/O 也同步完成。
10. **恢复执行**：回到触发缺页的那条指令重新执行（该指令会再次访问内存，这次页已在内存，正常完成）。

```text
访问页 P → PTE.valid=0 → 缺页 trap
   ┌────────────────────────────┐
   │ 1 陷入内核  2 保存现场      │
   │ 3 确认为缺页 4 检查合法性    │ ← 非法→杀掉进程
   │ 5 定位磁盘页 6 找空闲帧      │ ← 无帧→先置换(05)
   │ 7 发起磁盘读 8 等待 I/O      │
   │ 9 更新页表(valid=1)         │
   └────────────┬───────────────┘
                ▼
  10 回到原指令重执行 → 命中
```

::: important 为什么"回到原指令重执行"
触发缺页的指令可能读、可能写，甚至跨多页（如一条指令访问多个内存操作数）。第 5 步的指令指针被保存，缺页完成后从**该指令重新开始**最安全——避免"部分执行"的副作用。
:::

## 3. 性能：缺页率与 EAT

缺页是虚拟内存的性能分水岭：内存访问是**纳秒级**，磁盘 I/O 是**毫秒级**，一次缺页比一次命中慢上万倍。

### 3.1 EAT 公式

设：
- 内存访问时间 = `ma`（如 200ns）
- 缺页服务时间 = `pfs`（如 8ms = 8,000,000ns，含换出/换入）
- 缺页率 = `p`（0~1）

```
EAT（有效访问时间）= (1 - p) × ma + p × pfs
```

**例题 1**：ma=200ns，pfs=8ms。

| p（缺页率） | EAT | 相对纯内存访问 |
|---|---|---|
| 0（无缺页） | 0.999×200 + 0 = 200ns | 1× |
| 1/1000 = 0.001 | 199.8 + 8000 = **8199.8ns ≈ 8.2μs** | 41× |
| 1/10000 = 0.0001 | 199.98 + 800 = **999.98ns ≈ 1μs** | 5× |

**结论**：缺页率每增加一个数量级，EAT 就被磁盘拖垮。系统设计目标：让缺页率远低于 1/10000（约十万分之一以下），这正是 [页面置换算法](/kb/os/内存/05-页面置换算法/)、[内存性能与系统调优](/kb/os/内存/06-内存性能与系统调优/) 全部工作的目标。

**例题 2（含 TLB 的二段式）**：TLB 命中率 h=0.99、TLB 访问 20ns、内存访问 100ns、缺页率 p=0.0001、缺页服务 10ms：

```
EAT = h × (20 + 100)
    + (1-h) × (20 + 100 + 100)        ← TLB miss，需再访页表+数据（简化）
    + p × 10,000,000                  ← 缺页部分
    = 0.99×120 + 0.01×220 + 0.0001×1e7
    = 118.8 + 2.2 + 1000
    = 1121ns
```

::: tip 记忆框架
EAT 计算三步：先列"命中路径"时间，再列"未命中路径"时间，最后把缺页的巨额开销按概率 p 加权进去。面试给的变量往往很简单，别漏掉缺页那一项。
:::

## 4. 写时复制（Copy-on-Write，COW）

### 4.1 问题

`fork()` 创建子进程时，若把父进程全部页复制一份——大进程 fork 一次就慢到不可用。

### 4.2 方案

COW：fork 后父子**共享**所有页，把这些页标记为**只读**（写保护）：

```text
fork 后（共享，只读）：
  父 PTE ──► 页 X（只读）
  子 PTE ──► 页 X（只读）      ← 同一物理帧，两个进程共享

某一进程要写页 X：
  触发写保护缺页（protection fault）
  OS 复制该页 → 新帧 X'，两边各自指向自己的副本（重新可写）
```

- 只有**被写的页**才复制 → fork 成本从 O(全部页) 降到 O(实际写页数)。
- 大量子进程 fork 后立即 exec（见 [进程](/kb/os/进程线程/01-进程概念与状态模型/)）时收益巨大：exec 会替换地址空间，根本不用复制旧页。
- 内核常用 **vfork**：子进程立即 exec，与父完全共享不复制。
- 内核自身也借 COW 思想：内核线程/模块间共享只读页；`mmap` 的 `MAP_PRIVATE` 也是写时复制语义。

::: warning COW 靠谁触发
COW 不靠存在位，靠**写保护位**：PTE 只读 + 写访问 → 触发"写保护缺页"，内核才复制。因此 COW 页仍会产生缺页（minor fault），但比复制全部页便宜得多。
:::

## 5. 页面置换的背景

按需分页的漏洞：进程只加载用到的页，但总内存有限，进程们抢帧。当新页要调入却没有空闲帧时，必须**淘汰一个现有页**，把帧腾出来——这就是页面置换问题（[页面置换算法](/kb/os/内存/05-页面置换算法/) 全章内容）。

```text
调入页 P 需要一帧 ──► 有空闲帧？ ──是──► 直接用
                        │
                        否
                        ▼
            选一个牺牲页 victim ──► 脏页？ ──是──► 写回磁盘
                        │                        │
                        否                       │
                        ▼                        ▼
             空闲帧 ←─────────────────────────────┘
```

两个关键决策：
1. **选谁做牺牲页**（置换算法，05 章）。
2. **每个进程分多少帧**（帧分配，06 章）。

## 6. 虚拟内存的优点与挑战

### 6.1 优点

| 优点 | 说明 |
|---|---|
| 程序不受物理内存限制 | 可运行比物理内存大的程序 |
| 提高并发度 | 更多进程能同时驻留（只占部分页） |
| 按需加载，启动快 | 只用到的页才调入，避免无效 I/O |
| 进程隔离 + 共享兼顾 | 页表天然隔离，共享页可挂多个进程 |
| 内存利用高效 | 无外部碎片，按页分配 |

### 6.2 挑战

| 挑战 | 说明 |
|---|---|
| 缺页开销巨大 | 磁盘 I/O 毫秒级，需置换算法压住缺页率 |
| 颠簸（thrashing） | 并发过多、帧不足 → 频繁缺页换页，CPU 空转（05 章） |
| 页表本身耗内存 | 多级页表/倒置页表缓解，仍要 TLB 加速 |
| swap 区需求 | 换出需要磁盘空间，swap 不足直接失败 |
| 实时性受损 | 缺页延迟不可预测，不适合硬实时 |

## 7. 本章小结

- 虚拟内存 = 磁盘当内存延伸 + 按需调入；前提是分页/存在位/缺页中断/swap 区。
- valid-invalid 位决定"在内存 or 在磁盘"；invalid 且未分配 = 非法访问，invalid 但换出 = 正常缺页。
- 缺页处理 10 步：陷入内核→保存现场→确认类型→查合法性→定位磁盘→找帧(或置换)→磁盘 I/O→等待→更新页表→恢复指令重执行。
- EAT = (1-p)·ma + p·pfs；缺页率须压到万分之一以下才不拖垮性能。
- COW：fork 共享只读页，写时复制，只复制被写的页。
- 缺帧时触发页面置换 → 引出下一章算法选择。

## 8. 自测题

**1. 为什么虚拟内存能让程序比物理内存大？**
答：按需分页只把当前用到的页调入内存，其余留在磁盘；程序运行所需的"活动页集合"远小于整个程序，物理内存只需容纳活动部分，因此可运行大于物理内存的程序。

**2. valid-invalid 位如何区分"正常缺页"和"非法访问"？**
答：PTE valid=0 时再查进程地址空间的合法性：页号在合法范围内且曾被分配 → 正常缺页，调入后继续；页号越界/未分配 → 非法访问，杀进程。硬件只报缺页，区分逻辑由 OS 完成。

**3. 缺页处理的 10 步中，为什么完成后要"回到原指令重执行"？**
答：触发缺页的那条指令可能读或写多个操作数、跨多页，缺页时指令可能只执行了一部分。为消除部分执行的副作用，恢复现场后从该指令的起始重新执行，安全且正确。

**4. ma=100ns，pfs=10ms。缺页率 p=0.001 时 EAT 是多少？缺页率降到 0.0001 呢？**
答：p=0.001：EAT=(1-0.001)×100 + 0.001×10^7 = 99.9+10000 = 10099.9ns ≈ 10.1μs。p=0.0001：99.99 + 1000 = 1099.99ns ≈ 1.1μs。缺页率降一个数量级，EAT 降约一个数量级。

**5. 为什么缺页率必须非常低（万分之一以下）？**
答：因为缺页服务（磁盘 I/O）比内存访问慢约 5 个数量级：p=0.001 时 EAT 已经接近 8~10μs（相对 100~200ns 慢约 40~100 倍），系统吞吐基本被磁盘主导。p 必须低到让缺页项占总时间可忽略。

**6. COW 与普通缺页的触发机制有何不同？**
答：普通缺页由**存在位=0**（页不在内存）触发；COW 由**写保护位**（页在内存但只读，写访问）触发。COW 触发后不换入，而是复制该帧并让两个进程各自指向独立副本。

**7. fork() 后父子进程共享页为什么要标只读？**
答：只有标只读，任一进程写该共享页时才会触发写保护缺页，OS 才能拦截并复制；若直接可写，两进程就会在不知情下改同一物理帧，破坏进程隔离语义。

**8. 页面置换发生在缺页流程的第几步？脏页与非脏页换出有何不同？**
答：第 6 步（找空闲帧时无帧 → 触发置换）。脏页换出必须先把内容写回磁盘（保数据），非脏页内容与磁盘一致，直接丢弃帧即可，无需 I/O——这就是 PTE 的 dirty 位存在的意义（见 [分页与页表结构](/kb/os/内存/02-分页与页表结构/)）。

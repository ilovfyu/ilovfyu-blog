::: abstract 本章定位
连续分配的外部碎片无法根治，本章给出方案：**分页（Paging）**。物理内存切成等大**帧（frame）**，进程地址空间切成等大**页（page）**，页→帧的映射记在**页表（page table）**里，从此地址翻译从"基址+偏移"变成"查表"。本章的核心能力是**手算**：给定逻辑地址与页表算物理地址、算页表大小、设计多级页表；最后对比哈希页表/倒置页表这两种省内存的思路，以及分页 vs 分段。
:::

本章是全部内存系列的地基，[分段与段页式](/kb/os/内存/03-分段与段页式/)、[虚拟内存与按需分页](/kb/os/内存/04-虚拟内存与按需分页/) 都建立在页表机制之上。

## 1. 分页原理

### 1.1 帧与页

| 概念 | 含义 | 数量关系 |
|---|---|---|
| 帧（frame） | 物理内存被切成**等大小**的块 | 物理内存 4GB / 4KB = 1M 个帧 |
| 页（page） | 进程逻辑地址空间被切成**同样大小**的块 | 逻辑空间 2GB / 4KB = 512K 个页 |
| 页表（page table） | 页号 → 帧号 的映射表 | 每进程一张，每页一个表项（PTE） |

帧和页**大小必须相同**，这是分页成立的前提。在 Linux 上通常是 4KB（可用 `getconf PAGESIZE` 验证）。

### 1.2 逻辑地址拆分

设页面大小为 `2^n` 字节，逻辑地址 `d` 拆成两部分：

```
逻辑地址 d
┌─────────────────────┬────────────────────┐
│      页号 p          │    页偏移 offset   │
│   (高位, 其余位)      │   (低位, n 位)     │
└─────────────────────┴────────────────────┘
  p = d / 2^n             offset = d % 2^n
```

- **页号（page number, p）**：查页表的下标。
- **页偏移（offset, d）**：页内位置，帧内偏移与页内偏移**相同**。

翻译公式：**物理地址 = 帧号(f) × 页大小 + 页偏移**。

### 1.3 地址转换流程（ASCII 图）

```text
     逻辑地址 = (p, d)
          │
          ▼
  ┌────────────────┐
  │ 页表[p] → 帧号f  │   ← 查页表（下标 p，得到 f）
  └────────────────┘
          │ f
          ▼
 物理地址 = f × 页大小 + d ──→ 访问物理内存
```

页号与帧号**不必连续对应**——分页最大的自由是"进程的页可以放在任何空闲帧里"，这正是外部碎片消失的原因。

### 1.4 地址转换例题（教材经典）

页大小 = 100 字节，页表为：

| 页号 p | 帧号 f |
|---|---|
| 0 | 7 |
| 1 | 2 |
| 2 | 4 |
| 3 | 6 |

求逻辑地址 **346** 对应的物理地址：

```
p = 346 / 100 = 3
offset = 346 % 100 = 46
查表：页 3 → 帧 6
物理地址 = 6 × 100 + 46 = 646
```

求逻辑地址 **250**：

```
p = 250 / 100 = 2，offset = 50
页 2 → 帧 4
物理地址 = 4 × 100 + 50 = 450
```

### 1.5 例题：4KB 页 + 十六进制地址

页大小 4KB = 2^12，逻辑地址 32 位 = 页号 20 位 + 偏移 12 位。逻辑地址 `0x12345678`：

```
0x12345678
 └─高20位─┘ └低12位┘
 页号=0x12345   偏移=0x678
若页表：页 0x12345 → 帧 0x5678
物理地址 = 0x5678 × 0x1000 + 0x678 = 0x5678000 + 0x678 = 0x5678678
```

::: tip 技巧
页大小是 2 的幂时，"页号=地址右移 n 位，偏移=地址与 (2^n-1)"。若页表只给出某几页的映射，先算 p 和 offset，再查页表；查不到（p 越界）就是非法访问。
:::

## 2. 页表项 PTE

每个页表项（Page Table Entry）记录"该页映射到哪个帧"以及控制位。常见字段：

| 字段 | 作用 |
|---|---|
| 帧号（Frame Number / PFN） | 物理帧号，20~24 位，核心数据 |
| 存在位（present / valid bit） | 页是否在内存中（在 = 1）。缺页判断靠它 |
| 读/写位（R/W） | 页是否可写（COW、只读代码页需要） |
| 用户/内核位（U/S） | 该页是否允许用户态访问 |
| 访问位（accessed） | 该页最近是否被访问过（置换算法 [页面置换算法](/kb/os/内存/05-页面置换算法/) 用） |
| 脏位（dirty） | 该页是否被写过（写过的页换出时要回写磁盘） |
| 缓存控制（PWT/PCD） | 页面级 cache 策略 |

```text
x86-32 页表项（4 字节）示意：
┌───────────────┬──┬─┬─┬──┬─┬───┬──┐
│  帧号(20位)    │AV│0│D│A│U│R│P │
└───────────────┴──┴─┴─┴──┴─┴───┴──┘
   帧号(物理地址高20位)  D=脏位 A=访问位 U=用户 R=可写 P=存在位
```

::: important 存在位与缺页
存在位 = 0 时，CPU 查到该 PTE 会触发 **page fault**（缺页中断）。它把"分页"和"按需分页"（[虚拟内存与按需分页](/kb/os/内存/04-虚拟内存与按需分页/)）直接连通：页表不只在内存内做映射，还负责标记"这个页现在不在内存"。
:::

## 3. 页表大小计算

**单级页表**大小 = 页表项数 × PTE 大小，页表项数 = 页数 = 逻辑地址空间 / 页大小。

**例题**：32 位逻辑地址、4KB 页、PTE 4 字节：

```
页数 = 2^32 / 2^12 = 2^20 = 1,048,576
页表大小 = 2^20 × 4B = 4MB
```

4MB 页表放在哪？**每进程一张**，且页表本身要常驻内存。若同时 100 个进程 → 400MB 只装页表。

**例题（64 位）**：64 位逻辑地址、4KB 页、PTE 8 字节：

```
页数 = 2^64 / 2^12 = 2^52
页表大小 = 2^52 × 8 = 2^55 字节 ≈ 32 PB —— 不可能
```

这就是必须引入**多级页表**的根本原因。

## 4. 多级页表

把页表再切小，形成树状结构：外层页表项指向内层页表，**只有实际用到的内层表才分配**，大量未用地址空间不再占内存。

### 4.1 二级页表（32 位地址）

32 位地址拆成：`p1(10位) | p2(10位) | offset(12位)`。

- 页大小 = 2^12 = 4KB；每页可放 2^12/4 = 2^10 = 1024 个 PTE。
- 二级页表 = 1024 项 × 4B = 4KB，正好一页。
- 外层页表 = 1024 项 × 4B = 4KB。

```text
逻辑地址 (32 位)
┌───────┬───────┬──────────┐
│  p1   │  p2   │  offset  │
│ 10位  │ 10位  │   12位   │
└───┬───┴───┬───┴──────────┘
    ▼       ▼
外页表[p1]──►内页表[p2]──►帧号 ──► 物理地址
(1024项)   (1024项，按需分配)
```

**内存开销对比**：假设进程只用前 8MB 地址空间（= 2048 个页，恰好 2 个内层表全满）。

| 方案 | 开销 |
|---|---|
| 单级页表 | 2^20 × 4B = **4MB**（强制全部分配） |
| 二级页表 | 外页表 4KB + 2 个内页表 8KB = **12KB** |

二级页表在"地址空间稀疏"时优势巨大；地址空间满映射时二级页表略多一点（多了个外层表），但量级相同。

::: warning 满映射时二级页表不是更省
若进程把 4GB 全用上，二级页表 = 外 4KB + 1024 × 内 4KB ≈ 4MB，与单级相当。多级页表的价值在于**按需分配**，而不是压缩常数。
:::

### 4.2 四级页表（x86-64 标准）

64 位线性地址取低 48 位（canonical 形式），拆成 4 级：

```
┌────┬────┬────┬────┬───────┐
│PML4│PDPT│  PD│  PT│ offset│  每级 9 位（2^9=512 项）
│ 9位│ 9位│ 9位│ 9位│  12位 │
└────┴────┴────┴────┴───────┘
 9+9+9+9+12 = 48 位
```

- 每级页表 = 512 × 8B = 4KB，正好一页，天然支持按页分配。
- 只有被访问地址路径上的页表才分配，空地址空间零成本。

## 5. 省内存的另两种页表

### 5.1 哈希页表（Hashed Page Table）

地址空间大于 32 位（64 位系统）时常用：以**页号**做哈希，桶内放若干 `<页号, 帧号>` 条目（链式解决冲突）。查找：`哈希(页号) → 桶 → 遍历链比对页号`。

- 优点：页表大小与"使用中的页数"成正比，而非地址空间大小。
- 缺点：哈希冲突多时查找退化；还有"虚拟页号 + 链指针"的空间开销。

### 5.2 倒置页表（Inverted Page Table）

**反向**：不再"每进程一张、按页号索引"，而是**全系统一张、按帧号索引**——每个物理帧一项。

| 项内容 | 说明 |
|---|---|
| pid（进程标识） | 标明哪个进程占用此帧 |
| 页号（virtual page number） | 该进程的哪个虚拟页映射到此帧 |
| 控制位 | 访问/脏/锁定位 |

**例题**：物理内存 8GB、4KB 页、每项 16 字节：

```
帧数 = 8GB / 4KB = 2^23 = 8M 个帧
倒置页表大小 = 8M × 16B = 128MB（全系统只有这一张）
```

对比：若用 64 位虚拟地址的正向页表，理论上是 2^52 × 8B = 32PB，完全不可行。倒置页表把页表大小钉死在"物理帧数"上。

**代价**：按逻辑地址查物理地址时，只能**顺序扫描**找 `(pid, 页号)` → 慢。优化：配合哈希表（把 `(pid,页号)` 哈希到桶再线性查），以及用 TLB 缓存最近结果。

| 方案 | 大小与什么成正比 | 查表方式 | 适用 |
|---|---|---|---|
| 单级页表 | 地址空间 | O(1) 下标 | 32 位、小空间 |
| 多级页表 | 实际使用的页表路径 | 多级索引 | 64 位主流 |
| 哈希页表 | 使用中的页数 | 哈希+链 | 64 位地址空间 |
| 倒置页表 | 物理帧数 | 扫描/哈希 | 内存物理规模远小于虚拟空间 |

## 6. 分页 vs 分段

::: note 分段概念速览
分段（详见 [分段与段页式](/kb/os/内存/03-分段与段页式/)）按**逻辑含义**划分：一个段 = 一段代码/数据/栈。这里先给出对比表。
:::

| 维度 | 分页 Paging | 分段 Segmentation |
|---|---|---|
| 划分依据 | 物理等大小（页/帧固定 4KB） | 逻辑含义（段大小可变） |
| 地址拆分 | (页号, 偏移)，用户无感知 | (段号, 段内偏移)，对用户可见 |
| 页/段表 | 页表：页→帧 | 段表：base + limit |
| 外部碎片 | 无 | 有（段大小不一） |
| 内部碎片 | 有（最后一页浪费 ≤ 页大小-1） | 无 |
| 共享 | 难（需按页共享） | 易（整段共享） |
| 保护 | 按页设置 PTE 位 | 按段设置访问权限 |
| 用户视角 | 线性地址空间 | 多个独立逻辑空间 |
| 碎片补偿 | 无需要 | 需要紧凑 |

**一句话**：分页解决的是**物理空间利用率**（无外部碎片、可交换单页），分段解决的是**逻辑结构表达**（代码/数据/栈天然分开、易共享易保护）。两者不冲突——下一章把它们合体成**段页式**。

## 7. 本章小结

- 分页把内存切成等大帧、进程切成等大页，页表记录页→帧映射；物理地址 = 帧号×页大小 + 偏移。
- 翻译三步：拆页号/偏移 → 查页表得帧号 → 拼物理地址。
- PTE 关键位：存在位（决定是否缺页）、脏位（换出是否回写）、访问位（置换用）。
- 单级页表大小为"地址空间/页大小 × PTE 大小"，64 位下不可行 → 多级页表（x86-64 四级的 9|9|9|9|12 拆分）。
- 省内存三方案：多级（按路径分配）、哈希（按使用页数）、倒置（按物理帧数）。
- 分页消除外部碎片、便于交换；分段表达逻辑结构；页表的存在位为 [虚拟内存与按需分页](/kb/os/内存/04-虚拟内存与按需分页/) 的按需加载铺路。

## 8. 自测题

**1. 页大小 4KB，逻辑地址空间 16GB，求页数，以及单级页表大小（PTE 4 字节）。**
答：页数 = 2^34 / 2^12 = 2^22 = 4M 个页；页表 = 4M × 4B = 16MB。

**2. 页大小 100B，页表映射 页0→帧2、页1→帧5、页2→帧8、页3→帧1。逻辑地址 250 的物理地址？**
答：p = 250/100 = 2，offset = 50；页 2 → 帧 8；物理地址 = 8×100 + 50 = 850。

**3. 页大小 8KB，逻辑地址空间 32 位，页号占多少位？偏移占多少位？**
答：偏移 = log2(8KB) = 13 位；页号 = 32 - 13 = 19 位（页数 2^19）。

**4. 逻辑地址 0x3A48，页大小 4KB。页号和偏移各是多少（十六进制）？**
答：0x3A48 >> 12 = 0x3，offset = 0x3A48 & 0xFFF = 0xA48。即页 3、偏移 0xA48。

**5. 32 位地址、页大小 4KB、PTE 4B，采用二级页表。一个进程只用前 16MB 地址空间，页表总开销？**
答：每页 1024 个 PTE；16MB/4KB = 4096 页 = 4 个内层表。开销 = 外层 4KB + 4×内层 4KB = 20KB。（对比单级 4MB）

**6. 倒置页表为什么表项数是"物理帧数"而不是"虚拟页数"？代价是什么？**
答：倒置页表每帧一项、全系统一张，表大小只依赖物理内存（帧数），不随虚拟空间膨胀。代价：逻辑→物理的查找无法用"页号做下标"，需扫描 `(pid,页号)`，慢；通常配哈希表与 TLB 缓解。

**7. 分页为什么能消除外部碎片？又为什么会留下内部碎片？**
答：所有帧等大，进程任意页可放任意空闲帧，空闲帧不会形成"拼不起来的碎片" → 无外部碎片。但进程最后一页通常装不满，浪费 "页大小-1" 字节内 → 内部碎片（每进程平均约半页）。

**8. PTE 的 dirty 位为什么重要？没有它会怎样？**
答：dirty 位标记该页被写过。页被置换/换出时，脏页内容必须先写回磁盘，干净页可直接丢弃。若无 dirty 位，每次换出都盲目回写，磁盘 IO 翻倍，严重拖慢 [页面置换算法](/kb/os/内存/05-页面置换算法/) 中的置换性能。

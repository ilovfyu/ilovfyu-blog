::: abstract 本章定位
按需分页（[虚拟内存与按需分页](/kb/os/内存/04-虚拟内存与按需分页/)）让进程只装部分页，但物理内存有限，新页调入时必须**淘汰一个旧页**。淘汰谁？这就是页面置换算法。本章讲全部主流算法：OPT（最优但不可实现）、FIFO（最简但有 Belady 异常）、LRU（最接近最优但实现贵）、Clock/第二次机会（LRU 的工程近似）、计数类算法；并解释**工作集模型**如何根治"颠簸"（thrashing）。本章的硬核能力是**手算缺页次数**——面试高频。
:::

## 1. 置换问题背景

缺页发生时若无空闲帧，OS 选一个**牺牲页（victim）**腾出帧：

```text
新页调入 → 帧满了 → 选 victim
                      │
              victim 脏吗？
           是 ──► 写回磁盘（I/O）──► 帧空闲
           否 ──► 帧空闲（直接丢弃）
                      │
                      ▼
              新页读入该帧 → 更新页表
```

目标：**缺页次数最少**。评价标准：给定**引用串（reference string）**（如 `7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1`）和固定帧数，统计缺页数。理想下界是 OPT 的缺页数。

## 2. OPT 最优置换

**规则**：淘汰"**将来最久不再使用**"的页（向后看整个引用串）。

```text
引用串：7 0 1 2 0 3 0 4 ...
        在 3 帧中，调入 2 时淘汰谁？
        OPT 往后看：7 下次出现于第 18 位，0 在第 5 位，1 在第 14 位
        → 淘汰 7（最久不使用）
```

- 优点：缺页数最少，是**理论下界**。
- 缺点：需要预知整个未来引用串 → **离线算法**，现实不可实现。它的价值是当**基准**：衡量其他算法"离最优还差多远"。
- 现实近似：把"最近最久未用"当作"将来最久不用"的预测 → LRU。

## 3. FIFO 先进先出

**规则**：淘汰**最早调入**内存的页（像一个队列）。实现极简单：队列即可。

**Belady 异常**：FIFO 增加帧数，缺页次数**可能反而增加**——违反直觉，见下方完整例题。

### 3.1 Belady 异常示例

引用串 `1 2 3 4 1 2 5 1 2 3 4 5`：

| 帧数 | 算法 | 缺页次数 |
|---|---|---|
| 3 | FIFO | 9 |
| 4 | FIFO | **10**（帧更多反而更差！） |
| 3 | OPT | 7 |
| 4 | OPT | 6 |

::: warning Belady 异常的本质
FIFO 不利用页的**使用信息**，只凭到达时间淘汰。帧数从 3 增到 4，可能让某些"本可在旧帧里久住"的页被挤掉，导致未来反复缺页。LRU/OPT 都满足 **栈性质（stack property）**：帧数增加时缺页次数单调不增，不会出现 Belady 异常。
:::

### 3.2 手算：3 帧 FIFO，串 `1 2 3 4 1 2 5 1 2 3 4 5`

| 步 | 访问 | 帧内容(按到达序) | 结果 |
|---|---|---|---|
| 1 | 1 | [1] | 缺页 |
| 2 | 2 | [1,2] | 缺页 |
| 3 | 3 | [1,2,3] | 缺页 |
| 4 | 4 | 换 1 → [4,2,3] | 缺页 |
| 5 | 1 | 换 2 → [4,1,3] | 缺页 |
| 6 | 2 | 换 3 → [4,1,2] | 缺页 |
| 7 | 5 | 换 4 → [5,1,2] | 缺页 |
| 8 | 1 | 命中 | — |
| 9 | 2 | 命中 | — |
| 10 | 3 | 换 5 → [3,1,2] | 缺页 |
| 11 | 4 | 换 1 → [3,4,2] | 缺页 |
| 12 | 5 | 换 2 → [3,4,5] | 缺页 |

**缺页 = 9**。第 4 帧版手算得 10，出现 Belady 异常。

## 4. LRU 最近最少使用

**规则**：淘汰**最近最久未使用**的页（"过去最久没用的，未来多半也不用"——对 OPT 的务实预测）。

### 4.1 两种硬件实现

| 实现 | 机制 | 代价 |
|---|---|---|
| 计数器（counter） | 每个页表项记录"上次访问时间戳"，置换时找最小时间戳 | 每页一个寄存器/内存；置换时全表扫描 |
| 栈（stack） | 访问某页就把它移到栈顶，栈底即 LRU 页 | 每次访问要改栈（双链表），链表操作有开销 |

### 4.2 特性

- 满足栈性质 → **无 Belady 异常**；缺页次数通常远低于 FIFO、接近 OPT。
- 缺点：**精确 LRU 实现代价高**（每个访问都要更新时间戳/移动栈节点），硬件负担重。
- 现实方案：**近似 LRU**（Clock 算法）。

## 5. 近似 LRU：Clock / 第二次机会

利用 PTE 的 **reference（访问）位**，由硬件在每次访问时自动置 1，OS 定期/惰性检查，近似出"最近是否被用过"。

### 5.1 第二次机会算法（Second-Chance）

把物理帧排成**环形队列**，每个帧一个引用位 + 一个替换指针（钟表指针）：

1. 指针指向的帧 **R=1**（最近被用过）→ 清 R=0，指针前进，给它"第二次机会"。
2. 指针指向的帧 **R=0** → 淘汰它。

```text
        ┌── 帧0(R=1) ──┐
        │               ▼
    帧3(R=0)         帧1(R=0)
        ▲               │
        └── 帧2(R=1) ──┘
指针初始指向帧0：R=1→清0→前进；帧1 R=0→淘汰帧1
```

### 5.2 Clock 完整过程示例

5 个帧，引用位变化：

| 步骤 | 指针位置 | 该帧 R | 动作 |
|---|---|---|---|
| 缺页，指针指帧0 | 帧0 R=1 | 清 0，前进 |
| 缺页，指针指帧1 | 帧1 R=0 | **淘汰帧1**，装入新页置 R=1 |
| 缺页，指针指帧2 | 帧2 R=1 | 清 0，前进 |
| 缺页，指针指帧3 | 帧3 R=1 | 清 0，前进 |
| 缺页，指针指帧4 | 帧4 R=0 | **淘汰帧4** |

**要点**：一轮指针扫过的帧中，最近被用过的页被保下来（R=1 被"放行"一次）。若所有帧都被扫过且 R 全为 0，则退化为 FIFO。

::: tip 为什么说它是 LRU 近似
R 位只有"用过/没用过"一比特，无法区分"多久前用过"。但局部性原理保证：最近用过的页大概率近期还会用，保 R=1 的页 ≈ 保 LRU 会保的页。成本远低于精确 LRU。
:::

### 5.3 增强型 Clock（带脏位）

同时参考 **R（访问位）+ D（脏位）**，四类页按优先级淘汰：

| 优先级 | (R,D) | 含义 | 处理 |
|---|---|---|---|
| 0 | (0,0) | 最近没用过、且干净 | 最佳牺牲品（无需写回） |
| 1 | (0,1) | 最近没用过、但脏 | 需写回，次优 |
| 2 | (1,0) | 最近用过、干净 | 保护一轮 |
| 3 | (1,1) | 最近用过、且脏 | 最差牺牲品 |

实现：多轮扫描，第一轮找 (0,0)，第二轮把 (0,*) 处理时顺便清 R……直到找到合适牺牲页。D 位的价值：避免换出脏页时额外的磁盘写。

## 6. 计数类算法：LFU / MFU

| 算法 | 规则 | 问题 |
|---|---|---|
| LFU 最不常使用 | 淘汰**使用次数最少**的页 | 早期多用过的页可能永不被换（哪怕现在不用） |
| MFU 最常使用 | 淘汰**使用次数最多**的页（理由是"用得最多的页可能已用完"） | 反直觉，现实中少用 |

二者都需为每页维护计数器，且存在"旧历史主导"的缺陷，实用价值有限。**结论：Clock 及其变种是工业界主流**。

## 7. 页缓冲（Page Buffering）

置换不是"立即腾帧"，而是维护一个**空闲帧池**：

- 被置换的**干净页**直接进空闲池，新页优先从池中拿。
- 被置换的**脏页**先进"待写回列表"，后台慢慢写磁盘，写完再入池。
- 若置换的页很快又要用，还能从池中**无 I/O 找回**（页内容还在）。

效果：把置换的 I/O 延迟化、批量化的缓冲，显著降低缺页感知延迟。现代 OS（Linux 的 per-cpu pageset、页面回收路径）都带这种思想。

## 8. 工作集模型与预调页

### 8.1 工作集（Working Set）

局部性原理：进程在某个时间段只密集访问一小撮页。定义窗口大小 **Δ**（最近 Δ 次访问），**工作集 WS(t, Δ) = 过去 Δ 次引用中实际访问到的页集合**，其大小 **WSS** 随 Δ 单调不降。

```
引用串：2 6 1 5 7 7 7 7 7 1 6 5 1 5 1 ...
Δ=10 时，过去10次访问 = {2,6,1,5,7} → WSS=5
```

**用途**：
- 判断"进程到底需要多少帧"：WSS 就是合理帧数下界。
- **预调页（prepaging）**：换入时顺带把工作集内的相邻页一起调入，减少缺页次数（以可能浪费的 I/O 换取少缺页）。

### 8.2 工作集实现（书 9 版）

让引用位带上"上次使用时间"：系统定期扫描所有页，若某页 R=1 且自上次扫描未变，则认为它在工作集内（更新"上次使用时间"）；若某个页"上次使用时间"早于当前时间 - τ（τ≈Δ），则从工作集中剔除，**可被换出**。现代实现多用 Clock 指针维护近似工作集。

## 9. 颠簸（Thrashing）

### 9.1 症状与根因

**症状**：进程频繁缺页、持续换入换出，CPU 使用率反而**暴跌**（大部分时间在等磁盘）。

**根因**：系统让太多进程并发驻留，每个进程的帧数 < 工作集大小 → 进程刚换入的页立刻又被换出，永远缺页。

```text
进程增多 → 每进程帧数下降 → 缺页率飙升 → 进程等待 I/O → CPU 空闲
     ↑                                                      │
     └── OS 发现 CPU 空闲 → 又放更多进程进入 ──┐               │
                                             ▼               │
                              缺页率更高 → 颠簸螺旋 ◄────────┘
```

### 9.2 解决办法

| 方案 | 思想 |
|---|---|
| 工作集模型 | 只为满足 WSS 的进程分帧；不足就不调度它 |
| 缺页频率（PFF）控制 | 监控每进程缺页率：过高→加帧；过低→减帧。保缺页率稳定在目标区间 |
| 降低多道程序度 | 把部分进程**换出到磁盘**（swap），释放帧 |
| 平衡集（balancing set） | 调度器维护一个"能容纳进内存的进程集合"，只调度集合内的进程 |

::: important 面试记忆锚点
颠簸 = **多道程序度太高** 导致 **每进程帧数 < 工作集**，从而缺页率失控。解法一句话：**按工作集分帧、控住多道程序度**。
:::

## 10. 完整手算对比：经典引用串

引用串 `7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1`，**3 个帧**。三种算法全表（括号内为该步后帧内容，* 表示缺页）：

**FIFO（15 次缺页）**

| 步 | 访问 | 帧内容 | 缺页? |
|---|---|---|---|
| 1 | 7 | [7] | * |
| 2 | 0 | [7,0] | * |
| 3 | 1 | [7,0,1] | * |
| 4 | 2 | 换7→[2,0,1] | * |
| 5 | 0 | 命中 | |
| 6 | 3 | 换0→[2,3,1] | * |
| 7 | 0 | 换1→[2,3,0] | * |
| 8 | 4 | 换2→[4,3,0] | * |
| 9 | 2 | 换3→[4,2,0] | * |
| 10 | 3 | 换0→[4,2,3] | * |
| 11 | 0 | 换4→[0,2,3] | * |
| 12 | 3 | 命中 | |

| 19 | 0 | 换1→[7,0,2] | * |

**OPT（9 次缺页）**

| 步 | 访问 | 帧内容 | 淘汰理由 | 缺页? |
|---|---|---|---|---|
| 1 | 7 | [7] | — | * |
| 2 | 0 | [7,0] | — | * |
| 3 | 1 | [7,0,1] | — | * |
| 4 | 2 | 换7 | 7 下次出现最晚(第18步) | * |
| 5 | 0 | 命中 | | |
| 6 | 3 | 换1 | 1 下次出现(14)最晚 | * |
| 7 | 0 | 命中 | | |
| 8 | 4 | 换2 | 2 下次出现(9)较晚 | * |
| 9 | 2 | 换4 | 4 此后永不再用 | * |
| 10-13 | 3 0 3 2 | 命中×4 | | |
| 14 | 1 | 换3 | 3 此后永不再用 | * |
| 15-17 | 2 0 1 | 命中×3 | | |
| 18 | 7 | 换2 | 2 此后永不再用 | * |
| 19-20 | 0 1 | 命中×2 | | |

**汇总**：FIFO=15，LRU=12，OPT=9。OPT 是下界，LRU 逼近它，FIFO 最差。这正是 [内存性能与系统调优](/kb/os/内存/06-内存性能与系统调优/) 里"帧分配 + Clock"等工程决策的性能来源。

## 11. 本章小结

- 置换 = 缺页且无空闲帧时选 victim；脏页要回写、干净页可直接丢。
- OPT 淘汰"将来最久不用"，缺页下界，但离线不可实现。
- FIFO 淘汰最早调入者，实现最简，但有 **Belady 异常**（帧多缺页反而多）。
- LRU 淘汰"最近最久未用"，无 Belady、接近 OPT，但精确实现昂贵。
- Clock/第二次机会 = 环形帧 + 引用位，R=1 放行、R=0 淘汰，是工业界主流近似；增强型再加脏位分级。
- LFU/MFU 需计数器、易受历史主导，实用少。
- 页缓冲 = 空闲帧池 + 延迟回写，降低置换 I/O 感知。
- 工作集 = 窗口 Δ 内用到的页集合，决定"进程需要多少帧"；可预调页。
- 颠簸 = 帧数 < 工作集的恶性循环；解法按工作集分帧、控多道程序度。

## 12. 自测题

**1. 引用串 `1 2 3 4 1 2 5 1 2 3 4 5`，3 帧 FIFO 缺页次数？4 帧呢？这说明了什么？**
答：3 帧 = 9 次，4 帧 = 10 次（见 3.2 完整表）。说明 FIFO 存在 **Belady 异常**：增加帧数缺页反而变多，因为它完全不利用访问信息。

**2. 为什么 LRU 比 FIFO 更接近 OPT？代价是什么？**
答：LRU 用"过去最久未用"预测"将来最久不用"，与 OPT 的决策依据最接近，且满足栈性质（无 Belady）。代价：精确 LRU 每次访问都需更新时间戳或移动栈节点，硬件/软件成本高，所以实际用 Clock 近似。

**3. Clock 算法如何给一个页"第二次机会"？什么情况下退化为 FIFO？**
答：指针扫到 R=1 的帧时，不清除而是清 R=0 并前进，让它多活一轮（第二次机会）；扫到 R=0 的帧才淘汰。若所有帧在指针转一圈内 R 都已被清为 0，则退化为 FIFO（谁先到达谁先被淘汰）。

**4. 工作集模型如何判断"进程需要多少帧"？**
答：取窗口 Δ 内最近访问的页集合为工作集 WS，其大小 WSS 就是该进程的最低合理帧数。给进程的帧数 ≥ WSS 才能保证缺页率可控，否则必然频繁缺页。

**5. 什么是颠簸？根本原因和解法？**
答：颠簸 = 缺页率过高导致系统把大量时间花在换页上、CPU 利用率反而极低。根本原因：多道程序度太高，每进程帧数 < 工作集大小。解法：按工作集给足帧（或控缺页频率 PFF）、降低多道程序度、必要时换出部分进程。

**6. 引用串 `a b c d a b e a b c d e`，3 帧，LRU 缺页次数是多少？**
答：逐帧跟踪（最旧→最新）：a→[a]，b→[a,b]，c→[a,b,c]（3 缺页）；d 换 a→[b,c,d]（4）；a 换 b→[c,d,a]（5）；b 换 c→[d,a,b]（6）；e 换 d→[a,b,e]（7）；a,b 命中；c 换 e→[a,b,c]（8）；d 换 a→[b,c,d]（9）；e 换 b→[c,d,e]（10）。共 **10 次缺页**。

**7. 页缓冲（page buffering）为什么能降低缺页开销？**
答：置换的脏页先进"待写回池"异步写盘，干净页直接进空闲池；新页优先从池取帧，若被置换页很快又被用到，还可直接从池中无 I/O 找回。把"必须同步完成的换出"变成"后台慢慢写"，减少了同步等待磁盘的缺页延迟。

**8. 为什么增强型 Clock 把 (0,0) 页作为首选牺牲品？**
答：(0,0) = 最近未访问（以后大概率也不用）+ 干净（内容与磁盘一致，换出无需写回），淘汰它零 I/O、零未来代价，是成本最低的牺牲页。(1,1) 又要清位保一轮又要写回，成本最高，最后才考虑。

::: abstract 本章定位
进程要运行，代码和数据必须装进物理内存。本章回答：**"进程的地址"和"内存的地址"是什么关系？** 先讲地址的三个层次（逻辑/物理/虚拟）与三种地址绑定时机，再讲最朴素的内存管理方案——把进程放进一整块连续内存（固定分区/动态分区），由此引出两个核心问题：内部碎片、外部碎片，以及对应的三个适配算法（首次/最佳/最差）和两种补救手段（紧凑、交换）。
:::

学完本章，你会理解为什么"连续分配"不是终点——它为下一章的分页埋下两个伏笔：外部碎片无法根治、且每次换入换出要整块搬移。

## 1. 三个地址：逻辑、物理、虚拟

### 1.1 三者区别

| 地址 | 定义 | 谁在用 | 例子 |
|---|---|---|---|
| 逻辑地址（Logical Address） | CPU 生成的地址，是进程视角的地址 | 编译出的程序内部 | 程序里一条 `jmp` 指令指向的地址 |
| 物理地址（Physical Address） | 内存单元（内存总线）实际看到的地址 | 内存硬件 | 0x0001F200（真实 DIMM 上的位置） |
| 虚拟地址（Virtual Address） | 逻辑地址在虚拟内存下的叫法，两者在多数语境等价 | OS + MMU | 分页/分段前的"逻辑地址" |

::: warning 关键区分
**逻辑地址空间**是进程能看到的地址集合，**物理地址空间**是内存硬件提供的地址集合。在现代 OS 中两者通过**页表**建立映射，而 CPU 每执行一条指令访问内存时，逻辑地址都要被 **MMU** 翻译成物理地址。翻译发生在**运行时**，不是编译时。
:::

### 1.2 地址绑定的三个时机

地址绑定（Address Binding）= 把**符号地址**（`foo()`）最终确定成**物理地址**的过程，可在三个时间点发生：

1. **编译期绑定（Compile Time）**：编译时就知道进程装在哪个固定位置。若位置变化需重新编译。仅用于简单嵌入式/裸机系统。
2. **加载期绑定（Load Time）**：编译生成可重定位代码（相对地址），加载时确定物理地址并回填。若位置变化需重新加载。
3. **运行期绑定（Execution / Run Time）**：进程运行时才做映射，需硬件支持（MMU）。现代 OS 全部采用这种方式——进程可以在内存中被来回搬动（交换、紧凑）而无需重载。

```text
源代码 (符号)  →  编译/汇编  →  目标代码 (可重定位地址)  →  链接/加载  →  运行
   foo()           相对偏移      0x0000 指向段内           最终物理地址
                  └────────────── 绑定时机 ──────────────┘
  编译期绑定    加载期绑定                          运行期绑定（MMU 完成）
```

## 2. MMU 与基址+限长寄存器

运行期绑定依赖 MMU（Memory Management Unit，内存管理单元），它负责把 CPU 输出的逻辑地址翻译成物理地址。

最简单的连续分配方案用**一对寄存器**完成翻译与保护：

- **基址寄存器（base/reload register）**：进程在物理内存中的起始位置。
- **限长寄存器（limit register）**：进程地址空间的长度（物理地址上限）。

翻译规则：`物理地址 = 基址 + 逻辑地址`，且必须先检查 `逻辑地址 < 限长`，否则非法访问（越界陷阱）。

```text
        逻辑地址           物理地址
CPU ──── 346 ──────────┐
        │               │  检查 346 < 1000（limit）
        ▼               ▼
  base寄存器 = 1400   →  1400 + 346 = 1746 ──→ 内存
```

**示例**：进程基址 1400、限长 1000。
- 逻辑地址 346 → 物理地址 1746（合法）。
- 逻辑地址 1050 → `1050 > 1000`，触发越界 trap，OS 终止该进程。

::: tip 两种寄存器的分工
基址寄存器负责"定位"（把进程从物理内存里找出来），限长寄存器负责"保护"（防止进程访问邻居进程的内存）。这对寄存器就是最早的地址隔离手段，也是"进程间不能互相踩内存"的硬件基础。
:::

## 3. 连续内存分配

进程占用的物理内存必须连续的一段区域，叫**连续内存分配（Contiguous Memory Allocation）**。

### 3.1 固定分区（Fixed Partitioning）

内存被预先切成**固定大小**的若干分区：

- 分区大小可相等或不等，划分在系统启动/初始化时完成，之后不变。
- 每个分区同时只能装一个进程。

```text
| 分区0 | 分区1 | 分区2 | 分区3 | 分区4 |
| 8MB   | 8MB   | 16MB  | 16MB  | 16MB  |
| 空闲  | P1    | 空闲  | P2    | 空闲  |
```

**缺点**：
- 分区大小固定，进程大小几乎不可能与分区完全匹配 → **内部碎片**。
- 若所有分区都被占满，即使空闲空间总和够大，进程也进不来（进程无法跨分区使用多个不连续小块）。

::: warning 内部碎片（Internal Fragmentation）
已分配的分区内**无法再被利用**的剩余空间。例如 16MB 分区装入 11MB 进程，浪费 5MB 属于内部碎片。它"在分区内部"，外部看不见也分不出去。
:::

### 3.2 动态分区（Dynamic Partitioning）

不再预先切块，进程到来时从内存的**空洞（hole，空闲块）**里按需切一块给它：

```text
进程 P1(12MB) 到来：从 256MB 内存中切出 12MB
┌──────────────────── 256MB ────────────────────┐
│ P1 12MB │ 空闲 244MB                          │
└─────────┴─────────────────────────────────────┘
进程 P2(9MB) 到来：从空洞里再切
│ P1 12MB │ P2 9MB │ 空闲 235MB                 │
```

**外部碎片（External Fragmentation）**：随着进程频繁创建/退出，内存被切成越来越小、散布各处的空洞，**空洞总和大却无法容纳一个连续的大进程**。它发生在"分区之间的空隙"，与内部碎片相对。

## 4. 三种适配算法

当有新进程需要大小为 `s` 的内存时，从所有空闲块中选择哪一个？三种经典策略：

| 算法 | 规则 | 特点 |
|---|---|---|
| **首次适配 First-Fit** | 从地址**开头向后**扫描，选第一个 `>= s` 的空洞 | 最快（找到就停）；地址靠前的区域先被切碎，靠后的保留大块 |
| **最佳适配 Best-Fit** | 选所有 `>= s` 的洞中**最小**的那个 | 产生最小剩余块；每次要全表扫描；留下大量无法用的小碎片 |
| **最差适配 Worst-Fit** | 选**最大**的那个洞 | 剩余块依然很大可再用；同样需全表扫描，且大洞很快被切碎 |

::: tip 实践结论
现代研究表明 **首次适配**在速度和空间利用率上都是**最好**的（甚至优于最佳适配）。原因：最佳适配留下的"小碎渣"往往无法被任何进程利用，反而加剧外部碎片。
:::

### 4.1 完整例题（书 9 版经典题）

内存按顺序存在 5 个空洞：`100KB, 500KB, 200KB, 300KB, 600KB`。依次到达 4 个进程：`212KB, 417KB, 112KB, 426KB`。分别用三种算法分配。

**首次适配 First-Fit**（从前往后找第一个够大的洞）：

| 进程 | 选择 | 结果（该洞剩余） |
|---|---|---|
| 212 | 500KB（100 不够，500 第一个够） | 288KB |
| 417 | 600KB（100/288/200/300 都不够） | 183KB |
| 112 | 288KB（100 不够，288 第一个够） | 176KB |
| 426 | **失败**（100/176/200/300/183 均 < 426） | — |

**最佳适配 Best-Fit**（选 >= 需求的最小洞）：

| 进程 | 选择 | 结果 |
|---|---|---|
| 212 | 500KB（600 也够，选更小的 500） | 288KB |
| 417 | 600KB（唯一够的洞） | 183KB |
| 112 | 183KB（100 < 112 不可用；183 最小） | 71KB |
| 426 | **失败**（100/288/200/300/71 均 < 426） | — |

**最差适配 Worst-Fit**（选最大的洞）：

| 进程 | 选择 | 结果 |
|---|---|---|
| 212 | 600KB（最大） | 388KB |
| 417 | 500KB（388 < 417，选 500） | 83KB |
| 112 | 388KB（最大） | 276KB |
| 426 | **失败**（100/83/200/300/276 均 < 426） | — |

::: important 结论
三种算法在该例中 4 个进程都无法全部装下。这正说明**连续分配的瓶颈**：空洞被切碎（尤其 Best-Fit 留下 71KB 这种"废渣"），进程一大就装不进去。注意观察 Best-Fit 留下的碎片最小、最碎，最差适配的碎片最大。
:::

## 5. 紧凑与交换

面对外部碎片与内存不足，有两个补救手段。

### 5.1 紧凑（Compaction）

把进程往内存一端挪动，把分散的空洞合并成一个大空洞：

```text
紧凑前：
| P1 | 洞2MB | P2 | 洞6MB | P3 | 洞1MB |
紧凑后：
| P1 | P2 | P3 | 洞9MB                     |
```

- 可行前提：地址绑定发生在**运行期**（有 MMU/重定位硬件），进程可以自由搬移。
- 代价：**搬移是纯 CPU 开销**，大内存上极贵；且搬移期间该进程不可运行。
- 因此只有在"外部碎片很严重"且"紧凑成本低于扩容成本"时才值得做。

### 5.2 交换（Swapping）

内存吃紧时，把暂时不运行的进程**整块换出到后备存储**（backing store，通常是 swap 分区/文件），把内存腾给活跃进程；需要时再换回：

```text
         内存                      磁盘 (swap)
   +---------------+   换出 P0   +---------------+
   |  P0 (空闲)     | ◄────────── |      P0       |
   |  P1           |             +---------------+
   +---------------+   换入 P2
   |  P2           |  ◄────────── 磁盘中的 P2
   +---------------+
```

- 交换单位是整个进程（早期）或整个地址空间。
- **Roll-out / Roll-in**：调度器可把等待中的进程滚出、把高优先级的滚入。
- 现代 Linux 已不做整进程交换，而是**按页**换入换出（见 [虚拟内存与按需分页](/kb/os/内存/04-虚拟内存与按需分页/)），因为整块交换太贵。

::: warning 交换的两个代价
1. **换入换出慢**：磁盘传输远慢于内存访问，频繁交换会拖垮系统（这也是 [页面置换算法](/kb/os/内存/05-页面置换算法/) 中"颠簸"的根源之一）。
2. **交换区空间**：swap 区必须能容纳最大进程（严格说需要容纳并发换出进程的总量），swap 区不足会直接导致内存分配失败。
:::

## 6. 本章小结

- 三个地址层次：逻辑地址（进程视角）、物理地址（硬件视角）、虚拟地址（虚拟内存语境下的逻辑地址）；绑定时机分编译/加载/运行期，现代 OS 全部运行期绑定。
- MMU + 基址/限长寄存器完成"翻译 + 保护"：`物理 = 基址 + 逻辑`，越界由限长寄存器兜住。
- 连续分配 = 固定分区 / 动态分区；固定分区带来**内部碎片**，动态分区带来**外部碎片**。
- 三种适配算法：首次（最快、实际最好）、最佳（碎片最小但最碎）、最差（留大洞但大洞易被切碎）。
- 补救手段：紧凑（挪进程合并空洞，代价大）+ 交换（换出到磁盘，代价大）。

::: tip 引出下一章
连续分配的两大痛点——外部碎片难根治、整块搬移太贵——正是分页（[分页与页表结构](/kb/os/内存/02-分页与页表结构/)）要解决的：把内存切成等大帧、进程切成等大页，映射关系放进页表，外部碎片彻底消失，换入换出也变成"按页"进行。
:::

## 7. 自测题

**1. 逻辑地址、物理地址、虚拟地址三者什么关系？**
答：逻辑地址是 CPU/进程视角的地址；物理地址是内存硬件视角的地址；虚拟内存语境下"虚拟地址"就是逻辑地址。运行期经 MMU 翻译，逻辑地址 → 物理地址。

**2. 为什么现代 OS 必须采用运行期地址绑定？**
答：只有运行期绑定（靠 MMU）才能让进程在运行时被搬移（交换、紧凑），编译/加载期绑定下地址在装载时定死，进程不能移动，也无法实现虚拟内存。

**3. 基址寄存器和限长寄存器各自的作用？给出越界判断逻辑。**
答：基址寄存器 = 进程物理起始地址（定位），限长寄存器 = 进程空间长度（保护）。对逻辑地址 `d`：先判 `d < limit`，合法则 `物理 = base + d`，非法则越界 trap。

**4. 某进程基址 3000、限长 500。逻辑地址 450 和 4600 分别对应什么物理地址？**
答：450 < 500 合法 → 物理地址 3000+450 = 3450；4600 > 500 非法 → 触发越界异常，无物理地址。

**5. 内部碎片与外部碎片本质区别？分页消除了哪种？**
答：内部碎片 = 分配出去但用不完的块内空间（固定分区）；外部碎片 = 散布的空洞总和大却无法拼成一个连续块（动态分区）。分页（页帧等大）消除了外部碎片，但每页最后一页的剩余空间会产生内部碎片。

**6. 内存空洞（按序）50KB、120KB、70KB、200KB，进程依次请求 100KB、60KB、80KB。分别用首次/最佳/最差适配给出分配结果。**
答：
- 首次：100 → 120(余20)；60 → 70(余10)；80 → 200(余120)。三进程全部装下。
- 最佳：100 → 120(余20)；60 → 70(余10)；80 → 200(余120)。（各步都只有唯一够大的洞，结果相同）
- 最差：100 → 200(余100)；60 → 120(余60)；80 → 100(余20)。三进程全部装下。

::: note 第 6 题提示
这个序列中三个算法都能装下全部进程，但剩余碎片的分布不同。对比 [.1 完整例题（书 9 版经典题）](/kb/os/内存/01-内存管理基础与连续分配/#4.1%20%E5%AE%8C%E6%95%B4%E4%BE%8B%E9%A2%98%EF%BC%88%E4%B9%A6%209%20%E7%89%88%E7%BB%8F%E5%85%B8%E9%A2%98%EF%BC%89) 那个 426KB 装不下的例子，体会"碎片分布"如何影响后续进程的容纳。
:::

**7. 为什么说 Best-Fit 可能加剧外部碎片？**
答：Best-Fit 每次留下"最小剩余块"，长期运行会积累大量只有几 KB 的小空洞，这些洞装不下任何进程、又拼不成大块（除非紧凑），等于把可利用空间切成碎渣。

**8. 紧凑为什么要求运行期绑定？它有什么代价？**
答：紧凑要搬移正在运行的进程，只有运行期绑定（MMU 重定位）才能让搬移后的进程仍正确执行。代价是搬移本身就是大量内存读写，纯开销、无收益，内存大时成本极高，通常只在碎片严重且无其他方案时使用。

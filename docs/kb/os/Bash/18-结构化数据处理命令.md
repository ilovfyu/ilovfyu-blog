::: abstract 本章定位
`grep`、`awk`、`sed` 擅长处理“行”，现代 Linux/Bash 还必须理解 API JSON、YAML 配置、XML 节点、CSV 引号和 JSON Lines 日志。本篇补齐 `jq`、`yq`、`xmllint`、XMLStarlet、csvkit、Miller、`crudini`、`dasel`、`jo`、`jc` 等结构化工具，重点是**按结构取值、保留类型、安全修改、验证结果和处理大文件**。

前置知识见 [文本处理三剑客](/kb/os/Bash/02-文本处理三剑客/)，脚本中的引号、退出码和 `set -euo pipefail` 见 [Shell脚本编程进阶](/kb/os/Bash/08-Shell脚本编程进阶/)，HTTP 输入见 [网络命令](/kb/os/Bash/06-网络命令/)，可替代工具可延伸到 [现代高效命令行工具](/kb/os/Bash/20-现代高效命令行工具/)。
:::
## 1. 为什么不能总用 grep / awk / sed
```text
文本：user=alice status=200 latency=31
JSON：{"user":"alice","status":200,"latency":31}
CSV： user,note
     alice,"likes, commas"
```
纯文本工具看见的是字符，结构化工具看见的是对象、数组、字段、类型和转义规则。
| 问题 | 纯文本处理风险 | 结构化工具能力 |
|---|---|---|
| 类型 | `"200"`、`200`、`true` 混在一起 | 区分字符串、数字、布尔值、`null` |
| 嵌套 | 正则很难稳定匹配递归结构 | 字段路径、数组索引、XPath |
| CSV 引号 | 引号里的逗号会被 `-F,` 误切 | 真正的 CSV parser |
| 修改 | 同名字符串可能被全部替换 | 只更新指定节点 |
| 校验 | 搜到某个词不代表格式正确 | parser、Schema、退出码 |
| 大文件 | 整体载入可能耗尽内存 | NDJSON、记录流、`--stream` |
::: important 先判断输入形状
单个 JSON 文档、多个连续 JSON 值、JSON Lines、YAML 多文档和普通日志不是一回事。先确认“记录边界”和“是否需要全局聚合”，再选工具。
:::
## 2. 安装、实现与版本差异
先确认实际命令，不要根据名字猜实现：
```bash
command -v jq yq xmllint xmlstarlet csvlook mlr crudini dasel column jo jc curl
jq --version
yq --version
mlr --version
```
| 工具 | 安装包/命令 | 常见版本差异 |
|---|---|---|
| `grep`/`sed`/`awk` | Linux 默认；GNU `grep`/`sed`/`gawk`，macOS 为 BSD 版本 | `sed -i`、正则扩展和 awk 特性不同；都不是真正的 JSON/CSV parser |
| `jq` | `brew install jq`；`apt install jq` | 1.6 仍常见，1.7/1.8 增加选项并调整数字/错误细节；本篇核心 filter 兼容 1.6+ |
| Mike Farah `yq` | `brew install yq`；Linux 下载官方 Go 二进制 | v4 与旧 v3 CLI 不兼容；`-i`、`eval-all`、`-p/-o` 以 v4 为准 |
| Python `yq` | `brew install python-yq`；`pipx install yq`，另需 `jq` | 3.x/4.x 是 jq wrapper；`-y/-Y` 与 Go 版含义不同 |
| `xmllint` | Homebrew `libxml2`；Debian `libxml2-utils` | 能力取决于 libxml2 编译版本；macOS Homebrew 可能是 keg-only |
| XMLStarlet | `brew install xmlstarlet`；`apt install xmlstarlet` | 1.6.x 很常见；命令通常为 `xmlstarlet`，部分系统另有 `xml` 别名 |
| csvkit | `brew install csvkit` 或 `pipx install csvkit` | 1.x/2.x 均常见；2.x 默认 sniff 方言并推断类型 |
| Miller | `brew install miller`；`apt install miller` | Miller 5 与 6 的 JSON 输出参数、类型推断不同；本篇用 Miller 6 |
| `crudini` | `apt install crudini`；`pipx install crudini` | 发行版版本可能较旧；section、空值和输出格式以本机 `--help` 为准 |
| `dasel` | `brew install dasel`；下载官方二进制 | v3 重写查询语法并移除 v2 的 `put`/`delete`，不可混用文档 |
| `column` | Linux `util-linux`；macOS 系统自带 BSD 版 | util-linux 新版选项更多；基础 `-t -s` 最可移植 |
| `jo` | `brew install jo`；`apt install jo` | 老版本的嵌套键、类型强制和重复键选项可能不同 |
| `jc` | `brew install jc`；`apt install jc` 或 `pipx install jc` | parser 与输出 schema 随版本增长，不是 POSIX 标准 |
| `curl` | `brew install curl`；`apt install curl` | TLS/HTTP2/HTTP3 支持取决于编译；本篇只依赖稳定的 `-D/-o/-w/-f` |
::: warning 两个 yq 同名
`yq --version` 输出带 `mikefarah/yq` 才是下文默认的 Go 版 v4。某些发行版的 `apt install yq` 可能安装 Python 版，脚本应固定二进制来源和版本。
:::
## 3. jq：JSON 查询与变换
### 3.1 `.`：格式化和语法校验
输入并执行：
```bash
printf '%s\n' '{"ok":true,"items":[1,2]}' | jq .
```
输出：`{"ok":true,"items":[1,2]}` 的漂亮 JSON。
只校验、不输出：
```bash
printf '%s\n' '{"ok":true}' | jq empty; echo "$?"
printf '%s\n' '{"ok":}' | jq empty; echo "$?"
```
输出片段：`0`；非法输入报告 parse error，并返回非零退出码。
`.` 是 identity filter；jq 默认漂亮打印，所以也常用于 `curl ... | jq .`。Unix shell 中 filter 用单引号，避免 `$` 和反斜杠先被 shell 解释。
### 3.2 字段与数组索引
准备输入：
```bash
cat > /tmp/users.json <<'EOF'
{"meta":{"request-id":"r-001"},"users":[{"id":3,"name":"Cara","team":"ops"},{"id":1,"name":"Alice","team":"dev"},{"id":2,"name":"Bob","team":"ops"}]}
EOF
```
执行：
```bash
jq '.meta["request-id"]' /tmp/users.json
jq '.users[0].name' /tmp/users.json
jq '.users[-1].name' /tmp/users.json
jq '.users[0:2] | map(.name)' /tmp/users.json
```
输出：`"r-001"`、`"Cara"`、`"Bob"`、`["Cara","Alice"]`。
`.name` 适合普通键；含连字符、点号或以数字开头的键使用 `.["request-id"]`。数组从 0 开始，负数从末尾计数，切片右边界不包含。
### 3.3 `.[]` 与管道 `|`
```bash
jq '.users[] | .name' /tmp/users.json
```
输出是三个独立 JSON 值：`"Cara"`、`"Alice"`、`"Bob"`。
收集为一个数组：
```bash
jq '[.users[] | {id, user: .name}]' /tmp/users.json
```
输出：
```json
[{"id":3,"user":"Cara"},{"id":1,"user":"Alice"},{"id":2,"user":"Bob"}]
```
管道把左侧每个结果交给右侧；`.users[].name` 等价于 `.users[] | .name`。`[filter]` 会收集 filter 的全部输出。
### 3.4 `select` 与 `map`
```bash
jq '[.users[] | select(.team == "ops") | .name]' /tmp/users.json
printf '%s\n' '[1,2,3]' | jq 'map(. * 10)'
printf '%s\n' '{"a":1,"b":2}' | jq 'map_values(. + 1)'
```
输出：`["Cara","Bob"]`、`[10,20,30]`、`{"a":2,"b":3}`。
`select(f)` 条件为真时保留输入，否则不输出；`map(f)` 等价于 `[.[] | f]`；`map_values(f)` 对对象值逐个处理并保留键。
类型不会自动转换：
```bash
printf '%s\n' '[{"id":2},{"id":"2"}]' | jq '[.[] | select(.id == 2)]'
```
输出只含数字：
```json
[{"id":2}]
```
### 3.5 `sort_by`、`group_by`、`unique_by`
```bash
jq '.users | sort_by(.id) | map(.name)' /tmp/users.json
```
输出：`["Alice","Bob","Cara"]`。
准备分组输入：
```bash
printf '%s\n' '[{"team":"ops","score":4},{"team":"dev","score":9},{"team":"ops","score":7},{"team":"dev","score":3}]' > /tmp/scores.json
jq 'group_by(.team) | map({team: .[0].team, count: length, total: (map(.score) | add)})' /tmp/scores.json
```
输出：`[{"team":"dev","count":2,"total":12},{"team":"ops","count":2,"total":11}]`。
按键去重：
```bash
printf '%s\n' '[{"id":"a","v":1},{"id":"b","v":2},{"id":"a","v":1}]' | jq 'unique_by(.id)'
```
输出：
```json
[{"id":"a","v":1},{"id":"b","v":2}]
```
`group_by(x)` 会按键分组并排序；若“重复时保留最高分”，不要依赖输入顺序，应使用 `group_by(.id) | map(max_by(.score))` 明确规则。
### 3.6 `to_entries` 与 `from_entries`
```bash
printf '%s\n' '{"dev":3,"ops":7,"qa":2}' | jq 'to_entries | sort_by(.value) | reverse'
```
输出：`[{"key":"ops","value":7},{"key":"dev","value":3},{"key":"qa","value":2}]`。
修改键名并还原：
```bash
printf '%s\n' '{"app.port":8080,"app.name":"demo"}' \
  | jq 'to_entries | map(.key |= gsub("\\."; "_")) | from_entries'
```
输出：
```json
{"app_port":8080,"app_name":"demo"}
```
`with_entries(f)` 等价于 `to_entries | map(f) | from_entries`，适合批量修改对象的键和值。
### 3.7 `--arg` 与 `--argjson`
```bash
printf '%s\n' '{"users":[{"name":"Alice","age":30},{"name":"Bob","age":17}]}' \
  | jq --arg name 'Alice' '[.users[] | select(.name == $name)]'
printf '%s\n' '[10,20,30]' | jq --argjson min 20 'map(select(. >= $min))'
```
输出：`[{"name":"Alice","age":30}]` 和 `[20,30]`。
`--arg` 永远注入字符串，`--argjson` 先按 JSON 解析。数字、布尔值、数组和对象要用 `--argjson`；shell 变量仍要写成 `"$value"`。
### 3.8 `-r`、`-c`、`-s`
```bash
printf '%s\n' '{"name":"Alice"}' | jq '.name'
printf '%s\n' '{"name":"Alice"}' | jq -r '.name'
printf '%s\n' '{"id":1}' '{"id":2}' | jq -c '.'
printf '%s\n' '{"id":1}' '{"id":2}' | jq -s 'map(.id) | add'
```
输出：默认是 `"Alice"`，`-r` 是 `Alice`，`-c` 是一行一个对象，`-s` 是 `3`。
- `-r`：字符串 raw 输出，供 `read`、`xargs` 等文本消费者使用。
- `-c`：每个 JSON 值压成一行，是 JSON Lines 常用输出。
- `-s`：slurp，把所有输入收集成一个数组；方便聚合，但会占用与输入规模相关的内存。
### 3.9 编辑 JSON
输入：
```bash
printf '%s\n' '{"name":"demo","server":{"port":8080},"debug":true}' > /tmp/app.json
```
安全修改流程：
```bash
cp /tmp/app.json /tmp/app.json.bak
jq '.server.port = 9090 | .debug = false | .features = ["metrics"]' \
  /tmp/app.json > /tmp/app.json.tmp \
  && jq empty /tmp/app.json.tmp \
  && mv /tmp/app.json.tmp /tmp/app.json
jq -c '.' /tmp/app.json
```
输出：`{"name":"demo","server":{"port":9090},"debug":false,"features":["metrics"]}`。
`jq` 通常不提供通用 `-i`。不要写 `jq '...' file > file`，因为 shell 会在 jq 读取前先截断文件；使用同目录临时文件、验证、再 `mv`。
### 3.10 curl + jq 实战
```bash
body=$(mktemp)
status=$(curl -sS -o "$body" -w '%{http_code}' https://httpbin.org/json)
if [ "$status" = 200 ] && jq -e '.slideshow.slides | type == "array"' "$body" >/dev/null; then
  jq -r '.slideshow.slides[] | .title' "$body"
else
  printf 'HTTP=%s 或 JSON 结构错误\n' "$status" >&2
fi
rm -f "$body"
```
输出示例：每行一个 slideshow 标题，如 `Wake up to WonderWidgets!`、`Overview`。
GitHub API 示例：
```bash
curl -fsSL https://api.github.com/repos/jqlang/jq \
  | jq '{name, stars: .stargazers_count, language}'
```
输出结构（星数会变化）：
```json
{"name":"jq","stars":数值,"language":"C"}
```
`curl -f` 只保证 4xx/5xx 返回失败，不能证明 body 是合法 JSON，更不能证明业务字段正确；继续使用 `jq empty` 或 `jq -e` 验证。
### 3.11 `--stream`：超大 JSON
```bash
printf '%s\n' '{"users":[{"id":1},{"id":2}]}' | jq --stream -c '.'
```
输出片段：`[["users",0,"id"],1]`、`[["users",0,"id"]]` 等路径/值事件。
`--stream` 输出“路径、叶子值”事件，而不是完整对象。只抽取 `users[*].id`：
```bash
printf '%s\n' '{"users":[{"id":1},{"id":2}],"meta":{"id":99}}' \
  | jq --stream -r 'select(length == 2 and .[0][0] == "users" and .[0][-1] == "id") | .[1]'
```
输出：`1`、`2`。
## 4. yq：YAML 与 JSON
### 4.1 Go v4 与 Python yq 的区别
| 项目 | Mike Farah yq v4 | Python yq（kislyuk） |
|---|---|---|
| 实现 | Go 单文件二进制 | Python 转码器 + jq |
| 默认输出 | YAML | JSON |
| 写回 YAML | `yq -i '...' file.yml` | `yq -y/-Y --in-place '...' file.yml` |
| 格式转换 | `-p` 输入、`-o` 输出 | `-y/-Y` 转回 YAML，另有 `xq`/`tomlq` |
| 注释/样式 | 尽力保留，不保证字节级 round-trip | `-Y` 用额外元数据保留 tag/style，可能影响 jq filter |
下文未特别说明时均指 Mike Farah v4。
### 4.2 读字段、数组和筛选
```bash
cat > /tmp/app.yml <<'EOF'
app:
  name: demo
  replicas: 2
  ports: [8080, 8443]
  users:
    - {name: Alice, role: admin}
    - {name: Bob, role: viewer}
EOF
yq '.app.name' /tmp/app.yml
yq '.app.ports[0]' /tmp/app.yml
yq '.app.users[] | select(.role == "admin") | .name' /tmp/app.yml
```
输出：`demo`、`8080`、`Alice`。
### 4.3 写字段、数组和 `-i`
```bash
cp /tmp/app.yml /tmp/app.yml.bak
yq -i '.app.replicas = 3 | .app.ports += [9000]' /tmp/app.yml
yq -i '(.app.users[] | select(.name == "Bob") | .role) = "editor"' /tmp/app.yml
yq -o=json '{replicas: .app.replicas, ports: .app.ports, users: .app.users}' /tmp/app.yml
```
输出：`{"replicas":3,"ports":[8080,8443,9000],"users":[{"name":"Alice","role":"admin"},{"name":"Bob","role":"editor"}]}`。
`-i` 直接改文件且不自动备份；重要配置先复制、在 Git 工作树中检查 diff，或输出临时文件后替换。
### 4.4 多文档 YAML
```bash
cat > /tmp/multi.yml <<'EOF'
kind: ConfigMap
metadata: {name: one}
---
kind: ConfigMap
metadata: {name: two}
EOF
yq '.metadata.name' /tmp/multi.yml
yq eval-all -o=json '[.]' /tmp/multi.yml
```
输出：`one`、`two`，以及包含两个 document 的 JSON 数组。
普通 `eval` 逐文档运行，`eval-all`/`ea` 把全部文档同时加载，适合跨文件合并但会增加内存占用。
### 4.5 JSON/YAML 转换
```bash
printf '%s\n' '{"app":{"name":"demo","replicas":2}}' > /tmp/in.json
yq -p=json -o=yaml '.' /tmp/in.json
yq -p=yaml -o=json '.app' /tmp/app.yml
```
输出：
```yaml
app:
  name: demo
  replicas: 2
```
```json
{"name":"demo","replicas":3,"ports":[8080,8443,9000],"users":[{"name":"Alice","role":"admin"},{"name":"Bob","role":"editor"}]}
```
Python yq 的同类命令：
```bash
python3 -m yq -y '.' /tmp/in.json
python3 -m yq -Y --in-place '.app.replicas = 4' /tmp/app.yml
```
### 4.6 环境变量注入
```bash
APP_IMAGE='demo:2.0' REPLICAS=4 \
  yq '.app.image = strenv(APP_IMAGE) | .app.replicas = env(REPLICAS)' /tmp/app.yml
```
输出关键字段：
```yaml
replicas: 4
image: demo:2.0
```
`strenv(NAME)` 始终产生字符串；`env(NAME)` 按 YAML 值解析，可得到数字、布尔值或对象。输入不可信时优先 `strenv`，再显式转换并校验类型。
## 5. XML：xmllint 与 XMLStarlet
### 5.1 format、XPath、Schema
```bash
cat > /tmp/books.xml <<'EOF'
&lt;books&gt;&lt;book id="b1"&gt;&lt;title&gt;Shell&lt;/title&gt;&lt;price&gt;30&lt;/price&gt;&lt;/book&gt;&lt;book id="b2"&gt;&lt;title&gt;XML&lt;/title&gt;&lt;price&gt;45&lt;/price&gt;&lt;/book&gt;&lt;/books&gt;
EOF
xmllint --format /tmp/books.xml
xmllint --xpath 'string(/books/book[@id="b2"]/title)' /tmp/books.xml; printf '\n'
xmllint --xpath 'count(/books/book)' /tmp/books.xml; printf '\n'
```
输出：格式化 XML；XPath 查询分别得到 `XML` 和 `2`。
Schema 输入：
```bash
cat > /tmp/books.xsd <<'EOF'
<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema"><xs:element name="books"><xs:complexType><xs:sequence><xs:element name="book" maxOccurs="unbounded"><xs:complexType><xs:sequence><xs:element name="title" type="xs:string"/><xs:element name="price" type="xs:integer"/></xs:sequence><xs:attribute name="id" type="xs:string" use="required"/></xs:complexType></xs:element></xs:sequence></xs:complexType></xs:element></xs:schema>
EOF
xmllint --noout --schema /tmp/books.xsd /tmp/books.xml
```
输出：
```text
/tmp/books.xml validates
```
`--noout` 只检查解析；`--schema` 还检查 XSD 结构和类型，但不自动覆盖所有业务规则。
### 5.2 命名空间
```bash
printf '%s\n' '&lt;feed xmlns="urn:example:feed"&gt;&lt;entry&gt;&lt;title&gt;Hello&lt;/title&gt;&lt;/entry&gt;&lt;/feed&gt;' > /tmp/ns.xml
xmllint --xpath 'count(/feed/entry)' /tmp/ns.xml
xmllint --xpath 'count(/*[local-name()="feed"]/*[local-name()="entry"])' /tmp/ns.xml; printf '\n'
xmlstarlet sel -N f=urn:example:feed -t -v 'string(/f:feed/f:entry/f:title)' -n /tmp/ns.xml
```
输出：无命名空间 XPath 为空，`local-name()` 得到 `1`，XMLStarlet 得到 `Hello`。
默认命名空间中的元素不属于“无命名空间”。XMLStarlet 用 `-N 前缀=URI` 最清晰；`local-name()` 可应急，但可能忽略同名不同 URI 的区别。
### 5.3 XMLStarlet `sel` / `ed` / `fo`
查询成文本表：
```bash
xmlstarlet sel -T -t -m '/books/book' \
  -v '@id' -o '|' -v 'title' -o '|' -v 'price' -n /tmp/books.xml
```
输出：
```text
b1|Shell|30
b2|XML|45
```
编辑并格式化：
```bash
cp /tmp/books.xml /tmp/books-edit.xml
xmlstarlet ed -P -L -u '/books/book[@id="b1"]/price' -v '35' /tmp/books-edit.xml
xmlstarlet sel -T -t -v 'string(/books/book[@id="b1"]/price)' -n /tmp/books-edit.xml
printf '%s\n' '&lt;root&gt;&lt;item&gt;A&lt;/item&gt;&lt;item&gt;B&lt;/item&gt;&lt;/root&gt;' | xmlstarlet fo -s 2
```
输出：编辑查询得到 `35`；`fo` 得到缩进后的 `&lt;root&gt;&lt;item&gt;A&lt;/item&gt;&lt;item&gt;B&lt;/item&gt;&lt;/root&gt;`。
`ed -L` 原地修改，先备份；`fo`/`xmllint --format` 会重新序列化，不保证属性顺序和空白字节完全不变。
## 6. CSV：csvkit 与 Miller
### 6.1 awk 的明确局限
```bash
printf '%s\n' 'Alice,"likes, shells",10' | awk -F, '{print NF, $2}'
```
输出：`4 "likes`，说明 awk 把引号内逗号误当分隔符。
正确 CSV 中，引号字段可以包含逗号、双引号和换行。`awk -F,` 只适合明确保证“无引号、字段内无逗号/换行”的简单文件。
### 6.2 csvkit 基础数据
```bash
cat > /tmp/score.csv <<'EOF'
name,team,note,score
Alice,ops,"likes, shells",10
Bob,dev,"plain text",8
Cara,ops,"on call",9
EOF
csvlook /tmp/score.csv
```
输出：对齐表格，`likes, shells` 保持在一个字段内。
csvkit 2.x 默认 sniff 前 1024 字节并做类型推断；误判时用 `-y 0` 禁用 sniff，用 `-I` 禁用类型推断并保留 `0012` 等文本。
### 6.3 `csvcut` / `csvgrep` / `csvstat` / `csvsort`
```bash
csvcut -n /tmp/score.csv
csvcut -c name,score /tmp/score.csv
csvgrep -c team -m ops /tmp/score.csv
csvstat --count /tmp/score.csv
csvstat -c score --mean /tmp/score.csv
csvsort -r -c score /tmp/score.csv
```
输出要点：列名为 `name/team/note/score`，`csvcut` 选出 `name,score`，`csvgrep` 保留两条 ops，`csvstat` 输出总行数 `3` 和 score 平均值 `9`。
`csvsort -r -c score` 输出顺序为 Alice、Cara、Bob。精确排版和统计小数格式会受 csvkit 小版本与 locale 影响，脚本应固定版本并优先请求单一统计量。
### 6.4 `csvjoin`
```bash
printf '%s\n' 'team,owner' 'ops,Alice' 'dev,Bob' > /tmp/teams.csv
csvjoin -c team /tmp/score.csv /tmp/teams.csv
```
输出：增加 `owner` 列，Alice/Cara 的 owner 为 Alice，Bob 的 owner 为 Bob。
关联前要统一键的大小写、空白和类型；复杂外连接、重复键和超大文件更适合 Miller、SQL 或数据处理语言。
### 6.5 Miller：CSV/TSV/JSON 管道
```bash
mlr --icsv --opprint cat /tmp/score.csv
mlr --icsv --ocsv filter '$score >= 9' /tmp/score.csv
mlr --icsv --opprint put '$score = $score * 2' /tmp/score.csv
```
输出片段：`--opprint` 对齐四列；过滤保留 Alice/Cara，`put` 将 score 变成 20/16/18。
CSV 转 JSON Lines：
```bash
mlr --icsv --ojsonl cat /tmp/score.csv
```
输出：三行 JSON，每行一个 CSV 记录，并保留 `score` 为数字。
JSON Lines 转 TSV：
```bash
printf '%s\n' '{"name":"Alice","score":10}' '{"name":"Bob","score":8}' | mlr --ijsonl --otsv cat
```
输出：TSV 表头 `name&lt;TAB&gt;score`，后跟 Alice/10 和 Bob/8 两行。
Miller 6 用 `--ojson` 输出外层数组的漂亮 JSON，`--ojsonl` 输出 NDJSON；Miller 5 旧脚本常见 `--jvstack`/`--jlistwrap`，迁移时查对应版本文档。
## 7. INI / Properties / TOML
### 7.1 `crudini` 处理 INI
```bash
cat > /tmp/app.ini <<'EOF'
[server]
host=127.0.0.1
port=8080
[database]
name=demo
EOF
crudini --get /tmp/app.ini server port
crudini --set /tmp/app.ini server port 9090
crudini --get /tmp/app.ini server port
```
输出：
```text
8080
9090
```
它理解 section，比 `sed 's/^port=.*/.../'` 更不容易误改另一个 section。仍建议备份，因为 `--set` 会写原文件。
### 7.2 Properties
Mike Farah yq v4 支持 properties 输入/输出：
```bash
printf '%s\n' 'server.host = localhost' 'server.port = 8080' > /tmp/app.properties
yq -p=props '.' /tmp/app.properties
yq -p=props -o=props '.server.port = "9090"' /tmp/app.properties
```
输出：YAML 为 `server.host/server.port`，Properties 输出 `server.host = localhost` 与 `server.port = 9090`。
Properties 值默认偏向字符串；数组索引、续行和转义按具体实现约定，Java 项目应再由应用或官方 parser 验证。
### 7.3 TOML 与 `tomlq`
Python yq 包会安装 `tomlq`：
```bash
cat > /tmp/app.toml <<'EOF'
[server]
host = "127.0.0.1"
port = 8080
EOF
tomlq '.server.port' /tmp/app.toml
tomlq -t '.server.port = 9090' /tmp/app.toml
```
输出：先得到 `8080`，再输出 `[server]` 段且 `port = 9090`。
`tomlq -T` 尝试 round-trip 保留格式元数据；复杂 filter 需注意这些额外元数据。TOML 含日期、数组和嵌套 table 时不要用 grep/sed 模拟 parser。
### 7.4 `dasel` 跨格式（非默认）
Dasel v3 示例：
```bash
printf '%s\n' '{"server":{"port":8080}}' | dasel -i json 'server.port'
printf '%s\n' '{"server":{"port":8080}}' | dasel -i json --root 'server.port = 9090'
printf '%s\n' 'server:' '  port: 8080' | dasel -i yaml -o json
```
输出：`8080`、`{"server":{"port":9090}}`、`{"server":{"port":8080}}`。
v3 内置原地编辑被移除，使用临时文件：
```bash
dasel -i toml -o toml --root 'server.port = 9090' < /tmp/app.toml > /tmp/app.toml.tmp \
  && mv /tmp/app.toml.tmp /tmp/app.toml
```
v2 文档的 `dasel put`/`delete` 不适用于 v3。Dasel 很适合统一多格式，但它不是系统默认工具，团队脚本应固定主版本。
### 7.5 grep/sed 的风险
```bash
sed -i.bak 's/^port=.*/port=9090/' /tmp/app.ini
```
这条命令只适合明确保证单 section、单键、固定空白的极简单文件。重复键、注释、`port = 8080` 空白、值内 `#`/`;`、TOML 类型和 Properties 续行都会让结果失真。
## 8. 展示、生成与命令输出转 JSON
### 8.1 `column` 与 `mlr --opprint`
```bash
printf '%s\n' 'name|status|score' 'Alice|ok|10' 'Bob|warn|8' | column -t -s '|'
```
输出：三列对齐为 `name/status/score`。
`column` 只按分隔符展示，不理解 CSV 引号。真正 CSV 应使用：
```bash
mlr --icsv --opprint cat /tmp/score.csv
```
### 8.2 `jo` 生成 JSON
```bash
jo name=Alice age=30 active=true note='hello world'
jo -p point[lat]=31.2 point[lon]=121.5
jo -- -s version=0012 -n count=12
```
输出：对象、嵌套 point 对象，以及 version 为字符串 `"0012"`、count 为数字 `12`。
`jo` 默认猜类型；必须保留字符串时用 `-s`。不要手工拼 `{"x":"$value"}`，引号、换行和反斜杠很容易生成非法 JSON。
### 8.3 `jc` 把 Linux 命令输出转 JSON（非默认）
```bash
df -h | jc --df | jq 'map({filesystem, used, available, mount: .mounted_on}) | .[0]'
```
输出结构因机器而异：
```json
{"filesystem":"/dev/...","used":数值,"available":数值,"mount":"/"}
```
`jc --df -p` 漂亮打印，部分版本支持 `-r` 保留原始字符串。parser 只覆盖已实现的命令和平台输出，使用前查 `jc --help`、跑小样本并固定版本。
## 9. HTTP、JSON Lines 与大文件
### 9.1 分开保存响应头、body、状态码
```bash
body=$(mktemp)
headers=$(mktemp)
status=$(curl -sS -D "$headers" -o "$body" -w '%{http_code}' https://httpbin.org/json)
printf 'status=%s\n' "$status"
grep -i '^content-type:' "$headers" | tr -d '\r'
jq -e 'type == "object"' "$body" >/dev/null && echo 'valid object'
rm -f "$body" "$headers"
```
输出示例：`status=200`、`content-type: application/json`、`valid object`。
不要用 `curl -i ... | jq`，因为 `-i` 会把 HTTP 头混入 JSON body。用 `-D headers -o body -w '%{http_code}'` 分离三类数据。
### 9.2 JSON Lines / NDJSON
```bash
cat > /tmp/events.ndjson <<'EOF'
{"ts":"2026-01-01T10:00:00Z","level":"INFO","service":"api","latency_ms":12}
{"ts":"2026-01-01T10:00:01Z","level":"ERROR","service":"api","latency_ms":90}
{"ts":"2026-01-01T10:00:02Z","level":"INFO","service":"worker","latency_ms":20}
EOF
jq -c 'select(.level == "ERROR") | {service, latency_ms}' /tmp/events.ndjson
```
输出：`{"service":"api","latency_ms":90}`。
每行是独立 JSON 值，适合追加、`tail -f`、逐条重试和分区。字段中的换行必须由 JSON 转义，不能手工按可见换行切对象。
### 9.3 大文件策略
```bash
jq -s 'group_by(.level) | map({level: .[0].level, count: length})' /tmp/events.ndjson
```
输出：`[{"level":"ERROR","count":1},{"level":"INFO","count":2}]`。
`-s` 会整体载入；大日志应逐条 `jq -c`、Miller 聚合或导入数据库。选择建议：
| 输入 | 推荐 |
|---|---|
| 小型单 JSON | jq 普通 filter |
| 大型嵌套 JSON | `jq --stream` 或上游改 NDJSON |
| 追加日志 | NDJSON + `jq -c`/Miller |
| 大 CSV | Miller、qsv 或数据库 |
| 大 XML | 流式 XML parser；Python `xq --xml-item-depth` 也可选 |
## 10. 配置变更与验证案例
Kubernetes YAML 这里只作为嵌套格式示例，不涉及容器教程：
```bash
cat > /tmp/deploy.yml <<'EOF'
apiVersion: apps/v1
kind: Deployment
metadata: {name: web}
spec:
  replicas: 2
  template:
    spec:
      containers:
        - name: web
          image: example/web:1.0
          ports: [{containerPort: 8080}]
EOF
```
修改、验证、替换：
```bash
cp /tmp/deploy.yml /tmp/deploy.yml.bak
IMAGE='example/web:1.1' REPLICAS=3 \
  yq '.spec.replicas = env(REPLICAS) | .spec.template.spec.containers[0].image = strenv(IMAGE)' \
  /tmp/deploy.yml > /tmp/deploy.yml.tmp
yq -e '.apiVersion == "apps/v1" and .spec.replicas == 3 and (.spec.template.spec.containers | length) == 1' \
  /tmp/deploy.yml.tmp >/dev/null
mv /tmp/deploy.yml.tmp /tmp/deploy.yml
yq '{replicas: .spec.replicas, image: .spec.template.spec.containers[0].image}' /tmp/deploy.yml
```
输出：`replicas: 3`、`image: example/web:1.1`。
验证至少分三层：格式可解析、路径/类型正确、业务约束成立。正式项目有 JSON Schema/XSD/应用自带检查器时，应在替换前运行它们。
固定流程：
```text
备份 -> 生成临时文件 -> parser 校验 -> 结构/业务校验 -> mv 替换 -> 保留回滚点
```
## 11. 选型矩阵
| 任务 | grep/awk/sed | 首选结构化工具 | 原因 |
|---|---|---|---|
| 找含 ERROR 的普通日志行 | **首选** | 不必使用 | 行级搜索最快、依赖少 |
| 取 JSON 数组字段 | 脆弱 | **jq** | 理解类型、数组和转义 |
| 修改 YAML 节点 | 高风险 | **Mike Farah yq v4** | 路径更新、格式转换、多文档 |
| XML XPath/Schema | 不适合 | **xmllint** | 标准 parser、XPath、XSD |
| XML 查询/编辑 | 不适合 | **XMLStarlet** | `sel`/`ed`/`fo` 完整 |
| 正式 CSV 过滤关联 | `awk -F,` 不可靠 | **csvkit/Miller** | 正确处理引号和逗号 |
| 大型 CSV/JSONL 流水线 | 能做简单字段 | **Miller** | 记录流、跨格式、计算 |
| INI 指定 section 修改 | sed 易误改 | **crudini** | 理解 section 和键 |
| TOML/Properties | 正则风险高 | **tomlq/yq** | 理解类型和转义 |
| 跨格式统一查询 | 需多套正则 | **dasel** | 统一语法，但需固定 v3 |
| 生成 JSON | 手工拼接危险 | **jo/jq -n** | 自动转义和类型控制 |
| `df`/`ps` 输出转 JSON | 手工拆列易变 | **jc** | 已知命令 parser，非默认 |
| 人工对齐查看 | `printf` 较繁琐 | **column/mlr --opprint** | 只负责展示 |
判断口诀：**挑普通行用 grep，改普通行用 sed，算简单字段用 awk；一旦需要理解 JSON/YAML/XML/CSV 语义，就换 parser。**
## 12. 常见陷阱与排查
| 现象 | 常见原因 | 排查方式 |
|---|---|---|
| jq 输出空 | 路径不存在或类型不对 | 先 `jq 'type, keys'`，再逐段下钻 |
| yq 数字变字符串 | 使用了 `strenv` 或 shell 引号 | 用 `yq '... | type'` 检查 |
| XML XPath 为空 | 忽略默认命名空间 | `local-name()` 或 XMLStarlet `-N` |
| CSV 列数不稳定 | 引号内逗号/换行 | 换 csvkit/Miller，不用 `awk -F,` |
| 修改后文件为空 | `> file` 先截断源文件 | 使用 `.tmp`、校验后 `mv` |
| 排序结果不同 | locale 或类型推断不同 | 固定 `LC_ALL=C`、显式类型 |
| HTTP 成功但脚本失败 | 2xx body 不是预期结构 | 同时检查状态码、JSON、业务字段 |
| JSONL 中单行报错 | 某条记录损坏 | 逐行处理并记录行号/原文 |
| jq 大文件变慢 | `-s` 整体载入内存 | 改用 `-c`、`--stream` 或 Miller |
| YAML 注释消失 | 转换器不是字节级 round-trip | 在副本上 diff，必要时保留原注释 |
| macOS 选项报错 | BSD/GNU 命令差异 | `command -v`、`--help`、固定工具版本 |
| 配置值被误解析 | YAML/CSV 类型推断 | 使用 `-I`、`strenv` 或显式 schema |
| XML 外部内容异常 | DTD/实体和网络访问 | 默认禁止网络，按需显式开启并审查 |
## 本章小结
1. jq 的核心是 `.`、字段/数组索引、`|`、`select`、`map`、排序分组去重和对象/entries 转换。
2. `--arg` 注入字符串，`--argjson` 注入有类型的 JSON；`-r` 给文本工具，`-c` 给 JSON Lines，`-s` 会整体聚合。
3. `jq --stream` 处理路径/叶子事件，适合超大 JSON，但 filter 与普通树模式不同。
4. Mike Farah yq v4 与 Python yq 是不同程序；Go 版示例使用 `-i`、`eval-all`、`-p/-o`、`strenv/env`。
5. XML 用 `xmllint` format/xpath/schema，用 XMLStarlet `sel`/`ed`/`fo`；默认命名空间必须显式绑定。
6. CSV 引号使 `awk -F,` 不可靠；csvkit 适合探索，Miller 适合记录流和跨 JSON/CSV/TSV 转换。
7. INI 用 `crudini`，Properties/TOML 用对应 parser，`dasel` 可跨格式但 v2/v3 差异大。
8. `column` 只展示，`jo` 生成 JSON，`jc` 把部分系统命令输出转 JSON；后二者都不是默认标准命令。
9. HTTP 状态、响应头和 body 要分开保存并分别验证；2xx 不等于合法 JSON，更不等于业务结构正确。
10. 配置修改必须经过备份、临时文件、解析校验、业务校验和替换，不直接覆盖原文件。

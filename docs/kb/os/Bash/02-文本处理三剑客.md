::: abstract 本章定位
把"看日志、做统计、改配置"这三件运维日常浓缩成三把刀：`grep` 负责**筛选**（找行），`sed` 负责**编辑**（改行），`awk` 负责**处理**（算行）。学完本篇，你应该能在一条管道里完成"过滤 → 统计 → 输出报表"的完整流程，读懂 access log 的 Top IP、状态码分布与耗时分析。前序 [核心命令与文件操作](/kb/os/Bash/01-核心命令与文件操作/)，本篇是 [高级命令与文本处理](/kb/os/Bash/09-高级命令与文本处理/) 的基础，排查问题时常与 [排查方法论](/kb/os/问题排查/00-系统问题排查方法论/) 配合使用。
:::

这三把刀共同的工作对象是"文本流"。Linux 的哲学是"一切皆文件，一切可管道"，而文本正是进程间交换信息的最通用格式。**grep 从流里挑出符合条件的行，sed 对每一行做替换/删除/插入，awk 把每一行拆成字段再计算。** 三者输入输出都是文本，所以天然可以级联成流水线：

```
grep 过滤 → sed 清洗 → awk 计算 → sort/uniq 统计
```

## 1. grep：按模式筛选行

### 1.1 基础语法

```bash
grep [选项] 模式 [文件...]
```

`grep` 逐行读取文件（或标准输入），**只要某行包含模式匹配的内容就输出整行**。不指定文件时从标准输入读取，因此最常用于管道里做第一道过滤。

```bash
grep ERROR /var/log/app.log
```
预期输出（片段）：
```
2025-06-01 10:12:01 ERROR  db connection timeout
2025-06-01 10:12:02 ERROR  retry failed after 3 attempts
```
解读：两行都含 `ERROR`，整行输出。注意 grep 匹配的是"行内子串"，不是"整词"。

### 1.2 常用选项

| 选项 | 含义 | 典型场景 |
|---|---|---|
| `-i` | 忽略大小写 | `grep -i error` 同时命中 Error/ERROR/error |
| `-v` | 反向匹配（取反） | `grep -v '^#'` 去掉注释行 |
| `-r` | 递归搜索目录 | `grep -r listen /etc/nginx/` |
| `-l` | 只列出命中文件名 | 找出哪个配置引用了某变量 |
| `-c` | 只统计命中行数 | `grep -c ERROR app.log` |
| `-n` | 显示行号 | 定位错误出现的位置 |
| `-E` | 扩展正则（同 `egrep`） | `grep -E '^[0-9]{4}-'` |
| `-o` | 只输出匹配的部分 | `grep -o '[0-9.]\+'` 抽取 IP |
| `-A n` | 命中行后附带 n 行 | 看异常后面的堆栈 |
| `-B n` | 命中行前附带 n 行 | 看异常前的上下文 |
| `-C n` | 前后各 n 行 | 等价于 `-A n -B n` |
| `--color` | 高亮命中部分 | `grep --color=auto ERROR` |
| `-a` | 把二进制当文本处理 | 搜二进制日志 |

### 1.3 经典日志筛选示例

```bash
# 1. 统计今天有多少条 ERROR
grep -c 'ERROR' /var/log/app.log

# 2. 只看错误行并带上行号与上下文
grep -n -C 2 'ERROR' /var/log/app.log

# 3. 忽略大小写，抓出所有 warning 级别
grep -i 'warning\|error' /var/log/app.log

# 4. 找出 404 请求（-o 只抽状态码，避免整行输出）
grep -o '" [4][0-9][0-9] ' /var/log/nginx/access.log | sort | uniq -c

# 5. 递归搜索所有配置文件里监听的端口
grep -rn 'listen' /etc/nginx/
```
预期输出（第 1 条）：
```
327
```
解读：`-c` 只返回计数，常用于监控告警脚本里的"出错条数是否超阈值"判断。

### 1.4 BRE 与 ERE：基础 vs 扩展正则

grep 默认使用**基础正则（BRE）**，加 `-E` 后使用**扩展正则（ERE）**。核心区别是哪些元字符需要转义：

| 功能 | BRE（grep 默认） | ERE（grep -E / egrep） |
|---|---|---|
| 分组 | `\(abc\)` | `(abc)` |
| 或 | `a\|b` | `a|b` |
| 一次或多次 | `a\+` | `a+` |
| 问号（零或一次） | `a\?` | `a?` |
| 花括号量词 | `a\{2,3\}` | `a{2,3}` |

```bash
grep 'error\|fatal'   app.log   # BRE：| 要转义
grep -E 'error|fatal'  app.log  # ERE：| 直接写
egrep 'error|fatal'    app.log  # egrep == grep -E，等价
```
::: tip 实用建议
现代 Linux 里 `egrep` 就是 `grep -E` 的同义命令。日常写正则建议直接用 `-E`，少记一套转义规则。字符类 `[...]`、锚点 `^`/`$`、`*` 在两种模式下写法相同。
:::

### 1.5 与 find 的区别

`grep` 与 `find` 是两件事，却常被混用：

| 命令 | 作用对象 | 干什么 |
|---|---|---|
| `find` | 文件名/元数据 | 按名字、大小、时间**找文件** |
| `grep` | 文件内容 | 按内容**找行** |

```bash
find /etc -name '*.conf'    # 按文件名找
grep -rl 'root' /etc        # 按内容找（-r 递归，-l 只列文件名）
```
::: note
想"按文件名圈定范围，再按内容筛选"，两条命令天然配合：
`find /etc -name '*.conf' -print0 | xargs -0 -r grep -l 'timeout'`（GNU xargs 的 `-r` 表示空输入时不启动 grep；只求可移植时可改用 `find ... -exec grep -l timeout {} +`）。
:::

## 2. 正则表达式精讲

正则表达式（regex）是"用一套描述语言匹配文本模式"的语法，grep/awk/sed 都吃这一套，但细节有差异。

### 2.1 字符类

| 写法 | 含义 | 示例 |
|---|---|---|
| `[abc]` | a/b/c 中任意一个 | `[Rr]oot` |
| `[a-z]` | 字符区间 | `[0-9]` 匹配任意数字 |
| `[^abc]` | 排除集合 | `[^0-9]` 匹配非数字 |
| `.` | 任意单个字符 | `a.c` 匹配 abc/adc |
| `[[:digit:]]` / `[[:alnum:]_]` / `[[:space:]]` | 数字/单词字符/空白 | POSIX 字符类，grep/awk/sed 最可移植 |
| `\d` / `\w` / `\s` | 部分实现的扩展写法 | 不是 POSIX ERE；不要把 `grep -E` 当成 PCRE，需 PCRE 时明确使用 `grep -P`（GNU 专有且并非所有系统提供） |

::: warning 字符类与转义
元字符（`. * + ? ( ) [ ] { } | \ ^ $`）在字符类 `[]` 内部大多失去特殊含义；想匹配字面上的 `.` 要写 `\.`。这一点在 grep/awk/sed 中一致。
:::

### 2.2 锚点与量词

```bash
^行首    $行尾    \b单词边界（GNU grep 扩展；POSIX 用字符类改写）
*  零次或多次       +   一次或多次
?  零次或一次       {n} 恰好 n 次
{n,} 至少 n 次      {n,m} n 到 m 次
```

| 表达式 | 匹配 | 说明 |
|---|---|---|
| `^root` | 行首的 root | 锚定行首 |
| `root$` | 行尾的 root | 锚定行尾 |
| `^$` | 空行 | 行首紧跟行尾 |
| `[0-9]\{4\}` / `[0-9]{4}` | 4 位数字 | 注意 BRE 转义 |
| `colou?r` | color / colour | 问号使前一字符可选 |
| `a+` | a / aa / aaa... | 至少一个 a |
| `\bword\b` | GNU grep 中的单词边界 | 不匹配 sword；POSIX grep 不保证支持 `\b` |

### 2.3 分组与或、贪婪与懒惰

```bash
grep -E '^(error|fatal|panic):' app.log   # 分组 + 或：三种前缀任选其一

# POSIX 正则没有惰性量词；用排除字符类限制在最近的引号
echo 'a"b"c"d"' | grep -oE '".*"'          # 贪婪：从第一个引号到最后一个引号
echo 'a"b"c"d"' | grep -o '"[^"]*"'        # 可移植的“最短范围”写法
```
预期输出（第二条）：
```
"b"
"d"
```
解读：第一条的 `.*` 是贪婪匹配，会得到一个整体的 `"b"c"d"`；第二条的 `[^\"]*` 不允许中间再出现引号，所以得到 `"b"` 和 `"d"`。**POSIX 正则没有惰性量词**，不要写 `.*?` 并声称它可移植；需要最短范围时用 `[^分隔符]*`，或明确改用 PCRE/Perl/Python。

### 2.4 常用表达式速查表

| 目标 | 表达式 | 备注 |
|---|---|---|
| IP 地址 | `[0-9]{1,3}(\.[0-9]{1,3}){3}` | 简化版，未校验数值范围 |
| 邮箱 | `[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}` | 实用版 |
| 日期 | `[0-9]{4}-[0-9]{2}-[0-9]{2}` | YYYY-MM-DD |
| 路径 | `/[\w./-]*` 或 `/[^ ]+` | 用非空白字符集更稳 |
| 端口号 | `[0-9]{2,5}` | 粗略 |
| HTTP 状态码 | `[1-5][0-9][0-9]` | 三位数字 |

### 2.5 在 grep / awk / sed 中的差异

| 工具 | 匹配对象 | 默认正则 | 特殊说明 |
|---|---|---|---|
| `grep` | 整行 | BRE（`-E` 转 ERE） | POSIX 语法；`-P` 是 GNU 扩展，不是所有系统都有 |
| `sed` | 寻址/替换 | BRE（`-E` 转 ERE） | 替换右侧 `&`/`\1` 是特有语法 |
| `awk` | 字段（$1/$2...） | ERE | 正则写在 `/.../` 内，直接支持 `+ ? {n,m}` |

::: note awk 的正则最"现代"
`awk '$2 ~ /^[0-9]+$/ {print}'` 里 `+` 不用转义，而 `grep '^[0-9]\+$'` 要写 `\+`。**记忆口诀：BRE 是"元字符开小灶要转义"，ERE 是"元字符天生特殊"。**
:::

## 3. awk 入门：按列计算

### 3.1 工作原理

awk 是**面向记录与字段**的编程语言。它逐行读取输入，把每一行按**字段分隔符**拆成若干字段，然后对命中模式的行执行动作：

```
读取一行 → 按 FS 拆成 $1 $2 $3 ... → 检查 pattern 是否匹配 → 执行 action → 下一行
```

- `$0`：整行；`$1`：第一个字段；`$NF`：最后一个字段；`NF`：字段总数。
- 默认分隔符是空白（空格/Tab），可用 `-F` 修改。

```bash
echo 'alice 25 engineer' | awk '{print $1, $NF}'
```
预期输出：
```
alice engineer
```
解读：`$1` 是 alice，`$NF`（第 NF 个字段）是 engineer。

### 3.2 awk 程序结构

```awk
pattern { action }
pattern { action }
```

不写 pattern 则对每行都执行 action；不写 action 则默认 `print $0`（打印整行）。

```bash
# 只要 action：每行打印第一个字段
awk '{print $1}' file

# 只要 pattern：打印匹配的行（默认动作打印整行）
awk '/ERROR/' file

# 两者都有：只对匹配行做动作
awk '/ERROR/ {print $1}' file
```

### 3.3 内置变量

| 变量 | 含义 |
|---|---|
| `NR` | 当前记录号（第几行，从 1 开始） |
| `NF` | 当前记录字段数 |
| `FS` | 输入字段分隔符（默认空白，等价 `-F`） |
| `OFS` | 输出字段分隔符（默认空格） |
| `RS` | 记录分隔符（默认换行） |

```bash
# 打印行号和字段数
awk '{print "行号:" NR, "字段数:" NF}' /etc/passwd | head -3
```
预期输出：
```
行号:1 字段数:7
行号:2 字段数:7
行号:3 字段数:7
```
解读：`/etc/passwd` 每行 7 个字段（user:pass:uid:gid:...:home:shell），正好配合 `-F:` 拆字段。

### 3.4 内置函数与流程控制

| 函数 | 作用 |
|---|---|
| `length(s)` | 字符串长度 |
| `substr(s, m, n)` | 取 s 从 m 开始的 n 个字符 |
| `split(s, arr, sep)` | 把 s 按 sep 拆进数组 |
| `tolower(s)` / `toupper(s)` | 大小写转换 |
| `gsub(r, t, s)` | 全局替换 |

```bash
echo 'GET /api/v1/users HTTP/1.1' | awk '{print tolower($1), length($2)}'
```
预期输出：
```
get 14
```
解读：方法转小写、统计 URL 长度。

条件与循环：

```bash
awk '{ if ($3 > 100) print NR": "$1" 超过阈值"; else print "ok" }' data.txt
awk 'BEGIN{ for(i=1;i<=3;i++) printf "%d ", i; print "" }'
```

### 3.5 BEGIN / END

`BEGIN` 在读取第一行前执行（常用于初始化），`END` 在读完最后一行后执行（常用于输出汇总）：

```bash
awk 'BEGIN{print "=== 统计开始 ==="} {sum+=$2} END{print "总和:", sum}' data.txt
```
预期输出：
```
=== 统计开始 ===
总和: 560
```
解读：`sum+=$2` 在每行累加第 2 列，`END` 块打印最终结果——这就是"逐行处理 + 结束后汇总"的标准姿势。

### 3.6 `-F` 与统计示例

```bash
# 按冒号拆分 passwd，统计用户数，打印 uid>1000 的普通用户
awk -F: '$3 > 1000 {print $1}' /etc/passwd

# 求和：假设自定义日志的第 10 列是响应字节数
awk '{sum += $10} END {print "总字节:", sum}' custom-access.log

# 分组统计：按状态码计数
awk '{cnt[$9]++} END {for (code in cnt) print code, cnt[code]}' access.log
```
::: tip 为什么用 awk 而不是 cut
`cut` 只能"切固定位置"，awk 能"切完再算"。`cut -d: -f1` 等价于 `awk -F: '{print $1}'`，但 awk 还能求和、比较、统计、格式化输出（`printf "%8s %10d"`）。**只管取列用 cut，取完要算用 awk。**
:::

## 4. awk 进阶

### 4.1 关联数组：去重与统计

awk 数组是**关联数组**（key-value 映射），key 可以是任意字符串，天然适合计数：

```bash
# 去重：统计单词出现次数
awk '{for (i=1; i<=NF; i++) count[$i]++} END {for (w in count) print count[w], w}' words.txt

# 按 IP 去重（只统计 ip 列表）
awk '{ip[$1]++} END {for (k in ip) print k}' ip.txt
```
::: note 遍历顺序
`for (k in arr)` 的遍历顺序不保证有序，需要排序时输出管道给 `sort -rn`：
`awk '{count[$1]++} END {for (k in count) print count[k], k}' | sort -rn | head`
:::

### 4.2 字符串与数学函数

```bash
# substr 抽取时间字段里的分钟部分
echo '2025-06-01 10:12:01' | awk '{print substr($2, 4, 2)}'   # 12

# split：拆分 URL 取路径
echo '/api/v1/users?page=2' | awk '{split($1, a, "?"); print a[1]}'

# 数学：取整、随机、指数
awk 'BEGIN{print int(3.99), rand()*10, 2^10}'
```
预期输出：
```
12
/api/v1/users
3 8.xxx 1024
```

### 4.3 多行处理与 getline

`getline` 可以从**另一个文件**或**下一条记录**读取，实现"两文件关联"或"多行合并"：

```bash
# 跳过空行继续处理：读到空行时读下一行
awk '{if ($0=="") getline; print NR": "$0}' file

# 双文件 join：以文件 A 的 key 在文件 B 中查值
awk 'NR==FNR {a[$1]=$2; next} {print $0, a[$1]}' B.txt A.txt
```
解读：`NR==FNR` 是"正在读第一个文件"的经典判断（NR 是累计行号，FNR 是当前文件行号，两者相等只可能在前一个文件里）。`next` 跳过本次循环进入下一行。

### 4.4 实战：分析 access log

假设 `access.log` 是 Nginx 默认格式：
```
192.168.1.10 - - [01/Jun/2025:10:00:01 +0800] "GET /api/v1/users HTTP/1.1" 200 1823
192.168.1.20 - - [01/Jun/2025:10:00:02 +0800] "POST /api/v1/orders HTTP/1.1" 502 0
```

**按 IP 统计请求数，Top 5：**
```bash
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -5
```
预期输出：
```
   12 192.168.1.20
    8 192.168.1.10
```
解读：`awk` 取 IP 列 → `sort` 分组 → `uniq -c` 计数 → `sort -rn` 倒序 → `head` 取前 5。

**按状态码分组：**
```bash
awk '{code[$9]++} END {for (c in code) print c, code[c]}' access.log
```
预期输出：
```
200 18
502 3
404 1
```

**求平均响应耗时**（以下假设应用自定义日志的第 10 列为耗时；Nginx 默认 combined access log 通常只有 9 个空白字段，需先确认格式）：
```bash
awk 'NF >= 10 {sum+=$10; n++} END {if (n) printf "平均耗时: %.2f ms, 共 %d 条\n", sum/n, n}' custom-access.log
```
预期输出：
```
平均耗时: 23.45 ms, 共 22 条
```

## 5. sed 入门：流式编辑

### 5.1 工作原理

sed 是**流编辑器**（stream editor）：**逐行读入、编辑、输出，不落盘修改原文件**。它维护一个"模式空间"，每行的处理是：读入 → 应用命令 → 输出。

```bash
sed 's/旧/新/' file
```
含义：把每一行中第一个"旧"替换为"新"，输出结果。原文件**不变**。

### 5.2 寻址：指定处理哪些行

| 寻址 | 含义 |
|---|---|
| `5` | 第 5 行 |
| `5,10` | 第 5 到 10 行 |
| `/pattern/` | 匹配 pattern 的行 |
| `/start/,/end/` | 从匹配 start 到匹配 end 的范围 |
| `$` | 最后一行 |

```bash
sed '3p' file        # 打印第 3 行（配合 -n）
sed -n '5,10p' file  # 只打印 5-10 行
sed '/ERROR/d' file  # 删除含 ERROR 的行
```

### 5.3 常用命令

| 命令 | 作用 |
|---|---|
| `p` | 打印（通常配 `-n`，否则会重复输出） |
| `d` | 删除整行 |
| `s/旧/新/` | 替换第一个匹配；`s/旧/新/g` 替换全部 |
| `y/abc/ABC/` | 字符级转换 |
| `a\` / `i\` / `c\` | 行后追加 / 行前插入 / 整行替换 |
| `&` | 替换里引用"整个匹配内容" |
| `\1` | 替换里引用第一个分组 |

### 5.4 `-n` 与 `-i`

- `-n`：关闭默认打印，只有 `p` 命令显式输出——"我只想要结果行，不要 sed 把所有行都打印一遍"。
- `-i`：原地修改文件。**危险命令**，强烈建议带备份后缀。

```bash
sed -n '1,3p' config.conf      # 只打印前 3 行，不加 -n 会看到"重复行"
sed -i.bak 's/8080/9090/' nginx.conf   # 原地替换，同时保留 nginx.conf.bak 备份
```
::: warning 原地修改务必备份
`sed -i` 直接改文件，一旦正则写错回不了头。约定俗成写 `-i.bak`，改完检查再删备份：
`sed -i.bak 's/old/new/g' file && rm file.bak`
:::

### 5.5 典型示例

```bash
# 替换全部：全局加 g
sed 's/127.0.0.1/0.0.0.0/g' app.conf

# & 引用匹配内容：给数字加方括号
echo 'err 42' | sed 's/[0-9]\+/[&]/'

# \1 分组引用：交换前两个单词；字符类比 \w 更可移植
echo 'first second' | sed -E 's/([[:alnum:]_]+) ([[:alnum:]_]+)/\2 \1/'

# 删除空行
sed '/^$/d' file

# 提取配置区间
sed -n '/^server {/,/^}/p' nginx.conf
```
预期输出（第 3 条）：
```
second first
```
解读：`-E` 让分组括号与 `+` 生效，`\1`/`\2` 引用两个分组实现交换。这里使用 POSIX 字符类，不依赖 GNU sed 的 `\w` 扩展。

## 6. sed 进阶

### 6.1 多命令

用分号串行执行，或写成 `-e` 参数多次：

```bash
sed 's/a/A/g; s/b/B/g' file
sed -e 's/a/A/g' -e 's/b/B/g' file
```

### 6.2 范围处理与追加插入

```bash
# 处理某两个关键字之间的所有行
sed -n '/BEGIN/,/END/p' data.log

# 在 ERROR 行后追加一行提示
sed '/ERROR/a\--- 以上为错误 ---' app.log

# 在第 5 行前插入
sed '5i\# === 分隔线 ===' config

# 用某行整体替换匹配行
sed '/DEBUG/c\# (log removed)' app.log
```

### 6.3 变换流内容：y 与多行命令

```bash
# 字符级大小写映射（逐字符替换，无长度变化）
echo 'abc-123' | sed 'y/abcdef/ABCDEF/'

# 全局替换完整单词（GNU/BSD sed 都能理解的字符类写法）
sed -i.bak -E 's/(^|[^[:alnum:]_])warning([^[:alnum:]_]|$)/\1WARNING\2/g' app.log

# 花括号实现多命令范围编辑
sed '/^server {/,/^}/{ s/8080/9090/; s/^#//; }' nginx.conf
```

### 6.4 何时用 sed、何时用 awk

| 任务类型 | 首选工具 |
|---|---|
| 查找/替换、删行、简单增行 | **sed** |
| 按字段计算、统计、求和、分组 | **awk** |
| 仅筛选命中行 | **grep**（更快） |
| 只切固定列 | **cut** |

::: note 判断口诀
**改**用 sed，**算**用 awk，**挑**用 grep。sed 是"文本编辑器的命令行版"，awk 是"面向字段的迷你编程语言"。能把行拆成字段去求和计数，awk 一定比 sed 省力。
:::

### 6.5 与 cut / grep 组合

```bash
# grep 筛出错误行 → sed 清理乱码 → cut 取字段
grep ERROR app.log | sed 's/\x1b\[[0-9;]*m//g' | cut -d' ' -f1

# sed 抽取区间后交给 awk 计算
sed -n '/^BEGIN$/,/^END$/p' data.txt | awk '{sum+=$2} END{print sum}'
```
解读：第一句演示"三件工具各管一段"——grep 筛行、sed 去 ANSI 色码、cut 取列；第二句演示 sed 做"区间切割器"，awk 做"区间计算器"。

## 7. 三剑客协同：完整流水线

### 7.1 标准管道模式

```
数据源 → grep（过滤） → sed（清洗） → awk（计算） → sort/uniq（排序统计） → head（截取）
```

```bash
grep -E '2025-06-01' access.log | sed 's/"/ /g' | awk '{print $7}' | sort | uniq -c | sort -rn | head -10
```
解读：过滤日期 → 清洗引号 → 抽 URL → 计数 → 倒序 → 取 Top10。每段工具只做一件事，环环相扣。

### 7.2 实战：完整 access.log 分析

假设 `access.log`（Nginx 格式）：
```
192.168.1.10 - - [01/Jun/2025:10:00:01 +0800] "GET /api/v1/users HTTP/1.1" 200 1823
192.168.1.20 - - [01/Jun/2025:10:00:02 +0800] "POST /api/v1/orders HTTP/1.1" 502 0
192.168.1.10 - - [01/Jun/2025:10:00:03 +0800] "GET /api/v1/users HTTP/1.1" 200 1024
```

**① Top IP（前 5）**
```bash
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -5
```
预期输出：
```
2 192.168.1.10
1 192.168.1.20
```

**② Top URL**
```bash
awk '{print $7}' access.log | sort | uniq -c | sort -rn | head -5
```
预期输出：
```
2 /api/v1/users
1 /api/v1/orders
```

**③ 4xx/5xx 错误统计**
```bash
awk '$9 ~ /^[45][0-9][0-9]/ {print $9}' access.log | sort | uniq -c
```
预期输出：
```
1 502
```
解读：用正则 `^[45]` 只挑 4xx/5xx 状态码行，再分组计数。

**④ 一条流水线输出完整报表**
```bash
awk '{c[$1]++; code[$9]++; url[$7]++} END{
  print "== Top IP ==";
  for (k in c)   print c[k], k;
  print "== 状态码 ==";
  for (k in code) print code[k], k;
  print "== Top URL ==";
  for (k in url) print url[k], k;
}' access.log | sort -rn | head -20
```

### 7.3 常见任务速查

| 任务 | 一条命令 |
|---|---|
| 统计某天访问量 | `grep -c '01/Jun/2025' access.log` |
| 找出 500 错误最多的 URL | `grep ' 500 ' access.log \| awk '{print $7}' \| sort \| uniq -c \| sort -rn \| head` |
| 去重访问 IP 数 | `awk '{print $1}' access.log \| sort -u \| wc -l` |
| 平均响应耗时 | `awk '{sum+=$NF} END{print sum/NR}'` |

## 8. 性能与注意事项

### 8.1 大文件处理效率

| 建议 | 原因 |
|---|---|
| 能用 grep 别用 awk/sed | grep 用 Boyer-Moore 算法，处理大文件最快 |
| 尽早缩小数据量 | `grep` 先过滤，后面的 awk 只处理命中行 |
| 避免 `cat file \| grep` | 直接 `grep x file`，少一次进程与 IO |
| awk 少用 printf 大循环 | 大批量输出用 `print`，字符串拼接优于反复格式化 |
| 先 head 验证再全量 | `head -1000 file \| awk ...` 先看输出是否正确 |

### 8.2 二进制文件与 locale

```bash
# 二进制文件里搜字符串（如崩溃日志、数据库文件）
grep -a 'panic' core.dump

# 排查 locale 引起的匹配异常
grep -c '[[:alpha:]]' file     # POSIX 字符类，比 \w 稳定
```
::: warning locale 陷阱
环境变量 `LANG` 影响正则的字符范围：`[a-z]` 在部分 locale 下可能不止 a-z。脚本里统一 `export LC_ALL=C` 可避免诡异匹配，也能让 `sort` 按字节序稳定排序。
:::

::: note `strings` 不在本篇重复展开
`strings` 适合从二进制或混合文件抽取连续可打印字符串，但参数、编码和安全审计用法已经在 [二进制与安全审计命令](/kb/os/Bash/16-二进制与安全审计命令/) 详细说明。本篇只把它作为管道中的数据源，不复制正文。
:::

### 8.3 正则陷阱

| 陷阱 | 后果 | 对策 |
|---|---|---|
| 忘记转义 `.` | 匹配任意字符而非句点 | 匹配字面量用 `\.` |
| BRE/ERE 转义搞反 | 结果为空或报错 | 统一用 `-E`/`awk`/`sed -E` |
| `.*` 贪婪吞掉整行 | 替换把不该换的换了 | 用 `[^x]*` 收窄范围 |
| 嵌套量词 `(a+)+` | 指数级回溯，性能灾难 | 避免嵌套量词，加 `--max-count` 等限制 |
| 忘记 `g` | `s/old/new/` 只换第一个 | 全替换记得 `s/old/new/g` |
| 大正则匹配慢 | 卡死 | 先 `head` 采样，拆分正则逐段验证 |

::: note 调试技巧
用 `grep -o` 只看匹配片段，快速确认正则命中范围：
`grep -oE 'http[s]?://[^ ]+' access.log | head`
正则写错时先在小样本上验证，再上全量数据。
:::

## 本章小结

- **grep 挑行**：默认 BRE，`-E` 转 ERE；常用 `-i/-v/-c/-o/-n/-A/-B/-C`；`egrep` 等价 `grep -E`。
- **sed 改行**：流式逐行编辑，`s/旧/新/g` 替换，`-n` 关默认打印，`-i.bak` 原地改且备份。
- **awk 算字段**：`$0/$1/$NF` + `NR/NF/FS/OFS`，`pattern {action}` 结构，`BEGIN/END` 做初始与汇总，关联数组做去重统计。
- **正则三处相通、细节不同**：BRE 要转义，ERE 不用；awk 直接支持 `+ ? {n,m}`。
- **可移植正则优先**：POSIX 字符类 `[[:digit:]]`/`[[:space:]]` 跨 grep/awk/sed 更稳；`\d`/`\w`/`\s`、`\b`、`grep -P` 都要注明实现边界；POSIX 没有惰性量词。
- **日志字段先验格式**：Nginx 默认 combined 日志的状态码通常是 `$9`，耗时 `$10` 只在自定义格式成立，先用 `awk '{print NF}'` 验证。
- **协同流水线**：grep 过滤 → sed 清洗 → awk 计算 → sort/uniq 统计，一条管道输出报表。
- **性能**：grep 最快做前置过滤，awk 处理命中子集，`LC_ALL=C` 消除 locale 干扰；二进制字符串审计回看 [二进制与安全审计命令](/kb/os/Bash/16-二进制与安全审计命令/)。

## 动手实验

1. 用 `grep -E -i 'warning|error'` 分析任意一个系统日志，数出各类别条数，并把 `grep -E` 与 `grep -P`（若系统提供）的边界记下来。
2. 用 `grep -oE` 从一段文本中抽出所有 IP 地址并 `sort -u` 去重。
3. 用 `awk -F:` 解析 `/etc/passwd`，打印所有 shell 为 `/bin/bash` 的用户名。
4. 用 `awk` 对一组数字求平均，并输出 `printf` 格式化的两位小数结果；若日志没有第 10 列耗时，先修改为自定义样例格式。
5. 用 `sed -i.bak` 将某配置文件的端口替换为新值，验证备份文件已生成。
6. 合成一份小的 access.log，跑一遍"Top IP + 状态码分布 + 4xx/5xx 统计"的完整流水线；再额外添加耗时列，验证 `NF >= 10` 的平均值脚本。

## 自测题

1. `grep '^root'` 与 `grep 'root$'` 分别匹配什么？
   **答**：前者匹配行首为 root 的行；后者匹配行尾为 root 的行。

2. 为什么 `grep 'a|b' file` 匹配不到任何内容？
   **答**：默认 BRE 下 `|` 是普通字符，需写 `a\|b`，或改用 `grep -E 'a|b'`。

3. 写出统计 `file` 中非空行数的 awk 命令。
   **答**：`awk '$0 != "" {n++} END {print n}' file` 或 `grep -vc '^$' file`。

4. `awk '{print $NF}'` 输出的是什么？
   **答**：每行的最后一个字段（NF 表示字段数，$NF 即取第 NF 个字段）。

5. `sed 's/foo/bar/g'` 与去掉 `g` 有何区别？
   **答**：带 `g` 替换该行所有 foo；不带只替换每行第一个 foo。

6. `sed -i` 为什么要带备份后缀 `-i.bak`？
   **答**：`-i` 直接覆盖原文件且不可撤销；带后缀会先生成 `.bak` 备份，便于回滚。

7. 计算表达式：`echo 'a b c' | awk '{print NF, $2}'` 的输出是？
   **答**：`3 b`（3 个字段，第二字段为 b）。

8. 写出"统计 access.log 中各状态码出现次数"的 awk 一行命令。
   **答**：`awk '{code[$9]++} END {for (c in code) print c, code[c]}' access.log`。

9. `grep -E '".*"'` 与 `grep -o '"[^"]*"'` 在 `a"b"c"d"` 上分别得到什么？
   **答**：前者的贪婪 `.*` 得到整体 `"b"c"d"`；后者用排除字符类得到两段 `"b"`、`"d"`。POSIX 没有 `.*?` 惰性量词。

10. `grep -E '\d+'` 是否等价于 `grep -E '[[:digit:]]+'`？
    **答**：不保证等价。`[[:digit:]]+` 是 POSIX ERE；`\d` 不是 POSIX 写法，某些实现会把它当扩展、另一些会按字面处理，脚本应使用字符类或明确选择 PCRE。

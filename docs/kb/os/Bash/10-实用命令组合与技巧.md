::: abstract 本章定位
Bash 路线的收尾篇：不再单讲一个命令，而是把前面九篇攒下的 `ps`、`grep`、`awk`、`find`、`xargs`、管道、重定向**拼成真实工作场景里的"一条命令"**。目标是告别"记得每个命令、却不知道怎么组合"的尴尬——体检、看日志、查进程、排网络、批量操作、模板渲染、锁竞争全部一行或一小段脚本搞定，并配好别名、历史、PATH 这些"工位设施"。单个命令的完整参数说明回看 [核心命令与文件操作](/kb/os/Bash/01-核心命令与文件操作/)、[高级命令与文本处理](/kb/os/Bash/09-高级命令与文本处理/)，基础见 [Bash命令学习路线总览](/kb/os/Bash/00-Bash命令学习路线总览/)，脚本进阶见 [Shell脚本编程进阶](/kb/os/Bash/08-Shell脚本编程进阶/)。
:::

本篇默认你已掌握 [文件操作](/kb/os/Bash/01-核心命令与文件操作/)、[三剑客](/kb/os/Bash/02-文本处理三剑客/)、[进程控制](/kb/os/Bash/03-进程与作业控制/) 与 [xargs/管道进阶](/kb/os/Bash/09-高级命令与文本处理/)。某个命令不熟就回对应篇目复习。

## 1. 一键系统体检

### 1.1 组合解读：一条命令看全系统

场景：登录服务器第一件事，5 秒判断"机器健康吗"：

```bash
uptime && free -h && df -h && iostat -x 1 2 && ss -tlnp
```

| 环节 | 命令 | 回答的问题 |
| --- | --- | --- |
| 1 | `uptime` | 运行多久、load average 多高 |
| 2 | `free -h` | 内存已用/剩余/swap |
| 3 | `df -h` | 各磁盘剩余空间、是否快满 |
| 4 | `iostat -x 1 2` | 磁盘 IO：`%util`、await |
| 5 | `ss -tlnp` | 监听的端口及进程 |

输出（截取关键行）：

```
 10:22:15 up 63 days,  2 users,  load average: 1.02, 0.98, 0.90
Mem:            15Gi       6.2Gi       2.1Gi   buff/cache  available
/dev/vda1        40G   31G  6.7G  83% /
Device            r/s     w/s   r_await  w_await  %util
vda             12.5    33.2     0.45    0.83     3.2
LISTEN 0  128  0.0.0.0:80  0.0.0.0:*  users:(("nginx",pid=1420,fd=12))
```

讲解：
- `&&` 是"前一条**成功**才执行后一条"——体检时任何一条失败都值得停下来看，而不是继续糊弄；与 `;`（无条件顺序执行）本质不同。
- `iostat -x 1 2` 是"间隔 1 秒采 2 次"，第 2 次才有意义（第 1 次是开机以来累计平均）。`%util` 才是磁盘"真忙不忙"的指标。
- `ss -tlnp`：`-t` TCP、`-l` 仅监听、`-n` 不反解、`-p` 显示进程（需 root）。判断基线：几核机器 load 就该长期小于几，磁盘 83% 意味着很快写不进日志。

### 1.2 压成别名 + 落盘对比基线

```bash
alias sysinfo='uptime && free -h && df -h && iostat -x 1 2 2>/dev/null && ss -tlnp'
sysinfo
mkdir -p ~/logs && sysinfo > ~/logs/sysinfo_$(date +%F).log
seven_days_ago=$(date -d '7 days ago' +%F)   # GNU date
diff ~/logs/sysinfo_$(date +%F).log ~/logs/sysinfo_$seven_days_ago.log
```

讲解：
- 别名只是字符串替换，`&&` 逻辑原样保留，等价手敲。`2>/dev/null` 屏蔽 `iostat` 未安装的报错（重定向见 [高级命令与文本处理](/kb/os/Bash/09-高级命令与文本处理/)）。永久生效写进 `~/.bashrc` 后 `source`，规范见第 6 节。
- `$(date +%F)` 命令替换展开成 `2026-08-10`，文件名按天区分。上例 `date -d` 是 GNU 语法，macOS/BSD 改为 `date -v-7d +%F`。对比思路是**磁盘上涨、load 升高、`%util` 从 3% 飙到 90%**——正是 [性能分析](/kb/os/问题排查/01-性能分析方法论/) 里"先基线、后增量"的做法。

## 2. 日志分析组合

> nginx access log 一行形如：
> ```
> 192.168.1.15 - - [10/Aug/2026:09:31:07 +0800] "GET /api/user HTTP/1.1" 200 1024 "-" "curl/8.0"
> ```
> 排障方法论见 [排查](/kb/os/问题排查/00-系统问题排查方法论/)，这里只谈"把日志变成数字"。

### 2.1 最经典的一条：Top IP

场景：访问量异常，先问"谁在打我"。

```bash
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10
# 应用日志则先筛行再抽列：
grep ERROR app.log | awk '{print $1}' | sort | uniq -c | sort -rn | head
```

输出：

```
  84532 182.61.200.7
  30021 10.0.0.21
```

| 环节 | 命令 | 作用 |
| --- | --- | --- |
| 1 | `awk '{print $1}'` | 取第 1 列（IP），整行日志变一列 IP |
| 2 | `sort` | 字典序排序——`uniq` 只能合并相邻行 |
| 3 | `uniq -c` | 合并相邻相同行并计数 |
| 4 | `sort -rn` | 按计数降序 |
| 5 | `head` | 只留前 10 |

::: important `uniq` 前必须 `sort`
`uniq` 只消除**相邻**重复。`A B A` 不 sort 直接 uniq，两个 A 不会合并。这是文本管道里最经典的"沉默 bug"。
:::

### 2.2 请求数 / 状态码统计

```bash
wc -l < access.log                                     # 总请求数
awk '{print $9}' access.log | sort | uniq -c | sort -rn   # 按状态码分组
```

输出：

```
  99997 200
    145 301
     37 404
      8 502
```

讲解：
- `$9` 在默认切分下正好是状态码列；**日志格式不同先 `awk '{print NF}'` 数列再定位**。一眼锁定：`5xx` 服务端故障、`4xx` 客户端/爬虫、`3xx` 跳转。
- 高频尾部 `sort -rn | head` 可做成函数 `t() { sort -rn | head ${1:-10}; }`，之后 `... | t 5`。

### 2.3 按时间段过滤

```bash
grep '10/Aug/2026:15:' access.log | awk '$9 >= 500 {print $1}' | sort | uniq -c | sort -rn
# 或 awk 一次完成（多个分隔符切分时间戳）：
awk '$4 ~ /^\[10\/Aug\/2026:15:/ && $9 >= 500 {print $1}' access.log | sort | uniq -c | sort -rn
```

讲解：Nginx 默认 combined 格式中时间戳整体位于 `$4`（包含方括号），状态码位于 `$9`；日志时间戳里的 15 点就是 `15:xx:xx`。`grep` 直接筛行最简单；若用 awk，不要为了拆时间戳再引入 `-F'[:" ]'`，否则冒号和连续分隔符会改变字段编号。**能用 grep 筛就别把 awk 复杂化**，每步只做最简单的一件事。

### 2.4 错误率计算

```bash
total=$(wc -l < access.log)
bad=$(awk '$9 >= 500' access.log | wc -l)
if (( total > 0 )); then
  rate=$(printf 'scale=2; %s * 100 / %s\n' "$bad" "$total" | bc)
else
  rate=0
fi
printf 'error rate: %s%%\n' "$rate"
```

输出：`error rate: 0.03%`

讲解：变量 + 命令替换存两步结果，`bc` 做浮点除法（Bash 的 `$(( ))` 只支持整数）；显式处理空日志，避免除零。`printf` 用 `%s`/`%%` 防止数据被当格式串。原则：**一条管道计数、一条算比率**。套进 cron 超阈值告警，就是 10.3 的雏形。

## 3. 进程与资源组合

### 3.1 找最吃 CPU 的进程

```bash
ps -eo pid,ppid,%cpu,%mem,cmd --sort=-%cpu | head -10
```

输出：

```
  PID  PPID %CPU %MEM CMD
 3321     1 187.5  2.3 /usr/bin/python3 /opt/worker.py
 2110     1  12.0 18.0 /usr/sbin/mysqld
```

讲解：`-e` 全部进程、`-o` 自定义列、`--sort=-%cpu` 降序，比 `top` 更"一次性、可管道"。**`%cpu` 超 100% 说明用了多核**（多线程跑满）。确认后 `kill 3321` 温和终止、`kill -9` 强杀（见 [进程与作业控制](/kb/os/Bash/03-进程与作业控制/)）。"找到并杀"先打印确认，安全守则见第 9 节。

### 3.2 `ps aux | grep` vs `pgrep`

新手经典事故：`ps aux | grep nginx` 的输出里混进一条 `grep --color=auto nginx`——grep 自己命令行含 "nginx"，也被列出来了。正确姿势：

```bash
ps aux | grep [n]ginx      # 正则让 grep 匹配不到自己的命令行
pgrep -af nginx            # 推荐：专门查进程号的命令
pkill -f 'worker.py'       # 配套：按完整命令行杀
```

讲解：`[n]ginx` 让 grep 命令行不含连续串 `[n]ginx`，匹配不到自己。**`pgrep` 生来就干这个**，`-a` 附带命令行、`-f` 匹配完整命令行，先看再杀不杀错。

### 3.3 进程树批量处理 / 内存排序

```bash
pstree -p 2110                      # 看进程树
pgrep -P 2110                       # 列出 2110 的直接子进程
mapfile -t pids < <(pgrep -f '[w]orker\.py' || true)
printf '准备处理 PID: %s\n' "${pids[*]:-无}"
if ((${#pids[@]})); then kill "${pids[@]}"; fi
ps aux --sort=-%mem | head          # 内存占用排序
ps -eo pid,%mem,rss,cmd --sort=-%mem | head -5
```

讲解：`pstree -p` 可视化、`pgrep -P <父PID>` 查直接子代；批量杀要分清"整体停"还是"只杀叶子"，服务化场景优先 `systemctl restart`，kill 是兜底。`RSS`（Resident Set Size）是实际占用的物理内存，`%mem` 是占比，排序可叠加 `--sort=-%cpu,-%mem`。内存排查方法论见 [Linux 进程实操](/kb/os/Linux/01-Linux进程与调度实操/)。

## 4. 查找与批量操作组合

### 4.1 `find` + `xargs`：批量改权限 / 清理

```bash
find /data/uploads -type f -name '*.tmp' -exec chmod 644 {} \;
find /data/uploads -type f -name '*.tmp' -print0 | xargs -0 chmod 644
find /var/log -type f -name '*.log' -mtime +7 -print0 | xargs -0 rm -f
```

讲解：`-exec cmd {} \;` 每个文件跑一次；`xargs` 攒成参数一次性传，速度快但**文件名含空格会炸**。`-print0` + `xargs -0` 用 `\0` 分隔，是处理带空格文件名的**标准防炸写法**（[高级命令与文本处理](/kb/os/Bash/09-高级命令与文本处理/) 有专讲）。危险命令先"干跑"：`find ... -mtime +7`（不带 rm）先看会删什么。

::: danger 批量删前先 dry-run
`xargs rm` 不可撤销。习惯：先打印 → 核对 → 执行 → 验证。
:::

### 4.2 `find` + `tar`：备份目录

```bash
tar -czf /backup/app_$(date +%F).tar.gz --exclude='*.log' --exclude='.git' /opt/app
# 或 find 挑文件喂给 tar：
find /opt/app -type f ! -name '*.log' -print0 | tar -czf /backup/app.tar.gz --null -T -
```

讲解：`-T -` 让 tar 从标准输入读列表，`--null` 匹配 `-print0`，组合链是 **find 挑文件、tar 打包**。能用 `--exclude` 就别动 find——代码越简单越不易错。远程备份见 10.2。

### 4.3 找大文件 / 按时间找最近修改

```bash
find / -type f -size +1G -exec ls -lh {} \; 2>/dev/null | sort -k5 -rh
find /etc/nginx -type f -mtime -1 -ls        # 24 小时内改过
find /etc/nginx -type f -mmin -30 -ls        # 30 分钟内
find /opt/app -type f -newer /opt/app/release.v1   # 比某文件新
```

输出：

```
-rw------- 1 mysql mysql 12G Aug  8 03:00 /var/lib/mysql/ibdata1
```

讲解：`-size +1G` 大于 1G；`2>/dev/null` 吞掉权限报错（搜 `/` 必然遇到）。先 find 缩小范围再 `sort -k5 -rh` 按大小列排序。`-mtime` 按天、`-mmin` 按分钟、`-newer file` 以文件为基准，排查"上线后行为异常、怀疑有人改配置"极快。磁盘排查主线见 [磁盘排查](/kb/os/问题排查/04-磁盘与IO瓶颈排查/)。

## 5. 文件操作技巧

### 5.1 重定向三件套

```bash
cmd > /dev/null 2>&1      # 全丢黑洞：只要命令成败的 $?
cmd > file 2>&1           # stdout 和 stderr 都进 file
cmd &> file               # 同上（bash 简写）
```

| 写法 | 含义 | 适用 |
| --- | --- | --- |
| `cmd > /dev/null 2>&1` | 输出全扔 | cron 里的静默命令 |
| `cmd 2>&1` | 错误并入正常流 | 让 grep/tee 也能看到错误 |
| `cmd &> file` | 两路都进文件 | 保存完整日志 |

::: warning 顺序陷阱
`cmd > file 2>&1` 与 `cmd 2>&1 > file` **不等价**：重定向从左到右生效，后者先把 stderr 指向"当时的 stdout（终端）"，再改 stdout 到 file——stderr 漏了出去。面试必考、实战必踩。
:::

### 5.2 mktemp / /tmp 清理 / 追加 vs 覆盖

```bash
tmp=$(mktemp); tmpdir=$(mktemp -d)        # 随机后缀防冲突
cleanup() { rm -rf -- "$tmpdir"; }
trap cleanup EXIT                          # 脚本退出自动清理
find /tmp -type f -atime +3 -delete       # 清理 3 天没动的
echo "start" > log.txt                    # 覆盖：旧的清空
echo "next" >> log.txt                    # 追加：保留历史
```

讲解：`mktemp` 随机后缀天生避免"两个脚本抢同一个 tmp 文件"，**配合 EXIT cleanup 无论成败都清理**是专业脚本分界线；cleanup 内须使用 `--`，并在复杂脚本里先保存原退出码，完整模式见 [Shell脚本编程进阶](/kb/os/Bash/08-Shell脚本编程进阶/)。别用 `$$` 拼临时名（可预测，有安全风险）。`/tmp` 共享空间、重启可能清空，别放重要东西，生产用 `systemd-tmpfiles`/`tmpwatch` 定时清理。`>` 与 `>>` 差一个字符、后果天差地别——**`>` 会直接抹掉数据**，改配置前先 `cp` 原文件是廉价保险。

### 5.3 `sudo tee` 写受保护文件

```bash
sudo echo 'key=v' > /etc/app.conf             # 错：重定向由普通用户 shell 打开
echo 'key=v' | sudo tee /etc/app.conf         # 对：tee 在 sudo 提升后打开
echo 'key=v' | sudo tee -a /etc/app.conf      # 追加版
```

讲解：`>` 的重定向是当前 shell 干的，sudo 只提升了 `echo`。改配置习惯：先 `cp` 备份、改完 `nginx -t && systemctl reload nginx` 验证。

### 5.4 模板渲染 + 原子替换：避免半份配置

场景：将环境变量写入配置模板，同时避免变量未设置、模板渲染失败或写到一半时把正在使用的配置破坏。

```bash
: "${APP_HOST:?必须设置 APP_HOST}"
: "${APP_PORT:?必须设置 APP_PORT}"
target=/etc/myapp/app.conf
tmp=$(mktemp "${target}.XXXXXX")
trap 'rm -f -- "$tmp"' EXIT

envsubst '$APP_HOST $APP_PORT' < /etc/myapp/app.conf.tmpl > "$tmp"
grep -q '^listen=' "$tmp" || { printf '模板结果缺少 listen\n' >&2; exit 1; }
sudo install -m 640 -o root -g myapp "$tmp" "$target"
trap - EXIT
sudo systemctl reload myapp
```

讲解：`: "${VAR:?}"` 在渲染前阻止空变量；`envsubst` 只替换白名单，模板中的 `$HOME` 等其他变量不会意外变值；先写临时文件并做最小校验，最后用 `install` 在目标路径替换。`install` 的目标打开、权限与属主设置都由 sudo 进程完成，不会重演 `sudo echo > file` 的重定向权限问题。

易错点：示例中的 `install` 不保证保留旧文件 ACL、SELinux 上下文或扩展属性，生产服务须按自身要求验证（例如 `restorecon`）。`envsubst` 不是 YAML/JSON 解析器，复杂结构回看 [结构化数据处理命令](/kb/os/Bash/18-结构化数据处理命令/)；命令详情、未设置变量和 `sponge` 的读写同文件场景见 [高级命令与文本处理](/kb/os/Bash/09-高级命令与文本处理/)。

## 6. 效率利器：alias、history、PATH、vi 模式

### 6.1 alias 大全

```bash
alias ll='ls -alhF --color=auto'; alias la='ls -A --color=auto'
alias grep='grep --color=auto'
alias g='git'; alias gs='git status'; alias gl='git log --oneline --graph --all'
alias rm='rm -i'; alias mv='mv -i'; alias cp='cp -i'    # 危险操作加确认
```

讲解：别名只是字符串替换，可引用其他别名；`\grep` 或 `command grep` 绕过。**别覆盖系统命令默认行为**（改掉 `ls` 会让别人脚本出问题），`rm -i` 这类"加保险"别名强烈推荐。查看 `alias`、删除 `unalias rm`。Git 别名在 `~/.gitconfig`，两套体系。

### 6.2 history

```bash
history | tail -20     # 查看
!!                     # 重跑上一条；sudo !! 忘加 sudo 救场
!$                     # 上一条的最后一个参数（vim !$ 编辑刚 cp 的文件）
!ls                    # 最近一条以 ls 开头的命令
^foo^bar               # 上一条的 foo 换成 bar 重跑
```

| 符号 | 含义 |
| --- | --- |
| `!!` | 上一条命令 |
| `!$` | 上一条的最后一个参数 |
| `!string` / `!n` | 最近一条以 string 开头 / 历史第 n 条 |
| `^a^b` | 替换并重跑 |
| `Ctrl+R` | **反向增量搜索**，输关键词回车即执行 |

讲解：`Ctrl+R` 使用率最高：输 `pgre` 浮现最近的 `pgrep -af nginx`。持久化：`HISTSIZE=10000 HISTFILESIZE=20000` + `shopt -s histappend` 防多终端互相覆盖。

### 6.3 `fc`：编辑而不是重敲

```bash
fc -l 100 120     # 列历史 100~120
fc 100            # 开编辑器修第 100 条，保存后执行
fc -s ls          # 非交互改最近一条 ls 后执行
```

讲解：`fc`（fix command）把历史命令送进 `$EDITOR`（默认 vi）编辑，适合"30 个参数只改一个 IP"的长命令。

### 6.4 `.bashrc` 组织与 PATH

| 文件 | 加载时机 | 用途 |
| --- | --- | --- |
| `~/.bashrc` | 每个交互式 bash 启动 | alias、函数、提示符、PATH |
| `~/.profile` / `~/.bash_profile` | 登录 shell | 跨环境变量，一般 source .bashrc |
| `~/.zshrc` | zsh 交互会话 | zsh 用户对应物 |

```bash
[ -f ~/.aliases ] && . ~/.aliases      # 别名单独成文件，多设备同步方便
export EDITOR=vim                      # fc / crontab -e 都尊重它
export PATH="$HOME/bin:$HOME/.local/bin:$PATH"   # 自己脚本放最前
mkdir -p ~/bin && echo 'echo hi' > ~/bin/mycmd && chmod +x ~/bin/mycmd
which mycmd    # 确认被找到
```

讲解：**把"机器相关环境"和"个人偏好"分文件**，换新机器只拷几个 dotfile 就恢复习惯；别名是一次性命令，带参数逻辑进阶到函数见 [脚本篇](/kb/os/Bash/08-Shell脚本编程进阶/)。`$PATH` 冒号分隔、**前优先**；PATH 坏了自查 `echo $PATH`、用 `/usr/bin/ls` 绝对路径绕过。

### 6.5 `set -o vi`

```bash
set -o vi     # Esc 进 normal 模式，i 回 insert；Esc 后 / 搜历史、k/j 翻历史
```

讲解：Bash 默认 readline 是 emacs 模式（Ctrl+R 等），`set -o vi` 切 vi 键位，vim 用户行内编辑像在 vim。纯个人偏好，改回 `set -o emacs`。

## 7. 网络排障组合

### 7.1 一条命令看网络全貌

```bash
ip a && ip route && ss -tlnp && dig +short $(hostname)
```

| 环节 | 命令 | 看什么 |
| --- | --- | --- |
| 1 | `ip a` | 网卡、IP、是否 UP |
| 2 | `ip route` | 默认路由 |
| 3 | `ss -tlnp` | 监听的端口和进程 |
| 4 | `dig +short $(hostname)` | 主机名解析结果 |

输出（片段）：

```
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 ...
    inet 10.0.0.12/24 scope global eth0
default via 10.0.0.1 dev eth0 proto static
LISTEN 0  128  0.0.0.0:443 0.0.0.0:*  users:(("nginx",pid=1420,fd=15))
10.0.0.12
```

讲解：五秒判断网卡 UP、IP、网关、端口、DNS 五件事，任何一步异常就是下一步排查的起点。完整方法论见 [排查](/kb/os/问题排查/00-系统问题排查方法论/)。

### 7.2 分步定位：`ping` → `traceroute` → `mtr`

```bash
ping -c 4 10.0.0.1                # 网关通不通
ping -c 4 baidu.com               # 外网 + DNS
traceroute -n -w 2 baidu.com      # 逐跳看丢在哪
mtr -n -r -c 10 baidu.com         # 持续探活统计丢包率
```

| 症状 | 结论 |
| --- | --- |
| 网关都不通 | 网卡/交换机/局域网问题，别往外查 |
| 网关通、IP 通、域名不通 | DNS 问题，查 `/etc/resolv.conf` |
| 域名通、应用超时 | 应用层，看 ss、日志 |
| traceroute 某跳 `*` 丢包 | 该跳过滤 ICMP 或真丢包，继续看 mtr |

讲解：排查铁律**从近到远、层层收缩**。`mtr` 是 ping + traceroute 合体，持续统计每跳丢包率，`-r -c 10` 输出报告后退出，适合截给同事。

### 7.3 端口占用定位 / DNS 刷新

```bash
ss -tlnp | grep :8080     # 显示 PID 和进程名
lsof -i :8080             # 另一视角
fuser -k 8080/tcp         # 强杀占用（慎用，先看再杀）
systemd-resolve --flush-caches   # systemd 时代清 DNS 缓存
resolvectl flush-caches          # 新版改名（同一件事）
sudo killall -HUP mDNSResponder  # macOS
nslookup example.com             # 清完验证
```

输出：

```
LISTEN 0  128  *:8080  *:*  users:(("java",pid=8314,fd=81))
```

讲解：`ss -tlnp` 日常够用、`lsof -i :port` 传统命令互补；先看清楚是什么服务，能 systemctl 管理就用 systemctl，最后才 kill。DNS 清缓存命令因发行版而异，**先 `man` 确认**（`systemd-resolve` 新版改名 `resolvectl`）；"解析不生效"先 `dig`（权威）对比 `nslookup`（本机 resolver），确认是缓存问题再 flush。

## 8. 循环与批处理组合

### 8.1 for 循环与批量操作

```bash
for i in {1..10}; do echo "curl http://127.0.0.1/api?page=$i"; done
while IFS= read -r u; do wget -- "$u"; done < urls.txt  # 逐行批量下载，保留空格
for f in *.jpg; do mv "$f" "photo_$f"; done        # 批量加前缀
for n in {01..20}; do touch "file$n.txt"; done     # 批量建文件
```

讲解：`{1..10}` 花括号展开，可写 `{a..z}`、`{01..05}`（补零），是"把一条命令自动跑 N 次"的最小模板（完整 for/while 语法见 [脚本篇](/kb/os/Bash/08-Shell脚本编程进阶/)）。变量必须加双引号 `"$f"`——**文件名带空格漏引号直接炸**。来自文件的列表不要写 `for u in $(cat urls.txt)`，它会按空白拆词并触发 glob；用 `while IFS= read -r` 或 `find -print0`/`xargs -0`。

### 8.2 逐行处理：while read

```bash
while IFS= read -r line; do
  echo "processing: $line"
done < /path/to/list.txt
```

讲解：`-r` 保留反斜杠、`IFS=` 不修剪首尾空白，是**逐行读的标准安全写法**。`for line in $(cat file)` 按空白拆词还做通配展开，空行/空格/特殊字符全炸；while read 原样读入，批量重命名、批量重启服务都套这个模板。

### 8.3 并行：`&` + `wait`

```bash
set -u
pids=()
while IFS= read -r u; do
  [[ -n "$u" ]] || continue
  ( wget -q -- "$u" && printf 'ok: %s\n' "$u" ) &
  pids+=("$!")
done < urls.txt

rc=0
for pid in "${pids[@]}"; do wait "$pid" || rc=1; done
(( rc == 0 )) && printf 'all done\n' || { printf 'some downloads failed\n' >&2; exit 1; }
```

讲解：子 shell 后台 `&`、`$!` 收集 PID、`wait` 逐个回收，才能得到“任一下载是否失败”的最终状态。这个模板保留了每行 URL 的原样边界，但**不限制并发数**，只适合很小的列表。

并发要限量时：

```bash
xargs -r -n 1 -P 4 wget -q -- < urls.txt  # GNU xargs：最多 4 个下载
# 安装 GNU parallel 后：parallel -j 4 --halt soon,fail=1 wget -q -- :::: urls.txt
```

易错点：GNU `xargs -r` 在空输入时不启动 wget，macOS/BSD xargs 通常没有 `-r`，可先判断 `[[ -s urls.txt ]]`，或改用上方 while 模板。并行任务输出会交错，任务失败不会自动让已启动任务停止；要稳定输出、失败策略或重试，使用 [现代高效命令行工具](/kb/os/Bash/20-现代高效命令行工具/) 中的 GNU parallel 方案。`nohup` 脱离终端见 [进程与作业控制](/kb/os/Bash/03-进程与作业控制/)。

### 8.4 `seq`

```bash
seq 1 10            # 1..10 每行一个
seq 0 2 20          # 步长 2
seq -w 8 12          # 补零：08 09 10 11 12
seq -f 'node%02g' 1 3
n=5
for i in $(seq 1 "$n"); do printf 'node%d\n' "$i"; done
```

讲解：`{1..10}` 是 Bash 展开，适合静态短列表；`seq` 支持变量、步长、补零 `-w`、格式串 `-f`，输出又天然可接管道——**有变量时用 seq**（`{1..$n}` 不能展开变量）。`seq -f` 采用 printf 风格的单个浮点格式，适合生成固定命名。

易错点：`for i in $(seq ...)` 对 seq 产生的纯数字是可接受的，但不要把这个模式推广到任意文本文件；`seq` 的浮点精度会受实现影响，不应用于金额/精确时间序列。GNU/BSD/macOS 对 `-f`、小数、极大数字边界存在差异，跨平台脚本先用样本验证。

### 8.5 防重入：`flock` + cron 工作任务

场景：cron 每分钟触发同步，但上一轮可能还没结束。把锁放在任务最外层，确保同一主机上只有一个实例进入临界区。

```bash
#!/usr/bin/env bash
set -euo pipefail
lock=/var/tmp/myapp-sync.lock
exec 9>"$lock"
flock -n 9 || { printf '已有同步实例，跳过\n' >&2; exit 75; }

rsync -a --delete /srv/app/ /backup/app/
printf '[%s] sync complete\n' "$(date '+%F %T')"
```

讲解：fd 9 一直打开，锁会一直保持到脚本退出；`-n` 使第二个实例立即退出，cron 不会堆积。锁文件可一直存在，是否持锁取决于 fd，不取决于文件是否存在。

易错点：不要持锁时 `rm` 再建锁文件，否则不同实例可能锁住不同 inode；网络文件系统的锁语义要单独验证；macOS 默认缺 util-linux `flock`。`-w` 超时、共享/独占锁、跨平台策略详见 [Shell脚本编程进阶](/kb/os/Bash/08-Shell脚本编程进阶/)。

## 9. 安全与谨慎操作

### 9.1 危险命令防护

```bash
alias rm='rm -i'; alias mv='mv -i'; alias cp='cp -i'   # 删除要确认
set -u        # 引用未定义变量报错退出（防拼错变量名删错文件）
set -e        # 命令失败立即退出
set -o pipefail
```

讲解：`rm -i` 每次删都按 `y` 确认，是廉价保险——但 `rm -rf` 下照样可能删错，生产环境删除永远 `mv` 到回收站目录更稳。`set -u/-e/pipefail` 三件套让脚本"及早失败"，详见 [脚本篇](/kb/os/Bash/08-Shell脚本编程进阶/)。

### 9.2 sudo / 注入 / `!!`

```bash
sudo -v                      # 提前验证密码，后面不再立即要
sudo -k                      # 立刻作废缓存凭证（离开座位时）
```

讲解：`sudo` 有 15 分钟凭证缓存，`-v` 预热、`-k` 撤销。**密码不要出现在命令行**（`echo 'pass' | sudo -S` 会把密码留在 shell 历史，反模式）。

命令注入的本质是**特殊字符被 shell 当成语法而非数据**，三道防线：

```bash
[ -n "$name" ] || exit 1                               # 非空校验
case "$name" in *[!a-zA-Z0-9_-]*) exit 1;; esac         # 白名单字符
rm -rf -- "/data/$name"                                 # -- 终止选项解析
```

`!!` 的危险：它把上一条**原样**重跑，不检查不确认，**高危组合是 `sudo !!` + 上一条是危险命令**。重跑关键命令前先 `history | tail` 确认；`rm`/`mkfs`/`chmod -R` 这类命令坚持不用 `!!`。

### 9.3 锁定文件 / 备份习惯

```bash
sudo chattr +i /etc/app.conf     # 不可变属性：谁也改不了删不了（含 root）
sudo chattr -i /etc/app.conf     # 解锁
sudo lsattr /etc/app.conf        # 查看
cp file.conf file.conf.bak.$(date +%s)    # 改前随手备份（时间戳防覆盖）
```

输出：`----i---------e----- /etc/app.conf`

讲解：`+i` 是不可变锁，比权限位硬得多——**root 也删不掉**；代价是锁后"有权限却写不进"的诡异报错，排查前先 `lsattr`。`chattr +a`（append-only）只许追加，适合日志。它是 Linux 特有文件属性，文件系统也必须支持；macOS 不存在等价的 `chattr` 工作流。备份习惯：改配置前"一秒备份"成本最低，**没演练过的备份不算备份**，自动化见 10.3。

## 10. 综合工作流案例

### 10.1 案例 A：排查线上 CPU 飙高

场景：告警说 load 30、CPU 100%。按方法论（[性能分析](/kb/os/问题排查/01-性能分析方法论/)）走完整链条：

```bash
top -bn1 | head -20                              # 1. 全局状态
ps -eo pid,pcpu,pmem,comm --sort=-pcpu | head -5 # 2. 精确定位
strace -p 3321 -c 2>&1 | head                    # 3. 看系统调用
sudo perf top -p 3321                            # 4. 热点函数
pstree -ap | grep -C 3 3321                      # 5. 进程上下文
```

输出（top 片段）：

```
  PID USER  PR  NI  VIRT  RES  S %CPU %MEM CMD
 3321 root  20  0 1200m 360m R 187.5 2.3 /usr/bin/python3 /opt/worker.py
```

讲解：链条逻辑 **top 看全局 → ps 精确定位 → strace 看调用 → perf 看热点 → pstree 看上下文**，每步比上步更"微观"，即方法论要求的层层收敛。`%CPU 187.5` 且状态 `R`，说明进程确实在持续占 CPU（非 D 状态卡 IO），重点看 strace/perf 的热点是循环计算还是系统调用风暴。完整 CPU 方法论见 [CPU 排查](/kb/os/问题排查/02-CPU性能问题排查/)。

### 10.2 案例 B：备份目录到远程（tar | ssh）

场景：打包 `/opt/app` 直接推到备份机，本机不落地临时包。

```bash
tar -czf - /opt/app --exclude='*.log' | \
  ssh backup@10.0.0.100 'cat > /backup/app_$(date +%F).tar.gz'
ssh backup@10.0.0.100 'tar -tzf /backup/app_$(date +%F).tar.gz | head'   # 验证
```

讲解：`tar -czf -` 把包写到**标准输出**（`-` 表示 stdout），ssh 送远端 `cat > 文件`，全程流式不占本机磁盘。可 `tar -xzf - -C /restore` 流式还原；配 SSH 密钥（`ssh-keygen` + `ssh-copy-id`）后就能丢进 cron。

### 10.3 案例 C：自动清理旧日志（cron + 脚本）

场景：日志天天长大，每天凌晨 3 点清掉 7 天前的。呼应 [脚本篇](/kb/os/Bash/08-Shell脚本编程进阶/)。

```bash
cat > ~/bin/clean_logs.sh <<'EOF'
#!/bin/bash
set -u
LOG_DIR=/var/log/myapp
KEEP_DAYS=7
find "$LOG_DIR" -type f -name '*.log' -mtime +${KEEP_DAYS} -delete
echo "$(date +%F' '%T) cleaned $LOG_DIR" >> /var/log/clean.log
EOF
chmod +x ~/bin/clean_logs.sh
(crontab -l; echo "0 3 * * * /home/zhang/bin/clean_logs.sh") | crontab -
crontab -l     # 确认
```

讲解：脚本三要素 `set -u` 防变量拼错、`find -mtime` 删旧、`>> log` 留执行痕迹；先跑不带 `-delete` 的 find 看清单。`0 3 * * *` 是 cron 表达式（分 时 日 月 周），`crontab -e` 编辑、`-l` 列出、`-r` 清空。**能用 `logrotate`（系统自带日志轮转，压缩/删旧/按大小触发）就别自己写 find**，此脚本的价值在于演示 find + cron + 脚本的组合思路。

## 本章小结

1. **组合的本质**：管道把"输出→输入"串起来，`&&`/`;` 控制流程，别名/函数/脚本把组合固化成命令。这篇之前你认识工具，这篇之后你有了"接工具"的手感。
2. **高频骨架只有几个**：`awk | sort | uniq -c | sort -rn | head`（计数 Top N）、`find ... | xargs ...`（批量）、`for/while`（循环）、`&` + `wait`（并行）。记熟骨架，所有场景都是套模板。
3. **安全永远是第一参数**：删前 dry-run、`rm -i`、`chattr +i`、`sudo !!` 慎用、`set -u` 自保。快一分钟出一次事故，不划算。
4. **效率来自"工位设施"**：alias、history（`!!`、`!$`、`Ctrl+R`）、PATH、dotfile 整理，一次性投入每天复利。
5. **排查是一条收敛的链**：从 `top`/`ip a` 全局，到 `ps`/`ss` 精确定位，再到 `strace`/`perf`/`mtr` 微观——链条越走越窄，答案在最后一步。
6. **改配置要么全成功要么不动**：`mktemp` 出临时文件、`envsubst` 只展开白名单变量、最小校验通过后再用 `install`/`mv` 落到目标路径，避免线上出现"半份配置"。
7. **批量与并发靠列表和锁**：静态短列表用 `{1..10}`，带变量用 `seq`；并发用 `&` + `wait` 或 `xargs -P`，`parallel` 只在需要输出归拢与失败策略时引入；cron 任务用 `flock -n` 防重入，锁靠 fd 生命周期而非锁文件是否存在。
8. **命令行本身也是工位**：`fc` 把长命令丢进编辑器改，比重敲更少出错；`history`/`Ctrl+R` 负责召回，`alias`/函数负责固化。
9. 至此 Bash 路线收官，完整地图见 [Bash命令学习路线总览](/kb/os/Bash/00-Bash命令学习路线总览/)；把组合固化成可复用程序进入 [脚本篇](/kb/os/Bash/08-Shell脚本编程进阶/)。

## 动手实验

1. **自建 sysinfo**：按第 1 节组合 `sysinfo` 别名，跑两次并 `diff` 快照，说出哪几项数字变了。未装 `iostat` 则 `apt install sysstat` / `yum install sysstat`。
2. **日志 Top 分析**：`awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head` 分析真实日志（没有就自造几行），回答：Top 3 IP？总请求数？5xx 占比？
3. **防误删演练**：`echo hello > /tmp/safe.txt && chattr +i /tmp/safe.txt`，尝试 `rm` 和追加写入，记录两个阶段的报错；再 `chattr -i` 解锁删除。
4. **批量操作**：`for i in {01..10}` 建 10 个文件，一次性 `chmod 600 file*`（体会通配符与 find/xargs 的边界），最后 `find ... -delete` 清掉。
5. **历史效率大赏**：连续敲 3 条命令后，分别用 `!!`、`!$`、`Ctrl+R`、`^旧^新` 复现/改写它们，并把 `HISTSIZE` 调大写入 `~/.bashrc`。
6. **原子替换演练**：写一个含 `$APP_HOST`/`$APP_PORT` 的模板，先不设变量执行渲染脚本（应被 `${VAR:?}` 拦下），再设好变量走完 `mktemp` → `envsubst` → 校验 → `install` 全流程；最后确认模板里的 `$HOME` 没有被替换。
7. **列表两种来源**：用 `{1..5}` 和 `n=5; seq 1 "$n"` 各生成一次列表，解释为什么 `{1..$n}` 不展开；再用 `seq -w 8 12` 观察补零。
8. **flock 防重入**：开两个终端跑同一个持锁脚本，第二个用 `flock -n` 应立即退出并返回 75；把脚本挂到每分钟 cron，确认任务不会堆叠。
9. **fc 改长命令**：故意敲一条很长且写错的 `awk` 管道，用 `fc` 打开编辑器修正后执行，对比"重新敲一遍"的出错概率。

## 自测题

1. `uniq -c` 之前为什么必须 `sort`？
   - **答案**：`uniq` 只合并**相邻**重复行；不先排序，同样值分散各处不会被合并，计数就错。

2. `ps aux | grep nginx` 为什么常看到一条 `grep --color=auto nginx`？如何避免？
   - **答案**：grep 自己的命令行含 "nginx" 也被 `ps aux` 列出。用 `pgrep -af nginx` 或 `ps aux | grep '[n]ginx'`。

3. `cmd > file 2>&1` 与 `cmd 2>&1 > file` 有什么区别？
   - **答案**：重定向从左到右生效。前者两路都进 file；后者 stderr 先指向当时的 stdout（终端），再改 stdout 到 file——stderr 仍打印到终端。

4. 为什么 `sudo echo hi > /etc/x` 会 `Permission denied`？正确写法？
   - **答案**：`>` 由当前非 root shell 打开文件，sudo 只提升 `echo`。正确：`echo hi | sudo tee /etc/x`（追加 `sudo tee -a`）。

5. `for line in $(cat file)` 相对 `while IFS= read -r line; done < file` 有什么缺陷？
   - **答案**：前者按空白拆词并对 `*` 通配展开，空行/含空格行/特殊字符会被破坏；后者逐行原样读入，`-r` 保留反斜杠、`IFS=` 不修剪空白，更安全。

6. 写一条命令，统计 access.log 中出现次数最多的 5 个状态码。
   - **答案**：`awk '{print $9}' access.log | sort | uniq -c | sort -rn | head -5`（字段列号按日志格式调整）。

7. 端口 8080 被占用，如何一分钟定位占用进程？
   - **答案**：`ss -tlnp | grep :8080` 看 PID/进程名，或 `lsof -i :8080`；确认服务后 systemctl 管理，兜底才 kill。

8. `set -u` 的作用？为什么推荐与 `set -e`、`set -o pipefail` 一起用？
   - **答案**：`set -u` 引用未定义变量即报错退出，防止拼错变量名静默变成空串（如 `rm -rf /data/$nmae` 删错）；`set -e` 命令失败即退出、`pipefail` 管道任一段失败也算失败，三者让脚本及早失败而不是带错继续。

9. 为什么渲染配置要先写 `mktemp` 临时文件再 `install`/`mv`，而不是直接 `envsubst < tpl > /etc/app.conf`？
   - **答案**：直接重定向会在渲染开始前就截断目标文件，中途失败就留下半份甚至空配置；先写同一文件系统上的临时文件、校验通过再落位，替换才是原子的，失败时旧配置完好。同理 `cmd file > file` 也会清空输入，那种场景用 `sponge` 或临时文件。

10. `envsubst` 默认会替换模板里所有 `$VAR`（含 `$HOME`、`$PATH`），怎么只展开自己的变量？
    - **答案**：传入白名单，如 `envsubst '$APP_HOST $APP_PORT' < tpl`，未列出的 `$VAR` 原样保留。注意 `envsubst` 对未定义变量替换为空且不报错，必需项要先用 `: "${APP_HOST:?missing}"` 显式校验。

11. `{1..$n}` 为什么得不到序列？该用什么？
    - **答案**：花括号展开发生在变量展开之前，`$n` 那时还没被替换，结果是字面量 `{1..$n}`。用 `seq 1 "$n"`（或 `for ((i=1;i<=n;i++))`）；范围已知的静态列表才用 `{1..10}`。

12. `flock -n` 为什么比"检查锁文件是否存在"可靠？返回码怎么区分"没抢到锁"和"业务失败"？
    - **答案**：`test -e` + `touch` 两步之间存在竞态，且进程被 kill -9 后残留锁文件会永久卡死；`flock` 的锁绑定在打开的文件描述符上，进程退出由内核自动释放。`-n` 抢不到锁时默认退出 75（可用 `-E` 改），业务命令的退出码则原样透传，cron 里据此区分"本轮跳过"和"真失败"。

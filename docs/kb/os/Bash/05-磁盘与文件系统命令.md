::: abstract 本章定位
从"物理块设备"这一层开始实操：用 `lsblk`/`blkid`/`fdisk` 看懂磁盘布局与命名，用 `parted` 分区、`mkfs` 格式化、`mount` 挂载，再上 LVM/RAID 做弹性与冗余，最后用 `smartctl`/`badblocks` 给磁盘体检。安全红线贯穿始终：分区、格式化、镜像全是破坏性操作。承接 [Linux 文件实操](/kb/os/Linux/03-Linux文件系统与磁盘实操/)，但本篇管的是分区表之下的那层。
:::

[Linux 文件实操](/kb/os/Linux/03-Linux文件系统与磁盘实操/) 讲的是"在已挂载好的文件系统上干活"（`df`/`du`/`stat`/`ln`/`fsck`），本篇再往下一层：**没有分区表、没有文件系统时怎么办**。你把一块新硬盘插进服务器，面对的就是本篇的八个问题：它是谁（lsblk）→ 怎么分区（fdisk/parted）→ 怎么格式化（mkfs）→ 怎么挂（mount/swap）→ 怎么做弹性（LVM）→ 怎么做冗余（RAID）→ 怎么体检（smartctl/badblocks）。

## 1. 块设备查看：先看清"你手里有几块盘"

### 1.1 lsblk：树形看磁盘与分区

```bash
lsblk
```
预期输出片段：
```
NAME        MAJ:MIN RM  SIZE RO TYPE MOUNTPOINT
sda           8:0    0  100G  0 disk
├─sda1        8:1    0    1G  0 part /boot
├─sda2        8:2    0   99G  0 part
│ └─vg-lv     253:0  0   99G  0 lvm  /
nvme0n1     259:0    0  512G  0 disk
└─nvme0n1p1  259:1    0  512G  0 part /data
```
解读：
- 树形结构天然表达"磁盘 → 分区"的层级：`sda` 是整块盘，`sda1`/`sda2` 是它上面的分区；`└─` 分支里还有 `lvm`（逻辑卷，见第 6 节）。
- **磁盘是 `disk`，分区是 `part`**：`TYPE` 列一眼区分。`MOUNTPOINT` 是空的就是没挂载。

自定义列输出，是查看"这盘是 HDD 还是 SSD、走什么总线"的标准姿势：

```bash
lsblk -o NAME,SIZE,TYPE,TRAN,ROTA,MOUNTPOINT
```
预期输出片段：
```
NAME        SIZE TYPE TRAN ROTA MOUNTPOINT
sda        100G  disk sata    1
├─sda1       1G  part sata    1  /boot
└─sda2      99G  part sata    1
nvme0n1    512G  disk nvme    0  /data
```
| 列 | 含义 | 判读 |
|---|---|---|
| `NAME` | 设备名 | `sda`/`nvme0n1`... |
| `SIZE` | 容量 | 人类可读 |
| `TYPE` | disk/part/lvm/rom | 层级角色 |
| `TRAN` | 传输总线 | `sata`/`nvme`/`usb`/`sas` |
| `ROTA` | **rotational 旋转** | **1=HDD（机械盘），0=SSD** |
| `MOUNTPOINT` | 挂载点 | 空=未挂载 |

### 1.2 blkid：UUID 与文件系统类型

```bash
sudo blkid /dev/sda2
```
预期输出：`/dev/sda2: UUID="7f2a8c9e-..." TYPE="ext4" PARTUUID="b8a1..."`
```bash
sudo blkid -s UUID -o value /dev/sda2   # 只要 UUID 值（脚本里很常用）
```
解读：`blkid` 读出**块设备上已经写好的文件系统指纹**（UUID、类型、LABEL）。`UUID` 是格式化的那一刻写进磁盘元数据的，**跨机器唯一、稳定**，所以 `/etc/fstab` 里推荐用 `UUID=` 而不是 `/dev/sda2`（盘符顺序可能变化）。

### 1.3 fdisk -l：全局看分区表

```bash
sudo fdisk -l /dev/sda
```
预期输出片段：
```
Disk /dev/sda: 100 GiB, 107374182400 bytes, 209715200 sectors
Disk model: ST1000LM048
Device     Boot   Start       End   Sectors  Size Id Type
/dev/sda1  *       2048   2099199   2097152    1G 83 Linux
/dev/sda2       2099200 209715199 207616000   99G 83 Linux
```
解读：`fdisk -l` 读的是**分区表本身**（不是文件系统），能看到起始扇区、结束扇区、分区类型 ID。扇区号是 512 字节单位；起始 `2048` 是 1MiB 对齐的惯例（GPT 时代默认），磁盘每格以扇区计数。

### 1.4 /dev/sda 命名规则：看懂盘名

| 设备名 | 含义 | 分区命名 |
|---|---|---|
| `/dev/sda`, `/dev/sdb` | SCSI/SATA/USB（走 SCSI 子系统） | `sda1`, `sda2` |
| `/dev/nvme0n1` | NVMe：控制器 `0`、命名空间 `n1` | `nvme0n1p1`（**p+数字**，避免和盘名歧义） |
| `/dev/vda` | virtio（KVM/云主机） | `vda1` |
| `/dev/mmcblk0` | eMMC/SD 卡 | `mmcblk0p1` |
| `/dev/hda` | IDE（上古遗产，基本绝迹） | `hda1` |

::: tip 命名规律
字母 `a/b/c` 按**被发现顺序**分配，不是固定盘位；`nvme` 的 `p` 与 `mmcblk` 的 `p` 作用相同——**分区号前面加 `p` 防止 `nvme0n1` 和 `nvme0n11` 撞名**。
:::

### 1.5 /sys/block/：内核视角的"目录"

Linux 把每个块设备在 `/sys/block/` 下建一个目录，直接读就是内核的答案：

```bash
ls /sys/block/                          # 内核认识的块设备
cat /sys/block/sda/queue/rotational     # 1=机械盘 0=SSD（lsblk ROTA 的数据来源）
cat /sys/block/sda/size                 # 总扇区数（×512 字节 = 容量）
ls /sys/block/sda/                      # 里面 sda1/... 就是分区
udevadm info --query=path --name=/dev/sda   # udev 视角的设备路径
```
解读：`lsblk` 显示的数据本质上是把 `/sys` 里的这些文件"格式化排版"给你看。**`/sys/block/sda/size` 的单位永远是 512 字节扇区**，这是内核约定；`/proc/partitions` 也有一份。

## 2. 分区管理：fdisk 与 parted

### 2.1 fdisk 交互式操作流程

```bash
sudo fdisk /dev/sdb
```
进入交互提示符 `Command (m for help):`，常用子命令：

| 命令 | 作用 |
|---|---|
| `m` | 帮助 |
| `p` | 打印当前分区表 |
| `n` | 新建分区（new） |
| `d` | 删除分区（delete） |
| `t` | 改分区类型 ID |
| `w` | **写入并退出（write，真正落盘）** |
| `q` | 不保存退出（quit，所有改动作废） |

新盘分区流程（交互输入依次为）：
```
Command (m for help): n
Partition number (1-4, default 1):        # 回车默认 1
First sector (2048-20971519, default 2048): # 回车用默认，1MiB 对齐
Last sector, +/-sectors or +/-size{K,M,G} (default 20971519): 回车占满
Command (m for help): p                     # 检查
Command (m for help): w                     # 写入
```
预期输出片段（`p` 后）：
```
Device     Boot Start      End  Sectors Size Id Type
/dev/sdb1        2048 20971519 20969472  10G 83 Linux
```

::: warning fdisk 是真正的"危险动作"
`w` 提交后旧分区表被覆盖，**分区边界内的所有数据逻辑上全部丢失**。误操作且没写盘时，用 `q` 退出可完全撤销；写了盘就后悔不了了。线上磁盘操作前先 `lsblk` 核对盘符，再 `fdisk -l` 确认目标。
:::

### 2.2 parted：MBR 与 GPT 的取舍

```bash
sudo parted /dev/sdb mklabel gpt               # 建 GPT 分区表
sudo parted /dev/sdb mkpart primary ext4 1MiB 100%
sudo parted /dev/sdb print
```
预期输出片段：
```
Number  Start   End     Size    File system  Name     Flags
 1      1049kB  10.7GB  10.7GB  ext4         primary
```
`parted` 用命令式参数（非交互），适合脚本化；`print` 等价于 `fdisk -l`。

**MBR vs GPT 对比**：

| 维度 | MBR | GPT |
|---|---|---|
| 分区表存储 | 磁盘第 0 扇区（64 字节 4 个主分区项） | 磁盘头部 + 尾部各一份冗余 |
| 最大容量 | 2 TiB（LBA 32 位寻址） | 8 ZiB（LBA 64 位） |
| 主分区数 | 最多 4 个（可拆扩展分区） | 默认最多 128 个 |
| 引导方式 | Legacy BIOS | UEFI（也兼容 BIOS） |
| 数据保护 | 无校验，坏扇区即失 | CRC32 校验，可自检恢复 |

::: tip 怎么选
新机器一律 GPT + UEFI；只有需要兼容老 BIOS 引导、或要给老设备用的时候才考虑 MBR。**2 TiB 以上单盘必须 GPT**。
:::

### 2.3 分区表备份与验证

```bash
sudo sfdisk -d /dev/sdb > sdb-partition.bak    # 备份分区表（文本）
sudo sfdisk /dev/sdb < sdb-partition.bak       # 恢复（仅分区表，不含数据）
sudo dd if=/dev/sdb of=mbr.bak bs=512 count=1  # 备份 MBR 前 512 字节（含引导代码）
lsblk /dev/sdb                                 # 分区后验证树形结构
```
解读：`sfdisk -d` 把分区表导出为可读文本，比整盘 dd 快得多；**它只备份分区定义，不备份数据**，恢复后盘是"空分区+老布局"。验证永远用 `lsblk`/`fdisk -l` 再确认一次。

## 3. 格式化与文件系统：mkfs

### 3.1 mkfs：一行语法与别名

```bash
sudo mkfs.ext4 /dev/sdb1                  # 直接调 e2fsprogs
sudo mkfs -t xfs /dev/sdc1                # -t 指定类型
sudo mkfs.xfs /dev/sdc1                   # 等价写法（mkfs 是派发器）
```
::: important mkfs 的本质
`mkfs` 只是个"派发器"，真正干活的是 `mkfs.ext4`/`mkfs.xfs`/`mkfs.btrfs` 这些后端程序；`mkfs -t xfs` 和 `mkfs.xfs` 完全等价。**mkfs 只接受分区（如 `/dev/sdb1`）或整块盘，不接受挂载点**——它写的是块设备。
:::

### 3.2 mke2fs 关键选项（ext4 底层是 mke2fs）

```bash
sudo mkfs.ext4 -b 4096 -i 16384 -m 1 /dev/sdb1
```
预期输出片段：
```
mke2fs 1.46.5 (30-Dec-2021)
Creating filesystem with 2621440 4k blocks and 655360 inodes
Filesystem UUID: 7f2a8c9e-...   ← 每次 mkfs 都生成全新 UUID
Superblock backups stored on blocks:
```

| 选项 | 含义 | 场景 |
|---|---|---|
| `-b 块大小` | 数据块字节数（1024/2048/4096） | 大文件多选 4096，小文件多选 1024 |
| `-i 每 inode 字节` | 平均多少字节分配一个 inode | 小文件海量（缓存/日志）就调小，如 `-i 8192` |
| `-m 预留百分比` | 给 root 预留的块比例（默认 5%） | 大数据盘调小到 `-m 1`，省空间 |
| `-L LABEL` | 设置卷标 | 便于 `lsblk`/`blkid` 识别 |

::: warning mkfs 前必须确认
格式化 = 重建整个文件系统，**分区上的全部数据不可恢复**。先 `lsblk`、`df -h` 双重确认盘符，虚拟机上练习最稳妥。
:::

### 3.3 格式化之后的 UUID

```bash
sudo blkid /dev/sdb1
```
预期输出：`/dev/sdb1: UUID="7f2a8c9e-3b1d-..." TYPE="ext4"`。
解读：UUID 在 **mkfs 那一刻**生成并写盘，同一分区每次重新 mkfs UUID 都不同。这解释了为什么换了系统/重新格式化后 `/etc/fstab` 里的 UUID 对不上——**不要用 UUID 写死在一个会被反复格式化的实验盘上**。

### 3.4 文件系统类型选择

| 类型 | 定位 | 特点 | 缩容/扩容 |
|---|---|---|---|
| `ext4` | Linux 通用主力 | 最成熟、兼容性最好、fsck 生态完善 | 可扩可缩（`resize2fs`） |
| `xfs` | 大文件、高吞吐 | 性能好、**只支持在线扩容、不支持缩容** | 只扩（`xfs_growfs`） |
| `btrfs` | 现代 COW | 快照、校验和、透明压缩 | 扩缩都行，还有子卷 |
| `swap` | 交换空间 | 不是给用户数据用的，见第 5 节 | — |

选型一句话：**没特殊要求就 ext4；单文件超大或跑数据库选 xfs；要快照/子卷/压缩玩 btrfs**。btrfs 是 COW（写时复制）文件系统，概念上与 ext4 差别很大，这里只记结论。

## 4. 挂载与卸载：mount / umount / fstab

### 4.1 mount：挂载一个文件系统

```bash
sudo mount -t ext4 /dev/sdb1 /data            # -t 指定类型（通常可省略，自动探测）
sudo mount -o ro /dev/sdb1 /data              # 只读挂载
sudo mount -o remount,ro /data                # 对已挂载设备重挂为只读（不卸载）
sudo mount -o remount,noexec /data             # 对已挂载分区禁止执行二进制（安全加固）
sudo mount -o defaults,data=ordered /dev/sdb1 /data   # ext4 日志模式 ordered
```
常用 `-o` 选项：

| 选项 | 含义 | 典型场景 |
|---|---|---|
| `ro` / `rw` | 只读 / 读写 | 备份盘、光盘 |
| `noexec` | 禁止执行二进制 | /tmp、用户上传目录防提权 |
| `nodev` / `nosuid` | 禁止设备文件/清除 suid | 安全加固组合拳 |
| `noatime` | 不更新 atime | 减少读盘写放大（见 [Linux 文件实操](/kb/os/Linux/03-Linux文件系统与磁盘实操/)） |
| `remount` | 原地改挂载选项，不用卸载 | 把根文件系统切只读 |
| `data=ordered` | ext4 日志模式（默认）：先写数据再写元数据日志 | 崩溃一致性 |
| `loop` | 把普通文件当块设备挂载 | 实验镜像、ISO |

::: tip data=ordered 是什么
ext4 的三种日志模式：`writeback`（最快，元数据日志）、`ordered`（默认，数据先落盘再写元数据）、`journal`（最稳，数据和元数据都进日志）。运维日常看到 `data=ordered` 就是默认值，不必慌。
:::

### 4.2 umount：卸载

```bash
sudo umount /data                             # 常规卸载
sudo umount -l /data                          # 懒惰卸载：先摘挂载点，进程用完自动断开
sudo umount -f /dev/sdb1                      # 强制卸载（NFS 卡死、挂载点占用时）
```
解读：
- `-l`（lazy）：立即从目录树摘除，已打开该文件系统的进程还能继续读写，全部关闭后才真正卸载。**适合 NFS 卡住、普通 umount 一直 busy 的场景**。
- `-f`（force）：强行断开，NFS 服务器挂了时 `umount` 会卡住，`-f` 能救回来；本地磁盘一般不推荐 `-f`。

::: warning umount busy 排查
报 `target is busy` 时，用 `lsof +D /data` 或 `fuser -mv /data` 找到占用进程，而不是直接 `-f` 暴力卸载——除非能确认是 NFS/卡死。
:::

### 4.3 /etc/fstab：开机自动挂载

`/etc/fstab` 每行 6 个字段，**空格或 Tab 分隔**：

```
UUID=7f2a8c9e-...-3b1d  /data  ext4  defaults,noatime  0  2
```

| 列号 | 字段 | 含义 | 示例 |
|---|---|---|---|
| 1 | device | 设备标识，**推荐用 `UUID=`** | `UUID=7f2a...` |
| 2 | mountpoint | 挂载点目录 | `/data` |
| 3 | fstype | 文件系统类型 | `ext4` / `xfs` / `swap` |
| 4 | options | 挂载选项，逗号分隔 | `defaults,noatime` |
| 5 | dump | 是否备份（0=不备份） | 0 |
| 6 | pass | fsck 顺序：**0=不检查，1=根，2=其他** | 2 |

```bash
sudo mount -a        # 按 fstab 尝试挂载全部（改完 fstab 先跑这个，别急着 reboot）
cat /proc/mounts     # 内核真实的挂载状态（含选项），比 /etc/mtab 更权威
```
解读：`mount -a` 只挂 fstab 里标记为"待挂"的项；`pass` 为 1 的根先查、2 的其他后查。**fstab 写错会导致开机进不去救援模式**——所以改完必须 `mount -a` 自检，新手别直接 `reboot`。

### 4.4 mount --bind：把目录绑定过去

```bash
sudo mount --bind /var/www /data/www          # 把已有目录"镜像"到另一个位置
```
解读：`--bind` 不创建新文件系统，只是把目录树**绑定到另一挂载点**，两边是同一份数据。常用于：容器迁移时把数据目录挂到新路径、日志目录与备份目录共享。卸载用普通 `umount` 即可。

### 4.5 XFS 挂载注意

- **只支持扩容、不支持缩容**：想缩分区就趁 mkfs 前规划好。
- 在线扩容用 `xfs_growfs /data`（按**挂载点**，不是设备路径）。
- 常用优化挂载项：`defaults,noatime,nodiratime`。
- 没有 `fsck` 那套概念，检查工具是 `xfs_repair`（且必须在卸载后）。
- 别在同一块盘上用 XFS + 频繁断电的坏环境，损坏恢复成本高于 ext4。

## 5. swap 管理：内存的"第二层"

### 5.1 创建 swap 文件（推荐方式，不用分区）

```bash
sudo dd if=/dev/zero of=/swapfile bs=1M count=2048   # 先造一个 2G 文件
sudo chmod 600 /swapfile                             # swap 权限必须 600，防泄密
sudo mkswap /swapfile                                # 格式化为 swap
sudo swapon /swapfile                                # 开启
free -h                                              # 验证 Swap 行
```
预期输出片段（`free -h`）：
```
              total        used        free   ...
Mem:           7.7G        6.5G        1.2G
Swap:          2.0G        0.4G        1.6G
```
解读：`free -h` 的 `Swap` 行展示交换空间的总量/已用/剩余。`swapon --show` 能列出当前启用中的 swap 设备与优先级。

### 5.2 关闭与开机配置

```bash
sudo swapoff /swapfile            # 关闭（系统把交换内容收回内存）
```
`/etc/fstab` 追加一行：
```
/swapfile  none  swap  sw  0  0
```
注意：swap 行的 `mountpoint` 写 `none`，`fstype` 写 `swap`，`options` 用 `sw`。

### 5.3 swap 大小建议

| 场景 | 建议 |
|---|---|
| 传统经验值 | 2 × RAM（旧书常写，已过时） |
| 启用休眠（suspend-to-disk） | **swap ≥ RAM**（休眠要装下整个内存） |
| 现代服务器/容器 | 4–8 GB 足够，或干脆不要 |
| 内存 8G 以下的小机器 | 建议留 2–4 GB swap 兜底 |

调节激进程度：`cat /proc/sys/vm/swappiness`（默认 60，越小越不爱用 swap）。

::: tip zram：压缩的 swap
`zram` 是**内存里的压缩块设备**：先把内存页压缩再"交换"到 zram，等于给内存扩容。安卓、低内存笔记本常靠它。

:::```bash
> sudo modprobe zram num_devices=1; ZRAM=$(sudo zramctl --find --size 2G); sudo mkswap "$ZRAM"; sudo swapon "$ZRAM"
> ```
> 这背后是"匿名页压缩"机制，原理见 [交换疑难](/kb/os/问题排查/08-虚拟内存与交换疑难/)。

## 6. LVM：把磁盘变成可以随意伸缩的"乐高"

### 6.1 三层概念

```
PV(物理卷)                 VG(卷组)                LV(逻辑卷)
/dev/sdb1 ─────────┐
/dev/sdc1 ─────────┼─► vgdata(VG, 一块"虚拟大盘") ─► lvdata ─► /dev/vgdata/lvdata
  pvcreate         │             vgcreate            lvcreate  └► lvbackup
```
| 层 | 全称 | 作用 | 创建命令 |
|---|---|---|---|
| PV | Physical Volume | 一块可被 LVM 管理的物理盘/分区 | `pvcreate` |
| VG | Volume Group | 把多块 PV 合并成的"虚拟大池子" | `vgcreate` |
| LV | Logical Volume | 从 VG 里切出来、真正格式化挂载的卷 | `lvcreate` |

### 6.2 建库三板斧

```bash
sudo pvcreate /dev/sdb1 /dev/sdc1         # 1. 初始化 PV
sudo vgcreate vgdata /dev/sdb1 /dev/sdc1  # 2. 组卷组（注意是 vgcreate 后跟 VG 名再跟 PV）
sudo lvcreate -n lvdata -L 10G vgdata     # 3. 切逻辑卷（-n 名字，-L 大小）
sudo pvs; sudo vgs; sudo lvs              # 三层分别查看
sudo mkfs.ext4 /dev/vgdata/lvdata         # LV 就是个块设备，照常格式化
sudo mount /dev/vgdata/lvdata /mnt/data
```

### 6.3 在线扩容（LVM 的招牌能力）

```bash
sudo lvextend -L +5G /dev/vgdata/lvdata        # ① 先把 LV 从 10G 扩到 15G
sudo resize2fs /dev/vgdata/lvdata              # ② ext4 在线扩文件系统
# XFS 用:  sudo xfs_growfs /mnt/data           #    注意按挂载点、不能缩
# 一步到位: sudo lvextend -r -L +5G /dev/vgdata/lvdata   # -r 自动帮你扩文件系统
```
::: tip 扩容两步不要记反
顺序永远是 **先扩 LV（lvextend），再扩文件系统（resize2fs / xfs_growfs）**。反过来文件系统会报设备大小没变。缩容则相反且危险得多，不建议在线缩。
:::

### 6.4 快照与删除

```bash
sudo lvcreate -s -n lvdata-snap -L 1G /dev/vgdata/lvdata   # 快照：1G 的"时间机器"
sudo mount -o ro /dev/vgdata/lvdata-snap /mnt/snap          # 快照只读挂载做备份
sudo lvremove /dev/vgdata/lvdata-snap                       # 用完了删快照
sudo lvremove /dev/vgdata/lvdata                            # 删 LV（先 umount）
```
解读：LVM 快照走 COW（写时复制）——快照创建后，原卷**第一次被修改**的块才拷到快照区，所以快照刚建时几乎不占空间，随改动增多膨胀。`/dev/vgdata/lvdata` 这种路径也可以写成 `/dev/mapper/vgdata-lvdata`，二者指向同一设备。

### 6.5 LVM vs 直接分区

| 维度 | 直接分区 | LVM |
|---|---|---|
| 扩容 | 麻烦（要动分区表、怕破坏数据） | `lvextend` 一条命令，在线完成 |
| 多盘合并 | 不行，一盘一区 | VG 把多块盘合成一个池 |
| 快照 | 无 | 原生支持 |
| 复杂度 | 低 | 高一层，排障多一环 |
| 性能 | 略高（无映射层） | 差一丁点，几乎可忽略 |

宕机/坏盘后 LVM 元数据恢复是经典事故场景，见 [文件系统故障](/kb/os/问题排查/09-文件系统与磁盘故障/)。

## 7. RAID：用 mdadm 搭软阵列

### 7.1 创建各等级阵列

```bash
sudo mdadm --create /dev/md0 -l 0 -n 2 /dev/sdb1 /dev/sdc1   # RAID0：2 块条带化
sudo mdadm --create /dev/md1 -l 1 -n 2 /dev/sdd1 /dev/sde1   # RAID1：2 块镜像
sudo mdadm --create /dev/md5 -l 5 -n 3 /dev/sdb1 /dev/sdc1 /dev/sdd1  # RAID5：3 块(≥3)
sudo mdadm --create /dev/md10 -l 10 -n 4 /dev/sdb1 /dev/sdc1 /dev/sdd1 /dev/sde1  # RAID10：4 块(≥4)
```
参数速记：`--create` 后的 `/dev/md0` 是阵列名；`-l`（level）是等级；`-n` 是盘数。**盘数下限：RAID0/1 需 2 块，RAID5 需 3 块，RAID10 需 4 块**。

::: warning mdadm --create 会重建阵列头并破坏成员盘数据
与 mkfs 同级的危险操作。**用错 `-n` 或盘序会导致数据丢失**。练习一律用空盘/镜像文件。不同等级的取舍见 [RAID 概念](/kb/os/存储/01-磁盘结构与大容量存储/)。
:::

### 7.2 状态查看与监控

```bash
sudo mdadm --detail /dev/md0          # 阵列详情（等级、成员、状态、重建进度）
sudo mdadm --detail --scan            # 扫描并打印所有阵列（用于写 mdadm.conf）
cat /proc/mdstat                      # 内核实时状态，最常用
```
预期输出片段（`/proc/mdstat`）：
```
Personalities : [raid1]
md1 : active raid1 sde1[1] sdd1[0]
      1048576 blocks super 1.2 [2/2] [UU]
```
解读：`[2/2]` = 2 块盘里 2 块在线，`[UU]` = 两块都正常（`U`=up，`_`=down）；重建时这里会显示进度条 `[===>...]`。

### 7.3 降级、换盘与重建

```bash
sudo mdadm /dev/md1 -f /dev/sdd1      # fail：模拟一块盘坏掉 → 阵列降级
cat /proc/mdstat                      # [2/1] [_U] ← 只剩 1 块在线
sudo mdadm /dev/md1 -r /dev/sdd1      # remove：拔掉坏盘
sudo mdadm /dev/md1 -a /dev/sdd1      # add：插入新盘，自动触发 rebuild
cat /proc/mdstat                      # 观察重建进度
```
解读：**RAID1/5/10 在坏一块时能继续用（降级运行），RAID0 坏任何一块直接全损**。`-f`/`-r`/`-a` 的顺序即故障处理三连：标记失效 → 移除 → 替换重建。重建期间磁盘读写压力大，属于高风险窗口。

### 7.4 软 RAID vs 硬 RAID

| 维度 | 软 RAID（mdadm） | 硬 RAID（阵列卡） |
|---|---|---|
| 承担者 | CPU + 内核 `md` 模块 | 阵列卡上的专用芯片/缓存 |
| 成本 | 免费，普通主板即可 | 卡贵，电池/电容写缓存 |
| 性能 | 高负载下占 CPU | 硬件卸载，可加 BBU 缓存 |
| 系统可见性 | 每个成员盘可见，状态透明 | 只看到 `/dev/sda`（阵列卡虚拟出来的） |
| 配置 | `mdadm` + `/proc/mdstat` 全透明 | 进 BIOS/卡管理界面 |

::: tip 无论软硬，RAID ≠ 备份
RAID 防"盘坏"，不防"误删/勒索/火灾"。**重要数据必须在 RAID 之外再留一份**。
:::

## 8. 磁盘健康与性能

### 8.1 smartctl：S.M.A.R.T. 体检

```bash
sudo smartctl -a /dev/sda          # 全部 SMART 信息 + 属性表
sudo smartctl -H /dev/sda          # 只看健康结论（PASSED/FAILED）
```
预期输出片段（`-a` 属性表）：
```
ID# ATTRIBUTE_NAME          VALUE WORST THRESH TYPE      UPDATED  WHEN_FAILED RAW_VALUE
  5 Reallocated_Sector_Ct   100   100   010   Pre-fail  Always       -          0
  9 Power_On_Hours          100   100   000   Old_age    Always       -        14230
194 Temperature_Celsius      61    61    000   Old_age    Always       -           41
197 Current_Pending_Sector  100   100   000   Old-age    Always       -           0
```
| 属性 | 含义 | 警讯 |
|---|---|---|
| `5 Reallocated_Sector_Ct` | 重映射坏扇区数 | **>0 就要盯**，持续增长说明盘在加速损坏 |
| `197 Current_Pending_Sector` | 等待重映射的坏扇区 | 有值 = 有坏道正在酝酿 |
| `198 Offline_Uncorrectable` | 离线不可纠正错误 | 有值立刻备份 |
| `9 Power_On_Hours` | 累计通电小时数 | 判断盘龄 |
| `194 Temperature` | 温度 | >55°C 长期运行加速老化 |

::: warning SMART 指标都是"病发信号"
`Reallocated_Sector_Ct` 有一两颗可能是出厂/瞬时问题；**一旦连续增长或出现 Pending Sector，马上备份换盘**，别等 `-H` 报 FAILED——那通常已经晚了。
:::

### 8.2 badblocks：坏道扫描

```bash
sudo badblocks -sv /dev/sdb           # 只读检测（安全，不写盘）
sudo badblocks -svw /dev/sdb          # 写+读破坏性检测（会清空全盘数据！）
```
解读：`-s` 显示进度，`-v` 输出细节，`-w` 是 destructive write test（逐块写模式再读回验证），**仅限报废评估或全新盘**。日常体检优先 `smartctl`；`badblocks` 扫描慢、耗盘，只在怀疑物理坏道时用。

### 8.3 dd：磁盘镜像备份与恢复

```bash
sudo dd if=/dev/sda of=/backup/sda.img bs=4M status=progress   # 整盘备份
sudo dd if=/backup/sda.img of=/dev/sdb bs=4M status=progress   # 恢复到另一块盘
sudo dd if=/dev/sda bs=4M status=progress | gzip > sda.img.gz  # 备份+压缩（空盘更省）
```
解读：`if=` 输入、`of=` 输出、`bs=` 块大小、`status=progress` 显示进度（现代 dd）。整盘镜像 = 分区表 + 数据 + 引导全都要，是**按块复制、不关心文件系统**，挂掉的盘照样能 dd。

::: warning dd 的 of= 写错盘 = 全盘毁灭
`dd` 没有"确认"环节，**`of=/dev/sda` 写错一次就报废一整块盘**。写前 `lsblk` 三遍，of= 指向备份文件/新盘，绝不指向有数据的源盘。
:::

### 8.4 磁盘性能测试：dd 与 fio

```bash
dd if=/dev/zero of=/tmp/seqwrite bs=1M count=1024     # 粗略顺序写测速
dd if=/dev/sda of=/dev/null bs=1M count=1024           # 粗略顺序读测速
```
fio（专业基准，能压出随机读写/延迟）：
```bash
fio --name=randread --rw=randread --bs=4k --size=1G --filename=/dev/vgdata/lvdata --runtime=30
```
解读：`dd` 测试只能看"顺序大块吞吐"，且会被缓存干扰；`fio` 可控队列深度、随机/顺序、块大小、时长，是业界基准。**对在线生产盘做 fio 前先确认文件名**，写到 `/dev/vgdata/...` 会覆盖数据。深入的方法论见 [IO 实操](/kb/os/Linux/04-LinuxIO与性能监控实操/)。

### 8.5 findmnt / mountpoint：查询挂载状态

`mount` 既能挂载也能显示挂载信息，但在脚本和排障中，`findmnt` 更适合查询：它直接读取内核 mount API，能按设备、路径、文件系统类型过滤，并能用树形或 JSON 输出。

```bash
findmnt --target /data                 # 查询某个路径实际落在哪个文件系统
findmnt --source /dev/sdb1             # 按设备查挂载点
findmnt -t ext4,xfs -o TARGET,SOURCE,FSTYPE,OPTIONS
findmnt --json --target /data          # 脚本需要结构化输出
mountpoint /data
mountpoint -q /data; echo $?            # -q 静默检查，0=是挂载点，非 0=不是
```

预期输出：

```
TARGET SOURCE    FSTYPE OPTIONS
/data  /dev/sdb1 ext4   rw,relatime
/data is a mountpoint
0
```

用途与边界：`findmnt --target` 会解析路径所在的实际挂载，适合确认某个目录有没有跨到另一块盘；`mountpoint -q` 适合 shell 的成功/失败判断。查询时优先 `findmnt`，真正执行挂载/卸载仍用 `mount`/`umount`。

### 8.6 blockdev / hdparm / nvme：块设备与磁盘能力

先用无写入操作读取块设备的大小和扇区信息：

```bash
sudo blockdev --getsize64 /dev/sdb1        # 字节数
sudo blockdev --getss /dev/sdb1            # 逻辑扇区大小
sudo blockdev --getpbsz /dev/sdb1          # 物理扇区大小
sudo blockdev --getro /dev/sdb1            # 1=只读，0=可写
```

预期输出：

```
10737418240
512
4096
0
```

`blockdev` 适合在脚本中拿到内核认定的设备属性；不要把 `--setro`、`--setrw` 当作文件系统权限控制，它们只改变块设备层的访问状态，且可能影响正在使用它的服务。

SATA/SAS 设备可用 `hdparm` 查看 IDENTIFY 信息：

```bash
sudo hdparm -I /dev/sda                 # 型号、能力、扇区、写缓存等
sudo hdparm -tT /dev/sda               # 只读缓存/设备读取测试，避免在线高峰执行
```

预期输出片段：

```
/dev/sda:
 ATA device, with non-removable media
        Model Number:       ST1000LM048
        Sector size (logical/physical): 512 bytes / 4096 bytes
 Timing cached reads:   12000 MB in  2.00 seconds = 6000.00 MB/sec
 Timing buffered disk reads: 420 MB in  3.04 seconds = 138.16 MB/sec
```

`hdparm -I` 是查询，`-tT` 是粗略读取基准；`-W`、`-B` 等会改变写缓存或电源管理策略，除非已经理解控制器和断电保护，否则不要直接在生产盘上修改。

NVMe 设备用 `nvme-cli`，设备路径通常是控制器 `/dev/nvme0`，命名空间则是 `/dev/nvme0n1`：

```bash
sudo nvme list
sudo nvme smart-log /dev/nvme0             # 温度、寿命、介质错误、百分比使用量
sudo nvme smart-log /dev/nvme0 -o json    # 机器解析
```

预期输出片段：

```
Node             SN           Model                 Namespace  Usage
/dev/nvme0n1     ABC123       Example NVMe 1TB       1          1.00 TB / 1.00 TB
temperature : 38 C
percentage_used : 3%
media_errors : 0
```

`smartctl -a /dev/nvme0` 也能检查部分 NVMe，但 `nvme list`/`nvme smart-log` 是 NVMe 原生接口。硬件、驱动和 udev 的更深排查交叉到未来的 [内核模块硬件与系统参数命令](/kb/os/Bash/17-内核模块硬件与系统参数命令/)。

### 8.7 分区表变化：partprobe / partx / sgdisk / gdisk

修改分区表后，磁盘上的新表和内核当前使用的分区表可能暂时不同。先确认没有文件系统或 LVM 正在依赖目标分区，再让内核重新读取：

```bash
sudo partprobe /dev/sdb                  # 通知内核重新读取分区表
sudo partx --show /dev/sdb               # 显示内核认到的分区
sudo partx --update /dev/sdb             # 更新已有分区的内核信息
sudo partx --add /dev/sdb                # 添加内核尚未登记的分区
```

预期输出（`partx --show`）：

```
NR  START       END  SECTORS  SIZE NAME UUID
 1   2048  2099199  2097152    1G      ...
 2 2099200  ...       ...     99G      ...
```

`partprobe` 常常无输出，成功主要看 `lsblk`/`partx --show` 的结果。若提示设备忙，不要反复强刷；先卸载、停用 swap/LVM/RAID，或安排维护窗口。必要时重新登录或重启，避免应用继续使用旧边界。

GPT 的检查和备份可用 `sgdisk`，`gdisk` 适合交互式查看/修复建议：

```bash
sudo sgdisk --print /dev/sdb               # 非交互打印 GPT
sudo sgdisk --verify /dev/sdb              # 校验主/备 GPT 与 CRC
sudo sgdisk --backup=sdb.gpt.bak /dev/sdb  # 备份 GPT 结构
sudo gdisk -l /dev/sdb                     # 只读列出分区表
```

预期输出片段：`No problems found.  ... partitions ...`。`sgdisk --load-backup=...`、`--zap-all` 等写操作会覆盖分区表；恢复前先确认设备、备份文件和扇区布局，不能把 GPT 备份当作文件数据备份。

### 8.8 growpart：先扩分区，再扩文件系统

云盘或虚拟磁盘变大后，扩容必须经过两个不同层次：

1. **分区层**：用 `growpart` 把分区边界扩到磁盘末尾。
2. **文件系统层**：用对应的文件系统工具吃掉分区新增空间。

`growpart` 通常由 Debian/Ubuntu 的 `cloud-guest-utils` 或 RHEL 系的 `cloud-utils-growpart` 提供：

```bash
sudo growpart /dev/sdb 1                 # 把 /dev/sdb1 扩到磁盘末尾
sudo growpart /dev/nvme0n1 1             # NVMe 仍传“磁盘 + 分区号”，不是 p1
sudo partprobe /dev/sdb                  # 必要时刷新内核分区视图
```

预期输出：

```
CHANGED: partition=1 start=2048 old: size=20969472 end=20971519
new: size=41940991 end=41943038
```

第二步必须按文件系统选择：

```bash
# ext4：通常可在线扩容
sudo resize2fs /dev/sdb1

# XFS：必须按挂载点，不能按设备路径
sudo xfs_growfs /data

# Btrfs：按挂载点扩到设备当前最大可用空间
sudo btrfs filesystem resize max /data
```

预期验证：`lsblk` 的分区 SIZE 先变大，随后 `df -hT /data` 的文件系统容量才变大。**只执行 growpart 不会自动扩文件系统；只执行 resize2fs/xfs_growfs 也不会越过分区边界。** LVM 场景则是 `pvresize` → `lvextend` → 文件系统扩容，不能把 `growpart` 直接套在 LV 上。

### 8.9 wipefs：清理签名前先做无写入确认

`wipefs` 只清除能识别到的文件系统、RAID、LVM、分区表签名，不等同于安全擦除整块盘，但足以让系统“不再识别原来的卷”。

```bash
sudo wipefs --no-act /dev/sdb              # 只列出签名，不写盘
sudo wipefs --all --backup /dev/sdb        # 清除签名并尝试保存签名备份
```

预期输出（`--no-act`）：

```
DEVICE OFFSET TYPE UUID                                 LABEL
/dev/sdb 0x438 ext4 7f2a8c9e-...                         data
```

::: warning `wipefs --all` 是破坏性命令
执行前必须用 `lsblk -f`、`findmnt`、`pvs`、`vgs`、`lvs`、`cat /proc/mdstat` 确认目标没有挂载、swap、LVM、RAID 或加密映射。**不要在不知道用途的 `/dev/sdX` 上运行，也不要把 `--backup` 当成完整备份。**
:::

### 8.10 udevadm：设备属性、事件与等待

udev 负责把内核设备事件转换成 `/dev` 节点和属性。查看设备身份、监听插拔事件、等待规则处理完成分别使用 `info`、`monitor`、`settle`：

```bash
udevadm info --query=all --name=/dev/sdb       # 属性、ID、设备路径
udevadm info --attribute-walk --name=/dev/sdb  # 沿父设备树列出可用于规则的属性
sudo udevadm monitor --kernel --udev --property # 监听内核与 udev 事件，Ctrl+C 结束
sudo udevadm settle --timeout=10               # 等待队列中的 udev 事件处理完
```

预期输出片段：

```
E: DEVNAME=/dev/sdb
E: ID_BUS=ata
E: ID_SERIAL=ATA_Example_123
KERNEL[...].add /devices/.../block/sdb
UDEV  [...].add /devices/.../block/sdb
```

用途：热插拔脚本先 `udevadm monitor` 观察真实事件，规则调试用 `info --attribute-walk` 找属性，自动化流程在出现设备节点后用 `settle` 避免竞态。不要把 `/dev/sdX` 当永久身份，优先使用 `/dev/disk/by-id/`、UUID 或 WWN。

### 8.11 ext4 元数据：e2label / tune2fs / dumpe2fs / debugfs

这些命令读取或修改 ext2/3/4 的超级块和元数据。读取前确认设备和文件系统类型，修改标签不需要重新格式化：

```bash
sudo e2label /dev/sdb1                     # 读取 LABEL
sudo e2label /dev/sdb1 data-old             # 设置 LABEL
sudo tune2fs -l /dev/sdb1                   # 列出超级块摘要
sudo tune2fs -L data /dev/sdb1              # 修改 ext 文件系统标签
sudo dumpe2fs -h /dev/sdb1                  # 只看超级块/组摘要
sudo debugfs -R 'stats' /dev/sdb1           # 只读查看 ext 元数据统计
sudo debugfs -R 'stat <2>' /dev/sdb1        # 查看根目录 inode（inode 2）
```

预期输出片段：

```
Filesystem volume name = data
Filesystem UUID = 7f2a8c9e-...
Filesystem features: has_journal ext_attr resize_inode dir_index
Inode: 2   Type: directory   Mode: 0755
```

`tune2fs -l`/`dumpe2fs -h`/`debugfs -R` 主要用于只读审计；`debugfs` 的写命令（如 `write`、`clri`）绕过正常文件系统保护，除非正在做有明确方案的取证/恢复，否则不要使用。ext4 一致性修复仍用卸载后的 `e2fsck`，不能拿 `debugfs` 替代。

### 8.12 XFS 与 Btrfs 专项

XFS 的信息、低层只读数据库和修复工具：

```bash
sudo xfs_info /data                         # 查看已挂载 XFS 的几何参数
sudo xfs_db -r -c 'sb 0' -c 'p uuid blocksize' /dev/sdc1
sudo xfs_repair -n /dev/sdc1                # 卸载后只检查，不修改
```

预期输出片段：

```
meta-data=/dev/sdc1 isize=512 agcount=4, agsize=...
uuid = ...
blocksize = 4096
Phase 1 - find and verify superblock...
No modify flag set, skipping phase 5
```

::: warning `xfs_repair` 安全边界
`xfs_repair -n` 也必须对**已卸载**的 XFS 执行；真正的 `xfs_repair /dev/sdc1` 会修改文件系统元数据，可能丢失无法修复的目录项。先备份/做镜像、记录日志，确认没有挂载和进程占用，再在维护窗口执行。XFS 不支持缩容。
:::

Btrfs 的基础检查和空间管理以挂载点为主：

```bash
sudo btrfs filesystem show                 # 查看 Btrfs 文件系统与设备
sudo btrfs filesystem usage /data          # 设备、数据、元数据空间分布
sudo btrfs filesystem df /data             # 按 profile 查看分配
sudo btrfs device scan                     # 重新扫描 Btrfs 设备
sudo btrfs device add /dev/sdc1 /data      # 把设备加入已挂载文件系统
sudo btrfs filesystem resize max /data     # 底层设备变大后，让文件系统吃掉新增空间
sudo btrfs device remove /dev/sdc1 /data   # 迁移数据后移除设备
sudo btrfs subvolume create /data/@home
sudo btrfs subvolume list /data
sudo btrfs subvolume snapshot -r /data/@home /data/@home-ro
sudo btrfs subvolume delete /data/@home-ro
```

预期输出片段：

```
Label: none  uuid: ...
        Total devices 2 FS bytes used 12.00GiB
ID 256 gen 42 top level 5 path @home
```

`device add` 会把新设备加入文件系统的设备集合，但不会自动把旧数据均匀搬迁；需要重新分布时再评估 `btrfs balance start`。底层设备扩大后才用 `filesystem resize max` 吃掉新增边界；`device remove` 会迁移数据，空间不足会失败。删除子卷前先确认快照、挂载点和备份关系。Btrfs 的 profile、scrub、balance 属于更深的存储专题，本节只覆盖日常基础。

### 8.13 cryptsetup/LUKS 与 dmsetup：加密和设备映射

LUKS 把加密元数据放在块设备头部，通过 device-mapper 暴露 `/dev/mapper/&lt;name&gt;`：

```bash
sudo cryptsetup luksDump /dev/sdb1                    # 只读查看 LUKS 版本、UUID、keyslot
sudo cryptsetup luksHeaderBackup /dev/sdb1 \
  --header-backup-file /root/sdb1.luks-header.bak    # 备份头部，离线保管
sudo cryptsetup luksFormat --type luks2 /dev/sdb1    # 初始化 LUKS2
sudo cryptsetup open /dev/sdb1 secure_data            # 解锁并创建映射
sudo cryptsetup status secure_data
sudo mount /dev/mapper/secure_data /data
sudo umount /data && sudo cryptsetup close secure_data
sudo dmsetup ls --tree                                  # 查看 device-mapper 树
sudo dmsetup info /dev/mapper/secure_data
```

预期输出片段：

```
LUKS header information
Version:        2
UUID:           luks-...
secure_data (253:0)
└─ (8:17)
```

::: warning `cryptsetup luksFormat` 是破坏性命令
它会重写目标设备的加密头部，通常使原有数据不可用；没有口令、恢复密钥或有效 keyslot，数据无法恢复。执行前核对 `lsblk -f`，先做备份并确认使用的是实验设备。`luksHeaderBackup` 不是数据备份，头部备份本身也必须像密钥一样保密。不要直接 `dmsetup remove` 正在被 `cryptsetup`、LVM 或 RAID 使用的映射，应由上层工具按逆序关闭。
:::

### 8.14 losetup / mkisofs / xorriso：镜像文件和 ISO

`losetup` 把普通文件绑定成 loop 块设备；使用 `--partscan` 时，内核也会尝试发现镜像中的分区：

```bash
LOOP=$(sudo losetup --find --show --partscan /tmp/disk.img)
sudo losetup --list "$LOOP"
lsblk "$LOOP"
sudo losetup --detach "$LOOP"              # 必须先卸载、停用上层映射
```

预期输出：`/dev/loop0`，随后 `losetup --list` 显示 `BACK-FILE=/tmp/disk.img`。更简单的文件系统镜像可直接使用：

```bash
sudo mount -o loop,ro /tmp/rootfs.img /mnt/image       # mount 自动临时分配 loop
sudo umount /mnt/image
```

制作 ISO 时，老系统可能提供 `mkisofs`（或兼容的 `genisoimage`），现代系统常用 `xorriso`：

```bash
mkisofs -o backup.iso -V BACKUP /srv/export            # 目录打包成 ISO
xorriso -as mkisofs -o backup.iso -V BACKUP /srv/export
xorriso -indev backup.iso -ls                          # 列出 ISO 内容
```

预期输出片段：`Total translation table size: 0`、`Writing to 'stdio:backup.iso' completed successfully.`。ISO 创建只读源目录但会写输出文件，输出路径不要指向源盘或挂载中的关键路径；验证后再用 `mount -o loop,ro` 读取。

### 8.15 fsfreeze / sync / fstrim：一致性、落盘与回收

做快照或底层备份前，可以短暂冻结挂载点，让文件系统暂停新的写入：

```bash
sudo sync                                      # 请求把脏页写回存储设备
sudo fsfreeze --freeze /data                   # 冻结 /data 的文件系统
# 在这里执行存储快照或只读镜像操作
sudo fsfreeze --unfreeze /data                 # 必须成对执行
```

成功时 `sync`/`fsfreeze` 通常无输出；冻结期间写入程序会阻塞。若备份流程失败，也必须在清理路径执行 `fsfreeze --unfreeze`，否则业务可能长期卡住。`sync` 只负责提交写回请求，不等于备份完成，也不替代数据库自身的备份协议。

SSD、精简置备存储或虚拟磁盘可用 discard/TRIM 归还已不用的块：

```bash
sudo fstrim -v /data                 # 只处理一个挂载点
sudo fstrim -av                      # 处理所有支持 discard 的挂载点
systemctl status fstrim.timer       # 许多 systemd 系统按周自动执行
```

预期输出：`/data: 12.0 GiB (12884901888 bytes) trimmed`。不要把 `fstrim` 当作清除敏感数据的工具；它会给底层设备发送 discard，虚拟化或精简存储环境应按平台策略执行，频繁手工执行也没有收益。

### 8.16 zramctl 与 mdadm 的检查/恢复

更稳妥的 zram 创建方式是让 `zramctl` 分配设备，再把它格式化为 swap：

```bash
sudo modprobe zram num_devices=1
ZRAM=$(sudo zramctl --find --size 2G)
sudo mkswap "$ZRAM"
sudo swapon --priority 100 "$ZRAM"
zramctl
swapon --show
sudo swapoff "$ZRAM"
sudo zramctl --reset "$ZRAM"
```

预期输出片段：`/dev/zram0`，以及 `zramctl` 显示 `ALGORITHM lzo`、`DISKSIZE 2G`。zram 占用的是 RAM，不是磁盘；压力大的系统要观察压缩开销，不要盲目把 zram 配得远大于物理内存。已有 zram 由发行版服务管理时，先查服务配置，避免手动重复初始化。

RAID 恢复先检查成员盘的 md superblock，再尝试组装；恢复时不要用 `--create` 覆盖原元数据：

```bash
sudo mdadm --examine /dev/sdd1 /dev/sde1       # 查看成员 UUID、level、role
sudo mdadm --detail /dev/md1                   # 查看当前阵列状态
cat /proc/mdstat                               # 看降级/重建进度
sudo mdadm --assemble --scan                   # 从成员 superblock 自动组装
sudo mdadm --detail --scan                     # 生成阵列识别信息
sudo mdadm --monitor --scan --oneshot          # 立即检查可监控的阵列
```

若确认一块成员已坏，按“失效 → 移除 → 添加新盘”处理：

```bash
sudo mdadm /dev/md1 --fail /dev/sdd1
sudo mdadm /dev/md1 --remove /dev/sdd1
sudo mdadm /dev/md1 --add /dev/sdf1
watch cat /proc/mdstat                         # 重建期间持续观察
```

预期输出片段：`[2/1] [_U]` 表示降级，重建完成后回到 `[2/2] [UU]`。`--assemble --scan` 只能在成员元数据可信时使用；若多个成员同时缺失、阵列顺序不明或出现不同 UUID，先停写并制作成员盘镜像，按备份/厂商方案恢复。重建期间不要拔动其他成员，也不要把 RAID 当备份。

## 9. 本章小结

- 看清磁盘用 `lsblk`（ROTA 分 HDD/SSD、树形层级）+ `blkid`（UUID）+ `fdisk -l`（分区表）；命名规律记住 `sda`/`nvme0n1p1`/`vda`。
- 分区：`fdisk` 交互（m/n/p/w 提交、q 撤销），新盘用 GPT + `parted`；**`w` 提交即破坏，先备份分区表**。
- 查询挂载优先 `findmnt`，脚本判断用 `mountpoint -q`；`blockdev`/`hdparm`/`nvme-cli` 分别看内核块属性、SATA 能力与 NVMe SMART，设备事件用 `udevadm info/monitor/settle`。
- 分区表刷新用 `partprobe`/`partx`，GPT 检查与备份用 `sgdisk`/`gdisk`；云盘扩容明确是 **`growpart` 扩分区 → `resize2fs`/`xfs_growfs`/`btrfs filesystem resize` 扩文件系统** 两步。
- 格式化：`mkfs -t xfs` 等价 `mkfs.xfs`；`-b`/`-i`/`-m` 控制布局；UUID 每次 mkfs 都换，fstab 推荐 UUID。
- 挂载：`mount -o ro/noexec/remount/loop`、`umount -l/-f`、fstab 六字段、`--bind`；XFS 只能扩不能缩。
- `wipefs --no-act` 先审计签名，`--all` 会清掉识别签名；ext4 用 `e2label`/`tune2fs`/`dumpe2fs`/`debugfs` 读元数据，XFS 用 `xfs_info`/`xfs_db`/`xfs_repair -n`，修复前必须卸载并备份。
- Btrfs 的 `filesystem`/`device`/`subvolume` 管空间和子卷；LUKS 用 `cryptsetup`，映射关系用 `dmsetup`；LUKS 初始化、`wipefs` 和真正的 `xfs_repair` 都必须按破坏性操作审查。
- 镜像用 `losetup`，ISO 用 `mkisofs`/`xorriso`，读取 ISO 用 `mount -o loop,ro`；快照前可 `sync` + `fsfreeze`，SSD/精简存储按策略 `fstrim`，zram 用 `zramctl`。
- swap：`dd`+`mkswap`+`swapon`，fstab 一行，大小按场景（休眠要 ≥ RAM）；`zram` 是内存压缩交换。
- LVM 三层 PV→VG→LV，`-r` 一键在线扩容，快照靠 COW；RAID 用 `mdadm`，`-f/-r/-a` 处理降级，软硬 RAID 选型按成本与性能。
- mdadm 恢复先 `--examine`/`--detail`/`/proc/mdstat`，再 `--assemble --scan` 或按“fail → remove → add”重建，**恢复场景不要误用 `--create`**。
- 体检：`smartctl` 盯 `Reallocated_Sector_Ct`/`Pending_Sector`，`badblocks -w` 破坏性慎用，`dd` 整盘镜像但 of= 写错即全灭，性能用 `fio`。
- 设备、驱动、内核参数的延伸见未来的 [内核模块硬件与系统参数命令](/kb/os/Bash/17-内核模块硬件与系统参数命令/)；时间和终端环境命令交叉见未来的 [时间终端与环境管理命令](/kb/os/Bash/19-时间终端与环境管理命令/)。

## 10. 动手实验

::: warning 实验总则
以下练习**全部使用镜像文件 + `losetup`/`mount -o loop` 虚拟成块设备**，不碰真实磁盘。任何一步都不需要也不应该动 `fdisk /dev/sda`。
:::

1. **镜像文件全流程**（safe）：`dd if=/dev/zero of=/tmp/test.img bs=1M count=1024` 造 1G 文件 → `sudo mkfs.ext4 /tmp/test.img` → `sudo mount -o loop /tmp/test.img /mnt/t` → 写文件、`df -h` 观察 → `umount` 删除镜像。体会"文件系统可以建在任何块设备上"。
2. **分区练习**（safe，用镜像+loop）：造两个 2G 镜像，`LOOP=$(sudo losetup --find --show /tmp/disk1.img)` 挂成块设备 → `sudo fdisk "$LOOP"` 交互分区（m/n/p/w）→ `lsblk "$LOOP"` 验证 → 退出后 `sudo losetup --detach "$LOOP"` 解除。
3. **LVM 练习**（safe，loop 设备）：造两个 2G 镜像并 losetup → `pvcreate` → `vgcreate vgtest` → `lvcreate -L 1G` → mkfs + mount → `lvextend -r -L +1G` 在线扩容 → `df -h` 验证 → `lvremove`/`vgremove`/`pvremove` 清理。
4. **RAID0 练习**（safe，loop 设备）：造 4 个 1G 镜像并 losetup → `mdadm --create /dev/md0 -l 0 -n 2` → `cat /proc/mdstat` 看 `[2/2] [UU]` → mkfs + mount + 写数据 → `mdadm --stop /dev/md0` 清理。再加一块组 RAID1 并练习 `-f/-r/-a` 降级重建。
5. **swap 练习**（safe）：`dd` 造 512M 文件 → `chmod 600` → `mkswap` → `swapon` → `free -h` 对比 → `swapoff` 恢复原状。
6. **设备查询练习**（safe）：对一个只读 loop 镜像执行 `losetup --find --show`、`findmnt --target`、`mountpoint -q`、`blockdev --getsize64` 和 `udevadm info --query=all`，记录设备路径、大小、UUID 与挂载关系；最后卸载并 detach。
7. **ext4 元数据练习**（safe）：在临时镜像上 `mkfs.ext4`，用 `e2label` 设置标签，再用 `tune2fs -l`、`dumpe2fs -h`、`debugfs -R 'stats'` 对照 UUID、标签和特性；所有 debugfs 操作只做读取。
8. **扩容两步练习**（虚拟机/云盘或实验镜像）：先确认 `lsblk` 的分区边界，执行 `growpart` 扩分区，再执行对应的 `resize2fs`/`xfs_growfs`/`btrfs filesystem resize` 扩文件系统；每一步分别用 `lsblk` 与 `df -hT` 验证，体会两层大小不会自动同步。
9. **LUKS 练习**（仅临时镜像）：在空镜像上 `cryptsetup luksFormat` → `open` → `mkfs` → 挂载 → 卸载 → `close`，同时用 `luksDump`、`cryptsetup status`、`dmsetup ls --tree` 观察层次；确认无数据后再删除镜像。
10. **Btrfs/冻结练习**（可选）：创建 Btrfs 子卷和只读快照，执行 `filesystem show`/`usage`/`subvolume list`；对临时挂载点短暂 `sync`、`fsfreeze --freeze`、`fsfreeze --unfreeze`，最后检查 `fstrim -v` 是否被文件系统/loop 设备支持。
11. **RAID 恢复演练**（仅 loop 设备）：对 RAID1 用 `--examine`、`--detail`、`/proc/mdstat` 检查，模拟 `--fail` → `--remove` → `--add`，观察 `[UU]`、`[_U]` 与重建进度；不要对真实阵列使用 `--create` 练习。

## 11. 自测题

1. **`lsblk -o ROTA` 显示 1 和 0 分别代表什么？** 1 = 机械盘（rotational），0 = SSD/NVMe 等非旋转设备。
2. **`/dev/nvme0n1p2` 每个部分什么意思？** 第 0 个 NVMe 控制器的第 1 个命名空间（n1）上的第 2 个分区（p2）；NVMe 用 `p` 分隔分区号避免 `nvme0n1` 与 `nvme0n11` 歧义。
3. **为什么超过 2 TiB 的盘必须用 GPT？** MBR 用 32 位 LBA 寻址，上限 2 TiB；GPT 用 64 位，还带 CRC 校验和冗余副本。
4. **mkfs 之后 UUID 会变化吗？为什么 fstab 建议用 UUID 而不是 /dev/sda2？** 会，每次 mkfs 都生成全新 UUID；因为 `/dev/sdX` 按发现顺序分配，插拔/换内核可能变，UUID 稳定且跨机器唯一。
5. **`mount -o remount,ro /data` 和先 umount 再 mount 的区别？** remount 不中断挂载关系，原地改选项，适合根分区/有进程占用的目录；umount+mount 需要先保证无占用。
6. **fstab 六列各是什么，`dump` 和 `pass` 干什么？** device、mountpoint、fstype、options、dump（0=不备份）、pass（0=不 fsck，1=根，2=其他）。
7. **LVM 扩容 ext4 和 xfs 的命令差异？** ext4 先 `lvextend` 再 `resize2fs /dev/vgdata/lvdata`；xfs 用 `xfs_growfs` 且按**挂载点**传参；`lvextend -r` 可自动扩。
8. **RAID5 最少几块盘，坏一块还能读写吗？RAID0 呢？** RAID5 最少 3 块，坏一块降级但可继续读写（有奇偶校验可重建）；RAID0 坏任何一块全部数据丢失。
9. **SMART 哪个属性表示坏道重映射，看到它快速增长该做什么？** `Reallocated_Sector_Ct`（ID 5）；立即备份数据并准备换盘，尤其伴随 `Current_Pending_Sector` 增长时。
10. **`findmnt` 相比 `mount` 查询有什么优势？** `findmnt` 面向内核挂载表，能按路径/设备/类型过滤并输出树形或 JSON；`mount` 仍适合执行挂载操作。
11. **云盘扩容为什么要执行两层命令？** `growpart` 只扩大分区边界，文件系统仍保持旧大小；之后必须用 `resize2fs`、`xfs_growfs` 或 `btrfs filesystem resize` 扩文件系统。
12. **`wipefs --all`、`mkfs`、`cryptsetup luksFormat` 的共同风险是什么？** 都会重写关键元数据，使原有卷或数据不可用；先核对设备、卸载上层映射、做备份，并用临时设备练习。
13. **LUKS 映射、LVM 和 RAID 的关闭/恢复顺序为什么不能乱？** 它们是设备映射层；应先停业务并卸载文件系统，再按文件系统 → LVM/RAID → cryptsetup/dmsetup 的逆依赖顺序操作，避免 busy 或元数据损坏。
14. **`xfs_repair -n` 与 `xfs_repair` 的区别？** `-n` 只检查不修改，但仍要求 XFS 卸载；不带 `-n` 会实际修复元数据，可能丢失无法恢复的目录项，必须先备份并确认方案。
15. **RAID1 降级重建的安全流程是什么？** 先 `mdadm --examine/--detail` 确认成员，再 `--fail` 标坏、`--remove` 移除、`--add` 加入替换盘，持续看 `/proc/mdstat`；恢复场景不要用 `--create`。

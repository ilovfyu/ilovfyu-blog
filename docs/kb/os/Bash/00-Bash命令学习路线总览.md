## 2. 本目录的定位

三个目录看的是同一台机器，但分工不同：

| 目录 | 视角 | 回答的问题 | 典型命令 |
|---|---|---|---|
| `[Linux 实操](/kb/os/Linux/00-Linux实操学习路线/)` | **内核机制** | 进程状态机为什么是 R/S/D/Z？load average 怎么算？ | `ps` `top` `strace` `/proc` |
| 本目录（Bash） | **命令本身** | `ps` 的 `-eo` 怎么拼？管道/重定向怎么组合？怎么写成脚本？ | 一切命令的"用法 + 组合" |
| `[问题排查](/kb/os/问题排查/00-系统问题排查方法论/)` | **诊断流程** | 系统变慢了，从哪看起、按什么步骤定位？ | `top` → `vmstat` → `iostat` → 定位 |

一句话区分：**Linux 实操教你"看懂"，Bash 教你"会用"，问题排查教你"查谁"**。三者协同的典型场景：

```text
线上 CPU 飙高
   │
   ├─ 问题排查篇：按方法论把范围缩到"某进程吃满 CPU"
   ├─ Linux 实操篇：strace/perf 看清它在内核里调用了什么
   └─ Bash 篇：ps -eo pid,pcpu,cmd --sort=-pcpu | head -5 快速锁定嫌疑进程
```

三者是同一把刀的不同握法，本篇把"握刀"练到条件反射。

## 3. 命令学习的正确方法

### 3.1 为什么不要背命令

命令有几十万个选项组合，靠背记既记不住、也没意义。**`man` 和 `--help` 才是你的第一老师**：

```bash
man ls          # 全量手册：选项、示例、作者
ls --help       # 精简速查：比 man 好读，日常够用
man -k process  # 模糊搜索：记不清命令名时，按关键词找命令
```

::: important 遇到陌生命令，先 `man` 再猜
猜选项十次有九次是错的。先花 30 秒读 `man` 的 SYNOPSIS，比反复试错省十分钟。`man` 里按 `/` 搜索关键词，按 `q` 退出。
:::

### 3.2 "命令 + 预期输出 + 解读"三件套

本目录每一篇都遵循同一套路：先给可运行的**命令**，再给**预期输出**，最后**逐列解读**。你看懂一个例子，就学会了这类命令的骨架：

```bash
ls -lh /var/log/
```
预期输出：
```
total 5.4M
-rw-r--r-- 1 root root  2.1M Aug  1 03:12 syslog
-rw-r--r-- 1 root root  3.3M Aug  1 03:12 wtmp
```
解读：
- `-l` 长格式、`-h` 人类可读大小；`total` 是该目录所有块总和。
- 第一组 `-rw-r--r--`：文件类型 + 属主/属组/其他人三段权限。
- `Aug 1 03:12` 是最后修改时间，`syslog` 与 `wtmp` 是日志文件。

### 3.3 先掌握最小可用集，再横向扩展

**最小可用集**：先练熟下面这 12 条，覆盖日常操作的大头：

| 命令 | 必会用法 | 场景 |
|---|---|---|
| `ls` | `ls -l` `ls -la` `ls -lh` | 看文件与权限 |
| `cd` | `cd -` `cd ~` | 切换目录 |
| `cp` / `mv` / `rm` | 带 `-r` 递归、带引号 | 文件搬运与删除 |
| `cat` / `less` | `less` 翻页、`/` 搜索 | 看文件内容 |
| `grep` | `grep -r` `grep -v` `grep -i` | 按模式过滤 |
| `ps` / `top` | `ps -ef` `top` 后按 `P` | 看进程与负载 |
| `df` / `du` | `df -h` `du -sh` | 看磁盘占用 |
| `curl` | `curl -s` `curl -I` | 网络请求与测试 |

::: tip 80/20 法则
20% 的命令覆盖你 80% 的日常操作。先把上表练到闭眼能打，再向 `tcpdump`/`awk` 花式组合等高级用法扩展。**深度优先，广度靠查**。
:::

### 3.4 学习中的常见误区

| 误区 | 正确做法 |
|---|---|
| 抄笔记式学习，只看不敲 | 每条命令亲自敲一遍，输出和笔记对得上才算会 |
| 一上来就想写复杂脚本 | 先拆成单条命令验证，再串成管道，最后才包成脚本 |
| 遇到问题先问人 | 先 `man` + `--help` + `man -k` 自解，实在不行再查资料 |
| 死记选项拼写 | 记"我要做什么"，选项现查 `--help`，`ls --help` 一秒钟的事 |

### 路线 B：运维速成（倒推所需能力）

```
04 权限 ─→ 05 磁盘 ─→ 07 监控 ─→ 06 网络
   ─→ 08 脚本 ─→ 10 组合技巧
```

## 6. 环境准备

### 6.1 终端工具

| 工具 | 作用 | 建议 |
|---|---|---|
| 终端模拟器 | iTerm2 / Windows Terminal / Konsole | 支持多标签、复制粘贴 |
| **tmux** | 终端复用：会话不丢、分屏、断线重连 | 长期操作必备 |
| **vim** / **nano** | 编辑配置文件 | 至少熟一个 |
| **zsh** / bash | 交互 shell | 见 6.2 |

### 6.2 zsh 与 bash 的区别

| 对比项 | bash | zsh |
|---|---|---|
| 定位 | 事实标准，脚本兼容性最好 | 交互体验更好，兼容 bash 语法 |
| 自动补全 | 基础 | 强（目录/选项/历史提示） |
| 脚本 | **写脚本首选 bash**（`#!/bin/bash`） | 有 zsh 特有语法，跨机器易踩坑 |
| 配置文件 | `~/.bashrc` | `~/.zshrc`（macOS 默认） |

::: important 区分交互 shell 与脚本
交互体验用 zsh 没问题；但写脚本、跑定时任务，**一律用 bash 并显式声明 `#!/bin/bash`**，避免换机器后行为不一致。
:::

### 6.3 alias：给常用命令起别名

```bash
alias ll='ls -alF'        # 立即生效（当前 shell）
alias ..='cd ..'          # 少敲两下
echo 'alias ll="ls -alF"' >> ~/.bashrc   # 永久生效
source ~/.bashrc          # 让配置生效
```

::: tip alias 三件套
你自定义的 alias 存 `~/.bashrc`（或 `~/.zshrc`）；开机不生效就 `source` 一下；想知道某个命令是不是别名，用 `type <命令>`。
:::

### 6.4 PATH：命令去哪找

```bash
echo $PATH                    # 用冒号分隔的目录列表
which ls                      # 实际用了哪个 ls（/usr/bin/ls）
command -v docker             # 更可移植的查找方式
export PATH="$HOME/bin:$PATH" # 把自定义目录加到最前面
```

::: warning PATH 陷阱
`export PATH=$PATH:$HOME/bin` 与 `export PATH="$HOME/bin:$PATH"` 顺序不同，查找优先级不同。加入 `$HOME/bin` 到最前，你的同名命令会"覆盖"系统命令——这既是能力也是坑。
:::

### 6.5 man：手册的使用

| Section | 内容 | 例子 |
|---|---|---|
| 1 | 用户命令（shell 命令、工具） | `man ls` `man cp` |
| 2 | 系统调用 | `man 2 fork` `man 2 open` |
| 3 | C 库函数 | `man 3 printf` |
| 5 | 配置文件格式 | `man 5 passwd` `man 5 resolv.conf` |
| 7 | 杂项（约定、宏包、协议） | `man 7 signal` `man 7 tcp` |

::: tip 同名怎么办
`man passwd` 是"修改密码的命令"还是"密码文件格式"？用 `man 5 passwd` 显式指定 section 5，就不会看错文档。`man -f passwd` 可以列出所有 section 的同名条目。

### 6.6 环境自检与常用快捷键

```bash
# 一次性确认核心工具都在 PATH 中
for c in ls cat grep sed awk ps top df curl vim; do command -v $c || echo "缺: $c"; done
echo $SHELL       # 确认当前 shell
cat ~/.bashrc     # 确认配置存在
```

| 快捷键 | 作用 |
|---|---|
| `Tab` | 命令/文件自动补全 |
| `Ctrl+R` | 反向搜索历史命令 |
| `Ctrl+A` / `Ctrl+E` | 光标跳到行首/行尾 |
| `Ctrl+U` / `Ctrl+K` | 删除光标前/后的内容 |
| `Ctrl+C` | 终止当前前台命令 |

::: tip history 是你的"第二大脑"
敲过的好命令都在 `history` 里，`Ctrl+R` 秒搜回；`!!` 重跑上一条，`!$` 取上一条的最后一个参数——学会这三个，省一半打字。
:::

## 7. 常见陷阱清单

| 陷阱 | 现象 | 规避 |
|---|---|---|
| **管道权限** | `sudo cat secret.txt \| grep key` 中 `sudo` 只作用于 `cat`，grep 仍可能没权限 | `cat secret.txt \| sudo grep key`，或 `sudo sh -c 'cat f \| grep k'` |
| **通配符展开时机** | `rm *.log` 由 **shell** 先展开再交给 rm；`find -name '*.log'` 中引号阻止展开 | 需要 shell 展开就别加引号；需要原样传递就加引号 |
| **单/双/反引号** | 单引号不转义、双引号会展开变量、反引号/`$()` 会执行命令 | 脚本里用 `$()` 而非反引号（可嵌套、可读性好） |
| **文件名含空格** | `rm my file.txt` 被拆成两个参数 | 统一加引号：`rm "my file.txt"`；或养成 `rm -- 'file'` 习惯 |
| **危险命令** | `rm -rf /`、`rm -rf $VAR/`（VAR 为空）直接删根 | 先 `ls` 再 `rm`；给变量加默认值 `${VAR:-fallback}/`；关键目录加引号 |
| **别名遮蔽** | `alias ls='ls --color'` 被脚本继承后行为不一致 | 脚本里用绝对路径或 `command ls` 绕过 |
| **CRLF 换行** | Windows 编辑的脚本在 Linux 报 `$'\r': command not found` | `sed -i 's/\r$//' script.sh` |

::: warning 三条保命铁律
1. `rm`、`mv`、`dd`、`mkfs` 前先确认目标路径，宁可 `ls` 看三遍。
2. 变量展开前加引号，**永远对变量加双引号**（`"$@"`、`"$file"`）。
3. 测试脚本先在临时目录跑，别一上来就动生产数据。
:::

## 8. 学习完成标准

学完本目录，你应该能**不看文档**做到：

- [ ] **单命令**：用一条命令完成常见任务，如 `grep -rn 'error' /var/log/ | tail -20`、`du -sh ./* | sort -rh | head -10`。
- [ ] **管道组合**：把 3+ 条命令串成管道完成一个完整任务（找出占用空间最大的文件、抓出某端口进程等）。
- [ ] **脚本**：写一个 20 行以内的 bash 脚本，含变量、`for`/`if`、参数 `$1`、退出码 `$?`、`echo` 提示，并能 `chmod +x` 运行。
- [ ] **查手册**：见到陌生命令 1 分钟内用 `man`/`--help` 找到用法。
- [ ] **安全习惯**：重定向/管道/引号不踩坑，`rm` 前先确认。

::: tip 验收三连
① `ls -l /etc | awk '{print $NF}' | sort | uniq -c | sort -rn | head` 输出有内容；② `for i in {1..5}; do echo $i; done` 正常跑通；③ 能用 `history` 回看自己今天敲过的命令并讲清每一条在干嘛。
:::

## 9. 本章小结

本目录十条主线构成完整的命令能力链：**核心（文件/文本/进程）→ 常用（权限/磁盘/网络/监控）→ 高级（脚本/组合/技巧）**。学习方法不是背，而是"先会用、再查 man、后组合"；定位上它是 Linux 实操篇的"刀"，是问题排查篇的"手"。学完你将具备把一个任务拆成一条命令管道的能力——这是 Linux 运维与开发的吃饭功夫。

## 10. 自测题

1. **为什么说 `man` 比背命令更重要？** 命令选项组合近乎无限，`man`/`--help` 是即查即用的权威来源；会查手册就等于会"无限条命令"。
2. **`ls -l` 中 `-rw-r--r--` 每部分代表什么？** 第一个字符 `-` 表示普通文件；后三段分别对应属主、属组、其他人的读/写/执行权限（`r--`=可读不可写不可执行）。
3. **`rm *.log` 与 `find . -name '*.log'` 中引号的差异？** 前者 `*.log` 由 shell 展开（作用于当前目录），后者加单引号让 `find` 自己匹配（可递归）。
4. **双引号与单引号的区别？** 双引号内 `$VAR` 会展开为变量值，单引号内原样输出；`echo "$HOME"` 输出家目录，`echo '$HOME'` 输出 `$HOME` 字符串。
5. **`echo "$PATH"` 里 PATH 的用途是什么？** 冒号分隔的目录搜索列表，shell 依次在这些目录里找命令；`command -v ls` 可查实际命中位置。
6. **如何查看 system 手册的第 5 节？** `man 5 passwd`，看配置文件格式；`man -f passwd` 列出所有相关 section。
7. **写脚本时用什么 shebang 最安全？** `#!/bin/bash`，显式指定 bash 解释器，避免默认 shell 差异导致脚本行为不一致。

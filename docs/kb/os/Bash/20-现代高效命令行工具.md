::: abstract 本章定位
本篇补齐现代 CLI，但以经典 POSIX/GNU 命令为基准。`rg` 不是系统必备的 `grep` 替代品，`fd` 也不是所有机器都装有的 `find` 替代品；现代工具主要改善交互体验、默认过滤、可视化和统计。前置见 [核心命令与文件操作](/kb/os/Bash/01-核心命令与文件操作/)、[文本处理三剑客](/kb/os/Bash/02-文本处理三剑客/)、[高级命令与文本处理](/kb/os/Bash/09-高级命令与文本处理/)；指标解释见 [系统监控与性能命令](/kb/os/Bash/07-系统监控与性能命令/)；结构化输出延伸见 [结构化数据处理命令](/kb/os/Bash/18-结构化数据处理命令/)。
:::
## 1. 选型原则
### 1.1 三层基准
| 层次 | 命令 | 结论 |
|---|---|---|
| POSIX 基础 | `grep`、`find`、`cat`、`ls`、`cd`、`cut`、`xargs` | 脚本、救援系统、陌生服务器的共同语言 |
| GNU/Linux 常用 | `less`、`watch`、`dig`、`ps`、`top`、`df`、`du` | Linux 常见，但 macOS/BSD 选项可能不同 |
| 现代增强 | `rg`、`fd`、`fzf`、`bat`、`btop`、`hyperfine` 等 | 通常需安装，版本与输出必须管理 |
### 1.2 先问四个问题
1. 给人交互，还是给无人值守脚本？
2. 目标环境是否明确安装并锁定版本？
3. 输出是给人看，还是给程序解析？
4. 工具缺失时，是明确失败，还是能降级？
现代工具不要随意覆盖经典命令名：`alias grep=rg`、`alias find=fd`、`alias cat=bat` 都可能破坏参数习惯、脚本语义、颜色管道和排障判断。个人配置可使用 `ll`、`preview` 等新名字：
```bash
alias ll='eza -lah --group-directories-first'
alias preview='bat --paging=always'
type -a ls grep cat
```
## 2. 搜索
### 2.1 `rg` / ripgrep vs `grep`
**替代谁**：交互式增强 `grep -R`，不是替代所有 `grep`。
**优势**：默认递归、并行、遵守 `.gitignore`，跳过隐藏项和二进制，输出带行号和高亮；更适合源码树。
**安装**：项目名 ripgrep，包名通常 `ripgrep`，命令名 `rg`。
```bash
sudo apt install ripgrep
sudo dnf install ripgrep
brew install ripgrep
```
**常用命令**：
```bash
rg 'TODO|FIXME' src/
rg -n -C 2 'connection refused' logs/
rg -i --glob '*.md' 'posix' .
rg --glob '!vendor/**' 'deprecated' .
rg --hidden --glob '!.git/**' 'token' .
rg -l 'listen 443' /etc/nginx
rg -F 'a[b]' file.txt
rg -P '(?<=user=)[^&]+' access.log  # 需 PCRE2 构建
```
**何时不该用**：脚本不掌控环境、只过滤 stdin、依赖 POSIX/GNU grep 语法时用 `grep`；必须搜 ignore、隐藏或二进制内容时，注意 `rg` 默认会漏项，可按需用 `rg -uuu` 或 `grep -R`。`rg` 默认正则也不是 GNU grep 的 BRE/ERE，PCRE2 选项还可能未编译。
### 2.2 `fd` vs `find`
**替代谁**：增强 `find` 的按名称、扩展名、类型、深度搜索，不覆盖复杂元数据谓词和完整 `-exec` 语义。
**优势**：默认递归、彩色、并行，尊重 ignore，短选项更适合交互。
**安装与命名冲突**：项目名 fd。Debian/Ubuntu 包名通常是 `fd-find`，可执行文件常为 `fdfind`；Homebrew 包名和命令为 `fd`，Fedora 常见包名 `fd-find`。
```bash
sudo apt install fd-find
fdfind --version
sudo dnf install fd-find
brew install fd
```
个人 Debian 环境可只在用户目录建立别名链接：
```bash
mkdir -p "$HOME/.local/bin"
ln -s "$(command -v fdfind)" "$HOME/.local/bin/fd"
```
**常用命令**：
```bash
fd 'z'
fd -e md
fd -t f -e log . /var/log
fd -t d '^src$' .
fd -H -I '.env' .
fd --max-depth 3 -e yaml
fd -e jpg -x identify {}
fd -e jpg -X tar -cf images.tar
fd -0 -e txt | xargs -0 wc -l
```
**何时不该用**：按 owner、权限、inode、mtime 做复杂条件时用 `find`；系统恢复、精简镜像和严格跨平台脚本也优先 `find`。默认 ignore/隐藏规则可能造成审计漏报；删除前先 `-print` 预览，文件名列表用 NUL。
### 2.3 `fzf`：模糊选择、历史与预览
**替代谁**：不直接替代 `find`/`grep`，而是增强 Bash `select`、readline 历史搜索和手工复制路径。
**优势**：上游命令产生候选，fzf 边输入边模糊筛选，可多选、预览并返回结果。
**安装**：包名通常都是 `fzf`。
```bash
sudo apt install fzf
sudo dnf install fzf
brew install fzf
```
按当前版本初始化 Bash；旧发行包的集成脚本位置要查包文件：
```bash
eval "$(fzf --bash)"  # 支持该接口的版本
```
**常用命令与预览**：
```bash
printf '%s\n' dev staging production | fzf
git branch --format='%(refname:short)' | fzf
fd -t f | fzf --preview 'bat --color=always --line-range=:300 {}'
fd -t f | fzf --multi --preview 'bat --color=always {}'
rg -l 'TODO' | fzf --preview "rg -n --color=always 'TODO' {}"
vim "$(fd -t f | fzf)"
```
| 集成按键 | 用途 |
|---|---|
| `Ctrl-R` | 模糊搜索 shell 历史 |
| `Ctrl-T` | 模糊选择文件并插入命令行 |
| `Alt-C` | 模糊选择目录并切换 |
文件名可能含空格、引号或换行时使用 NUL 链路：
```bash
fd -0 -t f | fzf --read0 --print0 | xargs -0 -o vim
```
**何时不该用**：cron、CI、管道脚本没有 TTY；候选内容不是路径时不要直接送给 `rm`；只有一个确定目标时，精确路径更可复现。
## 3. 查看
### 3.1 `less` 仍是基础
**替代谁**：增强 `more`，也是 `man`、Git、`bat`、`delta` 常用的底层 pager。
**优势**：按需读取大文件，支持搜索、双向滚动和跟随增长，是现代工具不可缺的基础能力。
**安装**：包名通常 `less`，完整系统一般已有。
```bash
sudo apt install less
sudo dnf install less
brew install less
```
**常用命令**：
```bash
less -N app.log
less -S wide.csv
less +G app.log
less +F app.log       # Ctrl-C 回到普通浏览
journalctl -u nginx | less -R
```
`/error` 搜索，`n`/`N` 跳转，`g`/`G` 到首尾，`F` 跟随，`q` 退出。**何时不该用**：输出很短、要给下游程序或读取二进制时不需要它，分别用 `cat`、管道或 `xxd`。
### 3.2 `bat` vs `cat`
**替代谁**：增强交互式 `cat`，通常仍使用 `less` 分页；不替代 `cat` 的拼接和脚本普遍可用性。
**优势**：语法高亮、行号、不可见字符、Git 修改标记和自动分页。
**安装与冲突**：项目/包名 `bat`；部分 Debian/Ubuntu 版本因名称冲突，二进制叫 `batcat`。
```bash
sudo apt install bat
command -v bat batcat
sudo dnf install bat
brew install bat
```
**常用命令**：
```bash
bat README.md
bat -n src/main.rs
bat -p config.yaml
bat -A suspicious.txt
bat --diff src/main.rs
git show HEAD~1:src/main.rs | bat -l rust
tail -f app.log | bat --paging=never -l log
```
**何时不该用**：脚本拼接、重定向或复制时用 `cat`；二进制/未知控制字符先用 `file`、`xxd`；日志跟随必须关闭 paging；远端颜色支持差时用 `less`。
### 3.3 `eza` / `lsd` vs `ls`
**替代谁**：增强交互式 `ls`，不是目录数据的脚本接口。
**优势**：颜色、Git 状态、树形、目录优先排序和图标让人更快浏览；`eza` 是 exa 的活跃延续，`lsd` 更侧重图标与树形外观。
**安装**：项目/常见包名分别 `eza`、`lsd`；旧发行版可能没有 eza，先查 `apt-cache policy`/`dnf info`；Homebrew 可分别安装。
```bash
brew install eza lsd
cargo install lsd --locked
```
**常用命令**：
```bash
eza -lah --group-directories-first
eza -lah --git --icons=auto
eza --tree --level=2 src/
eza -l --sort=modified
lsd -lah --group-dirs first
lsd --tree --depth 2
```
**何时不该用**：不要解析 `ls`/`eza`/`lsd` 视觉输出；用 `find -print0`、shell glob、`stat` 或结构化接口。脚本、最小系统、ACL/设备/inode 审计优先经典命令；字体不支持时关闭图标。
### 3.4 `delta`：diff pager
**替代谁**：增强 `git diff | less` 和 `diff -u | less` 的阅读，不负责计算差异。
**优势**：语法与单词级高亮、行号、并排视图、文件间导航、Git blame 和冲突显示。
**安装与冲突**：上游项目名 delta，多数包管理器包名是 `git-delta`，可执行文件是 `delta`。
```bash
brew install git-delta
cargo install git-delta --locked
```
**常用命令**：
```bash
git diff | delta
diff -u old.conf new.conf | delta
git -c core.pager=delta show HEAD
git config --global core.pager delta
git config --global interactive.diffFilter 'delta --color-only'
git config --global delta.navigate true
```
**何时不该用**：机器解析 patch、CI、`git apply` 输入必须保留原始 unified diff；窄终端不强开 side-by-side。
### 3.5 `glow`：Markdown 阅读
**替代谁**：增强 `less README.md`，不替代编辑器、linter、frontmatter 检查或静态站点构建。
**优势**：终端渲染标题、列表、表格和代码块，适合 SSH 中读文档。
**安装**：包/命令名 `glow`，发行版可用性不一致，Homebrew formula 为 `glow`。
**常用命令**：
```bash
glow README.md
glow -p README.md
glow -w 100 README.md
glow .
```
**何时不该用**：需检查原始 Markdown、链接、转义或精确空白时用 `less`/编辑器；脚本提取内容时用解析器；终端颜色不佳时关闭渲染。
## 4. 导航
### 4.1 `zoxide` vs `cd`
**替代谁**：增强 shell 内建 `cd`，按访问频率和最近使用时间为目录打分；它依赖 shell hook 改变父 shell 的目录。
**优势**：输入少量关键词即可跳到最可能的目录，`zi` 可交互选择。
**安装**：项目/命令/常见包名 `zoxide`。
```bash
sudo apt install zoxide
sudo dnf install zoxide
brew install zoxide
eval "$(zoxide init bash)"
```
**常用命令**：
```bash
z proj api
z -
zi notes
zoxide query -ls proj
zoxide remove /old/path
```
**何时不该用**：脚本必须 `cd -- /absolute/path`，不能让历史数据库决定路径；目录重名先 `pwd -P` 确认；新容器没有历史时收益低。
### 4.2 `autojump`：历史跳转
**替代谁**：同样增强 `cd`，是较早流行的权重跳转方案。
**优势**：旧 dotfiles 和团队工作站中常见，命令通常是 `j`、`jc`、`jo`。
**安装**：包名通常 `autojump`，安装后按发行版说明 source shell 集成。
```bash
sudo apt install autojump
sudo dnf install autojump
brew install autojump
```
**常用命令**：
```bash
j project
jc src
j --stat
autojump --purge
```
**何时不该用**：不要与 zoxide 同时绑定同名函数；新配置通常二选一；自动化仍使用明确的 `cd`。
### 4.3 `broot`
**替代谁**：组合增强 `tree`、`ls`、`find` 与手工 `cd`。
**优势**：压缩低价值目录、模糊查找、预览文件、显示 Git/大小，并能选目录后返回父 shell。
**安装**：项目/命令名 `broot`，集成后常用 `br`；Homebrew、Cargo 均可。
**常用命令**：
```bash
br
br -s
br -sdp
br --sort-by-date ~
br -w
```
界面中 `Enter` 聚焦、`Alt-Enter` 返回 shell、`Ctrl-Right` 预览、`:q` 退出；按键随版本和终端可能变化。
**何时不该用**：无 TTY、串口、批量审计和无人值守场景不用；删除/移动前确认真实路径，脚本仍用 `find`/`cd`。
## 5. 磁盘
`df` 回答“挂载文件系统还剩多少”，`du` 回答“目录树中的文件占多少”。现代工具改善展示，不改变问题边界。基础见 [系统监控与性能命令](/kb/os/Bash/07-系统监控与性能命令/)。
### 5.1 `dust` vs `du`
**替代谁**：增强 `du -h | sort -h` 的目录树分析。
**优势**：树形展示最大分支和文件，自动比例条，不用手写 `sort`/`head`。
**安装与冲突**：项目名 dust，Rust crate 是 `du-dust`，命令是 `dust`。
```bash
brew install dust
cargo install du-dust --locked
```
**常用命令**：
```bash
dust /var/lib
dust -n 20 -d 3 .
dust -D .
dust -F .
dust -x /
dust -j . | jq .
```
**何时不该用**：脚本需要稳定数字用 `du -sk`/`du -sb`，并说明 GNU/BSD 口径；硬链接、稀疏文件、apparent size 要先确认；扫描 `/` 会造成 IO，必要时加 `-x`。
### 5.2 `duf` vs `df`
**替代谁**：增强 `df -h` 的文件系统容量总览，不分析目录内部。
**优势**：挂载点、类型、使用率和剩余空间更适合人读，支持 JSON。
**安装**：项目/命令名 `duf`，Homebrew formula 为 `duf`；Linux 仓库可用性随版本查询。
```bash
brew install duf
sudo apt install duf
```
**常用命令**：
```bash
duf
duf /home /var
duf --only local
duf --hide-fs tmpfs,devtmpfs
duf --json | jq .
```
**何时不该用**：监控和脚本优先 `df -P`/系统 API；不能解析彩色表格；inode 耗尽还要看 `df -i`。
### 5.3 `ncdu`：交互式 `du`
**替代谁**：增强 `du`，用 ncurses 下钻和排序。
**优势**：发行版常见、适合 SSH，可导出扫描结果后离线浏览。
**安装**：包/命令名 `ncdu`。
```bash
sudo apt install ncdu
sudo dnf install ncdu
brew install ncdu
```
**常用命令**：
```bash
ncdu -x /var
ncdu -x -r /
ncdu -x -o /tmp/root.ncdu /
ncdu -f /tmp/root.ncdu
```
**何时不该用**：无 TTY、生产低延迟时段、大根目录扫描都不合适；界面可能删除，巡检使用只读；结果只是扫描时快照。
### 5.4 `gdu`
**替代谁**：增强 `du`/`ncdu`，以 Go 并行扫描突出 SSD 场景。
**优势**：多核、非交互 top、JSON 导出、忽略路径和禁用删除。
**安装**：项目/命令名 `gdu`，Homebrew formula 为 `gdu`，Linux 可用发行版包或官方二进制。
**常用命令**：
```bash
gdu --no-delete /var/lib
gdu -x --no-delete /
gdu -t 20 -n /var
gdu -o /tmp/scan.json /var
gdu --sequential /mnt/hdd
```
**何时不该用**：机械盘上并行可能增加寻道，使用 `--sequential` 或 `ncdu`；生产扫描要避开敏感时段；脚本仍以 `du` 口径为准。
## 6. 进程与监控
### 6.1 `procs` vs `ps`
**替代谁**：增强人读的 `ps aux`/`ps -ef`，不覆盖 `ps -eo` 的精确字段和选择器。
**优势**：颜色、树形、端口、Docker 名称和过滤更直观。
**安装**：项目/命令/Cargo crate `procs`。
**常用命令**：
```bash
procs
procs nginx
procs 1234
procs --tree
```
**何时不该用**：脚本用 `ps -eo pid=,stat=,lstart=,args=`；最小容器、安全审计和精确字段不要依赖 procs。
### 6.2 `btop` / `bottom` vs `top`
**替代谁**：增强交互式 `top`；`btop` 命令为 `btop`，bottom 项目的命令为 `btm`。
**优势**：CPU、内存、磁盘、网络和进程同屏，曲线与筛选更友好。
**安装**：包名常为 `btop`、`bottom`；Cargo 安装 bottom 后得到 `btm`。
```bash
sudo apt install btop
sudo dnf install btop
brew install btop bottom
cargo install bottom --locked
```
**常用命令**：
```bash
btop
btm
btm --basic
btm --process-command
```
**何时不该用**：事故分析回到 `vmstat`、`mpstat`、`iostat`、`pidstat`、`sar`；低带宽 SSH、日志采集和脚本用 `top -b`/`ps`。
### 6.3 `gping` vs `ping`
**替代谁**：增强交互式 `ping`，绘制 RTT、抖动和丢包趋势；连通性脚本仍以系统 ping 为基准。
**优势**：同时比较多个目标，尖峰更容易被看见。
**安装**：项目/命令/Cargo crate `gping`，Homebrew formula 为 `gping`。
**常用命令**：
```bash
gping 1.1.1.1 8.8.8.8
gping example.com gateway.local
ping -c 3 -W 2 example.com
```
**何时不该用**：告警需要 `ping` 退出码和原始统计；ICMP 被禁不代表 TCP/HTTP 故障；长期监控使用监控系统。
### 6.4 `bandwhich` / `iftop`
**替代谁**：增强 `ss`、`netstat` 和网卡总量计数，分别偏进程归因与主机对流量。
**优势**：快速回答“哪个进程/哪台主机占带宽”。通常需要 root 或抓包 capability。
**安装**：项目/命令 `bandwhich`；包/命令 `iftop`。
```bash
brew install bandwhich iftop
sudo apt install iftop
cargo install bandwhich --locked
```
**常用命令**：
```bash
sudo bandwhich
sudo bandwhich -i eth0
sudo iftop -i eth0
sudo iftop -i eth0 -nNP
```
**何时不该用**：容器、namespace、VPN、NAT 会影响归因；抓包权限需控制；留档和协议细节用 `sar -n DEV`、`nstat`、`tcpdump` 或 Wireshark。
## 7. 性能测试
::: warning 授权与隔离
HTTP 压测和 `stress-ng` 会消耗 CPU、内存、端口、带宽和下游容量。只对本机、隔离环境或获授权目标运行，设置时长、并发和停止方式，并同时观察服务端。以下压测示例默认 `127.0.0.1`。
:::
### 7.1 `hyperfine` vs `time`
**替代谁**：增强 shell `time`；后者适合单次 real/user/sys，前者适合多轮统计比较。
**优势**：warmup、固定 runs、准备步骤、异常检测、相对耗时和 JSON/CSV/Markdown 导出。
**安装**：包/命令/Cargo crate `hyperfine`。
```bash
sudo apt install hyperfine
brew install hyperfine
cargo install hyperfine --locked
```
**常用命令**：
```bash
hyperfine 'grep -R TODO src' 'rg TODO src'
hyperfine --warmup 3 --runs 20 'make test'
hyperfine --prepare './reset-fixture' './build-index'
hyperfine --setup 'make clean' 'make -j4'
hyperfine --export-json bench.json 'rg TODO .'
hyperfine --export-csv bench.csv --export-markdown bench.md 'cmd1' 'cmd2'
```
`--warmup` 先热身不计入正式结果，`--runs` 固定正式轮数，`--prepare` 每轮前执行，`--setup` 每条命令的测试组开始前执行。缓存、调频、后台负载和网络噪声未控制时，不要过度解读小数。
**何时不该用**：微秒级函数用语言基准框架；一次线上慢请求需要 tracing/profiling；外部依赖不稳定时 hyperfine 只能报告环境噪声。
### 7.2 `oha` / `hey` vs curl/ab
**替代谁**：增强循环 `curl` 或 `ab`，生成并发 HTTP 请求并统计错误、吞吐和延迟。
**优势**：单二进制、请求数/时长/并发/header/body 选项短；`oha` 输出丰富，`hey` 简洁。
**安装**：项目/命令 `oha`、`hey`；Cargo crate `oha`，Go 可安装 hey，Homebrew 是否提供 hey 要以 `brew info` 为准。
```bash
brew install oha
cargo install oha --locked
go install github.com/rakyll/hey@latest
```
**常用命令**：
```bash
oha -n 100 -c 5 http://127.0.0.1:8080/health
oha -z 30s -c 20 -H 'Authorization: Bearer test' http://127.0.0.1:8080/me
hey -n 100 -c 5 http://127.0.0.1:8080/health
hey -z 30s -c 20 http://127.0.0.1:8080/api/items
curl -fsS http://127.0.0.1:8080/health
```
**何时不该用**：复杂用户旅程、动态 token、跨请求关联或分布式压测换 k6/JMeter/Locust；不要只看 requests/s，要看非 2xx、连接错误和 p95/p99；未授权公网压测会造成安全与运营事故。
### 7.3 `wrk`
**替代谁**：增强 `ab`/循环 curl，偏高吞吐、多线程和 Lua 请求脚本。
**优势**：适合固定接口的吞吐/延迟基线，`--latency` 输出分布。
**安装**：包/命令 `wrk`。
```bash
sudo apt install wrk
brew install wrk
```
**常用命令**：
```bash
wrk -t4 -c100 -d30s --latency http://127.0.0.1:8080/
wrk -t2 -c20 -d15s -H 'Accept: application/json' http://127.0.0.1:8080/items
wrk -t4 -c100 -d30s -s request.lua http://127.0.0.1:8080/
```
**何时不该用**：需要严格到达率时考虑 wrk2 或专业框架；复杂业务校验不是它的强项；生产和公网第三方禁止直接试跑。
### 7.4 `stress-ng`
**替代谁**：增强 `yes > /dev/null` 等粗糙压力命令，提供 CPU、VM、IO、调度和系统调用 stressor。
**优势**：可指定 worker、时长、操作数并汇总 metrics，适合测试限额、散热和故障保护。
**安装**：包/命令 `stress-ng`。
```bash
sudo apt install stress-ng
sudo dnf install stress-ng
```
**常用命令（仅限隔离测试环境）**：
```bash
stress-ng --cpu 2 --timeout 30s --metrics-brief
stress-ng --vm 1 --vm-bytes 512M --timeout 20s --metrics-brief
stress-ng --io 1 --timeout 20s --metrics-brief
stress-ng --cpu 0 --cpu-method all --timeout 60s --verify
```
**何时不该用**：生产、共享宿主机、电池供电或散热不明时不要用；内存可能触发 OOM，磁盘 stressor 会放大磨损和 IO；它验证承压稳定性，不等同真实业务性能。
## 8. 文件变化与自动执行
### 8.1 `entr`
**替代谁**：增强 `while sleep` 和 `watch`，从 stdin 接收待监视路径。
**优势**：接口极简，适合和 `find`、`git ls-files` 组合做测试/构建。
**安装**：包/命令 `entr`。
```bash
sudo apt install entr
sudo dnf install entr
brew install entr
```
**常用命令**：
```bash
find src -type f | entr make test
git ls-files '*.py' | entr -r pytest -q
printf '%s\n' config.yaml | entr -r ./server
find src -type f | entr -d make test
```
`-r` 命令退出后重启；`-d` 遇到新目录项退出，由外层循环重建列表。**何时不该用**：新增深层文件、复杂 ignore/debounce、文件名含换行或需要跨平台时换 watchexec；行列表不是可靠消息协议。
### 8.2 `watchexec`
**替代谁**：增强 entr 和自写 inotify 循环，适合递归监听、过滤和重启项目进程。
**优势**：跨平台事件后端、扩展名/路径过滤、`.gitignore`、debounce、清屏、信号和重启。
**安装**：项目/命令 `watchexec`，Cargo crate 通常 `watchexec-cli`，Homebrew formula `watchexec`。
```bash
brew install watchexec
cargo install watchexec-cli --locked
```
**常用命令**：
```bash
watchexec -e rs -- cargo test
watchexec -w src -w templates -- make test
watchexec --restart -e py -- python app.py
watchexec --ignore 'target/**' -- make check
```
**何时不该用**：CI 一次性任务不需要 watcher；挂载目录可能产生不同事件，应实测；重启有状态服务前先定义优雅停止。
### 8.3 `inotifywait`
**替代谁**：Linux 上增强轮询 `stat`/`find`，直接消费 inotify 原始事件，比 watchexec 更底层。
**优势**：事件类型明确、开销低、输出易编排。
**安装**：项目名 inotify-tools，包名 `inotify-tools`，其中提供 `inotifywait`。
```bash
sudo apt install inotify-tools
sudo dnf install inotify-tools
```
**常用命令**：
```bash
inotifywait -e close_write config.yaml
inotifywait -m -r -e create,delete,move,close_write src/
inotifywait -q -m -r -e close_write --format '%e %w%f' src/
```
**何时不该用**：macOS/BSD 没有 inotify；递归大树可能触及 `max_user_watches`；事件会合并/重复，业务必须重新读取和校验；不要把事件流当消息队列。
### 8.4 `watch`
**替代谁**：增强手工重复执行命令，不监听文件事件；它按时间轮询。
**优势**：最简单地刷新 `ss`、`df`、`ps` 快照，`-d` 高亮变化。
**安装**：Linux 通常来自 `procps`/`procps-ng`；macOS 默认无 GNU watch，Homebrew formula `watch`。**常用命令**：
```bash
watch -n 2 -d 'df -h / /var'
watch -n 1 -d 'ss -s'
watch -n 2 'ps -eo pid,pcpu,pmem,comm --sort=-pcpu | head'
```
**何时不该用**：不能漏掉瞬时事件时用事件工具；昂贵命令高频轮询会放大负载；`watch` 选项非 POSIX，不用于跨平台脚本。
### 8.5 对比
| 工具 | 模型 | 平台 | 新文件 | 场景 |
|---|---|---|---|---|
| `watch` | 定时轮询命令 | GNU/Linux | 每轮重新发现 | 系统快照 |
| `entr` | 监听 stdin 文件 | Unix-like | 默认不扩展 | 小项目测试 |
| `watchexec` | 递归事件+过滤 | 跨平台 | 支持 | 开发服务重启 |
| `inotifywait` | Linux 原始事件 | Linux | 递归可观察 | 系统脚本 |
## 9. 并行
### 9.1 GNU `parallel` vs `xargs -P`
`xargs` 是 POSIX，但 `-P` 不是 POSIX 基线；GNU/BSD 细节可能不同。GNU `parallel` 是独立包，不属于 GNU coreutils 默认组件。
| 维度 | `xargs -P` | GNU `parallel` |
|---|---|---|
| 可用性 | 更常见 | 必须安装 |
| 占位符 | `-I {}` | `{}`、`{.}`、`{/}`、`{#}`、`{%}` 等 |
| 日志/恢复 | 自己实现 | `--joblog`、`--resume-failed` |
| 失败策略 | 简单 | `--halt soon,fail=1` |
| 远程 | 无内建 | SSH host、传输、回收 |
### 9.2 安装与 `xargs -P`
```bash
sudo apt install parallel
sudo dnf install parallel
brew install parallel
parallel --version
```
够用时先用 `xargs -P`：
```bash
printf '%s\0' a b c d | xargs -0 -n1 -P4 sh -c 'work "$1"' sh
find images -type f -name '*.png' -print0 | xargs -0 -n1 -P4 gzip -k
```
`-P4` 表示最多四个并发进程，`-n1` 每次一个输入项；复杂 shell 片段用位置参数，不要把路径拼入代码字符串。
### 9.3 GNU parallel 参数和占位符
```bash
parallel echo ::: alpha beta gamma
seq 1 8 | parallel -j4 'sleep 1; echo job {}'
find photos -type f -name '*.jpg' -print0 | parallel -0 -j4 'convert {} {.}.webp'
find photos -type f -name '*.jpg' -print0 | parallel -0 --dry-run 'convert {} {.}.webp'
```
| 占位符 | 含义 | `/data/a.tar.gz` 示例 |
|---|---|---|
| `{}` | 完整输入项 | `/data/a.tar.gz` |
| `{.}` | 去最后扩展名 | `/data/a.tar` |
| `{/}` | basename | `a.tar.gz` |
| `{//}` | dirname | `/data` |
| `{/.}` | basename 去扩展名 | `a.tar` |
| `{#}` | 作业序号 | `1`、`2` |
| `{%}` | job slot | `1` 到并发数 |
### 9.4 joblog、halt、远程
```bash
parallel -j4 --joblog jobs.log './worker {}' ::: input/*.json
parallel -j4 --halt soon,fail=1 --joblog jobs.log './worker {}' ::: input/*.json
parallel -j4 --resume-failed --joblog jobs.log './worker {}' ::: input/*.json
parallel --sshlogin server1,server2 hostname ::: 1 2
parallel --sshloginfile hosts.txt 'sha256sum {}' ::: /data/a /data/b
```
`jobs.log` 记录主机、开始时间、耗时、退出码和信号；`--halt soon,fail=1` 失败后停止启动新任务；`--resume-failed` 依赖同一份 joblog。远程执行还要统一路径、locale、版本、SSH 权限和输出归属；大规模任务应使用调度器。
**何时不该并行**：共享文件/数据库无锁、短任务启动开销大、磁盘/API 已是瓶颈、输出必须严格有序或团队环境不掌控时。此时串行 `xargs` 更可审计。
## 10. 数据与网络辅助
### 10.1 `xh` / HTTPie vs `curl`
**替代谁**：增强交互式 `curl`，不等于替代脚本中的 curl。
**优势**：method、header、query、JSON body 接近自然表达，默认格式化响应；xh 是单二进制 Rust 工具，HTTPie 命令是 `http`。
**安装**：项目/命令 `xh`、HTTPie/`http`；包名通常 `xh`、`httpie`，Cargo crate `xh`。
```bash
brew install xh httpie
sudo apt install httpie
cargo install xh --locked
```
**常用命令**：
```bash
xh GET https://httpbin.org/get q==bash
xh POST https://httpbin.org/post name=alice active:=true
xh GET https://api.example.test/me 'Authorization:Bearer test-token'
http GET https://httpbin.org/get q==bash
http POST https://httpbin.org/post name=alice active:=true
curl -fsS 'https://httpbin.org/get?q=bash'
```
`key=value` 常表示 JSON 字符串，`key:=value` 是原始 JSON，`key==value` 是 URL query，实际细节查 `--help`。
**何时不该用**：部署脚本、健康检查、复杂代理/mTLS/重试、厂商文档优先 curl；机器解析时关闭颜色/pretty，交给 `jq` 等工具，见 [结构化数据处理命令](/kb/os/Bash/18-结构化数据处理命令/)；不要把真实 token 留在 history。
### 10.2 `doggo` / `dog` vs `dig`
**替代谁**：增强 `dig` 的人类输出，额外支持 JSON、DoH/DoT 等；DNS 权威排障基准仍是 `dig`。
**优势**：参数顺序自然、彩色表格紧凑；doggo 是 Go 项目，dog 是较早的 Rust 项目，两者不是同一工具。
**安装与冲突**：Homebrew formula 可为 `doggo` 或 `dog`；`dog` 名称可能与无关包/命令冲突，安装前 `brew info` 并检查项目来源。
```bash
brew install doggo
go install github.com/mr-karan/doggo/cmd/doggo@latest
command -v doggo dog dig
```
**常用命令**：
```bash
doggo example.com
doggo MX github.com @9.9.9.9
doggo --reverse 8.8.8.8 --short
doggo example.com --json | jq '.responses[0].answers[]?'
dog example.com MX @1.1.1.1
dig +short A example.com
dig +tcp @1.1.1.1 example.com MX
```
**何时不该用**：脚本、DNSSEC 细节和所有服务器默认环境优先 `dig`；DoH/DoT 可能绕过本机 resolver，不能代表应用实际解析；现代工具的 JSON schema 也可能变化。
### 10.3 `choose` vs `cut`
**替代谁**：增强简单 `cut`，有时替代只打印字段的 `awk`。
**优势**：零基索引、负索引、区间、正则分隔符较直觉；也因此偏离传统命令习惯。
**安装与冲突**：项目/命令/Cargo crate `choose`；Homebrew formula 是 `choose-rust`，不是 `choose`。它属于非默认程度较高的个人工具。
```bash
brew install choose-rust
cargo install choose --locked
```
**常用命令**：
```bash
printf '%s\n' 'alice 25 engineer' | choose 0 2
printf '%s\n' 'a:b:c:d' | choose -f ':' 0 3
printf '%s\n' 'a b c d' | choose -1
printf '%s\n' 'a b c d' | choose 1:3
cut -d: -f1,3 /etc/passwd
awk -F: '{print $1, $3}' /etc/passwd
```
`choose` 是零基，`cut -f` 是一基；要计算、条件和格式化直接用 `awk`；CSV/JSON 不要用空白字段切割，交给结构化解析器。
**何时不该用**：严格 POSIX、团队脚本、最小系统优先 `cut`/`awk`；依赖稳定字段协议时先写测试。
## 11. 安装管理与降级
### 11.1 发行版包优先
服务器、容器基础镜像和团队构建机优先使用发行版包，因为签名、依赖、安全更新和卸载记录进入系统管理范围：
```bash
cat /etc/os-release
apt-cache policy ripgrep fd-find fzf bat
dnf info ripgrep fd-find fzf bat
apt-file search bin/fdfind
dnf provides '*/inotifywait'
command -v fd fdfind bat batcat delta
```
不要混淆三个名字：上游项目名、发行版包名、可执行文件名。典型冲突是 `fd`/`fd-find`/`fdfind`、`bat`/`batcat`、delta/`git-delta`、choose/`choose-rust`、dust/`du-dust`。
### 11.2 Homebrew
Homebrew 适合个人工作站；Apple Silicon、Intel 和 Linuxbrew prefix 不同，团队脚本不能写死路径：
```bash
brew info ripgrep fd fzf bat git-delta
brew install ripgrep fd fzf bat git-delta
brew list --versions
brew pin git-delta
```
### 11.3 Cargo
Cargo 能获得较新的 Rust CLI，但需要 Rust、编译器、系统库和 PATH；不加锁可能产生不同依赖树，优先 `--locked`：
```bash
cargo install hyperfine --locked
cargo install choose --locked
cargo install --list
command -v hyperfine
```
团队镜像应固定 toolchain、依赖锁文件和二进制来源；个人机器才适合随意 `cargo install ...@latest`。release 二进制也要核对架构、校验和签名，不要无审查执行 `curl | sh`。
### 11.4 团队脚本为何优先经典命令
经典命令更容易在救援系统、BusyBox、CI runner 和陌生服务器出现，语义更容易查手册，依赖更少，输出也更容易做明确的 `-P`、`-n`、`-0` 协议。现代工具可以进入脚本，但应满足：
- 环境由容器/构建系统固定，并在 CI 测版本。
- 启动时检查依赖，缺失时快速失败或明确降级。
- 输出用 JSON/CSV/机器格式，不依赖颜色、图标、列宽。
- 有 dry-run、备份、事务或恢复方案。
一个交互配置可降级：
```bash
if command -v rg >/dev/null 2>&1; then
  rg -n --hidden --glob '!.git/**' 'TODO' .
else
  grep -RIn --exclude-dir=.git 'TODO' .
fi
```
需要现代工具的脚本则快速失败：
```bash
need_cmd() { command -v "$1" >/dev/null 2>&1 || { printf 'missing: %s\n' "$1" >&2; return 127; }; }
need_cmd hyperfine || exit
hyperfine --warmup 3 --runs 10 './benchmark-target'
```
NUL 安全降级：
```bash
if command -v fd >/dev/null 2>&1; then
  fd -0 -t f -e log . logs/
else
  find logs/ -type f -name '*.log' -print0
fi | xargs -0 -r wc -l
```
注意：`rg` 与 grep 的 ignore 规则、`fd` 与 find 的隐藏文件规则、`bat` 的颜色、`du` 的统计口径并不完全等价，降级行为要写进测试和文档。
## 12. 选择矩阵
| 任务 | 经典基准 | 现代增强 | 典型不要用场景 |
|---|---|---|---|
| 搜内容 | `grep` | `rg` | 不掌控环境的脚本 |
| 找文件 | `find` | `fd` | 复杂元数据谓词 |
| 人工选择 | shell/readline | `fzf` | cron/CI |
| 看文本 | `cat`/`less` | `bat`/`glow` | 机器解析 |
| 看目录 | `ls`/`tree` | `eza`/`lsd`/`broot` | 解析视觉表格 |
| 看 diff | `diff`/`less` | `delta` | patch 输入 |
| 跳目录 | `cd`/`history` | `zoxide`/`autojump` | 脚本依赖历史 |
| 目录占用 | `du` | `dust`/`ncdu`/`gdu` | 稳定采集接口 |
| 文件系统 | `df` | `duf` | inode 问题只看字节 |
| 进程 | `ps` | `procs` | 精确字段脚本 |
| 资源总览 | `top` | `btop`/`btm` | 事故只看图表 |
| 命令耗时 | `time` | `hyperfine` | 未控制环境噪声 |
| HTTP | `curl` | `xh`/`http` | 复杂部署脚本 |
| DNS | `dig` | `doggo`/`dog` | 权威排障 |
| 字段 | `cut`/`awk` | `choose` | 结构化数据 |
## 13. 综合实验
### 实验 1：`grep` 与 `rg` 的搜索范围
```bash
tmp="$(mktemp -d)"
mkdir -p "$tmp/src" "$tmp/.git" "$tmp/vendor"
printf 'TODO: source\n' > "$tmp/src/main.c"
printf 'TODO: hidden\n' > "$tmp/.env"
printf 'TODO: vendor\n' > "$tmp/vendor/lib.c"
printf '\0TODO\0' > "$tmp/data.bin"
printf 'vendor/\n' > "$tmp/.gitignore"
grep -RIn 'TODO' "$tmp"
rg -n 'TODO' "$tmp"
rg -uuu -n 'TODO' "$tmp"
rm -rf "$tmp"
```
解释默认 ignore、隐藏和二进制差异。
### 实验 2：NUL 文件名链路
```bash
tmp="$(mktemp -d)"
touch "$tmp/normal.log" "$tmp/file with space.log"
find "$tmp" -type f -name '*.log' -print0 | xargs -0 -n1 printf '<%s>\n'
(command -v fd || command -v fdfind) -0 -e log "$tmp" | xargs -0 -n1 printf '<%s>\n'
rm -rf "$tmp"
```
重点是 `-print0`/`-0`，而不是把文件名当普通空格分隔文本。
### 实验 3：fzf 文件预览
```bash
fd -t f -e md | fzf --preview 'bat --color=always --line-range=:120 {}'
```
输入部分文件名，观察预览；没有 bat 时可换 `sed -n '1,120p' {}`。
### 实验 4：比较目录和文件系统
```bash
du -h -d 1 . 2>/dev/null | sort -h
dust -d 1 .
ncdu -x .
df -h .
```
记录排序、下钻、删除能力、硬链接口径和是否适合脚本，说明 `du` 与 `df` 的问题不同。
### 实验 5：hyperfine 与导出
```bash
hyperfine --warmup 2 --runs 10 \
  'cat README.md >/dev/null' \
  'bat --paging=never --color=never README.md >/dev/null'
hyperfine --warmup 2 --runs 10 --export-json view.json 'cat README.md >/dev/null' 'bat --paging=never --color=never README.md >/dev/null'
```
说明 bat 的语法检测、装饰和 Git 检查为什么会增加工作；JSON 应交给结构化工具解析。
### 实验 6：本机 HTTP 小压测
对自己启动的 `127.0.0.1:8080` 服务执行：
```bash
curl -fsS http://127.0.0.1:8080/health
oha -n 100 -c 5 http://127.0.0.1:8080/health
top -b -n 1 | head
ss -s
```
记录请求数、错误数、平均延迟和 p95/p99；不要把本机示例复制到未知公网目标。
## 14. 小结
1. 现代 CLI 主要改善交互体验，不会让经典命令失去价值。
2. `rg`/`fd` 适合代码树和按名搜索，`fzf` 负责人工选择；复杂脚本回到 `grep`/`find`。
3. `bat`、`eza`/`lsd`、`delta`、`glow` 是人类阅读层，`less` 仍是基础 pager。
4. `zoxide`、`autojump`、`broot` 加速个人导航，脚本仍需确定路径。
5. `dust`/`ncdu`/`gdu` 看目录，`duf`/`df` 看文件系统；先确认统计口径。
6. `btop`、`procs`、`gping`、`bandwhich`、`iftop` 是交互入口，结论回到 `ps`、`vmstat`、`sar`、`iostat`。
7. `hyperfine` 比命令，`oha`/`hey`/`wrk` 造 HTTP 负载，`stress-ng` 做资源压力；压测必须授权隔离。
8. `entr`、`watchexec`、`inotifywait`、`watch` 分别代表列表、跨平台事件、Linux 原语和周期轮询。
9. GNU `parallel` 提供 joblog、halt、恢复和远程能力，简单任务仍可用 `xargs -P`。
10. `xh`/HTTPie、`doggo`/`dog`、`choose` 适合人类辅助；团队脚本优先 `curl`、`dig`、`cut`/`awk`。
## 15. 自测
### 基础题
1. `rg` 默认为什么可能搜不到 `.env` 或 `vendor/`？如何扩大范围？
2. Debian 安装 `fd-find` 后为什么可能用 `fdfind`？`bat` 有什么类似问题？
3. `df` 与 `du` 分别回答什么？为什么 `dust` 不能替代 `duf`？
4. bottom 的命令为什么是 `btm`？
5. fzf 的 `Ctrl-R`、`Ctrl-T`、`Alt-C` 各做什么？为什么不能用于 cron？
6. `less +F` 与 `watch -n 1` 的模型差异是什么？
### 命令题
7. 只在 `src/` 搜索 `.go` 文件中的 TODO，带行号和一行上下文，并写 grep 降级。
8. NUL 安全地找 `logs/` 下 `.log` 并统计每个文件行数。
9. 用 fzf 和 bat 做最多 200 行的文件预览。
10. hyperfine 预热 3 次、运行 15 次比较 grep/rg 并导出 CSV。
11. GNU parallel 最多 4 并发、写 `jobs.log`、首个失败后停止新任务。
12. 写一条只针对本机授权服务的 oha 命令，并解释不能直接压公网。
### 判断题
13. “bat 可以完全替代 cat，因此应该 alias cat=bat。”指出两个问题。
14. “目录占用 90%，整个磁盘只剩 10%。”还缺什么信息？
15. “stress-ng --vm 的结果就是应用内存性能。”缺少哪些条件？
16. “所有 Linux 都自带 GNU parallel。”错误在哪里？
### 参考答案要点
- 1：ignore、隐藏和二进制规则；用 `--hidden`、`--no-ignore` 或 `-uuu`，并评估误报。
- 2：包名冲突导致 `fdfind`；旧版 Debian/Ubuntu 的 bat 可能叫 `batcat`。
- 3：`df` 看文件系统，`du` 看目录树；`dust` 仍是目录分析。
- 4：项目叫 bottom，二进制叫 `btm`。
- 5：历史、文件插入、目录切换；需要交互 TTY。
- 6：`+F` 跟随一个文件；watch 周期性重跑命令，可能漏掉瞬时状态。
- 7：`rg -n -C 1 --glob '*.go' 'TODO' src/`；降级 `grep -RIn -C 1 --include='*.go' 'TODO' src/`。
- 8：`find logs -type f -name '*.log' -print0 | xargs -0 -r wc -l`。
- 9：`fd -t f | fzf --preview 'bat --color=always --line-range=:200 {}'`。
- 10：`hyperfine --warmup 3 --runs 15 --export-csv bench.csv 'grep -R TODO src' 'rg TODO src'`。
- 11：`parallel -j4 --joblog jobs.log --halt soon,fail=1 './worker {}' ::: input/*`。
- 12：例如 `oha -n 100 -c 5 http://127.0.0.1:8080/health`；公网会造成未授权流量、服务降级、计费或安全事件。
- 13：参数不完全兼容；装饰/颜色会污染管道，cat 的拼接和重定向语义应保持直观。
- 14：需要 `df -h` 的挂载点、inode、预留块和容器视角。
- 15：还需要真实访问模式、线程、NUMA、分配器、工作集、GC/缓存和应用观测。
- 16：parallel 是独立包，不属于 coreutils 默认组件，精简镜像和不同发行版未必安装。

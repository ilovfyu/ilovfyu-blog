::: abstract 本章定位
本篇补齐 Linux 日常命令手册中“内核模块、硬件、sysctl、namespace/cgroup、设备事件”这一整块：用 `sysctl` 读写运行时内核参数，用 `lsmod`/`modprobe` 管理可加载模块，用 `dmesg`/`journalctl -k` 还原内核事件，用硬件命令识别 CPU、内存、PCI、USB、存储和 RTC，再进入 namespace、cgroup v2、NUMA、中断与电源状态完成系统级排障。基础监控见 [系统监控与性能命令](/kb/os/Bash/07-系统监控与性能命令/)，服务资源边界见 [服务管理与定时任务](/kb/os/Bash/12-服务管理与定时任务/)，原理见 [内核架构](/kb/os/Linux/07-Linux内核架构与启动原理/)，启动故障联动 [启动排查](/kb/os/问题排查/06-系统启动与内核崩溃/)。
:::

这组命令分别观察 `/proc`、`/sys`、`/dev`、内核环形缓冲区和 journal。学习重点不是背选项，而是回答：当前状态是什么、修改影响哪一层、故障后如何回滚。

## 1. 接口地图与权限
### 1.1 四类接口
| 接口 | 典型路径 | 内容 | 入口命令 |
|---|---|---|---|
| procfs | `/proc` | 进程、内核计数器、启动参数、模块 | `cat`、`lsmod`、`uname` |
| sysfs | `/sys` | 设备模型、驱动、总线、CPU、内存、cgroup | `udevadm`、`lscpu`、`lsblk` |
| devtmpfs/udev | `/dev` | 设备节点、权限、稳定链接 | `ls -l`、`udevadm info` |
| kernel log/journal | 环形缓冲区、journal | 启动、驱动、硬件、内核告警 | `dmesg`、`journalctl -k` |
```bash
uname -r
ls /sys/class
ls -ld /sys/fs/cgroup
```
预期输出：
```
6.6.15-amd64
block  char  drm  firmware  net  power  scsi  tty
dr-xr-xr-x 5 root root 0 Aug 10 09:30 /sys/fs/cgroup
```
`/proc` 与 `/sys` 是虚拟文件系统，目录大小显示为 0 不代表没有内容；cgroup 目录存在也不代表一定是 v2。
### 1.2 先确认系统与权限
```bash
cat /etc/os-release
id
command -v systemctl modprobe lscpu lspci lsusb
```
预期输出：
```
PRETTY_NAME="Debian GNU/Linux 12 (bookworm)"
uid=1000(zhang) gid=1000(zhang) groups=1000(zhang),27(sudo)
/usr/bin/systemctl
/usr/sbin/modprobe
```
`lscpu`、`lsblk`、`uname` 通常普通用户即可；`modprobe`、`rmmod`、`dmidecode`、部分 `dmesg` 和 udev 监视接口通常需要 root 或 capability。容器内的 root 仍可能被 capability、seccomp 或 namespace 限制。
### 1.3 观察优先
| 目标 | 首选命令 |
|---|---|
| 内核与启动输入 | `uname`、`/boot`、`/proc/cmdline` |
| 参数与模块 | `sysctl`、`lsmod`、`modinfo` |
| 设备与驱动 | `lspci -k`、`lsusb -t`、`udevadm info` |
| 隔离与资源 | `lsns`、`nsenter`、`systemd-cgls` |
| 平台瓶颈 | `numastat`、`/proc/interrupts`、`turbostat` |
::: important 先保存基线
修改参数或模块前，保存 `uname -a`、相关 `sysctl`、`lsmod`、`dmesg`、硬件枚举和故障时间。没有基线就无法判断变更是否有效，也无法在重启后复盘。
:::

## 2. sysctl：运行时内核参数
### 2.1 接口模型与基本读取
`sysctl` 主要读写 `/proc/sys/`。路径中的 `/` 转成点号：
```text
/proc/sys/vm/swappiness       <-> vm.swappiness
/proc/sys/net/ipv4/ip_forward <-> net.ipv4.ip_forward
```
```bash
sysctl vm.swappiness
sysctl -n vm.swappiness
cat /proc/sys/vm/swappiness
```
预期输出：
```
vm.swappiness = 60
60
60
```
默认输出适合人工阅读，`-n` 只输出值，适合脚本；直接读 `/proc/sys` 可验证内核当前状态。
### 2.2 `sysctl -a`：枚举参数
```bash
sysctl -a
sysctl -a 2>/dev/null | grep -E '^(vm|fs|kernel|net)\.' | head -20
```
预期输出片段：
```
kernel.hostname = node01
vm.swappiness = 60
fs.file-max = 9223372036854775807
net.ipv4.ip_forward = 0
```
`-a` 列出当前可见的全部键值，不是“推荐配置”。不同内核、内存大小、工作负载、虚拟化环境和发行版默认值不同。
::: warning 不要盲调 `sysctl -a`
网上复制的“万能 sysctl.conf”可能破坏连接、内存回收、转发行为或安全边界。先明确参数对应的内核路径，再用指标验证，最后决定是否持久化。
:::
### 2.3 `sysctl -w`：临时写入
```bash
old=$(sysctl -n vm.swappiness)
sudo sysctl -w vm.swappiness=10
sysctl vm.swappiness
sudo sysctl -w vm.swappiness="$old"
```
输出 `vm.swappiness = 10` 表示当前内核已经接受写入。`-w` 通常只改变当前运行内核，重启后恢复默认或启动配置；修改前保存旧值，验证业务后回滚。
### 2.4 `sysctl -p`：读取配置文件
```bash
sudo sysctl -p
sudo sysctl -p /etc/sysctl.conf
sudo sysctl -p /etc/sysctl.d/60-myapp.conf
```
预期输出：
```
vm.swappiness = 10
fs.inotify.max_user_watches = 524288
```
| 命令 | 读取范围 |
|---|---|
| `sysctl -p` | 默认读取 `/etc/sysctl.conf` |
| `sysctl -p FILE` | 只读取指定文件 |
| 空行、`#` | 忽略 |
| 非法键值 | 报错，不能假定整批成功 |
### 2.5 `sysctl --system` 与配置位置
```bash
sudo sysctl --system
systemctl status systemd-sysctl.service
```
典型输出：
```
* Applying /usr/lib/sysctl.d/50-default.conf ...
* Applying /etc/sysctl.d/60-myapp.conf ...
* Applying /etc/sysctl.conf ...
vm.swappiness = 10
```
| 路径 | 角色 |
|---|---|
| `/usr/lib/sysctl.d/*.conf` | 软件包默认配置 |
| `/run/sysctl.d/*.conf` | 运行时生成或临时覆盖 |
| `/etc/sysctl.d/*.conf` | 管理员持久配置，推荐按用途拆分 |
| `/etc/sysctl.conf` | 传统兼容入口 |
`--system` 按 procps/systemd 约定读取多个目录；同名键通常由后处理配置覆盖。具体路径和顺序以当前命令输出为准。`-p` 只读一个文件，不能替代 `--system`。
### 2.6 持久化示例
```conf
# /etc/sysctl.d/60-observe.conf
vm.swappiness = 10
fs.inotify.max_user_watches = 524288
kernel.printk = 4 4 1 7
```
```bash
sudo sysctl --system
sysctl vm.swappiness fs.inotify.max_user_watches kernel.printk
```
应用专属设置写独立文件，安全基线可写入如 `99-hardening.conf` 的后置文件；不要直接修改 `/usr/lib/sysctl.d` 的包文件。
### 2.7 常见 `vm.*` 参数
```bash
sysctl vm.swappiness vm.overcommit_memory vm.overcommit_ratio
sysctl vm.dirty_background_ratio vm.dirty_ratio
sysctl vm.vfs_cache_pressure vm.max_map_count
grep -E 'MemAvailable|CommitLimit|Committed_AS|Swap' /proc/meminfo
```
| 参数 | 作用 | 判断重点 |
|---|---|---|
| `vm.swappiness` | 换出匿名页的倾向 | 结合 swap in/out 和延迟，不等于禁用 swap |
| `vm.overcommit_memory` | 0 启发式、1 允许、2 严格 | 影响大内存申请，需结合应用文档 |
| `vm.overcommit_ratio` | 严格模式的 RAM 百分比 | 与 `CommitLimit`、swap 一起看 |
| `vm.dirty_background_ratio` | 启动后台回写的脏页比例 | 大内存可能形成大批量回写 |
| `vm.dirty_ratio` | 触发同步回写的比例 | 过大可能长时间停顿 |
| `vm.vfs_cache_pressure` | inode/dentry 回收倾向 | 不代表缓存越多越快 |
| `vm.max_map_count` | 单进程最大映射数 | 按应用要求设置 |
| `vm.panic_on_oom` | OOM 时是否 panic | 高风险，先确认 kdump/重启策略 |
判断内存压力先看 `MemAvailable`、`vmstat` 的 `si/so`、cgroup `memory.events`，不要只看 `free`。
### 2.8 常见 `fs.*` 参数
```bash
sysctl fs.file-max fs.nr_open
sysctl fs.inotify.max_user_instances fs.inotify.max_user_watches
sysctl fs.aio-max-nr
```
| 参数 | 作用 | 症状 |
|---|---|---|
| `fs.file-max` | 系统级文件句柄上限 | 全系统 `Too many open files` |
| `fs.nr_open` | 单进程 `RLIMIT_NOFILE` 上限 | `LimitNOFILE` 受约束 |
| `max_user_instances` | 每 UID 的 inotify 实例 | watcher 实例失败 |
| `max_user_watches` | 每 UID 的 watcher 数 | 编辑器/构建工具 watch limit |
| `fs.aio-max-nr` | 异步 IO 事件上限 | AIO 创建失败 |
::: warning 提高上限不是修复泄漏
文件描述符、inotify watcher 或映射持续耗尽时，先查进程泄漏。把上限设得极大只会延迟故障并增加内核内存消耗。
:::
### 2.9 常见 `kernel.*` 参数
```bash
sysctl kernel.hostname kernel.threads-max kernel.pid_max
sysctl kernel.shmmax kernel.shmall
sysctl kernel.randomize_va_space kernel.core_pattern
sysctl kernel.modules_disabled kernel.unprivileged_bpf_disabled
```
| 参数 | 作用 | 风险/备注 |
|---|---|---|
| `kernel.hostname` | 内核主机名 | 持久主机名应由 `hostnamectl` 管理 |
| `kernel.threads-max` | 系统线程上限 | 过高增加内核内存预算 |
| `kernel.pid_max` | PID 分配上限 | 不等于并发进程数 |
| `kernel.shmmax/shmall` | SysV 共享内存限制 | 先确认应用使用机制 |
| `kernel.randomize_va_space` | ASLR 级别 | 降低会削弱安全性 |
| `kernel.core_pattern` | core 文件名或管道 | 可能由 systemd-coredump 接管 |
| `kernel.modules_disabled` | 禁止模块加载/卸载 | 设 1 后本次启动不可恢复 |
| `kernel.unprivileged_bpf_disabled` | 限制非特权 eBPF | 影响观测工具 |
### 2.10 常见 `net.*` 参数
```bash
sysctl net.ipv4.ip_forward net.ipv6.conf.all.forwarding
sysctl net.ipv4.tcp_syncookies net.ipv4.tcp_fin_timeout
sysctl net.core.somaxconn net.core.rmem_max net.core.wmem_max
sysctl net.ipv4.ip_local_port_range
```
| 参数 | 作用 | 注意 |
|---|---|---|
| `net.ipv4.ip_forward` | IPv4 转发 | 还要有路由和防火墙规则 |
| `net.ipv6.conf.all.forwarding` | IPv6 转发 | 与接口级设置共同决定 |
| `tcp_syncookies` | SYN backlog 压力保护 | 不是完整 DDoS 防护 |
| `tcp_fin_timeout` | 特定 FIN-WAIT 超时 | 过低改变异常关闭行为 |
| `net.core.somaxconn` | listen backlog 系统上限 | 与应用 backlog 一起调 |
| `rmem_max/wmem_max` | socket 缓冲最大值 | 增加每连接内存预算 |
| `ip_local_port_range` | 临时端口范围 | 还要查 TIME_WAIT/NAT |
::: warning 网络参数会改变可达性
修改转发、socket 缓冲、反向路径过滤或 SYN 参数前记录旧值，并与 [防火墙与网络安全命令](/kb/os/Bash/15-防火墙与网络安全命令/) 的规则一起验证；远程机器先准备控制台回滚路径。
:::
### 2.11 `kernel.printk`
```bash
sysctl kernel.printk
```
预期输出：`kernel.printk = 4 4 1 7`
四列依次是 `console_loglevel`、`default_message_loglevel`、`minimum_console_loglevel`、`default_console_loglevel`。数字越小越严重：0 emerg、3 err、4 warning、7 debug；第一列为 4 表示 warning 及更严重消息可到控制台。
```bash
sudo sysctl -w kernel.printk='4 4 1 7'
```
只建议调试控制台噪声或启动问题时临时使用；journal 收集级别不等于控制台级别。
### 2.12 临时、持久与高风险
| 操作 | 生命周期 | 回滚 |
|---|---|---|
| `sysctl key` | 只读当前值 | 不适用 |
| `sysctl -w key=value` | 当前启动周期 | 写回旧值 |
| `sysctl -p FILE` | 当前启动周期 | 恢复文件/旧值 |
| `/etc/sysctl.d/NN-name.conf` | 重启后仍加载 | 删除后 `sysctl --system` |
| `kernel.modules_disabled=1` | 本次启动不可恢复 | 只能重启 |
| `panic`、`drop_caches`、`MemoryMax` | 可能重启、抖动或 OOM kill | 先记录并准备恢复 |

## 3. 内核模块
### 3.1 模块树与 `lsmod`
```bash
uname -r
ls -ld /lib/modules/$(uname -r)
find /lib/modules/$(uname -r) -type f -name '*.ko*' | head
lsmod
cat /proc/modules
```
预期输出：
```
Module                  Size  Used by
nf_conntrack            172032  1 nft_ct
```
`/lib/modules/&lt;release&gt;` 保存 `.ko`、`modules.dep`、`modules.alias`、`modules.symbols`；`/etc/modprobe.d/*.conf` 保存管理员规则；`/proc/modules` 是当前加载表。`lsmod` 的 `Module/Size/Used by` 分别是名称、内核中大小、引用者线索，引用计数不等于完整使用者清单。
### 3.2 `modinfo`
```bash
modinfo ext4
modinfo -F filename ext4
modinfo -F vermagic ext4
modinfo -F alias nvme
modinfo -p e1000e
```
预期输出片段：
```
filename: /lib/modules/6.6.15-amd64/kernel/fs/ext4/ext4.ko
license: GPL
depends: mbcache,jbd2
vermagic: 6.6.15-amd64 SMP preempt mod_unload modversions
```
`filename` 是文件，`depends` 是依赖，`alias` 是匹配入口，`vermagic` 是构建兼容标记，`parm` 是可传参数。vermagic 通过不代表第三方模块安全兼容。
::: warning 模块运行在内核态
错误模块可能造成 Oops、数据损坏或 panic。优先使用与 `uname -r` 匹配的发行版模块和固件，第三方 `.ko` 先检查签名、来源和回滚路径。
:::
### 3.3 `modprobe`：依赖与 alias
```bash
sudo modprobe loop
sudo modprobe -v nf_conntrack
modprobe -n -v ext4
modprobe --show-depends ext4
modprobe -R 'pci:v00008086d000015F3*'
```
dry-run 可能输出：
```
insmod /lib/modules/.../crc16.ko
insmod /lib/modules/.../jbd2.ko
insmod /lib/modules/.../ext4.ko
```
| 形式 | 含义 |
|---|---|
| `modprobe NAME` | 按名加载并递归处理依赖 |
| `-v` | 打印实际动作 |
| `-n -v` | 只模拟，不加载 |
| `--show-depends` | 展示依赖顺序 |
| `NAME key=value` | 临时传参数 |
| `-R MODALIAS` | 反查匹配 alias |
| `-C FILE`/`-S RELEASE` | 指定配置/内核版本 |
`modprobe` 通常接收模块名，不需要 `.ko` 路径；模块名中的 `-` 与 `_` 等价。
### 3.4 `insmod`、`rmmod`、`modprobe -r`、`depmod`
```bash
sudo insmod ./hello.ko
sudo rmmod hello
sudo modprobe -r nf_conntrack
sudo modprobe -r -v bridge
sudo depmod -a
sudo depmod -a "$(uname -r)"
```
| 命令 | 行为 |
|---|---|
| `insmod FILE` | 直接插入一个 `.ko`，不解析依赖/alias |
| `rmmod NAME` | 直接卸载，被引用时失败 |
| `modprobe -r NAME` | 按依赖关系移除模块 |
| `rmmod -f NAME` | 强制卸载，要求内核支持，高风险 |
| `depmod -a` | 重建依赖、alias、符号索引 |
插入失败的详细原因通常在 `dmesg`，例如 `Invalid module format` 与 `version magic should be ...`。第三方模块安装流程：
```bash
sudo install -D -m 0644 mydrv.ko /lib/modules/$(uname -r)/extra/mydrv.ko
sudo depmod -a "$(uname -r)"
modprobe -n -v mydrv
sudo modprobe mydrv
```
::: warning 不要在线卸载关键模块
根文件系统、网卡、NVMe、加密和虚拟化存储驱动不能随意 `rmmod`；先看 `lsmod`、`mount`、`fuser` 和服务依赖，强制卸载可能断网、卸载根盘或破坏数据。
:::
### 3.5 模块参数、黑名单与故障表
```bash
sudo modprobe e1000e InterruptThrottleRate=3000
cat /sys/module/e1000e/parameters/InterruptThrottleRate
grep -R --line-number -E '^(options|blacklist|alias|softdep)' /etc/modprobe.d/
modprobe -c | grep -E 'blacklist|alias' | head
```
```conf
# /etc/modprobe.d/e1000e.conf
options e1000e InterruptThrottleRate=3000
# /etc/modprobe.d/blacklist-demo.conf
blacklist pcspkr
```
`options` 配参数，`blacklist` 主要阻止自动 alias 加载，`alias` 建映射，`softdep` 声明软依赖。影响 initramfs 时，Debian/Ubuntu 常用 `update-initramfs -u`，RHEL/Fedora 常用 `dracut -f`。
| 现象 | 检查 | 方向 |
|---|---|---|
| `Module not found` | `uname -r`、文件、`depmod` | 安装匹配模块包 |
| `Invalid module format` | `dmesg`、`vermagic`、签名 | 当前 headers/config 重编译 |
| `Required key not available` | Secure Boot、签名 | 受信任签名模块 |
| `Unknown symbol` | `depends`、导出符号 | 加载依赖/检查配置 |
| 设备无驱动 | `lspci -k`、`lsusb`、modalias | 驱动、固件、设备 ID |
| 无法卸载 | `lsmod`、`fuser`、挂载、服务 | 停使用者后 `modprobe -r` |
::: warning 黑名单可能阻断启动
把磁盘控制器、根文件系统、网卡或虚拟化存储驱动加入黑名单，可能让 initramfs 找不到根设备或让远程主机失联；先在有控制台的测试节点操作。
:::

## 4. 内核版本、启动参数与日志
### 4.1 `uname`、`/boot`、`/proc/cmdline`
```bash
uname -a
uname -r
uname -m
cat /proc/version
ls -lh /boot
cat /proc/cmdline
grep -oE 'crashkernel=[^ ]+|root=[^ ]+|quiet|ro|nomodeset' /proc/cmdline
```
预期输出片段：
```
Linux node01 6.6.15-amd64 #1 SMP PREEMPT_DYNAMIC x86_64 GNU/Linux
-rw-r--r-- 1 root root 38M initrd.img-6.6.15-amd64
BOOT_IMAGE=/vmlinuz-6.6.15-amd64 root=/dev/mapper/vg-root ro quiet
```
`uname -r` 是模块目录关键值，`-m` 是架构；`vmlinuz` 是内核，`initrd/initramfs` 是早期用户态，`config-*` 是构建配置，`root=` 是根设备，`ro/rw` 是初始挂载，`quiet` 减少控制台输出，`crashkernel=` 为 kdump 预留内存。当前真实启动输入以 `/proc/cmdline` 为准。
### 4.2 `dmesg -T/-w/-l`
```bash
dmesg -T | tail -30
dmesg -T -l err,warn
sudo dmesg -Tw
sudo dmesg --follow --level=err,warn
```
预期输出：
```
[Mon Aug 10 09:41:10 2026] nvme nvme0: controller is down
[Mon Aug 10 09:41:11 2026] blk_update_request: I/O error, dev nvme0n1
```
`-T` 把启动以来时间戳转换成人类时间，系统时间校正时只是近似；`-w` 持续跟踪；`-l` 按级别过滤。0-7 依次是 emerg、alert、crit、err、warn、notice、info、debug。权限不足查 `kernel.dmesg_restrict`。
### 4.3 `journalctl -k`
```bash
journalctl -k
journalctl -k -b
journalctl -k -b -1 -p warning
journalctl -k --since '30 min ago' --no-pager
journalctl -kf
```
`dmesg` 看当前环形缓冲区，重启后通常消失；`journalctl -k` 按启动、时间和优先级回放保存的内核日志，前提是 journald 当时收集并保存了它。
### 4.4 启动排查参数
| 参数 | 用途 | 注意 |
|---|---|---|
| `nomodeset` | 绕过显卡 KMS，排黑屏 | 可能失去图形驱动/分辨率 |
| `systemd.unit=emergency.target` | 最小救援 shell | 服务不会正常启动 |
| `rd.break` | initramfs 切根前暂停 | 修改根盘前正确挂载 |
| `init=/bin/bash` | 跳过 PID 1 | 权限极高，需手动 sync/重启 |
| `panic=10` | panic 后 10 秒重启 | 必须配 kdump |
| `crashkernel=512M` | 为 kdump 预留内存 | 过小抓不到，过大减少可用内存 |
启动链路见 [内核架构](/kb/os/Linux/07-Linux内核架构与启动原理/)，启动阶段故障见 [启动排查](/kb/os/问题排查/06-系统启动与内核崩溃/)。

## 5. 硬件识别命令
### 5.1 默认与非默认包
| 命令 | 常见包 | 默认情况 |
|---|---|---|
| `lscpu`、`lsmem`、`lsblk` | `util-linux` | 多数发行版默认 |
| `lsscsi` | `lsscsi` | 常为非默认 |
| `lspci` | `pciutils` | 精简系统可能没有 |
| `lsusb` | `usbutils` | 非默认 |
| `lshw`、`hwinfo`、`inxi` | 同名包 | 非默认 |
| `dmidecode` | `dmidecode` | 非默认、通常需 root |
| `cpupower`、`turbostat` | `linux-tools`/`kernel-tools` | 非默认 |
| `powertop`、`irqtop` | 同名/发行版工具包 | 非默认 |
```bash
command -v lscpu lsmem lshw hwinfo inxi dmidecode lspci lsusb lsscsi lsblk
```
Debian/Ubuntu 常见包：`pciutils usbutils lshw hwinfo inxi dmidecode lsscsi numactl powertop`；RHEL/Fedora 常见包：`pciutils usbutils lshw hwinfo inxi dmidecode lsscsi numactl kernel-tools powertop`。
### 5.2 `lscpu`、`lsmem`
```bash
lscpu
lscpu -e=CPU,CORE,SOCKET,NODE,ONLINE
lscpu -p=CPU,CORE,SOCKET,NODE,ONLINE
lsmem
lsmem --summary
lsmem -o RANGE,SIZE,STATE,REMOVABLE,BLOCK
```
预期输出：
```
CPU(s): 8
Thread(s) per core: 2
Core(s) per socket: 4
CPU CORE SOCKET NODE ONLINE
 0    0      0    0    yes
RANGE                                  SIZE STATE REMOVABLE BLOCK
0x0000000000000000-0x00000001ffffffff   8G online yes       0-63
```
`lscpu` 的 `CPU(s)` 是逻辑 CPU，`Thread(s) per core` 是 SMT，`Core(s) per socket` 是物理核心，`NODE` 是 NUMA；`-e` 给人读，`-p` 便于解析。`lsmem` 的 `RANGE/SIZE/STATE/REMOVABLE/BLOCK` 分别是物理范围、大小、在线状态、可移除性和内存 block。
### 5.3 `lshw`、`hwinfo`、`inxi`、`dmidecode`
```bash
sudo lshw -short
sudo lshw -class network -class storage
sudo hwinfo --network
sudo hwinfo --disk --short
inxi -Fxxxz
sudo dmidecode -t system
sudo dmidecode -t bios
sudo dmidecode -t memory
```
`lshw` 看硬件树，`hwinfo` 做细探测，`inxi -Fxxxz` 输出脱敏摘要，`dmidecode` 从 SMBIOS 看型号、BIOS、DIMM 槽和内存条。DMI 是固件数据，虚拟机可能伪造或缺失，序列号/UUID 外发前脱敏。
### 5.4 `lspci -k/-vv`
```bash
lspci -nn
lspci -k
lspci -vv -s 02:00.0
lspci -tv
```
预期输出：
```
02:00.0 Ethernet controller [0200]: Intel I210 [8086:1533]
        Kernel driver in use: igb
        Kernel modules: igb
```
`-nn` 显示 ID，`-k` 显示当前驱动/候选模块，`-vv` 显示 PCI 能力、IRQ、链路、AER，`-t` 显示设备树。`Kernel driver in use` 才证明已绑定；`Kernel modules` 只是候选。`LnkCap/LnkSta` 看理论/当前速度宽度，AER 增长且链路降级时优先查硬件/固件。
### 5.5 `lsusb -t/-v`
```bash
lsusb -nn
lsusb -t
lsusb -v -s 001:002
```
预期输出：
```
Bus 001 Device 002: ID 0781:5581 SanDisk Corp.
/ : Bus 01.Port 1: Dev 1, Class=root_hub, Driver=xhci_hcd, 5000M
    |__ Port 2: Dev 2, If 0, Class=Mass Storage, Driver=usb-storage, 5000M
```
Bus/Device 是当前枚举地址，`ID` 是 vendor:product，`-t` 看 hub、端口、速度和驱动，`-v` 看接口、端点和供电描述。
### 5.6 `lsscsi`、`lsblk`、`hwclock`
```bash
lsscsi -g
lsscsi -t
lsblk -o NAME,PATH,SIZE,TYPE,FSTYPE,UUID,ROTA,RO,MODEL,SERIAL,MOUNTPOINTS
lsblk -f
lsblk -S
sudo hwclock --show
sudo hwclock --verbose
```
预期输出片段：
```
2026-08-10 09:48:10.123456+08:00
Assuming RTC is kept in UTC
```
`lsscsi` 的 `[host:channel:id:lun]` 是 SCSI 地址，`-g` 增加通用节点，`-t` 显示传输路径；`lsblk` 的 `TYPE/FSTYPE/UUID/MOUNTPOINTS/ROTA` 连接块设备与文件系统。`hwclock --show` 读 RTC，`--hctosys`/`-s` 用 RTC 设置系统时间，`--systohc`/`-w` 反向写入；现代系统优先由 `timedatectl` 与 NTP 管理。

## 6. udev 与设备事件
### 6.1 规则位置与属性
```bash
systemctl status systemd-udevd
ls -ld /etc/udev/rules.d /run/udev/rules.d /usr/lib/udev/rules.d
udevadm info --query=all --name=/dev/sda
udevadm info --query=property --name=/dev/sda | sort
udevadm info --attribute-walk --name=/dev/sda
udevadm info --query=path --name=/dev/sda
```
规则目录：`/usr/lib/udev/rules.d` 是包默认，`/run/udev/rules.d` 是运行时，`/etc/udev/rules.d` 是管理员规则且优先级高。`P/N/S/E` 分别是 sysfs 路径、节点名、稳定链接、环境属性；常用 `SUBSYSTEM`、`DEVTYPE`、`ID_SERIAL`、`ID_PATH`、`DRIVER`、`MODALIAS`。
按属性排查：
```bash
udevadm info --query=property --path=/sys/class/net/eth0
readlink -f /sys/class/block/sda
udevadm info --query=property --path=/sys/bus/pci/devices/0000:02:00.0 | grep MODALIAS
```
优先用序列号、WWN、`ID_PATH` 和父设备属性，不要依赖可能变化的 `/dev/sdX` 或 Bus/Device 编号。
### 6.2 `udevadm monitor/test/trigger/settle`
```bash
sudo udevadm monitor --kernel --udev --property
sudo udevadm monitor --subsystem-match=block --udev
udevadm test /sys/class/block/sda
udevadm test --action=add /sys/class/net/eth0
udevadm test-builtin property /sys/class/block/sda
sudo udevadm control --reload-rules
sudo udevadm trigger --dry-run --subsystem-match=block
sudo udevadm trigger --subsystem-match=block
sudo udevadm settle --timeout=10
```
`KERNEL` 是原始事件，`UDEV` 是规则处理后的事件；`test` 计算规则但不执行 `RUN+=` 外部程序；`trigger` 重新发事件，`settle` 等待队列完成。先用 dry-run 再缩小范围。
::: warning trigger 会影响运行中的设备
重新触发可能改变权限、链接或 systemd 设备依赖；不要无范围地 trigger 所有生产设备，也不要在 `RUN+=` 中执行长任务。
:::
### 6.3 规则示例
```udev
# /etc/udev/rules.d/70-my-usb.rules
SUBSYSTEM=="usb", ATTR{idVendor}=="0781", ATTR{idProduct}=="5581", SYMLINK+="my-usb-disk"
```
```bash
sudo udevadm control --reload-rules
udevadm test /sys/bus/usb/devices/1-2 2>&1 | grep -E '70-my-usb|my-usb-disk'
```
常用匹配：`SUBSYSTEM==`、`KERNEL==`、`ATTR{}`、`ATTRS{}`、`ENV{}`、`DRIVERS==`；常用动作：`SYMLINK+=`、`TAG+=`。复杂工作应交给 systemd。

## 7. Namespace
### 7.1 类型与 `lsns`
| 类型 | 隔离内容 |
|---|---|
| mount/mnt | 挂载点树 |
| pid | PID 视图与容器内 PID 1 |
| net | 网卡、路由、端口 |
| user | UID/GID 与 capability |
| uts | hostname/domainname |
| ipc | SysV/POSIX IPC |
| cgroup | cgroup 视图 |
| time | monotonic/boottime 偏移 |
```bash
lsns
lsns -t net
lsns -p 1234
lsns -o NS,TYPE,PATH,NPROCS,PID,COMMAND
```
`NS` 是 namespace inode，`TYPE` 是类型，`PATH` 是 `/proc/PID/ns/TYPE`，`NPROCS` 是关联进程数；比较两个 PID 的同类型 inode，可判断是否共享视图。
### 7.2 `/proc/PID/ns/*` 与 `nsenter`
```bash
ls -l /proc/1234/ns
readlink /proc/1234/ns/pid
readlink /proc/1234/ns/mnt
readlink /proc/1234/ns/net
for ns in /proc/1234/ns/*; do printf '%-28s' "$ns"; readlink "$ns"; done
sudo nsenter -t 1234 -m -u -i -n -p -- ps -ef
sudo nsenter -t 1234 -n -- ip addr
sudo nsenter -t 1234 -m -- mount
```
预期标识：`net:[4026532456]`、`pid:[4026531836]`。`-m/-u/-i/-n/-p/-U/-C` 依次进入 mount、UTS、IPC、network、PID、user、cgroup；进入 PID 视图时常同时进入 mount，以匹配 `/proc`。
::: warning nsenter 不是只读工具
先运行 `ps`、`ip addr`、`mount`、`cat`；进入后执行 `ip link set`、`mount` 或防火墙命令会改变目标环境。
:::
### 7.3 `unshare` 与 `ip netns`
```bash
unshare --mount --fork sh
unshare --net --fork sh
unshare --user --map-root-user --mount-proc --fork sh
sudo ip netns list
sudo ip netns add demo
sudo ip netns exec demo ip link show
sudo ip netns exec demo ip link set lo up
sudo ip netns del demo
```
`--mount` 创建独立挂载视图，`--net` 创建只有 loopback 的网络视图，`--pid --fork` 让子进程成为新 PID 1，`--user --map-root-user` 在新 user namespace 内映射 root。`ip netns` 通常在 `/run/netns/NAME` 留下入口；只有 loopback 的 namespace 没有外网，需要 veth、路由和防火墙。

## 8. cgroup v2
### 8.1 判断版本与读取控制文件
```bash
stat -fc %T /sys/fs/cgroup
mount | grep cgroup
cat /sys/fs/cgroup/cgroup.controllers
cat /sys/fs/cgroup/cgroup.subtree_control
cat /sys/fs/cgroup/cgroup.procs
cat /sys/fs/cgroup/memory.current
cat /sys/fs/cgroup/memory.max
cat /sys/fs/cgroup/memory.events
cat /sys/fs/cgroup/cpu.stat
cat /sys/fs/cgroup/io.stat
```
预期输出：
```
cgroup2fs
cpuset cpu io memory hugetlb pids
8126464
max
oom 0
oom_kill 0
usage_usec 232001
```
`cgroup2fs`/单一 cgroup2 挂载是 v2 证据。`cgroup.procs` 是成员，`cgroup.controllers`/`subtree_control` 是控制器，`memory.current/max/events` 是用量/上限/OOM 事件，`cpu.stat` 是 CPU 统计，`io.stat` 是块 IO。
### 8.2 systemd cgroup 与 scope
```bash
systemd-cgls
systemd-cgls --all
systemd-cgtop
systemctl show nginx -p ControlGroup -p MemoryCurrent -p CPUUsageNSec
systemd-run --scope -p MemoryMax=512M -p CPUQuota=50% -- ./batch-job
systemctl show run-r12345.scope -p ControlGroup -p MemoryMax -p CPUQuotaPerSecUSec
```
`systemd-cgls` 看树，`systemd-cgtop` 按 cgroup 聚合，service/slice/scope 都映射到 cgroup；服务资源管理见 [服务管理与定时任务](/kb/os/Bash/12-服务管理与定时任务/)。
| 属性 | 含义 |
|---|---|
| `MemoryMax=512M` | 内存硬上限 |
| `CPUQuota=50%` | CPU 配额 |
| `TasksMax=100` | 任务数上限 |
::: warning MemoryMax 可能触发 OOM kill
超过硬上限时可能在该 cgroup 内杀进程；先看 `memory.current`/`memory.events`，生产优先使用可审计的 systemd drop-in。
:::
### 8.3 cgroup v1 历史
```bash
cgcreate -g memory,cpu:/demo
cgexec -g memory,cpu:/demo ./batch-job
cgdelete -g memory,cpu:/demo
```
这些 libcgroup 命令主要面向 v1；v1 控制器可分散在多个 hierarchy，v2 是统一 hierarchy：`memory.limit_in_bytes` 对应 `memory.max`，`cpu.cfs_quota_us` 对应 `cpu.max`。先确认 `cgroup2fs`，不要把 v1 命令直接套在 v2 上。

## 9. NUMA、CPU、电源与中断
### 9.1 `numactl`、`numastat`、CPU 亲和性
```bash
numactl --hardware
numactl --show
numactl --cpunodebind=0 --membind=0 ./worker
numactl --interleave=all ./batch-job
numastat
numastat -p 1234
lscpu -e=CPU,CORE,SOCKET,NODE,ONLINE
taskset -pc 1234
taskset -cp 0-3 1234
```
预期输出：
```
node 0 cpus: 0 1 2 3
node 1 cpus: 4 5 6 7
pid 1234's current affinity list: 0-7
```
`--cpunodebind` 绑定 CPU 节点，`--membind` 限制内存节点，`--interleave` 交错分配；`numastat -p` 看本地/远端分配；`taskset` 改进程 affinity，重启后消失。`membind` 可能因本地内存不足而失败。
### 9.2 `cpupower`、`turbostat`、`powertop`
```bash
cpupower frequency-info
cpupower monitor
cpupower idle-info
sudo cpupower frequency-set -g performance
sudo turbostat --interval 1 --quiet
sudo turbostat --interval 1 --show Bzy_MHz,TSC_MHz,Busy%,PkgWatt,C10%,IRQ
sudo powertop
sudo powertop --time=10 --html=/tmp/powertop.html
```
`frequency-info` 看驱动、策略和 governor，`monitor` 看频率，`idle-info` 看 C-state；`turbostat` 主要在 x86 看忙频率、参考频率、Busy%、功耗、C-state 和 IRQ；`powertop` 看唤醒源、设备和节能建议。
::: warning 慎用频率和节能写操作
`performance` 通常提高功耗和温度；`powertop --auto-tune` 会改变 USB autosuspend/设备电源策略，可能损害低延迟和外设稳定性。先保存现状并测试。
:::
### 9.3 `irqbalance`、`/proc/interrupts`、`irqtop`
```bash
systemctl is-active irqbalance
systemctl status irqbalance
cat /proc/interrupts
watch -n 1 'grep -E "eth|nvme|mlx" /proc/interrupts'
sudo irqtop
```
预期输出：
```
           CPU0 CPU1 CPU2 CPU3
24:        1024  980 45000  998 PCI-MSI eth0
41:           0    0  1200    0 PCI-MSI nvme0q0
```
表头是逻辑 CPU，行首是 IRQ 号，中间是累计计数，末尾是设备/队列；连续采样看增量。`irqbalance` 会分散中断，手工 IRQ affinity/RPS/XPS 需要明确替代方案；`irqtop` 非默认，缺失时可用 `watch` 对比 `/proc/interrupts`。

## 10. 完整案例：内核参数、模块与硬件故障
### 10.1 症状与基线
**症状**：数据库节点偶发 IO 延迟升高，随后网卡短暂掉线，重启后恢复，高负载时复发。假设分三类：NVMe/PCIe 硬件或链路；网卡/存储驱动与固件；cgroup、NUMA、IRQ 或电源策略。参数调优不能替代硬件证据。
```bash
date -Is
uname -a
cat /proc/cmdline
lsmod > /tmp/incident.lsmod
sysctl -a 2>/dev/null | grep -E '^(vm|fs|kernel|net)\.' > /tmp/incident.sysctl
lspci -nnk > /tmp/incident.lspci
lsblk -o NAME,PATH,SIZE,TYPE,FSTYPE,UUID,MODEL,SERIAL,MOUNTPOINTS > /tmp/incident.lsblk
```
先保存状态再卸载模块或改参数；序列号、UUID 和主机名外发前脱敏。
### 10.2 对齐日志并确认设备
```bash
sudo dmesg -T -l err,warn
journalctl -k --since '2 hours ago' -p warning --no-pager
journalctl -k -b -1 -p err --no-pager
lspci -s 02:00.0 -nnk
lspci -s 03:00.0 -vv
modinfo igb | grep -E '^(filename|version|vermagic|firmware|depends):'
modinfo nvme | grep -E '^(filename|version|vermagic|firmware|depends):'
ls -l /sys/bus/pci/devices/0000:02:00.0/driver
```
假设日志为：
```
nvme nvme0: I/O 23 QID 4 timeout, aborting
nvme nvme0: resetting controller
igb 0000:02:00.0: NETDEV WATCHDOG: transmit queue 0 timed out
```
NVMe timeout 先于网卡 watchdog，继续查 PCIe/电源/硬件；若先有 AER 或固件错误，硬件优先。`Kernel driver in use` 才是当前绑定证据，`modinfo` 核对模块与 `uname -r`。
### 10.3 检查参数、链路、中断、资源
```bash
sudo dmesg -T | grep -iE 'igb|nvme|firmware|taint|unknown symbol|invalid module'
grep -R --line-number -E '^(options|blacklist|softdep)' /etc/modprobe.d/
lspci -vv -s 03:00.0 | grep -E 'LnkSta|AER|Error|ASPM|Power Management'
grep -E 'nvme|igb|PCI-MSI' /proc/interrupts
systemctl is-active irqbalance
systemd-cgtop
systemctl show postgresql -p ControlGroup -p MemoryCurrent -p MemoryMax
cat /sys/fs/cgroup/system.slice/postgresql.service/memory.events
numastat -p "$(pidof postgres | awk '{print $1}')"
lscpu -e=CPU,CORE,SOCKET,NODE,ONLINE
sudo turbostat --interval 1 --quiet
```
若 `LnkSta` 低于 `LnkCap` 且 AER 增长，优先查槽位、固件、背板和硬件；若 IRQ 集中在单核，再审查 irqbalance/affinity；若 `oom_kill` 增长，说明 cgroup 内存压力可解释服务被杀，但不能解释 PCIe AER；低 `Bzy_MHz` 与高温则指向降频。
### 10.4 最小变更与回滚
```bash
sysctl -n vm.swappiness > /tmp/swappiness.old
sudo sysctl -w vm.swappiness=10
# 验证后回滚
sudo sysctl -w vm.swappiness="$(cat /tmp/swappiness.old)"
```
低风险优先升级匹配的内核/驱动/固件、检查连接、恢复合理 IRQ/NUMA 策略。验证前后状态：
```bash
sysctl -a 2>/dev/null | grep -E '^(vm|fs|kernel|net)\.' > /tmp/incident.after.sysctl
lsmod > /tmp/incident.after.lsmod
journalctl -k --since '10 min ago' --no-pager
diff -u /tmp/incident.sysctl /tmp/incident.after.sysctl
```
观察 IO timeout、AER、网络重传、IRQ 分布、P99 和重启后加载结果。不要把 `rmmod nvme`、`rmmod igb`、`kernel.modules_disabled=1`、`vm.drop_caches=3` 或强制卸载当作常规修复。

## 11. 命令选择闭环
| 症状 | 首先执行 | 深挖 |
|---|---|---|
| 启动卡住 | `uname`、`/proc/cmdline`、`dmesg`、`journalctl -k -b -1` | GRUB、initramfs、驱动、kdump |
| 设备不见 | `lspci`/`lsusb`、`lsblk`、`udevadm monitor` | 总线事件、规则、驱动、固件 |
| 驱动没加载 | `lspci -k`、`modinfo`、`modprobe -n -v` | alias、依赖、黑名单、签名 |
| IO timeout | `lsblk`、`lspci -vv`、`dmesg`、`/proc/interrupts` | AER、链路、IRQ、盘固件 |
| 内存不足 | `free`、`vmstat`、`sysctl vm.*`、`memory.events` | swap、OOM、泄漏、限制 |
| 容器视图异常 | `lsns`、`nsenter`、`readlink /proc/PID/ns/*` | namespace、capability、设备权限 |
| 服务超限 | `systemd-cgls`、`systemd-cgtop`、`systemctl show` | MemoryMax、CPUQuota、TasksMax |
| CPU 延迟抖动 | `lscpu -e`、`numastat`、`/proc/interrupts`、`turbostat` | NUMA、IRQ、频率、电源 |
```text
现象 -> 时间窗口 -> 内核/启动输入 -> 设备/驱动 -> 日志/事件增量
     -> namespace/cgroup/NUMA 上下文 -> 最小变更 -> 指标验证 -> 回滚/持久化
```

## 本章小结
- `sysctl -a` 枚举，`-w` 临时写，`-p` 读指定文件，`--system` 按系统目录加载；持久配置优先拆到 `/etc/sysctl.d/*.conf`，不要盲调 `vm`、`fs`、`kernel`、`net`。
- 模块链路是 `.ko` → `depmod` 索引 → alias/依赖 → `modprobe`；`insmod` 只插指定文件，`rmmod` 直接卸载，`modprobe -r` 处理依赖；`/proc/modules` 是 `lsmod` 的底层来源。
- `uname`、`/boot`、`/proc/cmdline` 看当前内核和启动输入；`dmesg -T/-w/-l` 看现场，`journalctl -k` 按启动和时间回放。
- `lscpu`/`lsmem` 看 CPU/内存布局，`lshw`/`hwinfo`/`inxi` 做总览，`dmidecode` 看固件，`lspci`/`lsusb` 看总线与驱动，`lsscsi`/`lsblk` 看存储，`hwclock` 看 RTC。
- udev 顺序是属性 → monitor → test → 小范围 trigger → settle；namespace 隔离视图，cgroup v2 限制和统计资源。
- NUMA、IRQ 和电源问题要同时看拓扑、远端分配、计数增量、频率和 C-state。变更遵循“基线、最小修改、指标验证、回滚、重启复核”。

## 动手实验
1. **sysctl 临时/持久**：记录 `sysctl vm.swappiness`，临时改为 10 后恢复；创建 `/etc/sysctl.d/60-lab.conf`，运行 `sudo sysctl --system`，删除并验证回滚。
2. **模块依赖**：运行 `modprobe -n -v ext4` 和 `modprobe --show-depends ext4`；只在测试机对无使用者模块执行加载与 `modprobe -r`。
3. **内核盘点**：执行 `uname -a`、`ls -lh /boot`、`cat /proc/cmdline`，标出 `vmlinuz`、`initrd`、`root=`、`quiet`、`crashkernel`。
4. **设备属性**：选网卡或 USB 盘，使用 `lspci -nnk`/`lsusb -t`、`udevadm info --query=property` 找 ID、驱动和 modalias。
5. **udev 事件**：运行 `sudo udevadm monitor --kernel --udev --property`，插拔测试设备；对事件路径运行 `udevadm test`，再用 `trigger --dry-run`。
6. **namespace**：运行 `unshare --user --map-root-user --pid --mount-proc --fork sh`，比较 `id`、`ps` 和 `readlink /proc/self/ns/pid`，退出后确认宿主不变。
7. **网络 namespace**：用 `ip netns add`、veth、地址和 `ping` 建立最小拓扑，用 `lsns -t net` 对照，最后清理。
8. **cgroup v2**：运行 `systemd-cgls`、`systemd-cgtop`，用 `systemd-run --scope -p MemoryMax=256M` 运行测试程序，观察 `memory.events`。
9. **NUMA/IRQ**：执行 `numactl --hardware`、`numastat`、`lscpu -e`，间隔 1 秒读取 `/proc/interrupts`，比较网卡/NVMe IRQ 增量。
10. **电源**：运行 `cpupower frequency-info`、`turbostat`、`powertop`，比较空闲与负载时频率、C-state、功耗；不要执行 `powertop --auto-tune`。

## 自测题
1. **`sysctl -w` 和 `/etc/sysctl.d` 的区别？** 前者通常只改当前内核，后者启动时加载并持久化。
2. **`sysctl -p` 和 `--system` 的区别？** `-p FILE` 读指定文件，`--system` 按系统约定读取多个目录和兼容入口。
3. **`insmod` 和 `modprobe` 的核心差别？** `insmod` 直接插文件，不处理依赖/alias；`modprobe` 按索引、配置和依赖加载。
4. **`Kernel modules` 与 `Kernel driver in use` 哪个证明已绑定？** 后者；前者只是候选模块。
5. **`dmesg -T` 为什么时间只是近似？** 它把启动以来时间戳按当前系统时间换算，时钟校正会产生偏差。
6. **`dmesg` 和 `journalctl -k` 分工？** 前者看当前环形缓冲区和实时事件，后者按启动/时间查询已保存日志。
7. **udev 排障为什么先看属性？** 规则匹配真实 sysfs/环境属性，稳定属性比设备编号可靠。
8. **namespace 与 cgroup 的边界？** namespace 隔离可见视图，cgroup 限制并统计资源。
9. **`memory.current`、`memory.max`、`memory.events` 是什么？** 当前用量、硬上限、压力与 OOM 事件计数。
10. **为什么 cgroup v1 命令可能不能用于现代系统？** v1 是多 hierarchy，v2 是统一 hierarchy；先确认 `cgroup2fs`。
11. **`numa_miss` 增长能直接证明 bug 吗？** 不能，还要结合绑定策略、远端延迟和业务指标。
12. **停用 irqbalance 前要确认什么？** 手工 affinity/RPS/XPS 的替代方案、持久化方式和单核热点证据。
13. **为什么案例不先卸载驱动或调 sysctl？** 先建立硬件、驱动、日志和资源证据，避免扩大故障或破坏现场。

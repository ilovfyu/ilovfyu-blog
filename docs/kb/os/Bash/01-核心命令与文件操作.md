::: abstract 本章定位
这是 Bash 的第一篇：把"文件系统里的东西到底长什么样"变成一套每天必用的命令肌肉记忆。从目录导航（`pwd`/`cd`/`ls`）、路径拆解与规范化，到文件的新建查看、复制移动删除、切分改名、查找定位，再到类型统计与基础文本处理。不追求花哨，只求**不看手册也能顺手敲出来**。进阶内容（管道深入、三剑客）见 [Bash命令学习路线总览](/kb/os/Bash/00-Bash命令学习路线总览/)，文件系统原理见 [Linux 文件实操](/kb/os/Linux/03-Linux文件系统与磁盘实操/)。
:::

## 1. 目录与导航
### 1.1 `pwd`：我在哪
```bash
pwd
```
预期输出：
```
/home/zhang/work/notes
```
解读：
- **p**rint **w**orking **d**irectory，打印当前所在目录的绝对路径。
- 对比 `echo $PWD`：`pwd` 是 shell 内建，沿符号链接走时显示链接路径；`pwd -P` 显示物理真实路径。

### 1.2 `cd`：去哪
```bash
cd -            # 回到上一个所在目录（来回切换的神器）
cd ~            # 回家目录
cd ~root        # 去 root 用户的家目录
cd ..           # 上一级
cd /etc         # 绝对路径
```

| 写法 | 含义 | 示例 |
| --- | --- | --- |
| `cd` | 回家目录（同 `cd ~`） | 任意位置回 `$HOME` |
| `cd -` | 回到上一次所在目录 | 两个目录间反复横跳 |
| `cd ~` | 回当前用户家目录 | 等价于 `cd $HOME` |
| `cd ~user` | 进指定用户家目录 | `cd ~ftp` |
| `cd ..` / `cd ../..` | 上一级 / 上两级 | 层层向上 |

解读：`cd -` 依赖 `$OLDPWD`，是两个目录间高频切换的利器。权限不足报 `Permission denied`；目录不存在报 `No such file or directory`。

### 1.3 `ls`：列出内容
```bash
ls -la        # 长格式 + 隐藏文件
ls -lh        # 人类可读大小
ls -lt / ls -lS    # 按时间 / 大小排序
ls *.md       # 通配符匹配
```
预期输出（`ls -lh`）：
```
total 56K
drwxr-xr-x 2 zhang zhang 4.0K Aug 10 10:00 notes
-rw-r--r-- 1 zhang zhang  12K Aug 10 09:30 report.md
-rw-r--r-- 1 zhang zhang 2.1K Aug  9 22:01 todo.txt
```

| 参数 | 含义 | 说明 |
| --- | --- | --- |
| `-l` | long 长格式 | 权限/链接数/属主/属组/大小/时间 |
| `-a` | all | 显示以 `.` 开头的隐藏文件 |
| `-h` | human-readable | 大小按 K/M/G 显示，须配 `-l` |
| `-t` | 按修改时间排序 | 最新在前，常用 `-lt` |
| `-S` | 按文件大小排序 | 最大在前 |
| `-i` | inode | 显示 inode 号（配合 ln 使用） |
| `*` 通配符 | 匹配任意字符序列 | `*.md` 匹配全部 md 文件 |

**`ls -l` 各列逐列解读**（以 `-rw-r--r-- 1 zhang zhang 12K Aug 10 09:30 report.md` 为例）：

| 位置 | 值 | 含义 |
| --- | --- | --- |
| 第 1 字符 | `-` | 文件类型：`-` 普通、`d` 目录、`l` 软链接、`c` 字符设备、`b` 块设备、`p` 管道 |
| 2-4 字符 | `rw-` | 属主（user）权限：读/写/执行 |
| 5-7 字符 | `r--` | 属组（group）权限 |
| 8-10 字符 | `r--` | 其他用户（other）权限 |
| 硬链接数 | `1` | 指向该 inode 的链接数（目录至少 2） |
| 属主 | `zhang` | owner |
| 属组 | `zhang` | group |
| 大小 | `12K` | 字节数（`-h` 后人类可读） |
| 修改时间 | `Aug 10 09:30` | mtime（内容最后修改时刻） |
| 文件名 | `report.md` | 以 `.` 开头为隐藏文件 |

### 1.4 `tree`：目录树
```bash
tree -L 2 /etc/nginx
```
预期输出（片段）：
```
/etc/nginx
├── nginx.conf
└── conf.d
    ├── default.conf
    └── ssl.conf
```
解读：用缩进树状展示层级，`-L 2` 限深度 2 层，`-d` 只看目录，`-h` 显示大小。精简系统可能未装，`apt install tree` / `yum install tree` 即可。

### 1.5 `alias ll`：给自己造命令
```bash
alias ll='ls -lh'
alias la='ls -la'
alias lt='ls -lt'
```
解读：别名只在当前 shell 会话生效，要长期使用写入 `~/.bashrc`。查看已有别名 `alias`；绕过别名执行原命令 `\ls` 或 `command ls`。

### 1.6 `basename`：从路径取最后一段

**用途**：删除路径中的目录部分，只保留文件名；它做的是字符串处理，目标不必真实存在。

**常用参数**：

| 参数/写法 | 作用 | 兼容性 |
| --- | --- | --- |
| `basename PATH` | 取路径最后一段 | POSIX，Linux/macOS 通用 |
| `basename PATH SUFFIX` | 顺便删除指定后缀 | POSIX |
| `-s SUFFIX` | 删除后缀 | GNU 常用；BSD/macOS 支持情况随版本而异 |
| `-a` | 处理多个路径 | GNU 扩展 |

**可运行示例**：

```bash
basename /srv/app/config.yaml
basename /srv/app/config.yaml .yaml
```

预期输出：

```text
config.yaml
config
```

**结果解读**：第一条仅去掉 `/srv/app/`，第二条再去掉精确后缀 `.yaml`。脚本中常用 `name=$(basename -- "$path")` 得到归档名。

**易错点**：`basename` 不检查文件是否存在，也不等同于“扩展名解析”；`archive.tar.gz` 删除 `.gz` 后仍是 `archive.tar`。GNU 的 `--` 可保护以 `-` 开头的路径，追求 POSIX 可移植性时可写 `basename "./$name"`。

### 1.7 `dirname`：从路径取目录部分

**用途**：删除路径最后一段，得到父路径字符串；常用于按脚本位置寻找相邻资源。

**常用参数**：日常只有 `dirname PATH`；GNU 版支持多个操作数和 `-z`（NUL 结尾），POSIX/BSD 版通常一次处理一个路径。

**可运行示例**：

```bash
dirname /srv/app/config.yaml
dirname relative/file.txt
dirname file.txt
```

预期输出：

```text
/srv/app
relative
.
```

**结果解读**：不含斜杠的 `file.txt` 其目录部分是当前目录 `.`。与 `basename` 组合即可拆开路径，但二者都只处理字符串。

**易错点**：`dirname "$0"` 得到的是调用时写下的脚本路径，可能仍是相对路径或符号链接；需要脚本真实目录时还要结合 `realpath`，Bash 被 `source` 的文件则优先使用 `${BASH_SOURCE[0]}`，详见 [Shell脚本编程进阶](/kb/os/Bash/08-Shell脚本编程进阶/)。

### 1.8 `realpath`：规范化为绝对路径

**用途**：解析 `.`、`..` 和符号链接，输出规范化绝对路径；适合脚本定位资源、日志中记录唯一形式的路径。

**常用参数**（GNU coreutils）：

| 参数 | 作用 |
| --- | --- |
| `-e` | 每一段都必须存在（GNU 默认行为） |
| `-m` | 即使部分路径不存在也规范化 |
| `--relative-to=DIR` | 输出相对 DIR 的路径 |
| `-s` | 只规范化字符串，不展开符号链接 |

**可运行示例**：

```bash
mkdir -p /tmp/path-lab/real
ln -s real /tmp/path-lab/link
realpath /tmp/path-lab/link/../link
realpath --relative-to=/tmp /tmp/path-lab/real
```

GNU/Linux 预期输出：

```text
/tmp/path-lab/real
path-lab/real
```

**结果解读**：第一条先展开 `link -> real` 再规范化；第二条把绝对路径改写成相对 `/tmp` 的路径。

**易错点**：GNU 与 BSD/macOS 的参数不统一，部分旧版 macOS 甚至没有系统自带 `realpath`；安装 GNU coreutils 后使用 `grealpath`。路径不存在时 GNU 默认失败，确实要处理“未来路径”才用 `-m`，不要把失败静默当成路径有效。

### 1.9 `readlink`：读取链接目标与获取真实路径

**用途**：不跟随符号链接，直接打印链接中保存的目标字符串；GNU `readlink -f` 还能递归解析为规范化绝对路径。

**常用参数**：

| 参数 | 作用 | 兼容性 |
| --- | --- | --- |
| 无参数 | 输出符号链接保存的目标 | Linux/macOS 通用 |
| `-f` | 所有链接递归解析，路径各段须存在（最后一段可不存在） | GNU/Linux 常用，macOS BSD 版没有 |
| `-e` | 所有路径段（含最后一段）都须存在 | GNU |
| `-m` | 路径不存在也尽量规范化 | GNU |

**可运行示例**：

```bash
mkdir -p /tmp/link-lab/target
ln -s target /tmp/link-lab/current
readlink /tmp/link-lab/current
readlink -f /tmp/link-lab/current
```

GNU/Linux 预期输出：

```text
target
/tmp/link-lab/target
```

**结果解读**：第一条显示链接里原样保存的相对目标 `target`；`-f` 把它相对链接所在目录解析成最终绝对路径。

**易错点**：`readlink link` 与 `realpath link` 语义不同，前者看“链接写了什么”，后者看“最终落到哪里”。macOS 不支持 `readlink -f`，可用 `realpath`（若系统提供）或 Homebrew coreutils 的 `greadlink -f`，脚本里不要假设 `-f` 跨平台可用。

## 2. 文件查看与创建
### 2.1 `cat` / `tac`：正读与倒读
```bash
cat /etc/hostname
tac /etc/passwd      # cat 反写：按行倒序输出
```
解读：`cat` 把文件内容顺序输出到 stdout，`cat file1 file2` 可拼接多文件；`cat` 无参数时读 stdin，等 Ctrl+D 结束。

### 2.2 `head` / `tail`：看头看尾

```bash
head -n 5 /etc/passwd     # 前 5 行
tail -n 3 /etc/passwd     # 后 3 行
tail -f /var/log/syslog   # 实时跟踪追加内容
```

| 命令 | 默认 | 常用参数 | 场景 |
| --- | --- | --- | --- |
| `head` | 前 10 行 | `-n 20`；`-c 100` 前 100 字节 | 看配置、文件开头 |
| `tail` | 后 10 行 | `-n 3`；`-f` 跟随；`-F` 日志轮转后仍有效 | 看日志末尾、实时监控 |

解读：`tail -f` 是排障标配；`tail -F` 更强，日志被 `logrotate` 改名重建后仍能继续跟踪。`tail -n +20` 表示从第 20 行看到结尾。

### 2.3 `less`：翻页阅读器
```bash
less /var/log/messages
```

| 按键 | 功能 |
| --- | --- |
| `空格` / `f` | 下一页 |
| `b` | 上一页 |
| `j` / `k` | 向下 / 向上滚动一行 |
| `/pattern` | 向下搜索，`n` 下一个，`N` 上一个 |
| `g` / `G` | 跳到第一行 / 最后一行 |
| `q` | 退出 |

解读：文件再大也瞬间打开——`less` 只读需要的部分进内存，是大日志首选。还能接管道：`dmesg | less`，让长输出不刷屏。

### 2.4 `touch`：建文件还是改时间
```bash
touch newfile.txt                   # 不存在则创建空文件
touch -d '2024-01-01 10:00' old.txt # 把时间改成指定时刻
```
解读：`touch` 本职是**把 atime/mtime 更新为当前时间**；文件不存在时顺手创建空文件——这是它被当"建文件命令"用的原因。`-a` 只改 atime，`-m` 只改 mtime，改完可用 `stat` 验证。

### 2.5 `truncate`：精确设置文件长度

**用途**：把文件扩展或缩短到指定字节数，常用于快速清空日志、制造固定大小测试文件和调整镜像文件。

**常用参数**（GNU coreutils）：

| 参数 | 作用 |
| --- | --- |
| `-s SIZE` | 设置大小，如 `0`、`1K`、`10M`、`+1M`、`-512K` |
| `-c` | 文件不存在时不要创建 |
| `-r FILE` | 令目标大小与参考文件相同 |

**可运行示例**：

```bash
printf 'abcdef\n' > /tmp/truncate-demo.txt
truncate -s 3 /tmp/truncate-demo.txt
wc -c /tmp/truncate-demo.txt
truncate -s 1M /tmp/sparse-demo.img
du -h /tmp/sparse-demo.img; ls -lh /tmp/sparse-demo.img
```

预期结果：第一个 `wc` 输出 `3`；稀疏文件的 `ls -lh` 显示逻辑大小 `1.0M`，`du` 可能显示占用 `0`。

**结果解读**：缩短会永久丢弃尾部字节；向后扩展通常形成洞（hole），读取洞得到 `\0`，但未必实际占用对应磁盘块。

**易错点**：`truncate -s 0 logfile` 会瞬间清空文件，不能撤销；对正在写日志的进程，清空通常比 `rm` 更能保留原 fd。macOS 默认通常没有 GNU `truncate`，可用 `: > file` 清空，或安装 coreutils 后使用 `gtruncate`。

### 2.6 `mkfifo`：创建命名管道

**用途**：创建有文件名的 FIFO，让两个互不相关的进程通过字节流通信；与普通管道 `|` 不同，它能由两条独立命令分别打开。

**常用参数**：`-m MODE` 在创建时直接指定权限，例如 `mkfifo -m 600 path`；多个路径可一次创建多个 FIFO。

**可运行示例**：

```bash
fifo=/tmp/demo.fifo
rm -f -- "$fifo"
mkfifo -m 600 "$fifo"
(printf 'hello fifo\n' > "$fifo") &
cat "$fifo"
rm -f -- "$fifo"
```

预期输出：

```text
hello fifo
```

**结果解读**：后台写进程与 `cat` 读进程在 FIFO 两端会合；数据被读走后不会像普通文件那样留在磁盘里。

**易错点**：默认阻塞是 FIFO 的核心语义：只有写端没有读端（或反之）时，`open` 往往会等待。`mkfifo` 只创建入口，不启动消费者；脚本退出要用 `trap` 清理 FIFO。Linux 与 macOS 都有该 POSIX 命令。

### 2.7 `echo`：打印与写内容
```bash
echo "Hello, Linux"
echo -e "a\tb\nc"   # -e 解析转义
echo $PATH          # 打印变量值
echo -n "no newline"  # -n 不输出末尾换行
```
解读：`echo` 输出到 stdout，是脚本里最常用的"说话"工具，配合 `>` 重定向可快速写文件。双引号 `"$var"` 展开变量，单引号 `'$var'` 原样输出。

::: tip 可移植输出优先 `printf`
不同 shell 对 `echo -e`、反斜杠和以 `-n` 开头的内容处理并不完全一致。格式固定或数据来自变量时使用 `printf '%s\n' "$value"`，详细见 [高级命令与文本处理](/kb/os/Bash/09-高级命令与文本处理/)。
:::

### 2.8 `wc`：数一数
```bash
wc /etc/passwd        # 行数 单词数 字节数
wc -l file.txt        # 只数行 / -w 字数 / -c 字节数
```
预期输出（`wc /etc/passwd`）：
```
 35  100  3000 /etc/passwd
```
解读：三列依次是**行数、单词数、字节数**。`wc -l` 常配合管道：`ps aux | wc -l` 看进程数。

## 3. 复制移动删除
### 3.1 `mkdir`：创建目录

**用途**：创建一个或多个目录；配合 `-p` 一次建立完整父目录链，是部署和脚本初始化目录的标准命令。

**常用参数**：

| 参数 | 作用 |
| --- | --- |
| `-p` | 父目录不存在就一并创建；目标已存在也不报错 |
| `-m MODE` | 创建时直接指定权限，如 `700` |
| `-v` | 打印实际创建的目录（GNU/BSD 均常见） |

**可运行示例**：

```bash
mkdir -p /tmp/mkdir-demo/{conf,log,run}
mkdir -m 700 /tmp/mkdir-demo/private
ls -ld /tmp/mkdir-demo/private
```

预期结果：前三个子目录一次建好，`private` 权限显示为 `drwx------`（实际还受系统特殊 ACL 等因素影响）。

**结果解读**：大括号展开先生成三个参数，再由 `mkdir -p` 创建；`-p` 让重复执行具备幂等性。

**易错点**：`mkdir a/b` 在 `a` 不存在时失败，脚本初始化通常应写 `mkdir -p -- "$dir"`。`-m` 的最终权限处理在不同系统上可能受默认 ACL 影响；涉及敏感目录时创建后再用 `stat`/`ls -ld` 验证。

### 3.2 `rmdir`：只删除空目录

**用途**：删除空目录；比 `rm -r` 更保守，目录内还有内容时会拒绝。

**常用参数**：`-p` 删除目标后继续删除变空的父目录；GNU 的 `--ignore-fail-on-non-empty` 可忽略“非空”失败，macOS BSD 版没有该长选项。

**可运行示例**：

```bash
mkdir -p /tmp/rmdir-demo/a/b
rmdir -p /tmp/rmdir-demo/a/b
test ! -e /tmp/rmdir-demo && printf '目录链已删除\n'
```

预期输出：`目录链已删除`。

**结果解读**：`b` 删除后 `a` 为空，`-p` 继续向上删除，直到参数路径中的父级 `/tmp/rmdir-demo`。

**易错点**：`rmdir` 不能删非空目录，这是保护而非缺陷。不要为了省事立刻换成 `rm -rf`；先 `ls -la -- "$dir"` 查明残留内容。

### 3.3 `cp`：复制
```bash
cp report.md backup.md            # 复制并改名
cp -r notes/ notes_copy/          # 递归复制目录
cp -p report.md keep_perms.md     # 保留权限与时间戳
cp -a project/ archive/           # 归档模式（保留一切属性）
cp -u *.c src/                    # 只覆盖更新的源文件
```

| 参数 | 含义 | 典型场景 |
| --- | --- | --- |
| `-r` | recursive，递归复制目录 | 备份目录树 |
| `-p` | preserve，保留权限/属主/时间戳 | 迁移配置 |
| `-a` | archive，保留一切属性 | 完整备份目录 |
| `-u` | update，仅当源更新时才覆盖 | 增量同步 |
| `-i` | interactive，覆盖前询问 | 防止误覆盖 |

解读：默认 `cp` 到已存在文件**直接覆盖**无提示，保险做法 `alias cp='cp -i'`。`cp -a` 连硬链接、权限、时间都保留，比 `cp -r` 更保险。`cp -u` 是"只补最新文件过去"的迷你版 `rsync`。

### 3.4 `mv`：移动与重命名
```bash
mv a.txt b.txt        # 重命名
mv b.txt notes/       # 移动到目录
mv notes/*.log /var/log/bak/
```
解读：`mv` 是"同一文件系统内改路径名"或"跨文件系统复制后删除"。目标是目录就移动，目标是文件名就是改名。也有 `-i` 覆盖询问、`-u` 只移动更新的版本。

::: warning 移动也可能覆盖
`mv` 覆盖同名目标通常无法撤销。交互操作可先用 `mv -i -- source target`；脚本中应显式检查目标、使用唯一名称或 GNU `mv -n`。macOS/BSD 虽常支持 `-n`，但 `-n/-f/-i` 同时出现时的优先级有实现差异，不要混写。
:::

### 3.5 `rm`：删除与误删风险
```bash
rm file.txt           # 删普通文件
rm -r notes/          # 递归删目录（危险）
rm -f *.tmp           # 强制删除，不提示
rm -i *.log           # 每个都问 y/n
rm -rf notes/         # 递归+强制：最危险组合
```

| 参数 | 含义 | 危险度 |
| --- | --- | --- |
| `-r` | 递归删除目录 | 高 |
| `-f` | force，忽略不存在且不询问 | 高 |
| `-i` | 逐个确认 | 低 |
| `-rf` 组合 | 静默递归删除一切 | 极高 |

::: warning 误删没有后悔药
`rm` 删除不经过回收站，目录项直接移除。三条铁律：① 慎用 `rm -rf`；② 绝不要写 `rm -rf /` 或 `rm -rf ~`；③ 危险命令前先 `printf '%q\n'`/`ls` 确认展开后的路径。参数来自变量时写 `rm -rf -- "$dir"`，并先校验非空、目录范围和预期前缀。GNU `rm` 有 `--one-file-system`、`--preserve-root` 等保护，BSD/macOS 参数较少，跨平台脚本不能依赖这些 GNU 保护。替代方案：先 `mv` 到隔离目录，确认后延迟删除。
:::

### 3.6 `ln`：硬链接与软链接
```bash
ln a.txt hard_a            # 硬链接
ln -s a.txt soft_a         # 软链接（符号链接）
ls -li a.txt hard_a soft_a # -i 观察 inode
```
预期输出：
```
1234567 -rw-r--r-- 2 zhang zhang 120 Aug 10 10:00 a.txt
1234567 -rw-r--r-- 2 zhang zhang 120 Aug 10 10:00 hard_a
1234568 lrwxrwxrwx 1 zhang zhang   5 Aug 10 10:01 soft_a -> a.txt
```

| 特性 | 硬链接 | 软链接 |
| --- | --- | --- |
| inode | 与原文件**相同** | **不同**（独立 inode） |
| 是否可指向目录 | 否 | 是 |
| 是否可跨文件系统 | 否 | 是 |
| 原文件删除后 | 链接仍有效，数据还在 | 链接失效（悬空/红链） |
| 本质 | 多个目录项指向同一 inode | 存了目标路径字符串 |

解读：观察 `ls -li` 第一列：`a.txt` 与 `hard_a` 的 inode 相同（1234567），链接数变 2；`soft_a` 是独立 inode，类型为 `l`，指向 `a.txt`。**硬链接数**本质是"有几个目录项指着这个 inode"。文件系统原理见 [Linux 文件实操](/kb/os/Linux/03-Linux文件系统与磁盘实操/)。删除软链接明确写 `rm -- soft_a`，不要在链接名后加 `/`；尾随斜杠会把参数解释为目录路径，各系统和命令的跟随行为不一，容易误操作目标目录。

### 3.7 `install`：复制 + 设权限一步到位
```bash
install -m 755 -o root -g root myscript.sh /usr/local/bin/
install -d /opt/app/logs    # -d 创建目录
```
解读：相比 `cp` 后还得 `chmod`/`chown`，`install` 一条命令完成"复制 + 权限校正"，是打包部署脚本的首选。

### 3.8 `split`：按行数或字节数等量切文件

**用途**：把大文件按固定行数或固定大小切成连续小文件，便于并行处理、传输或满足上传大小限制。

**常用参数**：

| 参数 | 作用 |
| --- | --- |
| `-l N` | 每个输出 N 行 |
| `-b SIZE` | 每个输出固定字节数，如 `100M` |
| `-d` | 使用数字后缀而非 `aa`、`ab`（GNU/BSD 常见） |
| `-a N` | 后缀宽度 N |
| `--additional-suffix=SUFFIX` | 再附加扩展名（GNU） |

**可运行示例**：

```bash
seq 1 7 > /tmp/split-input.txt
split -l 3 -d -a 2 /tmp/split-input.txt /tmp/part-
wc -l /tmp/part-00 /tmp/part-01 /tmp/part-02
cat /tmp/part-* > /tmp/split-joined.txt
cmp /tmp/split-input.txt /tmp/split-joined.txt && printf '重组一致\n'
```

预期结果：三个分片分别为 3、3、1 行，并输出 `重组一致`。

**结果解读**：最后一个参数是输出前缀，不是目录；分片名按 `/tmp/part-00`、`01`、`02` 递增。按文件名顺序 `cat` 即可无损重组。

**易错点**：重复执行会覆盖同名前缀分片，却不会自动删除上次多出来的旧分片，重组前应使用新的空目录。GNU `--additional-suffix`、`-n l/N` 等高级均分模式在 macOS BSD 版不可用；跨平台优先使用 `-l/-b/-a`。

### 3.9 `csplit`：按内容边界切文件

**用途**：依据行号或正则匹配位置切分文件，适合按章节标题、日志日期、记录分隔线拆分；与固定大小的 `split` 互补。

**常用参数**：

| 参数/操作数 | 作用 |
| --- | --- |
| `-f PREFIX` | 指定输出前缀 |
| `-n N` | 数字后缀宽度 |
| `-s` | 不打印每个分片的字节数 |
| `/REGEX/` | 在匹配行之前切开，该行进入新分片 |
| `{N}` / `{*}` | 重复前一个模式 N 次 / 直到文件末尾（`{*}` 常见于 GNU/BSD） |

**可运行示例**：

```bash
printf '第一节\n内容 A\n第二节\n内容 B\n第三节\n内容 C\n' > /tmp/chapters.txt
csplit -s -f /tmp/chapter- -n 2 /tmp/chapters.txt '/^第二节$/' '/^第三节$/'
for f in /tmp/chapter-??; do printf '%s: ' "$f"; head -n 1 "$f"; done
```

预期输出：

```text
/tmp/chapter-00: 第一节
/tmp/chapter-01: 第二节
/tmp/chapter-02: 第三节
```

**结果解读**：模式命中的标题行属于下一个文件，所以正好按章节切开；不加 `-s` 时 `csplit` 会向 stdout 打印各分片字节数。

**易错点**：若模式没找到，`csplit` 返回非 0，并默认删除本次已创建的分片；GNU `-k` 可在失败时保留。正则是基础正则，不要直接套 PCRE；GNU 与 BSD/macOS 的 `-b` 格式、重复模式细节有差异，跨平台先用小样本验证。

### 3.10 `rename`：批量重命名（先识别版本）

**用途**：按规则一次改多个文件名；Linux 上至少有 util-linux 版和 Perl 版两种不兼容实现，macOS 默认通常没有该命令。

**常用参数/语法**：

| 实现 | 语法 | 常见参数 |
| --- | --- | --- |
| util-linux | `rename FROM TO FILE...` | `-n` 预演、`-v` 显示改名 |
| Perl rename（Debian 常见） | `rename 's/REGEX/REPL/' FILE...` | `-n` 预演、`-v` 显示、`-f` 覆盖 |

**可运行示例**（先执行 `rename --version` 或查看 `man rename` 确认实现）：

```bash
mkdir -p /tmp/rename-demo
touch /tmp/rename-demo/report-draft-{1,2}.txt

# util-linux 版：把第一个 draft 子串换成 final
rename -n -v draft final /tmp/rename-demo/*draft*.txt

# Perl 版：同样先 -n 预演
rename -n -v 's/draft/final/' /tmp/rename-demo/*draft*.txt
```

预演结果应显示 `report-draft-1.txt` 将改为 `report-final-1.txt` 等，但不真正改名；去掉 `-n` 才执行。

**结果解读**：util-linux 版做简单子串替换；Perl 版执行 Perl 正则表达式，可写 `s/\.jpeg$/.jpg/i` 等复杂规则。两者命令同名，参数却不能互换。

::: warning 批量改名先预演
glob 会在 `rename` 启动前展开，规则写错可能同时毁掉成百上千个名字，重名目标还可能被跳过或覆盖。务必在副本/测试目录运行 `-n -v`，核对输入列表与目标名后再去掉 `-n`。macOS 可通过 Homebrew 安装 Perl rename，但包名和命令名可能是 `rename`/`perl-rename`；可移植脚本更适合用带引号的 `for` + `mv -i` 明确处理冲突。
:::

### 3.11 `shred`：覆写后删除敏感文件

**用途**：多次覆写普通文件的数据块，可选最后删除，降低传统旋转磁盘上从原数据块恢复内容的概率。

**常用参数**（GNU coreutils）：

| 参数 | 作用 |
| --- | --- |
| `-n N` | 随机覆写 N 次（默认 3） |
| `-z` | 最后再覆写一遍零，弱化“被擦除”痕迹 |
| `-u` | 覆写后删除文件名 |
| `-v` | 显示进度 |

**可运行示例**（只在临时实验文件上执行）：

```bash
printf 'temporary secret\n' > /tmp/shred-demo.txt
shred -n 1 -z -u -v /tmp/shred-demo.txt
test ! -e /tmp/shred-demo.txt && printf '文件名已移除\n'
```

**结果解读**：文件内容先被覆写，再由 `-u` 移除目录项；命令成功不代表所有历史副本都已消失。

::: warning `shred` 不是现代存储上的删除保证
在 SSD（磨损均衡/TRIM）、日志文件系统、CoW 文件系统（Btrfs/ZFS/APFS）、快照、RAID、压缩层、网络盘和备份中，覆写可能落到新物理块，旧副本仍在。敏感数据应优先采用全盘/目录加密并销毁密钥，退役设备使用厂商 secure erase/sanitize；`shred` 也无法擦除备份和快照。macOS 默认没有 GNU `shred`，安装 coreutils 后为 `gshred`。
:::

## 4. 查找
### 4.1 `find`：实时按条件找
```bash
find /var/log -name '*.log'            # 按名字
find /home -type d -name node_modules  # 类型+名字组合
find / -type f -size +100M             # 大于 100M 的文件
find /etc -mtime -7                    # 7 天内修改过的
find . -name '*.tmp' -exec rm {} \;    # 找到并删除
```

| 条件 | 含义 | 示例 |
| --- | --- | --- |
| `-name '模式'` | 按文件名（加引号防展开） | `-name '*.conf'` |
| `-type f/d/l` | 文件/目录/链接 | `-type d` 只找目录 |
| `-size +100M` | 大于 100M（`-100k` 小于） | 找大文件 |
| `-mtime -7` | 7 天内被修改 | 找近期改动 |
| `-exec cmd {} \;` | 对每个结果执行命令 | `-exec ls -l {} \;` |

解读：`find` 从给定目录**递归实时扫描**，慢但结果永远最新；路径必须放在表达式前。`-name` 参数务必加引号：不加引号 shell 会在 `find` 执行前把 `*.log` 展开成当前目录的匹配结果。`-exec ... {} +` 把结果一批传给命令，比 `{} \;` 逐个执行快。

### 4.2 `locate`：查数据库，快但可能旧
```bash
locate nginx.conf
```
解读：`locate` 查的是 `updatedb` 预建的数据库，毫秒级返回；缺点是**数据库可能未更新**，新建文件搜不到。手动更新 `updatedb`（需 root）。适合"我知道系统里有，只是忘了在哪"的场景。

### 4.3 `which` / `whereis`：命令在哪
```bash
which ls
which -a python        # 显示所有匹配路径
whereis python3        # 连源码/man 文档位置一起找
```
预期输出（`which ls`）：
```
/usr/bin/ls
```
| 命令 | 范围 | 用途 |
| --- | --- | --- |
| `which` | 在 `$PATH` 中找可执行文件 | 判断命令装没装、用的哪个版本 |
| `whereis` | 找二进制 + man + 源码路径 | 定位整套文件 |
| `type` | 也识别内建与别名 | `type cd` 显示 `cd is a shell builtin` |

::: tip 查用户、组和主机名不要只读文件
账户与目录服务查询用 `getent passwd 用户`、`getent group 组`、`getent hosts 主机`，它会遵循 `/etc/nsswitch.conf`，同时覆盖本地文件、LDAP/NIS、DNS 等来源。完整参数与身份映射放在 [权限与用户管理](/kb/os/Bash/04-权限与用户管理/)，本篇不重复展开。
:::

### 4.4 `find` 与 `grep` 组合的坑
```bash
# 错误示范：grep 匹配的是路径字符串，不是文件内容
find . -name '*.conf' | grep 'nginx'
# 正确做法：按内容找用 grep -r
grep -rl 'server_name' .
# 或者 find 内部用 -exec 调 grep
find . -name '*.conf' -exec grep -l 'server_name' {} \;
```

::: tip 区分两种语义
`find ... | grep` 管道的 `grep` 匹配的是**路径字符串**，不是文件内容。想按**内容**找文件，用 `grep -r` 直接递归（`grep -rl 'pattern' /dir`）或 `find -exec grep`。二者别混。`grep` 细节见 [文本处理三剑客](/kb/os/Bash/02-文本处理三剑客/)。
:::

## 5. 文件类型与统计
### 5.1 `file`：识别文件类型
```bash
file /bin/ls
file report.md
file data.bin
```
预期输出：
```
/bin/ls: ELF 64-bit LSB executable, x86-64, dynamically linked...
report.md: Unicode text, UTF-8 text
data.bin: data
```
解读：`file` 不看扩展名，读文件头部魔法字节（magic number）判断真实类型。扩展名在 Linux 里只是约定，`file` 才是"验明正身"的手段。

### 5.2 `stat`：inode 与三种时间戳
```bash
stat report.md
```
预期输出（关键行）：
```
  File: report.md
  Size: 12288          Blocks: 24         IO Block: 4096   regular file
Device: fd01h/64769d   Inode: 1234567     Links: 1
Access: 2024-08-10 09:30:00   # atime
Modify: 2024-08-10 10:15:30   # mtime
Change: 2024-08-10 10:16:02   # ctime
 Birth: 2024-08-08 18:00:00   # btime（部分文件系统才有）
```

| 时间戳 | 触发时机 | 谁改 | 举例 |
| --- | --- | --- | --- |
| **atime** | 访问（读） | read/cat/less | 查看内容就会刷新 |
| **mtime** | 内容被修改 | 写内容 | `echo x >> f` |
| **ctime** | inode 元数据被修改 | chmod/chown/mv | 改权限、改属主、改名 |
| **btime** | 文件被创建 | 创建时 | 出生时间 |

解读：ctime 是**变更时间**（change time）不是创建时间——它记录 inode 元数据最近一次改动，因此 `chmod`、`mv` 都会刷新 ctime。inode 是文件的"身份证号"，`stat` 里能看到 Inode 号与 Links（硬链接数）。文件描述符与 inode 的关系见 [fd](/kb/os/Linux/15-文件描述符详解/)。

### 5.3 `du`：目录占多大
```bash
du -sh /var/lib/mysql      # 总大小（人类可读）
du -h --max-depth=1 /home   # 只看一层子目录
du -sh * | sort -h          # 按大小排序
```
解读：`du` 统计目录下所有文件占用的磁盘块，`-s` 只给汇总、`-h` 人类可读、`--max-depth=N` 限深度。排查"磁盘被谁吃满"：`du -h --max-depth=1 / | sort -h` 逐层下钻。

### 5.4 `df`：磁盘剩多少
```bash
df -h
```
预期输出（片段）：
```
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1       100G   70G   30G  70% /
/dev/sdb1       500G  200G  300G  40% /data
```
解读：`df` 看**文件系统整体**用量与剩余，`-h` 人类可读，`Use%` 超 90% 就该清理。`df -i` 看 inode 用量——inode 耗尽时磁盘还有空间却无法建文件，原理见 [Linux 文件实操](/kb/os/Linux/03-Linux文件系统与磁盘实操/)。对比：`du` 统计具体目录内文件大小，`df` 看整个分区的剩余空间。

## 6. 文本基础处理
### 6.1 `sort`：排序
```bash
sort names.txt               # 按字典序
sort -n scores.txt           # 按数值
sort -r names.txt            # 倒序
sort -t: -k3 -n /etc/passwd  # 以 : 分隔，按第 3 列数值排
```
| 参数 | 含义 |
| --- | --- |
| `-n` | 按数值排序（否则 10 排在 2 前面） |
| `-r` | reverse 倒序 |
| `-t` + `-k` | 指定分隔符和列排序 |

### 6.2 `uniq`：去重（要先排序）
```bash
sort access.log | uniq -c      # 统计每行出现次数
sort access.log | uniq -d      # 只显示重复行
sort access.log | uniq -u      # 只显示唯一行
```
解读：`uniq` **只能去掉相邻的重复行**，所以去重/统计前必须先 `sort`。`-c` 前置计数、`-d` 只要重复、`-u` 只要唯一。

### 6.3 `cut`：按列切

```bash
cut -d: -f1 /etc/passwd        # 按 : 分隔取第 1 列（用户名）
cut -d: -f1,3 /etc/passwd     # 取第 1、3 列
cut -c1-5 file.txt             # 按字符位置切
```
解读：`-d` 指定分隔符（默认 tab），`-f` 选列，`-c` 按字符范围。cut 只能"竖着切"，做不了跨行重组。

### 6.4 `tr`：字符级替换/删除
```bash
echo "HELLO" | tr 'A-Z' 'a-z'    # 大写转小写
tr -d '\r' < win.txt > unix.txt  # 删 \r，Windows 换行转 Linux
tr -s ' ' < messy.txt            # 连续空格压缩为 1 个
```
解读：`tr` 处理**字符集**而非单词，`-d` 删除、`-s` 压缩重复。它不读文件只读 stdin，常配合 `<` 或管道。

### 6.5 `paste` / `join`：横向合并
```bash
paste names.txt phones.txt        # 按行横向拼（tab 分隔）
join -t: users.txt groups.txt     # 按公共字段（默认第 1 列）关联
```
解读：`paste` 按行号横向拼接，不要求排序；`join` 类似 SQL 的 inner join，要求两文件**已按关联字段排序**。复杂关联更适合 `awk`（见 [高级命令与文本处理](/kb/os/Bash/09-高级命令与文本处理/)）。

### 6.6 经典统计流水线
```bash
cat access.log | awk '{print $1}' | sort | uniq -c | sort -rn
```
解读（统计访问量最高的 IP）：
1. `awk '{print $1}'` 抽每行第一列（IP 地址）。
2. `sort` 把相同 IP 排成相邻。
3. `uniq -c` 统计出现次数，输出 `次数 IP`。
4. `sort -rn` 按次数数值倒序，最高排最前。

::: tip 万能四连
`sort | uniq -c | sort -rn` 是日志分析的经典骨架：去重计数 + 按量倒排。后面学到的任何"按某字段统计 Top N"都可以套进这个管道。
:::

## 7. 重定向与管道基础
> 本目录的重定向深入（`exec`、描述符操作）在 [高级命令与文本处理](/kb/os/Bash/09-高级命令与文本处理/) 展开，这里先建立直觉。

```bash
ls > out.txt            # 标准输出 → 文件（覆盖）
ls >> out.txt           # 标准输出 → 文件（追加）
ls 2> err.txt           # 错误输出 → 文件
ls > out.txt 2>&1       # stdout 和 stderr 都进 out.txt（顺序重要）
ls | grep 'conf'        # 前命令输出接后命令输入
ls 2>&1 | tee log.txt   # 边显示边写入文件
ls -R / 2>/dev/null     # 错误丢弃到黑洞
echo "$(date)"          # 命令替换：先执行再当文本用（旧式写法是反引号）
```

| 写法 | 含义 |
| --- | --- |
| `>` | 覆盖重定向标准输出 |
| `>>` | 追加标准输出 |
| `2>` | 重定向标准错误（fd=2） |
| `2>&1` | 把 stderr 并入 stdout 所在目标 |
| `\|` | 管道：左命令 stdout → 右命令 stdin |
| `tee [-a]` | 既显示又写入文件，`-a` 追加 |
| `/dev/null` | 黑洞设备，写进去即丢弃 |
| `$(cmd)` / `` `cmd` `` | 命令替换，先执行再嵌入 |

解读：`> out.txt 2>&1` 与 `2>&1 > out.txt` 结果不同，因为重定向按**从左到右**的书写顺序生效。前者先让 stdout 指向文件，再把 stderr 复制到 stdout 当前目标；后者先把 stderr 复制到当时的 stdout（终端），随后只改 stdout，所以错误仍留在终端。重定向本质是**改文件描述符 0/1/2 指向**，呼应 [fd](/kb/os/Linux/15-文件描述符详解/) 篇。`|` 管道连接左侧 stdout 与右侧 stdin；Bash 通常让管道各段在子进程环境运行，变量作用域细节见 [Shell脚本编程进阶](/kb/os/Bash/08-Shell脚本编程进阶/)。

### 7.1 `echo` 与 `read`：问与答
```bash
read -p "请输入名字: " name   # 提示并读取一行到变量 name
echo "你好, $name"
```
解读：`read` 从 stdin 读一行，`-p` 显示提示，读入存变量，是交互脚本的基础。配合重定向：`read line < file.txt` 读第一行；`while read line; do ...; done < file` 逐行处理。

### 8.1 `history` 与 `!` 命令
```bash
history            # 列出历史
history 10         # 只看最近 10 条
!!                 # 重跑上一条命令
!42                # 重跑历史编号 42 的命令
!ls                # 重跑最近一条以 ls 开头的命令
fc -l              # 列历史（同 history）
fc 42              # 打开编辑器修改第 42 条后再执行
```

| 写法 | 含义 | 示例 |
| --- | --- | --- |
| `!!` | 上一条命令 | 忘记 sudo 时 `sudo !!` |
| `!n` | 第 n 条历史 | `!42` |
| `!str` | 最近以 str 开头的命令 | `!find` |
| `!$` | 上一条命令的最后参数 | `mkdir a && cd !$` |
| `fc` | 历史编辑/重放 | `fc -l` 查看，`fc 42` 编辑重跑 |

::: tip 常用组合
写完长命令提示 `Permission denied`，只需 `sudo !!` 一秒补救，这是 `!!` 最经典的用法。`history` 默认落盘到 `~/.bash_history`，可用 `grep` 搜索历史。
:::

## 本章小结
1. 导航三件套 `pwd`/`cd`/`ls` 定下“我在哪、去哪、有什么”；路径字符串用 `basename`/`dirname` 拆，真实路径用 `realpath` 或 GNU `readlink -f` 解析。
2. 创建与查看用 `mkdir`/`rmdir`、`touch`/`truncate`、`cat`/`head`/`tail`/`less`；`mkfifo` 创建会阻塞等待两端接入的命名管道。
3. 复制移动删除注意 `cp`/`mv` 默认可能覆盖、`rm -rf` 极高危、软硬链接的 inode 差异要心里有数；批量重命名先辨认 util-linux/Perl `rename` 并 `-n` 预演。
4. 大文件按固定规模用 `split`，按内容边界用 `csplit`；`shred` 只对有限的传统存储场景有意义，不能替代加密、快照和介质安全擦除。
5. 查找记住“find 走文件系统、locate 走数据库”，`find | grep` 过滤的是路径不是内容；账号/组/主机查询交给遵循 NSS 的 `getent`。
6. `file`/`stat`/`du`/`df` 回答“是什么、inode 多少、谁占满、剩多少”；atime/mtime/ctime 别把 ctime 当创建时间。
7. `sort | uniq -c | sort -rn` 是统计分析骨架；重定向按从左到右生效，`>`/`>>`/`2>&1`/`|`/`$( )` 是 shell 的连接件。
8. 快捷键与 `!!`/`history` 减少重复输入，但高危命令不要未经检查直接 `sudo !!`。

## 动手实验
1. `mkdir -p /tmp/bash-file-lab/{real,out}`，建立 `link -> real`，分别用 `basename`、`dirname`、`readlink`、`readlink -f`/`realpath` 观察“路径字符串、链接内容、最终路径”的差异；macOS 缺少相应 GNU 参数时记录替代命令。
2. 用 `touch` 生成 10 个文件，`ls -lt` 和 `ls -lS` 排序对比；用 `truncate -s 1M sparse.img` 建稀疏文件，对比 `ls -lh` 与 `du -h`。
3. 用 `mkfifo` 建命名管道，先启动读端再从另一终端写三行，观察阻塞与消费行为；最后删除 FIFO。
4. 用 `seq 1 20` 生成文件，分别以 `split -l 6` 和匹配特定行的 `csplit` 拆分，再 `cat` 重组并用 `cmp` 验证。
5. 在 `/tmp/rename-lab` 建 5 个带 `draft` 的文件，先确认本机是哪一种 `rename`，用 `-n -v` 预演后再改名；不要在真实资料目录实验。
6. 对同一文件建硬链接和软链接，用 `ls -li` 对比 inode，`rm` 原文件后观察：硬链接还在、软链接悬空。
7. 用 `sort | uniq -c | sort -rn` 统计 `getent passwd` 中 shell 字段（最后一列）的分布，并解释为何它可能比直接读 `/etc/passwd` 更完整。
8. 故意执行 `ls /nonexistent 2>/dev/null`，再用 `ls /nonexistent 2>&1 | tee /tmp/err.log`，说明 `/dev/null` 和 `tee` 的作用；额外比较 `>out 2>&1` 与 `2>&1 >out`。

1. `d` 目录；`l` 符号链接；`-` 普通文件。
2. 回到上一次所在的目录；依赖 `$OLDPWD`。
3. 不会报错，只是把它的 atime/mtime 更新为当前时间，内容不变。
4. 硬链接仍有效（数据还在）；软链接失效变成悬空链接。
5. 匹配的是**路径字符串**；按内容找应使用 `grep -rl 'nginx' .` 或 `find . -name '*.conf' -exec grep -l nginx {} \;`。
6. atime 读取时更新；mtime 内容被修改时更新；ctime 元数据（权限/属主/改名）变化时更新。ctime 是"变更时间"不是创建时间。
7. `awk '{print $1}' 日志 | sort | uniq -c | sort -rn`（把 $1 换成实际 IP 所在列）。
8. 第一种：先让 stdout 指向 out.txt，再让 stderr 复制 stdout 的当前目标，所以两路都进文件；第二种：stderr 先复制当时指向终端的 stdout，之后只有 stdout 改到文件，所以错误仍显示在终端。重定向按从左到右生效。
9. `basename`/`dirname` 只拆路径字符串，不要求目标存在；`realpath` 规范化并通常解析符号链接。`readlink link` 输出链接中保存的目标字符串，不是必然的绝对路径。
10. `split` 按固定行数/字节数切，`csplit` 按行号或内容正则边界切。旧目录可能残留上次更多的分片，通配重组会误把旧文件拼进去。
11. util-linux 版是 `rename FROM TO FILE...` 的子串替换；Perl 版是 `rename 's/正则/替换/' FILE...`。先确认实现，再在测试目录用 `-n -v` 预演并检查重名冲突。

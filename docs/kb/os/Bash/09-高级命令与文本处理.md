::: abstract 本章定位
把"管道"从"能串"升级为"会串"：`xargs` 给管道补上参数引擎，`find` 深入条件与批量操作，`tee`/`timeout`/`watch` 处理输出与超时，进程替换玩转 fd，再配齐文本排版、换行编码、模板替换、数值计算、压缩归档、编码校验与磁盘监控，最后用综合实战把命令焊成一条龙。属 [Bash命令学习路线总览](/kb/os/Bash/00-Bash命令学习路线总览/) 高级层，前承 [Shell脚本编程进阶](/kb/os/Bash/08-Shell脚本编程进阶/)。
:::

前面的管道 `|` 只能"把 A 的输出喂给 B 的输入"，而 `rm`/`cp`/`mkdir` 这类命令**不吃 stdin、只吃命令行参数**。这一篇专门补这些缺口：参数怎么传、输出怎么存、超时怎么杀、文件怎么批量处理。命令按 Linux/GNU 行为书写，均可直接运行（macOS 差异见下方提醒）。

::: warning GNU 与 BSD 的差异
macOS 默认缺 GNU `timeout` 和 `watch`：`brew install coreutils` 后超时命令通常叫 `gtimeout`，而 `watch` 需单独 `brew install watch`，不属于 GNU coreutils。`md5sum`/`sha256sum` 对应 `md5`/`shasum -a 256`。写脚本前先用 `command -v` 探测，不要只按操作系统名猜。
:::

## 1. xargs：给管道一个"参数引擎"

### 1.1 为什么需要 xargs（管道传参限制）

```bash
find . -name '*.tmp' | rm     # 错！rm 不读 stdin，报错
echo a b c | xargs printf '[%s]\n'   # 预期输出：每行一个 [a] [b] [c]
```
解读：管道传的是**数据流**，`xargs` 是"翻译官"——读 stdin、按空白拆词，作为**参数**追加给命令执行。心智模型：**`| xargs cmd` = 把管道内容转成 `cmd` 的参数**。

### 1.2 `-n`：控制每批个数

```bash
echo {1..6} | xargs -n 2 echo "批次:"   # 预期：批次: 1 2 / 批次: 3 4 / 批次: 5 6
```
解读：`-n 2` 每批最多 2 个参数；`-n 1` 逐条执行。大批量时用 `-n` 防命令行超长；`ARG_MAX` 不是固定 2MB，可用 `getconf ARG_MAX` 查看当前系统上限，xargs 还会为环境变量和命令本身预留空间。

### 1.3 `-I {}`：替换占位符

```bash
find /tmp -name '*.jpg' | xargs -I {} cp {} /backup/images/
```
解读：`-I {}` 声明占位符，命令行中每个 `{}` 换成当前输入项，适合参数不在末尾的场景；使用 `-I` 后每批固定处理 1 个输入项。

### 1.4 `-0`：与 `find -print0` 配合，征服空格文件名

```bash
find . -name '*.txt' | xargs rm          # 危险！"my file.txt" 被拆成两个
find . -name '*.txt' -print0 | xargs -0 rm   # 正解
```
解读：`find -print0` 用 NUL 分隔文件名，`xargs -0` 按 NUL 而非空白拆分——**空格、引号、换行都不再是问题**。文件名越不守规矩越要用这对黄金组合。

### 1.5 `-P`：并行执行

```bash
seq 1 8 | xargs -P 4 -I {} sh -c 'sleep 1; printf "done %s\n" "$1"' _ {}  # 约 2 秒
xargs -P 10 -n 1 curl -fsSLO < urls.txt
```
解读：`-P N` 同时开 N 个进程，适合**无依赖**的独立任务（下载/转码）；写同一文件或有共享状态的任务慎用。

### 1.6 `echo | xargs` vs `$()` 对比

```bash
value=$(command)         # 命令替换：把 stdout 当一个字符串保存
find . -name '*.md' -print0 | xargs -0 wc -l   # 列表按 NUL 安全转参数
```
| 对比项 | `$( )` | `echo \| xargs` |
|---|---|---|
| 时机 | 先执行命令，拿输出当文本 | 管道内容作为参数喂给命令 |
| 文件名含空格/换行 | 未引用展开会碎；引用后仍只是一个字符串 | 加 `-0`（配合 `-print0`）安全 |
| 空输入 | 展开为空字符串 | GNU 默认仍执行一次（加 `-r` 不执行） |
| 批量 / 并行 | 不支持 | `-n` 分批、`-P` 并行 |

::: tip 选型
只是取值当字符串 → `$( )`；想把列表交给命令分批/并行执行 → `xargs`。
:::

### 1.7 常见用途

```bash
find /var/log -name '*.gz' -mtime +7 -print0 | xargs -0 rm -f   # 批量删除
xargs -P 10 -n 1 curl -fsSLO < urls.txt                         # 并行下载
find /srv -name '*.sh' -print0 | xargs -0 chmod +x              # 批量 chmod
```

### 1.8 xargs 的坑

| 坑 | 现象 | 规避 |
|---|---|---|
| 引号解析 | `echo '"a b"' \| xargs` 把 `a b` 当一个参数（xargs 自己解析引号） | 用 `-0` 或 `-d '\n'` |
| 空输入也执行 | GNU xargs 对空输入仍执行一次 | 加 `-r` |
| 参数过长 | 触发 `Argument list too long` | `-n 50` 分批 |
| 默认拆分行 | 换行和空格都当分隔符 | 一律 `-print0 \| xargs -0` |
| 无 `{}` 误解 | 不加 `-I` 时写 `{}` 无意义 | 需要占位就用 `-I {}` |

### 1.9 GNU `parallel`：比 xargs 更完整的任务调度器

**用途**：并发运行大量独立任务，并提供占位符、输出排序、失败停止、进度和远程执行等任务调度能力。它通常不默认安装；本篇只讲与 xargs 选型直接相关的部分。

**常用参数**：

| 参数 | 作用 |
|---|---|
| `-j N` | 同时运行 N 个任务；`-j 0` 尽量使用全部核心 |
| `{}` | 当前完整输入；`{/}` 文件名；`{//}` 目录；`{.}` 去扩展名 |
| `-k` / `--keep-order` | 最终输出保持输入顺序（任务仍并行） |
| `--halt soon,fail=1` | 任一任务失败后尽快停止启动新任务 |
| `--dry-run` | 只打印将执行的命令 |
| `-0` / `--null` | 按 NUL 分隔输入 |

**可运行示例**：

```bash
seq 1 4 | parallel -j 2 --keep-order 'sleep 1; printf "job %s done\n" {}'
find . -name '*.log' -print0 | parallel -0 -j 4 --dry-run gzip -- {}
```

预期结果：第一条约 2 秒完成，输出仍按 1、2、3、4 排列；第二条只显示将执行的 gzip 命令，不修改文件。

**结果解读**：`--keep-order` 通过缓冲每个任务输出保持顺序，便于日志阅读，但会增加缓存；`--dry-run` 是批处理上线前的关键预演手段。

**易错点**：GNU parallel 与更多 shell 表达式结合时仍要面对引用、命令注入和文件名分隔问题；不可信数据不要直接拼入 shell 代码，优先把值作为参数。它与其他名为 `parallel` 的程序不是同一工具，先执行 `parallel --version`。Debian/Ubuntu 可安装 `parallel` 包，macOS 可 `brew install parallel`；GNU parallel 首次运行可能显示 citation notice，批处理前应在交互环境确认。

**与 xargs 的准确对比**：

| 需求 | xargs | GNU parallel |
|---|---|---|
| 默认可用性 | Unix 系统通常自带 | 通常需安装 |
| 简单分批/并发 | `-n`、`-P` 足够 | 可以但较重 |
| 保持每个任务输出不交错 | 需自行重定向/临时文件 | 默认按任务归拢，`-k` 保输入顺序 |
| 失败后停止、重试、进度 | 能力有限且实现有差异 | `--halt`、`--retries`、`--bar` 更完整 |
| 文件名安全 | `find -print0 \| xargs -0` | `find -print0 \| parallel -0` |

结论：系统脚本只需“把 NUL 列表分批交给命令”时优先 xargs；任务需要稳定输出、复杂占位符、失败策略或重试时再引入 GNU parallel，避免为简单任务增加非默认依赖。更完整的现代工具选型与安装见 [现代高效命令行工具](/kb/os/Bash/20-现代高效命令行工具/)。

## 2. find 高级

### 2.1 `-exec {} \;` vs `-exec {} +` vs `xargs`

```bash
find . -name '*.log' -exec chmod 640 {} \;     # 每个文件一次
find . -name '*.log' -exec chmod 640 {} +      # 一批参数一次
find . -name '*.log' -print0 | xargs -0 chmod 640
```
| 方式 | 调用次数 | 空格安全 | 适用场景 |
|---|---|---|---|
| `-exec cmd {} \;` | 每个文件 1 次 | 安全 | 逐文件副作用 |
| `-exec cmd {} +` | 一批 1 次 | 安全 | 纯批量参数，性能最好 |
| `xargs` | 可 `-n` 控制 | 需 `-print0`+`-0` | 要 `-P` 并行、要管道组合 |

解读：`\;` 结尾分号需转义；`{} +` 要求 `{}` 是命令**最后一个参数**。默认优先 `{} +` 或 xargs。

### 2.2 `-print0` 与 `-print`

```bash
find . -name '*.conf'            # 默认 -print，换行分隔
find . -name '*.conf' -print0    # NUL 分隔，供 -0 消费
find . -name '*.conf' -print | wc -l   # 数个数（文件名含换行会误计）
```
解读：`-print0` 单独用没意义，意义在于和 `xargs -0`、`tar --null` 对接。

### 2.3 组合条件（`!` `-o` `-a` 优先级）

```bash
find . \( -name '*.log' -o -name '*.tmp' \) -size +1M
find . ! -name '*.py' -type f
```
解读：条件间无运算符隐含 `-a`（AND）；优先级 **`!` > `-a` > `-o`**。所以 `find . -name '*.log' -o -name '*.tmp' -delete` 等价于 `*.log` OR（`*.tmp` AND `-delete`），**只删 `.tmp`**，`*.log` 匹配到却无事发生。分组必须用 `\( \)`。

::: warning 经典翻车
想删 `.log` 和 `.tmp`，实际只删了 `.tmp`：`find . -name '*.log' -o -name '*.tmp' -delete`。正确写法：`find . \( -name '*.log' -o -name '*.tmp' \) -delete`。
:::

### 2.4 `-delete`：边找边删

```bash
find /var/log -name '*.gz' -mtime +90 -delete
```
解读：`-delete` 隐含 `-depth`（自底向上删，可顺带清空变空的目录）；**没有后悔药**，删除前先 `-print` 预览或 `-exec echo {} \;` 演练。

### 2.5 按时间：`-mtime` / `-newer`

```bash
find /var/log -mtime -1              # 1 天内修改
find /var/log -mtime +30 -type f     # 30 天前修改
find /etc -mmin -60                  # 60 分钟内（精确到分钟）
find . -newer report.md -name '*.c'  # 比 report.md 新
```
解读：`-mtime -N` N 天内、`+N` N 天前；`-mmin` 分钟版；`-newer file` 以某文件时间戳为基准。变体 `-atime`/`-ctime`（原理见 [Linux 文件实操](/kb/os/Linux/03-Linux文件系统与磁盘实操/)）。

### 2.6 `-maxdepth` / `-mindepth`

```bash
find . -maxdepth 2 -name '*.conf'   # 只往下 2 层
find . -mindepth 2 -type f          # 至少下 2 层才找
```
解读：`-maxdepth` 限制深度、加速大目录；`-mindepth` 用于"排除顶层文件、只处理子目录内容"。

### 2.7 批量操作实战

```bash
find /var/log -name '*.gz' -mtime +7 -exec rm {} +            # 找并删
find /var/www -name '*.php' -mtime -1 -print0 | tar -czf /backup/daily.tgz --null -T -   # 找并 tar
find /var/log -name '*.log' -size +1M -exec du -h {} \; | sort -rh | head   # 找并统计
find /tmp -name '*.bak' -exec echo "将删除: {}" \;           # 预览式删除
```
::: tip 安全三连
批量删除前：① `-print` 预览；② 在临时目录演练；③ 先 `-exec echo {} \;` 模拟再上真命令。
:::

## 3. tee：三通管道

### 3.1 同时输出到屏幕与文件

```bash
ls -lh /var/log | tee /tmp/before.txt     # 屏幕照常显示 + 落盘
ls -lh /var/log | tee -a /tmp/log.txt     # -a 追加而非覆盖
```
解读：`tee` 读 stdin，一份写 stdout（屏幕）、一份写文件；`-a` 追加。**核心用途：管道中间快照**。

### 3.2 配合 sudo

```bash
echo 'net.ipv4.ip_forward=1' > /etc/sysctl.conf    # Permission denied：重定向是 shell 干的，shell 非 root
echo 'net.ipv4.ip_forward=1' | sudo tee -a /etc/sysctl.conf   # 对
sudo tee /etc/apt/sources.list < mirror.list       # "以 root 写文件"惯用法
```
解读：`sudo echo x > file` 中 sudo 只管 `echo`，`>` 由当前 shell 执行。让 `tee` 被 sudo 提权，就能写 root 文件。

### 3.3 管道中间观察

```bash
cat access.log | tee /tmp/raw.log | awk '{print $1}' | sort | uniq -c | sort -rn | head
find . -name '*.log' -print0 | tee /tmp/list.nul | xargs -0 wc -l | tail -1
```
解读：`tee` 放管道中段 = **不改变下游数据的前提下偷看并留档**，是调试长管道的头号工具。

## 4. timeout 与后台超时

### 4.1 `timeout`：给命令限时

```bash
timeout 5 sleep 100            # 5 秒后发 TERM
timeout -k 2 10 ./slow.sh      # 10 秒 TERM，再过 2 秒 KILL 强杀
timeout 1 ping -c 5 8.8.8.8    # 防止网络命令挂死
timeout 5 sleep 100; echo $?   # 预期输出：124
```
解读：命令正常退出返回自身退出码，**因超时被杀返回 124**（脚本据此判断"卡死"）。`-k` 先发 TERM 给优雅退出的机会，宽限期后仍不退才发 KILL（不可捕获）；`--preserve-status` 保留原命令退出码。场景：CI 测试、网络探测、不确定时长的命令。

### 4.2 nohup 回顾与 `( cmd & )`

```bash
nohup long_task.sh > out.log 2>&1 &   # 忽略 SIGHUP，关终端不中断
(cd /app && python server.py &)       # 子 shell 后台，父 shell 退出后被 init 收养
sleep 300 &                           # 简单后台，配合 jobs/fg/bg
```
| 写法 | 行为 | 用途 |
|---|---|---|
| `cmd &` | 后台运行，挂当前 shell 作业表 | 同终端快速后台 |
| `nohup cmd &` | 忽略 SIGHUP，日志落文件 | 关终端后仍要跑 |
| `( cmd & )` / `disown` | 子 shell 后台或移出作业表，脱管运行 | 彻底"断链" |

::: tip 组合拳
`nohup bash long.sh > /var/log/long.log 2>&1 &` 是"保命后台三件套"：忽略挂断 + 日志落盘 + 立即返回提示符。原理见 [Linux 进程实操](/kb/os/Linux/01-Linux进程与调度实操/)。
:::

### 4.3 `watch`：周期性重复

```bash
watch -n 1 'ss -s'                 # 每秒刷新连接统计
watch -n 2 free -h
watch -n 1 -d 'ps -eo stat,comm | sort'   # -d 高亮变化行
watch -d 'ls -l /var/log/'         # 有文件变化立刻高亮
```
解读：`watch` 全屏循环执行同一命令，默认 2 秒一次；`-n` 改间隔，`-d`（difference）高亮差异。命令加引号可含管道，Ctrl+C 退出。`watch -n1 ss -s` 是看网络连接变化的经典姿势。

::: warning macOS 提示
`watch` macOS 默认没有，也不在 Homebrew coreutils 中；可 `brew install watch`。不额外安装时可用 `while true; do clear; netstat -an; sleep 1; done` 近似，命令内容需换成 macOS 实际提供的工具。
:::

## 5. 进程替换与 fd 高级

### 5.1 `<(...)`：把命令输出当"文件"

```bash
diff <(ls dir_a) <(ls dir_b)     # 比较两目录差异，零临时文件
while read f; do echo "读到: $f"; done < <(find . -maxdepth 1 -name '*.txt')
```
解读：`<(cmd)` 由 shell 创建**伪文件**（/dev/fd/N），内容是 `cmd` 输出，可传给任何"要吃文件路径"的命令。注意写法 `< <(...)` 中间有空格——相比 `cmd > tmp; diff tmp`，零临时文件、可嵌套。

### 5.2 `>(...)`：把输出重定向给"进程"

```bash
ls -l > >(grep -i log)                  # stdout 直接进另一进程
tar czf - /var/log | tee >(md5sum > /tmp/backup.md5) > /tmp/backup.tgz
```
解读：`>(cmd)` 是反向进程替换——写入它如写文件，数据实际送进 `cmd` 的 stdin。上例一个 `tee` 同时算 md5 又落盘，零临时文件。

### 5.3 `/dev/stdin`、`/dev/stdout` 与 `exec` 自定义 fd

```bash
echo hello | cat /dev/stdin      # 读标准输入（管道内容）
echo hello > /dev/stdout
cat /dev/fd/0                    # fd 0 = stdin
exec 3> /tmp/log.txt             # 打开 fd 3 用于写
echo '记录一条' >&3              # 写到 fd 3
exec 3>&-                        # 关闭 fd 3
exec 3<> /tmp/rw.txt             # 以读写方式打开（<>）
read line <&3
```
解读：`/dev/stdin`、`/dev/stdout`、`/dev/fd/N` 是符号链接，让"只认文件路径"的命令也能吃管道；进程替换的底层就是 `/dev/fd`。`exec 3>file` 把 fd 3 重定向到文件，之后 `>&3`/`<&3` 读写——fd 0/1/2 已占用，**3 及以上留给用户**，常用于脚本开头"开好日志 fd"随处写；`exec 3>&1` 让 fd 3 复制 stdout。机制见 [fd](/kb/os/Linux/15-文件描述符详解/)。

## 6. 文本增强工具

### 6.1 `nl`：带行号输出

```bash
nl -ba script.sh               # 所有行都编号（含空行）
nl -w 3 -s '. ' file.txt       # 宽度 3，分隔符 ". "；预期：     1  #!/bin/bash
```
解读：`nl` 默认跳过空行不编号，`-ba` 让空行也编号；`-w` 宽度、`-s` 分隔符。对比 `cat -n`：`nl` 排版更可控，贴代码片段常用。

### 6.2 `column`：对齐成表格

```bash
cat /etc/passwd | column -t -s ':'   # 预期：root x 0 0 root /root /bin/bash（各列对齐）
ps aux | column -t                    # 空格分列对齐
```
解读：`column -t` 按分隔符把散乱列对齐成表格，纯展示不改内容；看配置/命令输出一手 `column -t` 立刻变美观。

### 6.3 `paste` / `join`：横向合并

```bash
paste names.txt scores.txt             # 逐行并排（tab 分隔）
paste -d, names.txt scores.txt         # 逗号分隔
join -t: -1 1 -2 1 users.txt groups.txt   # 按第 1 列做内连接
```
| 工具 | 对齐方式 | 前提 | 场景 |
|---|---|---|---|
| `paste` | 按**行号**并排 | 无 | 两个文件逐行拼表 |
| `join` | 按**公共字段**关联 | 两文件**必须已按键排序** | 类似 SQL 内连接 |

解读：`join` 默认以第 1 列为键，`-1 1 -2 1` 指定两边用第几列，未排序则结果错乱；复杂关联直接上 `awk`（见 [文本处理三剑客](/kb/os/Bash/02-文本处理三剑客/)）。

### 6.4 `comm`：集合运算（-1/-2/-3）

```bash
comm -12 fileA fileB        # 只显示共同行
comm -23 fileA fileB        # 只在 A 有
comm -13 fileA fileB        # 只在 B 有
```
解读：`comm` 三列分别是"只在 A / 只在 B / 共有"，`-1`/`-2`/`-3` 隐藏对应列，组合出共同项/差集。**前提：两个输入都必须先排序**，这是头号坑。

### 6.5 `diff` / `cmp` / `patch`

```bash
diff -u old.txt new.txt          # unified 格式（git 同款）
diff -r dir_a dir_b              # 递归比较目录
diff old new > change.patch      # 生成补丁
patch -p1 < change.patch         # 应用补丁
cmp -l a.bin b.bin               # 逐字节对比，报告差异偏移
```
解读：`diff -u` 适合人看也适合 `patch`；`diff -r` 直接列目录差异；`cmp` 只做二进制逐字节比较（0 相同、1 不同、2 出错），`-l` 列出差异偏移。`diff -u`+`patch` 是源码发布的标准补丁流程。

### 6.6 `fmt`：按段落重新排版

**用途**：把普通文本段落按目标宽度重新折行，并合并段落内已有的短行；适合纯文本邮件、说明和注释草稿。

**常用参数**：`-w N` 设目标宽度；GNU `-g N` 设最大宽度、`-s` 只拆长行不合并短行、`-u` 统一单词间距；BSD/macOS 参数较少且细节不同。

**可运行示例**：

```bash
printf '%s\n' 'Linux command line tools compose small programs into repeatable workflows.' \
  | fmt -w 24
```

预期结果：句子被重排为多行，每行大致不超过 24 列，单词不会被随意切成两半。

**结果解读**：`fmt` 理解空白分隔的段落和单词，目标是可读排版，不是严格的固定字节切割。

**易错点**：Markdown 表格、代码、缩进和长 URL 可能被改坏；先在副本或 stdout 预览。宽度受 locale 和实现影响，GNU/BSD 对缩进、句末空格及长单词处理不完全一致；要机械按列切行用 `fold`。

### 6.7 `fold`：按列宽机械折行

**用途**：把每一条长行按固定显示列或字节数切成多行，不理解段落语义。

**常用参数**：`-w N` 每行最多 N 列；`-s` 尽量在空白处切；`-b` 按字节而非显示列计数。

**可运行示例**：

```bash
printf '1234567890\n' | fold -w 4
printf 'alpha beta gamma\n' | fold -s -w 10
```

预期输出：

```text
1234
5678
90
alpha
beta gamma
```

**结果解读**：第一条严格每 4 列切一次；第二条优先在空格处断行，所以不会把 `alpha`、`beta` 拦腰切开。

**易错点**：`-b` 可能在 UTF-8 多字节字符中间切断并制造非法文本；按显示列处理中文、组合字符和宽字符时 GNU/BSD/locale 结果仍可能不同。协议需要固定字节块时应使用专用工具，而不是假设终端列宽等于字节数。

### 6.8 `pr`：分页与多栏打印排版

**用途**：为文本添加页眉、页码、分页和多栏布局，传统上用于终端打印机，今天仍可快速生成审阅版纯文本。

**常用参数**：`-h TEXT` 自定义页眉；`-l N` 页长；`-w N` 页面宽度；`-N`（如 `-2`）分 N 栏；`-n` 加行号；`-t` 省略页眉页脚。

**可运行示例**：

```bash
seq 1 6 | pr -2 -t
printf 'line 1\nline 2\n' | pr -n -h 'DEMO'
```

预期结果：第一条把 1 到 6 排成两栏；第二条生成带 `DEMO` 页眉、页码和行号的打印版文本。

**结果解读**：`pr` 关注“页面”而非数据结构，多栏输出可能加入 tab 和空行以满足页长。

**易错点**：不要把 `pr` 输出当稳定机器接口；终端宽度、页长、时间格式和 GNU/BSD 默认值会影响外观。表格数据优先 `column`，正式 PDF/排版使用专用工具。

### 6.9 `expand` / `unexpand`：Tab 与空格互转

**用途**：`expand` 把 tab 展开为空格，`unexpand` 把对齐空格压回 tab；常用于统一补丁显示、Makefile 之外的文本缩进和检查不可见空白。

**常用参数**：两者都用 `-t N` 设置 tab stop 宽度；`unexpand -a` 转换所有可转换空白，默认通常只处理行首；GNU 还支持逗号分隔的自定义 tab stop，BSD 细节需看本机 man page。

**可运行示例**：

```bash
printf 'a\tb\n' | expand -t 4 | sed -n l
printf '    indented\n' | unexpand -a -t 4 | od -An -t x1
```

预期结果：第一条以可见形式显示 `a` 与 `b` 中间三个空格；第二条字节开头出现 `09`，表示四个空格被压成一个 tab。

**结果解读**：tab stop 是“下一个制表位置”，不是无条件替换成固定 N 个空格；从第 1 列到第 5 列需要 4 个空格，从第 2 列到第 5 列只需 3 个。

**易错点**：Makefile 的 recipe 行必须使用真实 tab，盲目 `expand` 会破坏语义；`unexpand` 默认是否只处理前导空白及 `-a` 支持范围要按实现确认。转换前后用 `sed -n l`、`od` 或编辑器可视空白核验。

### 6.10 `rev`：逐行反转字符顺序

**用途**：把每一行反向输出，常与 `cut`/`sed` 组合处理“从行尾数”的简单场景。

**常用参数**：日常用法只有 `rev [FILE...]`；无文件时读 stdin。GNU/Linux 常见版本来自 util-linux，macOS 自带 BSD 版。

**可运行示例**：

```bash
printf 'abc\n12345\n' | rev
```

预期输出：

```text
cba
54321
```

**结果解读**：每行独立反转，行与行的顺序不变；它不是 `tac`，后者反转行序而不反转行内字符。

**易错点**：emoji、组合附加符和某些 Unicode grapheme cluster 可能被拆开或显示异常，行为受 locale/实现影响。路径扩展名等结构化任务优先参数展开、`basename` 或专门解析，不要为了炫技堆叠多次 `rev`。

### 6.11 `printf` 命令：可预测的格式化输出

**用途**：按格式串输出字符串、整数、浮点数和转义字符；比 `echo -e` 更可移植、更适合脚本和固定列报表。Bash 通常优先执行同名内建，也可显式调用 `/usr/bin/printf`。

**常用格式**：`%s` 字符串、`%d` 整数、`%f` 浮点、`%b` 解释参数中的反斜杠、`%-10s` 左对齐宽 10、`%06d` 前导零；Bash 内建 `%q` 可生成可复用的 shell 转义文本，但不是 POSIX。

**可运行示例**：

```bash
printf '%-8s %06d %.2f\n' job 42 3.14159
value='100% ready'
printf '%s\n' "$value"
```

预期输出：

```text
job      000042 3.14
100% ready
```

**结果解读**：格式串决定列宽、补零和小数位；变量永远作为 `%s` 对应参数传入，百分号因此只被当数据。

**易错点**：不要写 `printf "$value"`，数据中的 `%s`、`%n` 或反斜杠会被当格式指令；固定写 `printf '%s\n' "$value"`。格式参数不足时 printf 会用空/零补齐并可能重复应用格式，脚本应明确参数数量。Bash `%q`、时间格式 `%(...)T` 等扩展不能直接用于 `/bin/sh`。

### 6.12 `yes`：无限重复一行

**用途**：持续输出指定字符串（默认 `y`），常用于生成测试流或给明确支持逐行确认的安全程序提供输入。

**常用参数**：`yes [STRING...]`；多个词会以空格连接成一行。GNU 版支持 `--help/--version`，日常没有必要依赖实现特有选项。

**可运行示例**：

```bash
yes test | head -n 3
```

预期输出：三行 `test`，随后 `head` 关闭管道，`yes` 因 SIGPIPE 停止。

**结果解读**：`yes` 本身不会主动结束，必须由下游关闭、信号或外部超时终止。

**易错点**：在 `set -o pipefail` 下，上例管道可能因 `yes` 收到 SIGPIPE 返回非 0；需要时显式处理。绝不要用 `yes | rm`、`yes | fsck` 等方式盲目确认危险操作，自动化应使用命令官方的非交互参数并先验证范围。

### 6.13 `od`：按字节和数值解释数据

**用途**：查看不可见字符、换行、NUL、端序和原始字节；是 POSIX 基础工具，在缺少 `xxd`/`hexdump` 的精简系统尤其有用。

**常用参数**：`-A n`/`-An` 隐藏偏移地址；`-t x1` 每字节十六进制；`-t c` 字符/转义显示；`-N N` 最多读 N 字节；`-j N` 跳过 N 字节（`-N/-j` 在常见 GNU/BSD 均有，严格 POSIX 脚本仍应查实现）。

**可运行示例**：

```bash
printf 'A\r\n' | od -An -t x1
printf 'A\tB\n' | od -An -t c
```

预期输出关键内容：

```text
41 0d 0a
A  \t   B  \n
```

**结果解读**：`41` 是 ASCII `A`，`0d 0a` 是 CRLF；字符视图把 tab、newline 显示成转义形式。

**易错点**：`od -x` 等多字节数值格式受主机端序影响，核对协议字节时使用 `-t x1`。默认输出可能压缩连续重复行（显示 `*`）；精确逐字节调查要了解本机 `od` 的 `-v` 选项。二进制深入对比见 [二进制与安全审计命令](/kb/os/Bash/16-二进制与安全审计命令/)。

### 6.14 `strings`：从二进制抽取可打印字符串

**用途**：从二进制或混合文件中提取连续可打印字符，快速寻找版本号、路径、URL 和错误消息。

**常用参数**：`-a` 扫描整个文件；`-n N` 只输出长度至少 N 的字符串；GNU `-t x` 打印十六进制偏移。不同 BSD/binutils 版本的编码和偏移参数有差异。

**可运行示例**：

```bash
printf '\0abc\0hello-world\0' | strings -n 5
```

预期输出：`hello-world`，长度 3 的 `abc` 被过滤。

**结果解读**：`strings` 只提供线索，不理解二进制结构，也不能证明某字符串在运行时一定会使用。

**易错点**：输出可能包含巧合噪声或敏感信息；分析不可信二进制时不要执行它。编码、UTF-16 与审计组合已经在 [二进制与安全审计命令](/kb/os/Bash/16-二进制与安全审计命令/) 详细说明，本篇不重复展开。

### 6.15 `sponge`：读完输入再覆盖文件

**用途**：先把全部 stdin 收集完，再一次性写入目标文件，解决 `cmd file > file` 中 shell 在命令读取前就清空文件的问题。

**常用参数**：`sponge FILE` 覆盖写；`sponge -a FILE` 追加。它来自 **moreutils**，不是默认系统命令；Debian/Ubuntu 安装 `moreutils`，macOS 可 `brew install moreutils`。

**可运行示例**：

```bash
printf 'c\na\nb\n' > /tmp/sponge-demo.txt
sort /tmp/sponge-demo.txt | sponge /tmp/sponge-demo.txt
cat /tmp/sponge-demo.txt
```

预期输出：

```text
a
b
c
```

**结果解读**：`sort` 完整读完原文件后，sponge 才覆盖同一路径，因此不会像 `sort file > file` 那样先得到空输入。

**易错点**：sponge 需要缓存全部输入，超大数据可能占大量内存或临时空间；它也不自动提供跨崩溃的事务保证。配置文件要求原子替换时，更稳的模式是同目录 `mktemp` → 写入并校验 → 保留权限/属主 → `mv` 替换。非默认依赖必须在脚本开头 `command -v sponge` 检查。

### 6.16 `envsubst`：受控展开环境变量模板

**用途**：把 stdin 中的 `$VAR`/`${VAR}` 替换为当前环境变量值，适合生成简单配置；它只替换变量，不执行命令替换、算术或 shell 语句，比 `eval` 安全得多。

**常用参数**：`envsubst` 默认替换模板中所有变量；`envsubst '$HOST $PORT'` 只允许指定变量；`envsubst -v '$HOST ${PORT}'` 只列出格式串引用的变量名（GNU gettext 版本）。命令来自 gettext，不是 shell 内建。

**可运行示例**：

```bash
export APP_HOST=127.0.0.1 APP_PORT=8080
printf 'listen=${APP_HOST}:${APP_PORT}\nliteral=$HOME\n' \
  | envsubst '$APP_HOST $APP_PORT'
```

预期输出：

```text
listen=127.0.0.1:8080
literal=$HOME
```

**结果解读**：白名单中只有 APP_HOST、APP_PORT，所以 `$HOME` 保持字面值；若不传变量列表，HOME 也会被展开。

**易错点**：变量必须已导出给 `envsubst` 子进程；未设置变量通常替换为空串，生成配置前应在 Bash 中用 `: "${VAR:?必须设置}"` 校验。变量列表要用**单引号**避免被当前 shell 提前展开。它不支持 `${VAR:-default}` 等参数展开，也不理解 YAML/JSON 转义；结构化配置应使用 [结构化数据处理命令](/kb/os/Bash/18-结构化数据处理命令/) 中的专用工具。Linux 常见包名 `gettext-base`/`gettext`，macOS Homebrew 为 `gettext`，安装后 PATH 位置需按提示配置。

## 7. 数值计算与表达式

### 7.1 `bc`：任意精度与小数计算

**用途**：从 stdin 读取表达式，执行任意精度十进制计算；弥补 Bash 算术只支持整数的限制。

**常用参数/变量**：`-l` 加载数学库并把默认 `scale` 设为较高精度；`-q` 不显示欢迎信息（交互版）；`scale=N` 控制除法等结果的小数位；`ibase`/`obase` 控制输入/输出进制。

**可运行示例**：

```bash
printf 'scale=2; 5 / 2\n' | bc
printf 'sqrt(2)\n' | bc -l
```

预期输出：

```text
2.50
1.41421356237309504880
```

**结果解读**：`scale=2` 让除法保留两位小数；`-l` 提供 `sqrt`/三角函数并提高精度。bc 通常截断到 scale，不是四舍五入。

**易错点**：不要把不可信字符串直接拼进 bc 程序；先用正则验证数字。`scale` 影响除法和部分函数但不是所有运算的简单“统一小数位”。bc 在精简 Linux 和部分 macOS 环境可能未安装，先 `command -v bc`；macOS 可 `brew install bc` 获得新版 GNU bc。

### 7.2 `expr`：传统表达式与字符串操作

**用途**：执行整数算术、比较和简单字符串匹配；主要用于维护旧 POSIX shell 脚本，新 Bash 脚本通常优先 `$(( ))`、`${#var}` 和 `[[ ]]`。

**常用操作**：算术 `+ - \* / %`；比较 `= != < <= > >=`；`length STRING`、`substr STRING POS LEN`、`index STRING CHARS`；冒号 `STRING : REGEX` 做锚定基础正则匹配。

**可运行示例**：

```bash
expr 7 \* 6
expr length 'hello'
expr 'file.txt' : '.*\.\(.*\)'
```

预期输出：

```text
42
5
txt
```

**结果解读**：`*` 必须转义，避免 shell glob；第三条 BRE 捕获组输出扩展名。

**易错点**：每个运算符和操作数都必须是独立参数；结果为空或数值 0 时 `expr` 返回退出码 1，因此在 `set -e` 下单独执行 `expr 1 - 1` 可能终止脚本。字符串可能被误认成运算符时加 `X` 前缀是旧式技巧；现代 Bash 直接使用更清晰的内建语法。

### 7.3 `factor`：整数质因数分解

**用途**：把一个或多个正整数分解为质因数，适合数学验证、练习和检查小型整数结构。

**常用参数**：`factor NUMBER...`；无参数时从 stdin 逐个读取整数。GNU coreutils 版支持大整数的范围取决于版本，macOS 默认通常没有 GNU factor。

**可运行示例**：

```bash
factor 60 97
```

预期输出：

```text
60: 2 2 3 5
97: 97
```

**结果解读**：60 被拆成 `2×2×3×5`；97 本身是质数，所以只输出自身。

**易错点**：它不是密码学大整数分解工具，不能拿来评估 RSA 安全；零、负数、超大数的接受范围和输出依实现而异。macOS 可安装 coreutils 后使用 `gfactor`。

### 7.4 `numfmt`：人类单位与原始数字互转

**用途**：把字节数/大整数格式化为 K、M、G 等可读单位，或把带单位输入还原为数字；适合给报表做显示层转换。

**常用参数**（GNU coreutils）：

| 参数 | 作用 |
|---|---|
| `--to=si` / `--to=iec` / `--to=iec-i` | 输出 1000 制 / 1024 制 / KiB 风格 |
| `--from=si` / `--from=iec` / `--from=iec-i` | 解析输入单位 |
| `--suffix=B` | 输出附加后缀 |
| `--field=N` | 只转换第 N 字段 |
| `--format='%.2f'` | 控制显示精度/宽度 |

**可运行示例**：

```bash
printf '1536\n1048576\n' | numfmt --to=iec-i --suffix=B
printf '1.5MiB\n' | numfmt --from=iec-i
```

预期输出：

```text
1.5KiB
1.0MiB
1572864
```

**结果解读**：`iec-i` 使用 1024 进制并显示 Ki/Mi；反向转换把 `1.5MiB` 还原为字节数。

**易错点**：SI 的 `K=1000` 与 IEC 的 `Ki=1024` 不要混用；numfmt 只做数值缩放，不验证“磁盘实际占用”。它是 GNU 扩展，macOS 默认没有，安装 coreutils 后使用 `gnumfmt`；跨平台脚本可用 awk 明确实现并固定单位规则。

## 8. 压缩与归档

### 8.1 `tar`：打包（归档）工具

```bash
tar -czvf app.tar.gz app/                  # c创建 z=gzip v显示 f=文件
tar -xzvf app.tar.gz -C /opt/app           # x解包，-C 指定目录
tar -tf app.tar.gz                         # 仅列内容
tar -czvf app.tar.gz --exclude='*.log' --exclude='cache/' app/
```
解读：`tar` 只归档，压缩由 `-z` gzip、`-j` bzip2、`-J` xz 完成。**口诀：`-czvf` 打包、`-xzvf` 解压、`-tf` 查看、`-C` 指定目录**；`--exclude` 打包时排除路径。

增量备份（`--listed-incremental` / `-g`）：
```bash
tar -czf full.tar.gz -g /tmp/app.snar app/   # 第一次：全量 + 记快照
tar -czf inc1.tar.gz -g /tmp/app.snar app/   # 之后：只打新增/变化
tar --list --incremental -f full.tar.gz      # 查看备份层
```
解读：`-g` 维护快照文件（.snar），tar 据此判断变化实现增量；恢复时按"全量→增量"顺序依次解包。

### 8.2 gzip / gunzip / zcat

```bash
gzip access.log             # 压缩成 access.log.gz（原文件消失）
gunzip access.log.gz        # 解压还原
zcat access.log.gz | head   # 不解压直接看（等价 gzip -dc）
gzip -9 access.log          # -1 最快 / -9 最高压缩率
```
解读：`gzip` 就地替换文件；`zcat` 解压到 stdout，看内容不用解压。同类还有 `bzcat`、`xzcat`。

### 8.3 bzip2 / xz：压缩率与速度对比

| 工具 | 压缩率 | 压缩速度 | 解压速度 | 典型场景 |
|---|---|---|---|---|
| `gzip` | 低 | 快 | 快 | 日志、网络传输、日常打包 |
| `bzip2` | 中 | 中 | 中 | 折中归档 |
| `xz` | 最高 | 慢 | 较快 | 软件包、长期冷存储 |

```bash
bzip2 -9 big.db                 # 生成 big.db.bz2
xz -T 4 big.db                  # -T 多线程加速
unxz big.db.xz                  # 解压
```
解读：压缩率 `xz > bzip2 > gzip`，速度反之。**高频/临时文件用 gzip，长期归档追求最小体积用 xz**。

### 8.4 zip / unzip（跨平台归档）

```bash
zip -r site.zip site/                  # 递归打包
unzip -l site.zip                      # 列内容
unzip site.zip '*.md' -d /tmp          # 只解部分文件
```
解读：`zip` 定位是**跨平台交换**（Windows 双击可解）；同机归档优先 tar 系，给别人发文件用 zip。

### 8.5 tar 管道到 ssh / 其他

```bash
tar czf - /var/www | ssh user@backup "tar xzf - -C /data/backup/www"
ssh user@web "tar czf - /etc" > etc-backup.tgz   # 远程打，本地存
```
解读：`tar czf -` 的 `-` 表示"输出到 stdout"，配合 ssh 两端**流式传输**归档，无需先传文件再解压，是"免中间态备份"的标准姿势。

### 8.6 备份最佳实践

- **3-2-1 原则**：至少 3 份拷贝、2 种介质、1 份异地。
- 备份后 `tar -tvzf` 验清单、`gzip -t` 测完整性；**定期恢复演练**——不能恢复的备份等于没有。
- 变化快的数据用增量（`-g` 或 rsync），变化慢的用全量 + xz；关键文件同时落 `sha256sum` 清单便于校验。

## 9. 编码与校验

### 9.1 md5sum / sha256sum：摘要校验

```bash
sha256sum app.tar.gz > app.sha256   # 生成清单
sha256sum -c app.sha256             # 校验，预期输出：app.tar.gz: OK
md5sum file                         # md5 只用于非安全场景
```
解读：摘要把任意文件映射成固定指纹，任何字节变化都改哈希。`-c` 按"哈希 文件名"清单校验。**md5 可构造碰撞已不安全**，安全场景用 SHA-256 以上（对应 [密码学](/kb/os/安全/02-身份认证与密码学基础/) 的"完整性"）。

::: warning macOS 差异
macOS 无 `md5sum`/`sha256sum`，对应 `md5`、`shasum -a 256`。
:::

### 9.2 base64：文本化编码

```bash
echo -n 'hello' | base64          # 预期输出：aGVsbG8=
echo 'aGVsbG8=' | base64 -d       # 解回 hello
base64 app.bin > app.b64          # 二进制 → 纯文本
```
解读：base64 把二进制映射成 64 个可打印字符，用于"二进制塞进文本通道"（邮件/JSON）；是**编码不是加密**，任何人可逆。

### 9.3 xxd / hexdump：十六进制查看

```bash
xxd file.bin | head                    # 十六进制 + 右侧 ASCII
hexdump -C file.bin | head             # 规范化分组格式
xxd -r -p hex.txt > out.bin            # -r 反向：十六进制文本转二进制
echo -n 'A' | xxd                      # 预期：41
```
解读：`xxd` 偏交互友好、可反向还原；`hexdump -C` 规范化展示（偏移/16 字节/ASCII）。排查二进制协议、看文件魔数必备。

### 9.4 iconv：字符编码转换

```bash
iconv -f UTF-8 -t GB18030 in.txt -o out.txt   # UTF-8 → 中文编码
iconv -f GBK -t UTF-8 gbk.txt -o utf8.txt     # 还原
iconv -l | grep -i gbk                        # 列出可用编码
```
解读：`-f` 源、`-t` 目标。中文最常见坑是"Windows 的 GBK 文件在 Linux 乱码"，`iconv -f GBK -t UTF-8` 一贴就好；遇到非法字符可加 `-c` 丢弃。

### 9.5 `dos2unix` / `unix2dos`：转换换行风格

**用途**：在 Unix LF 与 Windows CRLF 行尾之间转换纯文本，修复脚本出现 `bash\r`、配置解析多出 `\r` 等问题。

**常用参数**：`dos2unix FILE` 原地转 CRLF→LF；`unix2dos FILE` 原地转 LF→CRLF；`-n IN OUT` 写入新文件而不覆盖源；`-k` 尽量保留时间戳；`-q` 安静模式。不同发行版的 dos2unix 包选项略有差异，先查 `--help`。

**可运行示例**：

```bash
printf 'one\r\ntwo\r\n' > /tmp/crlf.txt
dos2unix -n /tmp/crlf.txt /tmp/lf.txt
od -An -t x1 /tmp/lf.txt
unix2dos -n /tmp/lf.txt /tmp/crlf-roundtrip.txt
od -An -t x1 /tmp/crlf-roundtrip.txt
```

预期结果关键字节：第一次 od 为 `6f 6e 65 0a ...`，第二次 od 为 `6f 6e 65 0d 0a ...`。

**结果解读**：`dos2unix` 删除每个行尾的 CR，`unix2dos` 在 LF 前补 CR；`-n` 让原文件保持不变，适合先生成对照。

**易错点**：这是行尾转换，不是 UTF-8/GBK 等字符编码转换；不要对图片、压缩包或任意二进制文件盲跑。`file`、`od` 可先确认类型与行尾；macOS 可用 Homebrew `dos2unix`，也可用 `tr -d '\r'` 处理简单文本，但后者没有 dos2unix 的编码/备份保护能力。

### 9.6 openssl：摘要与加密基础

```bash
openssl dgst -sha256 file              # 命令行摘要
openssl genrsa -out key.pem 2048       # 生成 RSA 私钥
openssl rsa -in key.pem -pubout -out pub.pem   # 导出公钥
openssl enc -aes-256-cbc -pbkdf2 -salt -in secret.txt -out secret.enc   # 加密
openssl enc -d -aes-256-cbc -pbkdf2 -in secret.enc -out secret.txt      # 解密
```
解读：`dgst` 可接多种摘要算法，`dgst -sign`/`-verify` 私钥签名公钥验签；`enc` 是文件加密（`-aes-256-cbc` 选算法、`-pbkdf2` 派生密钥、交互式输入口令）。对称/非对称/哈希三大件就是 [密码学](/kb/os/安全/02-身份认证与密码学基础/) 的落地工具。

## 10. 磁盘与内存监控微命令

### 10.1 `sync`：把脏数据刷回磁盘

```bash
sync      # 把内存中待写回（dirty）的脏页全部刷盘；拔 U 盘/断电前使用
```
解读：Linux 写文件先落页缓存（page cache），由内核后台写回；`sync` 强制立即落盘。日常不需要频繁调，内核 writeback 会兜底。

### 10.2 `hdparm`：磁盘参数与测速

```bash
sudo hdparm -t /dev/sda        # 缓存读测速；-I 查看型号/特性
```
解读：`hdparm` 面向物理盘，`-t` 测顺序读；结果受缓存影响，真实裸盘性能用 `dd iflag=direct`。内存硬件信息更全的是 `sudo dmidecode -t memory`（[Linux 实操](/kb/os/Linux/01-Linux进程与调度实操/) 已回顾）。

### 10.3 `dd` 高级：直接 IO、落盘、磁盘清零

```bash
dd if=/dev/zero of=/tmp/test.img bs=1M count=128 status=progress   # 造测试文件
dd if=/dev/zero of=/tmp/test.img bs=1M count=128 conv=fsync        # 写完强制落盘
dd if=/dev/sda of=/dev/null bs=1M iflag=direct                     # 绕过缓存测裸盘读速
```
| 参数 | 含义 |
|---|---|
| `bs=1M` `count=128` | 每块 1MB，共 128 块 |
| `iflag=direct` | 绕过页缓存直接设备 IO（测真实磁盘速度） |
| `conv=fsync` | 写完调用 fsync 确保落盘（写完立即断电的场景） |
| `status=progress` | 显示实时进度 |

```bash
# 磁盘清零/覆写（极度危险，目标盘会被清空）
sudo dd if=/dev/zero of=/dev/sdb bs=4M status=progress
sudo dd if=/dev/urandom of=/dev/sdb bs=4M status=progress   # 随机覆写更难恢复
```
::: warning 高危命令
`dd of=/dev/sdX` 会**整盘覆写**，写错目标就是灾难。永远先 `lsblk` 确认盘符再动手。
:::

### 10.4 `du` / `df` 组合：定位空间杀手

```bash
df -h                              # 看哪个分区满
du -h --max-depth=1 /var | sort -rh | head   # 逐层找最大目录
du -ah /var/log | sort -rh | head -5         # 找最大文件
```
解读：标准流程 `df -h` 锁定分区 → `du --max-depth=1 | sort -rh` 逐层下钻 → 定位具体文件。`df -i` 看 inode：**inode 满了磁盘还有空间却建不了文件**（详见 [磁盘与文件系统命令](/kb/os/Bash/05-磁盘与文件系统命令/)）。

### 10.5 `lsof` 高级：谁占用、已删除文件

```bash
lsof -i :8080                  # 谁监听/连接 8080 端口
lsof -p 1234                   # PID 1234 打开的所有文件
lsof +L1                       # "已删除但仍被进程占用"的文件
```
解读：`lsof`（list open files）配 `-i`（网络）、`-p`（进程）、`+L1`（link count=0）。**磁盘没满却放不出空间**的经典场景：日志被 `rm` 但进程仍持 fd，`lsof +L1` 找到 PID，重启/重开文件后空间才释放——删除只是去掉目录项，fd 仍指向 inode（见 [fd](/kb/os/Linux/15-文件描述符详解/)）。

## 11. 综合实战

### 11.1 find + xargs + awk：批量处理日志

```bash
# 统计近 1 天所有 .log 里访问量最高的前 10 个 IP
find /var/log -type f -name '*.log' -mtime -1 -print0 \
  | xargs -0 awk '{print $1}' \
  | sort | uniq -c | sort -rn | head -10
```
拆解：① `find -print0` 找近 1 天日志，NUL 防空格；② `xargs -0 awk '{print $1}'` 把列表喂给 awk 抽 IP；③ `sort | uniq -c | sort -rn` 计数倒序（万能四连，见 [核心命令与文件操作](/kb/os/Bash/01-核心命令与文件操作/)）；④ `head -10` 取 Top 10。

### 11.2 tee 记录管道中间态

```bash
find . -name '*.log' -print0 \
  | tee /tmp/rawlist.nul \
  | xargs -0 awk '{print $1}' | sort | uniq -c | sort -rn | head -5
```
解读：`tee` 在关键节点留档，事后直接翻中间文件核对——长管道的"断点续查"。

### 11.3 tar 增量备份

```bash
cd /backup
tar -czf full.tar.gz -g app.snar /data/app          # 周一：全量
touch /data/app/new.txt
tar -czf inc1.tar.gz -g app.snar /data/app          # 周二：只打增量
# 恢复：先全量再依次解增量
tar -xzf full.tar.gz -C /tmp/restore
tar -xzf inc1.tar.gz -C /tmp/restore
```
解读：`-g` 快照文件记录每个条目状态（mtime/新增），后续只打包变化部分；恢复按备份顺序依次解压。加进 cron 就是一套小型增量备份。

### 11.4 文本集合运算

```bash
sort a.txt -o a.sorted && sort b.txt -o b.sorted
comm -12 a.sorted b.sorted     # 共同项
comm -23 a.sorted b.sorted     # 只在 a.txt
comm -13 a.sorted b.sorted     # 只在 b.txt
# 一行流式版（进程替换，零临时文件）
comm -12 <(sort a.txt) <(sort b.txt)
```
解读：`sort -o` 结果写回自身文件（`>` 会先清空原文件，`-o` 安全）；`<(sort ...)` 让集合运算零临时文件。

## 本章小结

1. **xargs** 是管道与"吃参数命令"之间的翻译官：`-0` 征服空格、`-n` 分批、`-P` 并行、`-I {}` 占位；空输入与引号是两大坑。`ARG_MAX` 用 `getconf ARG_MAX` 查询，不能死记固定数值。
2. **GNU parallel** 在 xargs 之上补充复杂占位符、稳定输出、失败控制、重试和进度；简单 NUL 批处理仍优先默认可用的 xargs，现代工具选型见 [现代高效命令行工具](/kb/os/Bash/20-现代高效命令行工具/)。
3. **find 高级**：`-exec {} \;`/`{} +`/xargs 按需选型；组合条件记住 `!` > `-a` > `-o`，用 `\( \)` 分组，`-delete` 前务必预览。
4. **tee** 是三通：屏幕 + 文件两路，`sudo tee` 解决 root 写文件，管道中插 tee 是调试利器。
5. **timeout / watch**：`timeout -k` 限时强杀（退出码 124），`nohup`/`( cmd & )` 后台脱管；macOS 的 `watch` 需要单独安装，不是 coreutils 的 `gwatch`。
6. **进程替换** `<( )`/`>( )` 把命令输出当文件、零临时文件；`exec 3<>` 自定义 fd 呼应文件描述符原理。
7. **文本排版与流工具**：`nl`/`column`/`fmt`/`fold`/`pr` 排版，`expand`/`unexpand` 管 Tab，`rev` 反转行，`printf` 做可预测格式输出，`yes` 生成有限测试流，`od` 看原始字节。
8. **安全文本改写**：moreutils 的 `sponge` 解决读写同一路径，`envsubst` 只替换白名单变量；二进制字符串线索回看 [二进制与安全审计命令](/kb/os/Bash/16-二进制与安全审计命令/)，结构化配置使用 [结构化数据处理命令](/kb/os/Bash/18-结构化数据处理命令/)。
9. **数值工具**：`bc` 做高精度小数，`expr` 维护旧式表达式，`factor` 做质因数分解，`numfmt` 在 SI/IEC 人类单位间转换。
10. **压缩归档**：tar 打 gzip/bzip2/xz，压缩率与速度成反比；`-g` 增量、管道到 ssh、3-2-1 备份原则。
11. **编码校验**：`sha256sum -c` 验证完整性、base64 文本化、xxd 看二进制、iconv 转编码；`dos2unix`/`unix2dos` 只改 LF/CRLF 行尾，不是字符集转换，openssl 加解密对应 [密码学](/kb/os/安全/02-身份认证与密码学基础/)。
12. **磁盘监控**：`sync` 刷盘、`dd iflag=direct/conv=fsync` 测真实 IO、`du`/`df` 组合定位空间、`lsof +L1` 抓"已删除仍占用"。

## 动手实验

1. 在 `/tmp/lab` 建 5 个**带空格**的文件（`touch "my file 1.txt"`…），用 `find -print0 | xargs -0` 移到 `dir/` 下，再用 `find | xargs` 对比验证后者会碎。
2. `seq 1 8 | xargs -P 4 -I {} sh -c 'sleep 1; printf "job %s done\n" "$1"' _ {}` 记耗时，与 `-P 1` 对比；若安装 GNU parallel，再用 `parallel -j 4 --keep-order` 对照输出顺序。
3. 造 10 个 `*.tmp` 文件，先 `find . \( -name '*.tmp' -o -name '*.bak' \) -exec echo {} \;` 预览，确认后换 `-delete` 真正删除。
4. `timeout 3 sleep 100; echo $?` 验证 124；Linux 用 `watch -n 1 -d 'ss -s'`，macOS 先安装 `watch` 或改用 `while` 循环。
5. 对同一目录先后 `tar -czf full.tar.gz -g s.snar dir/` 与（新增一文件后）`tar -czf inc.tar.gz -g s.snar dir/`，用 `tar -tf` 对比两包差异。
6. 造 `a.txt`/`b.txt` 各含 5 行，用 `comm -12/-23/-13` 求共同项与两向差集，再用进程替换写成一行式。
7. `sha256sum` 生成清单并用 `-c` 校验，然后 `echo x >> file` 改一个字节再校验，观察 `FAILED`。
8. 对一段 80 列文本分别执行 `fmt -w 30`、`fold -s -w 30`、`pr -2 -t`，比较“语义排版、机械折行、分页多栏”的区别。
9. 用 `printf 'A\r\nB\r\n'` 生成 CRLF，先用 `od -An -t x1` 确认 `0d 0a`，再 `dos2unix -n`/`unix2dos -n` 往返转换；不要对二进制实验。
10. 安装 moreutils 后用 `sort file | sponge file` 原地排序；设置 `APP_HOST`/`APP_PORT` 用 `envsubst '$APP_HOST $APP_PORT'` 生成配置，并验证 `$HOME` 未被替换。
11. 分别用 `bc`、Bash `$(( ))`、`expr` 计算 `5/2`，解释整数与小数差异；再用 `numfmt` 比较 SI 与 IEC，最后用 `factor 60` 验证质因数分解。

<details><summary>参考答案</summary>

1. 因为 `rm` 不读 stdin，管道传的是数据流不是参数；正确做法：`find . -name '*.tmp' -exec rm {} +` 或 `find . -name '*.tmp' -print0 | xargs -0 rm`。
2. `\;` 每个文件调用一次命令；`{} +` 把一批文件合并成一次调用，减少进程启动开销所以更快。后者要求 `{}` 是命令最后一个参数。
3. 重定向 `>` 由**当前 shell**（非 root）执行所以无权限；`sudo tee` 把 root 权限赋予写文件的 `tee`，重定向只负责把 echo 的输出接过去。
4. GNU `timeout` 因超时被杀返回 **124**；命令正常结束则返回其自身退出码。脚本用 `$? == 124` 判断是否超时。
5. 输出两个文件中**共同的行**（`-1` 隐藏第 1 列、`-2` 隐藏第 2 列、`-3` 隐藏第 3 列）。前置条件：两个输入都必须先排序。
6. `iflag=direct` 绕过页缓存直接设备 IO，测真实磁盘速度（排除缓存干扰）；`conv=fsync` 写完强制 fsync 确保数据真正落盘。
7. 用于找出"文件已被删除但进程仍持有 fd"的情况（link count=0）。`rm` 只去掉目录项，进程 fd 仍指向 inode，空间要等进程释放 fd（重启/重开文件）后才回收。
8. 用 `-g /path/snap.snar`（`--listed-incremental`）：首次全量并记快照，后续只打增量。恢复时**按备份顺序**先解全量、再依次解增量。
9. `fmt` 按段落与单词重排，`fold` 按列/字节机械折行；`pr` 是打印分页排版，不应作为稳定结构化接口。
10. `expand`/`unexpand` 改 Tab 与空格；`dos2unix`/`unix2dos` 改 LF 与 CRLF 行尾，二者都不等于字符集转换。
11. `sponge` 先读完 stdin 再写目标，避免 `sort file > file` 先清空；它仍可能因缓存/写入中断而不具备事务保证。
12. 单引号阻止当前 Bash 展开 `$A`，让 envsubst 收到变量名格式串；envsubst 只替换变量，不执行 `$(date)`，但未列入白名单的变量也不会替换。
13. `bc` 做精确小数表达式，`expr` 是旧式整数/字符串工具，`factor` 分解整数，`numfmt` 转换人类单位；Bash `$(( ))` 本身只做整数。

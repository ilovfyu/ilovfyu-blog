::: abstract 本章定位
本目录聚焦《Operating System Concepts》Ch6 Synchronization Tools 与 Ch7 Synchronization Examples：回答"多个执行单元共享数据时，操作系统如何保证安全"这一核心问题。从竞态条件出发，先解决临界区互斥（锁），再到更高级的信号量、管程、条件变量，最后用经典问题检验理解，并延伸到现代无锁编程与 Linux 内核工程实现。
:::

并发是操作系统里"最容易出错、最考验功力"的主题。两个线程 `i++` 都可能把 100000 变成 99999；死锁了系统直接卡死。本目录要建立的能力是：

1. **看得懂**：能识别一段并发代码里的竞态条件（race condition）与临界区。
2. **写得出**：能用 mutex / semaphore / condition variable 正确实现生产者-消费者、读者-写者、哲学家进餐。
3. **讲得清**：能对比"自旋锁 vs 阻塞锁""信号量 vs 互斥锁 vs 管程""锁 vs 无锁编程"各自的取舍。
4. **看得见**：能在 Linux 上用 strace / perf / 源码观察到内核里的 spinlock、futex、rwlock 是怎么工作的。

## 2. 推荐学习顺序

### 2.1 零基础完整路线（推荐）

1. **建立直觉**：读本页，先动手跑一遍"实验清单"里的 `i++` 竞态 demo，亲眼看到 100000 变成 99999。这一步能让你对"为什么需要同步"产生真实恐惧，后面学什么都快。
2. **[临界区问题与互斥实现](/kb/os/同步异步/01-临界区问题与互斥实现/)**：理解问题定义（竞态、临界区三要求）与最底层的互斥手段（软件算法 + 硬件原子指令）。这是全部同步理论的地基。
3. **[信号量与同步原语](/kb/os/同步异步/02-信号量与同步原语/)**：从"一个锁"升级到"一个计数器"，理解 wait/signal、自旋与阻塞的取舍，对比 Linux 的各类锁。
4. **[管程与条件变量](/kb/os/同步异步/03-管程与条件变量/)**：学习更不容易出错的抽象——把锁和等待条件封装在一起，`pthread_cond_wait` 是重点中的重点。
5. **[经典同步问题详解](/kb/os/同步异步/04-经典同步问题详解/)**：用前四篇的知识解三大经典问题。面试 80% 的并发题都出在这里。
6. **[现代同步原语与无锁编程](/kb/os/同步异步/05-现代同步原语与无锁编程/)**：进阶。理解了锁的代价之后，再看 CAS、ABA、RCU 等无锁技术。
7. **回到实践**：用本页"实验清单"把所有示例代码编译运行一遍，再用"自测题"检验。

::: tip 学习顺序的底层逻辑
每一篇都解决上一篇留下的痛点：`01` 解决"怎么保证互斥"→ `02` 解决"一个互斥不够，需要计数同步" → `03` 解决"信号量代码容易写错，需要结构化抽象" → `04` 是综合运用 → `05` 解决"锁太慢，需要更低成本的并发"。
:::

::: important 实验环境
以下所有实验基于 Linux（虚拟机 / WSL2 / 云主机均可）。macOS 也支持 pthread，但 `sem_*` 部分需要额外适配。全部代码可用 `gcc -pthread` 编译（macOS 用 `-lpthread` 亦可）。
:::

### 4.1 竞态演示：两个线程对 `i++`

```c
// race.c —— 用 100000 次 i++ 亲眼看到竞态
#include <pthread.h>
#include <stdio.h>

int counter = 0;
#define N 100000

void *worker(void *arg) {
    for (int i = 0; i < N; i++) counter++;  // 非原子！read-modify-write
    return NULL;
}

int main() {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, worker, NULL);
    pthread_create(&t2, NULL, worker, NULL);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    printf("期望 200000，实际 %d\n", counter);
    return 0;
}
```

```bash
gcc -pthread -O0 race.c -o race
for i in $(seq 1 10); do ./race; done   # 多次运行，结果几乎都不是 200000
gcc -pthread -O2 race.c -o race2
./race2                                  # -O2 优化后可能稳定为 200000（编译器重排/合并！）
```

::: warning 优化层级的陷阱
`-O0` 下 race 明显，`-O2` 下结果可能"意外正确"——编译器把循环合并或指令重排掩盖了竞态。这说明：**竞态是调度与硬件层面的问题，能不能复现取决于编译器和 CPU，绝不能靠"试一次没出错"来判断代码正确**。
:::

## 6. 与相邻主题的关系

- **[线程](/kb/os/进程线程/04-线程概念与多线程模型/)**：同步的前提是并发。线程之间共享地址空间，才产生对共享数据的竞争；进程默认隔离，反而天然免于数据竞争（但进程间仍需 IPC 同步）。
- **[死锁](/kb/os/死锁/01-死锁特征与必要条件/)**：同步加锁只是必要条件，锁用的顺序不对就会死锁。同步 → 死锁是自然延伸，务必连起来看。
- **[Linux](/kb/os/Linux/01-Linux进程与调度实操/)**：Linux 是验证同步理论的完美实验场——`pthread` 是 glibc 对"锁原语"的工程实现，`futex` 是内核调度与同步的接口。
- **[IO](/kb/os/IO/01-IO硬件与设备控制/)**：IO 层面的异步（`epoll`、DMA 中断）是"同步/异步"另一条战线，本目录只聚焦并发线程同步；两条线在"异步编程"处交汇。

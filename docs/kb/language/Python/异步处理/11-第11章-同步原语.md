> 对应 Matthew Fowler《Python Concurrency with asyncio》第 11 章。本文重新组织概念并使用原创案例，不替代原书。

## 目标 / 地图

- `Lock` 保护跨暂停点的不变量；`Semaphore` 限制并发容量；`BoundedSemaphore` 还能发现多余释放。
- `Event` 广播“状态已发生”；`Condition` 在持锁条件下等待谓词。
- 重点理解：单线程事件循环仍会 race，取消也可能破坏状态。

传数据通常选 [队列](/kb/language/Python/异步处理/12-第12章-异步队列/)；保护共享状态才选本章原语。

## 概念机制

事件循环通常只有一个线程，但任务会在 `await` 主动让出执行权。若“读—改—写”之间暂停，两个任务可能都读到旧值，再覆盖彼此结果。没有 `await` 的短片段不会被同一循环中的另一任务抢占；一旦不变量跨越暂停点，就要同步。

`Lock` 只有锁定/未锁定两态，且不可重入。首选 `async with lock`，让异常和取消路径也释放锁。锁应只覆盖状态更新，不要覆盖慢网络 I/O。

`Semaphore(n)` 允许 n 个持有者，适合连接槽位等容量限制，但“并发 n”不等于“每秒 n 次”。普通信号量可释放到初值以上；固定容量资源宜用 `BoundedSemaphore`，重复 `release()` 会抛 `ValueError`。

`Event` 是布尔门闩：`set()` 置位并唤醒全部等待者，后来的等待者也立即通过；`clear()` 复位。它不累计信号，也不携带数据。

`Condition` 组合锁和通知。`wait()` 在持锁时原子地释放锁、等待、再重获锁。通知仅表示“状态可能变了”，所以应使用 `wait_for(predicate)`，或在 `while` 中重查。修改状态和 `notify()` 必须持有同一把锁。

等待原语时取消，任务通常从等待队列移除；已经获得原语后取消，则必须释放。把获取和释放放在同一个 `async with`，清理后不要无故吞掉 `CancelledError`。

## API

| API | 语义 |
|---|---|
| `Lock()` / `async with lock` | 互斥进入临界区 |
| `lock.locked()` | 瞬时诊断，不可用于检查后获取 |
| `Semaphore(n)` | 至多 n 个并发持有者 |
| `BoundedSemaphore(n)` | 超额释放时报错 |
| `Event.wait/set/clear` | 等待、广播置位、复位 |
| `Condition(lock=None)` | 可共享锁的条件变量 |
| `wait()` / `wait_for(pred)` | 等通知并重获锁 / 等谓词成立 |
| `notify(n)` / `notify_all()` | 持锁唤醒至多 n 个 / 全部等待者 |

这些对象不是线程同步工具，也没有 `timeout=` 参数。

## 完整原创可运行示例

档案室开门后最多容纳两人；锁保护跨 `await` 的访问计数，条件变量让主管等待所有访客离开。

```python
import asyncio


class Archive:
    def __init__(self) -> None:
        self.opened = asyncio.Event()
        self.seats = asyncio.BoundedSemaphore(2)
        self.lock = asyncio.Lock()
        self.empty = asyncio.Condition(self.lock)
        self.inside = 0
        self.visits = 0

    async def visit(self, name: str) -> None:
        await self.opened.wait()
        async with self.seats:
            async with self.empty:
                self.inside += 1
                old = self.visits
                self.visits = old + 1
                print(name, "entered", self.inside)
            try:
                await asyncio.sleep(0.05)  # 慢操作不占状态锁
            finally:
                async with self.empty:
                    self.inside -= 1
                    print(name, "left", self.inside)
                    if self.inside == 0:
                        self.empty.notify_all()

    async def wait_empty(self, expected_visits: int) -> None:
        async with self.empty:
            await self.empty.wait_for(
                lambda: self.inside == 0 and self.visits == expected_visits
            )


async def main() -> None:
    archive = Archive()
    tasks = [asyncio.create_task(archive.visit(f"v{i}")) for i in range(5)]
    archive.opened.set()
    while True:  # 先确认至少一人进入，避免初始空状态立即满足谓词
        async with archive.lock:
            if archive.inside:
                break
        await asyncio.sleep(0)
    await archive.wait_empty(len(tasks))
    await asyncio.gather(*tasks)
    print("visits", archive.visits)


asyncio.run(main())
```

## 时序

```text
访客 --wait--> Event --set/广播--> 访客
访客 --acquire--> Semaphore(2) --进入--> Lock/Condition
主管 --wait_for(inside == 0)--> 释放锁并等待
最后访客 --inside -= 1; notify_all--> 主管重获锁、重查谓词
```

被通知不等于立即运行；等待者还要等通知者释放锁。

## 陷阱

- 误认为单线程没有 race；复合状态操作跨 `await` 即可交错。
- 手写获取后漏释放、持锁执行慢 I/O、锁顺序不一致导致死锁。
- 把信号量当速率限制器，或用普通信号量掩盖重复释放。
- 把 `Event` 当可累计消息；快速 `set(); clear()` 可能被后来者错过。
- 未持锁调用 `Condition.notify()`，或被通知后不重查谓词。
- 吞掉 `CancelledError`，使上层误判任务正常完成。

## 现代 Python 补充

- 3.11+ 用 `TaskGroup` 管理同生命周期任务，用 `asyncio.timeout()` 限定一段等待的总时限。
- `CancelledError` 属于 `BaseException`；恢复不变量应放在 `finally`，通常清理后继续抛出。
- 3.12 eager task factory 会改变“创建后稍晚才执行”的时序假设；同步正确性不能依赖该假设。
- 原语应在运行循环内构造和使用，不要跨事件循环共享。详见 [现代 asyncio 补遗](/kb/language/Python/异步处理/15-现代-asyncio-补遗/)。

## 实践清单

- [ ] 明确写出不变量和全部暂停点。
- [ ] 获取/释放由同一 `async with` 管理，慢 I/O 移出临界区。
- [ ] 多锁有统一顺序；容量和速率限制没有混淆。
- [ ] `Condition` 围绕谓词，取消路径能恢复状态。
- [ ] 用 `sleep(0)`、随机延迟和取消测试交错。

> 对应 Matthew Fowler《Python Concurrency with asyncio》第 13 章。示例与论述均为原创。

## 目标 / 地图

- 默认用 `create_subprocess_exec()`；确需 shell 语法才用 `create_subprocess_shell()`。
- 用 `PIPE` 捕获数据，短输出用 `communicate()`，长输出可流式读取。
- 并发启动要限量；取消等待任务不会自动杀死操作系统进程。
- 同时排空 stdout/stderr，避免管道死锁；POSIX 上必要时取消整个进程组。

容量限制见 [第11章 同步原语](/kb/language/Python/异步处理/11-第11章-同步原语/)；结构化取消见 [现代 asyncio 补遗](/kb/language/Python/异步处理/15-现代-asyncio-补遗/)。

## 概念机制

`create_subprocess_exec(program, *args)` 直接保留参数边界，用户输入不会被解释成重定向或第二条命令。`create_subprocess_shell(command)` 交给 shell 解析；若拼接不可信输入，就可能 shell 注入。POSIX shell 可用 `shlex.quote()` 处理单个外部值；Windows `cmd.exe`、PowerShell 等必须遵循各自规则。跨平台代码应优先使用 exec，避免拼接 shell 命令。

`stdin/stdout/stderr=asyncio.subprocess.PIPE` 建立异步管道。`communicate(input)` 在输入非 `None` 时发送并关闭 stdin，同时读取 stdout/stderr 并等待退出；Python 3.12+ 即使 `input=None` 也会关闭 stdin。面向 3.11 且依赖 EOF 的协议应显式关闭 `process.stdin`。若手写 `await process.wait()` 却不读取已满的管道，子进程会阻塞写入，父进程又等它退出，形成 pipe deadlock。

持续日志可从 `process.stdout` 的 `StreamReader` 逐行读取，但 stderr 也必须同时消费，例如另建任务，或将 `stderr=STDOUT` 合流。流式读取的 `limit` 过小时，超长单行可能触发限制错误。

创建很多协程并不意味着可以无限创建 OS 进程；用信号量或队列限制并发。取消正在 `await communicate()` 的任务只取消 Python 等待者，不保证终止子进程。关闭协议应为：请求温和终止、限时等待、升级强杀、最终 `wait()` 回收。

POSIX 程序可能再派生进程。用 `start_new_session=True` 建立新会话后，可向 `os.getpgid(pid)` 对应进程组发 `SIGTERM/SIGKILL`。这是平台相关能力；Windows 需要其进程创建标志和控制事件方案。

## API

| API | 用途 |
|---|---|
| `create_subprocess_exec(prog, *args, ...)` | 安全传递独立参数 |
| `create_subprocess_shell(cmd, ...)` | 执行 shell 语法，调用方负责引用 |
| `PIPE` / `STDOUT` / `DEVNULL` | 管道、合流、丢弃 |
| `await process.communicate(input)` | 并发 I/O 并等待退出 |
| `process.stdout.readline()` | 流式读取一行 |
| `await process.wait()` | 等退出并取得 return code |
| `terminate()` / `kill()` / `send_signal()` | 请求终止、强杀、发送信号 |
| `process.returncode` | `None` 或退出码；POSIX 负数可表示信号 |

## 完整原创可运行示例

仅调用当前 Python 解释器，跨平台运行；信号量限制并发，取消时先 terminate，再限时升级 kill，且 stdout/stderr 由 `communicate()` 同时排空。

```python
import asyncio
import sys


CHILD = """
import sys, time
name, delay = sys.argv[1], float(sys.argv[2])
print('start:' + name, flush=True)
print('diagnostic:' + name, file=sys.stderr, flush=True)
time.sleep(delay)
print('done:' + name, flush=True)
"""


async def stop(process):
    if process.returncode is not None:
        return
    process.terminate()
    try:
        await asyncio.wait_for(process.wait(), 0.5)
    except TimeoutError:
        process.kill()
        await process.wait()


async def run_one(name, delay, slots):
    async with slots:
        process = await asyncio.create_subprocess_exec(
            sys.executable, "-c", CHILD, name, str(delay),
            stdout=asyncio.subprocess.PIPE,
            stderr=asyncio.subprocess.PIPE,
        )
        communication = asyncio.create_task(process.communicate())
        try:
            out, err = await asyncio.shield(communication)
        except asyncio.CancelledError:
            await stop(process)
            # communicate 仍在排空两个 PIPE；必须等待它完成后再传播取消。
            await communication
            raise
        return name, process.returncode, out.decode(), err.decode()


async def main():
    slots = asyncio.Semaphore(2)
    results = await asyncio.gather(
        *(run_one(f"job-{i}", 0.05 * i, slots) for i in range(4))
    )
    for name, code, out, err in results:
        print(name, code, out.strip(), err.strip())


asyncio.run(main())
```

## 时序

```text
父任务 --acquire slot--> create process --communicate--> 排空 stdout/stderr
子进程 --写两管道/退出-------------------------------> 父任务取得输出和退出码
取消：父任务 --terminate--> 限时 wait --仍存活则 kill--> wait 回收
```

流式模式中应同时运行“读 stdout”“读 stderr”“等退出”，而不是先完全读一边。

## 陷阱

- 把用户值拼入 shell 字符串，造成命令注入；exec 参数列表是默认答案。
- `wait()` 前不排空 `PIPE`，因缓冲区写满而互相等待。
- `communicate()` 收集无限输出，导致内存峰值；长流应逐块读取或写文件。
- 只读 stdout，不读 stderr；任一管道都可能写满。
- 将任务取消误当成进程取消，留下孤儿进程或僵尸。
- 只杀父进程，遗留其后代；需要时建立并终止进程组。
- 解码时假定平台默认编码；协议应明确编码和错误策略。
- 无限并发创建进程，耗尽文件描述符、内存和调度资源。

## 现代 Python 补充

- 3.11+ 可用 `TaskGroup` 管理一批命令；某个失败时要在各命令的取消清理中终止对应进程。
- `asyncio.timeout()` 可覆盖“启动后完成”的期限，但超时异常本身仍不会杀进程。
- `Process` 不是线程安全对象，也没有 `poll()`；使用 `returncode`。
- Windows 默认 Proactor 循环支持异步子进程；进程组信号代码必须按平台分支。详见 [现代 asyncio 补遗](/kb/language/Python/异步处理/15-现代-asyncio-补遗/)。

## 实践清单

- [ ] 默认 exec，shell 输入逐值引用且来源可信。

- [ ] 并发进程数有上限，退出码和 stderr 被记录。

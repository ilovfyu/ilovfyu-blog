## 本章目标

- 理解为什么同步数据库驱动会阻塞事件循环，并使用 asyncpg 连接 PostgreSQL。
- 定义可重复执行的 schema，并掌握 execute/fetch/fetchrow/fetchval。
- 用有界连接池并发执行独立查询，不越过数据库容量。
- 用事务上下文保证提交/回滚，理解嵌套事务和手动控制。
- 用异步生成器与 server-side cursor 流式消费大结果集。
- 为池获取、语句、事务和流式处理设置清晰 timeout 与资源清理边界。

## 概念精讲

### 5.1 为什么需要 asyncpg

传统同步驱动在连接、发送查询、等待服务端和读取结果时阻塞调用线程。把它直接放入协程会冻结事件循环。`asyncpg` 将 PostgreSQL 协议与 asyncio 集成，在网络等待处挂起 Task；这使多个**独立**查询可以通过多个连接重叠等待。

异步不会降低数据库执行一条 SQL 的成本。并发过高会争夺 CPU、锁、缓存和 I/O，反而抬高延迟。数据库连接是昂贵且有状态的资源，必须以池容量形成硬边界。

### 5.2 建立与关闭连接

`asyncpg.connect()` 可接收 DSN 或独立参数，返回 `Connection`。凭据应来自环境变量或密钥系统，不写入代码。连接使用后 `await connection.close()`；若连接失效且正常关闭不可行，可终止，但常规路径优先优雅关闭。

单连接不应被多个协程同时执行操作，否则可能出现 “another operation is in progress”。需要并发时从 Pool 为每个操作租借独立连接。

### 5.3 Schema 设计

原书以产品、SKU、颜色和尺寸等电商数据建立实验 schema。DDL 不只是示例准备：主键、唯一约束、非空约束和外键决定并发写入时的正确性。`CREATE TABLE IF NOT EXISTS` 便于教学脚本重跑，但正式 schema 应通过迁移工具版本化，避免应用启动时竞态修改结构。

### 5.4 查询 API 与参数化

- `execute()` 执行不需要行集的语句，返回如 `INSERT 0 1` 的状态字符串。
- `executemany()` 对参数序列重复执行命令，原子性和性能应查所用版本；超大批量通常考虑 COPY。
- `fetch()` 返回 `Record` 列表，会把全部结果装入内存。
- `fetchrow()` 返回第一行或 `None`。
- `fetchval()` 返回第一行指定列的标量。

asyncpg 使用 PostgreSQL 风格 `$1`、`$2` 参数。绝不能用 f-string 拼接用户值；参数化既防 SQL 注入，也让类型编码明确。表名/列名不能作为普通值参数，需要白名单构造标识符。

### 5.5 连接池与并发边界

`asyncpg.create_pool(min_size=..., max_size=...)` 管理连接复用。`async with pool.acquire() as conn` 保证异常、取消时连接归还。池不是“无限并发加速器”：同时执行查询的上限大致由 `max_size` 决定，多余任务在 acquire 队列等待。

池大小应结合 PostgreSQL `max_connections`、应用副本数、管理预留、每查询成本和压测确定。例如 10 个副本各开 20 条连接就是 200 条。应用层 Semaphore 可把并发限制在小于池容量的值，为事务、健康检查等留余量；也可以依靠 acquire 排队，但要给队列等待总期限。

原书用随机 SKU 展示大量独立 INSERT。实际批量导入优先单事务批处理、`executemany` 或 COPY，而不是盲目“一行一个并发 Task”。并发最适合彼此独立且数据库有余量的查询。

### 5.6 事务、嵌套事务与手动管理

`async with connection.transaction():` 正常退出提交，异常或取消回滚。事务内所有语句必须使用同一连接；不能每条语句分别 `pool.acquire()`，否则不在同一事务。

在已有事务中再次进入 `connection.transaction()`，asyncpg 使用 PostgreSQL savepoint 表达嵌套范围。内层失败可回滚到保存点，外层是否继续由调用方决定；若异常逃出外层，整个事务仍回滚。

手动方式是 `tx = connection.transaction(); await tx.start(); ...; await tx.commit()`，异常路径必须 `rollback()`。它适合事务范围无法用单个上下文表达的少数情况，但更易遗漏取消和回滚。事务应尽量短，尤其不要在持有数据库锁时等待 HTTP 或用户输入。

### 5.7 异步生成器与流式游标

含 `yield` 的 `async def` 是异步生成器，调用后返回异步迭代器；`async for` 每次请求下一项，生成器可在产生值之间 `await`。这天然表达背压：消费者慢，生产者就不会无限预取。

`connection.cursor(query, ..., prefetch=n)` 使用服务端游标分批获取结果，避免 `fetch()` 一次性占满内存。asyncpg 的非 scrollable cursor 必须在事务中使用。整个迭代期间连接被占用，慢消费者会延长事务并占住池槽；因此要限制处理时间、选择合理 prefetch，必要时把行复制到有界队列后尽快释放事务，但这会改变一致性与内存权衡。

## 关键API

| API | 用途 | 资源/语义边界 |
|---|---|---|
| `asyncpg.connect(dsn)` | 创建单连接 | 用后 `await close()` |
| `asyncpg.create_pool(...)` | 创建有界连接池 | `async with pool` 或显式 close |
| `pool.acquire()` | 租借连接 | 必须归还；取消安全依赖上下文 |
| `conn.execute()` | 执行命令 | 返回状态字符串 |
| `conn.fetch/fetchrow/fetchval()` | 获取多行/单行/标量 | `fetch` 会完整物化结果 |
| `conn.transaction()` | 事务/嵌套保存点上下文 | 同一事务固定同一连接 |
| `conn.cursor(..., prefetch=n)` | 流式结果游标 | 通常要求事务，期间占连接 |
| `conn.copy_records_to_table()` | 高吞吐批量导入 | 大批写入常优于逐行并发 |

## 完整可运行原创示例

要求 Python 3.11+、PostgreSQL 和 `asyncpg`：`python -m pip install asyncpg`。设置 `DATABASE_URL`，例如 `postgresql://postgres:postgres@localhost/postgres`。脚本只创建演示表，展示池边界、参数化 UPSERT、事务回滚语义和流式游标；所有资源均由上下文关闭。

```python
import asyncio
import os
from collections.abc import AsyncIterator

import asyncpg

SCHEMA = """
CREATE TABLE IF NOT EXISTS asyncio_note_product (
    sku text PRIMARY KEY,
    name text NOT NULL,
    price_cents integer NOT NULL CHECK (price_cents >= 0),
    stock integer NOT NULL CHECK (stock >= 0)
)
"""


async def upsert_product(
    pool: asyncpg.Pool,
    limiter: asyncio.Semaphore,
    sku: str,
    price_cents: int,
) -> None:
    async with limiter:
        async with pool.acquire() as conn:
            await conn.execute(
                """
                INSERT INTO asyncio_note_product(sku, name, price_cents, stock)
                VALUES($1, $2, $3, 10)
                ON CONFLICT (sku) DO UPDATE SET price_cents = EXCLUDED.price_cents
                """,
                sku,
                f"演示商品 {sku}",
                price_cents,
                timeout=2.0,
            )


async def transfer_stock(pool: asyncpg.Pool, source: str, target: str) -> None:
    async with pool.acquire() as conn:
        async with conn.transaction():
            changed = await conn.fetchval(
                """
                UPDATE asyncio_note_product
                SET stock = stock - 1
                WHERE sku = $1 AND stock > 0
                RETURNING stock
                """,
                source,
                timeout=2.0,
            )
            if changed is None:
                raise ValueError(f"{source} 库存不足或不存在")
            await conn.execute(
                "UPDATE asyncio_note_product SET stock = stock + 1 WHERE sku = $1",
                target,
                timeout=2.0,
            )


async def stream_products(pool: asyncpg.Pool) -> AsyncIterator[asyncpg.Record]:
    async with pool.acquire() as conn:
        async with conn.transaction(readonly=True):
            cursor = conn.cursor(
                "SELECT sku, price_cents, stock FROM asyncio_note_product ORDER BY sku",
                prefetch=50,
            )
            async for row in cursor:
                yield row


async def main() -> None:
    dsn = os.environ.get(
        "DATABASE_URL", "postgresql://postgres:postgres@localhost/postgres"
    )
    limiter = asyncio.Semaphore(3)  # 小于池上限，为事务/流式读取留连接
    async with asyncpg.create_pool(
        dsn,
        min_size=1,
        max_size=5,
        command_timeout=3.0,
    ) as pool:
        async with asyncio.timeout(5.0):  # 包含获取池连接的排队时间
            async with pool.acquire() as conn:
                await conn.execute(SCHEMA)

            async with asyncio.TaskGroup() as group:
                for index in range(8):
                    group.create_task(
                        upsert_product(pool, limiter, f"SKU-{index:03}", 1000 + index)
                    )

            await transfer_stock(pool, "SKU-000", "SKU-001")

            async for product in stream_products(pool):
                print(dict(product))


if __name__ == "__main__":
    asyncio.run(main())
```

若 `transfer_stock` 的第一条更新失败，抛出的异常使事务回滚；若第二条语句异常，第一条库存扣减同样回滚。演示表名带专用前缀，但脚本不会删除表或已有数据。

## 执行流程/时序说明

```text
main          创建 pool(min=1,max=5) -> 建表 -> 启动 8 个 upsert Task
Semaphore     同时仅 3 个 upsert 进入；其余不占连接
Pool          每个进入者 acquire 独立连接 -> 执行 SQL -> release
TaskGroup     等 8 项全部成功；任一失败则取消兄弟并汇报 ExceptionGroup
事务          acquire 一连接 -> BEGIN -> 扣 source -> 加 target -> COMMIT
流式读取      acquire 一连接 -> 只读事务 -> cursor 分批拉取 -> async for -> COMMIT/release
退出          timeout 作用域结束 -> pool 上下文等待连接关闭
```

流式生成器的资源作用域跨越整个 `async for`。消费者若提前退出，异步生成器应被及时关闭；顶层 `asyncio.run()` 会负责关闭尚存异步生成器，但业务代码不应依赖程序退出才释放池连接。

## 常见错误

- 在协程中调用 psycopg2 等同步驱动，阻塞事件循环；或用线程包装后误以为获得原生取消。
- 多个并发协程共享同一个 Connection，触发操作冲突或混淆事务状态。
- 池 `max_size` 按单实例设置，却忽略应用副本总数和 PostgreSQL 连接预算。
- 每条事务语句分别 acquire，实际上落到不同连接，失去原子性。
- 手动事务只写 commit，不在所有异常和取消路径 rollback。
- 使用 f-string 拼接值造成 SQL 注入；动态标识符也未做白名单。
- 用 `fetch()` 读取百万行导致内存峰值；改用 cursor 后又忘记事务要求。
- 在流式游标循环内执行慢 HTTP 调用，长期占用连接和快照。
- 只有 statement timeout，没有 pool acquire/整体业务 timeout，连接耗尽时无限排队。
- 一行一个 Task 并发导入海量数据；任务内存和数据库争用可能比 COPY/批处理差得多。

## 现代Python补充

- `TaskGroup` 适合“一批独立写入必须全部被观察”的并发结构；但数据库原子性仍只能由事务保证。TaskGroup 取消兄弟不等于回滚已经提交的其他连接。
- `asyncio.timeout()` 可覆盖 `pool.acquire()` 排队、SQL 和处理逻辑；asyncpg 的 `timeout=` / `command_timeout` 控制具体命令。应用总期限与数据库 `statement_timeout` 应分层配置。
- 原书的手动 loop 样板在数据库脚本中也应由 `asyncio.run()` 或 `Runner` 替代，确保异步生成器和执行器得到关闭。
- `ExceptionGroup` 可能包含批量任务的多个失败，可用 `except* asyncpg.PostgresError` 分类；不要因此忽略任务取消后的连接归还。
- Python 异步生成器支持 `aclose()`。若手工只消费部分结果，可保存生成器并在 `finally` 调用 `await generator.aclose()`；通常完整 `async for` 或 `contextlib.aclosing()` 更清晰。

## 实践清单

- [ ] 使用异步驱动，凭据来自环境/密钥系统。
- [ ] Pool 有明确生命周期、总连接预算、`min_size`/`max_size` 和获取期限。
- [ ] 一个并发数据库操作租借一个连接；一个事务始终固定同一连接。
- [ ] 所有 SQL 值参数化，动态标识符来自白名单。
- [ ] 事务尽量短，并覆盖异常与取消回滚路径。
- [ ] 批量写入比较并发单行、executemany 与 COPY，而非默认堆 Task。
- [ ] 大结果集使用游标/prefetch，并评估慢消费者占用连接的时间。
- [ ] 同时监控池等待、活跃连接、查询延迟、锁等待、事务时长和数据库负载。
- [ ] 用冲突、超时、取消、连接断开和消费者提前退出测试资源归还。

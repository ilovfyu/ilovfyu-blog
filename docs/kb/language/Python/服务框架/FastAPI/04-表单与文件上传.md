> 基线：FastAPI 0.141.1（2026-07-29 latest）、Python 3.10+、Pydantic v2。

浏览器表单和文件上传不使用 JSON 请求体。普通表单通常是 `application/x-www-form-urlencoded`，包含文件时使用 `multipart/form-data`。FastAPI 通过 `Form()` 和 `File()` 声明这些来源，并提供 Starlette 的 `UploadFile` 抽象。

## 1. 安装与协议基础

推荐安装：

```bash
uv add "fastapi[standard]"
```

表单解析依赖 `python-multipart`，标准安装通常已包含它。若使用最小依赖组合，需要单独安装：

```bash
uv add python-multipart
```

两种常见媒体类型：

- `application/x-www-form-urlencoded`：键值表单，不承载文件内容。
- `multipart/form-data`：请求体由 boundary 分隔为多个 part，每个 part 可包含字段或文件。

不要手工给 `curl -F` 或浏览器 `FormData` 设置 `Content-Type`，客户端需要自动生成带 boundary 的完整请求头。

## 2. 单个表单字段

```python
from typing import Annotated

from fastapi import Form


username: Annotated[str, Form(min_length=3, max_length=50)]
```

`Form()` 的作用与 `Body()` 类似，但明确告诉 FastAPI 从表单而非 JSON 读取。约束和元数据会进入 OpenAPI。

OAuth2 password flow 约定使用名为 `username` 和 `password` 的表单字段，而不是 JSON。这是协议约定，不表示任意登录接口都必须使用表单。

## 3. Form 参数模型与严格字段

一组表单字段可以封装为 Pydantic 模型：

```python
from typing import Annotated

from fastapi import Form
from pydantic import BaseModel, ConfigDict, Field


class ProfileForm(BaseModel):
    model_config = ConfigDict(extra="forbid")

    display_name: str = Field(min_length=1, max_length=80)
    bio: str = Field(default="", max_length=500)
    newsletter: bool = False


@app.post("/profiles")
async def create_profile(
    data: Annotated[ProfileForm, Form()],
):
    return data
```

`extra="forbid"` 会拒绝未声明表单键，适合避免字段拼写错误。边界：某些客户端可能提交按钮名或隐藏字段；启用严格模式前应先定义完整表单协议。

HTML checkbox 未勾选时通常完全不提交该字段，而不是提交 `false`，因此布尔字段应按页面行为提供合理默认值。

## 4. `UploadFile` 与 `bytes`

### `UploadFile`

```python
from fastapi import File, UploadFile


file: Annotated[UploadFile, File(description="头像文件")]
```

`UploadFile` 提供：

- `filename`：客户端提供的文件名，不可信，不能直接拼接为服务器路径。
- `content_type`：客户端声明的 MIME 类型，不等于真实内容检测。
- `size`：解析后可用的文件大小信息；仍应按部署和业务策略独立限制。
- `file`：底层 `SpooledTemporaryFile`，适合同步库读取。
- 异步方法：`await file.read(size)`、`await file.write(data)`、`await file.seek(offset)`、`await file.close()`。

小文件先保存在内存，超过 spool 阈值后落到临时文件，因此 `UploadFile` 比一次性 `bytes` 更适合大文件。读取会推进文件指针；若要再次读取，需要 `await file.seek(0)`。

### `bytes`

```python
content: Annotated[bytes, File()]
```

FastAPI 会把整个文件读入内存。它适合明确受限的小文件和简单处理，优点是直接得到字节，缺点是并发大文件上传时内存占用明显。

### 多文件

```python
files: Annotated[list[UploadFile], File()]
```

客户端对同一个字段名重复提交文件。总大小、文件数量和每个文件大小都需要限制。

## 5. JSON 与 multipart 不能同时作为同一请求体

以下需求不能通过“一个 JSON body 加一个文件 body”实现：

```python
# 不要期待客户端同时发送 application/json 和 multipart/form-data
async def create(payload: ItemModel, file: UploadFile): ...
```

一个 HTTP 请求只有一个顶层 `Content-Type`。上传文件时顶层必须是 `multipart/form-data`，其他元数据也必须作为 multipart part 发送。

可选设计：

- 简单元数据拆成普通 `Form()` 字段。
- 把 JSON 文本放进一个表单字段，然后显式执行 `Model.model_validate_json()`；此时 FastAPI 无法像原生 JSON body 那样自动展示内部字段。
- 先创建资源，再通过第二个请求上传文件。
- 客户端直传对象存储，API 只签发上传凭证；对象存储不属于 FastAPI 本身。

## 6. 上传限制与安全边界

文件上传是资源消耗入口，限制应分层实施：

1. 反向代理或云网关限制整个请求体大小、连接速率和超时。
2. ASGI 服务器配置连接与并发策略。
3. multipart 解析限制 part 大小、字段数和文件数。
4. 应用验证业务允许的文件大小、数量、扩展名和真实内容。
5. 存储层限制配额、文件名、路径和生命周期。

Starlette 的低层接口 `request.form(max_files=..., max_fields=..., max_part_size=...)` 可以限制 multipart 解析，但 FastAPI 声明式 `File()` 路由已经触发表单解析；不要在同一路由中再次解析请求体并假定限制会回溯生效。需要严格的解析前限制时，应在网关/服务器层拦截，或使用经过审计的自定义请求处理方案。

仅检查 `Content-Length` 不够：它可能缺失或不可信，分块传输也不依赖它。仅检查 `content_type` 和文件扩展名同样不够，它们都由客户端控制。

其他安全边界：

- 用服务端生成的文件 ID 保存，不使用 `filename` 作为路径，防止目录穿越和覆盖。
- 病毒扫描、图片解码炸弹防护、压缩炸弹检查属于专用安全处理，不由 FastAPI 自动提供。
- 不要在未校验前把上传内容交给 shell、模板引擎或媒体处理器。
- 处理结束后关闭文件；FastAPI 通常会清理临时资源，但显式控制长期任务的生命周期更可靠。

## 7. 完整可运行示例

下面的 `main.py` 包含严格表单模型、`UploadFile` 流式读取、小文件 `bytes` 和多文件元数据检查。示例只计算摘要，不把不可信文件写入磁盘。

```python
from hashlib import sha256
from typing import Annotated

from fastapi import FastAPI, File, Form, HTTPException, UploadFile, status
from pydantic import BaseModel, ConfigDict, Field


app = FastAPI(title="表单与上传 API")

MAX_AVATAR_SIZE = 2 * 1024 * 1024
ALLOWED_IMAGE_TYPES = {"image/jpeg", "image/png"}


class ProfileForm(BaseModel):
    model_config = ConfigDict(extra="forbid", str_strip_whitespace=True)

    display_name: str = Field(min_length=1, max_length=80)
    bio: str = Field(default="", max_length=500)
    newsletter: bool = False


async def digest_upload(file: UploadFile, max_size: int) -> tuple[int, str]:
    digest = sha256()
    total = 0
    while chunk := await file.read(64 * 1024):
        total += len(chunk)
        if total > max_size:
            raise HTTPException(
                status_code=status.HTTP_413_CONTENT_TOO_LARGE,
                detail=f"File exceeds {max_size} bytes",
            )
        digest.update(chunk)
    return total, digest.hexdigest()


@app.post("/profiles")
async def create_profile(
    data: Annotated[ProfileForm, Form()],
) -> dict[str, object]:
    return data.model_dump()


@app.post("/avatars", status_code=status.HTTP_201_CREATED)
async def upload_avatar(
    owner_id: Annotated[int, Form(gt=0)],
    avatar: Annotated[UploadFile, File(description="JPEG 或 PNG，最大 2 MiB")],
) -> dict[str, object]:
    if avatar.content_type not in ALLOWED_IMAGE_TYPES:
        raise HTTPException(status_code=415, detail="Only JPEG and PNG are accepted")

    try:
        size, digest = await digest_upload(avatar, MAX_AVATAR_SIZE)
    finally:
        await avatar.close()

    return {
        "owner_id": owner_id,
        "original_filename": avatar.filename,
        "declared_content_type": avatar.content_type,
        "size": size,
        "sha256": digest,
    }


@app.post("/tiny-text")
async def upload_tiny_text(
    content: Annotated[bytes, File(description="小型文本文件")],
) -> dict[str, object]:
    if len(content) > 16 * 1024:
        raise HTTPException(status_code=413, detail="File is too large")
    try:
        text = content.decode("utf-8")
    except UnicodeDecodeError as exc:
        raise HTTPException(status_code=400, detail="UTF-8 text required") from exc
    return {"characters": len(text), "preview": text[:80]}


@app.post("/attachments")
async def inspect_attachments(
    files: Annotated[list[UploadFile], File(min_length=1, max_length=5)],
) -> dict[str, object]:
    result = []
    for file in files:
        result.append(
            {
                "filename": file.filename,
                "content_type": file.content_type,
                "reported_size": file.size,
            }
        )
        await file.close()
    return {"files": result}
```

运行：

```bash
uv add "fastapi[standard]"
fastapi dev
```

测试表单与文件：

```bash
curl -X POST 'http://127.0.0.1:8000/profiles' \
  -F 'display_name=Alice' \
  -F 'bio=FastAPI learner' \
  -F 'newsletter=true'

curl -X POST 'http://127.0.0.1:8000/avatars' \
  -F 'owner_id=42' \
  -F 'avatar=@avatar.png;type=image/png'

curl -X POST 'http://127.0.0.1:8000/attachments' \
  -F 'files=@one.pdf' \
  -F 'files=@two.txt'
```

示例的 MIME 检查只是第一层筛选，不证明文件内容确实是 JPEG/PNG。生产系统还应检查文件签名并安全解码。

## 8. 常见错误

### 缺少 multipart 解析依赖

声明 `Form` 或 `File` 后启动报错，通常是未安装 `python-multipart`。推荐安装 `fastapi[standard]`。

### 同时安装名称相近但不兼容的包

FastAPI 需要的是 `python-multipart`。不要用另一个名为 `multipart` 的包替代它。

### 把文件声明为普通 body

文件应使用 `File()` 或 `UploadFile`，客户端使用 multipart。普通 JSON 无法直接承载原始文件，只能额外采用 Base64 等编码，通常效率更低。

### 一次性读取无限大小文件

`await file.read()` 不传大小会读到 EOF。大文件应分块读取，并在网关和应用层同时限制。

### 信任文件名和 MIME

`filename` 与 `content_type` 都来自客户端。必须生成安全存储名，并按真实内容验证。

### 读取两次得到空内容

第一次读取后文件指针已在末尾。再次读取前调用 `await file.seek(0)`。

## 9. 最佳实践

- 安装使用 `uv add "fastapi[standard]"`，开发使用 `fastapi dev`。
- 小而严格受限的内容才使用 `bytes`；一般上传优先 `UploadFile` 并分块处理。
- 限制总请求大小、单文件大小、文件数、字段数、速率和超时。
- 不直接使用客户端文件名作为本地路径。
- 将上传与 JSON 元数据设计成明确的 multipart 协议或两个请求。
- 文件持久化、对象存储和恶意内容扫描属于外围系统，FastAPI 只负责 HTTP 接入和声明式解析。

> 基线：FastAPI 0.141.1，Python 3.10+，Pydantic v2。流与 WebSocket 见 [WebSocket SSE 与流式响应](/kb/language/Python/服务框架/FastAPI/12-WebSocket-SSE-与流式响应/)，生产可观测性见 [部署容器性能与生产实践](/kb/language/Python/服务框架/FastAPI/15-部署容器性能与生产实践/)。

## 1. 测试分层与依赖

FastAPI 的 `TestClient` 基于 Starlette 和 HTTPX，在同一进程直接调用 ASGI 应用，无真实 TCP，适合快速接口测试。异步测试直接使用 HTTPX `AsyncClient + ASGITransport`。它们不会验证真实 Uvicorn、代理、TLS、超时和网络缓冲，关键链路仍需少量启动真实服务的端到端测试。

```bash
python -m pip install "fastapi[standard]==0.141.1" pytest anyio httpx asgi-lifespan sqlalchemy aiosqlite
```

### 被测应用

```python
# app.py
from contextlib import asynccontextmanager
from typing import Annotated

from fastapi import Depends, FastAPI, HTTPException, WebSocket, WebSocketDisconnect
from pydantic import BaseModel, ConfigDict


class User(BaseModel):
    model_config = ConfigDict(extra="forbid")
    id: int
    name: str


async def get_current_user() -> User:
    raise HTTPException(401, "not authenticated")


@asynccontextmanager
async def lifespan(app: FastAPI):
    app.state.ready = True
    yield
    app.state.ready = False


app = FastAPI(lifespan=lifespan)


@app.get("/me")
async def me(user: Annotated[User, Depends(get_current_user)]) -> User:
    return user


@app.get("/ready")
async def ready() -> dict[str, bool]:
    return {"ready": app.state.ready}


@app.websocket("/ws")
async def ws_echo(ws: WebSocket) -> None:
    await ws.accept()
    try:
        while True:
            await ws.send_json({"echo": await ws.receive_text()})
    except WebSocketDisconnect:
        pass
```

## 2. TestClient、override 与 lifespan

必须把 `TestClient` 用作上下文管理器，才会执行 lifespan 的启动和关闭。覆盖项的 key 必须是 `Depends` 中使用的**原函数对象**，不是调用结果。

```python
# test_app.py
from fastapi.testclient import TestClient

from app import User, app, get_current_user


def fake_user() -> User:
    return User(id=1, name="tester")


def test_me_and_lifespan() -> None:
    app.dependency_overrides[get_current_user] = fake_user
    try:
        with TestClient(app) as client:
            assert client.get("/ready").json() == {"ready": True}
            response = client.get("/me")
            assert response.status_code == 200
            assert response.json() == {"id": 1, "name": "tester"}
        assert app.state.ready is False
    finally:
        app.dependency_overrides.clear()


def test_validation_contract() -> None:
    with TestClient(app) as client:
        response = client.get("/me")
    assert response.status_code == 401
    assert response.json()["detail"] == "not authenticated"


def test_websocket() -> None:
    with TestClient(app) as client:
        with client.websocket_connect("/ws") as websocket:
            websocket.send_text("hello")
            assert websocket.receive_json() == {"echo": "hello"}
```

使用 fixture 自动清理更稳妥，防止一个测试的 override 泄漏到另一个测试：

```python
import pytest
from app import app

@pytest.fixture(autouse=True)
def clean_overrides():
    yield
    app.dependency_overrides.clear()
```

override 会绕过原依赖及其子依赖，适合替换认证、外部 API、时钟。不要 mock FastAPI 本身；尽量替换系统边界。测试应断言状态码、关键 headers、完整响应 schema 和副作用，不只断言一个字段。

## 3. 异步测试：HTTPX ASGITransport

`TestClient` 是同步 API，不能在异步测试里混用。HTTPX `ASGITransport` **不会自动触发 lifespan**，用 `asgi-lifespan`：

```python
# test_async.py
import pytest
from asgi_lifespan import LifespanManager
from httpx import ASGITransport, AsyncClient

from app import app


@pytest.mark.anyio
async def test_ready_async() -> None:
    async with LifespanManager(app) as manager:
        transport = ASGITransport(app=manager.app, raise_app_exceptions=False)
        async with AsyncClient(transport=transport, base_url="http://testserver") as client:
            response = await client.get("/ready")
    assert response.status_code == 200
    assert response.json() == {"ready": True}
```

默认 `raise_app_exceptions=True` 会把应用异常直接抛给测试，利于定位；要断言生产式 500 响应时设 False。`base_url` 影响 Host、绝对重定向和 Cookie。TrustedHost 开启后应使用允许的 host。ASGITransport 不支持 WebSocket，WebSocket 用同步 `TestClient.websocket_connect()`，或对真实服务使用 `websockets` 客户端做端到端测试。

AnyIO 可运行 asyncio/trio；若依赖只支持 asyncio，可在测试配置固定 backend。`Task attached to a different loop` 往往因为数据库 client 在模块导入时创建；应在 lifespan 或 async fixture 内创建和关闭。

## 4. 数据库测试：事务隔离而非共享生产库

原则：每个测试独立、可并行、失败后可回滚。SQLite 与 PostgreSQL 在类型、锁、JSON、约束上不同；纯单元测试可用 SQLite，数据库语义与迁移测试应使用临时 PostgreSQL 容器。

以下示例每个测试使用内存 SQLite，并通过依赖覆盖注入会话：

```python
# test_database.py
import pytest
from httpx import ASGITransport, AsyncClient
from sqlalchemy import Integer, String, select
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker, create_async_engine
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column


class Base(DeclarativeBase):
    pass


class Widget(Base):
    __tablename__ = "widgets"
    id: Mapped[int] = mapped_column(Integer, primary_key=True)
    name: Mapped[str] = mapped_column(String(100), unique=True)


@pytest.mark.anyio
async def test_database_round_trip() -> None:
    engine = create_async_engine("sqlite+aiosqlite:///:memory:")
    Session = async_sessionmaker(engine, expire_on_commit=False)
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.create_all)
    try:
        async with Session() as session:
            session.add(Widget(name="one"))
            await session.commit()
            result = await session.scalar(select(Widget).where(Widget.name == "one"))
            assert result is not None and result.name == "one"
    finally:
        await engine.dispose()
```

应用集成时定义 `get_session()` yield `AsyncSession`，测试用同签名 override。更快的方案是在 suite 建一次 schema、每测试开顶层事务并 rollback；若应用内部会 commit，需要 savepoint/nested transaction 配方。迁移应运行 Alembic，而不是只靠 `metadata.create_all()`，否则测不到真实迁移。测试绝不能读取生产 `DATABASE_URL`，应有环境保护断言。

## 5. 流、后台任务与时间

TestClient/ASGITransport 可能在内存里更积极地消费响应，无法证明代理下“逐块到达”。单元测试可断言 JSONL 的逐行内容、SSE wire event 和生成器清理；真实 backpressure、断开取消、超时必须走真实 Uvicorn。

后台任务在 TestClient 响应调用完成前通常已执行，可断言副作用，但跨进程任务队列应使用 fake producer，而不是在测试中跑真实 worker。时间、随机数和外部 HTTP 应通过依赖注入；避免 `sleep()` 等待，使用事件、可控时钟或轮询加明确超时。

## 6. 调试方法

开发启动：`fastapi dev app.py`，自动 reload 且日志详细。也可直接 `python app.py` 配合：

```python
if __name__ == "__main__":
    import uvicorn
    uvicorn.run("app:app", host="127.0.0.1", port=8000, reload=True)
```

IDE 断点时常关闭 reload，因为 reloader 会创建子进程；或让 IDE attach 到子进程。`breakpoint()` 可用，但不要遗留在生产路径。复现 422 时打印/检查 `response.json()["detail"]`，它包含 `loc/type/msg/input`；Pydantic v2 用 `model_dump()`、`model_validate()`，不要混用 v1 API。

推荐排错顺序：先做最小可复现请求并保留 request ID；看异常 traceback 的最初业务帧；核对实际依赖版本和环境变量；再检查代理/网络。不要用 `except Exception: return 500` 吞掉 traceback。生产错误响应不泄露栈、SQL、密钥；日志中保留异常、operation、request ID，并脱敏 header/body。

常用命令：

```bash
pytest -q
pytest -x -vv tests/test_app.py::test_me_and_lifespan
pytest --maxfail=1 --pdb
python -X dev -m pytest
```

## 7. 常见失败

- lifespan 中状态不存在：TestClient 没用 `with`，或 ASGITransport 没配 LifespanManager。
- override 不生效：key 不是原依赖函数，或 router import 的是另一个对象。
- 测试相互污染：全局 app、override、缓存、数据库未清理；用 app factory 和 fixture 隔离。
- 线上 500、测试抛异常：这是 ASGITransport/TestClient 默认重抛；按需关闭 raise_server_exceptions/raise_app_exceptions。
- async fixture 未 await 或 scope 错误：统一 pytest-anyio 配置，不跨 event loop 共享 async client。
- WebSocket 测试挂住：没有上下文退出、服务端没 accept、测试双方都在等待 receive；每一步定义协议和超时。

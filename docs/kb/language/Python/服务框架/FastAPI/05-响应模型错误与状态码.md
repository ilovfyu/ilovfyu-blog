> 基线：FastAPI 0.141.1（2026-07-29 latest）、Python 3.10+、Pydantic v2。

响应是公开 API 的最后一道边界。FastAPI 可以根据返回类型或 `response_model` 校验、序列化并过滤输出；也可以直接返回 Starlette `Response` 获得底层控制。本篇覆盖安全过滤、返回注解差异、状态码、`HTTPException`、异常处理器、`jsonable_encoder`、自定义响应、响应头、Cookie 和 OpenAPI additional responses。

## 1. FastAPI 的响应处理机制

路径操作返回普通 Python/Pydantic 数据时，FastAPI 大致执行：

1. 根据 `response_model` 或返回类型确定输出字段。
2. 验证返回数据是否符合输出契约。
3. 过滤未声明字段。
4. 将日期、UUID、枚举、Pydantic 模型等编码为 JSON 兼容数据。
5. 使用默认 JSON 响应发送状态、响应头和响应体。

如果服务端返回的数据违反响应模型，这通常是服务端代码错误。FastAPI 不应把内部校验细节当作普通客户端 `422` 返回；应修复实现并由监控记录异常。

直接返回 `Response` 子类时，FastAPI 会跳过自动数据转换和响应模型过滤，开发者必须保证内容、媒体类型和状态正确。

## 2. `response_model` 的安全过滤

内部模型可能含有密码哈希、权限或审计信息：

```python
from pydantic import BaseModel


class UserInternal(BaseModel):
    id: int
    username: str
    password_hash: str
    is_admin: bool


class UserPublic(BaseModel):
    id: int
    username: str


@app.get("/users/{user_id}", response_model=UserPublic)
async def read_user(user_id: int):
    return UserInternal(
        id=user_id,
        username="alice",
        password_hash="secret-hash",
        is_admin=True,
    )
```

响应只含 `id` 和 `username`。这不仅改善文档，更是避免字段泄露的安全边界。不要用 `response_model_exclude={...}` 长期维护敏感字段黑名单；单独定义公开输出模型更安全，因为新加内部字段默认不会暴露。

可用的精细选项包括：

- `response_model_exclude_unset=True`
- `response_model_exclude_defaults=True`
- `response_model_exclude_none=True`
- `response_model_include={...}`
- `response_model_exclude={...}`

这些适合特殊表示，但会让 OpenAPI Schema 与实际动态过滤产生理解成本。稳定公开 API 优先定义专门模型。

## 3. 返回类型注解与 `response_model` 的差异

### 只写返回注解

```python
@app.get("/users/{user_id}")
async def read_user(user_id: int) -> UserPublic:
    ...
```

FastAPI 可把返回注解用于验证、文档和过滤，同时编辑器也知道函数返回类型。适合实现确实返回该类型的场景。

### 显式写 `response_model`

```python
@app.get("/users/{user_id}", response_model=UserPublic)
async def read_user(user_id: int) -> UserInternal:
    ...
```

这里 Python 函数真实返回 `UserInternal`，但 HTTP 只公开 `UserPublic`。`response_model` 优先于返回注解，适合内部类型与外部表示不同的场景。

### 禁用响应模型推导

```python
from fastapi import Response


@app.get("/portal", response_model=None)
async def portal(redirect: bool = False) -> Response | dict[str, str]:
    ...
```

某些合法 Python 联合类型不是有效的 Pydantic Schema，例如 `Response | dict[...]`。此时可以设置 `response_model=None`。代价是失去自动输出验证、过滤和精确 Schema，应谨慎使用。

不要为了绕过类型错误随意删掉契约。优先判断函数究竟返回数据还是完整响应对象。

## 4. 状态码

装饰器上的 `status_code` 定义成功响应状态，并写入 OpenAPI：

```python
from fastapi import status


@app.post("/items", status_code=status.HTTP_201_CREATED)
async def create_item(): ...
```

常用语义：

| 状态码 | 典型用途 |
|---|---|
| `200 OK` | 成功读取或更新并返回响应体 |
| `201 Created` | 创建成功，通常配合 `Location` 头 |
| `202 Accepted` | 已接受但尚未完成；需要外部任务机制兑现语义 |
| `204 No Content` | 成功且无响应体 |
| `400 Bad Request` | 语法之外的通用客户端错误 |
| `401 Unauthorized` | 未认证，通常需要 `WWW-Authenticate` |
| `403 Forbidden` | 已识别但无权执行 |
| `404 Not Found` | 资源不存在，或安全策略隐藏其存在 |
| `409 Conflict` | 当前资源状态冲突 |
| `413 Content Too Large` | 请求体过大 |
| `415 Unsupported Media Type` | 不支持该媒体类型 |
| `422 Unprocessable Content` | 结构可解析但验证失败 |

动态状态码可以通过注入 `Response` 修改：

```python
from fastapi import Response, status


async def upsert(response: Response):
    response.status_code = status.HTTP_201_CREATED
    return {"created": True}
```

若直接返回 `JSONResponse(status_code=...)`，直接响应中的状态码优先，但自动响应模型处理会被绕过。

`204` 不应包含响应体。应返回 `Response(status_code=204)`，并在装饰器中设置合适状态，而不是返回 `{"ok": true}`。

## 5. `HTTPException`

```python
from fastapi import HTTPException


raise HTTPException(
    status_code=404,
    detail="Item not found",
    headers={"X-Error-Code": "ITEM_NOT_FOUND"},
)
```

必须使用 `raise`，不是 `return`。它会立即中断当前路径操作和尚未执行的依赖，由 FastAPI/Starlette 异常处理器转换为响应；已经进入的 `yield` 依赖仍会按照自身 `scope` 执行 teardown。

`detail` 可以是 JSON 可编码值，不必只有字符串。公开错误应具有稳定结构和机器可读错误码，但不要泄露 SQL、堆栈、密钥或内部路径。

认证失败通常应附带：

```python
headers={"WWW-Authenticate": "Bearer"}
```

## 6. 自定义异常处理器

领域异常不必依赖 HTTP，可以在边界统一映射：

```python
class ItemConflictError(Exception):
    def __init__(self, item_id: int):
        self.item_id = item_id


@app.exception_handler(ItemConflictError)
async def item_conflict_handler(request: Request, exc: ItemConflictError):
    return JSONResponse(
        status_code=409,
        content={"code": "item_conflict", "item_id": exc.item_id},
    )
```

还可覆盖 `RequestValidationError` 的默认处理，但应保留足够诊断信息，并同步更新 OpenAPI/客户端约定。Pydantic `ValidationError` 若出现在服务端内部数据处理中，通常代表代码或数据错误，不应一律伪装成客户端 `422`。

异常处理器基于 Starlette 的异常机制。日志、追踪、告警后端属于可观测性系统，不由 FastAPI 自动提供。

## 7. `jsonable_encoder`

`jsonable_encoder()` 把对象转换成 JSON 兼容的 Python 数据结构，但**不生成 JSON 字符串**：

```python
from datetime import datetime, timezone

from fastapi.encoders import jsonable_encoder


data = jsonable_encoder({"created_at": datetime.now(timezone.utc)})
# {"created_at": "...ISO 8601..."}
```

适用场景：

- 把 Pydantic 模型、日期、UUID 等交给只接受 JSON 兼容对象的存储层。
- 构造自定义 `JSONResponse` 的 `content`。
- 在 FastAPI 自动响应链之外复用编码规则。

普通路径直接返回 Pydantic 模型或字典时，FastAPI 已自动编码，通常无需手工调用。编码不等于校验，也不等于数据库序列化策略。

Pydantic v2 模型也可使用 `model_dump(mode="json")`。前者适合混合 FastAPI/Python 对象，后者适合单个 Pydantic 模型并遵循模型序列化配置。

## 8. 自定义 `Response`

FastAPI 可以返回任何 Starlette `Response`：

```python
from fastapi.responses import HTMLResponse, JSONResponse, PlainTextResponse
```

常见方式：

```python
@app.get("/health", response_class=PlainTextResponse)
async def health() -> str:
    return "ok"
```

`response_class` 会影响默认渲染和 OpenAPI 媒体类型。若直接返回实例：

```python
@app.get("/health")
async def health() -> PlainTextResponse:
    return PlainTextResponse("ok", headers={"X-Service": "catalog"})
```

返回实例会获得完全控制，但 FastAPI 不再过滤其内容。大文件应使用 `FileResponse`，持续生成内容可用 `StreamingResponse`；生成器的阻塞行为、连接断开和资源清理需要正确处理。

## 9. 响应头与 Cookie

### 保留自动序列化，同时设置头和 Cookie

```python
from fastapi import Response


@app.post("/sessions")
async def create_session(response: Response):
    response.headers["X-Request-Id"] = "req-123"
    response.set_cookie(
        key="session_id",
        value="opaque-token",
        httponly=True,
        secure=True,
        samesite="lax",
        max_age=3600,
    )
    return {"authenticated": True}
```

FastAPI 会把临时 `Response` 上的状态、头和 Cookie 合并到最终自动生成的响应，返回数据仍经过 `response_model`。

### 直接创建响应

```python
response = JSONResponse({"authenticated": True})
response.set_cookie(...)
return response
```

这种方式绕过自动模型过滤。还要注意：Cookie 的 `Secure` 会使浏览器只在 HTTPS 中发送它；本地 `http://` 测试看得到 `Set-Cookie`，后续请求却可能不回传。删除 Cookie 使用 `response.delete_cookie()`，其 path/domain 应与设置时匹配。

自定义响应头若要让浏览器前端 JavaScript 在跨域请求中读取，还需 CORS `expose_headers`；CORS 属于浏览器安全策略和中间件配置，不是响应头存在与否本身。

## 10. OpenAPI additional responses

`responses` 参数只描述额外可能响应，不会自动实现错误分支：

```python
@app.get(
    "/items/{item_id}",
    response_model=ItemPublic,
    responses={
        404: {
            "model": ErrorMessage,
            "description": "商品不存在",
        },
        409: {
            "model": ErrorMessage,
            "description": "商品状态冲突",
        },
    },
)
async def read_item(item_id: int):
    ...
```

FastAPI 会把 `model` 转为 OpenAPI Schema。实现中仍需 `raise HTTPException(...)` 或返回对应 `Response`。文档模型与实际错误体必须保持一致；仅填写 `description` 不会约束运行时。

也可以描述其他媒体类型：

```python
responses={
    200: {
        "content": {"image/png": {}},
        "description": "JSON 元数据或 PNG 图片",
    }
}
```

## 11. 完整可运行示例

以下 `main.py` 把主要机制组合在一个内存 API 中：

```python
from datetime import datetime, timezone
from typing import Annotated

from fastapi import FastAPI, Header, HTTPException, Request, Response, status
from fastapi.encoders import jsonable_encoder
from fastapi.responses import JSONResponse, PlainTextResponse
from pydantic import BaseModel, ConfigDict, Field


app = FastAPI(title="响应与错误 API")


class ItemCreate(BaseModel):
    model_config = ConfigDict(extra="forbid")

    name: str = Field(min_length=1, max_length=100)
    price: float = Field(gt=0)


class ItemInternal(ItemCreate):
    id: int
    cost_price: float
    created_at: datetime


class ItemPublic(ItemCreate):
    id: int
    created_at: datetime


class ErrorMessage(BaseModel):
    code: str
    message: str


class HTTPError(BaseModel):
    detail: ErrorMessage


class DuplicateItemError(Exception):
    def __init__(self, name: str):
        self.name = name


DB: dict[int, ItemInternal] = {}


@app.exception_handler(DuplicateItemError)
async def duplicate_item_handler(
    request: Request,
    exc: DuplicateItemError,
) -> JSONResponse:
    content = ErrorMessage(
        code="duplicate_item",
        message=f"Item '{exc.name}' already exists",
    )
    return JSONResponse(
        status_code=status.HTTP_409_CONFLICT,
        content=jsonable_encoder(content),
        headers={"X-Error-Code": "duplicate_item"},
    )


@app.get("/health", response_class=PlainTextResponse, tags=["system"])
async def health() -> str:
    return "ok"


@app.post(
    "/items",
    response_model=ItemPublic,
    status_code=status.HTTP_201_CREATED,
    responses={
        409: {"model": ErrorMessage, "description": "名称已存在"},
    },
)
async def create_item(
    payload: ItemCreate,
    response: Response,
    request_id: Annotated[str | None, Header(alias="X-Request-Id")] = None,
) -> ItemInternal:
    if any(item.name == payload.name for item in DB.values()):
        raise DuplicateItemError(payload.name)

    item_id = max(DB, default=0) + 1
    item = ItemInternal(
        id=item_id,
        name=payload.name,
        price=payload.price,
        cost_price=payload.price * 0.6,
        created_at=datetime.now(timezone.utc),
    )
    DB[item_id] = item

    response.headers["Location"] = f"/items/{item_id}"
    response.headers["X-Request-Id"] = request_id or f"generated-{item_id}"
    response.set_cookie(
        key="last_item_id",
        value=str(item_id),
        httponly=True,
        secure=False,  # 本地 HTTP 演示；生产 HTTPS 必须设为 True。
        samesite="lax",
        max_age=3600,
    )
    # cost_price 被 response_model=ItemPublic 安全过滤。
    return item


@app.get(
    "/items/{item_id}",
    response_model=ItemPublic,
    responses={
        404: {"model": HTTPError, "description": "商品不存在"},
    },
)
async def read_item(item_id: int) -> ItemInternal:
    item = DB.get(item_id)
    if item is None:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail=ErrorMessage(
                code="item_not_found",
                message="Item not found",
            ).model_dump(),
            headers={"X-Error-Code": "item_not_found"},
        )
    return item


@app.delete(
    "/items/{item_id}",
    status_code=status.HTTP_204_NO_CONTENT,
    response_class=Response,
)
async def delete_item(item_id: int) -> Response:
    if DB.pop(item_id, None) is None:
        raise HTTPException(status_code=404, detail="Item not found")
    return Response(status_code=status.HTTP_204_NO_CONTENT)
```

安装、启动和测试：

```bash
uv add "fastapi[standard]"
fastapi dev

curl -i -X POST 'http://127.0.0.1:8000/items' \
  -H 'Content-Type: application/json' \
  -H 'X-Request-Id: req-001' \
  -d '{"name":"Keyboard","price":699}'

curl -i 'http://127.0.0.1:8000/items/1'
curl -i 'http://127.0.0.1:8000/items/999'
curl -i -X DELETE 'http://127.0.0.1:8000/items/1'
```

观察结果：创建响应是 `201`，包含 `Location`、`X-Request-Id` 和 `Set-Cookie`；JSON 中没有 `cost_price`；不存在资源返回 `404`；删除成功返回 `204` 且没有响应体。

示例中的 `409` 由自定义处理器返回扁平的 `ErrorMessage`；默认 `HTTPException` 会把错误值放在 `detail` 下，所以 `404` 使用 `HTTPError` 描述包装结构。additional responses 与实际响应体需要逐项保持一致。

## 12. 常见错误

### 返回内部模型而没有输出契约

新增内部字段后可能自动进入 JSON。公开端点应定义 `response_model` 或可靠的返回模型。

### 直接返回 `JSONResponse` 仍期待过滤

`Response` 实例绕过自动响应模型处理。先显式构造公开模型，或返回普通数据让 FastAPI 处理。

### 把 `HTTPException` 当返回值

必须 `raise HTTPException(...)`。返回异常对象不会触发异常处理流程。

### 把请求校验错误都改成 400 却不同步契约

可以自定义处理器，但客户端、OpenAPI、测试和监控必须共享同一错误结构与状态语义。

### `204` 返回 JSON

`204` 按协议不能有响应体。返回空 `Response`。

### additional responses 只写文档不写实现

`responses={404: ...}` 不会自动检查资源并返回 `404`，也不会运行时校验 `HTTPException.detail`。

### 错误 Cookie 属性

生产会话 Cookie 缺少 `Secure`/`HttpOnly`，或删除时 path/domain 不一致，会造成安全问题或无法清除。

## 13. 最佳实践

- 输入、内部和公开输出模型分离，敏感字段使用允许列表式输出模型。
- 函数真实返回类型与公开类型不同的时候，显式使用 `response_model`。
- 使用 `fastapi.status` 常量表达状态码语义。
- 领域代码抛领域异常，在 HTTP 边界统一映射稳定错误结构。
- 普通数据优先交给 FastAPI 自动编码；只有需要完全控制时直接返回 `Response`。
- 文档中的 additional responses、实际响应体和测试保持一致。
- 响应头和 Cookie 是 HTTP 契约的一部分，纳入安全评审与集成测试。

::: important Lua 5.5
`global` 声明是 Lua 5.5 新语言特性，也是关键字。Lua 5.4 及更早版本不能解析本章含 `global` 的示例。
:::

## 变量类别与词法作用域

Lua 有局部变量、全局变量和表字段。参数等价于局部变量。局部声明从声明后的第一条语句开始生效，到包含它的最内层 block 结束。

```lua
local x = 10
do
  local x = x + 1 -- 右侧 x 是外层 x
  print(x)         -- 11
end
print(x)           -- 10
```

优先使用 local：访问更明确、更快，也避免模块间通过全局状态偶然耦合。

## Upvalue 与闭包

内层函数引用外层局部变量时，该变量成为函数的 upvalue：

```lua
local function counter(start)
  local value = start
  return function(delta)
    value = value + (delta or 1)
    return value
  end
end

local next_id = counter(100)
print(next_id(), next_id(5)) -- 101 106
```

闭包捕获变量本身，不是定义时值的快照。共享同一 upvalue 的闭包会看到彼此修改。

## 全局变量与 `_ENV`

全局名 `x` 在语法上等价于 `_ENV.x`。每个 chunk 都在一个外部局部变量 `_ENV` 的作用域内编译；默认 `_ENV` 是全局环境。`_G` 初始指向同一全局环境，但 Lua 内部不会依赖 `_G`。

```lua
local env = {print = print, answer = 42}
local fn = assert(load("print(answer)", "demo", "t", env))
fn()
```

修改 `_G` 变量自身不等于替换当前 `_ENV`。要隔离动态代码，应向 `load` 显式传环境。

## Lua 5.5 `global` 声明

所有 chunk 开头隐含 `global *`，因此不写显式声明时仍保持“自由名默认全局”的传统行为。但一旦在某个作用域出现其他 global 声明，该隐含声明在该作用域失效，未声明自由名会在编译期报错。

```lua
global print, app_name

app_name = "demo"
print(app_name)
-- typo_name = 1 -- 编译错误：未声明变量
```

这种模式能把拼写错误从运行期隐藏 bug 变成编译错误。

声明形式包括：

```lua
global x, y             -- 可读写全局
global limit &lt;const&gt;    -- 只读全局
global&lt;const&gt; math, print -- 前缀属性作用于列表
global none             -- 不隐式允许任何自由全局名
global *                -- 所有尚未声明的自由名均视为全局
global&lt;const&gt; *         -- 所有尚未声明自由名均为只读全局
```

`global none` 不是声明一个名为 none 的全局，而是显式空声明，用来进入“所有名字必须声明”模式。

一种严格脚本开头：

```lua
global&lt;const&gt; assert, ipairs, print, string, table
global result

local values = {"Lua", "5.5"}
result = table.concat(values, " ")
print(result)
```

## const 与 close 属性

变量属性写在尖括号中。`const` 可用于 local/global，表示声明后不能作为赋值左值；`close` 只允许 local，并在离开作用域时调用关闭协议。

```lua
local&lt;const&gt; MAX_RETRIES = 3
local endpoint &lt;const&gt; = "localhost"
```

属性是变量只读约束，不会冻结其引用对象：

```lua
local config &lt;const&gt; = {debug = false}
config.debug = true -- 允许：变量 config 未重新赋值
-- config = {}      -- 错误
```

`&lt;close&gt;` 详见 [错误处理与资源关闭](/kb/language/Lua/语法教程/08-错误处理与资源关闭/)。

## 声明与初始化时序

在 `local x = x` 中，新局部 x 尚未进入作用域，右侧引用外层 x。多个声明的右侧表达式也先求值再绑定新局部变量。

每次执行 local 声明都会创建新变量。循环中定义闭包时，块内 local 可为每轮创建独立捕获状态。

## 常见错误

- 忘记 `global` 是 5.5 关键字，拿 5.4 解释器测试。
- 认为 chunk 默认已经严格；隐含 `global *` 仍允许任意全局名。
- 在显式 global 声明后忘记声明 `print`、`math` 等标准库全局。
- 认为 `&lt;const&gt;` 会让 table 内容不可变。
- 通过 `_G` 随意共享模块状态，而不是返回模块表。
- 在受控环境中暴露 `load`、`debug`、`io` 或 `os` 后仍声称是安全沙箱。

## 练习

1. 把一个使用任意全局变量的脚本改为 `global none` 加显式声明。
2. 写两个闭包共享一个 upvalue，并观察彼此修改。
3. 用 `load` 和只含 `math`、`print` 的环境执行表达式。
4. 解释为什么 `local t &lt;const&gt; = {}` 仍允许 `t.x = 1`。

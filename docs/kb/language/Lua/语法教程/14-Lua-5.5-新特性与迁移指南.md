::: abstract 版本说明
Lua 5.5.0 于 2025-12-22 发布。Lua 的版本是 `x.y.z`：同一 `x.y` 的 release 主要是 bug fix，使用同一参考手册并保持 ABI；不同 `x.y` 之间可能改变语言、API、ABI 和虚拟机。
:::

## 主要语言变化

### 全局变量声明

5.5 新增 `global` 关键字和声明语义：

```lua
global&lt;const&gt; print, math
global result

result = math.sqrt(81)
print(result)
```

出现显式 global 声明后，作用域内不再继承 chunk 开头隐含的 `global *`，未声明自由名会编译失败。它可实现严格全局检查，但源码不兼容 5.4。

### 具名 vararg table

```lua
local function inspect(...args)
  print(args.n)
  return ...
end
```

名字 args 是只读 local，引用包含索引 1..n 与字段 n 的 vararg table；尾部 nil 也计入 n。匿名 `...` 仍可使用。兼容 5.4 的写法是 `local args = table.pack(...)`。

### For 控制变量只读

数值 for 的控制变量以及泛型 for 的第一个控制变量变为只读。旧代码若给它赋值会编译失败：

```lua
for i = 1, 3 do
  local i = i -- 创建可变 shadow
  i = i * 2
end
```

修改控制变量本来就容易制造误解；迁移时应改用新 local，而不是寻找绕过方式。

### 更深的 table constructor

5.5 提高构造器嵌套层级能力。它缓解生成代码/深层数据描述限制，但过深源码仍影响可读性，真实嵌套数据可考虑构建函数或外部数据格式。

## 标准库变化

### `table.create`

```lua
local sequence = table.create(10000)
local records = table.create(0, 1000)
```

预分配 sequence/hash 容量但不创建元素。它是 5.5-only API。

### `utf8.offset`

5.5 除起始字节位置外还返回字符最终位置，安全切取单个 UTF-8 code point 更方便。

### 数学与打印

- float 输出使用足够十进制位，确保文本可读回为相同 float。
- math 库包含 `math.frexp`、`math.ldexp`。

不要对 float 默认字符串的小数位数写脆弱快照测试；需要展示格式时显式 `string.format`。

## GC 与内存变化

- generational GC 的 major collection 改为增量执行。
- 大型 array representation 更紧凑，官方说明内存可减少约 60%。
- dump/undump、辅助 buffer 和静态 binary chunk 有内部内存复用改进。

这些是性能与实现变化，不能替代基准。升级后应重新测量延迟、吞吐、峰值内存和 GC 参数，不要沿用 5.4 调优值。

## C API/嵌入变化概览

5.5 增加 external strings、`luaL_openselectedlibs`、`luaL_makeseed`、`lua_closethread` 等能力，并调整部分 API。语法教程不展开 C 栈 API，但嵌入项目必须注意：

- 重新编译宿主和所有 C 模块。
- 不假定 5.4 ABI 或 bytecode 可用。
- 核对函数签名、常量和兼容宏。
- 用 `luaL_checkversion` 检查运行时一致性。
- 按最小权限选择加载标准库。

## 不兼容性检查

迁移 5.4 → 5.5 时至少搜索：

| 检查项 | 风险 |
|---|---|
| 标识符名 `global` | 现已是关键字，语法错误 |
| for 循环内给控制变量赋值 | 现为只读，语法错误 |
| 依赖 float 默认打印文本 | 输出精度/格式变化 |
| 预编译 `.luac` 文件 | 虚拟机版本不兼容 |
| C 扩展二进制 | ABI 不兼容，必须重编译 |
| debug API 对 varargs 的假设 | 具名 vararg table 可能改变可见方式 |
| GC 参数和暂停基线 | collector 行为变化 |

应以官方手册第 8 节为最终清单，不能只依赖“主要变化”摘要。

## 兼容 5.4 与 5.5 的策略

如果一个源码包必须同时运行于 5.4 和 5.5：

- 不使用 `global` 声明。
- 不使用具名 `...args`。
- 不给 for 控制变量赋值，两版都保持清晰写法。
- 用 `table.pack(...)` 代替具名 vararg table。
- 不直接依赖 `table.create`，或从独立兼容模块提供工厂。
- 对 `utf8.offset` 只消费第一返回值，除非按版本分支。
- 避免加载跨版本二进制 chunk。

不要用无法解析的 5.5 语法配合运行时 `_VERSION` 分支，因为 5.4 在执行分支前就已经解析失败。语法级差异需要不同源码入口、构建生成或选择共同子集。

## 迁移流程

1. 固定目标为 Lua 5.5.0，并记录构建配置、integer/float 宽度。
2. 在 5.5 下对全部 `.lua` 文件运行 `luac -p`。
3. 搜索 `global` 标识符和 for 控制变量赋值。
4. 重新编译并测试 C 模块。
5. 删除并重新生成全部 binary chunk。
6. 运行单元、集成和嵌入宿主测试。
7. 比较 float 文本、序列化结果和平台相关 I/O。
8. 压测 GC 暂停、内存和大数组行为。
9. 逐步采用 global 声明、具名 varargs 和 table.create，而非一次重写全部代码。

## 5.5 推荐代码风格

```lua
global&lt;const&gt; assert, ipairs, math, pairs, print, require, string, table, tostring

local M = {}

function M.summarize(...values)
  local result = table.create(values.n)
  for index = 1, values.n do
    result[index] = tostring(values[index])
  end
  return table.concat(result, ",")
end

return M
```

这段代码用显式只读全局、具名 vararg table 和容量预分配表达 5.5 风格。若 values 中含 nil，赋 nil 会在 result 中形成空洞，`table.concat` 不适用；生产代码必须先定义 nil 的序列化策略。

## 常见错误

- 只看 `_VERSION`，忽略宿主自定义数值宽度和库集合。
- 把 5.5 语法放在 5.4 不会执行的 if 分支，仍导致解析失败。
- 升级解释器但继续分发旧 `.luac` 或 C 模块。
- 因 table 更省内存就放弃 sequence 无空洞约束。
- 未测量就照搬旧 GC 参数。
- 使用新 global 声明后漏声明标准库名字。

## 迁移检查清单

- [ ] 运行时确认为 Lua 5.5.0。
- [ ] 全部源码通过 5.5 `luac -p`。
- [ ] `global` 标识符冲突已处理。
- [ ] for 控制变量不再被赋值。
- [ ] C 扩展全部针对 5.5 重编译。
- [ ] binary chunks 全部重新生成或改为分发源码。
- [ ] float 输出与序列化快照已审查。
- [ ] varargs 尾部 nil 行为有测试。
- [ ] GC 和大型 table 使用真实负载基准测试。
- [ ] 若支持 5.4，源码严格使用共同语法子集。

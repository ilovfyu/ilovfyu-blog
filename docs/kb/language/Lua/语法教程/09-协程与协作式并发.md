## 协程不是 OS 线程

Lua coroutine 是独立执行流，只有显式 `yield` 才暂停。默认没有并行、抢占、网络事件循环或自动调度；I/O 是否阻塞取决于宿主和库。

## create、resume 与 yield

```lua
local co = coroutine.create(function(first)
  print("started", first)
  local reply = coroutine.yield("paused", first * 2)
  return "finished", reply
end)

print(coroutine.status(co))              -- suspended
print(coroutine.resume(co, 10))          -- true paused 20
print(coroutine.status(co))              -- suspended
print(coroutine.resume(co, "continue")) -- true finished continue
print(coroutine.status(co))              -- dead
```

第一次 resume 的额外参数传给主函数。yield 的参数返回给 resume；下一次 resume 的额外参数成为 yield 调用的返回值。协程正常结束时 resume 返回 true 加函数返回值；失败返回 false 加错误对象。

## 状态

`coroutine.status(co)` 返回：

| 状态 | 含义 |
|---|---|
| `suspended` | 尚未开始或停在 yield |
| `running` | 当前正在运行 |
| `normal` | 它恢复了另一个协程并等待其返回 |
| `dead` | 已返回或因错误终止 |

不能 resume running 或 dead coroutine。

## 错误与堆栈

resume 不自动抛出协程错误：

```lua
local ok, value = coroutine.resume(co)
if not ok then
  io.stderr:write(debug.traceback(co, tostring(value)), "\n")
end
```

失败协程保留栈，便于 debug API 检查。生产封装应立即检查 ok，否则错误会被当普通返回值传播。

## wrap

`coroutine.wrap(fn)` 返回恢复函数，省略 resume 的状态 boolean，错误直接传播，并在错误时关闭协程：

```lua
local next_value = coroutine.wrap(function()
  for i = 1, 3 do coroutine.yield(i) end
end)

print(next_value(), next_value(), next_value())
```

wrap 简洁但隐藏 thread 句柄，不适合需要查询状态、显式 close 或定制错误处理的代码。

## close

`coroutine.close(co)` 关闭 suspended/dead coroutine，并关闭其待关闭变量。成功返回 true；关闭期间出错返回 false 加错误对象。不能关闭 running coroutine。

```lua
local co = coroutine.create(function()
  local file &lt;close&gt; = assert(io.tmpfile())
  coroutine.yield("ready")
end)

assert(coroutine.resume(co))
assert(coroutine.close(co))
```

拥有协程的代码必须定义谁负责最终 close，特别是迭代提前停止时。

## 生产者消费者

```lua
local function producer(values)
  return coroutine.create(function()
    for _, value in ipairs(values) do
      coroutine.yield(value)
    end
  end)
end

local function receive(co)
  local ok, value = coroutine.resume(co)
  if not ok then error(value, 2) end
  return value
end

local co = producer({"a", "b", "c"})
while coroutine.status(co) ~= "dead" do
  local value = receive(co)
  if value ~= nil then print(value) end
end
```

nil 不能直接作为“还有数据”的可靠值；复杂协议应传事件类型或额外状态。

## 协程迭代器

```lua
local function permutations(items)
  local function generate(n)
    if n == 1 then
      coroutine.yield(table.concat(items, ""))
      return
    end
    for i = 1, n do
      items[n], items[i] = items[i], items[n]
      generate(n - 1)
      items[n], items[i] = items[i], items[n]
    end
  end
  return coroutine.wrap(function() generate(#items) end)
end

for value in permutations({"a", "b", "c"}) do print(value) end
```

协程让递归生成器可以在深层 yield，不必手工保存遍历栈。

## 调度器边界

协程本身不等待 socket。异步框架通常规定 yield 一个“等待请求”，事件循环检测 I/O 后 resume 对应协程。若在协程里调用阻塞 `io.read()`，整个宿主线程仍会阻塞。

协程是协作式的：长 CPU 循环不 yield 会让其他协程饥饿。公平性、取消、超时和资源归属都需调度器协议定义。

## 常见错误

- 把 coroutine 当操作系统线程或多核并行。
- 忘记检查 `resume` 的首个 boolean。
- resume 已 dead 的协程。
- 提前放弃 suspended coroutine 而不 close，泄漏待关闭资源。
- 用 nil 同时表示数据和迭代结束。
- 在协程内执行阻塞 I/O，却声称系统是异步的。

## 练习

1. 跟踪 resume/yield 双向传值的完整时序。
2. 实现能产生斐波那契数的协程迭代器。
3. 构造含 `&lt;close&gt;` 变量的协程，验证 close 时资源清理。
4. 设计一个 yield `{"sleep", seconds}` 的最小调度协议。

# 工作者线程

> 上一章：[-模块](/kb/language/JavaScript/核心语法/25-模块/) · 下一章：[-最佳实践](/kb/language/JavaScript/核心语法/27-最佳实践/)

## 学习目标

- 理解主线程、事件循环与 Worker 的并发模型
- 使用专用 Worker 执行 CPU 密集型任务
- 掌握消息传递、结构化克隆、Transferable 与取消协议
- 区分 Dedicated Worker、Shared Worker、Service Worker 和 Worklet

## 1. Worker 解决什么问题

浏览器主线程负责 JavaScript、布局、绘制和用户输入。长时间同步计算会阻塞事件循环，导致动画掉帧、点击无响应。Worker 在独立线程和全局环境执行 JavaScript，适合图像处理、数据解析、压缩、搜索索引等 CPU 密集任务。

Worker 不会让算法自动变快，它通过并行和隔离保持主线程响应。创建线程、复制消息和调度也有成本，几十微秒的小任务通常不值得迁移。

Worker 中没有 `window` 和 DOM，不能直接操作页面。它通过消息把结果交给主线程，由主线程更新 UI。

## 2. 创建模块 Worker

现代项目优先使用模块 Worker，以便使用 `import` 和模块作用域。

```js
// main.js
const worker = new Worker(new URL("./sum-worker.js", import.meta.url), {
  type: "module"
});

worker.addEventListener("message", (event) => {
  console.log("总和：", event.data.result);
});

worker.addEventListener("error", (event) => {
  console.error("Worker 执行失败", event.message);
});

worker.postMessage({ type: "sum", values: [1, 2, 3, 4] });
```

```js
// sum-worker.js
self.addEventListener("message", (event) => {
  if (event.data.type !== "sum") return;
  const result = event.data.values.reduce((total, value) => total + value, 0);
  self.postMessage({ type: "result", result });
});
```

示例需要通过 HTTP(S) 服务器运行；直接打开本地文件可能受模块和源策略限制。

## 3. 结构化克隆

`postMessage()` 默认用结构化克隆算法复制数据。它支持对象、数组、Map、Set、Date、ArrayBuffer、类型化数组等，但函数和 DOM 节点不能克隆。

```js
const worker = new Worker("./worker.js", { type: "module" });

worker.postMessage({
  createdAt: new Date(),
  ids: new Set([1, 2, 3]),
  metadata: new Map([["source", "demo"]])
});
```

克隆大对象会同时消耗时间和内存。应只传任务必需的数据，避免反复传送巨大嵌套结构。

## 4. Transferable：转移所有权

`ArrayBuffer`、`MessagePort` 等对象可转移而非复制。转移后发送方的缓冲区会被分离，接收方取得所有权。

```js
// main.js
const worker = new Worker("./invert-worker.js", { type: "module" });
const pixels = new Uint8Array([0, 80, 200, 255]);

worker.postMessage({ buffer: pixels.buffer }, [pixels.buffer]);
console.log(pixels.byteLength); // 0，所有权已经转移

worker.onmessage = ({ data }) => {
  const result = new Uint8Array(data.buffer);
  console.log(result);
};
```

```js
// invert-worker.js
self.onmessage = ({ data }) => {
  const pixels = new Uint8Array(data.buffer);
  for (let i = 0; i < pixels.length; i += 1) {
    pixels[i] = 255 - pixels[i];
  }
  self.postMessage({ buffer: pixels.buffer }, [pixels.buffer]);
};
```

转移适合二进制大数据。发送后继续读取原缓冲区是常见错误，应在类型和控制流中明确所有权变化。

## 5. 请求响应协议

实际应用通常同时提交多个任务，需要使用请求 ID 关联响应，并统一错误格式。

```js
// main.js
const worker = new Worker("./rpc-worker.js", { type: "module" });
let nextId = 0;
const pending = new Map();

worker.onmessage = ({ data }) => {
  const request = pending.get(data.id);
  if (!request) return;
  pending.delete(data.id);
  data.ok ? request.resolve(data.value) : request.reject(new Error(data.error));
};

function callWorker(method, payload) {
  const id = ++nextId;
  return new Promise((resolve, reject) => {
    pending.set(id, { resolve, reject });
    worker.postMessage({ id, method, payload });
  });
}

callWorker("square", 12).then(console.log); // 144
```

```js
// rpc-worker.js
self.onmessage = ({ data }) => {
  try {
    if (data.method !== "square") throw new Error("未知方法");
    self.postMessage({ id: data.id, ok: true, value: data.payload ** 2 });
  } catch (error) {
    self.postMessage({ id: data.id, ok: false, error: error.message });
  }
};
```

`Error` 的跨环境序列化细节不应作为稳定协议，显式传递可公开的错误代码和消息更可控。

## 6. 取消与终止

`worker.terminate()` 会立即终止整个 Worker，适合销毁实例，但不能只取消其中一个任务。细粒度取消可定义协作协议，让任务分块并定期检查取消状态。

```js
// cancellable-worker.js
const cancelled = new Set();

self.onmessage = async ({ data }) => {
  if (data.type === "cancel") {
    cancelled.add(data.id);
    return;
  }

  if (data.type === "start") {
    let total = 0;
    for (let i = 0; i < data.limit; i += 1) {
      if (cancelled.has(data.id)) {
        cancelled.delete(data.id);
        self.postMessage({ id: data.id, type: "cancelled" });
        return;
      }
      total += i;
      if (i % 100_000 === 0) await new Promise(setTimeout);
    }
    self.postMessage({ id: data.id, type: "result", total });
  }
};
```

纯同步大循环无法在执行中接收取消消息，因此必须切块让 Worker 的事件循环获得处理消息的机会。切块本身有开销，需要结合任务粒度调优。

## 7. SharedArrayBuffer 与 Atomics

`SharedArrayBuffer` 允许多个线程访问同一内存，`Atomics` 提供原子读写与同步操作。它避免复制，但显著增加竞态、死锁和调试复杂度。

```js
const shared = new SharedArrayBuffer(Int32Array.BYTES_PER_ELEMENT);
const counter = new Int32Array(shared);

Atomics.add(counter, 0, 1);
console.log(Atomics.load(counter, 0)); // 1
```

浏览器使用 SharedArrayBuffer 通常要求页面启用跨源隔离，例如正确设置 COOP 和 COEP 响应头。除非有经过测量的性能需求，否则优先消息传递与所有权转移。

## 8. Worker 家族

- Dedicated Worker：仅由创建它的上下文使用，普通计算任务首选
- Shared Worker：可被同源多个窗口连接，支持有限且使用较少
- Service Worker：位于页面与网络之间，处理离线缓存、请求拦截、推送；生命周期独立于页面
- Worklet：面向渲染管线中的特定低级任务，如 AudioWorklet，不是通用后台线程

Service Worker 不是“更强的 Web Worker”。它由事件驱动，随时可能停止，不适合依赖常驻内存状态或执行任意长计算。

## 9. Worker 池与调度

创建过多 Worker 会争抢 CPU 和内存。重复独立任务可使用小型 Worker 池，池大小通常结合 `navigator.hardwareConcurrency`、任务性质和目标设备测试确定，而不是简单等于逻辑核心数。

调度时还应考虑：

- 给交互相关任务更高优先级
- 对过时任务做取消或丢弃结果
- 合并过小任务，避免消息开销超过计算收益
- 限制队列长度，形成背压
- 记录排队、传输和计算耗时，而不仅是总耗时

## 常见陷阱与最佳实践

- Worker 内不能直接访问 DOM，由主线程负责 UI 更新
- 优先模块 Worker，并用 `new URL(..., import.meta.url)` 定位脚本
- 大型二进制数据使用 Transferable，传输后不再访问原缓冲区
- 为消息定义 `type`、请求 ID、结果和错误的稳定协议
- 组件销毁或页面退出时终止不再使用的 Worker
- 对长任务提供取消、进度和背压，不无限堆积消息
- 先用性能工具确认主线程瓶颈，再引入并发复杂度
- 共享内存只用于确有收益且能严格证明同步正确性的场景

## 章节小结

Worker 通过线程隔离把重计算移出主线程。现代实现应以模块 Worker、结构化消息和 Transferable 为基础，并设计请求关联、错误、取消与资源释放协议。并发的目标是响应性和吞吐，而不是盲目增加线程；测量数据决定是否使用 Worker 及其粒度。

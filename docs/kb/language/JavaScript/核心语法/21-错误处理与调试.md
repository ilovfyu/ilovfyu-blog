# 错误处理与调试

> 前一章：[-JavaScript-API](/kb/language/JavaScript/核心语法/20-JavaScript-API/) ｜ 后一章：[-XML与JSON](/kb/language/JavaScript/核心语法/22-XML与JSON/)

## 学习目标

- 区分语法错误、运行时异常、Promise 拒绝与业务失败。
- 掌握 `try/catch/finally`、自定义错误、错误因果链和异步处理。
- 使用浏览器开发者工具系统定位问题，而不是依赖猜测。
- 建立安全、可观测且不过度吞错的生产错误策略。

## 1. 错误的分类

语法错误在代码解析阶段产生，通常无法由同一脚本附近的 `try/catch` 恢复。运行时错误包括类型使用错误、非法范围、网络失败和业务约束失败。

常见内建错误类型：

- `SyntaxError`：语法或解析内容无效，例如 `JSON.parse()` 失败。
- `TypeError`：值或操作类型不合预期。
- `RangeError`：数值超出允许范围，如无效数组长度。
- `ReferenceError`：访问不存在的绑定。
- `DOMException`：浏览器 API 违反状态、安全或参数约束。

错误分类应服务于处理决策。用户输入错误通常是可预期验证结果，不必都抛异常；程序不变量被破坏则适合抛错并停止当前流程。

## 2. `try/catch/finally`

`try/catch` 只捕获执行期间同步抛出的异常，以及在 `try` 内被 `await` 的 Promise 拒绝。`finally` 无论成功或失败都执行，适合释放资源和恢复界面状态。

```js
async function loadProfile(id) {
  setLoading(true);

  try {
    const response = await fetch(`/api/profiles/${encodeURIComponent(id)}`);
    if (!response.ok) {
      throw new Error(`Profile request failed: ${response.status}`);
    }
    return await response.json();
  } catch (error) {
    if (error instanceof Error) logError(error);
    throw error;
  } finally {
    setLoading(false);
  }
}
```

不要在 `finally` 中 `return`，它会覆盖 `try` 的返回值或正在传播的异常。

## 3. 抛出有意义的错误

JavaScript 允许抛出任意值，但应抛 `Error` 或其子类，以保留名称、消息、堆栈和因果信息。

```js
class ValidationError extends Error {
  constructor(message, fields, options) {
    super(message, options);
    this.name = 'ValidationError';
    this.fields = fields;
  }
}

function parseSettings(text) {
  try {
    return JSON.parse(text);
  } catch (cause) {
    throw new ValidationError('设置文件不是有效 JSON', ['file'], { cause });
  }
}
```

`cause` 保存底层错误而无需把细节拼进消息。自定义错误应只承载处理所需的稳定字段，不应通过字符串匹配错误消息决定逻辑。

## 4. Promise 与异步错误

Promise 链中的抛错会转成拒绝；拒绝处理器抛出的错误会继续传播。每个“即发即弃”任务也必须有明确错误出口。

```js
async function initialize() {
  const [user, flags] = await Promise.all([
    fetchUser(),
    fetchFeatureFlags(),
  ]);
  renderApp({ user, flags });
}

initialize().catch((error) => {
  renderFatalError();
  reportError(error);
});
```

`Promise.all()` 遇到首个拒绝就整体拒绝，但不会自动取消其他任务。需要完整结果时使用 `Promise.allSettled()`；需要停止网络请求时把同一个 `AbortSignal` 传入相关请求。

```js
const controller = new AbortController();

try {
  await fetch('/api/search', { signal: controller.signal });
} catch (error) {
  if (error instanceof DOMException && error.name === 'AbortError') return;
  throw error;
}
```

取消是预期控制流时不应报告为生产故障。

## 5. 全局错误边界

`window` 的 `error` 事件可观察未捕获同步错误和资源加载失败；`unhandledrejection` 观察未处理 Promise 拒绝。它们适合最后防线和遥测，不适合恢复任意应用状态。

```js
window.addEventListener('error', (event) => {
  reportError(event.error ?? new Error(`Resource failed: ${event.target?.src}`));
}, true);

window.addEventListener('unhandledrejection', (event) => {
  const error = event.reason instanceof Error
    ? event.reason
    : new Error(String(event.reason));
  reportError(error);
});
```

跨源脚本若没有正确 CORS 和 `crossorigin` 配置，错误详情可能受“Script error”限制。生产 source map 应控制访问权限，防止无意暴露源码。

## 6. 浏览器调试基本流程

有效调试是一套缩小范围的过程：稳定复现、记录输入和环境、定位首次偏离预期的位置、验证根因、补充回归测试。

常用 DevTools 能力：

- Sources：行断点、条件断点、日志断点、XHR/fetch 与事件监听断点。
- Console：交互检查值、调用栈、对象快照和上下文切换。
- Network：请求时序、请求体、响应、缓存、CORS 和节流模拟。
- Performance：长任务、脚本、样式计算、布局、绘制和 Web Vitals。
- Memory：堆快照、分配时间线、Detached DOM 节点。
- Application：存储、Cookie、缓存、Service Worker 和权限相关状态。

## 7. 断点与日志

`debugger` 语句在开发者工具打开时暂停执行，提交前通常应移除。条件断点比循环内大量打印更高效。

```js
console.groupCollapsed('Checkout calculation');
console.table(items.map(({ id, price, quantity }) => ({ id, price, quantity })));
console.assert(total >= 0, 'Total must not be negative', { total });
console.groupEnd();
```

`console.log(object)` 在一些工具中展示的是稍后展开时的对象状态，并非调用时快照。要保留关键值，可记录原始字段或创建可序列化快照；注意 `JSON.stringify()` 会丢失循环引用、函数、`undefined` 等信息。

生产日志应结构化并包含关联 ID、版本、路由和操作阶段，但不得记录密码、令牌、完整身份证件或不必要的个人数据。

## 8. Source Map 与构建产物

压缩和转译会让生产堆栈难以阅读。Source map 将构建位置映射回源代码。应保证：发布产物与 map 版本严格匹配；错误平台能取得 map；公开服务器不一定直接暴露 map；发布标识可关联到提交版本。

错误堆栈格式并非 ECMAScript 标准的一部分，不同引擎存在差异。不要把解析 `error.stack` 当作关键业务逻辑。

## 9. 网络与并发问题

HTTP 错误状态不会让 `fetch()` 自动拒绝；只有网络层失败、CORS 失败或取消等通常会拒绝。必须检查 `response.ok`。

```js
async function requestJson(url, options) {
  const response = await fetch(url, options);
  const contentType = response.headers.get('content-type') ?? '';

  if (!response.ok) {
    throw new Error(`HTTP ${response.status} for ${response.url}`);
  }
  if (!contentType.includes('application/json')) {
    throw new TypeError(`Expected JSON, received ${contentType || 'unknown'}`);
  }
  return response.json();
}
```

调试“偶现”问题时重点检查竞争条件、重复提交、过期响应覆盖新状态、共享可变数据和组件销毁后的异步回调。Network 节流与 CPU slowdown 有助于放大时序问题。

## 10. 错误恢复与用户体验

错误处理分层更可靠：底层补充技术上下文，中层决定重试或降级，界面层给用户可执行的信息。只在操作幂等且错误可能短暂时自动重试，并采用指数退避和随机抖动。

```js
async function retry(operation, attempts = 3) {
  let lastError;
  for (let attempt = 0; attempt < attempts; attempt += 1) {
    try {
      return await operation();
    } catch (error) {
      lastError = error;
      if (attempt + 1 < attempts) {
        await new Promise((resolve) => setTimeout(resolve, 2 ** attempt * 250));
      }
    }
  }
  throw lastError;
}
```

真实项目还应判断错误类型、响应状态和 `Retry-After`，并加入随机抖动。支付、创建订单等非幂等操作不能盲目重试。

## 11. 防御式编码与测试

在系统边界验证外部输入，在内部通过清晰契约保持代码简单。过多可选链可能把本应暴露的数据错误静默转换成 `undefined`。

```js
function assertUser(value) {
  if (!value || typeof value.id !== 'string' || typeof value.name !== 'string') {
    throw new TypeError('Invalid user payload');
  }
  return value;
}
```

修复错误后补充最小回归测试。测试异常路径、超时、取消、空数据、权限拒绝和边界值，而不只覆盖成功路径。

## 12. 低频与过时知识

旧 IE 的脚本调试器、`window.onerror` 字符串返回约定和浏览器专有错误对象主要用于维护遗留系统。`alert()` 适合极少数阻塞提示，不是调试工具。现代项目应使用 DevTools、自动测试和集中式错误监控。

## 常见陷阱与最佳实践

- 不使用空 `catch` 吞掉异常；若有意忽略，说明为什么该错误可安全忽略。
- 不抛字符串，统一抛 `Error`，需要分类时使用错误类型或稳定错误码。
- `catch` 后无法真正处理时补充上下文并重新抛出，保留 `cause`。
- 每个 Promise 链都有最终处理点，尤其注意未等待的异步任务。
- 区分取消、用户验证失败、暂时性故障和程序缺陷，采取不同策略。
- 生产遥测去除敏感信息，使用采样和去重控制成本。
- 先复现和测量，再改代码；修复后增加测试并验证没有掩盖根因。

## 章节小结

健壮的错误处理不是到处包裹 `try/catch`，而是让异常在有能力处理的层级被分类、补充上下文、恢复或上报。配合断点、网络与性能分析、source map、结构化日志和回归测试，才能从根因上解决问题并改善生产可观测性。

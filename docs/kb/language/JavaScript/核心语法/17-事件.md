# 事件

> 前一章：[-DOM2与DOM3](/kb/language/JavaScript/核心语法/16-DOM2与DOM3/) ｜ 后一章：[-动画与Canvas图形](/kb/language/JavaScript/核心语法/18-动画与Canvas图形/)

## 学习目标

- 理解捕获、目标、冒泡三个传播阶段及默认行为。
- 掌握事件监听、委托、清理和自定义事件的现代写法。
- 正确处理指针、键盘、输入、页面生命周期等常用事件。
- 建立兼顾性能、可访问性和安全性的交互设计习惯。

## 1. 事件流

事件先从 `window` 向目标传播（捕获），到达目标后再沿祖先链返回（冒泡）。并非所有事件都会冒泡，例如 `focus` 和 `blur`；委托焦点事件可使用会冒泡的 `focusin`、`focusout`。

```js
const controller = new AbortController();

document.addEventListener('click', handleCapture, {
  capture: true,
  signal: controller.signal,
});

document.addEventListener('click', handleBubble, {
  signal: controller.signal,
});

// 一次移除同一 signal 注册的监听器
controller.abort();
```

`event.target` 是原始目标，`event.currentTarget` 是当前执行监听器的节点。Shadow DOM 中可通过 `event.composedPath()` 查看经过重定向后的传播路径。

## 2. 注册与移除监听器

优先使用 `addEventListener()`，它允许同一事件注册多个处理器，并支持 `capture`、`once`、`passive`、`signal`。

```js
button.addEventListener('click', submitOnce, { once: true });

window.addEventListener('scroll', updatePosition, { passive: true });
```

`passive: true` 表示处理器不会调用 `preventDefault()`，浏览器可更快开始滚动。只有明确不取消默认行为时才使用。

移除监听器时，函数引用和 `capture` 必须匹配。匿名函数无法通过另一个外观相同的匿名函数移除；`AbortController` 通常更利于统一清理。

## 3. 传播控制与默认行为

- `preventDefault()` 取消可取消事件的默认行为。
- `stopPropagation()` 阻止事件继续传播，不阻止当前节点的其他处理器。
- `stopImmediatePropagation()` 还会阻止当前节点后续处理器。

```js
form.addEventListener('submit', async (event) => {
  event.preventDefault();
  if (!form.reportValidity()) return;
  await save(new FormData(form));
});
```

不要把 `return false` 当作原生事件控制方式；它主要是某些库或内联处理器的历史约定。传播控制应谨慎使用，否则会破坏上层分析、快捷键或组件协作。

## 4. 事件委托

将监听器放在稳定祖先上，可处理动态子元素并减少监听器数量。匹配后还要确认目标确实属于委托容器。

```js
const list = document.querySelector('.todo-list');

list.addEventListener('click', (event) => {
  const button = event.target.closest('button[data-action]');
  if (!button || !list.contains(button)) return;

  const item = button.closest('li');
  if (button.dataset.action === 'toggle') item.classList.toggle('done');
  if (button.dataset.action === 'remove') item.remove();
});
```

委托依赖冒泡。`mouseenter`、`mouseleave` 不冒泡，可按场景使用 `pointerover`、`pointerout` 并检查 `relatedTarget`。

## 5. 指针、鼠标与触摸

Pointer Events 统一鼠标、触摸和触控笔。`pointerId` 标识指针，`pointerType` 表示设备类型，指针捕获可保证拖动越出元素后仍收到后续事件。

```js
slider.addEventListener('pointerdown', (event) => {
  slider.setPointerCapture(event.pointerId);
  updateSlider(event.clientX);
});

slider.addEventListener('pointermove', (event) => {
  if (slider.hasPointerCapture(event.pointerId)) updateSlider(event.clientX);
});

slider.addEventListener('pointerup', (event) => {
  slider.releasePointerCapture(event.pointerId);
});
```

坐标系不可混用：`clientX/Y` 相对视口，`pageX/Y` 相对文档，`screenX/Y` 相对屏幕。CSS `touch-action` 能声明浏览器手势策略，通常优于在高频事件里盲目取消默认行为。

## 6. 键盘、焦点与输入

快捷键一般使用 `keydown`。`event.key` 表示用户意图字符，`event.code` 表示物理键位；不要继续依赖已废弃的 `keyCode`。

```js
document.addEventListener('keydown', (event) => {
  const modifier = navigator.userAgentData?.platform === 'macOS'
    ? event.metaKey
    : event.ctrlKey;

  if (modifier && event.key.toLowerCase() === 'k') {
    event.preventDefault();
    searchDialog.showModal();
  }
});
```

文本输入应关注 `beforeinput`、`input` 和组合输入事件。输入法组合期间，不能把每次键盘事件都当成最终文字。

```js
input.addEventListener('input', (event) => {
  if (event.isComposing) return;
  updateQuery(event.currentTarget.value);
});
```

点击交互不能只绑在非语义 `div` 上。优先使用 `button`、`a` 等原生可交互元素，自动获得键盘和可访问性行为。

## 7. 页面与资源事件

`DOMContentLoaded` 表示 HTML 已解析且延迟脚本已执行；`load` 还等待图片等资源。模块脚本默认延迟，通常无需把所有初始化都包进 `load`。

```js
if (document.readyState === 'loading') {
  document.addEventListener('DOMContentLoaded', init, { once: true });
} else {
  init();
}
```

页面进入往返缓存时会触发 `pagehide`/`pageshow`。不要依赖 `unload` 发送数据，它不可靠且可能妨碍 bfcache；少量遥测可考虑 `navigator.sendBeacon()`。

## 8. 自定义事件

`CustomEvent` 可用于 DOM 组件间低耦合通知，业务数据放在 `detail`。

```js
const event = new CustomEvent('cart:item-added', {
  detail: { productId: 'p-42', quantity: 1 },
  bubbles: true,
  composed: true,
});

cartElement.dispatchEvent(event);
```

事件名称最好使用命名空间式前缀。事件对象并非安全边界，任何能访问页面脚本上下文的代码都可能派发事件，接收方仍需验证数据。

## 9. 高频事件与性能

`scroll`、`pointermove`、`resize` 可能高频触发。视觉更新可合并到下一帧，而不是每次事件立即重绘。

```js
let scheduled = false;

window.addEventListener('scroll', () => {
  if (scheduled) return;
  scheduled = true;
  requestAnimationFrame(() => {
    scheduled = false;
    updateStickyHeader(window.scrollY);
  });
}, { passive: true });
```

元素尺寸、进入视口等需求优先评估 `ResizeObserver`、`IntersectionObserver`，而非持续轮询。

## 10. 低频与过时知识

DOM0 的 `onclick` 属性仍可用，但只能方便地保存一个处理器；内联 `onclick="..."` 混合结构与行为，也不利于 CSP。IE 的 `attachEvent`、`window.event`、`cancelBubble` 和键盘 `keyCode` 仅需在维护遗留代码时识别。

## 常见陷阱与最佳实践

- 用 `currentTarget` 获取监听器所属元素，不要误把内部图标当按钮。
- 组件卸载时清理监听器；推荐通过 `AbortSignal` 管理生命周期。
- 不滥用 `stopPropagation()`，优先让处理器自行判断是否相关。
- 不在被动监听器中调用 `preventDefault()`。
- 同时覆盖鼠标、触摸、触控笔和键盘，优先语义 HTML 与 Pointer Events。
- 高频处理器保持轻量，避免同步布局读取和长任务。
- 对事件携带的数据和触发时机做验证，不把“用户触发”当成可信证明。

## 章节小结

事件系统是浏览器交互的基础。可靠实现依赖对传播路径、默认行为和监听器生命周期的清晰理解；事件委托、Pointer Events、语义元素及帧调度共同构成现代高性能交互的常用方案。

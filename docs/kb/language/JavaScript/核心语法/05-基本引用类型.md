# 基本引用类型

> 章节映射：《JavaScript 高级程序设计》第 4 版第 5 章，聚焦现代常用内置对象。

## 学习目标

- 掌握 `Date`、`RegExp`、原始值包装机制和常用字符串方法
- 正确处理时间、Unicode 文本与正则表达式
- 理解 `globalThis`、`Math`、`JSON` 等基础内置能力
- 避免手动包装原始值和依赖环境差异

## 1. 对象实例与内置类型

引用类型描述对象的结构和行为，实例通过构造、字面量或工厂方法获得。现代代码优先使用可读性更高的字面量。

```js
const pattern = /js/iu;
const timestamp = new Date("2026-08-02T10:00:00Z");
const options = { strict: true };

console.log(pattern.test("JS"));
console.log(timestamp.toISOString());
console.log(options.strict);
```

本章关注不以“集合容器”为主要职责的基础对象；数组、Map、Set 等将在下一章展开。

## 2. Date：时间点不等于日历文本

`Date` 内部表示自 Unix 纪元起的毫秒数。它能表示时间点，但 API 混合了本地时区和 UTC 方法，容易出现边界错误。

```js
const now = new Date();
console.log(now.getTime());       // 毫秒时间戳
console.log(now.toISOString());   // UTC ISO 字符串

const deadline = new Date("2026-12-31T23:59:59Z");
console.log(deadline > now);
```

不要依赖非标准日期字符串解析。日期时间交换优先使用带时区的 ISO 8601 格式；纯日期如生日应视作日历值，而不是随意转换成午夜时间点。

用 `Intl.DateTimeFormat` 面向用户格式化：

```js
const formatter = new Intl.DateTimeFormat("zh-CN", {
  dateStyle: "long",
  timeStyle: "short",
  timeZone: "Asia/Shanghai",
});

console.log(formatter.format(new Date("2026-08-02T10:00:00Z")));
```

大量日期运算或复杂时区业务应考虑成熟库；支持目标明确时，也可评估更新的 `Temporal` API，而不是继续堆叠 `Date` 修补逻辑。

## 3. RegExp：用于模式，不用于解析一切

正则字面量由模式和标志组成。常用标志包括 `g`（全局）、`i`（忽略大小写）、`m`（多行）、`s`（点匹配换行）、`u`（Unicode）、`y`（粘连）、`d`（索引，需环境支持）。

```js
const text = "订单 A-102，订单 B-305";
const orderPattern = /\b([A-Z])-([0-9]{3})\b/gu;

for (const match of text.matchAll(orderPattern)) {
  console.log({ prefix: match[1], number: Number(match[2]) });
}
```

动态构造正则时要处理用户文本中的元字符：

```js
function escapeRegExp(text) {
  return text.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");
}

const keyword = "a+b";
const pattern = new RegExp(escapeRegExp(keyword), "iu");
console.log(pattern.test("查找 a+b 示例")); // true
```

带 `g` 或 `y` 的正则使用 `test/exec` 时会修改 `lastIndex`，复用实例可能产生状态相关结果：

```js
const globalPattern = /js/g;
console.log(globalPattern.test("js")); // true
console.log(globalPattern.test("js")); // false，因为 lastIndex 已变化
globalPattern.lastIndex = 0;
```

HTML、URL、编程语言等有正式语法的内容不宜只靠一个复杂正则解析，应使用专用解析器。

## 4. 原始值的自动装箱

字符串、数字、布尔值是原始值，却可以调用方法。引擎会临时提供相应包装对象行为，调用完成后即可丢弃。

```js
const title = "  JavaScript Core  ";
console.log(title.trim().toUpperCase());
console.log((12.345).toFixed(2)); // "12.35"
```

不要主动使用 `new String()`、`new Number()` 或 `new Boolean()`：

```js
const wrappedFalse = new Boolean(false);
console.log(Boolean(wrappedFalse)); // true，对象总是真值
console.log(typeof wrappedFalse);   // object
```

需要显式转换时调用不带 `new` 的 `String(value)`、`Number(value)`、`Boolean(value)`。

## 5. String 与 Unicode

JavaScript 字符串以 UTF-16 码元组织。`length` 和索引计算的是码元，不一定是用户看到的字符数量。

```js
const emoji = "A😀B";
console.log(emoji.length);      // 4
console.log([...emoji].length); // 3，按 Unicode 码点迭代
```

组合字符、肤色修饰和家庭 emoji 仍可能由多个码点组成。面向用户的字符分割可使用 `Intl.Segmenter`：

```js
const segmenter = new Intl.Segmenter("zh-CN", { granularity: "grapheme" });
const graphemes = [...segmenter.segment("👨‍👩‍👧‍👦你好")].map((item) => item.segment);
console.log(graphemes); // ["👨‍👩‍👧‍👦", "你", "好"]
```

常用字符串方法返回新字符串，不修改原值：

```js
const raw = "  apple,banana,pear  ";
const fruits = raw.trim().split(",");
console.log(fruits.includes("banana"));
console.log("JavaScript".startsWith("Java"));
console.log("ha".repeat(3));
```

按地区比较、排序或搜索时，使用 `Intl.Collator` 或 `localeCompare`，不要简单转小写后比较所有语言。

## 6. Number 与 Math

`Number` 提供解析和检查方法，`Math` 提供数学函数与常量。`Math.random()` 不适合密码、令牌或任何安全用途。

```js
const values = [3.2, -1.7, 8.9];
console.log(Math.floor(values[0])); // 3
console.log(Math.ceil(values[1]));  // -1
console.log(Math.max(...values));   // 8.9
console.log(Math.trunc(-1.7));      // -1
```

生成包含上下界的普通随机整数：

```js
function randomInteger(min, max) {
  const lower = Math.ceil(min);
  const upper = Math.floor(max);
  return Math.floor(Math.random() * (upper - lower + 1)) + lower;
}

console.log(randomInteger(1, 6));
```

安全随机值应使用浏览器的 `crypto.getRandomValues()` 或 Node.js `node:crypto`。

## 7. globalThis、编码与结构化数据

`globalThis` 是跨环境全局对象入口。历史上的浏览器 `window`、Node.js `global` 仍存在，但共享库不应无必要依赖它们。

URL 参数应使用 `URL` 与 `URLSearchParams`，局部编码可使用 `encodeURIComponent`：

```js
const url = new URL("https://example.com/search");
url.searchParams.set("q", "JavaScript 核心");
url.searchParams.set("page", "1");
console.log(url.toString());
```

JSON 是数据交换格式，不支持函数、`undefined`、`BigInt` 等全部 JavaScript 值：

```js
const json = JSON.stringify({ id: 1, active: true, ignored: undefined });
console.log(json); // {"id":1,"active":true}

const parsed = JSON.parse(json);
console.log(parsed.id);
```

解析 JSON 只是语法成功，不代表结构可信。外部数据仍须验证字段、范围和权限。

## 常见陷阱与最佳实践

- **解析模糊日期字符串**：交换时间使用明确时区的 ISO 8601 字符串。
- **混用本地与 UTC 方法**：先确定数据语义和显示时区，再统一处理。
- **复用带 `g` 的正则却忘记状态**：留意 `lastIndex`，或按调用创建合适实例。
- **用单个正则解析复杂语法**：改用 URL、DOM 或专用语法解析器。
- **手动创建包装对象**：转换用 `String/Number/Boolean`，不要使用 `new`。
- **把 `length` 当用户字符数**：Unicode 文本按需求使用码点迭代或 `Intl.Segmenter`。
- **用 `Math.random()` 生成令牌**：安全用途必须使用密码学随机源。
- **认为 JSON 解析后即可使用**：在系统边界验证解析结果。

## 章节小结

基础引用类型封装了时间、文本模式、字符串处理、数学及全局能力。真正困难的部分往往不是方法名称，而是数据语义：时间是否带时区、字符按什么单位计算、正则是否携带状态、随机数是否需要安全性。明确这些边界，才能正确选择内置 API。

# 表单脚本

> 前一章：[-动画与Canvas图形](/kb/language/JavaScript/核心语法/18-动画与Canvas图形/) ｜ 后一章：[-JavaScript-API](/kb/language/JavaScript/核心语法/20-JavaScript-API/)

## 学习目标

- 掌握表单控件访问、提交、重置和序列化。
- 正确使用原生约束验证并补充业务规则。
- 处理文本、选择、文件和富文本输入的常见交互。
- 实现防重复提交、可取消请求和无障碍错误反馈。

## 1. 表单与控件

`HTMLFormElement.elements` 是按文档顺序排列的控件集合，可按 `name` 或索引访问。推荐通过明确选择器或 `elements.namedItem()` 获取，避免控件名称覆盖表单对象属性造成歧义。

```js
const form = document.querySelector('#profile-form');
const email = form.elements.namedItem('email');

email.addEventListener('input', () => {
  email.value = email.value.trimStart();
});
```

按钮默认 `type` 在表单中通常是 `submit`。纯操作按钮务必写 `type="button"`，防止意外提交。

## 2. 提交流程

用户点击提交按钮或在合适控件中按 Enter 会触发 `submit`。监听表单而非按钮，才能覆盖键盘与辅助技术触发路径。

```js
form.addEventListener('submit', async (event) => {
  event.preventDefault();
  if (!form.reportValidity()) return;

  const submitter = event.submitter;
  submitter?.setAttribute('aria-disabled', 'true');

  try {
    await submitProfile(new FormData(form));
  } finally {
    submitter?.removeAttribute('aria-disabled');
  }
});
```

`form.submit()` 会绕过 `submit` 事件和约束验证；通常应调用 `form.requestSubmit(button)`，它模拟正常提交并保留提交按钮语义。

## 3. `FormData` 与序列化

`FormData` 遵循“成功控件”规则：禁用、无 `name`、未选中的复选框等不会被包含；同名控件可产生多个值。

```js
const data = new FormData(form);

for (const [name, value] of data) {
  console.log(name, value instanceof File ? value.name : value);
}

const tags = data.getAll('tags');
await fetch('/api/profile', { method: 'POST', body: data });
```

发送 `FormData` 时不要手动设置 `Content-Type: multipart/form-data`，浏览器需要自动加入 boundary。若后端接收 JSON，应显式转换并考虑重复键、文件和类型信息：

```js
const payload = Object.fromEntries(new FormData(form));
await fetch('/api/settings', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(payload),
});
```

## 4. 原生约束验证

HTML 提供 `required`、`minlength`、`maxlength`、`min`、`max`、`step`、`pattern` 和类型验证。JavaScript 可读取 `validity`、`validationMessage`，或用 `setCustomValidity()` 添加业务规则。

```js
const password = form.elements.namedItem('password');
const confirmation = form.elements.namedItem('confirmation');

function validateConfirmation() {
  confirmation.setCustomValidity(
    confirmation.value === password.value ? '' : '两次输入的密码不一致',
  );
}

password.addEventListener('input', validateConfirmation);
confirmation.addEventListener('input', validateConfirmation);
```

`checkValidity()` 返回结果并触发无效控件的 `invalid` 事件；`reportValidity()` 还请求浏览器展示提示。客户端验证只改善体验，服务端必须再次验证，因为请求可以绕过页面直接发送。

## 5. 文本输入与选择

`input` 适合响应实时值变化，`change` 通常在值确认或失焦后触发。对于输入法，应处理组合状态；对于程序化设置 `.value`，浏览器不会自动触发 `input`。

```js
const textarea = form.elements.namedItem('bio');

textarea.addEventListener('input', (event) => {
  if (event.isComposing) return;
  const remaining = 280 - textarea.value.length;
  document.querySelector('#bio-count').textContent = String(remaining);
});
```

选择文本可使用 `selectionStart`、`selectionEnd` 和 `setSelectionRange()`：

```js
function insertAtCursor(input, text) {
  const start = input.selectionStart;
  const end = input.selectionEnd;
  input.setRangeText(text, start, end, 'end');
  input.dispatchEvent(new InputEvent('input', { bubbles: true, inputType: 'insertText' }));
}
```

## 6. 复选框、单选框与选择框

应读取 `checked` 而不是比较 `value` 判断是否选中。单选按钮通过相同 `name` 形成组。

```js
const newsletter = form.elements.namedItem('newsletter').checked;
const plan = new FormData(form).get('plan');

const select = form.elements.namedItem('country');
console.log(select.value, select.selectedOptions[0]?.textContent);
```

多选框使用 `selectedOptions` 或 `FormData.getAll()`。动态生成选项可使用 `new Option(text, value)`，但不要把不可信字符串写入 `innerHTML`。

## 7. 文件输入与上传

`input.files` 是只读 `FileList`。前端可预览大小和 MIME 类型，但这些信息可伪造，服务端仍需检查实际内容、大小和扩展名。

```js
const fileInput = form.elements.namedItem('avatar');

fileInput.addEventListener('change', () => {
  const [file] = fileInput.files;
  if (!file) return;

  if (file.size > 5 * 1024 * 1024) {
    fileInput.setCustomValidity('文件不能超过 5 MB');
  } else {
    fileInput.setCustomValidity('');
  }
});
```

预览对象 URL 使用后应释放：

```js
const url = URL.createObjectURL(file);
preview.src = url;
preview.addEventListener('load', () => URL.revokeObjectURL(url), { once: true });
```

## 8. 可取消提交与防重复

禁用按钮能避免常规重复点击，但真正的写操作还需要服务端幂等键。客户端可取消上一次未完成请求。

```js
let submitController;

async function submitProfile(data) {
  submitController?.abort();
  submitController = new AbortController();

  const response = await fetch('/api/profile', {
    method: 'POST',
    body: data,
    signal: submitController.signal,
    headers: { 'Idempotency-Key': crypto.randomUUID() },
  });

  if (!response.ok) throw new Error(`保存失败：${response.status}`);
}
```

## 9. 富文本编辑

`contenteditable` 能快速提供编辑表面，但光标、粘贴、撤销、语义标记、移动端和安全净化都很复杂。`execCommand()` 已废弃。生产级编辑器通常采用成熟编辑框架，并在展示前净化输出。

`beforeinput` 提供编辑意图，Selection/Range 提供选区，但浏览器细节较多。不要把富文本编辑器当作简单表单控件实现。

## 10. 可访问性与错误反馈

每个控件应有可感知的 `&lt;label&gt;`。错误消息通过 `aria-describedby` 关联；动态汇总可使用适度的 `aria-live`，但避免每次按键都打断屏幕阅读器。

```js
function focusFirstInvalid(form) {
  const invalid = form.querySelector(':invalid');
  invalid?.focus({ preventScroll: true });
  invalid?.scrollIntoView({ block: 'center', behavior: 'smooth' });
}
```

不要只用颜色表示错误，也不要在第一次输入前就展示大量红色警告。

## 11. 低频与过时知识

旧式文本范围、`document.selection` 和 `execCommand()` 仅在遗留编辑器中可能遇到。通过按钮 `onclick` 手工调用 `form.submit()` 会绕过现代验证流程，不推荐。

## 常见陷阱与最佳实践

- 始终监听表单 `submit`，不要只监听提交按钮 `click`。
- 需要程序化提交时优先 `requestSubmit()`。
- 理解 `FormData` 不包含禁用和无名称控件，也不会自动转换数字与布尔类型。
- 每次重新验证前用空字符串清除旧的 `setCustomValidity()` 消息。
- 客户端与服务端采用同一业务规则，但服务端是最终安全边界。
- 文件对象 URL、请求和监听器都应按生命周期清理。
- 保留语义标签、键盘流程和清晰错误关联，不用占位符替代标签。

## 章节小结

表单是浏览器原生能力最丰富的组件之一。优先利用语义 HTML、约束验证与 `FormData`，再用 JavaScript 补充异步提交和业务规则；服务端验证、幂等处理和无障碍反馈同样是完整方案的一部分。

# 变量、作用域与内存

> 章节映射：《JavaScript 高级程序设计》第 4 版第 4 章，结合闭包、模块与现代垃圾回收实践。

## 学习目标

- 理解原始值、对象引用与参数传递
- 掌握词法作用域、作用域链和闭包
- 理解执行上下文及变量声明的可见范围
- 能识别常见内存泄漏并设计清理机制

## 1. 值、引用与可变性

变量保存一个值。原始值自身不可变；对象是可变数据结构，变量中保存的值可以理解为指向对象的引用。赋值对象变量时，两个变量会指向同一对象。

```js
let scoreA = 10;
let scoreB = scoreA;
scoreB += 5;
console.log(scoreA, scoreB); // 10 15

const userA = { name: "Lin" };
const userB = userA;
userB.name = "Chen";
console.log(userA.name); // Chen
```

如果不希望共享顶层状态，可创建浅拷贝：

```js
const original = { name: "Lin", preferences: { theme: "dark" } };
const copy = { ...original, name: "Chen" };

console.log(original.name); // Lin
console.log(copy.preferences === original.preferences); // true，嵌套对象仍共享
```

`structuredClone()` 可复制许多结构化数据，包括循环引用、`Map` 和 `Set`，但不能复制函数或 DOM 节点，也不应被当作所有场景的性能默认项。

```js
const state = { items: [{ id: 1 }], updatedAt: new Date() };
const cloned = structuredClone(state);
console.log(cloned.items !== state.items); // true
console.log(cloned.updatedAt instanceof Date); // true
```

## 2. 参数始终按值传递

调用函数时，参数接收实参值的副本。对象实参的值是引用，所以函数可以通过该引用修改对象，但把形参重新指向新对象不会改变外部变量。

```js
function updateAccount(account) {
  account.active = true;
  account = { active: false }; // 只改变局部形参
  return account;
}

const account = { active: false };
const returned = updateAccount(account);
console.log(account.active);  // true
console.log(returned.active); // false
```

“对象按引用传递”是容易误导的简称。更准确的说法是：JavaScript 一律按值传递，而对象值本身是引用。

## 3. 执行上下文与词法作用域

代码执行时会创建执行上下文。每个函数调用都有自己的局部环境，并能沿词法作用域链查找外层绑定。词法作用域由代码定义位置决定，而不是调用位置。

```js
const label = "global";

function createPrinter() {
  const label = "factory";
  return function print() {
    console.log(label);
  };
}

const print = createPrinter();
const labelOwner = { label: "object", print };
labelOwner.print(); // factory
```

内层找不到变量时向外查找；外层不能反向访问内层局部变量。应让变量存在于尽可能小的作用域，降低误用和命名冲突。

## 4. 块级作用域与暂时性死区

`let` 和 `const` 受 `{}` 限制。在声明语句执行前，绑定已经属于该作用域，但不可访问，这段区域称为暂时性死区。

```js
const status = "outer";

if (true) {
  // console.log(status); // ReferenceError，而不是读取 outer
  const status = "inner";
  console.log(status);
}

console.log(status);
```

`var` 只具有函数作用域，声明会提升并初始化为 `undefined`。这是遗留代码中循环闭包问题的来源之一：

```js
const tasks = [];
for (let index = 0; index < 3; index += 1) {
  tasks.push(() => index);
}
console.log(tasks.map((task) => task())); // [0, 1, 2]
```

`let` 在每轮循环创建对应绑定，无需旧式立即调用函数表达式来保存索引。

## 5. 声明提升要准确理解

函数声明可在声明文本之前调用。`var` 声明提升但赋值不提升；`let`、`const` 和 `class` 也建立绑定，却在初始化前不可访问。

```js
console.log(square(4)); // 16

function square(value) {
  return value * value;
}

// console.log(double(4)); // ReferenceError
const double = (value) => value * 2;
```

提升是规范执行方式的表现，不代表代码真的被移动。为了阅读顺序清晰，除简短函数声明外，不应刻意依赖先使用后声明。

## 6. 闭包保存词法环境

函数可以在外层函数结束后继续访问其词法环境，这就是闭包。闭包适合封装状态、创建专用函数和实现回调。

```js
function createCounter(initial = 0) {
  let count = initial;

  return {
    increment() {
      count += 1;
      return count;
    },
    current() {
      return count;
    },
  };
}

const counter = createCounter(5);
console.log(counter.increment()); // 6
console.log(counter.current());   // 6
```

闭包不是特殊语法，而是所有函数天然具备的词法访问能力。它也会延长所捕获数据的可达时间，所以不要无意捕获体积很大的对象。

## 7. 全局、模块与共享状态

经典脚本顶层声明可能进入全局环境；ES 模块拥有自己的顶层作用域。模块单例状态仍会被所有导入者共享，只是不会直接污染 `globalThis`。

```js
// id-sequence.js
let nextId = 1;

export function createId() {
  return nextId++;
}
```

共享状态应有明确生命周期。测试中如果模块状态无法重置，可能导致用例相互影响；依赖注入或实例工厂通常比隐式单例更容易测试。

## 8. 垃圾回收与可达性

现代引擎主要依据可达性回收内存：从全局对象、当前调用栈等根节点出发，无法再到达的对象可被清理。开发者不能也不应手动释放普通对象。

```js
let cache = { payload: new Array(10_000).fill("data") };
cache = null; // 解除这条引用；若无其他引用，对象之后可被回收
```

设为 `null` 不是立即释放命令，只是移除一个引用。局部变量通常会自然离开作用域，无需机械置空；长期存活对象中的大字段才可能值得主动断开。

## 9. 常见内存泄漏来源

泄漏通常不是“引擎忘记回收”，而是程序仍保留不需要的引用。高频来源包括：

- 未清除的定时器
- 未移除的事件监听器
- 无限增长的缓存或消息队列
- 闭包意外捕获大型对象
- 已移除 DOM 节点仍被 JavaScript 引用

可用 `AbortController` 统一管理可取消资源：

```js
function mountSearch(input) {
  const controller = new AbortController();

  input.addEventListener(
    "input",
    () => console.log(input.value),
    { signal: controller.signal },
  );

  return () => controller.abort();
}

// const unmount = mountSearch(document.querySelector("input"));
// unmount(); // 组件销毁时调用
```

缓存对象关联数据时，若不希望缓存阻止键对象回收，可考虑 `WeakMap`。它不可枚举，适合附加元数据，不适合作为需要列出所有项的业务存储。

```js
const metadata = new WeakMap();
const element = {};
metadata.set(element, { selected: true });
console.log(metadata.get(element));
```

## 常见陷阱与最佳实践

- **误以为展开语法会深拷贝**：对象和数组展开只复制一层。
- **把参数称为按引用传递**：重新赋值形参不会替换调用方变量。
- **过度扩大变量作用域**：尽量在第一次需要的位置附近声明。
- **依赖 `var` 提升**：新代码使用 `const`/`let`，旧代码迁移时留意循环与重复声明。
- **所有对象离开视图后仍保留监听**：组件或页面销毁时清理事件、观察器和任务。
- **创建无边界缓存**：设置容量、过期时间或淘汰策略。
- **为了“释放内存”到处赋 `null`**：先用性能工具确认保留路径，再处理长期引用。
- **把 `WeakMap` 当通用缓存**：它不能枚举，也不保证何时回收。

## 章节小结

JavaScript 始终按值传递，变量的可见性由词法作用域决定，闭包则让函数保留对外层环境的访问。垃圾回收围绕可达性工作，内存问题通常来自生命周期过长的引用。清晰限制作用域、避免无界共享状态、为订阅和缓存设计清理机制，是比手动“释放”更有效的实践。

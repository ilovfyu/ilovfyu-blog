# 迭代器与生成器

> 章节映射：《JavaScript 高级程序设计》第 4 版第 7 章，并补充异步迭代的现代实践。

## 学习目标

- 区分可迭代对象、迭代器和迭代结果
- 理解迭代协议如何驱动 `for...of` 与展开语法
- 使用生成器按需产生序列并控制执行暂停
- 掌握异步迭代与资源清理的基本模式

## 1. 为什么需要统一迭代协议

数组、字符串、Set、Map 的内部结构不同，但都能被 `for...of` 遍历，因为它们实现了同一套可迭代协议。消费方只关心如何取得下一个值，不需要知道集合如何存储数据。

```js
const collections = [
  ["a", "b"],
  new Set([1, 2]),
  "JS",
];

for (const collection of collections) {
  console.log([...collection]);
}
```

统一协议让展开、解构、`Array.from()`、`Promise.all()` 等能力可以接收多种数据来源。

## 2. 可迭代对象、迭代器与结果对象

三者职责不同：

- **可迭代对象（iterable）**：具有 `[Symbol.iterator]()` 方法。
- **迭代器（iterator）**：具有 `next()` 方法，通常也让自身可迭代。
- **迭代结果（iterator result）**：形如 `{ value, done }`。

手动观察数组迭代器：

```js
const iterator = [10, 20][Symbol.iterator]();
console.log(iterator.next()); // { value: 10, done: false }
console.log(iterator.next()); // { value: 20, done: false }
console.log(iterator.next()); // { value: undefined, done: true }
```

迭代器通常是一次性的、有状态的游标；可迭代集合通常可以反复创建新迭代器。

```js
const values = [1, 2, 3];
console.log([...values]); // 每次展开都取得一个新迭代器
console.log([...values]);
```

## 3. 自定义可迭代对象

实现 `[Symbol.iterator]()` 即可让领域对象参与语言级迭代。每次调用应创建独立状态，以支持并行遍历。

```js
function createRange(start, end, step = 1) {
  if (step <= 0) throw new RangeError("step 必须大于 0");

  return {
    [Symbol.iterator]() {
      let current = start;
      return {
        next() {
          if (current > end) return { value: undefined, done: true };
          const value = current;
          current += step;
          return { value, done: false };
        },
      };
    },
  };
}

console.log([...createRange(2, 8, 2)]); // [2, 4, 6, 8]
```

手写迭代器能展示协议，但业务代码中生成器通常更简洁。

## 4. 提前结束与迭代器关闭

迭代器可以实现可选的 `return()` 方法，用于消费者提前退出时清理资源。`for...of` 中的 `break`、`throw`、`return` 通常会触发关闭流程。

```js
const resource = {
  [Symbol.iterator]() {
    let value = 0;
    return {
      next() {
        return { value: value++, done: false };
      },
      return() {
        console.log("释放迭代资源");
        return { done: true };
      },
    };
  },
};

for (const value of resource) {
  console.log(value);
  if (value === 2) break;
}
```

如果迭代器持有文件句柄、读取器或订阅，清理协议尤其重要。不过外部资源还应有独立兜底清理，而不能只依赖消费者正确迭代。

## 5. 生成器：可暂停的函数

生成器函数使用 `function*` 声明，调用时不会立即执行函数体，而是返回生成器对象。每次 `next()` 将执行推进到下一个 `yield`。

```js
function* trafficLights() {
  yield "red";
  yield "green";
  yield "yellow";
}

const lights = trafficLights();
console.log(lights.next());
console.log(lights.next());
console.log([...lights]); // ["yellow"]，继续消费剩余部分
```

生成器同时是迭代器和可迭代对象，因此可以直接用于 `for...of`。

## 6. 用生成器表达惰性序列

生成器按需计算，适合大序列、无限序列或组合式数据管道。只有消费到某个值时，相应计算才发生。

```js
function* fibonacci() {
  let previous = 0;
  let current = 1;

  while (true) {
    yield previous;
    [previous, current] = [current, previous + current];
  }
}

function* take(iterable, count) {
  if (count <= 0) return;
  let taken = 0;
  for (const value of iterable) {
    yield value;
    taken += 1;
    if (taken >= count) return;
  }
}

console.log([...take(fibonacci(), 8)]); // [0, 1, 1, 2, 3, 5, 8, 13]
```

无限生成器不能直接展开为数组，必须由 `take` 一类边界限制消费。

## 7. yield* 委托迭代

`yield*` 把一段迭代过程委托给另一个可迭代对象，适合递归结构和组合序列。

```js
function* walkTree(node) {
  yield node.name;
  for (const child of node.children ?? []) {
    yield* walkTree(child);
  }
}

const tree = {
  name: "root",
  children: [
    { name: "docs" },
    { name: "src", children: [{ name: "index.js" }] },
  ],
};

console.log([...walkTree(tree)]); // ["root", "docs", "src", "index.js"]
```

与手动嵌套循环相比，委托能保持遍历逻辑聚焦，并自动转发产生的值。

## 8. next、return 与 throw 的双向通信

生成器不仅能向外产生值，调用者还可通过 `next(value)` 把值送回暂停点。第一次 `next()` 的参数会被忽略，因为还没有暂停的 `yield` 接收它。

```js
function* questionnaire() {
  const name = yield "你的名字？";
  const language = yield "常用语言？";
  return `${name} 使用 ${language}`;
}

const form = questionnaire();
console.log(form.next().value);
console.log(form.next("Ada").value);
console.log(form.next("JavaScript"));
```

`return(value)` 可要求生成器结束，`throw(error)` 可在暂停点抛入异常。虽然这能实现复杂控制流，但日常异步业务优先使用 `async/await`，通常更易读。

用 `try...finally` 处理提前关闭：

```js
function* managedSequence() {
  try {
    yield 1;
    yield 2;
  } finally {
    console.log("生成器已关闭");
  }
}

const sequence = managedSequence();
sequence.next();
sequence.return(); // 执行 finally
```

## 9. 异步迭代

异步可迭代对象实现 `[Symbol.asyncIterator]()`，其 `next()` 返回 Promise。异步生成器用 `async function*` 简化实现，消费端用 `for await...of`。

```js
const delay = (milliseconds) =>
  new Promise((resolve) => setTimeout(resolve, milliseconds));

async function* fetchPages(pageCount) {
  for (let page = 1; page <= pageCount; page += 1) {
    await delay(10);
    yield { page, items: [`item-${page}`] };
  }
}

async function run() {
  for await (const result of fetchPages(3)) {
    console.log(result);
  }
}

await run(); // 在 ES 模块中运行
```

异步迭代适合分页接口、流式响应、消息通道等“随时间到达的序列”。上例是串行拉取；如果各任务相互独立且需要并发，应使用有并发上限的任务池，而不是机械改成异步生成器。

## 10. 可取消的异步生成器

外部 I/O 通常应接收 `AbortSignal`，让停止消费能够真正终止底层任务，而不只是忽略结果。

```js
async function* poll(signal) {
  let count = 0;
  while (!signal.aborted) {
    await delay(20);
    if (signal.aborted) return;
    yield count++;
  }
}

const controller = new AbortController();

for await (const value of poll(controller.signal)) {
  console.log(value);
  if (value === 2) controller.abort();
}
```

真实网络请求应把同一个 `signal` 传给 `fetch`，并在 `finally` 中释放流读取器等资源。

## 常见陷阱与最佳实践

- **混淆 iterable 与 iterator**：前者能创建迭代器，后者记录一次遍历状态。
- **重复消费同一个迭代器**：迭代器通常不会自动回到开头；需要重跑时创建新迭代器。
- **把无限序列直接展开**：必须限制数量，否则会耗尽内存或永久运行。
- **在生成器中隐藏过多业务控制流**：简单集合转换优先使用数组方法或普通函数。
- **忽略提前退出清理**：资源型迭代器实现 `return()`，生成器使用 `try...finally`。
- **将异步迭代误当并发**：`for await...of` 通常逐项等待，需要并发时显式设计并发度。
- **只停止消费却不取消 I/O**：通过 `AbortController` 将取消传播到底层操作。
- **把生成器当作数组**：惰性序列没有现成长度，也可能只能消费一次。

## 章节小结

迭代协议把“数据如何产生”与“数据如何消费”解耦。生成器用暂停和恢复机制简化惰性序列，自定义迭代器则能精确控制状态和资源释放；异步迭代把同一模型扩展到随时间到达的数据。使用时应始终明确序列是否有限、能否重复消费、如何提前结束以及底层资源由谁清理。

# 最佳实践

> 上一章：[-工作者线程](/kb/language/JavaScript/核心语法/26-工作者线程/) · 下一章：[-未来展望](/kb/language/JavaScript/核心语法/28-未来展望/)

## 学习目标

- 编写可读、可维护且边界明确的现代 JavaScript
- 用测量驱动性能优化，改善加载与运行时响应
- 识别 XSS、原型污染、依赖链等常见安全风险
- 建立包含静态检查、测试、可观测性和发布控制的工程闭环

## 1. 可维护性优先

代码被阅读和修改的次数通常多于首次编写。清晰命名、较小职责和显式数据流比技巧性短代码更有价值。

```js
// 不清晰：参数和结果含义需要猜测
const f = (a, b) => a.filter((x) => x.s === b).map((x) => x.n);

// 清晰：业务含义体现在名称中
function getActiveCustomerNames(customers) {
  return customers
    .filter((customer) => customer.status === "active")
    .map((customer) => customer.name);
}
```

函数应围绕一个可描述的职责组织。不要为追求行数而过度拆分，但当一段逻辑同时承担校验、网络、持久化和渲染时，应划分边界。

## 2. 语言使用约定

现代代码通常遵循以下原则：

- 默认使用 `const`，确需重新赋值时使用 `let`，不用 `var`
- 使用 `===` / `!==`，只在明确理解类型转换时使用宽松相等
- 用可选链 `?.` 和空值合并 `??` 表达缺失值，不误伤 `0`、`false`、空字符串
- 使用模板字符串、解构和对象简写，但不牺牲可读性
- Promise 链与 `async` / `await` 保持一致的错误边界
- 用 `Map`、`Set` 表达专门语义，而不是勉强套用普通对象和数组

```js
function formatRetries(options = {}) {
  const retries = options.retries ?? 3;
  const label = options.meta?.label ?? "未命名任务";
  return `${label}：最多重试 ${retries} 次`;
}

console.log(formatRetries({ retries: 0 })); // 正确保留 0
```

## 3. 边界校验与不可变更新

外部输入包括网络响应、URL、存储内容、表单、跨窗口消息和第三方库结果。静态类型不能验证运行时数据，校验应发生在系统边界。

```js
function parseOrder(input) {
  if (!input || typeof input !== "object" || Array.isArray(input)) {
    throw new TypeError("订单必须是对象");
  }
  if (typeof input.id !== "string" || !Number.isInteger(input.quantity)) {
    throw new TypeError("订单字段不合法");
  }
  if (input.quantity < 1 || input.quantity > 100) {
    throw new RangeError("订单数量超出范围");
  }
  return { id: input.id, quantity: input.quantity };
}
```

更新共享状态时避免原地修改，尤其在依赖引用比较的 UI 框架中：

```js
const state = { user: { name: "Ada" }, items: [1, 2] };
const nextState = {
  ...state,
  user: { ...state.user, name: "Grace" },
  items: [...state.items, 3]
};

console.log(state.user.name);     // Ada
console.log(nextState.user.name); // Grace
```

不可变不是要求深拷贝整个世界，而是在状态边界创建发生变化的路径。

## 4. 错误处理与可观测性

只在能恢复、补充上下文或转换错误的层级捕获异常。不要捕获后静默忽略。

```js
async function loadSettings(userId) {
  try {
    const response = await fetch(`/api/users/${encodeURIComponent(userId)}/settings`);
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return await response.json();
  } catch (error) {
    throw new Error(`加载用户 ${userId} 的设置失败`, { cause: error });
  }
}
```

日志应包含请求 ID、功能位置、错误链和可操作上下文，但不得泄露令牌、密码和完整个人数据。生产监控需要同时关注错误率、延迟、资源加载和用户体验指标。

## 5. DOM 与渲染性能

浏览器每帧时间有限。同步长任务会阻塞输入和渲染。优化前先在 Performance 面板和真实用户监控中定位瓶颈。

批量构造 DOM，减少反复插入：

```js
function renderNames(names, list) {
  const fragment = document.createDocumentFragment();
  for (const name of names) {
    const item = document.createElement("li");
    item.textContent = name;
    fragment.append(item);
  }
  list.replaceChildren(fragment);
}
```

避免交替读取布局属性和写入样式造成布局抖动。先集中读取，再集中写入。视觉更新使用 `requestAnimationFrame()`；非关键任务可切片或调度到空闲阶段，但不能假设空闲回调一定及时发生。

高频事件可按场景限流：

```js
let scheduled = false;

window.addEventListener("scroll", () => {
  if (scheduled) return;
  scheduled = true;
  requestAnimationFrame(() => {
    document.documentElement.dataset.scrolled = String(window.scrollY > 0);
    scheduled = false;
  });
}, { passive: true });
```

## 6. 网络与加载性能

性能预算应覆盖 JavaScript 体积、图片、字体、请求数和第三方脚本。主要策略包括：

- 删除未使用代码，使用 ESM 和可靠的 Tree Shaking
- 按路由或大型低频功能动态导入
- 压缩文本资源，使用现代图片格式与响应式图片
- 正确设置长期缓存和内容哈希
- 避免加载后立即执行大量初始化
- 对独立请求并行，对大列表设置并发上限
- 根据 Core Web Vitals 等真实数据优化用户可感知体验

```js
async function openEditor() {
  const { mountEditor } = await import("./editor.js");
  mountEditor(document.querySelector("#editor"));
}

document.querySelector("#edit")?.addEventListener("click", openEditor, { once: true });
```

微优化循环语法通常不如减少算法复杂度、数据量、网络往返和主线程长任务有效。

## 7. 防御 XSS

XSS 发生在不可信数据被当作 HTML 或脚本解释时。默认使用 `textContent`，只有经过可靠净化且确实需要富文本时才使用 `innerHTML`。

```js
const message = new URL(location.href).searchParams.get("message") ?? "";
document.querySelector("#message").textContent = message;
```

高风险位置还包括事件处理属性、`javascript:` URL、`eval()`、`new Function()`、字符串形式的 `setTimeout`。采用严格 Content Security Policy，并逐步启用 Trusted Types，可降低注入漏洞造成的影响。

前端转义不能代替服务端校验。不同上下文需要不同编码规则，HTML 文本、属性、URL、CSS 和 JavaScript 字符串不能共享一个“万能转义函数”。

## 8. 原型污染与对象安全

把不可信键递归合并到普通对象可能修改原型链。应限制允许字段，不接受 `__proto__`、`constructor`、`prototype` 等危险路径。

```js
const allowedKeys = new Set(["theme", "density"]);

function readPreferences(input) {
  const output = Object.create(null);
  for (const [key, value] of Object.entries(input)) {
    if (allowedKeys.has(key) && typeof value === "string") {
      output[key] = value;
    }
  }
  return output;
}
```

不要用 `{ ...untrusted }` 就断言数据安全。展开语法不会完成业务校验，也不会限制危险或无关字段。

## 9. 身份、请求与秘密

- 浏览器代码中的字符串对用户可见，不能保存真正的秘密
- Cookie 会话使用 `HttpOnly`、`Secure`、合适的 `SameSite`
- 写操作实施 CSRF 防护，跨源消息校验 `origin`
- 服务端执行授权，不能依赖前端隐藏按钮
- URL 中避免放令牌和敏感数据，因为它们会进入历史、日志和 Referer
- 对重定向目标使用允许列表，防止开放重定向

```js
window.addEventListener("message", (event) => {
  if (event.origin !== "https://trusted.example") return;
  if (!event.data || event.data.type !== "resize") return;
  console.log("可信消息", event.data.height);
});
```

## 10. 依赖与供应链

每个依赖都会增加体积、漏洞和维护成本。引入前评估是否必要、维护状态、许可证、发布历史和浏览器支持。锁定依赖版本，在 CI 中审计已知漏洞，但不要把自动审计结果当作完整安全证明。

尽量减少第三方脚本权限。必须加载外部静态资源时可使用 Subresource Integrity；更关键的是限制来源、部署 CSP，并准备第三方服务不可用时的降级策略。

## 11. 测试与自动化质量门

测试组合应匹配风险：

- 单元测试覆盖纯逻辑与边界条件
- 集成测试覆盖模块、存储和网络协作
- 端到端测试覆盖少量关键用户路径
- 可访问性、兼容性与性能检查进入持续集成

```js
import test from "node:test";
import assert from "node:assert/strict";

function calculateTotal(items) {
  return items.reduce((total, item) => total + item.price * item.quantity, 0);
}

test("calculateTotal 汇总价格和数量", () => {
  assert.equal(calculateTotal([
    { price: 10, quantity: 2 },
    { price: 5, quantity: 1 }
  ]), 25);
});
```

格式化器解决风格一致性，lint 发现可疑模式，类型检查发现接口不匹配，测试验证行为。它们相互补充，不能互相替代。

## 12. 渐进增强与可访问性

优先使用语义 HTML 和平台能力，再用 JavaScript 增强。按钮应使用 `&lt;button&gt;` 而非带点击事件的 `<div>`；表单应保留标签、键盘操作、焦点管理和可理解的错误提示。

功能检测优于仅根据 User-Agent 推断：

```js
if ("IntersectionObserver" in window) {
  // 使用增强体验
} else {
  // 提供无需该 API 的基本体验
}
```

对新 API 提供合理降级，不为极少用户加载巨大 polyfill 之前先评估用户分布和业务要求。

## 常见陷阱与最佳实践

- 不做无测量依据的性能优化，也不忽略明显的 O(n²) 和长任务
- 不以压缩代码行数替代清晰抽象
- 不信任任何跨边界数据，包括本地存储和 `postMessage`
- 不用 `innerHTML` 渲染未经净化的用户内容
- 不在客户端存储秘密，不把前端校验当作授权
- 为请求、订阅、定时器和 Worker 提供取消与清理
- 保持依赖少而明确，自动化检查锁文件和发布产物
- 用真实设备和用户指标验证性能、兼容性与可访问性

## 章节小结

最佳实践不是固定技巧清单，而是围绕可维护性、正确性、性能和安全持续做权衡。现代 JavaScript 工程以清晰边界和平台能力为基础，通过测量、运行时校验、自动化测试与生产可观测性建立反馈闭环。先解决高影响问题，再引入与收益匹配的复杂度。

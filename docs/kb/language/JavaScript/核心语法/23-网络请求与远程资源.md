# 网络请求与远程资源

> 上一章：[-XML与JSON](/kb/language/JavaScript/核心语法/22-XML与JSON/) · 下一章：[-客户端存储](/kb/language/JavaScript/核心语法/24-客户端存储/)

## 学习目标

- 用 `fetch()` 完成现代 HTTP 请求与响应处理
- 理解状态码、请求头、跨域、凭据、缓存和取消机制
- 掌握超时、重试、并发控制和流式响应的基本实现
- 了解 XMLHttpRequest 的历史用途与保留场景

## 1. HTTP 请求的组成

前端网络代码位于浏览器安全模型之中。一次请求通常包含 URL、方法、请求头和可选请求体；响应包含状态码、响应头和响应体。接口成功与否不能只看“请求是否发出”，还要结合 HTTP 状态和业务数据判断。

常见方法语义：

- `GET`：读取资源，应尽量无副作用且可缓存
- `POST`：创建资源或提交操作
- `PUT`：整体替换，通常具备幂等语义
- `PATCH`：部分更新
- `DELETE`：删除资源，通常设计为幂等

## 2. fetch 基础

`fetch()` 返回 Promise。它只在网络失败、取消或策略阻止时拒绝；服务器返回 `404`、`500` 时 Promise 仍会兑现，因此必须检查 `response.ok`。

```js
async function getUser(id) {
  const response = await fetch(`/api/users/${encodeURIComponent(id)}`, {
    headers: { Accept: "application/json" }
  });

  if (!response.ok) {
    throw new Error(`读取用户失败：HTTP ${response.status}`);
  }
  return response.json();
}

getUser("42").then(console.log).catch(console.error);
```

响应体是一次性流。调用 `json()`、`text()`、`blob()`、`arrayBuffer()` 或读取 `body` 后，不能再次读取同一响应；确需读取两次时可提前 `response.clone()`，但会增加内存与流处理成本。

## 3. 提交 JSON 与表单

发送 JSON 时同时设置媒体类型：

```js
async function createTodo(title) {
  const response = await fetch("/api/todos", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      Accept: "application/json"
    },
    body: JSON.stringify({ title })
  });

  if (!response.ok) throw new Error(`创建失败：${response.status}`);
  return response.json();
}
```

上传文件应使用 `FormData`，不要手动设置 `Content-Type`，浏览器会生成包含 boundary 的正确请求头：

```js
async function uploadAvatar(file) {
  const form = new FormData();
  form.append("avatar", file);

  const response = await fetch("/api/avatar", {
    method: "POST",
    body: form
  });
  if (!response.ok) throw new Error("上传失败");
  return response.json();
}
```

## 4. 取消、超时与竞态

使用 `AbortController` 取消不再需要的请求。取消后通常会抛出名为 `AbortError` 的异常。

```js
const controller = new AbortController();

fetch("/api/report", { signal: controller.signal })
  .then((response) => {
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return response.json();
  })
  .then(console.log)
  .catch((error) => {
    if (error.name !== "AbortError") console.error(error);
  });

// 用户离开页面或发起了更新的同类请求时调用
controller.abort();
```

支持 `AbortSignal.timeout()` 的现代环境可直接设置超时：

```js
async function fetchWithTimeout(url, ms = 5000) {
  const response = await fetch(url, {
    signal: AbortSignal.timeout(ms)
  });
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.json();
}
```

搜索联想等场景应取消旧请求，避免较慢的旧响应覆盖新结果。取消不仅是优化，也是维持界面状态一致性的手段。

## 5. 重试与并发

重试应限定在暂时性故障，并考虑方法是否幂等。对无幂等键的 `POST` 自动重试可能创建重复订单。

```js
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function fetchJsonWithRetry(url, attempts = 3) {
  for (let index = 0; index < attempts; index += 1) {
    try {
      const response = await fetch(url);
      if (response.ok) return response.json();
      if (response.status < 500 && response.status !== 429) {
        throw new Error(`不可重试的 HTTP ${response.status}`);
      }
    } catch (error) {
      if (index === attempts - 1) throw error;
    }
    await wait(300 * 2 ** index + Math.random() * 100);
  }
  throw new Error("请求重试失败");
}
```

独立请求可并行，相关请求则按依赖顺序执行：

```js
async function loadDashboard() {
  const [profileResponse, noticesResponse] = await Promise.all([
    fetch("/api/profile"),
    fetch("/api/notices")
  ]);

  if (!profileResponse.ok || !noticesResponse.ok) {
    throw new Error("仪表盘加载失败");
  }
  return Promise.all([profileResponse.json(), noticesResponse.json()]);
}
```

大量请求应设置并发上限，不要一次 `Promise.all()` 数千个 URL。

## 6. 流式读取

`Response.body` 是 `ReadableStream`。文本流可逐块处理，降低首屏等待和峰值内存：

```js
async function printTextStream(url) {
  const response = await fetch(url);
  if (!response.ok || !response.body) throw new Error("流不可用");

  const reader = response.body.pipeThrough(new TextDecoderStream()).getReader();
  while (true) {
    const { value, done } = await reader.read();
    if (done) break;
    console.log(value);
  }
}
```

任意分块不等于消息边界。处理 NDJSON、SSE 或自定义协议时必须缓存残片并按协议分隔符拆分。

## 7. 跨域、凭据与 CSRF

同源策略限制脚本读取跨源响应。CORS 由服务器通过响应头授权，前端不能靠添加 `Access-Control-Allow-Origin` 绕过。某些方法和请求头会触发 OPTIONS 预检。

```js
const response = await fetch("https://api.example.com/me", {
  credentials: "include",
  headers: { Accept: "application/json" }
});
```

跨源发送 Cookie 时，服务端必须明确允许来源和凭据，Cookie 还受 `SameSite`、`Secure` 等属性影响。Cookie 身份认证的写操作需要 CSRF 防护；CORS 本身不是完整的 CSRF 防线。

`mode: "no-cors"` 通常只得到不可读取的 opaque 响应，不是解决跨域接口访问的方案。

## 8. 缓存与资源提示

HTTP 缓存由 `Cache-Control`、`ETag`、`Last-Modified` 等头控制。客户端应尊重协议，而不是随意给 URL 加时间戳禁用缓存。`fetch` 的 `cache` 选项可调整与浏览器 HTTP 缓存的交互，但不能替代服务端正确配置。

静态关键资源可使用 `&lt;link rel="preload"&gt;`，可能很快访问的跨源站点可使用 `preconnect`。资源提示过多会争抢带宽，应通过性能数据决定。

## 9. XMLHttpRequest 简述

`XMLHttpRequest` 是 fetch 之前的主要 API。新代码通常优先 fetch；XHR 仍可能用于需要上传进度事件的旧代码或遗留兼容层。

```js
const xhr = new XMLHttpRequest();
xhr.open("GET", "/api/status");
xhr.responseType = "json";
xhr.onload = () => {
  if (xhr.status >= 200 && xhr.status < 300) console.log(xhr.response);
};
xhr.onerror = () => console.error("网络错误");
xhr.send();
```

不要在主线程使用同步 XHR，它会阻塞页面且已被平台强烈限制。

## 常见陷阱与最佳实践

- 始终检查 `response.ok` 或明确允许的状态码
- 只读取响应体一次，并根据 `Content-Type` 选择解析方式
- 对用户输入的 URL 参数使用 `URL`、`URLSearchParams` 或 `encodeURIComponent`
- 组件卸载、路由切换或新请求开始时取消旧请求
- 重试使用指数退避和抖动，并限制次数
- 不在日志中记录令牌、Cookie、完整个人数据或敏感请求体
- 服务端负责 CORS、缓存和内容类型的正确响应头
- 对接口输入输出做运行时校验，错误信息同时保留状态和可诊断上下文

## 章节小结

现代网络请求的核心是 fetch、Promise、流与 AbortSignal。健壮代码必须区分网络错误、HTTP 错误和业务错误，并正确处理取消、重试、并发、缓存与浏览器安全边界。XHR 只需保留维护旧系统和上传进度场景所需的认识。

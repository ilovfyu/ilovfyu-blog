# 代理与反射

## 学习目标

- 理解 `Proxy`、目标对象和捕获器之间的关系。
- 掌握常用捕获器及 `Reflect` 的对应操作。
- 能实现验证、观测、负索引等实用功能。
- 识别代理不变量、内部槽位、身份与性能方面的限制。

## 1. Proxy 的基本模型

`Proxy` 在目标对象前建立一层可编程拦截。对代理执行读取、写入、调用等内部操作时，处理器中对应的捕获器会被调用。

```js
const target = { message: "hello" };
const proxy = new Proxy(target, {
  get(object, key, receiver) {
    console.log(`读取 ${String(key)}`);
    return Reflect.get(object, key, receiver);
  },
  set(object, key, value, receiver) {
    console.log(`写入 ${String(key)} = ${value}`);
    return Reflect.set(object, key, value, receiver);
  },
});

proxy.message;
proxy.count = 1;
console.log(target.count); // 1
```

代理不是目标对象的透明克隆。`proxy !== target`，二者作为 `Map` 键或 `Set` 成员时也是不同身份。

## 2. 为什么配合 Reflect

`Reflect` 将许多对象内部操作暴露为函数，命名和参数通常与代理捕获器一一对应。捕获器若只想扩展默认行为，转发给 `Reflect` 比手写 `target[key]` 更准确。

```js
const person = {
  firstName: "Grace",
  get label() {
    return this.firstName.toUpperCase();
  },
};

const observed = new Proxy(person, {
  get(target, key, receiver) {
    return Reflect.get(target, key, receiver);
  },
});

console.log(observed.label); // GRACE
```

这里传入 `receiver` 很重要：访问器中的 `this` 应指向最初参与操作的接收者，而不总是原始目标。

`Reflect.set()`、`Reflect.deleteProperty()`、`Reflect.defineProperty()` 等通常返回布尔值，便于统一处理成功或失败，而不是混合异常和隐式结果。

## 3. 常用捕获器

常见捕获器及用途如下：

| 捕获器 | 拦截的操作 | 常见用途 |
| --- | --- | --- |
| `get` | 属性读取 | 默认值、观测、懒加载 |
| `set` | 属性写入 | 校验、变更通知 |
| `has` | `key in object` | 控制可见性 |
| `deleteProperty` | `delete object[key]` | 审计、禁止删除 |
| `ownKeys` | 自有键枚举 | 虚拟键、过滤键 |
| `getOwnPropertyDescriptor` | 读取描述符 | 配合虚拟属性 |
| `apply` | 调用函数 | 计时、参数规范化 |
| `construct` | `new` 调用 | 构造参数检查 |

处理器可以只实现需要的捕获器，其他操作会直接转发到目标。

## 4. 数据验证

```js
const schema = {
  name: (value) => typeof value === "string" && value.length > 0,
  age: (value) => Number.isInteger(value) && value >= 0,
};

const user = new Proxy({}, {
  set(target, key, value, receiver) {
    const validate = schema[key];
    if (!validate) throw new TypeError(`未知字段：${String(key)}`);
    if (!validate(value)) throw new TypeError(`${String(key)} 的值无效`);
    return Reflect.set(target, key, value, receiver);
  },
});

user.name = "Lin";
user.age = 28;
console.log(user);
// user.age = -1; // TypeError
```

代理适合运行时边界校验，但不能代替静态类型工具或服务端校验。传入代理前已持有目标引用的代码仍可绕过代理。

## 5. 为数组实现负索引

```js
function withNegativeIndex(array) {
  return new Proxy(array, {
    get(target, key, receiver) {
      const index = Number(key);
      if (Number.isInteger(index) && index < 0) {
        return Reflect.get(target, String(target.length + index), receiver);
      }
      return Reflect.get(target, key, receiver);
    },
  });
}

const values = withNegativeIndex([10, 20, 30]);
console.log(values[-1], values[-2]); // 30 20
```

实际项目中读取末尾元素优先使用标准方法 `array.at(-1)`。这个例子主要用于展示属性键转换与拦截逻辑。

## 6. 代理函数

函数也是对象，可以拦截普通调用和构造调用。

```js
function sum(a, b) {
  return a + b;
}

const measuredSum = new Proxy(sum, {
  apply(target, thisArg, args) {
    const start = performance.now();
    const result = Reflect.apply(target, thisArg, args);
    console.log(`耗时 ${(performance.now() - start).toFixed(3)}ms`);
    return result;
  },
});

console.log(measuredSum(2, 3));
```

`apply` 捕获器要求目标本身可调用，`construct` 捕获器要求目标可构造。代理不能凭空让普通对象变成函数。

## 7. 可撤销代理

`Proxy.revocable()` 适合临时授权：撤销后，对代理的大部分操作都会抛出 `TypeError`。

```js
const documentData = { content: "draft" };
const { proxy: temporaryAccess, revoke } = Proxy.revocable(documentData, {});

console.log(temporaryAccess.content);
revoke();
// console.log(temporaryAccess.content); // TypeError
```

撤销不会销毁目标，也不会撤销其他持有者对目标的访问。

## 8. 代理不变量

捕获器不能任意“说谎”。语言规范要求代理保持目标对象的关键事实，例如：

- 不可配置的自有属性不能被 `ownKeys` 隐藏。
- 不可扩展目标不能凭空报告额外自有属性。
- 不可写、不可配置的数据属性不能被 `get` 报告为其他值。
- `set`、`deleteProperty` 等捕获器返回值必须符合目标描述符约束。

```js
const fixed = {};
Object.defineProperty(fixed, "id", {
  value: 1,
  configurable: false,
});

const invalid = new Proxy(fixed, {
  ownKeys() {
    return [];
  },
});

// Object.keys(invalid); // TypeError：不能隐藏不可配置属性
```

## 9. 内部槽位与 this

部分内建对象依赖内部槽位。简单代理后调用其方法，方法中的 `this` 是代理而非原目标，可能报“不兼容接收者”错误。

```js
const map = new Map([["a", 1]]);
const safeMap = new Proxy(map, {
  get(target, key) {
    const value = Reflect.get(target, key, target);
    return typeof value === "function" ? value.bind(target) : value;
  },
});

console.log(safeMap.get("a"));
```

绑定方法可解决常见调用问题，但会改变方法身份，并使方法内部操作绕过代理。设计包装层时应明确这种取舍。

## 常见陷阱与最佳实践

1. 捕获器优先使用同名 `Reflect` 方法转发，尤其注意传递 `receiver`。
2. `set`、`deleteProperty` 等捕获器应返回布尔值；严格模式下返回 `false` 可能导致异常。
3. 不要在捕获器中通过代理本身重复执行同一操作，否则会无限递归。
4. 代理不能拦截使用原始目标引用进行的操作，因此应控制目标对象的暴露范围。
5. 不要把代理放在极热循环中而不测量性能；属性拦截会妨碍部分引擎优化。
6. 私有字段带有品牌检查，代理实例通常不能直接作为私有方法的合法接收者。
7. 序列化、严格相等与对象身份相关逻辑要区分代理和目标。

## 章节小结

`Proxy` 提供元编程拦截能力，`Reflect` 提供与语言内部操作一致的转发接口。二者适合实现边界校验、访问观测和 API 包装，但代理受语言不变量、目标身份与内部槽位限制。使用时应尽量只增强默认语义，而不是制造难以理解的“魔法对象”。

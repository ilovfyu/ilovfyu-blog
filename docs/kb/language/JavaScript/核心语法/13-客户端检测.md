# 客户端检测

## 学习目标

- 理解能力检测、行为检测、浏览器检测与渐进增强的差异。
- 能为 Web API 设计可靠的支持判断和降级路径。
- 知道何时才应解析 User-Agent 或使用 User-Agent Client Hints。
- 避免检测结果与真实运行行为脱节。

## 1. 为什么需要客户端检测

Web 应用运行在不同浏览器版本、操作系统、输入设备、权限状态和嵌入环境中。检测的目的不是给用户贴上“某浏览器”的标签，而是确认当前环境能否完成某项任务，并选择合适实现。

现代策略的优先级通常是：

1. 使用广泛支持的标准和渐进增强。
2. 检测完成任务所需的具体能力。
3. 必要时验证 API 的实际行为。
4. 只有需求确实依赖浏览器或平台身份时才做身份检测。

## 2. 能力检测

能力检测直接询问“所需 API 是否存在”，而不是从浏览器名称推断支持情况。

```js
function savePreference(key, value) {
  if ("localStorage" in window) {
    try {
      localStorage.setItem(key, JSON.stringify(value));
      return true;
    } catch (error) {
      console.warn("本地存储不可用", error);
    }
  }
  return false;
}

console.log(savePreference("theme", "dark"));
```

仅有属性不代表调用一定成功。存储可能因隐私模式、配额或权限失败，所以仍要捕获运行时异常。

检测尽量靠近实际需求，并确认值的类型：

```js
const supportsShare = typeof navigator.share === "function";

async function sharePage(data) {
  if (supportsShare && (!navigator.canShare || navigator.canShare(data))) {
    await navigator.share(data);
    return;
  }
  await navigator.clipboard.writeText(data.url);
}
```

## 3. CSS 能力检测

样式特性优先通过 CSS 的 `@supports` 和媒体查询实现，不必把布局逻辑搬到 JavaScript。

```css
.cards {
  display: block;
}

@supports (display: grid) {
  .cards {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(16rem, 1fr));
  }
}

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    scroll-behavior: auto !important;
    animation-duration: 0.01ms !important;
  }
}
```

JavaScript 确实需要知道结果时，可使用 `CSS.supports()` 与 `matchMedia()`：

```js
const supportsGrid = CSS.supports("display", "grid");
const reducedMotion = matchMedia("(prefers-reduced-motion: reduce)");

console.log({ supportsGrid, reducedMotion: reducedMotion.matches });

reducedMotion.addEventListener("change", (event) => {
  console.log("减少动态效果偏好：", event.matches);
});
```

不要根据屏幕宽度判断“手机用户”。窗口可缩放，平板可连接键鼠，桌面也可能使用触屏。

## 4. 行为检测

有时 API 名称存在，但早期实现有缺陷或语义不完整。这时可运行最小、无破坏的测试验证关键行为。

```js
function supportsNamedGroups() {
  try {
    const match = /(?&lt;year&gt;\d{4})/.exec("2026");
    return match?.groups?.year === "2026";
  } catch {
    return false;
  }
}

console.log(supportsNamedGroups());
```

行为检测应满足：成本低、无可见副作用、结果可缓存、真正验证业务依赖的语义。不要为了检测而发送网络请求或弹出权限提示。

## 5. 权限与安全上下文

某些 API 同时要求能力存在、HTTPS、安全上下文、用户授权和用户手势。检测存在性只能完成第一步。

```js
async function getCameraPermissionState() {
  if (!isSecureContext || !navigator.mediaDevices?.getUserMedia) {
    return "unsupported";
  }

  if (!navigator.permissions?.query) return "unknown";

  try {
    const status = await navigator.permissions.query({ name: "camera" });
    return status.state;
  } catch {
    // 部分浏览器不支持查询 camera 权限，但仍支持实际请求。
    return "unknown";
  }
}

console.log(await getCameraPermissionState());
```

权限状态随时可能变化，且不同 API 的权限模型不同。真正调用时仍要处理 `NotAllowedError`、`NotFoundError` 等异常。

## 6. 输入方式与用户偏好

根据能力和偏好调整体验，比根据设备型号猜测更可靠。

```js
const coarsePointer = matchMedia("(pointer: coarse)").matches;
const hasHover = matchMedia("(hover: hover)").matches;
const darkScheme = matchMedia("(prefers-color-scheme: dark)").matches;
const highContrast = matchMedia("(prefers-contrast: more)").matches;

console.log({ coarsePointer, hasHover, darkScheme, highContrast });
```

这些查询表达“当前主要输入方式或偏好”，不是永久设备分类。设备可热插拔，媒体查询结果也会变化；关键界面应允许用户手动覆盖自动判断。

## 7. User-Agent 检测的局限

`navigator.userAgent` 是历史遗留字符串，存在伪装、格式复杂、版本冻结和隐私缩减问题。以下做法通常不可靠：

```js
// 不推荐：浏览器名称不能证明具体 API 可用。
if (navigator.userAgent.includes("Chrome")) {
  // 启用某功能
}
```

只有当问题确实由特定浏览器版本的已知缺陷导致，或服务端必须针对下载包、日志兼容性等身份信息作决策时，才考虑 UA 检测。此时应使用维护良好的解析库、记录检测原因，并设置移除条件。

## 8. User-Agent Client Hints

支持环境中可通过 `navigator.userAgentData` 获取结构化的低熵信息，并按需请求更高熵信息。它不是所有浏览器都支持，也不应用于功能检测。

```js
async function getPlatformInfo() {
  if (!navigator.userAgentData?.getHighEntropyValues) {
    return { platform: navigator.platform || "unknown" };
  }

  return navigator.userAgentData.getHighEntropyValues([
    "platform",
    "platformVersion",
    "architecture",
  ]);
}

console.log(await getPlatformInfo());
```

高熵信息增加指纹识别风险，浏览器可能拒绝、泛化或要求服务端通过响应头声明。只收集完成需求必需的数据。

## 9. 渐进增强与降级

可靠产品不只是“检测后显示不支持”，而是先提供基本路径，再增强体验。

```js
async function copy(text) {
  if (navigator.clipboard?.writeText && isSecureContext) {
    try {
      await navigator.clipboard.writeText(text);
      return { ok: true, method: "clipboard" };
    } catch {
      // 用户拒绝权限时继续提供手动方案。
    }
  }

  return { ok: false, method: "manual", text };
}

const result = await copy("https://example.com");
if (!result.ok) console.log("请手动复制：", result.text);
```

HTML 表单提交、普通链接和服务端渲染常可作为基础层；JavaScript 再增强即时校验、无刷新导航和交互反馈。

## 10. 构建期兼容与运行时检测

语法兼容通常在构建阶段处理，例如转译较新语法；API 兼容则可能需要 polyfill 或运行时分支。二者不能混为一谈：浏览器能解析箭头函数，不等于支持 `structuredClone()`。

推荐结合以下信息制定兼容策略：

- 明确受支持的浏览器和运行时范围。
- 使用 Browserslist 等工具统一构建目标。
- 参考 MDN、Can I Use 和真实遥测，而不是凭印象判断。
- 对关键能力做自动化跨浏览器测试。
- 按需加载 polyfill，避免给所有用户发送无用代码。

动态加载降级模块的示意：

```js
async function ensureDialogSupport() {
  if (typeof HTMLDialogElement === "undefined") {
    await import("./dialog-polyfill.js");
  }
}
```

## 11. 历史检测方式简述

早期网页常使用浏览器嗅探、条件注释、`document.all`、厂商前缀和对象怪癖区分浏览器。这些方式大多面向已经淘汰的环境，现代代码不应复用。厂商前缀仍可能出现在少量 CSS 或遗留 API 中，应交由构建工具和兼容数据库处理，而不是手工维护浏览器名单。

## 常见陷阱与最佳实践

1. 检测具体能力，不要由浏览器品牌间接推断能力。
2. API 存在不代表权限已授予、调用会成功或行为完全正确；实际调用必须处理失败。
3. 检测表达式应避免触发 getter 副作用，必要时用 `typeof`、可选链和 `try...catch`。
4. 不要把检测结果永久缓存到服务端；浏览器升级、设置和外接设备会改变环境。
5. 不要仅按触摸支持隐藏鼠标交互，也不要仅按宽度区分移动端和桌面端。
6. 身份与高熵信息涉及隐私，遵循数据最小化原则。
7. 降级路径也要测试，包括禁用 JavaScript、权限拒绝、离线和 API 调用失败。

## 章节小结

客户端检测的核心是围绕任务判断能力，而不是识别浏览器身份。CSS 特性使用 `@supports`，JavaScript API 使用存在性与必要的行为检测，敏感能力还要处理安全上下文、权限和用户手势。结合渐进增强、明确兼容目标和真实跨浏览器测试，才能获得长期可靠的体验。

# 模块

> 上一章：[-客户端存储](/kb/language/JavaScript/核心语法/24-客户端存储/) · 下一章：[-工作者线程](/kb/language/JavaScript/核心语法/26-工作者线程/)

## 学习目标

- 理解 ES Modules 的静态结构、作用域和实时绑定
- 熟练使用命名导出、默认导出、重导出与动态导入
- 区分浏览器 ESM、Node.js ESM 与 CommonJS
- 设计边界清晰、可测试且利于打包优化的模块

## 1. 为什么需要模块

模块把程序拆分为明确依赖与公开接口。相较于把脚本都挂到全局对象，模块提供独立作用域、显式导入导出、严格模式语义和可被工具静态分析的依赖图。

一个模块只应公开调用者真正需要的能力，内部实现保持私有：

```js
// counter.js
let count = 0;

export function increment() {
  count += 1;
}

export function getCount() {
  return count;
}
```

```js
// app.js
import { getCount, increment } from "./counter.js";

increment();
console.log(getCount()); // 1
```

## 2. 导出与导入

推荐优先使用命名导出。它让接口名称稳定、自动补全明确，也便于重构。

```js
// math.js
export const PI = Math.PI;

export function circleArea(radius) {
  return PI * radius ** 2;
}

function square(value) {
  return value * value;
}

export { square };
```

```js
import { circleArea, square as squared } from "./math.js";

console.log(circleArea(2));
console.log(squared(5));
```

默认导出允许导入方自行命名，适合模块确实只有一个主要概念时：

```js
// Logger.js
export default class Logger {
  info(message) {
    console.log(`[info] ${message}`);
  }
}
```

```js
import AppLogger from "./Logger.js";

new AppLogger().info("started");
```

避免一个文件堆叠大量不相关导出，也避免仅为创建“工具箱”而使用默认导出的巨型对象。

## 3. 实时绑定与只读导入

ESM 导入是导出绑定的只读视图，不是导入瞬间的值拷贝。

```js
// clock.js
export let ticks = 0;
export function tick() {
  ticks += 1;
}
```

```js
// observer.js
import { tick, ticks } from "./clock.js";

console.log(ticks); // 0
tick();
console.log(ticks); // 1
// ticks = 10;      // TypeError：不能给导入绑定赋值
```

导出的对象仍可被修改，因为只读的是绑定，不是对象本身。共享可变对象会让依赖难以追踪，通常应导出操作函数或不可变数据。

## 4. 模块加载与浏览器

浏览器中通过 `type="module"` 加载入口：

```html
&lt;script type="module" src="./app.js"&gt;&lt;/script&gt;
```

模块脚本默认延迟执行、默认启用严格模式，并受 CORS 约束。浏览器 ESM 的相对路径通常必须写完整扩展名。

模块顶层的 `this` 是 `undefined`，顶层声明不会成为 `window` 属性。每个模块在同一模块图中通常只求值一次，之后导入复用同一实例。

通过 `import.meta.url` 获取当前模块 URL，可可靠构造相邻资源路径：

```js
const workerUrl = new URL("./worker.js", import.meta.url);
console.log(workerUrl.href);
```

Import Maps 可让浏览器把裸模块名映射到 URL：

```html
&lt;script type="importmap"&gt;
{
  "imports": {
    "date-utils": "/vendor/date-utils.js"
  }
}
&lt;/script&gt;
```

生产环境仍需考虑版本锁定、缓存和内容安全策略。

## 5. 重导出与公共入口

包入口可集中重导出稳定 API：

```js
// index.js
export { parseDate, formatDate } from "./date.js";
export { createCalendar } from "./calendar.js";
```

`export * from` 不会转发默认导出，且大量 barrel 文件可能引入循环依赖、名称冲突或意外扩大打包范围。公共入口应服务于清晰边界，而不是机械转发每个内部文件。

## 6. 动态导入与代码分割

`import()` 返回 Promise，适合按路由、功能或用户操作延迟加载：

```js
async function exportReport(rows) {
  const { createCsv } = await import("./csv.js");
  return createCsv(rows);
}

document.querySelector("#export")?.addEventListener("click", async () => {
  const csv = await exportReport([{ id: 1, name: "Ada" }]);
  console.log(csv);
});
```

动态导入不是把所有小函数都拆成网络请求。应在足够大的、低频的功能边界上分割，并用实际加载指标验证收益。

## 7. 顶层 await

ESM 支持顶层 `await`，但当前模块及其依赖者会等待它完成：

```js
// config.js
const response = await fetch("/config.json");
if (!response.ok) throw new Error("配置加载失败");

export const config = await response.json();
```

顶层 await 适合模块初始化确实必须完成的情况。通用库中滥用它会把异步阻塞传播到整个模块图，更灵活的方式通常是导出显式的初始化函数或 Promise。

## 8. 循环依赖

模块 A 导入 B、B 又导入 A 就形成循环。ESM 的实时绑定能处理部分循环，但若模块求值期间过早读取尚未初始化的绑定，会抛出错误或出现难以理解的状态。

改善方式包括：

- 把双方共享概念提取到更低层模块
- 用依赖注入代替反向导入
- 避免模块顶层执行依赖业务状态的副作用
- 让依赖方向遵循领域层次，而不是通过 barrel 隐藏循环

## 9. Node.js ESM 与 CommonJS

Node.js 可通过 `.mjs`，或在 `package.json` 中设置 `"type": "module"` 使用 ESM。ESM 使用 `import` / `export`；传统 CommonJS 使用 `require()` / `module.exports`。两者解析、缓存和互操作规则不同，不应简单混用。

ESM 中没有 CommonJS 的 `__filename` 和 `__dirname`，可使用 `import.meta.url`，现代 Node 版本也提供相关便利属性。发布 npm 包时应通过 `exports` 明确公开入口，避免消费者依赖内部路径。

## 10. 模块设计与 Tree Shaking

打包器可基于 ESM 静态结构移除未使用导出，但效果依赖代码是否可静态分析以及副作用声明是否准确。

```js
// validators.js
export const isEmail = (value) => /^[^@]+@[^@]+$/.test(value);
export const isNonEmpty = (value) => value.trim().length > 0;
```

保持模块顶层少副作用，不要为了注册行为而隐式修改全局状态。包的 `sideEffects` 配置必须真实，否则打包器可能错误删除 CSS 导入或注册代码。

## 常见陷阱与最佳实践

- 优先命名导出，让公共 API 可发现且便于重构
- 在浏览器相对导入中写明路径和扩展名
- 避免共享可变状态和模块顶层业务副作用
- 通过依赖方向和职责拆分消除循环依赖
- 动态导入放在稳定的功能边界，不做无意义碎片化
- 不依赖包的内部文件路径，使用其公开 `exports`
- 测试公共行为而非内部实现，必要时通过参数注入依赖
- 同一项目明确 ESM/CommonJS 规则，避免文件含义随环境变化

## 章节小结

ES Modules 是现代 JavaScript 组织、加载和优化代码的基础。其关键不只在语法，而在静态依赖、实时绑定、模块作用域和明确接口。良好模块边界可以减少全局状态与循环依赖，并为按需加载、测试和 Tree Shaking 提供基础。

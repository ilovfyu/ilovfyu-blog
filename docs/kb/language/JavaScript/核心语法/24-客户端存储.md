# 客户端存储

> 上一章：[-网络请求与远程资源](/kb/language/JavaScript/核心语法/23-网络请求与远程资源/) · 下一章：[-模块](/kb/language/JavaScript/核心语法/25-模块/)

## 学习目标

- 区分 Cookie、Web Storage、IndexedDB 与 Cache API
- 根据容量、生命周期、查询和安全要求选择存储方案
- 掌握 localStorage 与 IndexedDB 的核心操作
- 设计可迁移、可过期、可清理且不保存敏感信息的客户端数据

## 1. 先决定是否应该存

客户端存储可改善离线体验、减少网络请求并恢复界面状态，但也带来过期数据、隐私泄露、版本迁移和容量限制。选择前先回答：

- 数据是否必须跨页面或跨会话保留？
- 数据能否由服务器重新获取？
- 数据量、查询方式和更新频率如何？
- 如果设备被共享或发生 XSS，数据暴露后果是什么？
- 是否需要离线访问和原子事务？

浏览器存储通常按源隔离，实际配额和清理策略因浏览器、设备、隐私模式而异。任何客户端存储都不能视为永久数据库。

## 2. Cookie

Cookie 适合需要随 HTTP 请求发送的小型状态，例如由服务端管理的会话标识。它容量小，每次匹配请求都会携带，不适合保存大量应用数据。

服务端设置会话 Cookie 的典型属性：

```http
Set-Cookie: session=opaque-id; Path=/; HttpOnly; Secure; SameSite=Lax; Max-Age=1800
```

- `HttpOnly`：阻止 JavaScript 读取，降低会话标识被 XSS 直接窃取的风险
- `Secure`：只通过 HTTPS 发送
- `SameSite`：限制跨站发送，有助于防御 CSRF
- `Max-Age` / `Expires`：控制持久时间
- `Path` / `Domain`：控制发送范围，应尽量收窄

脚本可通过 `document.cookie` 写入非 HttpOnly Cookie，但 API 是字符串接口且操作不直观：

```js
document.cookie = `theme=${encodeURIComponent("dark")}; Path=/; Max-Age=2592000; SameSite=Lax; Secure`;
console.log(document.cookie);
```

身份会话优先由服务端通过安全属性设置，不要把认证令牌放入可被脚本读取的 Cookie 只是为了方便。

## 3. localStorage 与 sessionStorage

Web Storage 保存字符串键值。`localStorage` 跨会话保留，`sessionStorage` 通常只在当前标签页会话存在。

```js
const key = "app:preferences:v1";
const preferences = { theme: "dark", compact: true };

localStorage.setItem(key, JSON.stringify(preferences));

const raw = localStorage.getItem(key);
const restored = raw === null ? null : JSON.parse(raw);
console.log(restored);

localStorage.removeItem(key);
```

Web Storage API 是同步的。大量读写或保存大 JSON 会阻塞主线程，复杂数据应使用 IndexedDB。访问还可能因隐私策略或配额失败，因此写入应捕获异常。

带过期时间的轻量封装：

```js
function setExpiringItem(key, value, ttlMs) {
  localStorage.setItem(key, JSON.stringify({
    value,
    expiresAt: Date.now() + ttlMs
  }));
}

function getExpiringItem(key) {
  const raw = localStorage.getItem(key);
  if (raw === null) return null;

  try {
    const entry = JSON.parse(raw);
    if (Date.now() >= entry.expiresAt) {
      localStorage.removeItem(key);
      return null;
    }
    return entry.value;
  } catch {
    localStorage.removeItem(key);
    return null;
  }
}

setExpiringItem("draft", { title: "Hello" }, 60_000);
console.log(getExpiringItem("draft"));
```

同源其他文档修改 `localStorage` 时，当前文档可监听 `storage` 事件。触发写入的文档本身不会收到该事件。

```js
window.addEventListener("storage", (event) => {
  if (event.key === "app:preferences:v1" && event.newValue) {
    console.log("其他标签页更新了偏好", JSON.parse(event.newValue));
  }
});
```

需要更直接的同源标签页通信时，可使用 `BroadcastChannel`，不要把 storage 事件当成通用消息总线。

## 4. IndexedDB

IndexedDB 是浏览器中的异步、事务型对象数据库，支持结构化克隆、索引和游标，适合离线数据、较大集合与需要查询的数据。

打开数据库并创建结构：

```js
function openNotesDatabase() {
  return new Promise((resolve, reject) => {
    const request = indexedDB.open("notes", 1);

    request.onupgradeneeded = () => {
      const db = request.result;
      const store = db.createObjectStore("notes", {
        keyPath: "id",
        autoIncrement: true
      });
      store.createIndex("updatedAt", "updatedAt");
    };

    request.onsuccess = () => resolve(request.result);
    request.onerror = () => reject(request.error);
    request.onblocked = () => console.warn("请关闭使用旧数据库版本的页面");
  });
}
```

写入和读取记录：

```js
function requestAsPromise(request) {
  return new Promise((resolve, reject) => {
    request.onsuccess = () => resolve(request.result);
    request.onerror = () => reject(request.error);
  });
}

async function addAndReadNote() {
  const db = await openNotesDatabase();

  const writeTx = db.transaction("notes", "readwrite");
  const id = await requestAsPromise(writeTx.objectStore("notes").add({
    title: "IndexedDB",
    body: "异步结构化存储",
    updatedAt: Date.now()
  }));

  const readTx = db.transaction("notes", "readonly");
  const note = await requestAsPromise(readTx.objectStore("notes").get(id));
  console.log(note);
  db.close();
}

addAndReadNote().catch(console.error);
```

事务在事件循环空闲后可能自动提交，不应在事务中等待无关网络请求。先准备网络数据，再开启短事务完成数据库操作。生产项目常使用轻量库把事件式 API 包装为 Promise，但仍需理解版本升级和事务边界。

## 5. Cache API 与离线资源

Cache API 存储 `Request` / `Response` 对，常与 Service Worker 配合缓存静态资源或 GET 响应。它不是通用对象数据库。

```js
async function cacheArticle(url) {
  const cache = await caches.open("articles-v1");
  const response = await fetch(url);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  await cache.put(url, response.clone());
  return response.json();
}

async function readCachedArticle(url) {
  const response = await caches.match(url);
  return response ? response.json() : null;
}
```

缓存 API 不会自动过期。应用需要版本命名、淘汰策略和更新规则，且不得缓存用户不应离线保留的敏感响应。

## 6. 配额、持久化与清理

可估算当前源的使用量和配额：

```js
async function showStorageEstimate() {
  if (!navigator.storage?.estimate) return;
  const { usage = 0, quota = 0 } = await navigator.storage.estimate();
  console.log(`${(usage / 1024 / 1024).toFixed(1)} MB / ${(quota / 1024 / 1024).toFixed(1)} MB`);
}

showStorageEstimate();
```

`navigator.storage.persist()` 可请求降低数据被自动清理的概率，但浏览器可以拒绝，也不能代替服务器备份。遇到配额错误时，应清理可再生成数据并给用户可理解的反馈。

## 7. 版本与迁移

持久数据一旦发布就形成兼容责任：

- 键名带命名空间与版本，例如 `app:settings:v2`
- 读取时校验结构，不信任旧版本或手动篡改的数据
- 迁移必须可重复、短小并能处理升级中断
- 保留 `updatedAt`、模式版本等必要元数据
- 用户退出时清理与账户相关的本地数据
- 区分“缓存”与“唯一副本”，缓存应随时可重建

## 常见陷阱与最佳实践

- 不把密码、长期访问令牌、银行卡号等敏感信息放入 Web Storage
- 防范 XSS，因为同源恶意脚本可读取 localStorage 和 IndexedDB
- 不假设存储永远可用、容量固定或写入必定成功
- 小型偏好使用 localStorage，大型可查询数据使用 IndexedDB
- Cookie 只保存确需随请求发送的小型状态，并正确配置安全属性
- Cache API 负责请求响应缓存，IndexedDB 负责领域数据
- 为所有持久结构准备版本、过期、清理和账户切换策略

## 章节小结

客户端存储没有通用最优解。Cookie 服务于 HTTP 会话，Web Storage 适合少量字符串状态，IndexedDB 适合结构化离线数据，Cache API 适合请求响应。现代应用应以最少持久化为原则，围绕安全、容量、生命周期和迁移明确设计。

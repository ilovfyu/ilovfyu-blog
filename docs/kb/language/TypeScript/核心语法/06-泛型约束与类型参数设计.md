> 版本基线：TypeScript 7.0.2，`strict` 默认开启。泛型的核心不是“接受任意类型”，而是保留输入、输出及成员之间的类型关系。

[上一章](/kb/language/TypeScript/核心语法/05-联合交叉窄化与穷尽检查/) · [下一章](/kb/language/TypeScript/核心语法/07-keyof-typeof索引访问与类型查询/)

## 学习目标

- 编写泛型函数、接口与类，并理解类型参数放置位置的影响。
- 利用推断减少显式类型实参，识别推断过宽或候选冲突。
- 使用 `extends`、`keyof` 和参数默认值表达真实约束。
- 从生产者、消费者视角理解协变、逆变和不变的实际意义。
- 使用 `const` 类型参数保留调用点字面量信息。
- 运用“更少参数、至少出现两次、向下推约束”等设计准则。

## 1. 泛型保存类型关系

`any` 会丢失输入与输出的联系；泛型类型参数可以捕获并复用该类型。

```ts
function identity&lt;T&gt;(value: T): T {
  return value;
}

const n = identity(42);       // 42
const s = identity("hello"); // "hello"
```

这里重要的不是函数接受很多类型，而是“返回类型与参数类型相同”。类型参数应代表关系，而不是装饰。

```ts
function first&lt;T&gt;(items: readonly T[]): T | undefined {
  return items[0];
}

const value = first([1, 2, 3]); // number | undefined
```

## 2. 泛型函数与推断

通常让编译器从实参推断类型：

```ts
function pair<A, B>(left: A, right: B): [A, B] {
  return [left, right];
}

const result = pair("count", 3); // [string, number]
```

必要时可显式提供类型实参，但一旦开始提供，不能跳过前面的必选类型参数。

```ts
const explicit = pair<string, number>("count", 3);
```

### 2.1 多个推断来源

同一 `T` 出现在多个输入位置时，编译器要寻找兼容候选。不要把本应独立的类型强行绑成一个参数。

```ts
// 不佳：要求 fallback 与 value 先推成同一个 T，调用体验可能意外
function choose&lt;T&gt;(value: T, fallback: T): T {
  return value ?? fallback;
}

// 若语义确实允许两个来源，可显式表达联合结果
function chooseEither<A, B>(value: A | null, fallback: B): A | B {
  return value ?? fallback;
}
```

### 2.2 返回值不能凭空推断

只出现在返回类型中的参数通常无法从调用实参推断，容易退化为断言 API。

```ts
function parseJsonUnsafe&lt;T&gt;(text: string): T {
  return JSON.parse(text) as T;
}

const user = parseJsonUnsafe<{ id: string }>("{}");
// 编译通过不代表运行时存在 id
```

更安全的设计从 `unknown` 返回，或接收运行时解析器：

```ts
function parseJson(text: string): unknown {
  return JSON.parse(text);
}

type Parser&lt;T&gt; = (value: unknown) => T;

function parseWith&lt;T&gt;(text: string, parser: Parser&lt;T&gt;): T {
  return parser(JSON.parse(text));
}
```

## 3. 泛型接口、类型别名与类

类型参数放在调用签名上，表示“每次调用都可选择新类型”；放在接口上，表示“实例创建或赋值时锁定类型”。

```ts
interface GenericCall {
  &lt;T&gt;(value: T): T;
}

interface Transformer&lt;T&gt; {
  transform(value: T): T;
}

const identityCall: GenericCall = value => value;
const trim: Transformer&lt;string&gt; = {
  transform: value => value.trim(),
};
```

泛型类的类型参数作用于实例侧，静态成员不能使用类的类型参数。

```ts
class Box&lt;T&gt; {
  constructor(private value: T) {}

  get(): T {
    return this.value;
  }

  set(value: T): void {
    this.value = value;
  }

  // static empty: T; // 错误：静态侧不属于某个 Box&lt;T&gt; 实例
}

const box = new Box({ id: "a" });
box.get().id;
```

接口适合描述公开协议；类适合同时提供运行时实现与实例状态；类型别名适合联合、元组和类型运算。

## 4. 泛型约束

未约束的 `T` 可能是任何类型，因此不能假设它有特定成员。

```ts
interface HasLength {
  length: number;
}

function longest&lt;T extends HasLength&gt;(a: T, b: T): T {
  return a.length >= b.length ? a : b;
}

longest("abc", "x");
longest([1], [1, 2]);
// longest(1, 2); // 错误：number 没有 length
```

约束限定可用能力，但返回值仍保留具体 `T`。若直接写 `(a: HasLength): HasLength`，则会丢失额外字段。

### 4.1 `keyof` 约束

一个类型参数可以依赖另一个类型参数：

```ts
function getProperty&lt;T extends object, K extends keyof T&gt;(obj: T, key: K): T[K] {
  return obj[key];
}

const account = { id: "u1", active: true };
const id = getProperty(account, "id");         // string
const active = getProperty(account, "active"); // boolean
// getProperty(account, "name"); // 错误
```

`K extends keyof T` 保证键在类型层面被 `T` 允许，并让返回值关联到该键对应的 `T[K]`，比返回 `T[keyof T]` 精确。它不保证可选属性或开放索引签名中的键在运行时真实存在；这类 API 应让返回类型包含 `undefined`。

### 4.2 构造签名约束

泛型工厂接收的是类的值侧构造器，而不是实例类型本身。

```ts
type Constructor&lt;T&gt; = new (...args: never[]) => T;

function create&lt;T&gt;(Ctor: Constructor&lt;T&gt;): T {
  return new Ctor();
}

class Service {
  ping() { return "pong"; }
}

const service = create(Service);
```

若构造参数需要保留，应额外建模参数元组，而不是用 `any[]` 草率放宽。

## 5. 泛型参数默认值

默认值让类型参数变成可选。必选参数必须位于带默认值参数之前，默认类型必须满足约束。

```ts
interface ApiResponse&lt;TData = unknown, TMeta = Record&lt;string, unknown&gt;> {
  data: TData;
  meta: TMeta;
}

type UnknownResponse = ApiResponse;
type UserResponse = ApiResponse<{ id: string }>;
```

当推断能得到候选时优先使用推断结果；没有候选时才使用默认值。默认用 `unknown` 往往比 `any` 安全，因为消费方必须先窄化。

```ts
function wrap&lt;T = string&gt;(value?: T): { value: T | undefined } {
  return { value };
}

const a = wrap();    // T 使用默认 string
const b = wrap(123); // T 推断为 number
```

## 6. `const` 类型参数

`const` 修饰类型参数，使调用点中直接写出的对象、数组和原始字面量倾向于保留更具体的字面量与只读结构，减少调用者写 `as const` 的需要。

```ts
function defineRoutes&lt;const T extends readonly string[]&gt;(routes: T): T {
  return routes;
}

const routes = defineRoutes(["/", "/users"]);
// readonly ["/", "/users"]
```

对象配置也可保留辨识值：

```ts
function defineAction&lt;const T extends { type: string }&gt;(action: T): T {
  return action;
}

const action = defineAction({ type: "user/loaded", payload: { id: "u1" } });
// action.type 保留为 "user/loaded"
```

注意：`const` 推断只影响推断偏好，不会把已经存入宽类型变量的值重新变窄。

```ts
const names: string[] = ["a", "b"];
const result = defineRoutes(names); // string[]，字面量信息已经丢失
```

约束也会影响回退结果。若希望只读元组，应将约束写为 `readonly` 容器；可变数组约束可能迫使候选回退为宽类型。

## 7. 方差的实用理解

先定义 `Cat extends Animal`：

```ts
interface Animal { name: string }
interface Cat extends Animal { meow(): void }
```

### 7.1 生产者通常协变

只输出 `T` 的生产者中，`Producer&lt;Cat&gt;` 可用于需要 `Producer&lt;Animal&gt;` 的位置，因为产出的猫一定是动物。

```ts
interface Producer&lt;out T&gt; {
  produce(): T;
}
```

### 7.2 消费者通常逆变

只输入 `T` 的消费者中，能处理任意动物的函数当然能处理猫，所以 `Consumer&lt;Animal&gt;` 可用于需要 `Consumer&lt;Cat&gt;` 的位置，方向与继承关系相反。

```ts
interface Consumer&lt;in T&gt; {
  consume: (value: T) => void;
}
```

### 7.3 同时读写通常不变

`Box&lt;T&gt;` 同时接收和返回 `T`。若把 `Box&lt;Cat&gt;` 当成 `Box&lt;Animal&gt;`，调用者可能写入一只狗，随后原持有者却按猫读取，因而不安全。

```ts
interface MutableBox&lt;in out T&gt; {
  get(): T;
  set: (value: T) => void;
}
```

TypeScript 会从结构自动推断方差。`in`、`out` 注解是用于特定循环类型或性能问题的高级工具，只在同一泛型类型的实例化比较中参与优化，不能改变结构比较规则。正常业务代码不应靠方差注解“强迫”赋值关系；若写，必须与真实结构方差一致。

::: warning
方法参数在兼容性上有历史性的双变处理空间，而函数属性在 `strictFunctionTypes` 下更严格。回调协议需要可靠逆变检查时，优先写 `handler: (value: T) => void`，而不是方法语法 `handler(value: T): void`。
:::

## 8. 泛型 API 设计准则

### 8.1 使用尽可能少的类型参数

```ts
// 不佳：F 只重复约束，没有带来额外关系
function filter1<T, F extends (value: T) => boolean>(items: T[], fn: F): T[] {
  return items.filter(fn);
}

function filter2&lt;T&gt;(items: T[], fn: (value: T) => boolean): T[] {
  return items.filter(fn);
}
```

每个额外类型参数都会增加推断、报错和维护成本。只有当调用者需要观察该具体类型，或它连接多个位置时才引入。

### 8.2 类型参数最好至少出现两次

若 `T` 只出现一次，它通常没有表达关系，可直接用约束类型代替。

```ts
// 不佳
function greet&lt;T extends { name: string }&gt;(value: T): void {
  console.log(value.name);
}

// 更直接
function greet(value: { name: string }): void {
  console.log(value.name);
}
```

“出现两次”是强力启发式，不是机械规则。返回值供上下文推断、构造器协议等高级场景可能例外，但要能说明关系在哪里。

### 8.3 向下推约束（push type parameters down）

尽量约束参数本身，而不是先约束整个类型参数。这样推断更直接，编译器更早得到具体容器元素。

```ts
// 较差：T 先被约束为任意数组，再从 T[number] 计算
function firstA&lt;T extends readonly unknown[]&gt;(items: T): T[number] | undefined {
  return items[0];
}

// 常规集合 API 更简单
function firstB&lt;T&gt;(items: readonly T[]): T | undefined {
  return items[0];
}
```

若确实需要保留完整元组形状，`firstA` 才有理由存在。原则是约束应贴近真正需要变化的层级。

## 9. 常见陷阱

### 9.1 泛型不等于运行时验证

`fetch&lt;T&gt;()`、`JSON.parse() as T` 只是在编译期承诺，无法验证服务器响应。边界数据应为 `unknown`，再由 schema 或守卫解析。

### 9.2 无意义的 `T extends any`

它几乎不增加信息，还会传播 `any` 的不安全性。未知类型默认无需约束；确需安全顶层类型时考虑 `unknown`。

### 9.3 过宽约束损失属性关系

使用 `object` 只能证明它不是原始值，不能读取任意属性。用最小结构约束，例如 `{ id: string }`。

### 9.4 返回一个满足约束但不是 `T` 的值

```ts
function minimumLength&lt;T extends { length: number }&gt;(value: T, min: number): T {
  if (value.length >= min) return value;
  // return { length: min }; // 错误：满足约束但未必具有 T 的其他字段
  throw new Error("长度不足");
}
```

`T extends X` 表示调用者可传入比 `X` 更具体的子类型，函数若承诺返回 `T` 就必须保留那些额外要求。

### 9.5 过度显式指定类型实参

显式实参可能把原本精确的推断拓宽，或掩盖 API 难以推断的问题。优先让参数值驱动推断，仅在无推断来源、需要选择重载语义或刻意拓宽时指定。

### 9.6 可变数组与只读输入

只读取数组的函数应接收 `readonly T[]`，这样既接受普通数组，也接受只读元组，并明确函数不会修改输入。

## 综合示例：类型安全仓库

```ts
interface Entity {
  id: string;
}

interface Repository&lt;T extends Entity&gt; {
  find&lt;K extends keyof T&gt;(key: K, value: T[K]): T | undefined;
  save(entity: T): void;
}

class MemoryRepository&lt;T extends Entity&gt; implements Repository&lt;T&gt; {
  #items: T[] = [];

  find&lt;K extends keyof T&gt;(key: K, value: T[K]): T | undefined {
    return this.#items.find(item => item[key] === value);
  }

  save(entity: T): void {
    this.#items.push(entity);
  }
}

interface User extends Entity {
  email: string;
  active: boolean;
}

const users = new MemoryRepository&lt;User&gt;();
users.find("active", true);
// users.find("active", "yes"); // 错误
```

## 练习

1. 实现 `groupBy<T, K extends PropertyKey>`，回调从 `T` 产生 `K`，结果为 `Map<K, T[]>`。
2. 设计 `EventBus&lt;Events&gt;`，使事件名受 `keyof Events` 限制，监听器参数为 `Events[K]`。
3. 将一个无意义的单次出现类型参数重构为普通参数类型，并比较报错信息。
4. 用 `const` 类型参数实现 `defineColumns`，保留列名元组；再传入预先声明的 `string[]` 观察差异。
5. 分析只读 `Source&lt;T&gt;`、只写 `Sink&lt;T&gt;`、可读写 `Cell&lt;T&gt;` 分别表现为何种方差。

## 检查清单

- [ ] 每个类型参数都表达了至少两个位置之间的关系，或有明确例外理由。
- [ ] API 使用了最少必要的类型参数。
- [ ] 约束描述实现真正依赖的最小能力。
- [ ] 只读容器参数使用 `readonly`。
- [ ] 优先依赖推断，而不是要求调用者重复类型信息。
- [ ] 泛型默认值满足约束，并优先选择 `unknown` 而不是 `any`。
- [ ] 需要字面量保真时使用 `const` 类型参数，并采用只读约束。
- [ ] 外部数据没有通过无验证的 `parse&lt;T&gt;` 假装安全。
- [ ] 没有用方差注解改变本应由结构决定的兼容性。

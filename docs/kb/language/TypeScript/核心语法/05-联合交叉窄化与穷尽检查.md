> 版本基线：TypeScript 7.0.2，默认启用 `strict`。本章中的类型安全依赖严格空值检查等严格模式行为。

[上一章](/kb/language/TypeScript/核心语法/04-函数类型重载与this/) · [下一章](/kb/language/TypeScript/核心语法/06-泛型约束与类型参数设计/)

## 学习目标

- 用联合类型表达“若干可能之一”，用交叉类型组合多个能力。
- 理解控制流分析如何根据可达性、赋值和类型守卫缩小类型。
- 熟练使用 `typeof`、真值、相等性、`in`、`instanceof` 完成窄化。
- 用可辨识联合建模状态，避免“多个可选字段”的非法组合。
- 编写类型谓词与断言函数，并认识它们不受编译器验证的风险。
- 使用 `never` 做穷尽检查，让新增分支在编译期暴露遗漏。

## 1. 联合类型：值可能是其中之一

联合类型 `A | B` 表示值属于 `A` 或 `B`。在尚未窄化时，只能使用所有成员都安全支持的操作。

```ts
function formatId(id: string | number): string {
  // id.toUpperCase(); // 错误：number 没有 toUpperCase
  return typeof id === "string" ? id.toUpperCase() : id.toFixed(0);
}

type Status = "idle" | "loading" | "success" | "error";
let status: Status = "idle";
// status = "done"; // 错误
```

联合不是把成员属性简单相加。`Cat | Dog` 在未窄化前，只能可靠访问两者共有的属性。

```ts
interface Cat {
  name: string;
  meow(): void;
}

interface Dog {
  name: string;
  bark(): void;
}

function greet(pet: Cat | Dog) {
  console.log(pet.name);
  // pet.meow(); // 错误：pet 也可能是 Dog
}
```

## 2. 交叉类型：同时满足多个类型

交叉类型 `A & B` 要求值同时符合 `A` 和 `B`，常用于组合正交能力。

```ts
type Timestamped = { createdAt: Date };
type Identified = { id: string };
type Entity = Timestamped & Identified;

const entity: Entity = {
  id: "u_1",
  createdAt: new Date(),
};
```

交叉不是运行时对象合并，它只描述结果必须具备的结构。可以用函数在运行时完成真正的合并：

```ts
function extend<A extends object, B extends object>(a: A, b: B): A & B {
  return Object.assign({}, a, b);
}

const user = extend({ name: "Lin" }, { role: "admin" as const });
// user: { name: string } & { role: "admin" }
```

冲突属性可能产生不可居住类型：

```ts
type Impossible = { id: string } & { id: number };
// Impossible["id"] 是 never，不存在同时为 string 和 number 的值
```

::: tip
联合表达选择，交叉表达组合。领域状态通常优先用可辨识联合；能力拼装、mixin 结果和附加元数据常用交叉。
:::

## 3. 控制流窄化

TypeScript 分析 `if`、`switch`、循环、提前返回和赋值后的可达路径。同一变量在不同程序点可以有不同的“观察类型”，但赋值仍按声明类型检查。

```ts
function normalize(value: string | number) {
  if (typeof value === "number") {
    return value.toString();
  }
  // number 分支已经返回，此处 value 是 string
  return value.trim();
}

let value: string | number = Math.random() ? "ok" : 1;
value = 42;     // 此处观察为 number
value = "yes"; // 仍合法：声明类型是 string | number
```

### 3.1 `typeof` 守卫

编译器识别 JavaScript 的运行时结果：`"string"`、`"number"`、`"bigint"`、`"boolean"`、`"symbol"`、`"undefined"`、`"object"`、`"function"`。

```ts
function describe(value: string | number | (() => void)) {
  if (typeof value === "function") return "callable";
  if (typeof value === "number") return value.toFixed(2);
  return value.toUpperCase();
}
```

历史陷阱：`typeof null === "object"`。对象判断必须先排除 `null`。

```ts
function keys(value: object | null): string[] {
  if (value !== null && typeof value === "object") {
    return Object.keys(value);
  }
  return [];
}
```

### 3.2 真值窄化

`if (value)` 会排除当前类型中可表达的 falsy 值，例如 `null` 和 `undefined`；运行时还会排除 `false`、`0`、`0n`、`NaN`、空字符串。

```ts
function printLength(text: string | null) {
  if (text) {
    console.log(text.length);
  }
}
```

这里遗漏了合法的 `""`。若目标只是排除空值，应明确写：

```ts
function printLengthSafely(text: string | null) {
  if (text !== null) {
    console.log(text.length); // 空字符串得到 0
  }
}
```

### 3.3 相等性窄化

`===`、`!==`、`switch` 以及 `==`、`!=` 都可参与窄化。业务代码通常优先严格相等；`value != null` 是有意同时排除 `null` 与 `undefined` 的实用惯用法。

```ts
function scale(value: number | null | undefined, factor: number) {
  if (value != null) {
    return value * factor; // value: number
  }
  return 0;
}

function compare(x: string | number, y: string | boolean) {
  if (x === y) {
    x.toUpperCase(); // 两者唯一重叠类型为 string
    y.toUpperCase();
  }
}
```

### 3.4 `in` 运算符

`"prop" in value` 检查自有属性或原型链属性。联合成员具有必选或可选属性时会进入 true 分支；具有可选属性的成员也可能留在 false 分支。

```ts
type FileResult = { path: string; content: string };
type UrlResult = { url: URL; status: number };

function sourceOf(result: FileResult | UrlResult) {
  if ("path" in result) {
    return result.path;
  }
  return result.url.href;
}
```

不要把属性存在误当成属性值有效。对于 `{ token?: string }`，`"token" in x` 不能证明 `x.token` 是非空字符串。

### 3.5 `instanceof` 守卫

`instanceof` 按原型链工作，适合真正由构造器创建的实例。

```ts
function serialize(value: Date | Error | string) {
  if (value instanceof Date) return value.toISOString();
  if (value instanceof Error) return value.message;
  return value;
}
```

来自 JSON 的普通对象没有类原型；跨 iframe/realm 的实例也可能无法通过当前 realm 的 `instanceof`。这类数据更适合结构校验或辨识字段。

## 4. 可辨识联合：让非法状态不可表示

下面这种“一个接口加多个可选字段”无法表达字段间关系：

```ts
interface BadRequestState {
  state: "loading" | "success" | "error";
  data?: string;
  error?: Error;
}
```

它允许 `{ state: "success", error: new Error() }`。应让每个成员都有共同的字面量辨识字段：

```ts
type RequestState =
  | { state: "idle" }
  | { state: "loading"; startedAt: number }
  | { state: "success"; data: string }
  | { state: "error"; error: Error };

function render(state: RequestState): string {
  switch (state.state) {
    case "idle":
      return "尚未请求";
    case "loading":
      return `加载中：${state.startedAt}`;
    case "success":
      return state.data;
    case "error":
      return state.error.message;
  }
}
```

设计辨识字段时应满足：所有成员都存在、值为互斥字面量、名称稳定。常见名称有 `kind`、`type`、`status`。

## 5. 用户定义类型谓词

返回类型 `value is T` 告诉编译器：函数返回 `true` 时，参数可视为 `T`。

```ts
type Fish = { kind: "fish"; swim(): void };
type Bird = { kind: "bird"; fly(): void };

function isFish(animal: Fish | Bird): animal is Fish {
  return animal.kind === "fish";
}

const animals: (Fish | Bird)[] = [];
const fish = animals.filter(isFish); // Fish[]
```

边界输入应从 `unknown` 开始并逐层校验：

```ts
function isRecord(value: unknown): value is Record<PropertyKey, unknown> {
  return typeof value === "object" && value !== null;
}

function isUser(value: unknown): value is { id: string; active: boolean } {
  return isRecord(value)
    && typeof value.id === "string"
    && typeof value.active === "boolean";
}
```

类型谓词的实现不会被证明正确。写成 `return true` 也能骗过编译器，因此它是需要测试的信任边界。

## 6. 断言函数

断言函数失败时抛出异常，成功返回后收窄类型。签名有 `asserts condition` 和 `asserts value is T` 两种。

```ts
function assertDefined&lt;T&gt;(value: T): asserts value is NonNullable&lt;T&gt; {
  if (value == null) {
    throw new Error("值不能为空");
  }
}

function assertString(value: unknown): asserts value is string {
  if (typeof value !== "string") {
    throw new TypeError("期望 string");
  }
}

declare const input: unknown;
assertString(input);
input.toUpperCase();
```

断言函数也可能不安全：签名声称的事实与运行时检查必须完全一致。它与类型断言 `as T` 不同，前者至少执行运行时检查，后者只让编译器相信且不会生成检查代码。

## 7. `never` 与穷尽检查

联合所有可能都被排除后，剩余类型是 `never`。利用“普通类型不可赋给 `never`”可检测遗漏分支。

```ts
function assertNever(value: never): never {
  throw new Error(`未处理的值：${JSON.stringify(value)}`);
}

function label(state: RequestState): string {
  switch (state.state) {
    case "idle": return "空闲";
    case "loading": return "加载中";
    case "success": return "成功";
    case "error": return "失败";
    default: return assertNever(state);
  }
}
```

当联合新增成员而 `switch` 未更新时，`state` 不再是 `never`，调用处立即报错。也可不写辅助函数：

```ts
default: {
  const exhaustive: never = state;
  return exhaustive;
}
```

::: warning
`default` 只保证静态联合的穷尽性。外部 JSON 仍可能携带未知辨识值，所以边界解析必须先验证；运行时 `throw` 仍有价值。
:::

## 8. 不安全守卫与窄化失效

### 8.1 用类型断言偷看属性

```ts
function isAdmin(value: unknown): value is { role: "admin" } {
  return (value as { role?: unknown }).role === "admin";
}
```

当 `value` 为 `null` 时会抛错。应先检查对象，再读取属性。

### 8.2 只检查标签，不检查载荷

外部输入 `{ state: "success" }` 仍缺少 `data`。可辨识联合保护的是已被正确类型化的内部值，不自动验证网络数据。

### 8.3 守卫后发生可变别名修改

对象属性可能被其他函数修改。回调、异步边界和可变共享状态会使先前事实不再可靠。应复制到局部常量，或采用不可变数据。

```ts
function use(config: { token?: string }) {
  const token = config.token;
  if (token !== undefined) {
    queueMicrotask(() => console.log(token.toUpperCase()));
  }
}
```

### 8.4 `Boolean` 与 `!!`

`Boolean(value)` 通常得到 `boolean`；`!!value` 在字面量场景可能得到更窄的布尔字面量。但两者都遵守 JavaScript 真值语义，不适合区分“缺失”和合法的 `0`、`""`。

## 练习

1. 将 `{ status; data?; error? }` 重写为 `idle | pending | fulfilled | rejected` 可辨识联合，并实现穷尽渲染函数。
2. 为 `unknown` 编写 `isPoint`，要求对象恰能安全读取有限数值 `x`、`y`；思考是否需要拒绝额外属性。
3. 实现 `assertNonEmptyString(value: unknown): asserts value is string`，并为 `""`、空白串、数字和 `null` 写测试。
4. 分析为什么 `"swim" in animal` 对含 `swim?` 的成员不能在 false 分支完全排除该成员。
5. 给现有联合新增一个成员，观察 `assertNever` 在何处报错。

## 检查清单

- [ ] 联合表示互斥状态时，每个成员都有稳定的字面量辨识字段。
- [ ] 只排除空值时使用 `value != null` 或显式比较，而不是笼统真值判断。
- [ ] `typeof "object"` 判断同时排除了 `null`。
- [ ] `instanceof` 只用于可靠的原型链场景。
- [ ] 类型谓词和断言函数的运行时逻辑有针对反例的测试。
- [ ] 外部数据先以 `unknown` 接收并验证，再进入内部联合。
- [ ] 关键 `switch` 使用 `never` 穷尽检查。
- [ ] 没有用 `as` 或非空断言 `!` 掩盖模型设计问题。

> 本章基于 2026-08-02 的稳定版 TypeScript 7.0.2。TypeScript 7 于 2026-07-08 正式宣布，核心编译器与语言服务已原生移植到 Go。

## 学习目标

- 理解 TypeScript、Node.js、npm 与 `tsc` 各自负责什么
- 在项目内安装并锁定 TypeScript 7.0.2
- 使用 npm scripts 和 `npx tsc` 检查、构建项目
- 区分类型检查（check）与代码生成（emit）
- 理解“类型会被擦除”对运行时的含义
- 建立可扩展的 `src` / `dist` 目录结构
- 了解 TS 7 原生 Go 编译器及程序化 API 的现状

## 心智模型：TypeScript 是 JavaScript 的静态检查层

浏览器和 Node.js 最终执行的是 JavaScript，不是 TypeScript 类型。

可以把日常流程看成：

```text
源代码 .ts
   │
   ├─ 类型检查：发现不安全的调用、赋值和访问
   │
   └─ 代码生成：删除类型语法，输出 .js
                         │
                         └─ Node.js / 浏览器执行
```

`tsc` 可以同时做两件事，也可以只检查不输出。

TypeScript 不会自动验证网络响应、环境变量或用户输入。

类型系统描述的是编译时知识，运行时边界仍需要校验。

## 工具链角色

| 工具 | 作用 |
| --- | --- |
| Node.js | 执行生成后的 JavaScript，也承载 npm CLI |
| npm | 安装依赖、执行项目脚本 |
| TypeScript | 提供 `tsc` 编译器和编辑器语言服务 |
| `npx` | 优先运行当前项目的可执行文件；本地缺失时也可能从缓存或 registry 获取 |
| 编辑器 | 展示诊断、补全、跳转和重构能力 |

## 版本前提

TypeScript 7.0.2 包元数据声明：

```json
{
  "engines": {
    "node": ">=16.20.0"
  }
}
```

这表示安装和运行该 npm 包至少需要 Node.js 16.20.0。

实际新项目应优先使用仍受支持的 Node.js LTS，而不是仅满足最低版本。

检查本机版本：

```bash
node --version
npm --version
```

## 为什么本地安装 TypeScript

推荐把 TypeScript 安装为项目的开发依赖：

```bash
npm install --save-dev typescript@7.0.2
```

本地安装有三个直接收益：

1. 每位协作者使用同一个编译器版本。
2. CI 与开发机执行结果更容易一致。
3. `package-lock.json` 可以记录精确依赖解析结果。

不建议把全局 `tsc` 当作项目构建依据。

全局版本可能与项目要求不同，也不会被锁文件约束。

## 从零创建 quick project

下面的命令在一个空目录中执行：

```bash
mkdir ts-quick-start
cd ts-quick-start
npm init -y
npm install --save-dev typescript@7.0.2
mkdir src
```

初始化配置：

```bash
npx tsc --init
```

`npx tsc` 会优先运行当前项目安装的 `tsc`。

确认版本：

```bash
npx tsc --version
```

预期主版本与安装版本一致：

```text
Version 7.0.2
```

## 推荐目录布局

```text
ts-quick-start/
├── package.json
├── package-lock.json
├── tsconfig.json
├── src/
│   ├── index.ts
│   └── price.ts
└── dist/              # 构建后生成，不手写
```

把源码和构建产物分开，能避免误编辑 `.js`、重复测试和发布脏文件。

## 最小可用 tsconfig.json

将生成的配置整理为：

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "rootDir": "src",
    "outDir": "dist",
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true,
    "sourceMap": true
  },
  "include": ["src/**/*.ts"]
}
```

关键选项：

| 选项 | 含义 |
| --- | --- |
| `target` | 输出 JavaScript 使用的语法级别 |
| `module` | 模块输出和解析语义 |
| `rootDir` | 源文件根目录 |
| `outDir` | JavaScript 输出目录 |
| `strict` | 开启严格类型检查族 |
| `sourceMap` | 生成调试映射 |
| `include` | 指定项目纳入检查的文件 |

TS 7 新建配置的严格检查基线是开启的；不要照搬“`strict` 默认是 `false`”的旧教程。

显式写出 `strict: true` 仍有价值：它让项目意图对读者和跨版本工具清晰可见。

## 编写第一个模块

`src/price.ts`：

```ts
export function formatPrice(cents: number, currency = "CNY"): string {
  return new Intl.NumberFormat("zh-CN", {
    style: "currency",
    currency,
  }).format(cents / 100);
}
```

`src/index.ts`：

```ts
import { formatPrice } from "./price.js";

const subtotal = 12_500;
console.log(formatPrice(subtotal));
```

在 `NodeNext` ESM 语义下，源码导入通常写运行时将存在的 `.js` 扩展名。

如果 `package.json` 使用 ESM，再加入：

```json
{
  "type": "module"
}
```

实际文件中应把该字段合并到现有 `package.json`，不要创建第二个 JSON 对象。

## npm scripts

在 `package.json` 中加入：

```json
{
  "scripts": {
    "check": "tsc --noEmit",
    "build": "tsc",
    "dev": "tsc --watch",
    "start": "node dist/index.js"
  }
}
```

常用流程：

```bash
npm run check
npm run build
npm start
```

npm script 会自动把 `node_modules/.bin` 加到命令路径，因此脚本中直接写 `tsc` 即可。

在脚本外临时执行时使用：

```bash
npx tsc --noEmit
```

## 类型检查与 emit 是两条轴

考虑以下源码：

```ts
const total: number = "100";
console.log(total);
```

它有类型错误，但“是否输出 JavaScript”由编译选项决定。

不要把“有类型错误”自动等同于“绝不会产生文件”。

团队通常采用两种明确模式：

```bash
# 只检查，适合提交前和 CI
npx tsc --noEmit

# 检查并构建
npx tsc
```

`noEmit` 只禁止写出文件，不会降低检查强度。

也可以在专门的检查配置中写：

```json
{
  "compilerOptions": {
    "noEmit": true
  }
}
```

若由 bundler 负责输出，TypeScript 常被设置为 `noEmit: true`，只承担类型检查。

## 类型擦除

输入：

```ts
type UserId = string;

interface User {
  id: UserId;
  name: string;
}

function greet(user: User): string {
  return `你好，${user.name}`;
}
```

概念上的 JavaScript 输出：

```js
function greet(user) {
  return `你好，${user.name}`;
}
```

`type`、`interface`、参数类型和返回类型都被删除。

因此下面的思路不可行：

```ts
interface User {
  name: string;
}

// 运行时没有 User 这个值
// if (input instanceof User) {}
```

应在运行时检查真实存在的值：

```ts
function isUser(value: unknown): value is { name: string } {
  return (
    typeof value === "object" &&
    value !== null &&
    "name" in value &&
    typeof value.name === "string"
  );
}
```

## TS 7：原生 Go 编译器

TypeScript 7 的核心编译器和语言服务是 Go 原生实现。

这不是“把 TypeScript 源码转译为 Go”，而是 TypeScript 工具本身的实现语言发生变化。

对应用开发者，主要体验是更快的检查、构建和编辑器反馈。

CLI 仍通过 `typescript` npm 包提供，常规入口仍是 `tsc`。

但工具作者要特别注意：TS 7 **没有与旧 JavaScript Compiler API 对等的稳定程序化 API**。

7.0.2 包中可见的程序化导出仍以 `typescript/unstable/*` 命名。

`unstable` 表示接口可能变化，不应当作稳定兼容契约。

如果你在编写 AST 转换器、lint 工具或自定义语言服务，必须单独评估迁移，不要假设旧版 `import ts from "typescript"` API 原样可用。

普通应用项目只调用 CLI，通常不受这一限制影响。

## 编辑器说明

VS Code、WebStorm 等编辑器会使用 TypeScript 语言服务显示错误与补全。CLI 与编辑器应分别核验：`npx tsc --version` 只证明命令行编译器版本；编辑器还必须确认 TypeScript 7 原生语言服务器已经启用，并从扩展状态或日志核验版本。

TypeScript 7.0 发布时，VS Code 通过官方 TypeScript 7 原生扩展提供该体验，之后也可能由编辑器内置集成。旧的 Workspace Version 选择器主要面向 JavaScript `tsserver`，不能单独证明 TypeScript 7 LSP 正在运行，应以编辑器当前文档为准。

编辑器红线不是构建结果的替代品；CI 仍应执行 `npm run check`。

## 常见陷阱

### 把 TypeScript 当运行时校验器

```ts
type Payload = { count: number };
const payload = JSON.parse('{"count":"oops"}') as Payload;
```

断言不会修改字符串，也不会验证 JSON。

### 全局版本遮蔽项目版本

看到异常诊断时先执行：

```bash
npx tsc --version
```

### 同时编译输入文件和项目

不要写：

```bash
npx tsc src/index.ts --project tsconfig.json
```

传入具体文件与 `--project` 是两种入口，应选择其一。

### 提交 dist

是否提交构建产物取决于发布方式；应用项目通常把 `dist/` 加入 `.gitignore`。

### 误解 noEmit

`noEmit` 不执行代码，也不生成 JavaScript；需要运行时测试时仍要构建或使用兼容工具。

## 动手练习

1. 创建 quick project，并固定安装 `typescript@7.0.2`。
2. 添加 `src/price.ts` 和 `src/index.ts`，完成一次构建。
3. 故意把 `formatPrice("100")` 写入源码，观察 `npm run check`。
4. 比较执行 `tsc` 与 `tsc --noEmit` 后 `dist/` 的变化。
5. 打开生成的 JavaScript，找出被擦除的所有类型语法。
6. 将编辑器切换到工作区 TypeScript，再确认版本。

## 本章检查清单

- [ ] Node.js 版本至少为 16.20.0
- [ ] TypeScript 7.0.2 是项目本地开发依赖
- [ ] `npx tsc --version` 输出预期版本
- [ ] 源码位于 `src/`，产物位于 `dist/`
- [ ] `npm run check` 使用 `tsc --noEmit`
- [ ] `npm run build` 可以生成可运行 JavaScript
- [ ] 理解类型在运行时不存在
- [ ] 知道 TS 7 程序化 API 尚无稳定兼容承诺

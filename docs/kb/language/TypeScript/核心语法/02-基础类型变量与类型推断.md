> 本章使用 TypeScript 7.0.2，并以 TS 7 新项目的严格检查默认基线为准。

## 学习目标

- 掌握 JavaScript 原始值对应的 TypeScript 类型
- 理解数组、元组、联合类型和字面量类型
- 根据可变性正确选择 `const` 与 `let`
- 区分推断、拓宽和显式类型注解
- 正确使用 `unknown`、`never`、`void`，谨慎隔离 `any`
- 处理 `null`、`undefined` 与控制流收窄
- 区分类型注解、类型断言、`as const` 与 `satisfies`
- 使用常见 JavaScript 运算符驱动类型收窄

## 心智模型：类型是值集合

可以把类型理解成“允许出现的值的集合”。

```text
"ready"        是只含一个值的集合
string         是所有字符串的集合
string | null  是字符串集合与 null 的并集
never          是空集合
unknown        是所有可能值的安全上界
```

赋值是否合法，本质上是在问右侧值集合是否能放进左侧集合。

类型推断则是编译器根据初始化值和上下文，为表达式寻找合适的集合。

## JavaScript 原始类型

常用原始类型：

```ts
const title: string = "TypeScript";
const count: number = 42;
const enabled: boolean = true;
const huge: bigint = 9_007_199_254_740_993n;
const token: symbol = Symbol("token");
const missing: undefined = undefined;
const empty: null = null;
```

JavaScript 的整数和小数都属于 `number`：

```ts
const integer = 10;
const decimal = 3.14;
const notANumber = Number.NaN;
```

类型名应使用小写：

```ts
let name: string = "Ada";

// 避免包装对象类型
// let bad: String = new String("Ada");
```

`String`、`Number`、`Boolean` 指包装对象类型，业务代码通常不需要它们。

## 数组

两种等价写法：

```ts
const scores: number[] = [90, 95, 88];
const labels: Array&lt;string&gt; = ["new", "hot"];
```

数组元素可用联合类型：

```ts
const ids: Array&lt;string | number&gt; = [1, "A-2", 3];
```

只读数组表达“不通过这个引用修改”：

```ts
function sum(values: readonly number[]): number {
  return values.reduce((total, value) => total + value, 0);
}
```

`readonly` 是编译时约束，不会自动执行 `Object.freeze`。

## 元组入门

元组知道位置和长度：

```ts
const entry: [string, number] = ["visits", 3];
const key = entry[0];   // string
const value = entry[1]; // number
```

带标签的元组更易读：

```ts
type Coordinate = [x: number, y: number];
const origin: Coordinate = [0, 0];
```

数组与元组不同：

```ts
const pair = ["ok", 200];
// 推断通常是 (string | number)[]，不是固定二元组

const exactPair = ["ok", 200] as const;
// readonly ["ok", 200]
```

## const、let 与 var

默认使用 `const`，需要重新赋值时才使用 `let`。

```ts
const port = 3000;
let retries = 0;
retries += 1;
```

`const` 禁止变量重新绑定，但不让对象自动不可变：

```ts
const settings = { theme: "light" };
settings.theme = "dark"; // 合法
```

避免 `var`，因为函数作用域和提升行为更容易制造意外。

## 类型推断

有初始化值时通常无需注解：

```ts
const username = "lin"; // "lin"
let attempts = 0;       // number
const active = true;    // true
```

函数返回类型也能推断：

```ts
function double(value: number) {
  return value * 2; // 推断返回 number
}
```

公共 API 显式写返回类型可以固定契约：

```ts
export function normalize(input: string): string {
  return input.trim().toLowerCase();
}
```

## 拓宽（widening）

编译器会考虑值以后是否可变。

```ts
const fixed = "GET"; // 类型 "GET"
let method = "GET";  // 类型 string
method = "POST";
```

对象属性即使位于 `const` 对象中，通常也会拓宽：

```ts
const request = {
  method: "GET", // string，因为属性可修改
  timeout: 1000, // number
};
```

这不是推断失败，而是为合法写操作保留空间。

## 字面量类型

字面量类型精确描述某个值：

```ts
type Method = "GET" | "POST" | "PATCH";
type Dice = 1 | 2 | 3 | 4 | 5 | 6;
type Result = true | false;
```

使用联合字面量限制状态：

```ts
function send(method: Method, url: string): void {
  console.log(method, url);
}

send("GET", "/users");
// send("FETCH", "/users"); // 类型错误
```

`boolean` 等价于值层面的 `true | false`，但通常直接写 `boolean`。

## 显式类型注解

注解适合以下场景：

- 变量稍后初始化
- 空容器无法提供足够信息
- 约束公共边界
- 有意拓宽或限制允许值

```ts
let responseText: string;
responseText = await Promise.resolve("ok");

const queue: string[] = [];

let status: "idle" | "loading" | "done" = "idle";
status = "loading";
```

不要为显而易见的局部值重复类型：

```ts
const age = 20; // 比 const age: number = 20 更简洁
```

## any：关闭检查

`any` 会把不安全性继续传播：

```ts
let data: any = JSON.parse("{}");
data.user.profile.callAnything(); // 编译器不阻止
const count: number = data;       // 也不阻止
```

它适合作为迁移期间受控的逃生舱，不应成为默认输入类型。

把 `any` 限制在边界，并尽快转换为已验证类型。

## unknown：先检查再使用

`unknown` 可以接收任何值，但使用前必须收窄：

```ts
function stringify(value: unknown): string {
  if (typeof value === "string") {
    return value;
  }

  if (typeof value === "number") {
    return value.toString();
  }

  return JSON.stringify(value) ?? String(value);
}
```

`JSON.stringify` 对 `undefined`、函数和 symbol 顶层值可能返回 `undefined`，对循环引用或某些 bigint 值还可能抛错。上例用回退值维持返回类型，但接受任意值的生产 API 仍应明确序列化失败策略。

捕获外部输入时优先从 `unknown` 开始：

```ts
function getMessage(error: unknown): string {
  return error instanceof Error ? error.message : String(error);
}
```

## never：不可能出现的值

永不正常返回的函数可推断或标注为 `never`：

```ts
function fail(message: string): never {
  throw new Error(message);
}
```

`never` 也用于穷尽性检查：

```ts
type State = "idle" | "loading" | "done";

function label(state: State): string {
  switch (state) {
    case "idle":
      return "空闲";
    case "loading":
      return "加载中";
    case "done":
      return "完成";
    default: {
      const unreachable: never = state;
      return unreachable;
    }
  }
}
```

增加新状态却忘记处理时，`never` 赋值会报错。

## void：调用者不使用返回结果

```ts
function log(message: string): void {
  console.log(message);
}
```

`void` 通常描述函数返回值不应被使用，不等于函数在运行时必定返回 `undefined`。

回调中的特殊行为将在 [函数类型重载与this](/kb/language/TypeScript/核心语法/04-函数类型重载与this/) 详述。

## null 与 undefined

严格空值检查下，它们不是普通 `string` 或 `number`：

```ts
let nickname: string | null = null;
nickname = "小林";

let selectedId: string | undefined;
selectedId = "u-1";
```

常见约定：

- `undefined` 常表示缺省、未传入或属性不存在
- `null` 常表示调用方明确提供“空”

约定应在项目内保持一致。

使用空值合并：

```ts
const displayName = nickname ?? "匿名用户";
```

不要用 `||` 替代所有缺省逻辑：

```ts
const input = 0;
const a = input || 10; // 10，把 0 当成假值
const b = input ?? 10; // 0，只处理 null/undefined
```

## 类型断言

断言表示“我比编译器知道得更多”：

```ts
const canvas = document.querySelector("canvas") as HTMLCanvasElement | null;
```

断言不会检查 DOM，也不会改变运行时值。

应优先通过检查收窄：

```ts
const element = document.querySelector("canvas");

if (element instanceof HTMLCanvasElement) {
  element.getContext("2d");
}
```

非空断言 `!` 同样没有运行时保护：

```ts
const root = document.querySelector("#root")!;
```

只有环境确实保证元素存在时才使用。

## as const

`as const` 请求最窄的字面量推断，并把对象属性、数组元素设为只读：

```ts
const config = {
  mode: "production",
  ports: [80, 443],
} as const;
```

推断结果近似：

```ts
type Config = {
  readonly mode: "production";
  readonly ports: readonly [80, 443];
};
```

它只提供类型层面的深层只读推断，不会在运行时递归冻结对象。

## satisfies

`satisfies` 检查表达式满足目标类型，同时尽量保留表达式自身的精确信息：

```ts
type Theme = {
  mode: "light" | "dark";
  contrast: number;
};

const theme = {
  mode: "dark",
  contrast: 1.2,
} satisfies Theme;

theme.mode; // "dark"
```

与注解对比：

```ts
const annotated: Theme = {
  mode: "dark",
  contrast: 1.2,
};

annotated.mode; // "light" | "dark"
```

与断言对比：`satisfies` 会真正检查兼容性，`as Theme` 更像要求编译器接受你的判断。

## 常见运算符

算术与字符串：

```ts
const total = 10 + 20;
const average = total / 2;
const greeting = "你好，" + "TypeScript";
```

比较和逻辑：

```ts
const inRange = average >= 0 && average <= 100;
const changed = total !== 0;
```

优先使用严格相等 `===` 和 `!==`。

可选链与空值合并：

```ts
type Profile = { address?: { city?: string } };
const profile: Profile = {};
const city = profile.address?.city ?? "未知";
```

`typeof` 是运行时运算符，也能触发收窄：

```ts
function lengthOf(value: string | string[]): number {
  if (typeof value === "string") {
    return value.length;
  }

  return value.length;
}
```

## 控制流分析基础

TypeScript 会沿分支追踪类型：

```ts
function printId(id: string | number): void {
  if (typeof id === "string") {
    console.log(id.toUpperCase());
  } else {
    console.log(id.toFixed(0));
  }
}
```

空值检查：

```ts
function upper(value: string | undefined): string {
  if (value === undefined) {
    return "";
  }

  return value.toUpperCase();
}
```

真值检查可能把空字符串也排除：

```ts
function show(value: string | null): string {
  if (value) {
    return value; // 此处也排除了 ""
  }

  return "无内容";
}
```

若空字符串有业务意义，应明确检查 `value !== null`。

数组检查：

```ts
function first(value: string | string[]): string {
  if (Array.isArray(value)) {
    return value[0] ?? "";
  }

  return value.charAt(0);
}
```

## 常见陷阱

### 空数组推断不符合意图

为跨语句累积的空数组写元素类型：

```ts
const names: string[] = [];
names.push("Ada");
```

### 过度标注

局部变量应让推断工作，把注解留给边界和意图不明确处。

### 用 as 掩盖错误

如果断言连续出现，优先修正源类型或增加运行时验证。

### 混淆 const 与不可变

`const` 只固定绑定；使用 `readonly`、`as const` 或运行时冻结表达更强约束。

### 误传旧版 strict 结论

TS 7 的严格检查默认基线已经改变。项目仍可显式配置，但不要声称它默认关闭。

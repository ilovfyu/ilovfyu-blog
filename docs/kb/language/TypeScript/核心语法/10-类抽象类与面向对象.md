::: info 版本基线
本文以 TypeScript 7.0.2 为基线。TypeScript 的类建立在 JavaScript `class` 运行时语义之上，同时增加静态类型检查。
:::

## 学习目标

- 正确声明字段、构造器、可见性、只读成员和静态成员。
- 区分 ECMAScript `#private` 与 TypeScript `private`。
- 使用 `extends`、`implements`、`abstract` 和 `override` 表达继承契约。
- 理解类同时位于值空间和类型空间，以及结构化兼容性的边界。
- 在 TypeScript 7 与原生类型擦除环境中避开不可擦除语法。

## 1. 字段与构造器

```ts
class Account {
  id: string;
  displayName: string;
  active = true;

  constructor(id: string, displayName: string) {
    this.id = id;
    this.displayName = displayName;
  }
}

const account = new Account("a1", "Ada");
```

字段声明用于告诉类型系统实例的形状。无初始化器的字段通常应在构造器中完成赋值。

### 1.1 `strictPropertyInitialization`

启用 `strict` 时，`strictPropertyInitialization` 默认开启，编译器要求实例字段在构造结束前确定赋值：

```ts
class Session {
  token: string; // 错误：没有初始化
}
```

优先使用初始化器或构造器赋值：

```ts
class Session {
  token: string;

  constructor(token: string) {
    this.token = token;
  }
}
```

确定赋值断言 `!` 只是在向编译器承诺“稍后一定赋值”：

```ts
class View {
  root!: HTMLElement;
}
```

它不会生成检查。只应在框架生命周期或依赖注入确实保证赋值、且普通构造器无法表达时使用。

### 1.2 派生类构造器

```ts
class AdminAccount extends Account {
  permissions: string[];

  constructor(id: string, displayName: string, permissions: string[]) {
    super(id, displayName);
    this.permissions = permissions;
  }
}
```

派生类访问 `this` 前必须调用 `super()`，这是 JavaScript 的运行时规则。

## 2. 可见性

### 2.1 `public`、`protected`、`private`

```ts
class Wallet {
  public owner: string;
  protected balance = 0;
  private auditNote = "created";

  constructor(owner: string) {
    this.owner = owner;
  }
}
```

- `public` 是默认值，任何位置可访问。
- `protected` 可在类内部及其派生类访问。
- `private` 只允许在声明它的类中访问。

TypeScript 的 `private` 主要是静态检查。传统编译目标下，生成的 JavaScript 属性仍可能通过括号访问或被反射看到，因此不要把它当作安全边界。

### 2.2 `#private`：运行时私有字段

```ts
class SecureWallet {
  #balance = 0;

  deposit(amount: number) {
    if (amount <= 0) throw new RangeError("amount must be positive");
    this.#balance += amount;
  }

  get balance() {
    return this.#balance;
  }
}
```

`#balance` 是 ECMAScript 私有字段，浏览器或 Node 在运行时强制品牌检查，类外无法合法访问。它不能被子类直接访问，也不能与普通属性动态互换。

选择建议：需要真实封装时使用 `#private`；只想表达 TypeScript 层面的类内约束、或需要 `protected` 式继承访问时使用访问修饰符。

## 3. `readonly`

```ts
class Order {
  readonly id: string;
  readonly items: string[];

  constructor(id: string, items: string[]) {
    this.id = id;
    this.items = items;
  }
}
```

`readonly` 字段只能在声明处或构造器中赋值，但它是浅层约束：

```ts
const order = new Order("o1", []);
order.items.push("book"); // 允许，数组本身仍可变
// order.items = [];      // 错误，不能替换引用
```

需要只读数组时声明为 `readonly string[]` 或 `ReadonlyArray&lt;string&gt;`。

## 4. 参数属性与 `erasableSyntaxOnly`

传统 TypeScript 支持在构造参数前加修饰符，自动创建并初始化同名字段：

```ts
class LegacyPoint {
  constructor(
    public x: number,
    public y: number,
  ) {}
}
```

这叫 parameter properties（参数属性）。它不是标准 JavaScript，必须由 TypeScript 转换生成字段赋值。

::: warning TypeScript 7 与原生类型擦除
参数属性在常规 TypeScript emit 流程中仍可表达类成员，但它不是“只擦除类型即可运行”的语法。启用 `erasableSyntaxOnly`，或让支持 type stripping 的 Node 直接运行 `.ts` 时，它会报错。面向 TypeScript 7、新 Node 原生执行或多编译器工具链，推荐显式字段写法。
:::

```ts
class Point {
  x: number;
  y: number;

  constructor(x: number, y: number) {
    this.x = x;
    this.y = y;
  }
}
```

这段代码移除类型标注后仍是合法 JavaScript，也更清楚地区分声明和初始化。

## 5. 静态成员

```ts
class IdGenerator {
  static #next = 1;
  static readonly prefix = "item";

  static create(): string {
    return `${this.prefix}-${this.#next++}`;
  }
}

IdGenerator.create();
```

静态成员属于类构造器本身，不属于实例。避免声明 `name`、`length`、`call` 等与函数对象内建成员冲突的静态名称。

静态初始化块可完成一次性初始化：

```ts
class Registry {
  static entries = new Map<string, string>();

  static {
    Registry.entries.set("default", "ready");
  }
}
```

## 6. `extends` 与 `implements`

`extends` 建立运行时原型继承，也继承实例类型：

```ts
class Animal {
  move(distance: number) {
    console.log(`moved ${distance}m`);
  }
}

class Dog extends Animal {
  bark() {
    console.log("woof");
  }
}
```

`implements` 只检查实例侧是否满足契约，不生成方法，也不改变推断：

```ts
interface JsonSerializable {
  toJSON(): unknown;
}

class UserRecord implements JsonSerializable {
  name: string;

  constructor(name: string) {
    this.name = name;
  }

  toJSON() {
    return { name: this.name };
  }
}
```

接口中的可选属性不会因 `implements` 自动出现在类实例上。构造器签名也不属于实例侧接口；若要约束类构造器，应单独声明 `new` 签名。

```ts
interface ServiceConstructor&lt;T&gt; {
  new (url: string): T;
}
```

## 7. 抽象类

抽象类可以包含状态、已实现方法和必须由子类实现的抽象成员：

```ts
abstract class Repository&lt;T extends { id: string }&gt; {
  abstract find(id: string): Promise&lt;T | undefined&gt;;
  abstract save(entity: T): Promise&lt;void&gt;;

  async require(id: string): Promise&lt;T&gt; {
    const entity = await this.find(id);
    if (!entity) throw new Error(`entity ${id} not found`);
    return entity;
  }
}
```

抽象类不能直接 `new`。`abstract` 只在类型层面限制实例化，运行时若绕过类型系统，JavaScript 不会自动阻止调用。

```ts
interface StoredUser { id: string; name: string }

class MemoryUserRepository extends Repository&lt;StoredUser&gt; {
  #data = new Map<string, StoredUser>();

  override async find(id: string) {
    return this.#data.get(id);
  }

  override async save(user: StoredUser) {
    this.#data.set(user.id, user);
  }
}
```

抽象类适合共享实现和状态；接口适合只描述能力，并允许类实现多个契约。不要为了“面向对象”而制造深继承树，组合通常更易测试。

## 8. `override` 与 `noImplicitOverride`

```ts
class BaseLogger {
  format(message: string): string {
    return message;
  }
}

class JsonLogger extends BaseLogger {
  override format(message: string): string {
    return JSON.stringify({ message });
  }
}
```

`override` 让编译器确认基类确实存在同名成员。建议启用：

```json
{
  "compilerOptions": {
    "noImplicitOverride": true
  }
}
```

这样基类重命名方法后，子类不会悄悄变成一个无关的新方法。若确实要覆盖字段或访问器，也应明确标注 `override`。

## 9. 访问器

```ts
class Temperature {
  #celsius = 0;

  get celsius(): number {
    return this.#celsius;
  }

  set celsius(value: number) {
    if (!Number.isFinite(value)) {
      throw new TypeError("temperature must be finite");
    }
    this.#celsius = value;
  }
}
```

只有 getter、没有 setter 的属性会被推断为只读。现代 TypeScript 允许 getter 与 setter 类型不同，但写入类型必须与读取类型保持合理关系；公共 API 中应避免令人意外的非对称转换。

自动访问器 `accessor` 属于较新的 JavaScript 类特性，其目标运行时和转译工具支持需单独确认，不要仅凭类型检查通过就假定部署环境支持。

## 10. 多态 `this` 类型

方法返回 `this` 可让链式 API 在子类中保留精确类型：

```ts
class QueryBuilder {
  protected clauses: string[] = [];

  where(clause: string): this {
    this.clauses.push(clause);
    return this;
  }
}

class UserQuery extends QueryBuilder {
  activeOnly(): this {
    return this.where("active = true");
  }
}

new UserQuery().where("role = 'admin'").activeOnly();
```

`other: this` 还可要求参数与当前派生实例兼容。注意箭头函数字段和原型方法的运行时分配、绑定与覆盖行为不同：每个实例都会创建箭头函数字段，而原型方法共享一个函数。

## 11. 类的值/类型双重身份

```ts
class UserService {
  getName() { return "Ada"; }
}

let service: UserService;          // 实例类型
let Constructor: typeof UserService; // 类值/构造器类型

Constructor = UserService;
service = new Constructor();
```

类声明同时创建：

- 一个运行时值，即构造函数和静态成员容器。
- 一个实例类型，用于描述 `new` 之后的对象。

泛型工厂通常约束构造器值：

```ts
type Constructor<A extends unknown[], T> = new (...args: A) => T;

function create<A extends unknown[], T>(
  Ctor: Constructor<A, T>,
  ...args: A
): T {
  return new Ctor(...args);
}
```

## 12. 结构化兼容性的注意事项

TypeScript 默认按成员形状判断兼容，而不是只看类名：

```ts
class Point2D {
  x = 0;
  y = 0;
}

class Coordinate {
  x = 0;
  y = 0;
}

const point: Point2D = new Coordinate(); // 允许
```

这对 JavaScript 生态很实用，但有几个边界：

- 静态成员和构造器不参与实例兼容性比较。
- 含 TypeScript `private`/`protected` 成员的类型，兼容时要求成员来自同一声明来源，因而产生一定的名义化效果。
- ECMAScript `#private` 具有运行时品牌，也会让不同类实例无法互换。
- 空类几乎与任意对象兼容，不能用作可靠的领域品牌。
- `implements` 不会进行运行时实例检查；`instanceof` 检查原型链，不检查接口。

若两个相同形状的 ID 不应混用，可使用品牌字段或封装对象，而不是依赖类名。

## 13. Mixin 简述

Mixin 通常是“接收基类、返回派生类”的类表达式：

```ts
type Constructor&lt;T = object&gt; = new (...args: any[]) => T;

function Timestamped&lt;TBase extends Constructor&gt;(Base: TBase) {
  return class extends Base {
    createdAt = new Date();
  };
}

class Model {}
class TimedModel extends Timestamped(Model) {}
```

Mixin 能绕开单继承限制，但复杂组合会带来构造器约束、成员冲突和声明输出难读等问题。优先考虑把能力放进普通对象并通过组合注入；只有框架或实例协议确实需要继承时才使用 mixin。

## 常见陷阱

- 在构造器中调用可覆盖方法，子类字段可能尚未初始化。
- `private` 不是 JavaScript 运行时安全边界；真正私有使用 `#private`。
- `readonly` 是浅层静态约束。
- `implements` 不会生成代码，也不会自动复制默认实现。
- 参数属性与 `erasableSyntaxOnly`、Node type stripping 不兼容。
- 子类字段可能覆盖基类访问器或成员；使用 `override` 并理解初始化顺序。
- 把深继承当作复用机制通常比组合更脆弱。

## 练习

1. 实现抽象 `Shape`，包含抽象 `area()`，再实现 `Circle` 和 `Rectangle`。
2. 将参数属性类改写为可通过 `erasableSyntaxOnly` 的显式字段形式。
3. 编写带 `#balance`、只读账号和校验访问器的 `BankAccount`。
4. 为基类和子类开启 `noImplicitOverride`，观察方法拼写错误如何被发现。
5. 写一个接受构造器的工厂，并区分 `T`、`typeof T` 与 `InstanceType&lt;C&gt;`。

- [ ] 所有字段在构造结束前有可靠初值。
- [ ] 没有用 `!` 掩盖真实初始化缺陷。
- [ ] 需要运行时私有性时使用了 `#private`。
- [ ] 新代码考虑了 `erasableSyntaxOnly` 与目标运行工具链。
- [ ] 覆盖成员使用 `override`，项目开启了 `noImplicitOverride`。
- [ ] 继承表达的是稳定的 is-a 关系，而不只是代码复用。

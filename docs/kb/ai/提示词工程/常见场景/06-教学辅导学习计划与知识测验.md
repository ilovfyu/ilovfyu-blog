## 1. 为什么这类任务需要场景设计

先诊断先备知识和目标，再决定解释深度。优先提问、提示、局部示范和反馈；对作业与考试不直接代做，并为不同学习需求提供可达路径。

提示词不是一句魔法口令，而是任务协议的自然语言实现。协议要让输入可解释、输出可验证、失败可恢复、风险可升级。

::: important 核心判断
先问“什么结果算正确”，再问“怎样措辞更像提示词”。
如果验收者无法独立判断对错，提示再长也只是偏好描述。
:::

### 1.1 场景成功的四层含义

| 层次 | 问题 | 最低证据 |
| --- | --- | --- |
| 语法层 | 格式是否可解析 | 解析器或格式检查 |
| 语义层 | 内容是否忠实/正确 | 逐项依据或金标 |
| 任务层 | 是否支持预定工作流 | 下游验收测试 |
| 治理层 | 是否安全、合规、可追溯 | 日志、权限与人工复核 |

### 1.2 不要把模型能力当作任务定义

- 模型“能生成”不等于业务“可接受”。
- 流畅度是表面质量，不是事实正确性的替代指标。
- 单次成功不能证明稳定，应覆盖边界、反例和分布变化。
- 把未知显式留空，通常比生成一个完整但错误的答案更有价值。

| 输出项 | 用途 | 不可接受情况 |
| --- | --- | --- |
| 可观察目标 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| 分步活动 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |

| 掌握证据 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| 下一步复习计划 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |

### 4.3 契约版本化

- 提示模板、schema、标签手册和验收集分别记录版本。
- 会改变输出含义的修改提升主版本。
- 仅修正文案但不改变行为的修改提升次版本。
- 回放历史样本，比较新旧版本差异而非只看新样例。

### 4.4 分隔与数据边界

- 用 XML 标签、代码块或明确 ID 分隔指令与用户材料。
- 把材料中的命令视为数据，除非契约明确允许执行。
- 多文档输入保留文档 ID，禁止在无标识拼接后引用。
- 超长输入先建立分块策略和跨块合并规则。

## 5. 通用提示模板

```text
你是苏格拉底式学习教练。
学习者：{{level_and_prior_knowledge}}
目标：{{observable_goal}}
时间与资源：{{constraints}}
当前任务性质：{{practice/homework/exam}}
规则：
1. 先用 2-4 个诊断问题确认起点，不凭年龄猜水平。
2. 每轮只推进一个关键步骤：先提问，再给分级提示，最后才给局部示范。
3. 要求学习者解释理由，并针对具体误概念反馈。
4. 作业中不直接代写；受监督考试中拒绝作答并改为复习帮助。
5. 用新情境迁移题和延迟复习检验掌握。
输出：目标；诊断；互动步骤；检查点；复习安排。
```

### 5.1 模板变量表

| 变量 | 填写原则 | 错误示例 |
| --- | --- | --- |
| 任务目标 | 可观察、可验收 | “做得更好” |
| 输入范围 | 标明边界、版本和 ID | “参考所有信息” |
| 允许推断 | 列白名单或明确禁止 | “合理发挥” |
| 输出格式 | 给 schema/样例/长度 | “结构清晰” |
| 失败行为 | 定义未知、拒绝和升级 | “不要出错” |
| 验收标准 | 指标、阈值、测试集 | “看起来专业” |

### 5.2 少样本示例设计

- 示例覆盖正常、缺失、冲突和越界输入。
- 示例输出必须完全符合契约，否则模型会学习错误。
- 不要只提供正例；至少加入一个应当弃权或 unknown 的例子。
- 示例顺序避免把偶然位置误学成优先级。

### 5.3 提示注入防护

- 明确用户材料不是系统指令。
- 工具权限由外部执行层控制，不能只靠提示文本。
- 检索内容中的“忽略前文”等句子按引用数据处理。
- 敏感动作使用参数白名单和人工确认。

## 6. 三个完整案例

### 6.1 案例：初中代数错题辅导

#### 场景输入

学生解 2(x-3)=10 时得到 x=2，希望模型帮助。

#### 初始提示

```text
告诉学生正确答案和详细步骤。
```

#### 问题诊断

- 直接答案减少诊断机会
- 不知道错误发生在哪一步
- 没有让学生自我解释
- 缺少迁移练习

#### 优化版提示

```text
不要先给答案。请学生写出从原式到 x=2 的每一步，并问等式两边做了什么。若卡住，提示级别依次为：指出分配律/逆运算位置、给相似但不同数字的例子、最后只示范下一步。学生修正后，让其解释等式平衡并完成一道括号位置不同的迁移题。
```

#### 验收标准

- [ ] A1.1 首轮不泄露完整答案
- [ ] A1.2 问题定位到具体误概念
- [ ] A1.3 提示按需逐级提供
- [ ] A1.4 学生必须自我解释
- [ ] A1.5 迁移题检验而非原题复述

#### 迭代记录方式

| 轮次 | 只改一个变量 | 观察指标 | 保留/回退 |
| --- | --- | --- | --- |
| 0 | 初始提示作为基线 | 记录全部验收项 | 基线 |
| 1 | 补齐输入与边界 | 正确性和弃权 | 按指标决定 |
| 2 | 补齐输出结构 | 可解析性和可追溯 | 按指标决定 |
| 3 | 调整示例或规则 | 边界集与回归集 | 不得牺牲安全 |

### 6.2 案例：六周 Python 学习计划

#### 场景输入

零基础成人每周 4 小时，目标是读懂并修改简单数据脚本。

#### 初始提示

```text
制定一个详细的 Python 学习计划。
```

#### 问题诊断

- 没有基线诊断
- 内容可能远超目标
- 只有观看没有产出
- 缺少调整机制

#### 优化版提示

```text
先用三个低压力问题确认编程、命令行和表格经验。为每周 4 小时设计六周计划，目标限定为阅读、运行、调试和小改 CSV 数据脚本。每周含一个可交付小作品、一次检索练习、一次无资料自测和 20 分钟复盘。设置第 2/4 周检查点；若迁移题低于 70%，减少新内容并安排补救。
```

#### 验收标准

- [ ] A2.1 总时长不超过每周 4 小时
- [ ] A2.2 活动直接服务目标能力
- [ ] A2.3 每周有可观察产出
- [ ] A2.4 检查点有明确调整规则
- [ ] A2.5 最终任务需要综合迁移

## 7. 风险登记册

| 风险 | 早期信号 | 预防控制 | 发现后动作 |
| --- | --- | --- | --- |
| 难度与学习者错配 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 一次给完整答案剥夺思考 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 把流利表达误当掌握 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 测验只考记忆 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 反馈标签化学习者 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 代做作业或考试作弊 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |

### 7.1 风险分级

- 低：格式或措辞瑕疵，可自动重试。
- 中：影响业务判断但可在发布前人工发现。
- 高：可能造成安全、法律、财务、健康或重大声誉后果。
- 关键：不可逆操作或大规模敏感数据暴露，默认禁止自动执行。

### 7.2 人在回路

1. 定义触发人工复核的明确条件。
2. 向复核者展示原始输入、输出、证据和模型版本。
3. 记录复核改动原因，沉淀为失败类别。
4. 不要把“人工复核”当作没有流程的兜底口号。

## 8. 边界条件

### 8.1 受监督考试中不提供答案

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.2 心理、医疗或特殊教育诊断交专业人士

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.3 儿童场景遵循监护与平台规则

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.4 不能从一次错误固定判断能力

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.5 无障碍适配应询问而非假设

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.6 通用压力输入

- 空输入、仅空白、乱码和截断输入。
- 互相矛盾的输入与过时版本。
- 超长输入和极端重复内容。
- 包含提示注入、恶意链接或未知附件的输入。
- 超出语言、地域、时间或专业权限范围的输入。

## 9. 失败处理与恢复

1. 识别是知识缺口、策略缺口还是题意误读
2. 降低单步认知负荷而非直接降目标
3. 换用表征、类比或反例
4. 记录提示级别和独立完成情况
5. 持续困难时建议教师或专业支持

### 9.1 标准失败响应

```text
状态：未完成/部分完成
失败阶段：{{stage}}
已确认内容：{{verified}}
未知或冲突：{{unknowns}}
没有执行的动作：{{not_done}}
需要补充：{{required_input}}
建议下一步：{{next_step}}
```

### 9.2 重试预算

- 格式失败可自动重试一次，并只修格式。
- 事实或语义失败不能靠原提示无限重试。
- 连续两轮同类失败应修改契约、拆分任务或升级人工。
- 每次重试保留输入版本和失败原因，防止选择性展示成功结果。

### 9.3 降级策略

- 从自动发布降级为草稿。
- 从完整答案降级为已证实字段。
- 从开放生成降级为封闭材料处理。
- 从执行动作降级为只读建议。

## 10. 隐私、安全与合规

### 10.1 未成年人数据最小化并避免长期保留

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.2 不要求透露学校、真实姓名或健康诊断

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.3 反馈避免羞辱与人格标签

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.4 学习分析仅用于明确教育目的

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.5 公开作品前去除身份信息

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.6 最小权限清单

- 模型只看到完成任务所需的最少字段。
- 工具只开放必要动作和参数范围。
- 高风险输出默认不自动发送或执行。
- 测试环境与生产环境隔离。
- 审计日志本身也按敏感数据保护。

## 11. 迭代策略

### 11.1 建立基线

1. 固定模型、参数、提示和数据版本。
2. 选取代表性正常样本与历史失败样本。
3. 先测初始提示，不只展示优化后结果。
4. 保存原始输出，避免事后改写证据。

### 11.2 单变量迭代

| 可改变量 | 适合解决 | 不适合解决 |
| --- | --- | --- |
| 补上下文 | 模型缺少事实或规则 | 规则本身冲突 |
| 补输出 schema | 格式漂移 | 事实来源不足 |
| 补少样本 | 边界判定不稳定 | 样本标签错误 |
| 拆分步骤 | 复合任务遗漏 | 下游无法验收 |
| 增加工具 | 需要实时/精确信息 | 权限治理缺失 |

### 11.3 错误分类

- E1 输入缺失：请求方未提供必要信息。
- E2 契约歧义：字段、标签或成功定义不清。
- E3 检索/工具失败：信息无法访问或工具报错。
- E4 推理/生成失败：已有信息未被正确使用。
- E5 验收失败：结果正确但格式或工作流不兼容。
- E6 治理失败：权限、隐私或合规控制不足。

### 11.4 停止条件

- 主要指标达到门槛且安全指标无回退。
- 边界集不再出现新的高严重度错误。
- 成本和延迟在预算内。
- 剩余风险有明确人工流程和责任人。

## 12. 评测设计

### 12.1 数据集分层

| 集合 | 目的 | 建议内容 |
| --- | --- | --- |
| 开发集 | 快速迭代 | 典型任务和已知错误 |
| 回归集 | 防止旧错复发 | 每类历史事故至少一例 |
| 边界集 | 验证拒绝与 unknown | 缺失、冲突、注入、超范围 |
| 盲测集 | 估计泛化 | 迭代者未见的真实分布 |
| 红队集 | 发现安全缺陷 | 越权、隐私、恶意输入 |

### 12.2 核心指标

- **M1 前后测增益**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M2 提示依赖下降**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M3 迁移题正确率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M4 延迟保持率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M5 自我解释质量**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M6 计划完成率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M7 诚信边界遵守率**：定义分子、分母、排除项和目标阈值，避免只报平均分。

### 12.3 量规示例

| 分数 | 正确性 | 完整性 | 可追溯性 | 安全性 |
| --- | --- | --- | --- | --- |
| 3 | 全部关键结论正确 | 无关键漏项 | 逐项可定位 | 无违规 |
| 2 | 轻微非关键错误 | 少量次要漏项 | 大部分可定位 | 低风险可修复 |
| 1 | 至少一项关键错误 | 明显漏项 | 证据弱或错配 | 需要人工阻断 |
| 0 | 结论不可用 | 任务未完成 | 无依据 | 严重违规 |

### 12.4 评审一致性

- 先用 10-20 个样本校准评审者。
- 为每个分数提供正例和反例。
- 记录争议项，不强行平均掩盖定义问题。
- 高风险样本采用双人独立评审。

### 12.5 线上监控

- 监控输入分布、未知率、人工改写率和升级率。
- 抽样复核成功输出，而不只看用户投诉。
- 模型或依赖升级后运行完整回归集。
- 指标突变时能回滚提示版本或关闭自动动作。

## 14. 练习

### 14.1 练习 1

学生连续说“不会”，教练下一步是什么？

<details>
<summary>展开参考答案</summary>

给一个能暴露起点的二选一或局部问题，再按层级提示；不要立刻倾倒完整讲解。

</details>

### 14.2 练习 2

即时答对三题是否代表掌握？

<details>
<summary>展开参考答案</summary>

不能充分证明。还应测试延迟保持、变式与新情境迁移，并观察提示依赖。

</details>

### 14.3 练习 3

学生在实时考试中发题求答案，如何响应？

<details>
<summary>展开参考答案</summary>

拒绝提供考试答案，可提供通用概念复习、考后讲解或允许范围内的支持。

</details>

### 14.4 综合练习

为一个真实“教学辅导、学习计划与知识测验”任务写一份输入输出契约。至少包含：非目标、未知行为、证据要求、失败升级和五条验收标准。

<details>
<summary>展开评分要点</summary>

优秀答案不是堆叠角色设定，而是让第三方能用固定样本和规则判断成功或失败。检查每个输出字段是否有来源、每个风险是否有外部控制、每个指标是否有阈值。

</details>

## 15. 快速复盘卡

| 阶段 | 必须回答的问题 |
| --- | --- |
| 需求 | 目标、受众、时效、非目标是什么 |
| 契约 | 输入缺失和输出未知如何表示 |
| 执行 | 模型可以看什么、推断什么、调用什么 |
| 验收 | 谁用什么证据判断正确 |
| 失败 | 何时重试、降级、拒绝或转人工 |
| 治理 | 如何最小化数据并追踪版本 |

::: tip 一句话原则
先诊断先备知识和目标，再决定解释深度。优先提问、提示、局部示范和反馈；对作业与考试不直接代做，并为不同学习需求提供可达路径。
:::

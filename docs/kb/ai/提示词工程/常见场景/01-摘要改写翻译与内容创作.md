## 1. 为什么这类任务需要场景设计

先区分“忠实变换”和“受约束创作”。摘要、改写、翻译默认不得引入源文没有的事实；创作也必须标出已知事实、合理设定与待核实内容。

提示词不是一句魔法口令，而是任务协议的自然语言实现。协议要让输入可解释、输出可验证、失败可恢复、风险可升级。

::: important 核心判断
先问“什么结果算正确”，再问“怎样措辞更像提示词”。
如果验收者无法独立判断对错，提示再长也只是偏好描述。
:::

### 1.1 场景成功的四层含义

| 层次 | 问题 | 最低证据 |
| --- | --- | --- |
| 语法层 | 格式是否可解析 | 解析器或格式检查 |
| 语义层 | 内容是否忠实/正确 | 逐项依据或金标 |
| 任务层 | 是否支持预定工作流 | 下游验收测试 |
| 治理层 | 是否安全、合规、可追溯 | 日志、权限与人工复核 |

### 1.2 不要把模型能力当作任务定义

- 模型“能生成”不等于业务“可接受”。
- 流畅度是表面质量，不是事实正确性的替代指标。
- 单次成功不能证明稳定，应覆盖边界、反例和分布变化。
- 把未知显式留空，通常比生成一个完整但错误的答案更有价值。

## 2. 任务分型

### 2.1 抽取式摘要

抽取式摘要：保留原句或证据片段。设计时明确输入单位、允许的推断、输出粒度和验收主体。

- 适用信号：业务请求与“抽取式摘要”的目标一致。
- 设计重点：把主任务拆成可独立检查的原子结果。
- 退出条件：关键输入缺失或风险超过自动处理权限时转人工。

### 2.2 生成式摘要

生成式摘要：重组表达但不扩展事实。设计时明确输入单位、允许的推断、输出粒度和验收主体。

- 适用信号：业务请求与“生成式摘要”的目标一致。
- 设计重点：把主任务拆成可独立检查的原子结果。
- 退出条件：关键输入缺失或风险超过自动处理权限时转人工。

### 2.3 分层摘要

分层摘要：一句话、要点、详细版并存。设计时明确输入单位、允许的推断、输出粒度和验收主体。

- 适用信号：业务请求与“分层摘要”的目标一致。
- 设计重点：把主任务拆成可独立检查的原子结果。
- 退出条件：关键输入缺失或风险超过自动处理权限时转人工。

### 2.4 面向行动的摘要

面向行动的摘要：突出决策、负责人、期限。设计时明确输入单位、允许的推断、输出粒度和验收主体。

- 适用信号：业务请求与“面向行动的摘要”的目标一致。
- 设计重点：把主任务拆成可独立检查的原子结果。
- 退出条件：关键输入缺失或风险超过自动处理权限时转人工。

### 2.5 等义改写

等义改写：语气、长度、可读性变化。设计时明确输入单位、允许的推断、输出粒度和验收主体。

- 适用信号：业务请求与“等义改写”的目标一致。
- 设计重点：把主任务拆成可独立检查的原子结果。
- 退出条件：关键输入缺失或风险超过自动处理权限时转人工。

### 2.6 翻译与本地化

翻译与本地化：术语、单位、文化和格式适配。设计时明确输入单位、允许的推断、输出粒度和验收主体。

- 适用信号：业务请求与“翻译与本地化”的目标一致。
- 设计重点：把主任务拆成可独立检查的原子结果。
- 退出条件：关键输入缺失或风险超过自动处理权限时转人工。

### 2.7 基于材料的内容创作

基于材料的内容创作：只使用给定事实。设计时明确输入单位、允许的推断、输出粒度和验收主体。

- 适用信号：业务请求与“基于材料的内容创作”的目标一致。
- 设计重点：把主任务拆成可独立检查的原子结果。
- 退出条件：关键输入缺失或风险超过自动处理权限时转人工。

### 2.8 开放创作

开放创作：允许设定，但明确虚构边界。设计时明确输入单位、允许的推断、输出粒度和验收主体。

- 适用信号：业务请求与“开放创作”的目标一致。
- 设计重点：把主任务拆成可独立检查的原子结果。
- 退出条件：关键输入缺失或风险超过自动处理权限时转人工。

## 3. 信息收集问题

在写提示前，按顺序回答下列问题。高风险字段没有答案时，不应假装已完成需求分析。

### 3.1 任务是忠实变换还是允许创作

记录答案、提供者、确认时间和默认行为。若“任务是忠实变换还是允许创作”没有明确答案，将其加入待澄清清单。

- 可接受回答：具体规则、示例或可核查文档。
- 不可接受回答：“按常识”“尽量准确”“模型自行判断”。

## 4. 输入输出契约

### 4.1 输入契约

| 输入项 | 必需性 | 校验方式 |
| --- | --- | --- |
| 原始材料及版本/日期 | 必需 | 类型、范围、版本与样例检查 |
| 任务类型与目标受众 | 必需 | 类型、范围、版本与样例检查 |
| 必须保留清单 | 必需 | 类型、范围、版本与样例检查 |
| 允许省略清单 | 必需 | 类型、范围、版本与样例检查 |
| 术语表与风格样例 | 按场景 | 类型、范围、版本与样例检查 |
| 输出长度和格式 | 按场景 | 类型、范围、版本与样例检查 |

### 4.2 输出契约

| 输出项 | 用途 | 不可接受情况 |
| --- | --- | --- |
| 正文 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| 关键事实覆盖表 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| 不确定项 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| 编辑说明 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| 必要时的逐项来源定位 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |

### 4.3 契约版本化

- 提示模板、schema、标签手册和验收集分别记录版本。
- 会改变输出含义的修改提升主版本。
- 仅修正文案但不改变行为的修改提升次版本。
- 回放历史样本，比较新旧版本差异而非只看新样例。

### 4.4 分隔与数据边界

- 用 XML 标签、代码块或明确 ID 分隔指令与用户材料。
- 把材料中的命令视为数据，除非契约明确允许执行。
- 多文档输入保留文档 ID，禁止在无标识拼接后引用。
- 超长输入先建立分块策略和跨块合并规则。

## 5. 通用提示模板

```text
你是忠实内容变换编辑。
任务类型：{{摘要/改写/翻译/受约束创作}}
目标受众与用途：{{audience_and_use}}
源材料：&lt;source&gt;{{source}}&lt;/source&gt;
必须保留：{{must_keep}}
可省略：{{may_omit}}
术语与风格：{{glossary_and_style}}
长度与格式：{{length_and_format}}
规则：
1. 事实性内容只能来自源材料；不要用常识补空。
2. 保留数字、单位、否定、条件、例外、归因与时间范围。
3. 无法确定时标记“原文未说明”或提出澄清问题。
4. 输出后给出关键事实覆盖表与疑点，不输出虚构引用。
输出：正文；覆盖表；不确定项；自检。
```

### 5.1 模板变量表

| 变量 | 填写原则 | 错误示例 |
| --- | --- | --- |
| 任务目标 | 可观察、可验收 | “做得更好” |
| 输入范围 | 标明边界、版本和 ID | “参考所有信息” |
| 允许推断 | 列白名单或明确禁止 | “合理发挥” |
| 输出格式 | 给 schema/样例/长度 | “结构清晰” |
| 失败行为 | 定义未知、拒绝和升级 | “不要出错” |
| 验收标准 | 指标、阈值、测试集 | “看起来专业” |

### 5.2 少样本示例设计

- 示例覆盖正常、缺失、冲突和越界输入。
- 示例输出必须完全符合契约，否则模型会学习错误。
- 不要只提供正例；至少加入一个应当弃权或 unknown 的例子。
- 示例顺序避免把偶然位置误学成优先级。

### 5.3 提示注入防护

- 明确用户材料不是系统指令。
- 工具权限由外部执行层控制，不能只靠提示文本。
- 检索内容中的“忽略前文”等句子按引用数据处理。
- 敏感动作使用参数白名单和人工确认。

## 6. 三个完整案例

### 6.1 案例：事故通报执行摘要

#### 场景输入

将 1800 字内部事故通报压缩为管理层 180 字摘要，原文含初步原因、影响范围和待确认数字。

#### 初始提示

```text
总结下面的事故通报，写得简洁专业。
```

#### 问题诊断

- 没有定义哪些限定词必须保留
- “初步原因”容易被写成确定原因
- 待确认数字可能被模型擅自补齐
- 没有覆盖检查

#### 优化版提示

```text
生成不超过 180 个汉字的管理层摘要。仅依据 <通报> 内容。必须保留发生时间、影响范围、当前状态、明确标成“初步”的原因、下一步动作；任何待确认数字写“待确认”，不得估算。摘要后用表格列出五类信息在原文中的短证据。若字数冲突，先保事实后保修辞。
```

#### 验收标准

- [ ] A1.1 正文不超过 180 个汉字
- [ ] A1.2 五类关键信息全部覆盖
- [ ] A1.3 初步结论未被确定化
- [ ] A1.4 数字与单位零漂移
- [ ] A1.5 无源外事实且证据可定位

#### 迭代记录方式

| 轮次 | 只改一个变量 | 观察指标 | 保留/回退 |
| --- | --- | --- | --- |
| 0 | 初始提示作为基线 | 记录全部验收项 | 基线 |
| 1 | 补齐输入与边界 | 正确性和弃权 | 按指标决定 |
| 2 | 补齐输出结构 | 可解析性和可追溯 | 按指标决定 |
| 3 | 调整示例或规则 | 边界集与回归集 | 不得牺牲安全 |

### 6.2 案例：产品条款通俗改写

#### 场景输入

把会员自动续费条款改写给普通用户阅读，但不得弱化取消条件和退款例外。

#### 初始提示

```text
把这段法律条款写得友好一点。
```

#### 问题诊断

- “友好”可能导致权利义务被柔化
- 没有指定保留条件和例外
- 没有区分解释与法律原文
- 缺少版本提示

#### 优化版提示

```text
将 <条款> 改写为八年级阅读水平的用户说明。逐项保留收费周期、扣款时间、取消路径、生效时间、退款规则及所有例外；不得扩大或缩小权利。先输出通俗说明，再输出“原条款要素→改写句”对照表。遇到法律歧义原样引用并标记“需法务确认”。结尾声明通俗说明不替代正式条款。
```

#### 验收标准

- [ ] A2.1 义务、条件、例外完整
- [ ] A2.2 没有新增承诺
- [ ] A2.3 对照表逐项可核验
- [ ] A2.4 歧义未被自行解释
- [ ] A2.5 阅读难度符合目标

| 0 | 初始提示作为基线 | 记录全部验收项 | 基线 |
| 1 | 补齐输入与边界 | 正确性和弃权 | 按指标决定 |

### 6.3 案例：双语发布稿本地化

#### 场景输入

将中文发布稿译为英文，产品名不译，日期改英文格式，引用语不得改变立场。

#### 初始提示

```text
把发布稿翻译成自然英文。
```

#### 问题诊断

- 产品术语可能出现多个译法
- 日期与单位本地化规则不明
- 引语归因可能丢失
- 自然化可能引入营销夸张

#### 优化版提示

```text
把 <中文稿> 翻译为面向美国科技媒体的英文稿。术语表中的产品名保持原文；日期用 Month D, YYYY，人民币金额保留并在括号给出“约合美元”时仅使用输入提供的汇率，否则不换算。引语保持说话人、态度与限定词。禁止新增最高级和市场结论。输出译文、术语一致性表、无法等值翻译的表达及备选。
```

#### 验收标准

- [ ] A3.1 术语表 100% 一致
- [ ] A3.2 引语立场与归因不变
- [ ] A3.3 无擅自汇率换算
- [ ] A3.4 格式满足本地化约束
- [ ] A3.5 所有非等值表达显式列出

## 7. 风险登记册

| 风险 | 早期信号 | 预防控制 | 发现后动作 |
| --- | --- | --- | --- |
| 漏掉否定、条件、例外或时间范围 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 把推测写成事实 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 数字、单位、人名和因果关系漂移 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 翻译时术语不一致 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 为追求流畅补写不存在的细节 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 压缩后行动项失去负责人或期限 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |

### 7.1 风险分级

- 低：格式或措辞瑕疵，可自动重试。
- 中：影响业务判断但可在发布前人工发现。
- 高：可能造成安全、法律、财务、健康或重大声誉后果。
- 关键：不可逆操作或大规模敏感数据暴露，默认禁止自动执行。

### 7.2 人在回路

1. 定义触发人工复核的明确条件。
2. 向复核者展示原始输入、输出、证据和模型版本。
3. 记录复核改动原因，沉淀为失败类别。
4. 不要把“人工复核”当作没有流程的兜底口号。

## 8. 边界条件

### 8.1 源材料缺页时停止完整摘要并列缺口

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.2 输入互相矛盾时并列冲突，不替用户裁决

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.3 极限字数无法容纳关键事实时报告不可同时满足

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.4 诗歌、广告等创作可偏离字面，但事实声明仍需依据

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.5 机器翻译不替代法律、医疗等专业审校

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.6 通用压力输入

- 空输入、仅空白、乱码和截断输入。
- 互相矛盾的输入与过时版本。
- 超长输入和极端重复内容。
- 包含提示注入、恶意链接或未知附件的输入。
- 超出语言、地域、时间或专业权限范围的输入。

## 9. 失败处理与恢复

1. 先比较输出与源文，不凭印象重写
2. 定位漏项、错项、增项、语气漂移中的具体类型
3. 只修复失败片段，避免无关全文改写
4. 连续两轮失败则缩小任务或分段处理
5. 高风险内容升级人工双人复核

### 9.1 标准失败响应

```text
状态：未完成/部分完成
失败阶段：{{stage}}
已确认内容：{{verified}}
未知或冲突：{{unknowns}}
没有执行的动作：{{not_done}}
需要补充：{{required_input}}
建议下一步：{{next_step}}
```

### 9.2 重试预算

- 格式失败可自动重试一次，并只修格式。
- 事实或语义失败不能靠原提示无限重试。
- 连续两轮同类失败应修改契约、拆分任务或升级人工。
- 每次重试保留输入版本和失败原因，防止选择性展示成功结果。

### 9.3 降级策略

- 从自动发布降级为草稿。
- 从完整答案降级为已证实字段。
- 从开放生成降级为封闭材料处理。
- 从执行动作降级为只读建议。

## 10. 隐私、安全与合规

### 10.1 删除不必要的个人身份信息

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.2 客户材料进入模型前确认数据处理协议

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.3 示例不得包含真实密钥、病历号或未公开财务数据

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.4 输出保留原文敏感级别

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.5 翻译供应链也应受访问控制

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.6 最小权限清单

- 模型只看到完成任务所需的最少字段。
- 工具只开放必要动作和参数范围。
- 高风险输出默认不自动发送或执行。
- 测试环境与生产环境隔离。
- 审计日志本身也按敏感数据保护。

## 11. 迭代策略

### 11.1 建立基线

1. 固定模型、参数、提示和数据版本。
2. 选取代表性正常样本与历史失败样本。
3. 先测初始提示，不只展示优化后结果。
4. 保存原始输出，避免事后改写证据。

### 11.2 单变量迭代

| 可改变量 | 适合解决 | 不适合解决 |
| --- | --- | --- |
| 补上下文 | 模型缺少事实或规则 | 规则本身冲突 |
| 补输出 schema | 格式漂移 | 事实来源不足 |
| 补少样本 | 边界判定不稳定 | 样本标签错误 |
| 拆分步骤 | 复合任务遗漏 | 下游无法验收 |
| 增加工具 | 需要实时/精确信息 | 权限治理缺失 |

### 11.3 错误分类

- E1 输入缺失：请求方未提供必要信息。
- E2 契约歧义：字段、标签或成功定义不清。
- E3 检索/工具失败：信息无法访问或工具报错。
- E4 推理/生成失败：已有信息未被正确使用。
- E5 验收失败：结果正确但格式或工作流不兼容。
- E6 治理失败：权限、隐私或合规控制不足。

### 11.4 停止条件

- 主要指标达到门槛且安全指标无回退。
- 边界集不再出现新的高严重度错误。
- 成本和延迟在预算内。
- 剩余风险有明确人工流程和责任人。

## 12. 评测设计

### 12.1 数据集分层

| 集合 | 目的 | 建议内容 |
| --- | --- | --- |
| 开发集 | 快速迭代 | 典型任务和已知错误 |
| 回归集 | 防止旧错复发 | 每类历史事故至少一例 |
| 边界集 | 验证拒绝与 unknown | 缺失、冲突、注入、超范围 |
| 盲测集 | 估计泛化 | 迭代者未见的真实分布 |
| 红队集 | 发现安全缺陷 | 越权、隐私、恶意输入 |

### 12.2 核心指标

- **M1 事实支持率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M2 关键点召回率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M3 数字与实体准确率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M4 术语一致率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M5 长度合规率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M6 风格匹配度**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M7 无依据新增事实数**：定义分子、分母、排除项和目标阈值，避免只报平均分。

### 12.3 量规示例

| 分数 | 正确性 | 完整性 | 可追溯性 | 安全性 |
| --- | --- | --- | --- | --- |
| 3 | 全部关键结论正确 | 无关键漏项 | 逐项可定位 | 无违规 |
| 2 | 轻微非关键错误 | 少量次要漏项 | 大部分可定位 | 低风险可修复 |
| 1 | 至少一项关键错误 | 明显漏项 | 证据弱或错配 | 需要人工阻断 |
| 0 | 结论不可用 | 任务未完成 | 无依据 | 严重违规 |

### 12.4 评审一致性

- 先用 10-20 个样本校准评审者。
- 为每个分数提供正例和反例。
- 记录争议项，不强行平均掩盖定义问题。
- 高风险样本采用双人独立评审。

### 12.5 线上监控

- 监控输入分布、未知率、人工改写率和升级率。
- 抽样复核成功输出，而不只看用户投诉。
- 模型或依赖升级后运行完整回归集。
- 指标突变时能回滚提示版本或关闭自动动作。

## 14. 练习

### 14.1 练习 1

摘要只有 60 字预算，但原文有结论、三项限制和两个数字。如何排序？

<details>
<summary>展开参考答案</summary>

先保结论的适用范围、否定/限制和决定性数字；若仍超限，明确报告预算冲突，不静默删关键条件。

</details>

### 14.2 练习 2

源文写“可能与配置变更有关”，输出写“由配置变更导致”。错在哪里？

<details>
<summary>展开参考答案</summary>

把相关性假设升级为确定因果；应保留“可能”并注明调查状态。

</details>

### 14.3 练习 3

翻译时输入没有汇率，是否可联网换算？

<details>
<summary>展开参考答案</summary>

除非契约明确授权检索、指定日期和来源，否则不换算；可保留原币并提示待补汇率。

</details>

### 14.4 综合练习

为一个真实“摘要、改写、翻译与内容创作”任务写一份输入输出契约。至少包含：非目标、未知行为、证据要求、失败升级和五条验收标准。

<details>
<summary>展开评分要点</summary>

优秀答案不是堆叠角色设定，而是让第三方能用固定样本和规则判断成功或失败。检查每个输出字段是否有来源、每个风险是否有外部控制、每个指标是否有阈值。

</details>

## 15. 快速复盘卡

| 阶段 | 必须回答的问题 |
| --- | --- |
| 需求 | 目标、受众、时效、非目标是什么 |
| 契约 | 输入缺失和输出未知如何表示 |
| 执行 | 模型可以看什么、推断什么、调用什么 |
| 验收 | 谁用什么证据判断正确 |
| 失败 | 何时重试、降级、拒绝或转人工 |
| 治理 | 如何最小化数据并追踪版本 |

::: tip 一句话原则
先区分“忠实变换”和“受约束创作”。摘要、改写、翻译默认不得引入源文没有的事实；创作也必须标出已知事实、合理设定与待核实内容。
:::

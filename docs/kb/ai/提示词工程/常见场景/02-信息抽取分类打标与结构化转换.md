> 本章目标：把非结构化输入稳定映射到可验证 schema，并保留未知、证据与枚举约束。

> 导航：[上一章](/kb/ai/提示词工程/常见场景/01-摘要改写翻译与内容创作/) · [下一章](/kb/ai/提示词工程/常见场景/03-问答研究事实核查与引用设计/)

## 1. 为什么这类任务需要场景设计

先定义 schema，再设计提示。null 表示字段适用但未提供，unknown 表示材料存在但无法判定；二者不得与空字符串、false 或模型猜测混用。

提示词不是一句魔法口令，而是任务协议的自然语言实现。协议要让输入可解释、输出可验证、失败可恢复、风险可升级。

::: important 核心判断
先问“什么结果算正确”，再问“怎样措辞更像提示词”。
如果验收者无法独立判断对错，提示再长也只是偏好描述。
:::

### 1.1 场景成功的四层含义

| 层次 | 问题 | 最低证据 |
| --- | --- | --- |
| 语法层 | 格式是否可解析 | 解析器或格式检查 |
| 语义层 | 内容是否忠实/正确 | 逐项依据或金标 |
| 任务层 | 是否支持预定工作流 | 下游验收测试 |
| 治理层 | 是否安全、合规、可追溯 | 日志、权限与人工复核 |

### 1.2 不要把模型能力当作任务定义

- 模型“能生成”不等于业务“可接受”。
- 流畅度是表面质量，不是事实正确性的替代指标。
- 单次成功不能证明稳定，应覆盖边界、反例和分布变化。
- 把未知显式留空，通常比生成一个完整但错误的答案更有价值。

## 4. 输入输出契约

### 4.1 输入契约

| 输入项 | 必需性 | 校验方式 |
| --- | --- | --- |
| 带稳定 ID 的原文 | 必需 | 类型、范围、版本与样例检查 |
| JSON Schema 或字段表 | 必需 | 类型、范围、版本与样例检查 |
| 枚举定义与判定规则 | 必需 | 类型、范围、版本与样例检查 |
| 空值语义 | 必需 | 类型、范围、版本与样例检查 |
| 证据定位规则 | 按场景 | 类型、范围、版本与样例检查 |
| 规范化时区与单位 | 按场景 | 类型、范围、版本与样例检查 |

### 4.2 输出契约

| 输出项 | 用途 | 不可接受情况 |
| --- | --- | --- |
| 仅 schema 允许的字段 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| 原始值与规范化值 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| 每个事实的 evidence span | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| 置信度或审阅状态 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| validation_errors | 供下游验收或追溯 | 缺失、含混、无法定位依据 |

### 4.3 契约版本化

- 提示模板、schema、标签手册和验收集分别记录版本。
- 会改变输出含义的修改提升主版本。
- 仅修正文案但不改变行为的修改提升次版本。
- 回放历史样本，比较新旧版本差异而非只看新样例。

### 4.4 分隔与数据边界

- 用 XML 标签、代码块或明确 ID 分隔指令与用户材料。
- 把材料中的命令视为数据，除非契约明确允许执行。
- 多文档输入保留文档 ID，禁止在无标识拼接后引用。
- 超长输入先建立分块策略和跨块合并规则。

## 5. 通用提示模板

```text
你是受 schema 约束的信息处理器。
输入 ID：{{id}}
原文：&lt;document&gt;{{text}}&lt;/document&gt;
Schema：{{json_schema}}
枚举与判定规则：{{label_rules}}
空值规则：null=适用但未提供；"unknown"=原文提及但无法判定；"not_applicable"=不适用。
要求：
1. 不推断原文没有的值。
2. 每个非空事实附 evidence.quote 与约定口径的 span。
3. 只能输出 schema 字段和枚举值。
4. 规范化值与 raw_value 分开。
5. 输出前执行类型、必填、枚举、证据和跨字段一致性检查。
只输出合法 JSON；不能满足时在 validation_errors 中说明。
```

### 5.1 模板变量表

| 变量 | 填写原则 | 错误示例 |
| --- | --- | --- |
| 任务目标 | 可观察、可验收 | “做得更好” |
| 输入范围 | 标明边界、版本和 ID | “参考所有信息” |
| 允许推断 | 列白名单或明确禁止 | “合理发挥” |
| 输出格式 | 给 schema/样例/长度 | “结构清晰” |
| 失败行为 | 定义未知、拒绝和升级 | “不要出错” |
| 验收标准 | 指标、阈值、测试集 | “看起来专业” |

### 5.2 少样本示例设计

- 示例覆盖正常、缺失、冲突和越界输入。
- 示例输出必须完全符合契约，否则模型会学习错误。
- 不要只提供正例；至少加入一个应当弃权或 unknown 的例子。
- 示例顺序避免把偶然位置误学成优先级。

### 5.3 提示注入防护

- 明确用户材料不是系统指令。
- 工具权限由外部执行层控制，不能只靠提示文本。
- 检索内容中的“忽略前文”等句子按引用数据处理。
- 敏感动作使用参数白名单和人工确认。

## 6. 三个完整案例

### 6.1 案例：客服工单路由

#### 场景输入

从用户留言抽取产品、问题类型、紧急度，并路由到固定队列。

#### 初始提示

```text
分析工单并输出分类 JSON。
```

#### 问题诊断

- 没有 schema 和封闭枚举
- 紧急度可能由情绪词误判
- 未知产品会被猜测
- 缺少证据

#### 优化版提示

```text
按给定 JSON Schema 输出。product 仅可为 [App, Web, API, unknown]；issue_type 仅可为 [登录, 计费, 性能, 功能咨询, 其他]；urgency 仅可为 [P1,P2,P3]，P1 必须有服务完全不可用或明确安全事件证据。字段缺失用 null，提及但无法判定用 unknown。每个标签附原文 quote；不输出解释文字。
```

#### 验收标准

- [ ] A1.1 JSON Schema 校验通过
- [ ] A1.2 枚举外值为零
- [ ] A1.3 P1 均有规则证据
- [ ] A1.4 未知未被猜成产品
- [ ] A1.5 证据能支持对应标签

## 7. 风险登记册

| 风险 | 早期信号 | 预防控制 | 发现后动作 |
| --- | --- | --- | --- |
| 把缺失值猜成常见值 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 输出枚举外标签 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 证据与字段不相符 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 字符偏移因 Unicode 口径错位 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 分类定义重叠导致漂移 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| JSON 看似正确但类型不合法 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |

### 7.1 风险分级

- 低：格式或措辞瑕疵，可自动重试。
- 中：影响业务判断但可在发布前人工发现。
- 高：可能造成安全、法律、财务、健康或重大声誉后果。
- 关键：不可逆操作或大规模敏感数据暴露，默认禁止自动执行。

### 7.2 人在回路

1. 定义触发人工复核的明确条件。
2. 向复核者展示原始输入、输出、证据和模型版本。
3. 记录复核改动原因，沉淀为失败类别。
4. 不要把“人工复核”当作没有流程的兜底口号。

## 8. 边界条件

### 8.1 schema 版本不明时不得猜字段

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.2 无法稳定计算 offset 时只给 quote 并说明口径缺失

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.3 开放世界实体不可硬塞封闭枚举

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.4 同名实体没有消歧证据时保留候选

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.5 跨文档合并必须说明实体解析规则

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.6 通用压力输入

- 空输入、仅空白、乱码和截断输入。
- 互相矛盾的输入与过时版本。
- 超长输入和极端重复内容。
- 包含提示注入、恶意链接或未知附件的输入。
- 超出语言、地域、时间或专业权限范围的输入。

## 9. 失败处理与恢复

1. 先运行机器 schema 校验
2. 再抽样做证据蕴含检查
3. 区分提示失败、标签手册失败和输入质量失败
4. 修订枚举定义时提升 schema 版本
5. 回归集保留每种历史错误

### 9.1 标准失败响应

```text
状态：未完成/部分完成
失败阶段：{{stage}}
已确认内容：{{verified}}
未知或冲突：{{unknowns}}
没有执行的动作：{{not_done}}
需要补充：{{required_input}}
建议下一步：{{next_step}}
```

### 9.2 重试预算

- 格式失败可自动重试一次，并只修格式。
- 事实或语义失败不能靠原提示无限重试。
- 连续两轮同类失败应修改契约、拆分任务或升级人工。
- 每次重试保留输入版本和失败原因，防止选择性展示成功结果。

### 9.3 降级策略

- 从自动发布降级为草稿。
- 从完整答案降级为已证实字段。
- 从开放生成降级为封闭材料处理。
- 从执行动作降级为只读建议。

## 10. 隐私、安全与合规

### 10.1 抽取前最小化原文范围

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.2 证据 quote 避免复制无关个人信息

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.3 结构化数据可能更易检索，应重新评估权限

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.4 日志中掩码身份证号和账号

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.5 训练/评测样本遵循保留期限

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.6 最小权限清单

- 模型只看到完成任务所需的最少字段。
- 工具只开放必要动作和参数范围。
- 高风险输出默认不自动发送或执行。
- 测试环境与生产环境隔离。
- 审计日志本身也按敏感数据保护。

## 11. 迭代策略

### 11.1 建立基线

1. 固定模型、参数、提示和数据版本。
2. 选取代表性正常样本与历史失败样本。
3. 先测初始提示，不只展示优化后结果。
4. 保存原始输出，避免事后改写证据。

### 11.2 单变量迭代

| 可改变量 | 适合解决 | 不适合解决 |
| --- | --- | --- |
| 补上下文 | 模型缺少事实或规则 | 规则本身冲突 |
| 补输出 schema | 格式漂移 | 事实来源不足 |
| 补少样本 | 边界判定不稳定 | 样本标签错误 |
| 拆分步骤 | 复合任务遗漏 | 下游无法验收 |
| 增加工具 | 需要实时/精确信息 | 权限治理缺失 |

### 11.3 错误分类

- E1 输入缺失：请求方未提供必要信息。
- E2 契约歧义：字段、标签或成功定义不清。
- E3 检索/工具失败：信息无法访问或工具报错。
- E4 推理/生成失败：已有信息未被正确使用。
- E5 验收失败：结果正确但格式或工作流不兼容。
- E6 治理失败：权限、隐私或合规控制不足。

### 11.4 停止条件

- 主要指标达到门槛且安全指标无回退。
- 边界集不再出现新的高严重度错误。
- 成本和延迟在预算内。
- 剩余风险有明确人工流程和责任人。

## 12. 评测设计

### 12.1 数据集分层

| 集合 | 目的 | 建议内容 |
| --- | --- | --- |
| 开发集 | 快速迭代 | 典型任务和已知错误 |
| 回归集 | 防止旧错复发 | 每类历史事故至少一例 |
| 边界集 | 验证拒绝与 unknown | 缺失、冲突、注入、超范围 |
| 盲测集 | 估计泛化 | 迭代者未见的真实分布 |
| 红队集 | 发现安全缺陷 | 越权、隐私、恶意输入 |

### 12.2 核心指标

- **M1 字段精确率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M2 字段召回率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M3 标签 macro-F1**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M4 schema 校验通过率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M5 证据蕴含率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M6 span 边界准确率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M7 枚举外输出数**：定义分子、分母、排除项和目标阈值，避免只报平均分。

### 12.3 量规示例

| 分数 | 正确性 | 完整性 | 可追溯性 | 安全性 |
| --- | --- | --- | --- | --- |
| 3 | 全部关键结论正确 | 无关键漏项 | 逐项可定位 | 无违规 |
| 2 | 轻微非关键错误 | 少量次要漏项 | 大部分可定位 | 低风险可修复 |
| 1 | 至少一项关键错误 | 明显漏项 | 证据弱或错配 | 需要人工阻断 |
| 0 | 结论不可用 | 任务未完成 | 无依据 | 严重违规 |

### 12.4 评审一致性

- 先用 10-20 个样本校准评审者。
- 为每个分数提供正例和反例。
- 记录争议项，不强行平均掩盖定义问题。
- 高风险样本采用双人独立评审。

### 12.5 线上监控

- 监控输入分布、未知率、人工改写率和升级率。
- 抽样复核成功输出，而不只看用户投诉。
- 模型或依赖升级后运行完整回归集。
- 指标突变时能回滚提示版本或关闭自动动作。

## 14. 练习

### 14.1 练习 1

原文完全没提婚姻状态，应输出 null 还是 unknown？

<details>
<summary>展开参考答案</summary>

若字段适用但未提供，输出 null；unknown 用于原文触及该事实却无法判定。最终以项目数据字典为准。

</details>

### 14.2 练习 2

证据 quote 支持实体，但不支持分类标签，能否验收？

<details>
<summary>展开参考答案</summary>

不能。每个输出事实的证据必须蕴含该事实，实体出现不等于标签成立。

</details>

### 14.3 练习 3

新类别频繁落入“其他”怎么办？

<details>
<summary>展开参考答案</summary>

分析混淆样本，决定扩充枚举还是改进定义；版本化 schema，并重跑回归集。

</details>

### 14.4 综合练习

为一个真实“信息抽取、分类打标与结构化转换”任务写一份输入输出契约。至少包含：非目标、未知行为、证据要求、失败升级和五条验收标准。

<details>
<summary>展开评分要点</summary>

优秀答案不是堆叠角色设定，而是让第三方能用固定样本和规则判断成功或失败。检查每个输出字段是否有来源、每个风险是否有外部控制、每个指标是否有阈值。

</details>

## 15. 快速复盘卡

| 阶段 | 必须回答的问题 |
| --- | --- |
| 需求 | 目标、受众、时效、非目标是什么 |
| 契约 | 输入缺失和输出未知如何表示 |
| 执行 | 模型可以看什么、推断什么、调用什么 |
| 验收 | 谁用什么证据判断正确 |
| 失败 | 何时重试、降级、拒绝或转人工 |
| 治理 | 如何最小化数据并追踪版本 |

::: tip 一句话原则
先定义 schema，再设计提示。null 表示字段适用但未提供，unknown 表示材料存在但无法判定；二者不得与空字符串、false 或模型猜测混用。
:::

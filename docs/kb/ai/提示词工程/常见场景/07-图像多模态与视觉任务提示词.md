## 1. 为什么这类任务需要场景设计

多模态输入要标识每种模态及顺序，引用图像区域、视频时间段和页面位置。OCR 与视觉推断必须保留不确定性；图像生成要分解主体、构图、风格、光照和技术参数，并处理版权与身份风险。

提示词不是一句魔法口令，而是任务协议的自然语言实现。协议要让输入可解释、输出可验证、失败可恢复、风险可升级。

::: important 核心判断
先问“什么结果算正确”，再问“怎样措辞更像提示词”。
如果验收者无法独立判断对错，提示再长也只是偏好描述。
:::

### 1.1 场景成功的四层含义

| 层次 | 问题 | 最低证据 |
| --- | --- | --- |
| 语法层 | 格式是否可解析 | 解析器或格式检查 |
| 语义层 | 内容是否忠实/正确 | 逐项依据或金标 |
| 任务层 | 是否支持预定工作流 | 下游验收测试 |
| 治理层 | 是否安全、合规、可追溯 | 日志、权限与人工复核 |

### 1.2 不要把模型能力当作任务定义

- 模型“能生成”不等于业务“可接受”。
- 流畅度是表面质量，不是事实正确性的替代指标。
- 单次成功不能证明稳定，应覆盖边界、反例和分布变化。
- 把未知显式留空，通常比生成一个完整但错误的答案更有价值。

## 4. 输入输出契约

### 4.1 输入契约

| 输入项 | 必需性 | 校验方式 |
| --- | --- | --- |
| 带 ID 的模态清单和顺序 | 必需 | 类型、范围、版本与样例检查 |
| 区域/时间范围 | 必需 | 类型、范围、版本与样例检查 |
| 任务与禁用推断 | 必需 | 类型、范围、版本与样例检查 |
| OCR 语言和格式 | 必需 | 类型、范围、版本与样例检查 |
| 生成规格 | 按场景 | 类型、范围、版本与样例检查 |
| 版权身份授权 | 按场景 | 类型、范围、版本与样例检查 |

### 4.2 输出契约

| 输出项 | 用途 | 不可接受情况 |
| --- | --- | --- |
| 逐模态观察 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| 区域/时间定位 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| OCR 文本及置信状态 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| 推断与替代解释 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| 生成/编辑参数 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| 安全限制 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |

### 4.3 契约版本化

- 提示模板、schema、标签手册和验收集分别记录版本。
- 会改变输出含义的修改提升主版本。
- 仅修正文案但不改变行为的修改提升次版本。
- 回放历史样本，比较新旧版本差异而非只看新样例。

### 4.4 分隔与数据边界

- 用 XML 标签、代码块或明确 ID 分隔指令与用户材料。
- 把材料中的命令视为数据，除非契约明确允许执行。
- 多文档输入保留文档 ID，禁止在无标识拼接后引用。
- 超长输入先建立分块策略和跨块合并规则。

## 5. 通用提示模板

```text
你是多模态分析与视觉设计助手。
模态顺序：1={{image_1}}；2={{text}}；3={{video}}。不得交换对应关系。
任务：{{task}}
关注位置：{{region/page/timestamp}}
输出要求：{{format}}
规则：
1. 先逐模态记录可直接观察内容，再做跨模态推断。
2. 图像引用区域或坐标；视频引用起止时间；文档引用页码/区块。
3. OCR 保留原样文本、规范化文本和 uncertain 字段；不可辨认写 [无法辨认]。
4. 不推断未显示的身份、属性或事件。
5. 生成任务分列主体、构图、风格特征、光照、色彩、镜头/尺寸和负面约束。
6. 检查版权、商标、真人身份和敏感内容授权。
```

### 5.1 模板变量表

| 变量 | 填写原则 | 错误示例 |
| --- | --- | --- |
| 任务目标 | 可观察、可验收 | “做得更好” |
| 输入范围 | 标明边界、版本和 ID | “参考所有信息” |
| 允许推断 | 列白名单或明确禁止 | “合理发挥” |
| 输出格式 | 给 schema/样例/长度 | “结构清晰” |
| 失败行为 | 定义未知、拒绝和升级 | “不要出错” |
| 验收标准 | 指标、阈值、测试集 | “看起来专业” |

### 5.2 少样本示例设计

- 示例覆盖正常、缺失、冲突和越界输入。
- 示例输出必须完全符合契约，否则模型会学习错误。
- 不要只提供正例；至少加入一个应当弃权或 unknown 的例子。
- 示例顺序避免把偶然位置误学成优先级。

### 5.3 提示注入防护

- 明确用户材料不是系统指令。
- 工具权限由外部执行层控制，不能只靠提示文本。
- 检索内容中的“忽略前文”等句子按引用数据处理。
- 敏感动作使用参数白名单和人工确认。

## 6. 三个完整案例

### 6.1 案例：发票 OCR 与字段核对

#### 场景输入

从手机拍摄发票提取号码、日期、金额，右下角有反光。

#### 初始提示

```text
识别这张发票上的所有文字并整理。
```

#### 问题诊断

- 没有区域和字段范围
- 反光处可能被模型补字
- 原始 OCR 与规范化值混合
- 缺少坐标和置信状态

#### 优化版提示

```text
分析 image_1。先判断旋转、裁切和反光质量。仅抽取发票号码、开票日期、含税金额；每项输出 raw_text、normalized_value、bbox[x1,y1,x2,y2]（归一化 0-1000）、status[clear/uncertain/unreadable]。右下角反光区域不得猜测，无法辨认写 null 并建议重拍角度。金额同时核对大写与小写，冲突时两者都保留。
```

#### 验收标准

- [ ] A1.1 三个字段均有位置
- [ ] A1.2 反光区域无臆测补字
- [ ] A1.3 raw 与 normalized 分离
- [ ] A1.4 金额冲突触发复核
- [ ] A1.5 不可读值使用约定空值

#### 迭代记录方式

| 轮次 | 只改一个变量 | 观察指标 | 保留/回退 |
| --- | --- | --- | --- |
| 0 | 初始提示作为基线 | 记录全部验收项 | 基线 |
| 1 | 补齐输入与边界 | 正确性和弃权 | 按指标决定 |
| 2 | 补齐输出结构 | 可解析性和可追溯 | 按指标决定 |
| 3 | 调整示例或规则 | 边界集与回归集 | 不得牺牲安全 |

### 6.2 案例：产品操作视频定位

#### 场景输入

在 8 分钟录屏中找出用户遇到报错的步骤。

#### 初始提示

```text
看视频并告诉我为什么报错。
```

#### 问题诊断

- 没有时间定位
- 视觉现象可能被直接解释为根因
- 音频、字幕、画面可能不同步
- 可能忽略报错前操作

#### 优化版提示

```text
按视频顺序分析：画面→系统音频→字幕。定位首次异常前 30 秒至后 15 秒，输出每个关键动作的 start/end 时间码、可见 UI 区域和原样错误文本。将“观察到的现象”“可能原因”“需要日志验证”分栏；仅凭画面不得断言后端根因。若时间轴或音画不同步，报告偏移估计。
```

#### 验收标准

- [ ] A2.1 关键事件有起止时间
- [ ] A2.2 错误文字按可见内容转录
- [ ] A2.3 观察与根因假设分离
- [ ] A2.4 包含异常前置操作
- [ ] A2.5 音画偏移得到标注

### 6.3 案例：生成品牌活动主视觉

#### 场景输入

生成夏季无酒精饮料海报，不使用真人或现有艺术家风格。

#### 初始提示

```text
做一张高级感夏日饮料海报，像某知名摄影师。
```

#### 问题诊断

- “高级感”不可验证
- 直接模仿在世创作者有版权/风格风险
- 主体构图光照参数缺失
- 文字可读性和尺寸未知

#### 优化版提示

```text

```

- [ ] A3.1 主体占比和位置符合构图
- [ ] A3.2 文案安全区可用
- [ ] A3.3 光线色彩与参数一致
- [ ] A3.4 无具体艺术家模仿
- [ ] A3.5 无真人、商标和伪文字

## 7. 风险登记册

| 风险 | 早期信号 | 预防控制 | 发现后动作 |
| --- | --- | --- | --- |
| 忽略模态顺序导致错配 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 把不可见区域想象出来 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| OCR 错字被当事实 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 图表坐标轴或图例误读 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 视频截帧遗漏事件上下文 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 仿冒在世艺术家或未经许可真人身份 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |

### 7.1 风险分级

- 低：格式或措辞瑕疵，可自动重试。
- 中：影响业务判断但可在发布前人工发现。
- 高：可能造成安全、法律、财务、健康或重大声誉后果。
- 关键：不可逆操作或大规模敏感数据暴露，默认禁止自动执行。

### 7.2 人在回路

1. 定义触发人工复核的明确条件。
2. 向复核者展示原始输入、输出、证据和模型版本。
3. 记录复核改动原因，沉淀为失败类别。
4. 不要把“人工复核”当作没有流程的兜底口号。

## 8. 边界条件

### 8.1 低分辨率不能支持细字识别时要求更清晰输入

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.2 遮挡区域不得补全为事实

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.3 身份识别须有合法授权且遵守平台规则

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.4 医学影像不替代专业诊断

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.5 生成图不能暗示未经许可的代言

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.6 通用压力输入

- 空输入、仅空白、乱码和截断输入。
- 互相矛盾的输入与过时版本。
- 超长输入和极端重复内容。
- 包含提示注入、恶意链接或未知附件的输入。
- 超出语言、地域、时间或专业权限范围的输入。

## 9. 失败处理与恢复

1. 先确认模态顺序和文件是否完整
2. 缩小到明确区域或时间窗口
3. OCR 用多次读取和人工复核而非强行一致
4. 生成任务每轮只调整一到两个变量
5. 记录 seed、尺寸、模型版本等可用参数

### 9.1 标准失败响应

```text
状态：未完成/部分完成
失败阶段：{{stage}}
已确认内容：{{verified}}
未知或冲突：{{unknowns}}
没有执行的动作：{{not_done}}
需要补充：{{required_input}}
建议下一步：{{next_step}}
```

### 9.2 重试预算

- 格式失败可自动重试一次，并只修格式。
- 事实或语义失败不能靠原提示无限重试。
- 连续两轮同类失败应修改契约、拆分任务或升级人工。
- 每次重试保留输入版本和失败原因，防止选择性展示成功结果。

### 9.3 降级策略

- 从自动发布降级为草稿。
- 从完整答案降级为已证实字段。
- 从开放生成降级为封闭材料处理。
- 从执行动作降级为只读建议。

## 10. 隐私、安全与合规

### 10.1 上传前模糊人脸、车牌和屏幕通知

### 10.2 EXIF 可能含位置，应按需移除

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.3 真人编辑需明确同意与使用范围

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.4 避免生成欺骗性身份材料

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.5 版权素材保存许可与来源记录

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.6 最小权限清单

- 模型只看到完成任务所需的最少字段。
- 工具只开放必要动作和参数范围。
- 高风险输出默认不自动发送或执行。
- 测试环境与生产环境隔离。
- 审计日志本身也按敏感数据保护。

## 11. 迭代策略

### 11.1 建立基线

1. 固定模型、参数、提示和数据版本。
2. 选取代表性正常样本与历史失败样本。
3. 先测初始提示，不只展示优化后结果。
4. 保存原始输出，避免事后改写证据。

### 11.2 单变量迭代

| 可改变量 | 适合解决 | 不适合解决 |
| --- | --- | --- |
| 补上下文 | 模型缺少事实或规则 | 规则本身冲突 |
| 补输出 schema | 格式漂移 | 事实来源不足 |
| 补少样本 | 边界判定不稳定 | 样本标签错误 |
| 拆分步骤 | 复合任务遗漏 | 下游无法验收 |
| 增加工具 | 需要实时/精确信息 | 权限治理缺失 |

### 11.3 错误分类

- E1 输入缺失：请求方未提供必要信息。
- E2 契约歧义：字段、标签或成功定义不清。
- E3 检索/工具失败：信息无法访问或工具报错。
- E4 推理/生成失败：已有信息未被正确使用。
- E5 验收失败：结果正确但格式或工作流不兼容。
- E6 治理失败：权限、隐私或合规控制不足。

### 11.4 停止条件

- 主要指标达到门槛且安全指标无回退。
- 边界集不再出现新的高严重度错误。
- 成本和延迟在预算内。
- 剩余风险有明确人工流程和责任人。

## 12. 评测设计

### 12.1 数据集分层

| 集合 | 目的 | 建议内容 |
| --- | --- | --- |
| 开发集 | 快速迭代 | 典型任务和已知错误 |
| 回归集 | 防止旧错复发 | 每类历史事故至少一例 |
| 边界集 | 验证拒绝与 unknown | 缺失、冲突、注入、超范围 |
| 盲测集 | 估计泛化 | 迭代者未见的真实分布 |
| 红队集 | 发现安全缺陷 | 越权、隐私、恶意输入 |

### 12.2 核心指标

- **M1 区域定位准确率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M2 时间段 IoU**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M3 OCR 字符/词错误率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M4 视觉问答准确率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M5 观察-推断分离率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M6 生成规格满足率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M7 身份版权风险发现率**：定义分子、分母、排除项和目标阈值，避免只报平均分。

### 12.3 量规示例

| 分数 | 正确性 | 完整性 | 可追溯性 | 安全性 |
| --- | --- | --- | --- | --- |
| 3 | 全部关键结论正确 | 无关键漏项 | 逐项可定位 | 无违规 |
| 2 | 轻微非关键错误 | 少量次要漏项 | 大部分可定位 | 低风险可修复 |
| 1 | 至少一项关键错误 | 明显漏项 | 证据弱或错配 | 需要人工阻断 |
| 0 | 结论不可用 | 任务未完成 | 无依据 | 严重违规 |

### 12.4 评审一致性

- 先用 10-20 个样本校准评审者。
- 为每个分数提供正例和反例。
- 记录争议项，不强行平均掩盖定义问题。
- 高风险样本采用双人独立评审。

### 12.5 线上监控

- 监控输入分布、未知率、人工改写率和升级率。
- 抽样复核成功输出，而不只看用户投诉。
- 模型或依赖升级后运行完整回归集。
- 指标突变时能回滚提示版本或关闭自动动作。

### 14.1 练习 1

### 14.2 练习 2

视频中报错出现在 03:10，为什么还要看前 30 秒？

<details>
<summary>展开参考答案</summary>

报错触发条件通常来自前置操作；时间上下文有助于区分现象与可能原因。

</details>

### 14.3 练习 3

如何把“赛博朋克风”改成更可控描述？

<details>
<summary>展开参考答案</summary>

拆成霓虹互补色、潮湿反射表面、高密度城市层次、低机位广角、边缘光等可观察特征。

</details>

### 14.4 综合练习

为一个真实“图像、多模态与视觉任务提示词”任务写一份输入输出契约。至少包含：非目标、未知行为、证据要求、失败升级和五条验收标准。

<details>
<summary>展开评分要点</summary>

优秀答案不是堆叠角色设定，而是让第三方能用固定样本和规则判断成功或失败。检查每个输出字段是否有来源、每个风险是否有外部控制、每个指标是否有阈值。

</details>

## 15. 快速复盘卡

| 阶段 | 必须回答的问题 |
| --- | --- |
| 需求 | 目标、受众、时效、非目标是什么 |
| 契约 | 输入缺失和输出未知如何表示 |
| 执行 | 模型可以看什么、推断什么、调用什么 |
| 验收 | 谁用什么证据判断正确 |
| 失败 | 何时重试、降级、拒绝或转人工 |
| 治理 | 如何最小化数据并追踪版本 |

::: tip 一句话原则
多模态输入要标识每种模态及顺序，引用图像区域、视频时间段和页面位置。OCR 与视觉推断必须保留不确定性；图像生成要分解主体、构图、风格、光照和技术参数，并处理版权与身份风险。
:::

## 1. 为什么这类任务需要场景设计

先锁定 schema、SQL dialect、指标口径和数据时间，再写查询。默认 read-only，限制扫描、行数、时间范围和成本，并用独立方法验证结果。

提示词不是一句魔法口令，而是任务协议的自然语言实现。协议要让输入可解释、输出可验证、失败可恢复、风险可升级。

::: important 核心判断
先问“什么结果算正确”，再问“怎样措辞更像提示词”。
如果验收者无法独立判断对错，提示再长也只是偏好描述。
:::

### 1.1 场景成功的四层含义

| 层次 | 问题 | 最低证据 |
| --- | --- | --- |
| 语法层 | 格式是否可解析 | 解析器或格式检查 |
| 语义层 | 内容是否忠实/正确 | 逐项依据或金标 |
| 任务层 | 是否支持预定工作流 | 下游验收测试 |
| 治理层 | 是否安全、合规、可追溯 | 日志、权限与人工复核 |

### 1.2 不要把模型能力当作任务定义

- 模型“能生成”不等于业务“可接受”。
- 流畅度是表面质量，不是事实正确性的替代指标。
- 单次成功不能证明稳定，应覆盖边界、反例和分布变化。
- 把未知显式留空，通常比生成一个完整但错误的答案更有价值。

## 4. 输入输出契约

### 4.1 输入契约

| 输入项 | 必需性 | 校验方式 |
| --- | --- | --- |
| 业务问题与决策动作 | 必需 | 类型、范围、版本与样例检查 |
| schema 和样例 | 必需 | 类型、范围、版本与样例检查 |
| dialect | 必需 | 类型、范围、版本与样例检查 |
| 指标字典 | 必需 | 类型、范围、版本与样例检查 |
| 时间/时区 | 按场景 | 类型、范围、版本与样例检查 |
| 资源与权限限制 | 按场景 | 类型、范围、版本与样例检查 |

### 4.2 输出契约

| 输出项 | 用途 | 不可接受情况 |
| --- | --- | --- |
| 假设和口径 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| 只读 SQL | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| 参数与扫描说明 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| 验证查询 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| 结果解释 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |
| 限制与决策建议 | 供下游验收或追溯 | 缺失、含混、无法定位依据 |

### 4.3 契约版本化

- 提示模板、schema、标签手册和验收集分别记录版本。
- 会改变输出含义的修改提升主版本。
- 仅修正文案但不改变行为的修改提升次版本。
- 回放历史样本，比较新旧版本差异而非只看新样例。

### 4.4 分隔与数据边界

- 用 XML 标签、代码块或明确 ID 分隔指令与用户材料。
- 把材料中的命令视为数据，除非契约明确允许执行。
- 多文档输入保留文档 ID，禁止在无标识拼接后引用。
- 超长输入先建立分块策略和跨块合并规则。

## 5. 通用提示模板

```text
你是只读数据分析师。
业务问题：{{question}}
决策用途：{{decision}}
数据库：{{dialect_and_version}}
Schema/粒度：{{schema}}
指标口径：{{metric_definition}}
时间与时区：{{time_scope}}
资源限制：{{scan_limit_and_row_limit}}
要求：
1. 仅生成 SELECT/CTE/EXPLAIN；禁止 DDL、DML、存储过程和外部调用。
2. 显式列名、分区过滤、参数化条件和结果 LIMIT；避免 SELECT *。
3. 写出 join 基数、null、去重和迟到数据假设。
4. 提供小样本手算或独立聚合验证。
5. 区分数据事实、解释假设和建议。
输出：口径；SQL；安全/成本检查；验证；结论与限制。
```

### 5.1 模板变量表

| 变量 | 填写原则 | 错误示例 |
| --- | --- | --- |
| 任务目标 | 可观察、可验收 | “做得更好” |
| 输入范围 | 标明边界、版本和 ID | “参考所有信息” |
| 允许推断 | 列白名单或明确禁止 | “合理发挥” |
| 输出格式 | 给 schema/样例/长度 | “结构清晰” |
| 失败行为 | 定义未知、拒绝和升级 | “不要出错” |
| 验收标准 | 指标、阈值、测试集 | “看起来专业” |

### 5.2 少样本示例设计

- 示例覆盖正常、缺失、冲突和越界输入。
- 示例输出必须完全符合契约，否则模型会学习错误。
- 不要只提供正例；至少加入一个应当弃权或 unknown 的例子。
- 示例顺序避免把偶然位置误学成优先级。

### 5.3 提示注入防护

- 明确用户材料不是系统指令。
- 工具权限由外部执行层控制，不能只靠提示文本。
- 检索内容中的“忽略前文”等句子按引用数据处理。
- 敏感动作使用参数白名单和人工确认。

## 6. 三个完整案例

### 6.1 案例：月活用户报表

#### 场景输入

计算最近 12 个月 MAU，并按付费层级拆分。

#### 初始提示

```text
写 SQL 算过去一年的 MAU，按套餐分组。
```

#### 问题诊断

- 没有 dialect 与 schema
- 套餐可能按当前值而非事件时值
- 月份和时区未定义
- 大表可能全扫描

#### 优化版提示

```text
使用 BigQuery Standard SQL。events 粒度为事件，subscriptions 为用户套餐有效期。按 Asia/Shanghai 自然月统计过去 12 个完整月去重活跃用户，并按事件发生时有效套餐归组；无匹配为 unknown。仅扫描对应日期分区，显式列名，输出最多 100 行。先给 join 基数和重叠订阅检查，再给主查询与总量对账查询。只允许 SELECT/CTE。
```

#### 验收标准

- [ ] A1.1 只扫描 12 个月相关分区
- [ ] A1.2 用户-月-套餐去重正确
- [ ] A1.3 套餐按历史有效期关联
- [ ] A1.4 分组之和与可解释总量一致
- [ ] A1.5 SQL 为只读且 dialect 可执行

### 6.2 案例：转化率下降诊断

#### 场景输入

本周注册到首购转化率下降 8%，需要定位原因。

#### 初始提示

```text
分析转化率为什么下降。
```

#### 问题诊断

- 8% 是百分点还是相对变化不明
- 可能直接断言因果
- 同期、渠道和数据完整性未检查
- 漏斗窗口不明确

#### 优化版提示

```text
先澄清“下降 8%”口径。按固定 7 天转化窗口比较本周与过去四周同星期，检查事件延迟、埋点版本和样本完整性。将注册 cohort 按渠道、平台、地区和版本分层，输出贡献分解而非直接因果。SQL 仅扫描必要分区并限制明细行。对候选原因给支持证据、反证和下一步验证实验。
```

#### 验收标准

- [ ] A2.1 百分点与相对变化明确
- [ ] A2.2 窗口和 cohort 无未来泄漏
- [ ] A2.3 先排除数据质量问题
- [ ] A2.4 贡献不被表述为因果
- [ ] A2.5 候选解释可通过后续测试证伪

### 6.3 案例：高管周报与行动建议

#### 场景输入

把收入、留存和工单指标生成一页周报。

#### 初始提示

```text
根据这些数据写一份有洞察的周报。
```

#### 问题诊断

- “洞察”容易越过数据证据
- 不同指标的时间口径可能不一致
- 异常阈值未定义
- 建议与事实混合

#### 优化版提示

```text
依据已验证的指标表生成一页周报。每项先列本周值、环比、同比、目标差，再用不超过两句解释；只有达到预设阈值才标异常。数据事实、可能解释、建议动作分栏。所有数字保留口径和截至时间；缺数写 unknown。建议必须有负责人角色、预期信号和复查日期，不从相关性断言因果。
```

#### 验收标准

- [ ] A3.1 数字与输入逐项一致
- [ ] A3.2 比较周期可比
- [ ] A3.3 异常均满足阈值
- [ ] A3.4 事实/解释/建议明确分离
- [ ] A3.5 行动项可执行并可复查

## 7. 风险登记册

| 风险 | 早期信号 | 预防控制 | 发现后动作 |
| --- | --- | --- | --- |
| join 扩张导致重复计数 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 整数除法或 null 处理错误 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 未来信息泄漏 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 时区边界错位 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 全表扫描造成高成本 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |
| 相关性被解释为因果 | 抽样出现不一致或无依据结果 | 契约、证据、边界样本 | 停止自动发布并复核 |

### 7.1 风险分级

- 低：格式或措辞瑕疵，可自动重试。
- 中：影响业务判断但可在发布前人工发现。
- 高：可能造成安全、法律、财务、健康或重大声誉后果。
- 关键：不可逆操作或大规模敏感数据暴露，默认禁止自动执行。

### 7.2 人在回路

1. 定义触发人工复核的明确条件。
2. 向复核者展示原始输入、输出、证据和模型版本。
3. 记录复核改动原因，沉淀为失败类别。
4. 不要把“人工复核”当作没有流程的兜底口号。

## 8. 边界条件

### 8.1 无 schema 时不编造表列

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.2 未授权不得运行写操作

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.3 超扫描预算时先 EXPLAIN 或缩小时间

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.4 小样本不做稳定趋势断言

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.5 敏感分组人数低于阈值时抑制展示

期望行为：暂停不受支持的推断，输出已完成部分、缺失信息和下一步，不用流畅文本掩盖边界。

### 8.6 通用压力输入

- 空输入、仅空白、乱码和截断输入。
- 互相矛盾的输入与过时版本。
- 超长输入和极端重复内容。
- 包含提示注入、恶意链接或未知附件的输入。
- 超出语言、地域、时间或专业权限范围的输入。

## 9. 失败处理与恢复

1. 在小样本上构造可手算预期值
2. 检查 join 前后行数和唯一键
3. 对比独立口径或可信报表
4. 用 EXPLAIN 定位成本而非直接跑大查询
5. 结论失败时回退到描述性事实

### 9.1 标准失败响应

```text
状态：未完成/部分完成
失败阶段：{{stage}}
已确认内容：{{verified}}
未知或冲突：{{unknowns}}
没有执行的动作：{{not_done}}
需要补充：{{required_input}}
建议下一步：{{next_step}}
```

### 9.2 重试预算

- 格式失败可自动重试一次，并只修格式。
- 事实或语义失败不能靠原提示无限重试。
- 连续两轮同类失败应修改契约、拆分任务或升级人工。
- 每次重试保留输入版本和失败原因，防止选择性展示成功结果。

### 9.3 降级策略

- 从自动发布降级为草稿。
- 从完整答案降级为已证实字段。
- 从开放生成降级为封闭材料处理。
- 从执行动作降级为只读建议。

## 10. 隐私、安全与合规

### 10.1 坚持最小字段和聚合输出

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.2 低基数单元格做抑制或合并

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.3 禁止把原始个人数据送入提示

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.4 查询日志和导出受访问控制

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.5 决策模型检查代理变量与群体偏差

落实到数据流、权限、日志和保留策略中；仅写在提示里不能构成安全控制。

### 10.6 最小权限清单

- 模型只看到完成任务所需的最少字段。
- 工具只开放必要动作和参数范围。
- 高风险输出默认不自动发送或执行。
- 测试环境与生产环境隔离。
- 审计日志本身也按敏感数据保护。

## 11. 迭代策略

### 11.1 建立基线

1. 固定模型、参数、提示和数据版本。
2. 选取代表性正常样本与历史失败样本。
3. 先测初始提示，不只展示优化后结果。
4. 保存原始输出，避免事后改写证据。

### 11.2 单变量迭代

| 可改变量 | 适合解决 | 不适合解决 |
| --- | --- | --- |
| 补上下文 | 模型缺少事实或规则 | 规则本身冲突 |
| 补输出 schema | 格式漂移 | 事实来源不足 |
| 补少样本 | 边界判定不稳定 | 样本标签错误 |
| 拆分步骤 | 复合任务遗漏 | 下游无法验收 |
| 增加工具 | 需要实时/精确信息 | 权限治理缺失 |

### 11.3 错误分类

- E1 输入缺失：请求方未提供必要信息。
- E2 契约歧义：字段、标签或成功定义不清。
- E3 检索/工具失败：信息无法访问或工具报错。
- E4 推理/生成失败：已有信息未被正确使用。
- E5 验收失败：结果正确但格式或工作流不兼容。
- E6 治理失败：权限、隐私或合规控制不足。

### 11.4 停止条件

- 主要指标达到门槛且安全指标无回退。
- 边界集不再出现新的高严重度错误。
- 成本和延迟在预算内。
- 剩余风险有明确人工流程和责任人。

## 12. 评测设计

### 12.1 数据集分层

| 集合 | 目的 | 建议内容 |
| --- | --- | --- |
| 开发集 | 快速迭代 | 典型任务和已知错误 |
| 回归集 | 防止旧错复发 | 每类历史事故至少一例 |
| 边界集 | 验证拒绝与 unknown | 缺失、冲突、注入、超范围 |
| 盲测集 | 估计泛化 | 迭代者未见的真实分布 |
| 红队集 | 发现安全缺陷 | 越权、隐私、恶意输入 |

### 12.2 核心指标

- **M1 口径一致率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M2 查询正确率**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M3 扫描字节/分区数**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M4 重复计数检查**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M5 独立复算偏差**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M6 报表刷新时效**：定义分子、分母、排除项和目标阈值，避免只报平均分。
- **M7 结论校准度**：定义分子、分母、排除项和目标阈值，避免只报平均分。

### 12.3 量规示例

| 分数 | 正确性 | 完整性 | 可追溯性 | 安全性 |
| --- | --- | --- | --- | --- |
| 3 | 全部关键结论正确 | 无关键漏项 | 逐项可定位 | 无违规 |
| 2 | 轻微非关键错误 | 少量次要漏项 | 大部分可定位 | 低风险可修复 |
| 1 | 至少一项关键错误 | 明显漏项 | 证据弱或错配 | 需要人工阻断 |
| 0 | 结论不可用 | 任务未完成 | 无依据 | 严重违规 |

### 12.4 评审一致性

- 先用 10-20 个样本校准评审者。
- 为每个分数提供正例和反例。
- 记录争议项，不强行平均掩盖定义问题。
- 高风险样本采用双人独立评审。

### 12.5 线上监控

- 监控输入分布、未知率、人工改写率和升级率。
- 抽样复核成功输出，而不只看用户投诉。
- 模型或依赖升级后运行完整回归集。
- 指标突变时能回滚提示版本或关闭自动动作。

## 14. 练习

### 14.1 练习 1

订单表 join 订单项后 SUM(order_amount) 翻倍，如何修？

<details>
<summary>展开参考答案</summary>

先明确粒度；在订单粒度聚合或对订单项预聚合，检查 join 基数，不能简单用 DISTINCT 金额。

</details>

### 14.2 练习 2

只读分析为什么仍需安全限制？

<details>
<summary>展开参考答案</summary>

昂贵 SELECT 可造成成本和资源争用，也可能导出敏感数据；需分区过滤、LIMIT、超时和最小权限。

</details>

### 14.3 练习 3

相关性很强能否直接建议上线策略？

<details>
<summary>展开参考答案</summary>

不能自动推出因果。应给替代解释，并用实验、准实验或额外证据验证。

</details>

### 14.4 综合练习

为一个真实“数据分析、SQL、报表与决策支持”任务写一份输入输出契约。至少包含：非目标、未知行为、证据要求、失败升级和五条验收标准。

<details>
<summary>展开评分要点</summary>

优秀答案不是堆叠角色设定，而是让第三方能用固定样本和规则判断成功或失败。检查每个输出字段是否有来源、每个风险是否有外部控制、每个指标是否有阈值。

</details>

## 15. 快速复盘卡

| 阶段 | 必须回答的问题 |
| --- | --- |
| 需求 | 目标、受众、时效、非目标是什么 |
| 契约 | 输入缺失和输出未知如何表示 |
| 执行 | 模型可以看什么、推断什么、调用什么 |
| 验收 | 谁用什么证据判断正确 |
| 失败 | 何时重试、降级、拒绝或转人工 |
| 治理 | 如何最小化数据并追踪版本 |

::: tip 一句话原则
先锁定 schema、SQL dialect、指标口径和数据时间，再写查询。默认 read-only，限制扫描、行数、时间范围和成本，并用独立方法验证结果。
:::

## 学习目标

- 区分离线 A/B、在线 A/B、影子和小流量发布。
- 用单变量和配对实验建立归因。
- 建立常驻回归集与发布门禁。
- 固定 model、prompt、config、tools、retrieval。
- 记录可复现的运行清单。
- 为随机输出设计多次采样。
- 定义监控、停止和回滚条件。
- 处理供应商模型升级与数据漂移。

## 一、实验在优化闭环中的位置

```text
定义任务与约束
-> baseline
-> 分层测试集
-> 错误分类
-> 一次一个变量
-> 离线评测
-> 人工复核
-> 小流量上线
-> 监控回滚
```

实验管理连接离线改进和线上发布。

它回答三个问题：

1. 变化真的来自本次修改吗？
2. 变化是否足够稳定、有业务价值？
3. 出问题时能否迅速恢复已知状态？

## 二、四种比较方式

### 离线 A/B

同一冻结数据集上运行两个版本。

适合：

- 快速筛选。
- 错误定位。
- 低成本重复采样。
- 发布前门禁。

不能完整覆盖：

- 真实用户行为。
- 流量分布漂移。
- 下游系统反馈。
- 实际并发和限流。

### 影子测试

线上请求复制给候选版本，但候选结果不返回用户、不产生副作用。

适合：

- 观察真实输入。
- 测量延迟与成本。
- 检查工具参数。

必须禁止候选执行付款、发信、删除等副作用。

### 小流量发布

候选真实服务少量用户。

适合验证：

- 真实 task success。
- 用户行为。
- 端到端稳定性。
- 业务指标。

### 完全发布

只有在离线门禁、人工复核和小流量均通过后进行。

## 三、实验的最小单位

### 只改变一个变量

每次只改变：

- Prompt 文本。
- Model 版本。
- Temperature。
- Tool schema。
- Retrieval top-k。
- Reranker。
- 输出解析器。

其余保持一致。

### 为什么配置也算变量

以下变化足以改变结果：

- `temperature: 0 -> 0.2`。
- `max_output_tokens: 256 -> 512`。
- 工具描述措辞变化。
- 检索语料更新。
- 系统消息顺序变化。
- JSON schema 增加默认值。

### 多变量实验

若必须同时改变 A 和 B，至少运行：

| 组 | A | B |
|---|---|---|
| Baseline | 否 | 否 |
| A only | 是 | 否 |
| B only | 否 | 是 |
| A+B | 是 | 是 |

这能观察主效应和交互。

## 四、实验假设与预注册

### 实验卡模板

```markdown
# Experiment EXP-042

- 假设：增加退款/账单优先规则会改善边界切片
- 唯一变量：prompt rule R7
- Baseline：prompt 1.4.0
- Candidate：prompt 1.5.0-rc1
- 数据集：eval 3.2.0
- 主指标：refund recall
- 最小实际效应：+3pp
- 护栏：billing precision 下降不超过 1pp
- 硬门槛：S1/S2 零回归
- 采样：每样本 5 次
- 统计方法：按样本配对 bootstrap
- 人工复核：全部回归 + 关键切片 50 条
- 决策规则：区间下界 > 0 且护栏通过
```

先写决策规则，再看结果。

否则容易事后挑选对候选有利的指标。

## 五、离线 A/B 设计

### 配对原则

A 和 B 使用：

- 同一批输入。
- 同一参考答案。
- 同一 Rubric。
- 同一 judge 版本。
- 同一运行窗口。
- 相同采样次数。

### 运行顺序

避免所有 A 先跑、所有 B 后跑。

可按样本随机交错运行，以降低服务时间变化影响。

### 盲审

人工或 judge 不应知道：

- 哪个是 baseline。
- 哪个是候选。
- 团队预期。
- 版本名称。

成对 judge 还需交换答案位置。

## 六、回归测试体系

### 回归集来源

- 历史生产事故。
- 用户投诉。
- 开发中发现的失败。
- 安全红队样本。
- 高风险边界。
- 已修复 bug。
- 供应商升级差异。

### 每个回归样本需要

- 唯一 ID。
- 输入。
- 期望行为。
- 错误类别。
- 严重度。
- 加入原因。
- 来源版本。
- 适用范围。
- 最小判定规则。

### 回归集不是全部评测集

回归集会逐渐偏向历史失败。

因此同时维护：

- 代表性集。
- 挑战集。
- 回归集。
- 隐藏集。

### 删除回归样本

只有满足以下条件才考虑删除：

- 对应功能已永久下线。
- 任务契约明确变化。
- 样本标签被证实错误。
- 与其他样本完全重复。

删除必须记录理由，不能为提高分数删除。

## 七、发布门禁

### 示例门禁

```text
必须全部满足：
- S1/S2 回归数 = 0
- Macro F1 不下降
- 关键类 recall >= 0.95
- JSON valid rate >= 99.9%
- Groundedness >= 0.97
- Task success 的差值区间下界 >= 0
- 平均成本增长 <= 10%
- p95 延迟 <= 2.5 秒
- all_pass@5 >= baseline
```

### 硬门槛与软权衡

硬门槛不可用其他指标补偿。

例：隐私泄露不能用准确率提升抵消。

软指标可通过加权决策，但权重必须事先定义。

## 八、版本固定的完整范围

只保存 Prompt 文本远远不够。

### Model

- 供应商。
- 模型名称。
- 精确版本或快照。
- 区域和部署。
- API 版本。

### Prompt

- System prompt。
- Developer prompt。
- User template。
- Few-shot 示例。
- 模板渲染器版本。
- 内容 hash。

### Config

- temperature。
- top_p。
- max tokens。
- stop sequences。
- seed，如果支持。
- timeout。
- retry policy。

### Tools

- 工具名和描述。
- 参数 schema。
- 实现版本。
- 权限。
- 沙箱策略。
- 超时和重试。

### Retrieval

- 语料快照。
- chunker 版本。
- embedding 模型。
- 索引版本。
- 查询改写。
- top-k。
- reranker。
- 过滤条件。

### Evaluation

- 数据集版本。
- Rubric 版本。
- Judge 版本与配置。
- 评测代码版本。
- 采样次数。
- 统计方法。

## 十、Prompt 版本语义

可采用语义版本：

- MAJOR：任务契约或输出接口不兼容变化。
- MINOR：新增规则、示例或能力，接口兼容。
- PATCH：不改变意图的小修复。

但 Prompt 的微小措辞也可能大幅改变行为。

所以语义版本之外，始终保存内容 hash。

### Changelog 模板

```markdown
## 1.5.0 - 2026-08-03

### Changed
- 明确 refund 与 billing 的冲突优先级。

### Expected
- 提升 billing_refund_boundary recall。

### Risks
- 可能过度预测 refund。

### Evidence
- EXP-042，离线通过。
- 人工盲审 80 条，无 S1/S2 回归。
```

## 十一、标准库版本工具

```python
import hashlib
import json
from pathlib import Path


def sha256_text(text):
    return hashlib.sha256(text.encode("utf-8")).hexdigest()


def write_manifest(path, manifest):
    content = json.dumps(manifest, ensure_ascii=False, indent=2, sort_keys=True)
    Path(path).write_text(content + "\n", encoding="utf-8")


def verify_prompt(prompt_path, expected_hash):
    text = Path(prompt_path).read_text(encoding="utf-8")
    actual = sha256_text(text)
    if actual != expected_hash:
        raise RuntimeError(f"prompt hash mismatch: {actual}")
```

实际仓库还应依赖 Git 提交和制品存储，而非只靠文件名。

## 十二、随机输出的实验控制

即使设置 temperature=0，也要考虑非确定性。

### 重复采样

- 每样本固定 k 次。
- A/B 使用相同 k。
- 记录每次调用而非只留多数结果。
- 按样本计算一致率。
- 报告 `all_pass@k` 和平均通过率。

### 配对种子

若平台提供 seed，它有助于比较，但不保证跨模型、跨版本完全一致。

不要把 seed 当作版本固定的替代品。

### 置信区间

优先对 A/B 的配对差值构建区间。

避免只比较两个独立点估计。

## 十三、样本量与最小实际效应

实验前定义：

- 当前 baseline。
- 最小值得发布的提升。
- 可接受的误判风险。
- 关键切片所需样本。

统计显著不等于业务显著。

百万样本下 0.05 个百分点也可能显著，却不值得增加 20% 成本。

小样本下 5 个百分点可能不显著，却可能提示高风险问题。

### 小切片处理

- 报告原始计数。
- 给出置信区间。
- 合并必须有业务理由。
- 高风险样本进行人工审计。
- 不因“样本太少”忽略 S1。

## 十四、在线 A/B 随机化

### 随机化单位

按请求随机可能让同一用户前后体验不一致。

可选单位：

- 请求。
- 会话。
- 用户。
- 组织。
- 时间窗口。

通常按用户或会话保持粘性。

### 污染风险

- 用户跨设备进入不同组。
- 客服同时看到两个版本并调整行为。
- 缓存跨组共享。
- 检索索引在实验中途变化。
- 运营活动只影响一组。

### 分层随机

按以下维度平衡：

- 地区。
- 语言。
- 用户等级。
- 流量渠道。
- 历史活跃度。

不要在实验后随意改分层定义。

## 十五、小流量发布流程

示例：

1. 内部流量。
2. 1% 外部流量。
3. 5% 流量。
4. 20% 流量。
5. 50% 流量。
6. 100% 流量。

每一级都要满足：

- 最短观察时间。
- 最少样本量。
- 质量门槛。
- 成本和延迟门槛。
- 无严重事故。
- 人工抽查通过。

流量比例不是唯一条件。

低频风险需要足够时间才会出现。

## 十六、监控设计

### 系统指标

- QPS。
- 错误率。
- 超时率。
- 限流率。
- 重试率。
- p50/p95/p99 延迟。
- Token 与成本。

### 质量代理指标

- JSON valid rate。
- Schema valid rate。
- 拒答率。
- 工具成功率。
- 引用覆盖率。
- 用户重试率。
- 人工转接率。
- 投诉率。

代理指标可能被“优化”而失真。

因此定期抽样做人审。

### 分布漂移

监控：

- 标签分布。
- 输入长度。
- 语言比例。
- 新实体。
- 检索空结果率。
- 工具参数分布。

## 十七、停止与回滚

### 自动停止条件示例

- 任一 S1 事故。
- S2 率超过 baseline 指定阈值。
- JSON valid rate 低于 99.5%。
- p95 延迟超过 SLA 持续 10 分钟。
- 单请求成本增长超过 25%。
- 工具越权调用大于 0。

### 回滚对象

回滚必须覆盖整个版本束：

- Model。
- Prompt。
- Config。
- Tools。
- Retrieval。
- Parser。

只回滚 Prompt 可能留下不兼容 schema。

### 回滚演练

- 谁能触发？
- 需要审批吗？
- 多久生效？
- 缓存如何失效？
- 正在执行的工具任务如何停止？
- 回滚后如何确认恢复？

## 十八、供应商模型升级

“同名模型”可能在服务端变化。

应：

- 优先使用可固定快照。
- 订阅变更通知。
- 建立升级影子环境。
- 全量运行回归集。
- 对随机输出重复采样。
- 比较质量、成本和延迟。
- 保留旧版本回滚路径。

模型升级不是普通依赖 patch。

它可能改变所有输出行为。

## 二十一、常见误区

### 误区 1：线上直接 50/50

高风险变更应先离线、影子和小流量。

### 误区 2：实验期间更新知识库

retrieval 变化破坏归因。

### 误区 3：只保存 Prompt 名称

文件名不能证明内容相同。

### 误区 4：平均指标提升就发布

关键切片和硬门槛可能回归。

### 误区 5：没有最小观察时间

早停可能只捕获工作日或白天流量。

### 误区 6：用 any_pass@k 代表单次体验

统计口径与线上行为不匹配。

### 误区 7：只回滚 Prompt

版本束其他部分可能已不兼容。

### 误区 8：实验后挑指标

容易产生选择性报告。

### 误区 9：永不清理实验流量

长期分叉增加维护和审计风险。

### 误区 10：同名模型即同版本

供应商可能更新权重或服务实现。

## 二十三、练习

### 练习 1：识别变量

候选改了提示词并把 temperature 从 0 改为 0.3，能否归因？

<details>
<summary>参考答案</summary>

不能。

至少运行仅改提示词、仅改 temperature 和两者组合。

</details>

### 练习 2：回归集设计

一次生产事故来自工具在未确认时发出了邮件。怎样沉淀？

<details>
<summary>参考答案</summary>

创建高严重度回归样本，包含原输入、工具状态、期望“不调用发送工具”、判定规则和事故来源。

它应成为发布硬门槛，并在影子环境验证无副作用。

</details>

### 练习 3：版本缺口

已保存 model 和 prompt，但结果无法复现，还应检查什么？

<details>
<summary>参考答案</summary>

检查 config、tools、retrieval、parser、数据集、Rubric、judge、runner、区域和供应商服务快照。

</details>

### 练习 4：小流量回滚

候选质量提升但 p95 延迟连续越过 SLA，是否继续放量？

<details>
<summary>参考答案</summary>

不应。

延迟是预设护栏，应停止放量或回滚，定位 token、重试、工具或模型瓶颈。

</details>

### 练习 5：模型升级

供应商宣布同名模型升级，应直接接受吗？

<details>
<summary>参考答案</summary>

不应直接接受。

应冻结旧版本，候选版本跑完整离线、回归、影子和小流量流程，并比较成本、延迟与稳定性。

</details>

## 二十四、本章小结

受控发布依赖：

- 单变量假设。
- 配对离线评测。
- 常驻回归门禁。
- 完整版本束。
- 随机输出多次采样。
- 盲审与置信区间。
- 小流量和自动回滚。

固定的不只是 Prompt。

必须固定 `model + prompt + config + tools + retrieval + evaluator`。

## 1. 选书原则

书籍适合建立稳定的概念框架、案例组织和工程思维，但不适合充当最新 API reference。
模型、参数、上下文限制、structured output 和工具调用接口变化很快，模型特定细节必须以当前官方文档为准。

本页只核准确定的书名与作者；不确定的出版日期、ISBN、版次或页数不猜测。

## 2. 核心书目

### Prompt Engineering for Generative AI

- 书名：*Prompt Engineering for Generative AI*
- 作者：James Phoenix、Mike Taylor
- 出版方：O'Reilly Media
- 官方页：[O'Reilly: Prompt Engineering for Generative AI](https://www.oreilly.com/library/view/prompt-engineering-for/9781098153427/)

适合读者：

- 已会使用生成式 AI，希望系统理解提示设计的人；
- 需要把文本、图像等生成任务组织成可复用模式的开发者；
- 希望从零散技巧走向工作流的人。

阅读重点：

- 提示词的组成与迭代；
- 任务分解与示例；
- 不同生成任务的设计方式；
- 从实验到应用的思考。

阅读评价：

该书适合建立广义生成式 AI 的提示设计视角。
阅读时应把具体模型语法视为示例，而不是永久接口。
每章最好转化成一个带基线、数据集和指标的小实验。

实践作业：

1. 选择分类、抽取和生成三个任务。
2. 为每个任务建立最小 prompt。
3. 添加边界示例和结构化输出。
4. 用同一评测集比较版本。
5. 记录成本、延迟与失败类型。

### Prompt Engineering for LLMs

- 书名：*Prompt Engineering for LLMs*
- 作者：John Berryman、Albert Ziegler
- 出版方：O'Reilly Media
- 官方页：[O'Reilly: Prompt Engineering for LLMs](https://www.oreilly.com/library/view/prompt-engineering-for/9781098156145/)

适合读者：

- 软件工程师和 AI 应用开发者；
- 希望理解 LLM 行为、提示模式与应用构建关系的人；
- 正在设计检索、工具或复杂工作流的人。

阅读重点：

- 从语言模型能力边界理解提示；
- 用上下文、示例和结构约束任务；
- 将 prompt 放入应用架构而非孤立优化；
- 识别脆弱模式和评测需求。

阅读评价：

书名中的 “for LLMs” 提醒读者关注模型行为与应用契约的关系。
将案例与当前模型 API 对照阅读，尤其核对工具调用、上下文和输出约束。
不要把书中某个技巧的效果跨模型直接外推。

实践作业：

1. 选一个真实业务任务写输入/输出契约。
2. 建立 zero-shot 基线。
3. 加入 few-shot 和明确失败状态。
4. 加入 schema 验证。
5. 构造 prompt injection 和信息不足样本。
6. 写发布与回滚计划。

### The Art of Prompt Engineering with ChatGPT

- 书名：*The Art of Prompt Engineering with ChatGPT*
- 作者：Nathan Hunter
- 作者网站：[Nathan Hunter](https://nathanhunter.com/)

适合读者：

- 希望从 ChatGPT 交互实践理解提示表达的人；
- 非专业开发者、内容工作者和早期学习者；
- 需要大量练习来形成迭代习惯的人。

阅读重点：

- 明确目标和上下文；
- 通过约束与迭代改善输出；
- 观察不同表达对结果的影响；
- 建立个人使用模式。

阅读评价：

这本书可用于交互层面的实践补充。
ChatGPT 产品行为和模型会更新，因此具体界面或技巧要以当前产品与官方文档为准。
对于生产系统，还必须补充 schema、eval、安全、权限、日志和回滚知识。

实践作业：

1. 将一个日常提示改成任务契约。
2. 写出成功、失败和边界示例。
3. 比较交互式输出与 API structured output。
4. 记录哪些改进可复现，哪些只发生一次。

## 3. 三本书如何选择

| 需求 | 首选 | 补充 |
|---|---|---|
| 广义生成式 AI 提示实践 | Phoenix / Taylor | 官方平台文档 |
| LLM 应用与工程视角 | Berryman / Ziegler | RAG、Agent、安全文档 |
| ChatGPT 交互入门 | Nathan Hunter | 当前 ChatGPT 官方说明 |
| 生产系统上线 | 三本都不是单独答案 | OWASP、NIST、官方 API、评测 |

## 4. 推荐阅读顺序

### 开发者路线

1. 先读目标模型当前官方 prompting 和 API 文档。
2. 读 *Prompt Engineering for LLMs* 建立应用视角。
3. 用 [通用任务提示词模板](/kb/ai/提示词工程/模板库/01-通用任务提示词模板/) 实现三个小任务。
4. 读 *Prompt Engineering for Generative AI* 扩展任务模式。
5. 学习 RAG、Agent、安全与评测。
6. 用真实项目完成一次灰度与回滚。

### 产品与内容路线

1. 读 *The Art of Prompt Engineering with ChatGPT* 形成迭代习惯。
2. 完成 DeepLearning.AI 短课。
3. 读 *Prompt Engineering for Generative AI*。
4. 学习需求评审和评测模板。
5. 与工程、安全共同定义生产边界。

### 架构与安全路线

1. 快速浏览三本书的任务与应用章节。
2. 精读 OWASP LLM01:2025。
3. 精读 NIST AI RMF 和 GenAI Profile。
4. 研究 RAG、ReAct 和工具调用官方文档。
5. 完成 threat model、eval gates、SLO、fallback 和 rollback。

## 5. 四周阅读计划

### 第 1 周：任务契约

目标：不再把提示词理解为“神奇措辞”。

任务：

- 阅读一本核心书的入门章节；
- 阅读当前官方 prompting guide；
- 写分类、抽取、摘要三个模板；
- 为每个模板写 20 个样本；
- 记录失败分类。

产出：

- prompt v1；
- 输入/输出 schema；
- 基线评测报告。

### 第 2 周：上下文与证据

目标：理解 context、ICL 和 RAG 的差异。

任务：

- 阅读 RAG 原始论文概要；
- 建立带 chunk ID 的小知识库；
- 实现引用存在性验证；
- 加入证据不足 abstain；
- 加入恶意文档。

产出：

- 检索评测；
- grounding 评测；
- injection 回归样本。

### 第 3 周：工具与安全

目标：让模型只能提出受控候选动作。

任务：

- 阅读 ReAct 论文；
- 设计一个只读工具 schema；
- 添加权限、预算和停止条件；
- 添加恶意工具结果；
- 设计人工审批界面。

产出：

- 状态机；
- 工具契约；
- 红队结果。

### 第 4 周：发布工程

目标：完成可观测和可回滚发布。

任务：

- 固定 model/prompt/params/schema/tools/retriever；
- 建立 eval gates；
- 定义 SLO；
- 演练 provider fallback；
- 演练完整 rollback。

产出：

- Release manifest；
- dashboard；
- go/no-go 记录。

## 8. 不要怎样读书

- 不抄“万能 prompt”而忽略任务定义；
- 不因为作者示例成功就跳过评测；
- 不把旧模型现象当成当前 API 保证；
- 不用角色修辞代替证据与 schema；
- 不把 CoT 当成必须公开的输出；
- 不把 ReAct 当成无限自主循环；
- 不把提示词当成权限边界；
- 不猜测书籍出版信息或作者观点；
- 不只读书而不运行实验。

## 9. 书籍之外必须补充的主题

### 官方 API

- 当前模型能力；
- structured output；
- tool calling；
- token 与速率限制；
- 数据使用与保留；
- 错误与重试语义。

### 评测

- 数据集版本；
- 确定性断言；
- 人工 rubric；
- 模型评审器校准；
- 线上漂移；
- 子群与安全门禁。

### 安全

- OWASP LLM01:2025；
- direct/indirect injection；
- 最小权限；
- 输出验证；
- 人工批准；
- 日志、红队和事件响应。

### 运维

- 完整配置版本化；
- SLO 与成本预算；
- fallback；
- rollback；
- on-call 与事故演练。

## 10. 从阅读到项目

选题建议：企业政策问答。

第一版：

- 静态证据；
- 引用 ID；
- schema 输出；
- 明确 abstain。

第二版：

- 加入检索与 ACL；
- 加入冲突和时效；
- 加入恶意文档；
- 评测 grounding。

第三版：

- 加只读状态查询工具；
- 工具 schema 和状态机；
- 预算与停止条件；
- 恶意工具结果测试。

第四版：

- 版本化完整配置；
- 灰度、SLO 和 dashboard；
- provider fallback；
- rollback 演练。

## 11. 读书会问题

1. 作者的主张适用于哪些模型和任务？
2. 示例是否有清晰基线？
3. 结果是否可复现？
4. 技巧增加了多少 token、延迟和成本？
5. 失败时的最坏后果是什么？
6. 哪些控制必须在应用层实现？
7. 当前官方文档是否已改变接口或建议？
8. 如何把主张转化为回归样本？

## 12. 结论

1. 三本核心书用于建立体系和练习方法。
2. 书籍中的模型特定细节以当前官方文档为准。
3. 任何技巧都要通过目标任务的固定评测集验证。
4. 生产能力来自 prompt、context、schema、tools、retriever、权限和运维的组合。
5. 安全不能靠书中的一句“防注入提示词”解决。
6. 最有效的阅读结果不是更多模板，而是一套可复现的实验与发布流程。

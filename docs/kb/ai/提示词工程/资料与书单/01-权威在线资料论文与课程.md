## 1. 使用说明

本页优先收录官方文档、原始论文、标准框架和长期维护的公开课程。
链接与 API 会变化，阅读时记录访问日期、页面版本、模型版本和示例所用 API。

不要把任何单一厂商的提示词技巧当成跨模型永久规律。
先用当前目标模型和当前 API 做小规模评测，再进入生产回归集。

## 2. OpenAI 官方文档

### OpenAI Prompting

- 地址：[Prompting](https://platform.openai.com/docs/guides/prompting)
- 类型：官方指南。
- 适合：理解当前 OpenAI API 中提示词组织、复用和优化方式。
- 优点：与产品能力和平台实践直接对应。
- 局限：页面、模型名称、推荐 API 和参数可能变化。
- 使用建议：注明访问日期；实现前检查当前模型页面、迁移指南和 API reference。

### OpenAI API Documentation

- 地址：[OpenAI API Documentation](https://platform.openai.com/docs/overview)
- 类型：官方 API 文档入口。
- 适合：核对模型能力、structured output、tool calling、限制与安全行为。
- 优点：实现依据优先级最高。
- 局限：不同模型、端点和 SDK 的接口可能不同；旧博客示例可能已过时。
- 使用建议：锁定实际 model ID、SDK 版本和 API 日期，不依赖 `latest` 心智模型。

### OpenAI Cookbook

- 地址：[OpenAI Cookbook](https://cookbook.openai.com/)
- 仓库：[openai/openai-cookbook](https://github.com/openai/openai-cookbook)
- 类型：官方示例与实践集合。
- 适合：评测、RAG、structured output、工具调用和生产模式原型。
- 优点：示例具体，可快速验证 API。
- 局限：Cookbook 是示例，不是稳定 API 契约；访问路径、模型和 API 可能变化。
- 使用建议：先核对发布时间、依赖版本和当前官方 API reference，再移植到生产。

### OpenAI Evals

- 地址：[Evals design guide](https://platform.openai.com/docs/guides/evals)
- 类型：官方评测指南。
- 适合：建立任务特定评测、数据集和持续回归。
- 评价：比凭感觉改 prompt 更接近工程实践；具体平台接口仍需以当前页面为准。

## 8. 综合综述

### The Prompt Report

- 题目：*The Prompt Report: A Systematic Survey of Prompting Techniques*
- arXiv：[2406.06608](https://arxiv.org/abs/2406.06608)
- 指定版本：[v6](https://arxiv.org/abs/2406.06608v6)
- 类型：系统性综述与分类。
- 价值：提供广泛术语、技术分类和文献入口，适合建立技术谱系。
- 局限：覆盖面广不等于每项技术都有同等证据；模型更新会改变相对效果。
- 阅读方法：先看分类图和术语，再按任务追原始论文；引用时注明 v6。

## 9. 关键论文

### Chain-of-Thought Prompting

- 题目：*Chain-of-Thought Prompting Elicits Reasoning in Large Language Models*
- 作者：Jason Wei 等。
- arXiv：[2201.11903](https://arxiv.org/abs/2201.11903)
- 核心贡献：展示在若干算术、常识和符号推理任务中，通过中间推理示例改善大型模型表现。
- 重要边界：实验结论依赖模型规模、任务和评测设置。
- 工程解释：可研究“任务分解和中间计算”，但生产系统不必要求向用户暴露私有 chain-of-thought。
- 推荐验证：比较直接回答、少样本示例、结构化中间结果与外部计算器。

### ReAct

- 题目：*ReAct: Synergizing Reasoning and Acting in Language Models*
- 作者：Shunyu Yao 等。
- arXiv：[2210.03629](https://arxiv.org/abs/2210.03629)
- 核心贡献：研究将推理轨迹与动作交错，用环境反馈支持问答和交互决策。
- 价值：启发“观察、决策、动作、新观察”的 Agent 循环。
- 工程边界：ReAct 是研究模式，不是要求产品暴露私有推理。
- 生产要求：工具 schema、权限、前置条件、幂等、预算、停止条件、审批和状态机仍由应用保证。

### Tree of Thoughts

- 题目：*Tree of Thoughts: Deliberate Problem Solving with Large Language Models*
- 作者：Shunyu Yao 等。
- arXiv：[2305.10601](https://arxiv.org/abs/2305.10601)
- 核心贡献：把问题求解建模为对多个“thought”候选的搜索、评估和回溯。
- 适合研究：可明确搜索空间和验证函数的组合问题。
- 局限：推理调用与成本显著增加，评估器可能偏置；不应默认用于每个任务。
- 工程建议：优先比较确定性算法、单次生成和较小搜索预算。

## 10. 安全框架

### OWASP GenAI LLM Top 10

- 项目入口：[OWASP GenAI Security Project](https://genai.owasp.org/)
- Top 10：[OWASP Top 10 for LLM Applications](https://genai.owasp.org/llm-top-10/)
- LLM01:2025：[Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)
- 类型：开放安全风险框架。
- 价值：用于 threat model、安全控制、红队和评审清单。
- 核心认识：直接和间接 prompt injection 都可能导致非预期行为；纯提示词防护不是万无一失。
- 工程落地：隔离不可信内容、最小权限、输出验证、人工批准、监控和对抗测试。
- 注意：OWASP 页面和版本可能更新；审计材料应注明使用的是 LLM01:2025 还是后续版本。

### NIST AI Risk Management Framework

- AI RMF 1.0：[NIST AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework)
- PDF：[Artificial Intelligence Risk Management Framework (AI RMF 1.0)](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.100-1.pdf)
- Playbook：[NIST AI RMF Playbook](https://airc.nist.gov/AI_RMF_Knowledge_Base/Playbook)
- 类型：自愿性风险管理框架。
- 核心函数：Govern、Map、Measure、Manage。
- 价值：把模型评测连接到组织治理、责任、风险接受和持续管理。
- 局限：它不是某个 LLM API 的技术实现手册，也不替代适用法律和行业要求。

### NIST Generative AI Profile

- 地址：[NIST AI 600-1, Generative Artificial Intelligence Profile](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)
- 类型：AI RMF 的生成式 AI 配套 profile。
- 适合：识别生成式 AI 特有风险和管理行动。
- 使用建议：与组织已有安全、隐私和供应商风险流程结合。

## 11. RAG 与检索补充

### Retrieval-Augmented Generation 原始论文

- 题目：*Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks*
- arXiv：[2005.11401](https://arxiv.org/abs/2005.11401)
- 价值：理解 RAG 研究起点和参数化/非参数化记忆组合。
- 边界：现代生产 RAG 的 chunking、权限、引用、安全和可观测性远超原始论文范围。

### BEIR

- 题目：*BEIR: A Heterogeneous Benchmark for Zero-shot Evaluation of Information Retrieval Models*
- arXiv：[2104.08663](https://arxiv.org/abs/2104.08663)
- 价值：理解检索评测跨数据集泛化和 nDCG 等指标。
- 边界：企业 RAG 仍需自己的权限、时效和真实查询评测集。

## 12. 工具与结构化输出阅读顺序

1. 阅读目标 provider 当前 API reference。
2. 确认模型是否支持原生 tool calling 和 structured output。
3. 明确 schema 支持子集与限制。
4. 查看官方最小示例。
5. 添加服务端 schema 与业务验证。
6. 添加权限、幂等、预算和审批。
7. 构造错误、超时、恶意工具结果测试。
8. 记录 model/prompt/params/schema/tools 全版本。

## 16. 推荐学习路线

### 第一阶段：API 与任务契约

- OpenAI/Anthropic/Google/Microsoft/AWS 中选择实际平台的当前官方文档；
- DeepLearning.AI 短课完成基础练习；
- 用 schema 实现分类和抽取。

### 第二阶段：评测

- 阅读各厂商 eval 指南；
- 建立 50 至 200 条真实任务集；
- 加入正常、边界、不可回答和恶意输入；
- 对比基线，而非只看最好样本。

### 第三阶段：RAG 与 Agent

- 阅读 RAG 和 ReAct 原始论文；
- 同时学习 [RAG提示词与基于证据的回答](/kb/ai/提示词工程/工程化与安全/01-RAG提示词与基于证据的回答/)；
- 同时学习 [工具调用Agent提示词与状态机](/kb/ai/提示词工程/工程化与安全/02-工具调用Agent提示词与状态机/)。

### 第四阶段：安全与治理

- 阅读 OWASP LLM01:2025；
- 阅读 NIST AI RMF 和 GenAI Profile；
- 完成 threat model、red team 和 incident drill。

## 17. 资料使用原则

1. 当前官方 API 文档优先于旧教程。
2. 原始论文优先于二手总结。
3. 论文实验结论不能自动等同于生产收益。
4. 厂商特定技巧必须在目标模型上复测。
5. Prompt 技巧不能替代权限、隔离和验证。
6. 记录访问日期和版本，防止不可复现。
7. 最终判断来自任务评测和线上监控。

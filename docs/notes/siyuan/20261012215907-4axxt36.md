为创建和查询任务写自动化测试，再区分开发启动与生产运行，形成可以重复验证的接口交付流程。

## 回到第二章的任务接口

本章在第二章的 ​`main.py` 旁创建测试文件，不使用第三章的模块化分页项目。先安装测试依赖：

```bash
python -m pip install pytest httpx2
```

本文示例已在 FastAPI 0.137.1、Starlette 1.3.1、Pydantic 2.13.4 环境验证；测试传输采用 Starlette 当前使用的 HTTPX2。

创建 ​`test_main.py`：

```python
import pytest
from fastapi.testclient import TestClient
from main import app, tasks

client = TestClient(app)

@pytest.fixture(autouse=True)
def clear_tasks():
    tasks.clear()
    yield
    tasks.clear()

def test_create_and_read():
    response = client.post("/tasks", json={"title": "学习 FastAPI"})
    assert response.status_code == 201
    task = response.json()
    assert task["done"] is False
    assert client.get(f"/tasks/{task['id']}").json() == task

def test_invalid_title():
    assert client.post("/tasks", json={"title": ""}).status_code == 422

def test_unknown_task():
    assert client.get("/tasks/999").status_code == 404

def test_invalid_id():
    assert client.get("/tasks/0").status_code == 422
```

执行：

```bash
python -m pytest -q
```

四个测试分别覆盖正常创建与读取、请求体校验、资源不存在，以及路径参数校验。夹具会清空内存任务表，使不同测试之间不共享任务数据；测试读取创建结果中的 ID，不依赖固定编号。

## 如何理解这些测试

`TestClient` 直接向应用发送测试请求，无需先启动一个监听端口的服务器。这里没有启动资源的生命周期逻辑；以后加入数据库初始化等操作时，可按官方文档使用上下文管理器运行客户端，并为测试替换依赖。

接口改动后先运行测试，再手动打开 ​`/docs` 验证使用体验。业务规则增加时，把对应成功与失败情况补成测试。

## 开发启动与生产运行

开发时使用：

```bash
fastapi dev main.py
```

部署到服务器时可使用：

```bash
fastapi run main.py --host 0.0.0.0 --port 8000
```

生产运行不使用开发热重载。这条命令只是启动进程；完整部署还需要结合运行环境处理 HTTPS、进程重启、配置与持久化。任务表仍在内存里时，重启或增加进程都会影响数据，应先接入持久化存储。

依赖注入解决的是“这个处理函数需要什么，以及这些东西由谁准备”。它不只是把数据库会话传进来，也可以承载分页参数、当前用户、配置、权限判断和可替换的外部客户端。

## 从函数依赖开始

```python
from dataclasses import dataclass
from typing import Annotated

from fastapi import Depends, Query


@dataclass
class PageParams:
    limit: int
    offset: int


def pagination(
    limit: Annotated[int, Query(ge=1, le=100)] = 20,
    offset: Annotated[int, Query(ge=0)] = 0,
) -> PageParams:
    return PageParams(limit=limit, offset=offset)


PageDep = Annotated[PageParams, Depends(pagination)]


@app.get("/tasks")
def list_tasks(page: PageDep) -> dict:
    return {"limit": page.limit, "offset": page.offset}
```

`Depends(pagination)`​ 会先解析 ​`pagination` 的参数，再把返回值传给路由。依赖可以继续依赖其他依赖，FastAPI 会按拓扑顺序解析。

## yield 依赖与会话生命周期

数据库会话是最典型的 ​`yield` 依赖：

```python
from collections.abc import Generator

from fastapi import Request
from sqlalchemy.orm import Session


def get_db(request: Request) -> Generator[Session, None, None]:
    factory = request.app.state.session_factory
    with factory() as session:
        try:
            yield session
        except Exception:
            session.rollback()
            raise
```

请求结束后，​`with`​ 块关闭会话；异常时先回滚。这里**不**在依赖里统一 ​`commit`，而是让路由或服务层决定事务边界：一个请求可能需要多次写入、也可能需要调用外部系统后再提交。统一在依赖里提交，会让“什么时候提交”变得隐式。

如果选择 unit-of-work 模式，也可以在 ​`yield` 后提交，但要在项目内保持一致，并为异常路径写测试。

## 类依赖

当依赖需要保存状态或多个方法时，用类：

```python
class Pagination:
    def __init__(
        self,
        limit: Annotated[int, Query(ge=1, le=100)] = 20,
        offset: Annotated[int, Query(ge=0)] = 0,
    ) -> None:
        self.limit = limit
        self.offset = offset

    @property
    def window(self) -> tuple[int, int]:
        return self.offset, self.offset + self.limit


@app.get("/tasks")
def list_tasks(page: Annotated[Pagination, Depends()]) -> dict:
    start, end = page.window
    return {"start": start, "end": end}
```

`Depends()` 不传参数时，FastAPI 会用类本身作为依赖，并解析构造函数的参数。

## 依赖缓存与 use_cache

同一个请求里多次 ​`Depends(get_current_user)`，默认只执行一次，结果会被缓存。这对数据库查询和令牌解析很重要。

如果某个依赖每次都需要重新计算，例如生成一次性随机值，可以关闭缓存：

```python
from uuid import uuid4


def request_nonce() -> str:
    return uuid4().hex


NonceDep = Annotated[str, Depends(request_nonce, use_cache=False)]
```

不要为了“避免缓存”而滥用 ​`use_cache=False`；大多数依赖在同一请求内应该保持一致。

## 在测试里替换依赖

依赖注入最大的收益之一是可替换：

```python
def override_db():
    with TestSession() as session:
        yield session


app.dependency_overrides[get_db] = override_db
```

测试结束后清理：

```python
app.dependency_overrides.clear()
```

这比 monkeypatch 全局变量更明确，也不会污染其他测试。第 17 章会用临时 SQLite 数据库完整演示。

## 依赖的边界

- 依赖适合准备请求上下文，不适合承载大段业务逻辑。
- 依赖可以抛 ​`HTTPException`，例如未登录返回 401。
- 依赖失败会阻止路由执行，这是权限校验的理想位置。
- 避免在依赖里做不可回滚的外部副作用。
- 依赖图过深会难以排障；三层以内通常足够。

列表接口最容易写，也最容易在数据量上来后变慢。分页、过滤、计数和仓储层不是“架构洁癖”，而是把查询边界和响应契约固定下来，避免每个路由各写一套 SQL。

## 分页契约

先定义稳定的响应：

```python
class TaskPage(BaseModel):
    items: list[TaskPublic]
    total: int
    limit: int
    offset: int
```

对应的查询参数：

```python
class PageParams(BaseModel):
    limit: int = Field(default=20, ge=1, le=100)
    offset: int = Field(default=0, ge=0)
```

`limit`​ 必须有上限。没有上限的接口会被一次请求拖垮数据库，也会让响应体不可控。​`total`​ 让前端能显示页数，但大表上的 ​`COUNT(*)` 可能很贵；数据量很大时改用近似计数或游标分页。

## 过滤与索引

```python
filters = [Task.owner_id == owner_id]
if q:
    filters.append(Task.title.ilike(f"%{q}%"))
if done is not None:
    filters.append(Task.done == done)
```

`ilike('%keyword%')` 前面的通配符会让普通 B-Tree 索引失效。数据量上来后，考虑：

- 前缀搜索：​`title.ilike(f"{q}%")`，可走索引。
- PostgreSQL ​`pg_trgm` 或全文检索。
- 独立的搜索服务。

不要为了“支持搜索”在应用层把所有任务取出来再用 Python 过滤。

## 仓储层

把查询集中到一个对象里，路由只负责 HTTP：

```python
from sqlalchemy import func, select
from sqlalchemy.orm import Session


class TaskRepository:
    def __init__(self, session: Session) -> None:
        self.session = session

    def list_for_owner(
        self,
        owner_id: int,
        *,
        limit: int,
        offset: int,
        q: str | None = None,
        done: bool | None = None,
    ) -> tuple[list[Task], int]:
        filters = [Task.owner_id == owner_id]
        if q:
            filters.append(Task.title.ilike(f"%{q}%"))
        if done is not None:
            filters.append(Task.done == done)

        total = self.session.scalar(
            select(func.count()).select_from(Task).where(*filters)
        ) or 0
        items = list(
            self.session.scalars(
                select(Task)
                .where(*filters)
                .order_by(Task.id.desc())
                .limit(limit)
                .offset(offset)
            )
        )
        return items, total

    def get_owned(self, task_id: int, owner_id: int) -> Task | None:
        return self.session.scalar(
            select(Task).where(Task.id == task_id, Task.owner_id == owner_id)
        )

    def add(self, task: Task) -> Task:
        self.session.add(task)
        self.session.commit()
        self.session.refresh(task)
        return task
```

路由：

```python
@router.get("", response_model=TaskPage)
def list_tasks(
    db: DbSession,
    user: CurrentUser,
    page: Annotated[PageParams, Query()],
    q: Annotated[str | None, Query(max_length=100)] = None,
    done: bool | None = None,
) -> TaskPage:
    repo = TaskRepository(db)
    items, total = repo.list_for_owner(
        user.id, limit=page.limit, offset=page.offset, q=q, done=done
    )
    return TaskPage(items=items, total=total, limit=page.limit, offset=page.offset)
```

示例把 ​`commit()`​ 放在仓储的 ​`add()` 里。如果项目采用服务层统一管理事务，应把提交上移，并让所有写接口遵守同一约定；不要有的仓储提交、有的路由提交。

仓储层不是必须的。小项目可以直接在路由里写 ​`select`；当查询开始复用、需要单元测试或要替换数据源时，再引入这一层。不要为了模式而模式。

## 游标分页

`OFFSET` 越大越慢，而且并发插入会导致重复或漏项。稳定排序的游标分页：

```python
@router.get("/tasks/keyset")
def list_keyset(
    db: DbSession,
    user: CurrentUser,
    cursor: int | None = None,
    limit: Annotated[int, Query(ge=1, le=100)] = 20,
) -> dict:
    stmt = select(Task).where(Task.owner_id == user.id).order_by(Task.id.desc()).limit(limit + 1)
    if cursor is not None:
        stmt = stmt.where(Task.id < cursor)
    rows = list(db.scalars(stmt))
    has_more = len(rows) > limit
    rows = rows[:limit]
    return {
        "items": [TaskPublic.model_validate(row) for row in rows],
        "next_cursor": rows[-1].id if has_more and rows else None,
    }
```

游标必须基于唯一且稳定的排序键，通常是 ​`(created_at, id)`​。只按 ​`created_at` 排序时，同一时间的多条记录可能跳项。

## N+1 与预加载

如果每个任务都要显示所有者邮箱，逐个访问 ​`task.owner` 会产生 N+1 查询。同步会话用：

```python
from sqlalchemy.orm import selectinload

stmt = select(Task).options(selectinload(Task.owner)).where(Task.owner_id == user.id)
```

异步会话尤其要显式预加载，否则隐式懒加载会报错。先看查询日志，再决定是否优化；不要凭感觉加 ​`joinedload`。

## 响应序列化

`TaskPage.items`​ 使用 ​`TaskPublic`​，每个元素都按响应模型过滤字段。如果直接返回 ORM 对象列表，FastAPI 仍会尝试序列化，但容易把内部字段带出去。列表接口也要声明 ​`response_model`。

## 练习

1. 给分页增加 ​`created_after` 过滤。
2. 用 ​`EXPLAIN`​ 比较 ​`ilike('%x%')` 和前缀搜索的执行计划。
3. 把游标改成 ​`(created_at, id)` 组合游标。
4. 写一个仓储层单元测试，使用内存 SQLite 和 ​`StaticPool`。

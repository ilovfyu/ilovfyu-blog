有些工作不需要让客户端等待：发送通知、写审计日志、生成缩略图。有些响应则要持续输出：大文件下载、进度流、Server-Sent Events。两类需求都涉及“响应已经返回，但工作还没结束”，边界必须说清楚。

## BackgroundTasks 的边界

```python
from fastapi import BackgroundTasks


def send_notification(email: str, title: str) -> None:
    # 真实项目里应调用邮件服务或消息队列
    print(f"notify {email}: {title}")


@router.post("/tasks/{task_id}/remind", status_code=202)
def remind(
    task_id: int,
    background: BackgroundTasks,
    db: DbSession,
    user: CurrentUser,
) -> dict:
    task = get_owned_task(task_id, user.id, db)
    background.add_task(send_notification, user.email, task.title)
    return {"status": "scheduled"}
```

`BackgroundTasks` 在响应发送后、同一进程内执行。它适合短小、可丢失、无需重试的任务。不适合：

- 支付、发券、扣库存等必须成功的工作。
- 需要重试、延迟、定时或跨进程协调的任务。
- 耗时很长的 CPU/IO 任务，会占用 worker。
- 需要保证执行一次的任务。

这些场景应使用 Celery、RQ、Arq、Dramatiq 或云队列。应用只负责把消息可靠地写入队列，再由独立 worker 消费。

## 流式下载

不要把大文件一次性读进内存：

```python
from fastapi.responses import FileResponse, StreamingResponse


@router.get("/files/{file_id}")
def download(file_id: str) -> FileResponse:
    path = safe_path_for(file_id)
    return FileResponse(path, filename="report.pdf", media_type="application/pdf")


@router.get("/exports")
def export() -> StreamingResponse:
    def rows():
        yield "id,title\n"
        for task in iter_tasks():
            yield f"{task.id},{task.title}\n"

    return StreamingResponse(
        rows(),
        media_type="text/csv",
        headers={"Content-Disposition": 'attachment; filename="tasks.csv"'},
    )
```

同步生成器会在线程池中执行；异步生成器用 ​`async def`​ 加 ​`yield`。无论哪种，都要处理客户端断开：生成器被取消时释放文件句柄和数据库游标。

## Server-Sent Events

SSE 是单向的服务器到客户端流，基于普通 HTTP，适合通知、日志、进度：

```python
import asyncio
import json

from fastapi import Request
from fastapi.responses import StreamingResponse


@router.get("/events")
async def events(request: Request) -> StreamingResponse:
    async def stream():
        for index in range(3):
            if await request.is_disconnected():
                break
            payload = json.dumps({"seq": index, "message": "tick"}, ensure_ascii=False)
            yield f"event: tick\ndata: {payload}\n\n"
            await asyncio.sleep(1)
        yield "event: done\ndata: {}\n\n"

    return StreamingResponse(
        stream(),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "Connection": "keep-alive",
            "X-Accel-Buffering": "no",
        },
    )
```

事件格式：

```text
event: tick
data: {"seq":0,"message":"tick"}

```

每条事件以空行结束。​`id:`​ 可用于断线重连，​`retry:`​ 建议客户端重连间隔。浏览器端用 ​`EventSource`​ 消费；它不能自定义 ​`Authorization` 头，需要 Cookie 或短期查询令牌，注意日志泄漏风险。

## SSE 的生产注意事项

- 反向代理可能缓冲响应。Nginx 需要关闭 ​`proxy_buffering`​，或设置 ​`X-Accel-Buffering: no`。
- 连接可能被负载均衡器在空闲一段时间后关闭；定期发送注释行 ​`: ping\n\n` 作为心跳。
- 客户端断开后要停止生成，避免后台任务无限运行。
- 每个连接都会占用一个 worker 连接槽；长连接数量要和 worker/代理容量匹配。
- 压缩可能让流式输出失去实时性；对 ​`text/event-stream` 谨慎启用 gzip。
- JSON 中的 ​`NaN`​、​`Infinity` 不是合法 JSON。FastAPI 0.143.3 修复了 JSONL 和 SSE 流中的非有限浮点序列化，但业务层仍应避免输出非有限值。

## 流式响应的错误处理

响应头一旦发送，就不能再改成 500。流开始前的错误应正常抛出；流开始后的错误只能在事件里表达：

```python
yield f"event: error\ndata: {json.dumps({'message': '生成失败'})}\n\n"
```

不要伪造一个 200 的成功事件来掩盖失败。客户端需要能区分“正常结束”和“中途失败”。

> 一句话总结：3.15 是「写起来更顺」的一版——`lazy import` 让启动变快，`frozendict` 和 `sentinel` 补上了两个长期靠约定解决的坑，UTF-8 成为默认编码；同时性能分析换成了专业的 `profiling` 包，采样分析器 Tachyon 可以直接挂到线上进程上看。

## 版本速览

|项目|内容|
| ------------| ----------------------------------------------------------------|
|发布时间|2026 年 10 月 9 日|
|上一个版本|3.14|
|维护节奏|常规修复约 2 年，之后继续做安全修复|
|核心主题|惰性导入、冻结字典、哨兵、UTF-8 默认、推导式解包、profiling 包|
|升级成本|偏低，但有编码行为和 `.pth` 启动文件的坑要检查|

3.15 没有 3.14 那种「一门新语法」的冲击感，但几处改动会实打实地改变你写代码的习惯：

- **启动更快**：`lazy import` 让你能继续把 import 写在文件顶部，又不用为没用到的模块买单。
- **少踩两个老坑**：`frozendict` 替代「dict + 自觉不修改」，`sentinel` 替代 `None` 做「未传值」标记。
- **编码统一**：`open()` 默认就是 UTF-8，跨平台终于一致。
- **性能分析换代**：`cProfile` 升级成 `profiling` 包，新增的 Tachyon 可以零开销挂到运行中的进程上。

## 1. `lazy import`：把「加载」推迟到真正用的时候（PEP 810）

大型项目启动慢，很大一部分时间花在 import 上：找文件、读文件、编译、执行模块顶层代码。即使这次运行只用到其中一个模块，其他模块的代价也照付。

过去的绕法是「把 import 挪进函数里」，代价是 import 散落各处、可读性变差。3.15 给了个更干净的办法：在 import 前加 `lazy`。

```python
lazy import json
lazy from pathlib import Path

print("开始启动")          # 此时 json 和 pathlib 都还没真正加载

data = json.loads('{"k": 1}')   # 到这一行，json 才被完整加载
p = Path(".")                   # pathlib 同理
```

机制上，Python 会先创建一个轻量代理对象，真正访问这个名称时才去加载模块。如果模块不存在，报错时机也推迟到第一次使用，而且回溯里会同时给出「你访问名称的位置」和「最初那行 import」，排查并不困难。

**限制**（先记住，能省很多困惑）：

- `lazy` 只能写在模块顶层。写在函数体、类体、`try` 块里会直接 `SyntaxError`。
- `lazy from x import *` 和 `lazy from __future__ import ...` 不允许。
- 代理对象的类型是 `types.LazyImportType`，需要判断时可以检查它。

**不想改源码也能全局打开**：

```bash
python -X lazy_imports=all app.py
PYTHON_LAZY_IMPORTS=all python app.py
```

代码里也可以动态控制：

```python
import sys

sys.set_lazy_imports("all")     # 全部惰性
sys.set_lazy_imports("normal")  # 只对写了 lazy 的生效

# 只让自己的模块惰性，第三方依赖仍立即加载
def only_myapp(importing, imported, fromlist):
    return imported.startswith("myapp.")

sys.set_lazy_imports_filter(only_myapp)
```

**要兼容旧版本？**  用 `__lazy_modules__` 声明一份名单，然后再正常 import 即可：

```python
__lazy_modules__ = ["json", "pathlib"]

import json      # 惰性
import os        # 仍然是立即加载
```

> 使用建议：CLI 工具、Web 服务的入口最适合用它；一旦写进库的公共 API，请注意很多工具（静态分析、打包、热重载）还不完全理解惰性导入。

## 2. `frozendict`：能当字典用，还能当缓存键（PEP 814）

长期以来需要一个「不可变的 dict」时，大家的做法是 `MappingProxyType`、`types.MappingProxyType` 或者干脆自觉不修改。3.15 在 builtins 里加了 `frozendict`：

```python
a = frozendict(x=1, y=2)
print(a["x"])        # 1

a["z"] = 3           # TypeError: 'frozendict' object does not support item assignment
```

几个关键点：

- 它**不是** `dict` 的子类，直接继承 `object`。
- 键和值都可哈希时，它本身也可哈希，于是能当 `dict` 的键或 `lru_cache` 的参数。
- 保持插入顺序，但比较时不看顺序：

```python
a = frozendict(x=1, y=2)
b = frozendict(y=2, x=1)
print(a == b)            # True
print(hash(a) == hash(b))  # True
```

标准库里 `copy`、`json`、`pickle`、`pprint`、`marshal`、`decimal` 等模块已经跟进支持；`eval()`、`exec()` 能把它当 globals，`type()`、`str.maketrans()` 也能接受。

**迁移提醒**：用 `isinstance(arg, dict)` 判断「是不是映射」的代码，遇到 `frozendict` 会返回 `False`。建议改成 `isinstance(arg, collections.abc.Mapping)`，一次覆盖 `dict`、`frozendict`、`MappingProxyType`。

## 3. `sentinel`：一个不会和任何值撞车的「标记」（PEP 661）

用 `None` 表示「没传值」是老传统，也老出问题：如果 `None` 本身就是合法值呢？过去大家只能自己 `MISSING = object()`。现在有专门的内置类型：

```python
MISSING = sentinel("MISSING")

def next_value(default=MISSING):
    if default is MISSING:
        return compute()
    return default
```

它的行为很干净：

- 打印出来就是 `MISSING`，日志里一眼能看懂；也可以自定义表示 `sentinel("MISSING", repr="<MISSING>")`。
- 真值为真，只和自身相等，**约定用** **`is`** **比较**。
- 复制（浅拷贝、深拷贝）都返回它本身。
- 支持在类型表达式里用 `|`：

```python
def find(key: str, default: int | MISSING = MISSING): ...
```

- 放在模块全局或类作用域、且名字与哨兵名一致时，可以被 pickle，反序列化后仍是同一个对象。
- 不能被继承。

> 一句话：把「未提供」和「提供了 None」彻底分开，接口设计会清晰很多。

## 4. UTF-8 成为默认编码（PEP 686）

这是 3.15 里**最容易被忽视、也最容易在 Windows 上出事**的改动：

```python
open("notes.txt")   # 3.15 起默认按 UTF-8 读写，不再跟随系统区域设置
```

以前默认编码取决于当前平台的 locale：Linux/macOS 通常是 UTF-8，Windows 上经常是 `cp936` / `cp1252`，于是「同一份代码在公司能跑、在同事电脑上乱码」。3.15 统一成 UTF-8。

需要保留旧行为的场景：

```bash
PYTHONUTF8=0 python legacy.py     # 关闭 UTF-8 模式
python -X utf8=0 legacy.py
```

需要「按当前区域」的设置，用显式参数：

```python
open("notes.txt", encoding="locale")
```

**建议**：不管在哪个版本，读写文本都显式写 `encoding="utf-8"`。这是最省事的长期方案，也能让代码在 3.13、3.14 上行为一致。

## 5. 推导式里也能解包了（PEP 798）

以前想把一堆列表「摊平」进一个列表，得写嵌套推导式或者 `itertools.chain`。现在可以直接解包：

```python
lists = [[1, 2], [3, 4], [5]]
print([*L for L in lists])     # [1, 2, 3, 4, 5]

sets = [{1, 2}, {2, 3}]
print({*s for s in sets})      # {1, 2, 3}

dicts = [{"a": 1}, {"b": 2}, {"a": 3}]
print({**d for d in dicts})    # {'a': 3, 'b': 2}
```

生成器表达式和异步生成器表达式同样支持：

```python
gen = (*L for L in lists)      # 等价于 (x for L in lists for x in L)
print(list(gen))
```

这不只是语法糖：对「合并多个来源的配置」「展平分页结果」这类需求，读写成本都低了一截。

## 6. 性能分析换代：`profiling` 包与 Tachyon（PEP 799）

3.15 把性能分析工具整理成一个统一的包：

- `profiling.tracing`：确定型调用追踪，也就是原来的 `cProfile`。
- `profiling.sampling`：新增的统计型采样分析器，代号 Tachyon。

`cProfile` 仍作为别名保留，老代码不受影响；旧的 `profile` 模块已弃用，将在 3.17 移除。

**两者差别一句话**：追踪像有人跟着你记录每一步，精确但慢；采样像每隔一段时间拍张照片，开销极低但可能漏掉很短的动作。

Tachyon 的亮点是「零开销」：它从外部读取进程的调用栈，不需要改代码、不需要重启、也不需要停进程。

```bash
# 直接跑脚本并分析
python -m profiling.sampling run script.py

# 挂到正在运行的服务上（PID）
python -m profiling.sampling attach 12345

# 抓一次快照，适合排查「卡住了」
python -m profiling.sampling dump 12345

# 生成可交互的火焰图
python -m profiling.sampling run --flamegraph -o profile.html script.py

# 类 top 的实时界面
python -m profiling.sampling run --live script.py
```

选指标也有讲究：

|模式|看什么|什么时候用|
| ------| -----------------------| ------------------------|
|`--mode wall`|真实耗时，含 I/O 等待|想知道「时间都去哪了」|
|`--mode cpu`|纯 CPU 时间|找真正的计算瓶颈|
|`--mode gil`|持有 GIL 的时间|多线程里找「抢锁大户」|
|`--mode exception`|异常处理的开销|怀疑异常被当控制流用|

输出格式支持 `--pstats`、`--collapsed`、`--flamegraph`、`--gecko`（Firefox Profiler）、`--heatmap`（行级热力图），还可以用 `--async-aware` 分析 asyncio 任务、用 `--opcodes` 下探到字节码。

> 对线上服务来说，这是 3.15 最实用的新能力：以前只能「复现了再 profile」，现在可以直接对生产进程取样。

## 7. 报错信息再进一步

3.15 的错误提示开始「跨对象、跨语言」地给建议：

- 属性在某个成员里时，提示完整路径：

```text
AttributeError: 'Container' object has no attribute 'area'. Did you mean '.inner.area' instead of '.area'?
```

- 把其他语言的习惯方法名映射到 Python 写法：

```text
>>> [1, 2, 3].push(4)
AttributeError: 'list' object has no attribute 'push'. Did you mean '.append'?

>>> "hello".toUpperCase()
AttributeError: 'str' object has no attribute 'toUpperCase'. Did you mean '.upper'?

>>> {}.put("a", 1)
AttributeError: 'dict' object has no attribute 'put'. Use d[k] = v.
```

- 在不可变类型上调用可变方法，会提示换类型：

```text
>>> (1, 2, 3).append(4)
AttributeError: 'tuple' object has no attribute 'append'. Did you mean to use a 'list' object?
```

顺带一提，`python --help`、`ast`、`calendar`、`sqlite3`、`unittest` 等命令行输出的颜色也变多了，可以统一用环境变量控制。

## 8. 性能与底层：这次是真的快了

- **默认启用帧指针（PEP 831）** ：编译时默认带 `-fno-omit-frame-pointer`，系统级性能分析器、调试器、eBPF 工具终于能完整展开 Python 的栈。这是「可观测性」的基础设施级改进。
- **JIT 明显升级**：新增寄存器分配、更多常量传播、基于真实执行路径的追踪前端。官方基准显示 x86-64 Linux 上比不带 JIT 的标准解释器快 **7%–8%** ，AArch64 macOS 上比尾调用解释器快 **11%–12%** 。
- **base64 / base32 大幅加速**：base64 编码约 2 倍、解码约 3 倍；Base32、Ascii85、Base85、Z85 用 C 重写，速度提升两个数量级。
- **自由线程稳定 ABI（PEP 803）** ：新增 `abi3t`，C 扩展可以编译出一份同时兼容自由线程构建的 wheel，不用再为每个小版本重新打包。
- **mimalloc 成为自由线程构建的默认分配器**，减少高并发下的内存分配争用。
- **GC 回到分代式**：3.14 试过的增量式 GC 因内存压力问题被撤回，3.15 使用 3.13 的分代式回收。
- **官方二进制变化**：Windows 64 位官方包改用尾调用解释器；macOS 官方包默认包含自由线程支持。

## 9. 类型系统：三件新工具

- **TypedDict 支持** **`closed`** **和** **`extra_items`** **（PEP 728）** ：终于能精确表达「只允许这些键」或「额外键必须是某种类型」。

```python
from typing import TypedDict

class Config(TypedDict, closed=True):
    debug: bool

class WithExtra(TypedDict, extra_items=int):
    name: str
```

- **`TypeForm`** **（PEP 747）** ：用来标注「参数本身就是类型表达式」的场景，写 `cast`、注册表这类 API 时更准确。

```python
from typing import Any, TypeForm

def cast[T](typ: TypeForm[T], value: Any) -> T: ...
```

-  **`@typing.disjoint_base`** **（PEP 800）** ：高级特性，把类标记为「互斥基类」，让类型检查器如实反映内置类型和 C 扩展类型的运行时语义。写框架、写类型检查器时才会用到。

## 10. 标准库的实用更新

- **`bytearray.take_bytes()`** ：取走缓冲区内容而不复制，写协议解析、数据管道时能省一次内存拷贝。

```python
buffer = bytearray(b"abc\ndef")
n = buffer.find(b"\n")
data = buffer.take_bytes(n + 1)   # b"abc\n"，buffer 里只剩 b"def"
```

- **`asyncio.TaskGroup.cancel()`** ：任务组可以主动取消，不用再「造一个异常然后抑制它」这种反直觉写法。
- **`Counter`** **支持对称差**：`c1 ^ c2`，统计场景很顺手。
- **新增** **`math.integer`**：把 `comb`、`factorial`、`gcd`、`isqrt`、`lcm`、`perm` 这些只处理整数的函数集中到一个模块。
- **`slice`** **支持下标**：`slice` 现在是泛型类型，可以写 `slice[int]`。
- **`memoryview`** **支持复数格式**：新增 `Zf`、`Zd` 等 C 类型格式字符。
-  **`.start`** **启动配置文件（PEP 829）** ：把 `.pth` 里「偷偷执行 import」的做法换成显式的 `pkg.mod:callable` 入口，启动时执行什么变得可审计；`.pth` 的路径扩展行不受影响。

## 升级检查清单

从 3.14 升到 3.15 之前：

1. **检查编码假设**：有没有依赖系统默认编码读写文件、调用子进程输出。显式补 `encoding="utf-8"` 最稳。
2. **检查**  **`.pth`** **文件**：里面有没有 `import xxx` 这种副作用写法，换成 `.start` 文件。
3. **检查** **`isinstance(x, dict)`** ：如果会收到 `frozendict`，改成 `Mapping`。
4. **不要盲开** **`lazy_imports=all`**：先在测试环境观察，确认没有工具依赖「导入即执行」的副作用。
5. **替换性能分析脚本**：`profile` 模块将在 3.17 移除，迁到 `profiling`。
6. **C 扩展发布者**：评估是否要产出 `abi3t` wheel，减少自由线程用户的重编译成本。
7. **验证构建环境**：如果你们自己编译 CPython，注意帧指针相关编译参数，别让原生组件破坏栈展开。

## 小结

3.15 的关键词是「把约定变成语言能力」：

- 惰性导入让「顶部统一 import」和「快速启动」不再矛盾。
- `frozendict` 和 `sentinel` 把两个靠自觉维持的约定变成了类型。
- UTF-8 默认编码消灭了一整类跨平台乱码问题。
- `profiling` + Tachyon 把性能分析从「开发期工具」推进到「生产可用」。

三个版本连起来看，脉络很清楚：3.13 改善体验并搭好实验框架，3.14 交付语言级新能力，3.15 把这些能力打磨成日常顺手的东西。

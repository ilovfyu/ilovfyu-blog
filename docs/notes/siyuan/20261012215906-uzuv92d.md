把重复的分页参数抽成依赖，再用 APIRouter 拆分路由，理解一个 FastAPI 项目如何从单文件走向模块化。

## 本章使用独立的小项目

为了只观察依赖注入与文件组织，本章不接入上一章的内存任务表。新建下面的目录，两个 ​`__init__.py` 留空：

```text
app/
  __init__.py
  main.py
  dependencies.py
  routers/
    __init__.py
    tasks.py
```

## 1. 抽出分页依赖

`app/dependencies.py`：

```python
from typing import Annotated
from fastapi import Query

def pagination(
    limit: Annotated[int, Query(ge=1, le=100)] = 20,
    offset: Annotated[int, Query(ge=0)] = 0,
) -> dict[str, int]:
    return {"limit": limit, "offset": offset}
```

## 2. 路由依赖分页结果

`app/routers/tasks.py`：

```python
from typing import Annotated
from fastapi import APIRouter, Depends
from app.dependencies import pagination

router = APIRouter(prefix="/tasks", tags=["tasks"])

@router.get("")
def list_tasks(paging: Annotated[dict[str, int], Depends(pagination)]):
    return {"items": [], **paging}
```

空列表用于展示接口结构。接入真实任务仓储后，将查询结果填入 ​`items`​。​`Depends` 会先解析、校验依赖需要的参数，再把结果传给路由。

## 3. 组装应用

`app/main.py`：

```python
from fastapi import FastAPI
from app.routers import tasks

app = FastAPI(title="模块化任务接口")
app.include_router(tasks.router)
```

从项目根目录启动：

```bash
fastapi dev app/main.py
curl 'http://127.0.0.1:8000/tasks?limit=5&offset=10'
```

预期响应包含 ​`items: []`​、​`limit: 5`​、​`offset: 10`​。把 ​`limit` 改为 0，应得到 422；交互文档会显示分页参数，并将路由归到 tasks 分组。

## 文件为什么这样分

- `main.py`：组装路由与应用配置。
- `routers/`：处理请求、选择响应。
- `dependencies.py`：放可复用的请求依赖。
- 项目继续扩大时，再加入 ​`schemas/`​、​`services/` 和仓储层；按实际职责拆分。

依赖注入也适合提供当前用户、数据库会话等请求上下文。本章先聚焦参数复用，下一章回到第二章的任务接口做自动化验证。

## 版本速览

|项目|内容|
| ----------| ---------------------------------------------------------|
|发布时间|2024 年 10 月 7 日|
|维护节奏|常规修复约 2 年，之后继续做安全修复（到 2029 年 10 月）|
|核心主题|新 REPL、彩色回溯、实验性自由线程、实验性 JIT|
|升级成本|中等，主要来自被移除的老模块|

Python 3.13 不是一个「教你新语法」的版本，它做的是三件事：

1. **让日常交互更顺手**：交互式解释器换成了接近编辑器的实现。
2. **让错误更容易看懂**：报错信息继续加料，回溯默认上色。
3. **为未来铺路**：提供关掉 GIL、带 JIT 的实验性构建。

下面按「每天都会碰到」到「了解就行」的顺序展开。

## 1. 交互式解释器换代：从「一行一行」到「像编辑器」

平时敲 `python` 进入的那个 `>>>` 界面，在 3.13 换成了由 PyPy 项目贡献的 pyrepl 实现。变化都很具体：

- **多行编辑**：写一个多行函数时可以按方向键回到上面修改，不再是「只能改最后一行」。
- **历史记录**：支持多行历史，退出后重进仍能翻到之前输入的内容。历史文件位置可以用 `PYTHON_HISTORY` 环境变量修改。
- **高亮**：提示符、输入内容、回溯都带颜色。
- **几个快捷键**：`F1` 打开交互式帮助；`F2` 只看输入、隐藏输出；`F3` 进入粘贴模式，粘贴大段代码时不会被自动缩进搞乱。
- **直接写命令**：`help`、`exit`、`quit` 不用再写成 `help()`。

如果终端环境或老习惯不兼容，可以退回旧实现：

```bash
PYTHON_BASIC_REPL=1 python
```

> 新 REPL 只在真正的终端里启用。用管道、重定向或被其他程序嵌入时仍按标准输入处理，脚本行为不受影响。

## 2. 报错更聪明，回溯默认彩色

从 3.10 开始的「友好错误提示」在 3.13 又补了一批，配合默认开启的彩色回溯，定位问题会快很多：

- 参数名拼错时直接给出候选。例如把 `maxsplit` 写成 `maxsplits`，会提示正确的名字。
- 括号、逗号、`elif` 位置这类常见语法错误，会说明「错在哪一步」。
- 把模块当函数调用、方法名写错时，会给出可能的替代写法。

颜色可以用环境变量关闭，适合把输出写进日志的环境：

```bash
NO_COLOR=1 python app.py
```

## 3. 实验性自由线程：把 GIL 这把「大锁」变成可选（PEP 703）

先说 GIL 是什么：CPython 中所有线程执行 Python 字节码前都要先拿到一把全局锁（Global Interpreter Lock）。好处是线程安全相对简单，代价是**同一时刻只有一个线程在跑 Python 代码**，多核跑不满。

3.13 提供了一种**实验性**的自由线程构建：可以编译出不带 GIL 的解释器，让多个线程真正并行执行 Python 代码。它需要单独的可执行文件，通常叫 `python3.13t`；官方 Windows / macOS 安装器里可以勾选安装，也可以加 `--disable-gil` 从源码构建。

```bash
# 查看自由线程构建的版本信息
python3.13t -V

# 在运行时选择是否启用 GIL
python3.13t -X gil=1      # 打开 GIL
python3.13t -X gil=0      # 关闭 GIL

# 在代码里确认 GIL 是否真的没开
python3.13t -c "import sys; print(sys._is_gil_enabled())"
```

**代价要提前知道**：

- 单线程场景通常比普通构建**慢一些**，因为要处理更多同步细节。
- C 扩展需要单独构建，并显式声明自己支持自由线程（`Py_mod_gil` 槽位）；没有声明的扩展一导入，GIL 就会被重新打开，除非用 `-X gil=0` 强制关闭。
- pip 需要 24.1 以上版本，生态还在补齐。

所以 3.13 的自由线程是「可以试」，而不是「应该上」。把它变成正式支持，是 3.14 的事。

## 4. 实验性 JIT：先有，再快（PEP 744）

3.13 还加入了一个基础的即时编译（JIT）编译器：运行时把热点字节码翻译成机器码。它默认关闭，需要专门构建：

```bash
# 从源码构建时启用
./configure --enable-experimental-jit
make -j

# 运行时也可以开关（取决于构建时的选项）
PYTHON_JIT=1 python app.py   # 开启
PYTHON_JIT=0 python app.py   # 关闭
```

这个阶段的 JIT **提速有限**，官方也明确说是「小幅提升，后续版本继续改进」。它更重要的意义是把「字节码 → 中间表示 → 机器码」的管线搭了起来，后面的版本才有地方继续优化。

## 5. 类型标注：四个实用改进

如果你写类型注解，或用 mypy / pyright 做检查，这几个变化值得单独记住。

### 类型参数可以有默认值了（PEP 696）

以前 `Generic` 想表达「默认是 int」得绕一圈，现在可以直接写：

```python
class Box[T = int]:
    def __init__(self, value: T) -> None:
        self.value = value

box = Box(42)   # 不写类型参数时，T 默认为 int
```

`TypeVar`、`ParamSpec`、`TypeVarTuple` 都支持默认值，写库时能省掉不少样板代码。

### 弃用可以「双面」标注（PEP 702）

`warnings.deprecated()` 既让类型检查器知道这个 API 已弃用，也能在运行时发出 `DeprecationWarning`：

```python
from warnings import deprecated

@deprecated("请改用 new_api()，旧接口将在 3.16 移除")
def old_api() -> None:
    print("still works, but don't use me")
```

### `TypeIs` 让类型收窄更精确（PEP 742）

`TypeGuard` 的问题是：它只告诉你「条件成立时是什么类型」，不保证「条件不成立时是什么」。`TypeIs` 补上了反向推断：

```python
from typing import TypeIs

def is_str_list(val: list[object]) -> TypeIs[list[str]]:
    return all(isinstance(x, str) for x in val)

def show(val: list[object]) -> None:
    if is_str_list(val):
        print(val[0].upper())   # 这里 val 是 list[str]
    else:
        print(val)              # 这里仍是 list[object]
```

写校验函数、`isinstance` 的包装器时更合适。

### TypedDict 的只读项（PEP 705）

把某一项标记成「能读不能写」，交给类型检查器把关：

```python
from typing import TypedDict, ReadOnly

class User(TypedDict):
    id: ReadOnly[int]
    name: str

u: User = {"id": 1, "name": "Ada"}
u["name"] = "Grace"   # 可以
u["id"] = 2           # 类型检查器会报错
```

## 6. `locals()` 的行为终于被写清楚了（PEP 667）

以前在函数里改 `locals()` 返回的字典会发生什么，属于「能跑但别依赖」的灰色地带，不同实现各有各的做法。3.13 把这个行为标准化了：

- 在函数、生成器、推导式等**优化作用域**里，`locals()` 每次返回一份**独立快照**，改它不再影响真正的局部变量。
- `frame.f_locals` 在优化作用域里返回一个**写入代理**，读取是实时的。
- 调试器、`pdb`、覆盖率工具在并发场景下更新局部变量会更可靠。

如果有代码靠 `exec()` 修改函数局部变量，需要显式传命名空间：

```python
def f() -> None:
    namespace = {}
    exec("x = 1", {}, namespace)
    print(namespace["x"])   # 1
```

## 7. 移除与弃用：升级前必须过一遍

### 19 个「死电池」被移除（PEP 594）

这些模块从 3.11 起弃用，3.13 正式删除：

|被移除模块|常见替代|
| ------------------------------------------------| -----------------------------------|
|`cgi`、`cgitb`|`email.message`、`urllib.parse`|
|`crypt`|`hashlib`，或 PyPI 的 `bcrypt`、`argon2-cffi`|
|`telnetlib`|自己用 `asyncio` 写，或用 PyPI 的 `telnetlib3`|
|`imghdr`|PyPI 的 `filetype`、`puremagic`|
|`pipes`|`subprocess`|
|`aifc`、`audioop`、`sunau`、`chunk`|PyPI 上的 `standard-*` 重新发布包|
|`mailcap`|自己解析，或用第三方库|
|`msilib`、`nis`、`nntplib`、`ossaudiodev`、`sndhdr`、`spwd`、`uu`、`xdrlib`|基本都属于「几乎没人用」的老模块|

### 其他移除项

- `2to3` 工具和 `lib2to3` 模块。
- `tkinter.tix`。
- `locale.resetlocale()`。
- `typing.io`、`typing.re` 命名空间。
- 链式的 `classmethod` 描述器写法。

> 实践建议：升级前先跑测试，并检查依赖里是否直接 import 了这些模块。很多老项目出事，不是自己用了，而是某个老依赖用了。

## 8. 标准库里的小惊喜

- **`copy.replace()`** ：按字段替换出对象的新副本，`dataclass` 和多数内置类型都支持。

```python
from copy import replace
from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int

p = Point(1, 2)
print(replace(p, x=10))   # Point(x=10, y=2)
```

- **`dbm.sqlite3`**：新的 dbm 后端，并成为默认后端，适合做简单的键值存储。
- **`base64.z85encode()`**   **/**  **`z85decode()`** ：Z85 编码（ZeroMQ 生态常用）。
- **`glob.translate()`** ：把 glob 模式转成正则，自己实现匹配逻辑时很方便。
- **`os.path.isreserved()`** ：判断文件名是否是 Windows 保留名（比如 `CON`、`NUL`）。
- **`random`** **有了命令行**：`python -m random egg bacon spam` 直接随机挑一个；加 `--integer`、`--float` 还能生成随机数。
- **`argparse`** **支持弃用参数**：`add_argument(..., deprecated=True)`，旧命令行选项可以平滑下线。
- **`mimetypes.guess_file_type()`** ：按路径猜 MIME 类型，比 `guess_type()` 的语义更明确。

## 9. 性能与底层变化

- **mimalloc**：CPython 开始默认捆绑 mimalloc 内存分配器，自由线程构建默认使用它，分配开销更小。
- **导入更快**：`typing`、`enum`、`functools`、`threading` 等模块的导入时间被压缩，其中 `typing` 约减少三分之一。
- **文档字符串自动去缩进**：编译器会去掉 docstring 每行的公共前导空格，`.pyc` 会变小（例如 SQLAlchemy 的某些模块减小约 5%）。
- **类的新属性**：`__static_attributes__` 列出通过 `self.x` 赋值的属性名，`__firstlineno__` 记录类定义的起始行，写代码分析工具时会用到。
- **移动端**：iOS 和 Android 成为官方支持平台（第 3 层级）。
- **`PythonFinalizationError`**：解释器收尾阶段被阻塞的操作，现在抛出这个更明确的异常，而不是笼统的 `RuntimeError`。

## 升级检查清单

从 3.12 升到 3.13 之前，建议按这个顺序检查：

1. 搜索代码和依赖里是否 import 了那 19 个被移除的模块，以及 `lib2to3`。
2. 检查是否有代码依赖 `locals()` 的旧行为，尤其是用 `exec` 改局部变量的调试或热更新逻辑。
3. 跑一遍完整测试，关注解释器收尾阶段（`os.fork()`、`_thread`、`subprocess`）异常类型的变化。
4. 把类型检查器升级到支持 3.13 的版本，再逐步用上 `TypeIs`、类型参数默认值。
5. 想试自由线程或 JIT 就单独装一个构建版本，不要混进生产环境。

## 小结

3.13 的关键词是「体验 + 铺路」：

- 交互式解释器和报错体验，是马上能感受到的提升。
- 自由线程和 JIT 在 3.13 还是实验品，但它们是后面几个版本性能故事的开端。
- 类型标注的默认值、`TypeIs`、`@deprecated`，写库和写业务都能立刻用上。
- 升级的主要阻力来自被移除的老模块。

测试不是为了追求覆盖率数字，而是为了在改动接口、模型和数据库时，能快速知道哪条契约被破坏。FastAPI 的测试可以覆盖 HTTP、数据库、认证、上传、SSE 和 WebSocket，但需要把依赖和生命周期隔离开。

## 测试依赖

```bash
python -m pip install "pytest==9.1.1" "httpx2==2.13.1"
```

Starlette 1.8 的 ​`TestClient`​ 基于 ​`httpx2`​，不是 FastAPI ​`standard`​ 里声明的 ​`httpx`​。只装 ​`httpx` 会遇到：

```text
The starlette.testclient module requires the httpx2 package to be installed.
```

## 应用与数据库夹具

```python
import pytest
from fastapi.testclient import TestClient

from app.core.config import Settings
from app.main import create_app


@pytest.fixture
def app(tmp_path):
    settings = Settings(
        name="Task API Test",
        database_url=f"sqlite:///{tmp_path / 'test.db'}",
        secret_key="x" * 40,
        access_token_expire_minutes=15,
        cors_origins=["http://testserver"],
    )
    return create_app(settings)


@pytest.fixture
def client(app):
    with TestClient(app) as test_client:
        yield test_client
```

`with TestClient(app)`​ 会触发 lifespan，创建引擎和表；请求结束后关闭。不要用模块级 ​`TestClient(app)`，否则应用状态会跨测试泄漏。

每个测试使用独立的临时数据库文件，是最简单的隔离方式。内存 SQLite 需要 ​`StaticPool`​ 和 ​`check_same_thread=False`：

```python
from sqlalchemy import create_engine
from sqlalchemy.pool import StaticPool

engine = create_engine(
    "sqlite://",
    connect_args={"check_same_thread": False},
    poolclass=StaticPool,
)
```

`StaticPool` 让所有线程复用同一个连接；没有它，每个连接会看到不同的内存数据库。

## 认证夹具

```python
def register(client, email="a@example.com", password="strong-password"):
    response = client.post(
        "/api/v1/auth/register",
        json={"email": email, "password": password},
    )
    assert response.status_code == 201
    return response.json()


def login(client, email="a@example.com", password="strong-password"):
    response = client.post(
        "/api/v1/auth/token",
        data={"username": email, "password": password},
    )
    assert response.status_code == 200
    return response.json()["access_token"]


def auth(token):
    return {"Authorization": f"Bearer {token}"}
```

测试不要依赖固定用户 ID 或令牌内容；从注册和登录响应里取实际值。

## 覆盖关键路径

```python
def test_task_crud(client):
    register(client)
    token = login(client)
    created = client.post(
        "/api/v1/tasks",
        json={"title": "写测试", "done": False},
        headers=auth(token),
    )
    assert created.status_code == 201
    task = created.json()

    assert client.get("/api/v1/tasks", headers=auth(token)).json()["total"] == 1
    updated = client.patch(
        f"/api/v1/tasks/{task['id']}",
        json={"done": True},
        headers=auth(token),
    )
    assert updated.json()["done"] is True
    assert client.delete(f"/api/v1/tasks/{task['id']}", headers=auth(token)).status_code == 204
```

至少覆盖：

- 成功路径。
- 未认证 401、无权限 403。
- 资源不存在 404。
- 字段校验 422 及错误契约。
- 资源归属：用户 A 不能读取用户 B 的任务。
- 重复创建、并发冲突等业务错误。

## 依赖覆盖

```python
from app.deps import get_current_user
from app.models import User


def test_override_current_user(app, client):
    def fake_user() -> User:
        return User(
            id=1,
            email="tester@example.com",
            hashed_password="not-used",
            is_active=True,
            is_admin=False,
        )

    app.dependency_overrides[get_current_user] = fake_user
    try:
        response = client.get("/api/v1/auth/me")
        assert response.status_code == 200
        assert response.json()["email"] == "tester@example.com"
    finally:
        app.dependency_overrides.clear()
```

覆盖依赖比 monkeypatch 全局变量更可控。注意清理，否则会影响同一测试文件里的后续用例。

## 上传、SSE 与 WebSocket

```python
def test_upload(client):
    register(client)
    token = login(client)
    response = client.post(
        "/api/v1/tasks/attachments",
        files={"file": ("note.txt", b"hello", "text/plain")},
        headers=auth(token),
    )
    assert response.status_code == 200
    assert response.json()["size"] == 5


def test_sse(client):
    register(client)
    token = login(client)
    response = client.get("/api/v1/tasks/stream/events", headers=auth(token))
    assert response.status_code == 200
    assert "event: tick" in response.text


def test_websocket(client):
    register(client)
    token = login(client)
    with client.websocket_connect(f"/api/v1/ws/tasks?token={token}") as websocket:
        websocket.send_text("hello")
        assert websocket.receive_text() == "echo:hello"
```

`TestClient` 会缓冲 SSE 响应；如果服务端流永不结束，测试会挂住。生产 SSE 端点应有明确的结束条件，或在测试里使用可取消的客户端。

## 异步测试

```python
import httpx2
import pytest


@pytest.mark.anyio
async def test_health_async(app):
    transport = httpx2.ASGITransport(app=app)
    async with httpx2.AsyncClient(transport=transport, base_url="http://test") as client:
        response = await client.get("/health")
        assert response.status_code == 200
```

`ASGITransport`​ 不会自动运行 lifespan。需要数据库初始化时，在 fixture 里手动创建表，或使用独立的 lifespan 管理器。不要把 ​`TestClient`​ 和 ​`AsyncClient` 混在同一个测试里。

## 500 错误

默认 ​`TestClient` 会把服务端异常重新抛出。要测试 500 响应，关闭这个行为：

```python
client = TestClient(app, raise_server_exceptions=False)
```

否则你看到的是测试失败堆栈，而不是应用的错误处理器。

## CI 中的测试

```yaml
- uses: actions/setup-python@v5
  with:
    python-version: "3.13"
- run: python -m pip install -e ".[dev]"
- run: python -m pytest -q
```

测试应使用与生产一致的 Python 版本和数据库类型；SQLite 测试通过不代表 PostgreSQL 迁移没问题。关键迁移和 SQL 最好在 CI 里对真实 PostgreSQL 跑一遍。

## 练习

1. 为用户 A 和 B 写归属隔离测试。
2. 用 ​`dependency_overrides` 替换数据库会话，验证不会写入主库。
3. 写一个 500 处理器测试，确认不返回异常文本。
4. 在 CI 中加 PostgreSQL service，跑迁移和测试。

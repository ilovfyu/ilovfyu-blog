WebSocket 适合双向、低延迟的交互：协同编辑、通知、实时任务状态。FastAPI 直接暴露 Starlette 的 WebSocket 接口，但连接管理、鉴权、广播和断线清理需要自己实现。

## 最小端点

```python
from fastapi import APIRouter, WebSocket, WebSocketDisconnect

router = APIRouter()


@router.websocket("/ws/echo")
async def echo(websocket: WebSocket) -> None:
    await websocket.accept()
    try:
        while True:
            message = await websocket.receive_text()
            await websocket.send_text(f"echo:{message}")
    except WebSocketDisconnect:
        return
```

WebSocket 握手不是普通 HTTP 路由。​`accept()`​ 之前不能发送消息；断开时 ​`receive_*`​ 会抛 ​`WebSocketDisconnect`​。不要用 ​`try/except Exception` 吞掉所有异常，否则连接状态会难以排查。

## 鉴权

浏览器 WebSocket API 不能自定义请求头，常见做法是把短期令牌放在查询参数，或在连接后的第一条消息里发送令牌：

```python
from fastapi import Query
from jwt import InvalidTokenError


@router.websocket("/ws/tasks")
async def tasks_socket(websocket: WebSocket, token: str = Query()) -> None:
    settings = websocket.app.state.settings
    try:
        payload = decode_token(token, settings)
        user_id = int(payload["sub"])
    except (InvalidTokenError, KeyError, TypeError, ValueError):
        await websocket.close(code=1008)
        return

    await websocket.accept()
    ...
```

查询参数会出现在代理和访问日志里。更稳妥的方式是先用短期、一次性的连接票据，或通过 Cookie 认证并校验 ​`Origin`​。无论哪种方式，都要在 ​`accept()` 前完成鉴权，避免未认证连接进入业务逻辑。

## 连接管理

```python
from collections import defaultdict


class ConnectionManager:
    def __init__(self) -> None:
        self.active: dict[int, set[WebSocket]] = defaultdict(set)

    async def connect(self, websocket: WebSocket, user_id: int) -> None:
        await websocket.accept()
        self.active[user_id].add(websocket)

    def disconnect(self, websocket: WebSocket, user_id: int) -> None:
        self.active[user_id].discard(websocket)
        if not self.active[user_id]:
            self.active.pop(user_id, None)

    async def broadcast(self, user_id: int, message: str) -> None:
        for connection in list(self.active.get(user_id, ())):
            await connection.send_text(message)


manager = ConnectionManager()
```

按用户分组是最小实现。还需要考虑：

- 房间/频道：任务、项目或文档级别的订阅。
- 多 worker：进程内字典只在单进程有效；多 worker 需要 Redis Pub/Sub、NATS 或消息队列。
- 背压：慢客户端会拖住广播；为每个连接设置发送超时或独立队列。
- 清理：客户端异常断开、网络抖动、服务重启都要移除连接。
- 心跳：定期 ping/pong，清理半开连接。

## 广播与业务事件

任务状态变化后通知所有订阅者：

```python
async def notify_task_changed(user_id: int, task_id: int, done: bool) -> None:
    await manager.broadcast(
        user_id,
        f'{{"type":"task.changed","task_id":{task_id},"done":{str(done).lower()}}}',
    )
```

生产项目应发送结构化 JSON，并定义事件版本。不要在事件里发送完整 ORM 对象；客户端需要的是稳定契约。

## 前端连接

```javascript
const socket = new WebSocket(`wss://api.example.com/api/v1/ws/tasks?token=${token}`);
socket.onmessage = (event) => {
  const data = JSON.parse(event.data);
  console.log(data);
};
socket.onclose = (event) => {
  if (event.code !== 1000) {
    // 指数退避重连
  }
};
```

重连要加退避和上限；不要在页面隐藏时保持大量连接。令牌过期后应重新获取连接票据，而不是无限重试旧令牌。

## 测试

```python
def test_websocket_echo(client, token):
    with client.websocket_connect(f"/api/v1/ws/tasks?token={token}") as websocket:
        websocket.send_text("hello")
        assert websocket.receive_text() == "echo:hello"
```

`TestClient`​ 的 ​`websocket_connect`​ 会走完整的 ASGI 生命周期。测试未认证连接时，预期 ​`WebSocketDisconnect` 或关闭码 1008。

## 生产部署

- 反向代理必须支持 WebSocket Upgrade；Nginx 需要 ​`proxy_http_version 1.1`​ 和 ​`Upgrade`​/​`Connection` 头。
- 负载均衡器要支持长连接；必要时开启粘性会话，但跨进程广播仍要靠外部 Pub/Sub。
- 设置空闲超时、最大连接数和消息大小限制。
- 不要把 WebSocket 当作可靠消息系统；重要事件仍要落库，客户端重连后补拉。

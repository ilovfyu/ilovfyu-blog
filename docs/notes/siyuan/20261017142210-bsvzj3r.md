单文件适合学习，不适合长期维护。当路由、模型、数据库和配置开始相互引用时，需要一个稳定的目录边界：谁可以依赖谁，应用在哪里创建，启动和关闭资源放在哪里。

## 目标结构

```text
task-api/
├── app/
│   ├── __init__.py
│   ├── main.py
│   ├── core/
│   │   ├── __init__.py
│   │   └── config.py
│   ├── db.py
│   ├── models.py
│   ├── schemas.py
│   ├── security.py
│   ├── deps.py
│   ├── errors.py
│   └── api/
│       ├── __init__.py
│       └── v1/
│           ├── __init__.py
│           ├── router.py
│           ├── auth.py
│           ├── tasks.py
│           └── ws.py
└── tests/
```

依赖方向从上到下：​`api`​ → ​`services/repositories`​ → ​`db/models`​；​`core` 只提供配置，不反向依赖业务模块。不要为了让 import 通过而制造循环依赖，循环通常说明职责放错了位置。

这一章先把最小骨架跑起来：​`db.py`​ 只负责引擎和会话工厂，路由先接入 ​`tasks`，认证和 WebSocket 分别在第 13、16 章加入。

## 配置与应用工厂

`app/core/config.py`：

```python
from functools import lru_cache

from pydantic import SecretStr
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", env_prefix="APP_", extra="ignore")

    name: str = "Task API"
    environment: str = "dev"
    database_url: str = "sqlite:///./tasks.db"
    secret_key: SecretStr = SecretStr("dev-only-change-me-please-32bytes")
    access_token_expire_minutes: int = 60


@lru_cache
def get_settings() -> Settings:
    return Settings()
```

配置不应该在 import 时读取并连接数据库。​`get_settings()`​ 使用缓存，测试可以通过 ​`create_app(settings)` 注入不同配置。

`app/db.py`（第 8 章会继续扩展模型和查询）：

```python
from sqlalchemy import create_engine
from sqlalchemy.orm import DeclarativeBase, sessionmaker


class Base(DeclarativeBase):
    pass


def make_engine(url: str):
    connect_args = {"check_same_thread": False} if url.startswith("sqlite") else {}
    return create_engine(url, connect_args=connect_args)


def make_session_factory(engine):
    return sessionmaker(bind=engine, autoflush=False, expire_on_commit=False)
```

`app/main.py`：

```python
from contextlib import asynccontextmanager

from fastapi import FastAPI

from .api.v1.router import api_router
from .core.config import Settings, get_settings
from .db import Base, make_engine, make_session_factory


def build_lifespan(settings: Settings):
    @asynccontextmanager
    async def lifespan(app: FastAPI):
        engine = make_engine(settings.database_url)
        # 仅用于教程演示；生产环境用 Alembic 迁移建表。
        Base.metadata.create_all(engine)
        app.state.engine = engine
        app.state.session_factory = make_session_factory(engine)
        yield
        engine.dispose()

    return lifespan


def create_app(settings: Settings | None = None) -> FastAPI:
    settings = settings or get_settings()
    app = FastAPI(title=settings.name, version="1.0.0", lifespan=build_lifespan(settings))
    app.state.settings = settings

    @app.get("/health", tags=["system"])
    def health() -> dict:
        return {"status": "ok"}

    app.include_router(api_router, prefix="/api/v1")
    return app


app = create_app()
```

`create_app()`​ 让测试可以构造隔离的应用实例；​`app = create_app()`​ 让 ​`fastapi dev`​ 和 ​`fastapi run` 能找到默认应用。

## 路由聚合

`app/api/v1/router.py`：

```python
from fastapi import APIRouter

from . import tasks

api_router = APIRouter()
api_router.include_router(tasks.router)
```

认证路由和 WebSocket 路由会在后续章节加入；现在先保持 ​`router.py` 可运行。

`app/api/v1/tasks.py`：

```python
from fastapi import APIRouter

router = APIRouter(prefix="/tasks", tags=["tasks"])


@router.get("")
def list_tasks() -> list[dict]:
    return []
```

最终 URL 由三层前缀拼成：应用前缀 ​`/api/v1`​、路由前缀 ​`/tasks`​、路径 ​`""`​。留空路径会生成 ​`/api/v1/tasks`​；写成 ​`"/"` 会生成带尾斜杠的地址，可能导致重定向。选定一种风格并保持一致。

## lifespan 管理启动与关闭

`lifespan` 适合做：

- 创建连接池、HTTP 客户端、缓存客户端。
- 初始化需要在进程生命周期内复用的资源。
- 在关闭时释放连接、刷新日志和指标。

不适合做：

- 每个请求都要做的初始化。
- 长时间阻塞的迁移或数据导入。
- 在启动时偷偷修改生产数据。

数据库迁移应作为独立部署步骤执行，而不是放在 ​`lifespan` 里。多个 worker 同时启动时，迁移可能被并发执行。

## 从单文件迁移

1. 把 ​`main.py`​ 里的模型移到 ​`schemas.py`。
2. 把数据库引擎、会话和 ​`Base`​ 移到 ​`db.py`。
3. 把 ORM 模型移到 ​`models.py`（第 8 章）。
4. 把路由按资源拆到 ​`api/v1/`。
5. 把共用依赖移到 ​`deps.py`。
6. 用 ​`create_app()`​ 取代模块级的 ​`app = FastAPI(...)`。
7. 先跑测试，再启动 ​`fastapi dev app/main.py`。

## 练习

1. 增加 ​`app/core/logging.py`​，提供 ​`configure_logging()`。
2. 把 ​`api_router`​ 拆成 ​`api/v1/tasks.py`​ 和 ​`api/v1/auth.py`。
3. 用测试构造两个不同 ​`database_url` 的应用实例，确认互不影响。
4. 解释为什么不应该在 ​`settings.py`​ 里创建 ​`SessionLocal`。

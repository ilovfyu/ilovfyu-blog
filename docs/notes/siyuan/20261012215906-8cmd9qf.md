用 Pydantic 模型定义请求与响应，为任务接口加入字段约束、路径参数校验和明确的错误状态。

## 请求和响应先分开

创建任务时，调用方只提交标题和完成状态；任务 ID 由服务端生成。用两个模型分别描述输入和输出，能让接口文档表达这条边界。

将上一章的 ​`main.py` 替换为下面的完整代码：

```python
from itertools import count
from typing import Annotated

from fastapi import FastAPI, HTTPException, Path
from pydantic import BaseModel, Field

app = FastAPI(title="Task API")

class TaskCreate(BaseModel):
    title: str = Field(min_length=1, max_length=100)
    done: bool = False

class TaskPublic(TaskCreate):
    id: int

tasks: dict[int, TaskPublic] = {}
sequence = count(1)

@app.post("/tasks", response_model=TaskPublic, status_code=201)
def create_task(payload: TaskCreate):
    task = TaskPublic(id=next(sequence), **payload.model_dump())
    tasks[task.id] = task
    return task

@app.get("/tasks/{task_id}", response_model=TaskPublic)
def get_task(task_id: Annotated[int, Path(ge=1)]):
    task = tasks.get(task_id)
    if task is None:
        raise HTTPException(status_code=404, detail="Task not found")
    return task
```

这里的字典只用于学习：重启进程会丢失任务，不同进程也不共享数据。需要持久化时，再把这部分替换成数据库或仓储层。

## 哪种参数来自哪里

|声明|数据来源|约束|
| ------| -------------| -------------------------|
|`payload: TaskCreate`|JSON 请求体|标题长度 1～100|
|`task_id`|URL 路径|整数且不小于 1|
|`response_model=TaskPublic`|输出结构|包含 ID、标题与完成状态|

`Field`​ 描述模型字段；​`Path` 描述路径参数。长度约束不会自动去掉空白字符，若需要禁止纯空白标题，应额外做规范化与验证。

## 发起请求

保持 ​`fastapi dev main.py` 运行，另开一个终端：

```bash
curl -X POST http://127.0.0.1:8000/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"学习 FastAPI"}'
```

记录响应中的 ID，再用它调用 ​`GET /tasks/{task_id}`。创建成功返回 201；不满足模型或路径约束返回 422；合法 ID 查不到任务时返回 404。

## 练习清单

- 提交空字符串标题，确认得到 422。
- 查询 ID 为 0 的任务，确认路径校验生效。
- 查询一个不存在的正整数 ID，观察 404 与校验失败的区别。
- 将标题长度限制改为 50，在 ​`/docs` 中查看约束。

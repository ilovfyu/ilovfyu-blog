本地能跑通只是起点。生产环境还要回答：进程如何启动、日志去哪里、请求如何追踪、数据库如何迁移、代理如何处理长连接，以及 CI 如何阻止坏代码上线。

## 日志与请求 ID

```python
import logging
import time
from uuid import uuid4

from fastapi import Request

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(name)s %(message)s",
)
logger = logging.getLogger("task_api")


@app.middleware("http")
async def access_log(request: Request, call_next):
    request_id = request.headers.get("X-Request-ID") or uuid4().hex
    request.state.request_id = request_id
    started = time.perf_counter()
    response = await call_next(request)
    elapsed_ms = (time.perf_counter() - started) * 1000
    logger.info(
        "%s %s %s %.1fms request_id=%s",
        request.method,
        request.url.path,
        response.status_code,
        elapsed_ms,
        request_id,
    )
    response.headers["X-Request-ID"] = request_id
    return response
```

生产日志建议输出 JSON，方便采集和检索；字段至少包含时间、级别、服务名、请求 ID、方法、路径、状态码、耗时。不要记录密码、令牌、Cookie 和完整请求体。

## 健康检查与就绪检查

```python
from fastapi import Request
from sqlalchemy import text


@app.get("/health", tags=["system"])
def health() -> dict:
    return {"status": "ok"}


@app.get("/ready", tags=["system"])
def ready(request: Request) -> dict:
    with request.app.state.session_factory() as session:
        session.execute(text("SELECT 1"))
    return {"status": "ready"}
```

- `/health` 只表示进程活着，用于 liveness。
- `/ready` 检查数据库等关键依赖，用于 readiness；失败时负载均衡器不应把流量切进来。
- 不要把 ​`/ready` 做成重查询或外部服务全链路探测，避免健康检查本身拖垮系统。

## OpenTelemetry：0.143 的显式开关

FastAPI 0.143.0 起，自动配置 OpenTelemetry Exporter 变为**显式开启**。升级后如果依赖 ​`OTEL_*` 环境变量自动配置，需要设置：

```bash
FASTAPI_OTEL_AUTO_CONFIGURE=true
```

或在创建应用时传入：

```python
app = FastAPI(telemetry={"auto_configure": True})
```

自动配置只支持 OTLP HTTP/protobuf，需要配置：

```bash
OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector:4318
OTEL_TRACES_EXPORTER=otlp
OTEL_METRICS_EXPORTER=otlp
OTEL_LOGS_EXPORTER=otlp
```

如果应用自己创建了 TracerProvider、MeterProvider 或 LoggerProvider，保持 ​`auto_configure=False`，避免重复注册。完全关闭 SDK：

```bash
OTEL_SDK_DISABLED=true
```

自动配置失败不会阻止应用启动，但会丢失遥测数据；上线前要在预发环境确认 trace 已经到达后端。

`pip install .`​ 会把 ​`app`​ 包安装进镜像；​`pip install -e ".[dev]"`​ 用于本地开发。生产镜像不要安装 ​`dev` 额外项，测试依赖只进 CI。

## 容器镜像

```dockerfile
FROM python:3.13-slim

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    PIP_NO_CACHE_DIR=1

WORKDIR /app

RUN adduser --disabled-password --gecos "" appuser

COPY pyproject.toml ./
COPY app ./app
RUN python -m pip install --upgrade pip && python -m pip install .

COPY alembic.ini ./
COPY migrations ./migrations

USER appuser
EXPOSE 8000

HEALTHCHECK --interval=30s --timeout=3s --start-period=10s \
  CMD python -c "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8000/health')"

CMD ["fastapi", "run", "app/main.py", "--host", "0.0.0.0", "--port", "8000"]
```

要点：

- 使用非 root 用户。
- 不在镜像里放 ​`.env` 或密钥。
- 先复制依赖文件再复制源码，利用构建缓存。
- 生产不需要 ​`fastapi dev` 和热重载。
- 迁移文件要进镜像，部署时执行 ​`alembic upgrade head`。

## 进程模型与反向代理

```bash
fastapi run app/main.py --host 0.0.0.0 --port 8000 --workers 4
```

- `--workers` 适合 CPU 密集或多核场景；数据库连接池总数要乘以 worker 数。
- 容器里通常由 Kubernetes 或进程管理器控制副本数，worker 数不要和副本数重复放大。
- 反向代理负责 TLS、请求体上限、超时、压缩和静态资源。
- 长连接（SSE/WebSocket）需要代理支持并关闭缓冲。
- 可信代理场景配置 ​`--proxy-headers`​ 和 ​`--forwarded-allow-ips`​，不要信任任意来源的 ​`X-Forwarded-For`。

## 部署顺序

1. 构建镜像并推送。
2. 备份数据库。
3. 运行 ​`alembic upgrade head`（单独 job）。
4. 启动新版本实例。
5. 等待 ​`/ready` 通过。
6. 切换流量。
7. 观察错误率、延迟和日志。
8. 保留旧版本以便回滚。

不要在应用启动时自动迁移。多副本同时启动会并发执行迁移，失败时难以恢复。

## GitHub Actions 示例

```yaml
name: test
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.13"
      - run: python -m pip install -e ".[dev]"
      - run: python -m pytest -q
```

需要 PostgreSQL 时加 service 容器，并在测试前执行迁移。镜像构建、推送和部署放在单独的 workflow，用环境环境保护生产密钥。

路由不是把函数挂到网址上就结束了。一个可维护的接口需要明确 HTTP 方法、状态码、路径参数、查询参数、响应结构和文档分组。这一章用内存任务表把这些边界跑通，下一章再补上严格的模型校验。

## 一个可运行的版本

把 ​`main.py` 换成下面的内容。为了让焦点停留在路由和文档上，这里先用最简单的 Pydantic 模型描述输入输出：

```python
from typing import Annotated

from fastapi import FastAPI, HTTPException, Path, Query, status
from pydantic import BaseModel


class TaskIn(BaseModel):
    title: str
    done: bool = False


class TaskOut(TaskIn):
    id: int


app = FastAPI(
    title="Task API",
    version="0.2.0",
    openapi_tags=[
        {"name": "system", "description": "健康检查与运行信息"},
        {"name": "tasks", "description": "任务的创建、查询与删除"},
    ],
)

tasks: dict[int, TaskOut] = {}
next_id = 1


@app.get("/tasks", tags=["tasks"], summary="列出任务")
def list_tasks(
    done: Annotated[bool | None, Query(description="按完成状态过滤")] = None,
    limit: Annotated[int, Query(ge=1, le=100)] = 20,
) -> list[TaskOut]:
    items = list(tasks.values())
    if done is not None:
        items = [task for task in items if task.done is done]
    return items[:limit]


@app.post("/tasks", tags=["tasks"], status_code=status.HTTP_201_CREATED, summary="创建任务")
def create_task(payload: TaskIn) -> TaskOut:
    global next_id
    task = TaskOut(id=next_id, **payload.model_dump())
    tasks[task.id] = task
    next_id += 1
    return task


@app.get("/tasks/summary", tags=["tasks"], summary="任务统计")
def task_summary() -> dict[str, int]:
    return {
        "total": len(tasks),
        "done": sum(1 for task in tasks.values() if task.done),
    }


@app.get("/tasks/{task_id}", tags=["tasks"], summary="读取一个任务")
def get_task(task_id: Annotated[int, Path(ge=1)]) -> TaskOut:
    task = tasks.get(task_id)
    if task is None:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="任务不存在")
    return task


@app.delete(
    "/tasks/{task_id}",
    tags=["tasks"],
    status_code=status.HTTP_204_NO_CONTENT,
    summary="删除任务",
)
def delete_task(task_id: Annotated[int, Path(ge=1)]) -> None:
    if tasks.pop(task_id, None) is None:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="任务不存在")
```

启动后，​`/docs`​ 会把接口按 ​`system`​ 和 ​`tasks`​ 分组。每个函数的 ​`summary`​ 会显示在文档标题上，​`Query`​ 和 ​`Path` 里的约束会成为可交互参数。

## 参数来自哪里

|声明|数据来源|示例|
| -----------| -----------------| --------------------|
|路径参数|URL 路径|`/tasks/42`|
|查询参数|`?` 后面的键值|`/tasks?done=true&limit=10`|
|请求体|JSON body|`POST /tasks`|
|请求头|Header|后续章节的认证令牌|
|Cookie|Cookie|会话或偏好设置|
|表单/文件|`multipart/form-data`|文件上传|

FastAPI 根据类型和位置标记判断来源。路径参数名必须出现在路径模板里；查询参数是函数签名里没有出现在路径中的普通参数。

## 状态码要表达语义

- `200 OK`：读取或更新成功。
- `201 Created`​：创建了新资源。示例在 ​`POST /tasks` 上显式设置。
- `204 No Content`​：删除成功且没有响应体。函数返回 ​`None`​，不要再返回 ​`{"ok": true}`。
- `400`：请求语义错误。
- `401`：没有通过身份认证。
- `403`：已认证但没有权限。
- `404`：资源不存在。
- `409`：与当前资源状态冲突，例如重复邮箱。
- `422`：请求结构或字段校验失败。FastAPI 默认用它表示 Pydantic 校验错误。

状态码不是装饰。客户端会根据它决定重试、提示还是跳转；用 200 包一个 ​`{"success": false}` 会让所有调用方多写一层判断。

## 路由顺序有影响

`/tasks/summary`​ 必须写在 ​`/tasks/{task_id}`​ 前面。FastAPI 按注册顺序匹配；如果先注册动态路径，​`summary`​ 会被当成 ​`task_id`，然后因为不是整数返回 422。静态路径放在动态路径之前，是路由表的基本纪律。

## 让 OpenAPI 更有用

FastAPI 会从函数签名、模型、路径和状态码自动生成文档。额外补充这些信息，调用方才能理解接口：

- `tags`：文档分组。
- `summary`：一句话说明。
- `description`：更长的业务说明，可写在装饰器里。
- `response_description`：响应含义。
- `responses`​：补充错误状态码的文档，例如 ​`responses={404: {"description": "任务不存在"}}`。
- `deprecated=True`：标记即将废弃的接口。
- `include_in_schema=False`：内部接口不进入公开文档。

## 验证

```bash
curl -X POST http://127.0.0.1:8000/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"学习路由"}'

curl 'http://127.0.0.1:8000/tasks?done=false&limit=10'
curl http://127.0.0.1:8000/tasks/summary
curl http://127.0.0.1:8000/tasks/1
curl -X DELETE http://127.0.0.1:8000/tasks/1 -i
```

观察 ​`POST`​ 返回 201、​`DELETE`​ 返回 204、未知任务返回 404，以及 ​`limit=0` 返回 422。

## 练习

1. 增加 ​`GET /tasks/{task_id}/status`​，只返回 ​`id`​ 和 ​`done`。
2. 给 ​`GET /tasks`​ 增加 ​`offset` 查询参数，并限制为不小于 0。
3. 把 ​`POST /tasks`​ 的 ​`201`​ 响应补上 ​`Location` 响应头。
4. 在 ​`/docs` 中确认静态路由和动态路由的顺序差异。

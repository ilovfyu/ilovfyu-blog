## 请求如何穿过系统

```text
HTTP 请求
  → CORS / 请求 ID / 日志中间件
  → 路由匹配（/api/v1/tasks）
  → 依赖：设置、数据库会话、当前用户
  → 路由函数：参数校验、调用服务/仓储
  → 响应模型：过滤字段、生成 OpenAPI
  → 异常处理器：统一错误结构
  → 响应
```

每一层只做自己的事：中间件不写业务 SQL，路由不直接拼错误 JSON，仓储不依赖 FastAPI，模型不访问数据库。这样测试时可以只替换一层，而不是启动整个系统。

## 应用入口

```python
from contextlib import asynccontextmanager

from fastapi import FastAPI

from .api.v1.router import api_router
from .core.config import Settings, get_settings
from .db import Base, make_engine, make_session_factory
from .errors import install_error_handlers


def build_lifespan(settings: Settings):
    @asynccontextmanager
    async def lifespan(app: FastAPI):
        engine = make_engine(settings.database_url)
        app.state.engine = engine
        app.state.session_factory = make_session_factory(engine)
        yield
        engine.dispose()

    return lifespan


def create_app(settings: Settings | None = None) -> FastAPI:
    settings = settings or get_settings()
    app = FastAPI(
        title=settings.name,
        version="1.0.0",
        lifespan=build_lifespan(settings),
    )
    app.state.settings = settings
    install_error_handlers(app)
    app.include_router(api_router, prefix="/api/v1")
    return app


app = create_app()
```

生产环境不要在 lifespan 里 ​`create_all()`；建表交给 Alembic。应用只负责创建连接池和复用资源。

## 路由层保持薄

```python
@router.get("", response_model=TaskPage)
def list_tasks(
    db: DbSession,
    user: CurrentUser,
    page: Annotated[PageParams, Query()],
    q: Annotated[str | None, Query(max_length=100)] = None,
) -> TaskPage:
    repo = TaskRepository(db)
    items, total = repo.list_for_owner(
        user.id,
        limit=page.limit,
        offset=page.offset,
        q=q,
    )
    return TaskPage(items=items, total=total, limit=page.limit, offset=page.offset)
```

路由负责 HTTP 语义：读取参数、调用依赖、选择状态码、返回响应模型。它不负责密码哈希、事务重试、复杂查询或第三方 SDK 细节。需要复用或单元测试的逻辑，放到服务层或仓储层。

## 生产化清单

|项目|最低要求|
| --------| --------------------------------------------------|
|数据库|使用 PostgreSQL；迁移独立执行；备份可恢复|
|密钥|平台 Secret 注入；至少 32 字节；可轮换|
|认证|短效 access token；HTTPS；登出/撤销策略|
|授权|资源级所有权检查；管理员角色或 scope|
|错误|统一结构；500 不泄漏内部信息；日志带请求 ID|
|观测|访问日志、延迟、错误率、trace；健康与就绪检查|
|测试|单元、接口、迁移、关键并发；CI 阻断|
|部署|非 root 容器；反向代理；优雅关闭；滚动发布|
|长连接|SSE/WebSocket 代理配置；心跳；多 worker 广播方案|

## 继续演进

这个任务 API 还可以继续扩展：

- 刷新令牌、令牌版本号和强制下线。
- 基于项目/团队的 RBAC，而不只是 owner。
- Redis 限流、缓存和 WebSocket 广播。
- 队列处理邮件、导出和长任务。
- 全文检索与游标分页。
- 结构化日志、指标和告警规则。
- OpenAPI 客户端生成和契约测试。
- 多环境部署、蓝绿发布和回滚演练。

不要一次把所有东西加进来。每增加一层，都先补测试和观测，再上线。

同步会话简单，但每个请求会占用一个线程。高并发 I/O 场景下，异步会话可以让等待数据库的时间不再阻塞线程。代价是代码更长、事务边界更明显，而且不能把同步和异步会话混用。

## 依赖与安装

```bash
python -m pip install "sqlalchemy[asyncio]==2.1.5" aiosqlite asyncpg
```

- `sqlalchemy[asyncio]`​ 会安装 ​`greenlet`，异步 ORM 需要它。
- `aiosqlite` 用于本地异步 SQLite。
- `asyncpg`​ 用于生产 PostgreSQL；也可以选择 ​`psycopg` 的异步模式。
- 不要在生产使用 ​`aiosqlite` 承担高并发写入。

## 异步引擎与会话

```python
from collections.abc import AsyncIterator

from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker, create_async_engine

engine = create_async_engine(
    "sqlite+aiosqlite:///./tasks.db",
    pool_pre_ping=True,
)
SessionLocal = async_sessionmaker(engine, expire_on_commit=False)


async def get_db() -> AsyncIterator[AsyncSession]:
    async with SessionLocal() as session:
        try:
            yield session
        except Exception:
            await session.rollback()
            raise
```

路由必须使用 ​`async def`：

```python
from typing import Annotated

from fastapi import Depends, APIRouter

DbSession = Annotated[AsyncSession, Depends(get_db)]
router = APIRouter()


@router.get("/tasks")
async def list_tasks(db: DbSession) -> list[dict]:
    result = await db.execute(select(Task).order_by(Task.id.desc()).limit(20))
    tasks = result.scalars().all()
    return [{"id": task.id, "title": task.title} for task in tasks]
```

## 事务的两种写法

显式提交：

```python
async def create_task(payload: TaskCreate, db: AsyncSession, user_id: int) -> Task:
    task = Task(**payload.model_dump(), owner_id=user_id)
    db.add(task)
    await db.commit()
    await db.refresh(task)
    return task
```

上下文事务：

```python
async def create_task(payload: TaskCreate, db: AsyncSession, user_id: int) -> Task:
    async with db.begin():
        task = Task(**payload.model_dump(), owner_id=user_id)
        db.add(task)
    await db.refresh(task)
    return task
```

`async with db.begin()`​ 在退出时提交，异常时回滚。不要在已经 ​`begin()`​ 的事务里再调用 ​`commit()`，否则会报事务已结束。选择一种风格，并在服务层统一。

如果会话前面执行过查询，SQLAlchemy 已经自动开启事务，此时再 ​`begin()`​ 会报 ​`A transaction is already begun`​。要么在会话创建后立刻进入事务，要么统一使用显式 ​`commit()`；不要在同一个请求里混用两种边界。

## 异步查询

```python
from sqlalchemy import func, select


async def list_for_owner(
    db: AsyncSession, owner_id: int, limit: int, offset: int
) -> tuple[list[Task], int]:
    filters = [Task.owner_id == owner_id]
    total = await db.scalar(select(func.count()).select_from(Task).where(*filters)) or 0
    result = await db.execute(
        select(Task)
        .where(*filters)
        .order_by(Task.id.desc())
        .limit(limit)
        .offset(offset)
    )
    return list(result.scalars().all()), total
```

`await db.execute()`​ 之后用 ​`result.scalars().all()`​；​`await db.scalar()`​ 直接取单值。关系加载用 ​`selectinload`​，不要在异步会话里触发隐式懒加载，否则会遇到 ​`MissingGreenlet` 或额外查询。

## 连接池

PostgreSQL 生产配置示例：

```python
engine = create_async_engine(
    settings.database_url,
    pool_pre_ping=True,
    pool_size=10,
    max_overflow=20,
    pool_timeout=30,
    pool_recycle=1800,
)
```

- `pool_size` 不是越大越好，要结合数据库最大连接数和 worker 数量。
- `max_overflow`​ 是突发容量，超过后会等待 ​`pool_timeout`。
- `pool_recycle` 避免连接被中间代理断开后继续使用。
- 每个 Uvicorn worker 都会有自己的连接池；总连接数要乘以 worker 数。

## 常见错误

- 在 ​`async def`​ 路由里使用同步 ​`Session`，阻塞事件循环。
- 在异步会话里访问未加载的关系，触发隐式 I/O。
- 忘记 ​`await session.commit()`，请求返回成功但数据没写入。
- 在全局模块里创建异步引擎，导致事件循环绑定到错误的进程。
- 在 ​`lifespan`​ 外创建连接池，关闭时没有 ​`await engine.dispose()`。

## 测试

```python
import pytest
from sqlalchemy import select
from sqlalchemy.ext.asyncio import async_sessionmaker, create_async_engine


@pytest.mark.anyio
async def test_async_task(tmp_path):
    engine = create_async_engine(f"sqlite+aiosqlite:///{tmp_path / 'test.db'}")
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.create_all)
    factory = async_sessionmaker(engine, expire_on_commit=False)
    async with factory() as session:
        task = Task(title="async", owner_id=1)
        session.add(task)
        await session.commit()
        found = await session.scalar(select(Task).where(Task.title == "async"))
        assert found is not None
    await engine.dispose()
```

`@pytest.mark.anyio`​ 由 ​`anyio`​ 的 pytest 插件提供；​`anyio`​ 会随 Starlette 安装。测试结束要 ​`dispose()`，否则连接池会留在事件循环里。

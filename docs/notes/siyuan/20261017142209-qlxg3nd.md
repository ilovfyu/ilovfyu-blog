接口出错时，调用方最需要知道三件事：发生了什么、能不能重试、如何定位。默认的 ​`HTTPException` 和 422 结构能工作，但不同接口各写一套错误格式，会让前端和排障都变得困难。

## 先区分三类错误

1. **协议错误**：路径不存在、方法不允许、请求体不是合法 JSON。由框架处理。
2. **业务错误**：任务不存在、邮箱重复、状态不允许流转。由应用显式抛出。
3. **未预期错误**：数据库连接断开、代码缺陷。记录日志，返回通用 500，不暴露堆栈。

业务错误用自定义异常表达，而不是在每个路由里手写 ​`JSONResponse`：

```python
class AppError(Exception):
    def __init__(
        self,
        status_code: int,
        code: str,
        message: str,
        details: list[dict] | None = None,
    ) -> None:
        self.status_code = status_code
        self.code = code
        self.message = message
        self.details = details


def error_payload(code: str, message: str, details: list[dict] | None = None) -> dict:
    body: dict = {"code": code, "message": message}
    if details:
        body["details"] = details
    return {"error": body}
```

## 注册异常处理器

```python
import logging

from fastapi import FastAPI, Request
from fastapi.exceptions import RequestValidationError
from fastapi.responses import JSONResponse

logger = logging.getLogger(__name__)


def install_error_handlers(app: FastAPI) -> None:
    @app.exception_handler(AppError)
    async def handle_app_error(request: Request, exc: AppError) -> JSONResponse:
        return JSONResponse(
            status_code=exc.status_code,
            content=error_payload(exc.code, exc.message, exc.details),
        )

    @app.exception_handler(RequestValidationError)
    async def handle_validation_error(
        request: Request, exc: RequestValidationError
    ) -> JSONResponse:
        details = [
            {"loc": list(item["loc"]), "msg": item["msg"], "type": item["type"]}
            for item in exc.errors()
        ]
        return JSONResponse(
            status_code=422,
            content=error_payload("validation_error", "请求参数校验失败", details),
        )

    @app.exception_handler(Exception)
    async def handle_unexpected_error(request: Request, exc: Exception) -> JSONResponse:
        logger.exception("unhandled error on %s %s", request.method, request.url.path)
        return JSONResponse(
            status_code=500,
            content=error_payload("internal_error", "服务内部错误"),
        )
```

统一后的响应：

```json
{
  "error": {
    "code": "validation_error",
    "message": "请求参数校验失败",
    "details": [
      {"loc": ["body", "title"], "msg": "String should have at least 1 character", "type": "string_too_short"}
    ]
  }
}
```

`RequestValidationError.errors()`​ 默认可能包含 ​`ctx`​ 里的 ​`ValueError`​ 对象。直接把它塞进 ​`JSONResponse`​ 会序列化失败，所以这里只保留 ​`loc`​、​`msg`​、​`type` 三个稳定字段。需要更多上下文时，显式转换成可 JSON 序列化的值。

## 在路由里抛出业务错误

```python
from fastapi import APIRouter

router = APIRouter(prefix="/tasks", tags=["tasks"])


@router.get("/{task_id}")
def get_task(task_id: int) -> dict:
    task = tasks.get(task_id)
    if task is None:
        raise AppError(404, "task_not_found", "任务不存在")
    return task
```

也可以在异常处理器里把 ​`AppError`​ 映射到业务错误码。​`code`​ 给机器判断，​`message`​ 给人阅读，​`details` 只放不会泄漏内部信息的内容。

## 让文档描述错误响应

```python
from pydantic import BaseModel


class ErrorBody(BaseModel):
    code: str
    message: str
    details: list[dict] | None = None


class ErrorResponse(BaseModel):
    error: ErrorBody


@router.get(
    "/{task_id}",
    response_model=TaskPublic,
    responses={404: {"model": ErrorResponse, "description": "任务不存在"}},
)
def get_task(task_id: int) -> TaskPublic:
    ...
```

OpenAPI 会把 404 的响应结构标出来，生成客户端或写前端时不必猜。注意 ​`responses` 只影响文档，不会自动产生错误；错误仍要在代码里抛出。

## 不要泄漏内部信息

- 500 响应不要包含 SQL、文件路径、堆栈或第三方服务地址。
- 认证失败统一返回 401，不要区分“用户不存在”和“密码错误”。
- 日志可以记录异常，但不要记录密码、令牌、完整 Cookie。
- 对可预期的冲突使用 409，对权限不足使用 403，不要全部返回 400。
- 重试语义要明确：​`429`​ 配合 ​`Retry-After`​；幂等创建可以用 ​`Idempotency-Key`。

## 测试错误契约

```python
def test_validation_error_shape(client):
    response = client.post("/tasks", json={"title": ""})
    assert response.status_code == 422
    body = response.json()
    assert body["error"]["code"] == "validation_error"
    assert body["error"]["details"][0]["loc"] == ["body", "title"]


def test_not_found(client):
    response = client.get("/tasks/999")
    assert response.status_code == 404
    assert response.json()["error"]["code"] == "task_not_found"
```

错误契约一旦发布，就是 API 的一部分。修改字段名或状态码前，先考虑现有客户端。

## 练习

1. 给 ​`AppError`​ 增加 ​`headers`​ 参数，让 401 能带 ​`WWW-Authenticate`。
2. 为“标题在同一用户下重复”定义 409 错误码。
3. 写一个测试，确认 500 响应不包含异常文本。
4. 设计一个分页参数非法的错误码，并决定它应该返回 400 还是 422。
